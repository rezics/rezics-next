# Access growth shadow triage

The unit of this report is one listed check/metric occurrence. File paths in the table are relative to
`services/kernel`. R means work exceeding its declared derivation; B means an inadequate bound/model;
N means state noise; T means a defective measurement fixture or scale axis. Each row has one primary class:
a known fixture defect takes precedence over attributing its effects to noise.

The derivations come from the [Access Cost rows](../../services/kernel/src/access/README.md#cost), the eleven
listed test files and their native SQL/index definitions in `db/access/schema.sql`, the Community Realm role
reader, and Auth's `current-consent.ts`/schema. Measurement semantics come from the kernel README's
[Growth checks](../../services/kernel/README.md#growth-checks) and `test/support/growth{,-cost,-bound,-model}.ts`.
No production code, existing test, bound or calibration value is changed by this report.

Use the supplied calibration, not the looser checked-in shadow defaults: rows have radius 22, blocks have
radius `max(9, 0.03 × median)`, and statements have radius zero. The maximum implements the harness's absolute
floor/relative allowance convention. A constant row series therefore needs a common intersection of its
22-row intervals; a range exceeding 44 fails even if every increase is below the old 10% slack. A decrease
can fail the new rule too: every allowed family has a nonnegative slope, while the old step rule lets cheaper
later plans pass.

`classifySeries` tests affine constant/log/linear curves, which are narrower than Big-O classes. Indexed
buffer work is a sum of discrete tree traversals and page accesses. A depth or layout transition shared by
many point probes can exceed the calibrated block allowance without becoming a full relation scan. Such a
model mismatch is B; it is not evidence that the repeatability calibration should be enlarged.

Unless a row says otherwise, the harness supplies one warm-up per scale and five measured repetitions.
`[occurrence 2]` identifies another occurrence in the supplied coverage list. There is only one source
check declaration for each corresponding name; the duplicate receives its own row and the same derivation.
The coverage run's original counts/plans were not supplied, so a new run must not be presented as a replay
of either original occurrence.
