# Complete bulk capture and a cross-home confirmation cut

Research evidence, accessed 2026-11-02; repository source baseline `129bf1ff7be77f5ceec93f503d77ba870bcea9d6`.
This is an independent producer/composition analysis, not an adopted ABI, native acceptance, source release or implementation.
Only the earlier [integrated journey report](library-bulk-bound-selection.md) was read; no parallel research report was consulted.

## Finding and recommendation

The adopted cut is logically implementable with **complete writer-maintained capture witnesses plus durable, dependency-local confirmation interlocks**.
It is not implementable by merely attaching either proposed admission role to today's Search/Source readers.
Recommend developing the interlock protocol below as a cross-owner proposal, using the existing operation as its decision record.
Prefer the genuine members-preparation result and admitted durable reader when the source already qualifies for that preparation.
Use the alternative bulk work episode only after explicit adoption of its native construction and source placements; it does not improve currentness by itself.
Neither option currently has complete producers, physical access paths, retention admission or an inclusive original-frame price.
Consequently **common confirmation remains unavailable**. This report gives finite missing bodies and conflicts, not an impossibility claim or a request to raise limits.

The fixed behavior is one private operation, one immutable effect manifest, a complete preview and explicit confirmation.
Relevant population, meaning, original/terminal identity and captured native action-expectation drift before the proved cut rejects confirmation without dispatch.
After that cut, retain exact intentions and earlier effects: target expectation drift conflicts; source/account/consent/delegation or other operation-wide authority loss stops remaining work.
Current original and terminal disclosure, exclusions/NOT/order, foreign dependencies, source/mount and account authority are independent obligations throughout.
A complete retained result is evidence, never permission; unknown or incomplete coverage cannot establish either zero or currentness.

## Four primary systems: what actually closes validation

**PostgreSQL facts.** RR reuses a transaction snapshot; SSI checks conflicts within native serializable transactions; locking returned rows does not protect an absent predicate match.
Independent committed transactions do not become one transaction because each used SSI. [PostgreSQL 18 isolation](https://www.postgresql.org/docs/18/transaction-iso.html).
Pinned `src/backend/storage/lmgr/predicate.c`, notably `CheckForSerializableConflictIn` and `PreCommit_CheckForSerializationFailure`, places writer conflict detection and validation in the native transaction machinery. [Pinned source][pg-ssi].
`snapmgr.c:ImportSnapshot` checks the database identity; exporting keeps transaction-lifetime resources. A textual snapshot ID is not durable cross-home evidence. [Pinned source][pg-snapshot].
Prepared transactions can release the session while retaining durable transaction state and locks; they need prompt transaction-manager resolution and impede vacuum if held. [PostgreSQL 18 PREPARE](https://www.postgresql.org/docs/18/sql-prepare-transaction.html), [pinned `twophase.c`][pg-2pc].
**Inference:** native 2PC is a possible building block, not an installed cross-owner coordinator or a cheap substitute for complete predicate registration. Holding prepared transactions across preview think time is unsuitable.

**FoundationDB facts.** Its transaction authority checks read/write conflict ranges as part of commit, including ranges containing absent keys; snapshot reads omit those read conflicts.
Pinned `fdbserver/resolver/Resolver.cpp` constructs a `ConflictBatch`, calls `detectConflicts`, and returns committed/conflict/too-old dispositions.
Pinned developer documentation limits transaction duration and explicitly addresses unknown commit results. [Conflict-range guide](https://apple.github.io/foundationdb/developer-guide.html#conflict-ranges), [transaction authority](https://apple.github.io/foundationdb/transaction-processing.html), [pinned resolver][fdb-resolver].
**Inference:** retaining ranges from a completed read transaction is insufficient; writer conflict history, accepted read version and the actual decision share an authoritative commit mechanism.
Do not add FoundationDB, emulate its global version, or assume independent PostgreSQL homes already supply that mechanism. Its finite transaction lifetime cannot span a human preview.

**DBOS facts.** Pinned `src/dbos-executor.ts:callStepFunction` invokes the body before recording the operation result; a native effect can commit in that gap.
`src/client.ts:enqueueInTransaction` uses an already-open caller transaction on the system database; it does not merge arbitrary external home commits.
[Pinned step executor][dbos-step], [pinned enqueue][dbos-client], [transaction documentation](https://docs.dbos.dev/typescript/tutorials/transaction-tutorial).
**Inference:** use exact native receipts and REZICS's existing intent/effect route. Durable orchestration alone does not capture a population or supply cross-home currentness.

**OpenTofu facts.** Pinned `internal/backend/local/backend_local.go` takes a state lock before saved-plan lineage/serial checks; `backend_apply.go` releases it after apply.
Saved-plan apply consumes recorded actions. [Pinned validation][tofu-local], [pinned apply][tofu-apply], [saved-plan documentation](https://opentofu.org/docs/v1.11/cli/commands/apply/).
**Inference:** immutable intention plus writer-participating state control is the transferable pattern. Its state lock does not control independent provider changes, authorization or REZICS's multiple native homes.

Shared pattern: identify all dependencies, enroll their writers, keep a durable intention, make validation inseparable from a native decision, and resolve unknown commits from authoritative evidence.
None supplies REZICS Source permission, complete identity capture, Library lifecycle witnesses or an original-frame price. No upstream implementation is proposed for copying.

### Required capture algorithm, conditional on new native producers

1. Admit the complete filter/source/order/release and current authority before enumeration. Capture the exact original frame, remaining allowance and absolute deadlines; persist only permitted provenance and locators.
2. Resolve a **complete dependency cover** before using absence or EOF: population ranges, native owner fact scopes, selected public projection/meaning, original/terminal canonical groups, exclusion/NOT/order and foreign/privacy routing. A selected-ID set cannot be this cover.
3. For each native cover cell, register before its first scan under the same local writer control that guards changes. Retain a non-ABA committed witness and a lossless changed-key frontier. Include empty ranges and future inserts, not only extant rows.
4. Scan bounded canonical source inputs and native evidence using current Source/Search. Count raw aliases, duplicates, misses and tombstones; true matches enter a unique `(generation,canonical)` result or the operation's subject selection. `not_proven` remains unsettled work.
5. Writers commit old/new affected keys and witness changes atomically with their domain mutation. An indexed dirty queue keyed by capture/cell/native key repairs changed keys behind the scan frontier. It includes removals, negative-to-positive arrivals and foreign source-key routing. No suffix-only fix, repeated whole-source restart or all-results scan.
6. A correct snapshot-plus-delta builder either retains the required immutable input version or replays **every** change since registration against settled per-key state. Merely rescanning current rows can miss delete/recreate and ordering moves. Local change positions must be commit-lossless: allocate/update under the native control lock through commit, not a sequence whose low position can commit after its high-water was passed.
7. Drain indexed dirty work, finalize complete canonical/dedup coverage, then validate captured witnesses under the interlocks below. While building, repair and advance derived capture only with explicit owner-native completion; after sealing, never repair witnesses or membership into the old preview. Stable finite input must settle; changing input may invalidate the build without granting a new frame.
8. Capture target intentions before complete preview. Present entries retain exact incarnation/revision; absent explicit status needs a genuine slot lifecycle witness. Subject-based removal scans the target Collection's real occurrences once, probing an indexed transferred selected-subject set. Explicit occurrences capture only those IDs. Include active/deleted lifecycle, actual member IDs and member_revision; never fabricate occurrences from canonical subjects.
9. Complete occurrence expansion needs its own stable native collection scan/change repair and completion cut. Mutable ordinal paging alone misses a row moved behind the frontier. Keep immutable transfer page/equality evidence and acknowledgement until the same operation adopts every row. A later added occurrence is not appended to the sealed manifest.
10. Atomically bind the complete source/result and target-expectation coverage to the operation's sealed generation, counts, exact action bytes and manifest checkpoint. A digest only corroborates retained rows. Display complete private preview only under current independent disclosure, with unavailable rather than zero for missing proof.

The complete cover, lossless dirty routing and stable result/occurrence finalization in steps 2–9 are **missing producers**, not capabilities inferred from the existing canonical store.
For a private bounded structural source, producer routing can name its native Collection/account scopes and indexed foreign dependencies.
For an all-catalogue predicate, logical coverage still spans all 4,096 homes, including empty/behind-frontier homes. A new home activation, late foreign dependency registration or moved owner must join that cover atomically or make it unavailable.
The existing public privacy requirement admits indexed behind/changed coverage, not two 4,096-head sweeps. No such complete bulk capture/confirmation body is established here.

## A concrete currentness protocol to develop

Call the following records **claims** and **tickets** only within this proposal. They are neither supported Source exports nor permission certificates.
The decision record is the existing Commerce operation; there is no second manifest, global epoch, global gate, durable exported reader or second scheduler.
Native cells are derived from the admitted complete cover. A cell can be a native Collection/account scope, a predicate range/property scope on one home, or a captured entry-slot/member lifecycle key.
Use exclusive holder slots with deterministic key order; overlapping confirmations serialize on those local cells, while disjoint scopes proceed. Do not replace all scopes with one common lock.
The exact cell decomposition, particularly overlapping ranges and foreign registration, needs owner-selected physical indexes and a finite writer footprint before adoption.

### Acquire, decide and release

1. At explicit confirm, restore current initiator/source authority and compare the submitted sealed generation/action to the immutable operation. Open only an admitted confirmation episode; captured definition, membership, expectations and original expiry never change.
2. Visit each covered home separately. On its current native client, lock the relevant writer control and current owner/partition/account fences in agreed order; compare the **captured** non-ABA witnesses, not today's re-created equivalent values.
3. If changed, return stale with no dispatch; if absent/pending/unproved, return unavailable. Otherwise persist a durable holder bound to operation, seal, exact local capture/coverage and native commit evidence. Commit and release the client before visiting another home.
4. Every relevant writer must check that same control **inside its final native mutation transaction** and keep the lock through commit. A writer that checked before acquisition therefore commits first and makes acquisition stale, or is forced to encounter the holder. A preflight-only check is insufficient.
5. Transfer each acquired claim's committed provenance to the operation home in a bounded idempotent acknowledgement. Exact claim/cover equality plus a unique insert and root-counter update make duplicate delivery harmless. The cover is a producer-proved complete cover; a count/hash of consumer-discovered homes cannot establish it.
6. While holders remain active, the root transaction can confirm only when all cover claims are acquired, every captured target expectation is included, pending-writer count is zero, current command authority passes, and cancel/expiry/proof-validity conditions still hold. Commit phase, exact confirmation receipt and ordinary domain continuation event atomically. **That commit is the cut.**
7. Release local holders only after reading the authoritative committed root decision through its owner, with exact immutable binding. A local timeout, lease expiry, coordinator crash or lack of heartbeat is not a release certificate. Release is keyed/idempotent and grants no Source reading or effect authority.
8. Once confirmed, use only immutable manifest targets with current native admission/CAS and stable original receipt keys. Do not re-query membership or route an old original to a new terminal. No promise protects expectations through the first/all effects.

Holding a database connection between steps is unnecessary: the holder is committed native control state, and each visit releases its client.
Claim acquisition must be conditional and resumable, not wait while retaining a foreign client. On contention, release this transaction and defer through the existing operation work path or close the attempt within its original deadline.
A deterministic acquisition order prevents cyclic acquisition; finite retained claims still need indexed abort/release recovery. A stalled owner cannot let the root invent an acknowledgement.

### Let native writers proceed without fabricating a cut

Simply queuing all writes behind a crashed confirmer is insufficient for ordinary lifecycle/revocation. A concrete escape path is a writer ticket and root pending interlock:

1. A writer encountering a holder stages a bounded ticket on that home under the same control lock, without its domain effect; release the connection. The ticket is a locator/fence for one real mutation attempt, not another worker or a copy of its domain request.
2. Visit the operation home. Atomically register that ticket as pending if the operation is unconfirmed, or read its exact confirmed/closed decision. Pending registration and root confirmation serialize on the operation row. Release that connection.
3. If confirmation won first, the domain mutation can only commit **after** the cut. If pending registration won, confirmation cannot commit until this ticket is definitively resolved. Reenter the native mutation with current ordinary authorization, exact ticket/holder and local fencing; never hold the root connection.
4. A successful mutation atomically advances its non-ABA witnesses and records committed ticket disposition with its actual native receipt/effect. Delivering this outcome makes the unconfirmed operation stale. Its pending marker already barred any cut during delivery delay.
5. On definite rollback/no change, clear pending only after a native terminal-abort/no-inflight fence proves that the ticket cannot later commit, and the original captured witnesses still match. Unknown commit stays pending until the exact native receipt/disposition resolves it. A missing row or current-value equality is not an abort proof.
6. Root closure, cancel/expiry and terminal owner erasure fence later ticket use; indexed recovery drains tickets/claims with the existing kernel work and original authority. Operation restoration cannot revive a closed capture or renew proof.

This resolves the rollback problem of preemptively marking every preview stale before a writer even commits: a rolled-back write need only make confirmation temporarily unavailable.
It requires a **new original-owner writer-disposition producer**, including no-inflight fencing, protected evidence after revocation, expiry and all native writer paths. Existing receipts/receipt-only mode alone do not supply it.
A native privacy/account write cannot be reported committed while its old state is still used to confirm. If the remote decision is unavailable, either the write fails before commit or confirmation remains barred by a durably registered pending marker.
Owners must settle availability of urgent lifecycle writes under a missing root and exact terminal-erasure recovery authority; freezing permission is not an acceptable fallback.
Exclusive holder slots avoid scanning all active readers on an ordinary write, but broad/narrow dependency overlap may still produce multiple tickets. Its indexed intersection and total fanout are an explicit missing finite-cost obligation, not a new numeric cap.

### Closure of the demonstrated race

Suppose confirmation has validated Q, then a writer changes P or captured entry/member expectation B, then confirmation updates its root H.
If P/B changed before its claim, captured-witness comparison fails, even for change-away-and-back. No dispatch follows.
If its claim was acknowledged first, the final mutation must encounter its holder. Either the writer's root pending insert wins, barring confirmation until stale/abort disposition, or H confirms first while the native data remains unchanged, making the mutation strictly later.
If the writer was in flight before the claim, the shared local control lock orders its commit before acquisition or forces the holder path. No gap remains between a free precheck and its final commit.
Inductively, every acknowledged claim stays protective until root terminal disposition. At a successful root commit all captured witnesses still held and no pending writer could have committed before it.
This argument includes target expectations on their **actual** homes; it never assumes owner entries live on subject homes, or that a target Collection shares the source home.
It depends on complete cover and writer closure. An unenrolled writer, prematurely expired holder, skipped negative range or fabricated native ACK breaks the proof exactly there.

### Other currentness choices and their precise gaps

Writer-maintained invalidation alone is necessary for capture but insufficient for the cut: Q can change after validation and before H commits.
Asynchronous invalidation delivered after a writer commit has the same gap. A root CAS or digest does not close it.
An alternative complete protocol could put native writer conflict registration and Commerce's decision in one distributed validation/commit authority, as FoundationDB does.
The missing primitive would accept the complete original capture and target-expectation read set/ranges, reject any intervening relevant committed change, and atomically commit the operation decision with durable recovery, phantom coverage and bounded costs.
Independent per-home SSI, a revision vector or a list of receipts is not that primitive; none is installed in this PostgreSQL/Core stack. Introducing it needs cross-owner architecture adoption, not a bulk consumer patch.
PostgreSQL prepared local transactions could retain real locks after releasing connections, but require absent-range writer locks, durable coordinator/resolve authority, max-prepared/storage admission and crash/erasure cleanup not present in Core.
It is a distinct owner choice with lock/vacuum/resource consequences, not a free version of the current operational executor. Do not prepare across user think time or create another scheduler.
A bounded all-same-home transaction is a useful optimization if every dependency/expectation fits; it cannot replace required cross-home support.

### Proposed interlock and manifest bodies: exact obligations, unavailable prices

The logical protocol specifies atomic records but not a physical cell/range index, SQL envelope or byte schema; therefore numerical rows/blocks/bytes/points for its **whole body are unavailable**.
The following statement counts are a concrete unfused candidate body, excluding Core/Access/setup/finalization/trigger work, not an executable ABI or an allowed extra budget.

For each original invocation f define actual initial vector `A_f`; every invoked body j transfers the same reservation and consumes `V_fj` before dispatch.
The only valid remaining allowance is `R_f = A_f − Σ_j V_fj` componentwise, with no negative coordinate, refunded dispatched work, hidden new frame or renewed deadline.
The **inclusive** sum must contain time/admission/restoration/Access, Source preparation/prefix/evaluate, full original/terminal/negative/foreign evidence, engine work, capture/dirty storage, target witnesses, claim/ticket/ACK/cut/release, manifest/checkpoint, receipt/outbox/effect/continuation and cleanup.
It must also include failed/missing/empty seeks, lookahead, aliases/duplicates/tombstones/nonmatches, abandoned/discarded pages, rollback/serialization retries and unknown-commit reconciliation.
Whole lifecycle work is the sum of those already admitted frames, including writer-side invalidation/control work and bounded recovery; summing frames does not give a single call a refill.
No initial `A_f` allocation for the proposed bulk result reader/interlock bodies, complete V sequence, byte schema or child footprints exists. Thus the numeric whole-call total and numeric remaining allowance are **unavailable**, including the zero-target case.
The equations are an accounting obligation, not a measured bound or a numerical feasibility claim.

Preserve direct ceilings: c≤min(600,6s+3), engine searches6/owner seeks3, three refill rounds, points16+8c, examined rows64+16c, blocks6 per budgeted row, request64KiB+1KiB×c, response16KiB+4KiB×c and statements12/backend.
Ready reads retain c≤2s+2 and at most2 result-index reads. Common pages retain R≤16, Σs≤128, statements8+4R/backend; maxima c816/points6784/rows14080/statements72/engine96.
Preparation retains input/result≤1000, frontier writes1, points8/input, rows64+16input, statements16/backend, engine4, response4MiB. Applicable native raw-key steps remain≤100, not1000 or256.
All phases retain one connection/backend, 100 explicit IDs/16KiB request and 100-page segment. Derive page k from **remaining** dimensions including all witnesses/control/manifest writes; k=100 is not automatic admission.
Reading all 4,096 privacy heads twice costs8,192 logical rows alone, contradicting the required two-statement `64+2×(behind+changed homes)` privacy subset when behind/changed are zero. Packing/hashing does not remove it.
Even a fitting local claim quote cannot price an arbitrary number of homes in one confirm call. A bounded resumable confirmation episode requires explicit owner adoption under the existing original episode/deadline/allowance; it cannot be silently invented to move excess work elsewhere.
These concrete conflicts require better native access paths/composition or an explicit owning decision; no population/version cap, extra statement budget or permission freeze is selected.
