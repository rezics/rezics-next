# Zone protection through cleanup commit

Research recommendation for adoption; this report authorizes no implementation. **Choose a Zone-specific admitted operand and the existing native head/receiving fences, keeping ordinary `RecordPurgeAuthority` unchanged.** Semantic owns Zone payload; Content owns notice/order evidence references; Accounts owns terminal barriers and its physical copies; Access owns grants; each physical store owns minimization. No new service, scheduler, Source, receipt family, ownership graph or cross-home protocol is needed. Preserve active worker handles and M1 ordering; adopt the boundary in owner text before resuming security/integrity implementation.

## Evidence and fixed policy

The [configured-site journey](zones-site-journey-design.md#lifecycle-completion-means-custody-of-actual-copies) already establishes the missing moderation routes, partial account integration, ownerless-read ambiguity and actual-copy obligation. Its query/product survey is not repeated here. Both [independent resolution](native-retention-discovery-resolution-independent.md#copy-abort-snapshot-and-erasure-inventory) and [constructive resolution](native-retention-discovery-resolution-constructive.md#inclusive-cost-ledger-and-the-actual-admission-inequality) distinguish locator coverage, physical removal and inclusive cost; neither establishes executed protection or cleanup. Their DBOS two-cutoff discovery problem is not this Zone keyed-deadline problem: do not import a discovery index or claim their 40/4,000 allowance as a Zone price.

[Zones](../zones.md#deletion-restoration-withholding-and-durable-cleanup) fixes: “Restore is available only through the current owner role with current `zone:restore` and T strictly before `restore_until`”; “Legal holds suspend cleanup without changing restore deadlines”; “Only the explicit `legal_order` intent branch with an order reference can purge that covered original, and a legal hold still blocks it.” Takedown starts neither deletion nor a clock. Ordinary expiry, early privacy and terminal-account private cleanup retain minimum covered originals and reversal locators while removing uncovered personal/private fields. Named release removes its own decision only. Source withholding remains with its source owner.

[Deletion](../deletion.md#account-erasure) requires actual minimized copies, closed producer fences, late-item resolution and separate active/retained/backup outcomes. Public/unlisted-ever deleted Zones retain only nonpersonal tombstones; always-private rows disappear after protection and copy obligations settle. Account confirmation is terminal immediately, including within an individual restore window. Eligible active public contributions follow account retention policy; this report does not make ownerless Zones readable or invent a public-copy policy.

## Transaction and adversarial schedules

Use `runCommand` and its real `CommandTransaction`, authoritative command time, partition fence and original finite deadline. Proposed lock order: command/home fence → Zone head → exact protection/intent/progress rows → source writer/inventory → exact local copy and associations. Adapt every Zone moderation, intent, cleanup, configuration and account writer to this order; retry deadlocks inside the original budget. No network callback or second connection supplies a local destructive predicate. Current authorization precedes exact receipt replay; exact replay cannot return purged historical payload.

Maintain exact version-scoped coverage counts keyed by canonical pointer under the parent lock, incremented/decremented by each named decision’s at most 16 pointers. Release never scans all decisions or recomputes their union. For each visited payload target, indexed ancestor coverage determines retention; retain descendants of covered objects. An uncovered container is traversed, not deleted wholesale if descendants may be protected. Persist a target-path cursor and process at most 16 targets per invocation; parent revision/protection revision invalidate an old plan. Configuration changes must preserve protected originals/version locators and explicitly rebind coverage before replacing positional arrays; reject an unbound replacement rather than infer a new covered location. Historical target/decision rows page separately and cannot hide in a boolean eligibility probe.

The Zone head is the insertion fence: every insert/update/delete of named decisions, hold state, cleanup intent or payload copies must first `SELECT ... FOR UPDATE` that exact parent. A lookup of an absent decision is insufficient. Deferred constraints must reject child/copy production without the native parent admission; deleted always-private parents cannot be recreated (IDs are never reused and the durable cleanup/source identity remains closed). Existing `semantic.record_purge_writer` is the surviving exact source root; serialize its creation with the head/unique key and retain the minimal closed marker after row removal. Validate children before parent removal, not by cascading unbounded DELETE.

For each local physical minimizer, the native head lock and protection plan remain held until its destructive SQL and progress commit. Hold insertion cannot commit between validation and effect. A JSON projection read, SERIALIZABLE annotation, scheduler registration or ACK cannot replace this. Guard price: untrusted pointers/intents and concurrent protection changes can irreversibly erase covered originals or disclose retained text; after removal neither readers nor runtime inference can reconstruct the admitted legal scope. The smallest fence is the existing exact native parent plus opaque issuer operand and CAS, not a generic guard framework.

Foreign copies use only existing `prepare/read/lockRecordPurgeReceivingHold`, `recordRecordPurgeReceivingCompletion` and `releaseRecordPurgeReceivingHold` in `record-purge-custody.ts`: commit a source hold, release source checkout, accept durable receiver custody, lock receiver row and epoch through the physical effect, record completion with the native committed command position, then verify before source release. `semantic.record_purge_hold/receiving` bind source/version/generation/epochs; source and home gates block source mutation while unreleased. The receiver's existing lock explicitly admits **ordinary-deletion plus 720 hours**, so privacy/order/account operands cannot use it today. Extend its discriminant/validation explicitly for Zone operands; never manufacture an ordinary timestamp or reuse an account ACK.

A hold/release request racing an outstanding receiving hold currently gets `record_purge_receiving_hold_outstanding` (`55P03`); it has not committed protection. Preserve that immutable accepted-command custody, return a retryable incomplete result, and retry the protection command after native release under current authorization. No successful hold may be acknowledged before its native commit. A stuck receiver must keep the source pinned/incomplete rather than release on timeout. If owner policy later requires immediate protection acceptance across an already accepted foreign effect, that needs an adopted owner protocol; no such protocol or movement/enrollment widening is recommended here.

## Bounded durable page and proof plan

For integer `K=1..100`, select `K+1` **raw** ordered source keys, charge all returned keys before held/deadline/protection filtering, process at most K and retain the lookahead without effects. Persist the raw frontier even for held/ineligible keys. Use exact `semantic.record_retention_key` identity plus cleanup generation; proposed keyed due/retry rows are maintained atomically by delete, intent, protection release and account-barrier writers. Indexed `(partition,next_run,key)` wakeups avoid a wraparound rescan of held populations. A wakeup is discovery, never destructive admission. Terminal “empty” uses closed source/copy fences and exact indexed existence checks, not counts or an eligibility scan hidden behind LIMIT.

Persist separate per-key history/source-set, physical-copy, grant and preparation cursors, not a single cursor that skips selected history. One invocation processes at most 16 payload targets, four history members and one physical copy **in total**, sharing budget across selected keys; do not multiply those allowances silently by K. A full history page persists progress and returns continuation; no enumerate-all-versions JSON aggregate, cascade, consumer enumeration or recursive DBOS deletion. Keep existing work registration and finite command deadlines; keyed future wakeups and late obligations survive restart.

Proposed internal byte admission: 1,024 bytes per raw key descriptor (IDs, counters, bounded timestamps), 4,096 bytes per ordinary progress/control row, and 2,097,152 UTF-8 canonical payload bytes for one selected Zone/current-or-history unit per invocation. Existing composition documents are capped at 65,536 bytes and 16 pages (`packages/composition/src/{registry,zone}.ts`); this does not establish a total stored-row/copy bound. Compute actual encoded bytes including JSON keys/escaping, arrays, source tuples and protocol envelopes; cap at the owner boundary and separately page oversized historical artifacts instead of dropping or declaring them absent. Do not silently impose a new accepted-input cap: oversize historical minimization needs that custodian's bounded byte-range/disposition seam before release.

Reserve one invocation as `V = V_begin/settings/commit-or-rollback + V_selection(K+1) + sum(V_admission+V_CAS+V_wakeup for <=K) + V_history(<=4) + V_copy(<=1) + V_progress/receipt/outbox`. Charge nested triggers, constraints, empty seeks, authorization/replay controls, failed attempts and cleanup; report rows, points, statements, UTF-8 bytes and engine requests separately. Known descriptor transport is at most `1024*(K+1)`; payload admission at most 2,097,152 bytes; controls contribute `4096*c` for the explicitly counted control rows, plus actual envelope/returned bytes. For the proposed local body, budget at most K parent/intent/progress admissions, K progress/wakeup writes, one native payload CAS, 16 target visits, four history entries and one copy; return unfinished keys without a payload effect when that shared allowance is spent. Coverage adds at most `16*(D+1)` indexed existence probes for maximum admitted pointer-token depth D, with no decision-population term; derive D and encoded ancestor bytes from the selected bounded payload, and reserve them before effects. BEGIN, settings, COMMIT and reserved ROLLBACK each count as controls; owner callbacks and deferred triggers remain additional explicit vectors. Physical engine blocks/WAL are separate from these application bounds. Unknown owner minimizer cost is unavailable, never zero; no numerical whole-path price or executed pass is established by this derivation.

Use real `test/zones/resource-fixture.ts`: `resourceFixture`, `createBody`, `page`, `f.call`, `f.create`, `f.conditional`, `f.advance`, `f.raw`, native `f.db.pool/admin`; ordinary writer APIs are `insertZone`, `compareAndSetZone`, `enrollResourceRecordSources`, `semanticRetention(...).step`. Existing `test/zones/{record-retention,account-erasure-user-cases}.test.ts` supply starting cases, not proof of the new branch contract.

Add focused native two-connection schedules from the table, pausing after parent/receiver locks with two checked-out pool clients and actual command transactions, then observe blocking/COMMIT/ROLLBACK and raw payload. Include absent-decision insertion, forged brand/order, hold on each branch, overlapping decisions, exact deadline, authorization revoked before replay, stale generation, crash after copy commit before source release, uncertain command still consuming response, unavailable owner and late copy after empty observation. Seed setup through actual writers; use administrative SQL for observations and controlled test interleaving, not fabricated success/ACKs.

Independently grow selected history to 64/512/4096 fixed-size versions/copy associations; one invocation must retain fixed rows/statements/bytes at fixed per-page work, with index-depth block growth only, while repeated durable pages eventually finish every eligible artifact. Also increase viewers/preparation rows and grants for one selected Zone to expose the current bulk DELETE. Keep inclusive native/History/receiver controls in the capture.
