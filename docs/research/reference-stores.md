## Site observations

### Steam

- **Pages and captures:** [store home](https://store.steampowered.com/) (`steam-home.jpg`), [Stardew Valley game page](https://store.steampowered.com/app/413150/Stardew_Valley/) (`steam-game.jpg`). The [Farming category](https://store.steampowered.com/category/farming) showed linked tags and an Add to wishlist control. [Curators](https://store.steampowered.com/curators/) and the personalized [Discovery Queue](https://store.steampowered.com/explore/) asked for sign-in; I used Steam's public [curator explanation](https://store.steampowered.com/curators/aboutcurators/), [new-release queue page](https://store.steampowered.com/explore/new/) and [wishlist notification explanation](https://store.steampowered.com/notifications) for those gated flows.
- **Best at:** a game page opens with a large playable media/gallery area beside a short pitch, recent and overall review summaries, developer/publisher, tags, play modes, supported languages and system requirements. Home separates featured recommendations, new releases, top sellers and topical categories; the queues offer a finite discovery session. A curator recommendation carries the voice behind a pick, which maps well to a Realm's public editorial decision. Wishlist notifications connect interest to later availability or deals.
- **Lesson for REZICS:** present a game as a playable product with clear platform and release status, while keeping its discussion and editorial history attached. A review headline needs its population and period: Steam's “recent” and “overall” are different questions, not one timeless score. Price, checkout and commercial rank are only relevant if REZICS later admits commerce and its evidence.

### Modrinth

- **Pages and captures:** [mods browse](https://modrinth.com/discover/mods) (`modrinth-browse.jpg`), [Sodium project](https://modrinth.com/mod/sodium) (`modrinth-mod.jpg`), and a release opened from its Versions tab (`modrinth-version.jpg`).
- **Best at:** search and include/exclude filters for game version, loader, category, client/server environment, license and “Depends on”. The project puts compatibility, download, links, creator roles and description/gallery/changelog/versions in predictable places. Its version table distinguishes release/beta/alpha and shows game version, loader, publish time and file download; the version page gives the exact file and changes. This is the strongest model for the Mods Zone and mod Work page.
- **Lesson for REZICS:** a mod's Work identity is distinct from its exact release and file. A single “latest” badge is unsafe when latest is an alpha for the wrong loader. Filter and install recommendations must bind an environment and disclose unknown compatibility rather than infer it from a tag.

### CurseForge

- **Pages and captures:** [Minecraft mod browse](https://www.curseforge.com/minecraft/mc-mods) (`curseforge-browse.jpg`), [Just Enough Items](https://www.curseforge.com/minecraft/mc-mods/jei) (`curseforge-mod.jpg`) and [its Files tab](https://www.curseforge.com/minecraft/mc-mods/jei/files/all) (`curseforge-files.jpg`).
- **Best at:** game-scoped browse with category include/exclude, loader and game-version filters; recent files from several versions and loaders directly on the project page; then a dense file table with release channel, game version, loader, size, downloads and upload date. Description, gallery, relations and issues have stable tabs. The global browse menu spans different games.
- **Lesson for REZICS:** use the compact “recent compatible files” pattern after the reader chooses an environment; keep the full file history available. The visited page's prominent ads and long global navigation are a poor model for a calm Work page. CurseForge “relations” must retain their native meaning; an included file and a required dependency are different claims ([package profiles](../contracts/package-profiles.md#minecraft-loaders-and-providers)).

### Nexus Mods

- **Pages and captures:** [Skyrim Special Edition mod browse](https://www.nexusmods.com/games/skyrimspecialedition/mods) (`nexus-browse.jpg`), [Unofficial Skyrim Special Edition Patch](https://www.nexusmods.com/skyrimspecialedition/mods/266) (`nexus-mod.jpg`); its [Files tab](https://www.nexusmods.com/skyrimspecialedition/mods/266?tab=files) was also inspected.
- **Best at:** game-scoped search with category, include/exclude tags and search parameters. A project foregrounds requirements, permissions/credits, translations, mods using this mod and collections containing it. The Files tab exposes exact version, size, upload date and history, though download required login in this visit. Collections show the value of a tested bundle, beyond one isolated mod.
- **Lesson for REZICS:** show dependency direction, credit, permissions and collection membership with explicit provenance. A virus-scan label is evidence about a particular file and scan, not a general promise that the mod is safe. Keep large stats and discussion counts secondary to compatibility and installation instructions.

### Flathub

- **Pages and capture:** [Firefox listing](https://flathub.org/apps/org.mozilla.firefox) (`flathub-app.jpg`). Its Install control opened a public handoff page with a `.flatpakref` fallback and a link to Flatpak setup instructions; no installation was attempted.
- **Best at:** a short install decision: developer and verification marker, install action, download size, risk summary, device class, screenshot gallery, current version changes, architectures and links to the project, support and manifest. The fallbacks explain what to do when the system cannot open a Flatpak URL.
- **Lesson for REZICS:** make source, supported platforms/architectures, artifact size and an actionable installation route visible together. Verification and risk labels need stated evidence and scope; an external link alone cannot justify a REZICS “verified” badge. The Firefox listing displayed no user-review section, so Flathub is the install/trust reference here rather than the review reference.

### AlternativeTo

- **Page and capture:** [VS Code alternatives](https://alternativeto.net/software/visual-studio-code/) (`alternativeto-app.jpg`). I opened “Show all filters” in the browser.
- **Best at:** answering “what can I use instead?” with comparison comments beside each candidate. The expanded filters cover platform, application type, properties, features, cost, license and sort, with visible result counts; candidate rows expose the differences people cite, not just a list of names.
- **Lesson for REZICS:** alternatives should be typed, attributed relations (“alternative for this task” with a reason), then filtered by an admitted facet path. Platform or “privacy focused” must be an attributed, contestable claim, not an unqualified keyword. The page's long AI-written preamble and ad placement should not displace the choices.

### Product Hunt

- **Page and capture:** [Notion product](https://www.producthunt.com/products/notion) (`producthunt-app.jpg`).
- **Best at:** retaining launches as a dated timeline for one product, while keeping screenshots, maker/team, forum, alternatives, reviews and follower interest nearby. The review view includes a count behind the summary and recurring pros/cons, making the text easier to challenge against individual reviews.
- **Lesson for REZICS:** separate a Work's durable identity from launch events and exact versions. Launch discussion can live in a Realm without becoming a release record. A generated review digest, if ever used, must name its population, period and source reviews; it must not masquerade as editorial judgment.

### Mac App Store

- **Page and capture:** Apple's public [Pages listing](https://apps.apple.com/us/app/pages-create-documents/id361309726) (`apple-pages-web.jpg`) states iPhone, iPad and Mac availability and shows screenshots, rating count, reviews, “What's New”, privacy and accessibility disclosures. I also checked a published [Mac-only listing](https://apps.apple.com/us/app/versions-doc-version-control/id1455993400?mt=12) for its version-history format. BrowserOS redirected attempts to open a Mac-only page to the Chinese iPhone store home, so the capture is the cross-platform Pages web listing, **not** a verified Mac-native layout.
- **Best at:** a compact metadata strip (rating count, age, category, developer, language, size), a visual screenshot rail, platform availability and a visible update/privacy/accessibility record. The web listing makes those facts inspectable before opening the App Store client.
- **Lesson for REZICS:** give each platform its own compatibility and media claims, and show update notes and privacy/accessibility disclosures with who supplied them. Do not present an app's platform marketing claim as proof that an artifact has passed REZICS verification.

## What the running REZICS already has

In the local web app on port 3000, signed out, Home showed a populated public feed and the official Mods and Software Zones. The [Mods Zone](http://127.0.0.1:3000/en/r/mods) already has featured Works, game/loader links, an editor list and **“Why … is here”** links to Realm decisions. That public reason is as good as, and more accountable than, a bare store feature slot. The mod [Work overview](http://127.0.0.1:3000/en/w/01a0e6d4-fb61-72f5-a456-fa1b9a8c4038) already has community-scoped ratings, discussions and a Versions tab; the [Versions view](http://127.0.0.1:3000/en/w/01a0e6d4-fb61-72f5-a456-fa1b9a8c4038/versions) only offered kind and language filters in the observed fixture. On that mod, “Start reading”, “Want to read” and a “Genres” section containing Minecraft and Forge obscured the install decision. The [Software Zone](http://127.0.0.1:3000/en/r/software) showed editor picks and decision links, but the seed entries were documentation Works with “Start reading”, so it did not demonstrate an application listing.

As Daniel in the shared local browser session, Home showed Continue, followed Realms and a moderation queue. [Library](http://127.0.0.1:3000/en/library) showed shelves, reading states, ratings and a saved mod, but the mod carried “Read” shelving semantics. Captures: `rezics-home.jpg`, `rezics-mods-zone.jpg`, `rezics-mod-work-overview.jpg`, `rezics-mod-work.jpg` (Versions), `rezics-software-zone.jpg`, `rezics-library-daniel.jpg`. The browser already held Daniel's local session after the REZICS sign-in redirect; no credentials were entered and no content was changed.

These observations fit [frontend direction](../plan/frontend.md#zones): each Zone needs its field's information layout. The existing [Work type profile](../../model/definitions/work-type-v1.ts) admits `rv:ModPackage` and `schema:SoftwareApplication` but not a game-specific type; the observed Software seed consists of documents. [Package management](../contracts/package-management.md) already handles some native resolution/locks and [package profiles](../contracts/package-profiles.md#minecraft-loaders-and-providers) preserve provider relation meanings, but that does not itself supply a public Work release/compatibility read. [Queries](../contracts/queries.md#moving-to-this-contract) records the current fixed search profiles and the planned unified Facet query. These are the starting contracts, not evidence that the proposed UI data already reaches the site.

## What REZICS should adopt

Priorities describe the order for product slices; “Main data” names data or API work beyond the observed public read. Every result must distinguish unknown, incompatible, stale and unavailable information, especially before an install or download.

| Priority · surface | Build and reason | Main data / API |
| --- | --- | --- |
| **P0 · Work page, Library** | Choose the primary action by admitted Work type: read a Book/document, inspect an app/mod, get an exact compatible release or visit a verified source, and save any Work for later. Replace reading labels on mod and software listings; retain reading progress for readable content. | **Yes:** a type-aware public action/availability read and a saved-Work state distinct from reading shelf status. Existing type identity and shelf data can be reused. |
| **P0 · Mods Zone, search** | Make the first browse decision game → game version → loader → client/server, then categories, required dependency and included/excluded Concepts. Show active conditions and result counts; refuse unsupported combinations rather than silently broaden. This prevents a good-looking but unusable mod result. | **Yes:** admitted, bounded Facets over exact release compatibility and dependency relations; a query that binds conditions to one compatible release, not different releases of the same Work. Preserve [FilterDocument semantics](../contracts/queries.md#filter-contract). |
| **P0 · mod Work page, Studio** | Put compatibility, release channel and the best compatible file beside Get; let readers inspect versions, changelog, gallery, requirements, permissions and credit. Studio captures those as structured release data with source and editor attribution. Keep Work, Main Version, exact release and artifact separate. | **Yes:** public release/file IDs, game and loader version ranges, environment, channel, hashes/size where verified, relation type and direction, changelog/media, rights and source evidence. Reuse native package profiles where admitted; do not infer a safe artifact from a Work recommendation. |
| **P1 · Games Zone, game Work page, Discover** | Use Steam's media-first detail and separate curated, new, upcoming and topical game shelves. Put concise play mode, platform, language, release status and recent/overall review context near the pitch; Realm picks link to decisions. A finite “next game” session is an optional Discover view with a clear reason and end. | **Yes:** admit a game Work shape/type (the current type profile has no game-specific type), media, platform/features, dates/status and review summaries bound to question, population, period and Context. Curated shelves can reuse Zone modules and decision links. |
| **P1 · Software Zone, app Work page** | Pair Flathub's platform/install facts with AlternativeTo's attributed alternatives. Show screenshots, current changes, source/maintainer, license, privacy/accessibility disclosures and platform-specific install handoff; do not imply REZICS performs an install when it only links out. | **Yes:** typed application releases, OS/architecture availability, source and install destinations/instructions, version notes, media and evidence-backed trust claims; attributed alternative relations and applicable Facets. Existing package recommendation data is not a public install claim. |
| **P1 · Realm, Zone, Manage** | Extend already strong public editorial picks into named mod collections and game/software guides. Each pick says who chose it and why; a collection says its target environment and whether compatibility was checked. Manage shows stale picks and broken destinations for review. | **Some:** reuse decision provenance and Zone modules; add collection membership, target environment, compatibility-check basis and stale-source status if a collection is presented as installable. |
| **P1 · Library, notifications, profile** | Add a “watch” list for upcoming games and mod/app updates, separate from shelves and follows. Let people choose new release, compatible update and editorial-pick notifications by channel; show the triggering change and permit mute. | **Yes:** per-Work watch preferences, release/update event identity, environment/channel preferences, delivery reason and dedupe state. Do not derive a user's installed state from a download click. |
| **P1 · Home, onboarding** | Continue the current feed and reader resume strip. Offer followed Realms/Concepts and pinned Saved Filters at onboarding, then explain any game/mod/software recommendation by the followed value or Realm decision. Ask for a mod platform/game version only when a compatibility view needs it. | **Some:** Saved Filters, follow and environment preferences plus reason-bearing recommendation reads; existing feed and Realm follow data already cover part of this. |
| **P2 · reader, Studio, Manage** | Render readable install guides, README and changelogs calmly as content, with version and source visible. Studio validates required fields for an installable release; Manage can withdraw an unsafe or stale claim without erasing the Work or its discussion. | **Yes where missing:** revision-linked guide/changelog publication, typed validation, claim provenance and withdrawal/read freshness. Keep external instructions distinct from executable installation permission. |

The first validation slice should use a Minecraft mod with two loaders and a beta newer than its stable release. A reader choosing the older game version must see only compatible exact files, the correct dependency direction and an explicit unknown state when provider evidence is absent. Check the same flow on desktop/phone and as signed out/Daniel; then test an app with different Mac and Linux availability. This would falsify the most consequential parts of the proposed catalogue before expanding the Games Zone.
