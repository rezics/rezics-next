# Bounded native owner TITLE matching

## Finding and scope

Source inspection on 2026-10-29, repository base `ca7c319edefd8d8a272b8fb51c6d57eff5fa2383`.
This is evidence and a recommendation, not an adopted ABI, migration, implementation or native acceptance result.
The product is fixed: one header field; Collection/Library scope is a shared-filter condition; request text and viewer-self owner facts execute together in the native owner plan.
The smallest feasible first mechanism is retained, bounded preparation over the ONE structural owner directory, with batched authorized native title-form reads and local evaluation of the existing text AST. It needs missing producers before it can run.
A persistent owner-local title-term derivative can later accelerate proven shapes, but PostgreSQL GIN plus `LIMIT` cannot establish a bounded direct plan for arbitrary text, Boolean owner leaves, scope and order.
Neither choice requires a public private-document index, public top-N intersection, catalogue scan, separate engine/process/queue/budget, or a new per-built-in/per-Collection membership cache.
The sibling title investigation was not used. The adopted owner-index pair was inspected only for the fixed structural-directory constraints below, never as evidence that title matching exists.

## The exact text and title boundary

`H/text.ts` parses adjacency AND, `|` OR, unary `-`, parentheses, quoted phrases and its specified escapes. Reuse this parser and AST; neither SQL web-search syntax, substring/regex matching nor another Boolean language is equivalent.
The delivered limits are 512 UTF-8 text bytes, depth 4, 64 leaves and 32 admission tokens per phrase. Its Unicode whitespace/CJK phrase counter is an admission counter, not the Search analyzer.
`compileText` emits `match` with `operator: 'and'`, `match_phrase`, and Boolean must/should/must-not structure. Preserve multi-token terms, phrases, negative clauses and operator precedence.
`service.ts` currently compiles text against `search_text`; both `names` and `descriptions` copy into that field. The mandated owner TITLE boundary is narrower: reuse request syntax/analysis semantics over title forms, excluding descriptions, private notes, progress and personal label names.
Existing `names` consists of distinct values of all current native labels and aliases, across all languages. `termValues` folds label replacement/retraction per language and alias assertion/retraction per value; it creates no automatic translation or romanization beyond stored aliases.
Selected statement values are separate `property=value` keyword/facet data. A statement whose property happens to mean “title” is not currently added to `names`; do not invent another title source from it.
Recommendation for Semantic to adopt: expose the complete current label/alias forms of the authorized displayed terminal, retaining native form/provenance dependencies. A redirected original's historical names are not implicitly terminal aliases: public indexing deletes redirected subjects and native display reads the terminal.
This recommendation still requires explicit title-source ownership: which term assertions are eligible under source withdrawal, and how original/terminal/form dependencies are returned. The current snapshot's statement-entry fence path does not prove that every label/alias term has complete source-fence coverage.
An owner witness must be authorized on its stored original AND terminal. A visible terminal title cannot launder a withheld original's owner facts; current summary permission neither fills missing alternate forms nor grants permission to retain them.

The pinned public pipeline is `nfkc_cf` ICU normalization → standard tokenizer → `Traditional-Simplified; Hiragana-Katakana` transform → CJK bigrams → `_cjk_` stop words. It is neither ASCII lowercasing nor the viewer's current locale collation.
OpenSearch's factory defaults bigrams across Han/Hiragana/Katakana/Hangul with `output_unigrams=false`; positions and multi-value boundaries matter. A single isolated CJK character still has its own token behavior; do not approximate CJK with character substrings.
| Counterexample / obligation | Consequence for an owner evaluator |
| --- | --- |
| Title `東京都`, request `東京` | Public CJK bigram tokens can match `東京`; PostgreSQL `simple` whole-word lexemes do not supply the same matching rule. |
| `圖書館`/`图书馆`, hiragana/katakana, fullwidth `Ａ`/`A` | The configured transform/normalization equates forms which plain PostgreSQL lowercasing/locale comparison does not establish. |
| `running` versus request `run` | PostgreSQL English stemming can match where the configured public pipeline has no English stemmer. Switching dictionaries changes meaning. |
| Separate aliases `red` and `blue`; request `red blue` versus `"red blue"` | AND may find both terms in one subject across forms; a zero-slop phrase must not cross separate values. Preserve positions/gaps, not just a set of words or concatenated strings. |
| Stop-only or punctuation-only input; `-foo`; `foo | -bar` | Preserve analyzed-zero-token and AST polarity behavior. Public service rejects queries with no positive text/filter anchor; syntactic positivity is not proof of analyzed tokens. Do not turn these into match-all accidentally. |
| Accents, combining forms, casefold expansions, emoji, mixed CJK/Latin | Versioned tokenizer/ICU behavior needs conformance evidence. NFKC casefold is not arbitrary accent removal; current-locale `toLowerCase` is insufficient. |

Thus exact current public matching is not supplied by stock `to_tsvector`, `plainto_tsquery`, `websearch_to_tsquery`, SQL collation or `ILIKE`. PostgreSQL can store/query externally normalized tokens, but does not itself deliver this analyzer.
The smallest missing semantic choice is a versioned, engine-independent owner evaluator conforming to the existing pinned analyzer and AST, including token positions/value gaps/zero-token behavior; no such complete local evaluator was found in the inspected owner/Search ports.
If that fidelity cannot be supplied in this stack, the owner text contract must explicitly adopt a stated alternative and its counterexamples before runtime. This report grants no silent relaxation, new engine, engine RPC allowance or dependency installation.
Empty header input should omit `text` and still execute scope plus owner filters. Literal `text: ""` and whitespace-only strings currently fail `parseText`; freezing boundary normalization versus preserving that error is a small HTTP SPEC decision, not permission to alter the parser unnoticed.
Negated text must be evaluated over the finite authorized scoped candidate universe. Preserve the current positive-anchor admission rule unless an owner SPEC explicitly explains how that existing rule maps to a positive Library/Collection condition; do not infer admission merely from a hidden population size.
Public default sort is relevance with text, name otherwise; allowed sorts also include id/collections/rating. Relevance uses corpus scoring plus exact-name/phrase boosts. Owner-local scores, PostgreSQL rank and public BM25 are not interchangeable.
`name_sort` chooses the first label by language-key order, normalizes with ICU, uses the missing-name sentinel and has over-limit behavior. It is not the UI's preferred display label or a database default collation.
The owner sort/admission SPEC must name supported meanings, tie-breakers and all score/order dependencies; it cannot promise public-global relevance by copying only title tokens. ID order is the smallest mechanically supportable order, but changing the request default requires explicit adoption, not an implementation shortcut.

## Composition with actual owner leaves and Collection scope

The exact existing leaves are `owner.presence: true`; `owner.state: {profileId,stateSetId,in}`; `owner.label: {id}`; `owner.session: {profileId,lifecycle}`; and `owner.holding: {profileId,kind?,status?}`. There is no owner-account operand.
Bind all of them to the authenticated viewer-self. Expand saved filters, then walk every AND/OR/NOT branch to admit historical pins and register source dependencies, including excluded and ordering inputs.
For state, select the highest LIVE native `owner_write_seq` winner among eligible originals before testing requested state. A newer nonmatching state defeats an older matching state; null cutover sequences are unknown, not low-ranked or timestamp-sorted.
Everything is live state OR effective live personal-label assignment OR retained session/history OR holding. Empty shells, follows, reactions and a manual occurrence alone do not create Everything presence; completed sessions without state and label-only subjects still qualify.
A curated Collection condition can supply manual-only candidates even when `owner.presence` is false. Multiple occurrences/aliases collapse to one search subject; the separate occurrence editor keeps every occurrence and its own ordering.
Use actual curated membership ranges as native inputs to that scope, reducing them into quota-bound query results. Do not add a permanent Collection-specific support/membership mirror to the structural directory to implement this exception.
Private dynamic conditions use current authorized native owner truth. Nonowner/public dynamic scope reads only a completely published membership generation, never a fresh evaluation of private curator facts or a copied private definition on public wire.
The exact Collection-condition wire is being agreed with Semantic and is not frozen. No callable shared Collection helper currently exists. These are semantic composition requirements, not a proposed JSON variant or function signature.
Scope, owner facts and title matching belong in one admitted plan; authorization/source eligibility is an outer invariant on every disclosed result, never a Boolean leaf that OR/NOT can cancel.
Missing/uncovered pin, source, title or identity evidence remains unready/unknown under NOT. A complete native absence can produce false and then negate; an absent directory row, withheld title or failed read cannot.

## Smallest feasible access and maintenance choices

| Choice using the same directory | Benefit | Physical limit / recommendation |
| --- | --- | --- |
| Persistent owner-local derived normalized forms/terms plus access metadata | Reuses analysis across queries; candidate/term/order indexes can accelerate selective admitted shapes. | Copies public title contents privately once per supported title/form, plus private owner association. Common postings, NOT, phrase rechecks, owner rejection and unrelated sort still require retained preparation. Not the minimum first cut. |
| Retained preparation over finite directory candidates, bounded authorized title reads, local AST evaluation | No durable per-owner copy of every supported title. Keep only quota-bound ordered query results, complete dependency registrations, frontier and repair metadata. | Linear finite preparation is explicit; first request cannot scan all candidates. Complete title/evaluator/privacy ports are still missing. Recommended baseline. |
| Combination: small shared access metadata / reusable title derivative, retained fallback | May amortize repeated title reads for up to 32 active queries. | Only add measured acceleration within the ONE directory; no second membership authority or mandatory copy of the global catalogue. |

A title derivative is derived access data, never canonical title truth or permission. Its source lifetime is the selected native form's current eligibility; its owner lifetime ends when no admitted support/query needs it, on expiry/withdrawal, or at owner erase T, whichever fences it first.
Rename/repoint replaces old payload and order dependencies; withholding removes or minimizes ineligible title/token payload while retaining only authorized minimal repair locators. Reveal requires new current source admission, never resurrection from an old cached permission.
If retained, store only authorized required forms or normalized tokens/positions and exact private source locators. This duplicates global/public text where that text is public, not personal note/progress facts; the owner↔subject association and private forms/query definitions remain private.
Do not persist a full public catalogue in each owner partition. One title with a million sessions/copies creates no million title copies. Redirect-support aliases may require distinct original dependencies, but identical terminal title payload can be shared inside that owner without erasing original authorization distinctions.
For retained evaluation, read a bounded candidate/support keyset, release the owner checkout, group bounded full-key title requests by actual native source home, then return to the owner for guarded result/frontier commit. No per-subject checkout loop, cross-partition SQL join or owner connection held during source checkout.
Batching must bound raw rows, bytes, statements and source history work, not merely ID count. Existing 256-ID snapshots and per-ID authorized summaries do not meet this producer requirement automatically; very large form sets require a bounded native form frontier.
Build ordered unique canonical result rows and query dependency metadata as retained outputs, not permanent per-Collection/built-in caches. Every examined exclusion advances durable progress; positive hits alone are insufficient change coverage.
An input prefix is not an ordered output prefix: an unseen renamed/title-sorted or higher-ranked candidate can precede every stored hit. Publish a settled prefix only with proof about the remaining range, or finish the finite build before returning its first ordered page.
Maintain actual current source and query dependencies for original AND terminal, selected forms and their provenance/fences, selected statement/pin/release inputs, Collection authority/membership, owner predicates, and sort keys. Excluded subjects and order-only sources matter as much as returned rows.
Registration must cover not-yet-scanned inputs and creations behind the frontier: a native writer/registration handoff captures old/new affected keys, or establishes a coherent source cut and replay coverage, before a negative or finished frontier is trusted.
Use indexed dependency→live-query repair routing. Broad account fact heads/partition positions can raise alarms; they are not a selective completeness proof and must not restart every result after unrelated writes.
At source rename/withhold/repoint, fence affected results before stale disclosure, retain bounded repair progress, and replace/remove old title/order keys. Reveal/restoration must revisit excluded/behind-frontier inputs, not wait for cursor wraparound or rely on positive-hit dependencies.
The current identity requirement is SCOPED/PARTITIONED/CONCURRENT: bind to actual affected source/query/group dependencies, never a global active marker, universal page gate, guessed revision vector, home sweeps or old basis witnesses. Unrelated identity jobs must not reset unchanged finite-owner work.
Source withdrawal needs native privacy-reduction observations plus producer writes, not only Access on selected candidates. NOT exclusions, rank/name order and a rename behind the settled frontier can disclose a change without returning that source as a candidate.
Final publication/read must reobserve the actual covered source/identity boundary with a native guarded transition; rereading the same repeatable-read snapshot or substituting the latest sink ACK cannot detect a concurrent reduction.

## Physical costs and bounds

Let `N` be all native titles/facts/history; `O` the owner's distinct candidate subjects; `U` distinct original/support scopes; `D` duplicate occurrences/alias supports; `F` relevant native owner facts traversed at bootstrap; `q` fixed admitted text bytes/terms; `s` page size; `R` composed reads.
Let `T` be needed native title forms across those supports, `B` their UTF-8 bytes and `K` analyzed token-position occurrences. `N`, `O`, `F`, `D`, `B` and source fan-out are independent growth dimensions; fixed `q` does not bound a subject's stored title bytes.
| Operation | Derived work, not a runtime measurement |
| --- | --- |
| Initial native directory/bootstrap | Total at least `Ω(F + D)` input visits and `O(O + U)` structural rows, paged through native immutable ranges with concurrent writer capture. Ordinary native fact/index storage remains `Θ(F)`, not copied into directory witnesses. |
| Initial optional title projection | `Θ(B + K)` analysis/output work and `Θ(T)` form metadata per owner needing those forms, plus token/index growth. It is neither `O(1)` initialization nor `Θ(N)` per owner unless that owner's actual supported population is the catalogue. |
| One owner-fact update | Native full-key change plus affected first/last/extremum/index updates; logarithmic seeks for next support/winner. Large cascades/rekeys become bounded durable work, never synchronous history scans. |
| One source-title change | Native source cause plus indexed affected-consumer discovery; total at least proportional to affected owners/forms/queries. Each account processes bounded batches; no synchronous all-owner loop or claim of constant total fan-out. |
| Privacy reduction / reveal repair | Fence affected disclosure immediately; retained work visits affected source scopes, including excluded/order dependencies. Repair/delete cost is proportional to actual affected derivative/results; source auth and minimization remain separate obligations. |
| Retained initial preparation | Linear logical input visits/analysis in relevant candidates/supports/title bytes/positions; indexed reduction/result insertion adds logarithmic B-tree search/write work per changed key. At most one full relevant traversal per build plus permitted bounded replay, not repeated whole-owner scans per page. |
| Current ready read | Ordered result seek plus bounded current disclosure, summary, complete-source/identity observations and any bounded repair. No `O(O)` title evaluation/sort, `N` per-subject calls, or scan through duplicate occurrences. |
| Cursor continuation | Constant bounded encrypted state/locator and indexed result seek at the retained basis; stale affected bases repair/reprepare explicitly. A cursor is not a saved permission or a bag of visited/private IDs. |

For physical bytes, PostgreSQL source defines a usual 24-byte aligned heap header, 4-byte line pointer, 24-byte page header, and an 8-byte index-tuple header (including TID); alignment, null maps, variable-width headers, TOAST, fillfactor and dead versions add cost.
For a schematic row payload of `p` bytes, budget approximately `4 + align8(24 + p)` heap bytes; each ordinary B-tree entry adds approximately `4 + align8(8 + keyBytes)` before page overhead. These are lower accounting components, not frozen DDL or an exact allocated-size claim.
A routed owner UUID plus subject UUID already supplies 36 payload bytes: even that key-only heap row is about 68 bytes before extra coverage/extrema columns and indexes. Original/scope/inverse keys add their own heap/index copies; do not price a directory entry as just a UUID.
Form projection adds total `B` payload bytes, form/version/source locators and row headers, plus positions `K`; a relational term-posting design adds `K` keyed entries and repeated owner/subject/form/term bytes. Packed vectors reduce repeated keys but still store lexemes/positions and GIN posting structures, pending lists and heap recheck costs.
Across `H` owners retaining a given public title, its private derivative bytes multiply by `H`; across `D` repeated sessions/occurrences of that same title they must not. This is a real public-title copy with private association, even if only tokens are retained.
Retained-only preparation avoids durable `B + K` copies after evaluation, but keeps up to `O(O + U)` ordered-result/dependency data per live query; the shared 32-result quota makes the worst case 32 such query outputs, not free storage. Frontiers and workflow payloads remain bounded locators.

The authoritative direct-read ceiling in `docs/filtered-lists.md` is 12 statements per backend for one read, or `8 + 4R` composed (`R ≤ 16`), with one connection per backend. Composition shares admission/safety observations and summary work; each consumer cannot independently spend 12.
For `1 ≤ s ≤ 100`, candidate allowance is `c ≤ min(600, 6s + 3)`, at most three keyset/refill rounds or six engine searches; each refill requests at most twice remaining slots plus one. Total composed slots are at most 128; admitted filter leaves at most 32.
Points are at most `16 + 8c`; PostgreSQL examined rows including removals at most `64 + 16c`; shared blocks at most six per budgeted examined row; request bytes `64 KiB + 1 KiB*c`, response `16 KiB + 4 KiB*c`. Logarithmic index descent remains a growth obligation.
Ready prepared output examines at most `2s + 2` candidates with at most two index reads, still under shared statements/rows/bytes/points ceilings. Privacy observation is at most two statements and `64 + 2*(behind homes + changed homes)` rows via indexed affected scope, not repeated 4096-home scans.
PostgreSQL GIN's `gin_extract_tsquery` selects `GIN_SEARCH_MODE_ALL` when no positive term is required; positional checks can require heap recheck. `gingetbitmap` collects matching items/pending-list work before the executor can limit/sort the output.
Therefore common terms plus rare owner/Collection residuals, common-term phrases, negative text and a different requested order can examine `Θ(O)` postings/rows/blocks even with `LIMIT s`; a bounded result count and constant statement count prove no physical bound.
Only admit a direct shape with a source/index/order proof satisfying every physical ceiling. Otherwise choose retained preparation before dispatch; do not discover unlimited work after an unbounded query or quietly spend a new allowance.

The filtered-list preparation ceiling is 1000 input and 1000 result rows per step, 16 statements/backend, one connection/backend, four engine calls, 4 MiB response, eight points/input and examined rows `64 + 16*input`.
The Kernel job authority is tighter where applicable: at most 100 RAW items/page, 100 pages/segment and 5000 ms command; a shorter caller deadline wins. The 100 RAW cap is job authority, not a newly universal public-page rule.
Count aliases, duplicates, rejected inputs, lookahead, source/internal rows and replay work physically. Bound title-form bytes/positions and multi-statement batching inside those existing ceilings; a single “subject” is not an unlimited free unit.
Durable frontiers are at most eight scalars/2048 UTF-8 JSON bytes; workflow arguments/results at most 4096 bytes. Put private large work/results in Library A5 stores, not DBOS arguments or response payloads.
Admission and retention use the existing shared owner quota of 32 live prepared results with 24-hour idle expiry/least-recently-read eviction; no separate title quota or numeric retry budget is proposed.
Use existing deadline-bounded transaction/job retries and charge each attempt's actual reads/writes/bytes; replay can reread at most the bounded permitted step. Timeouts alone cannot bound work, and a queued check/job is not evidence of a stalled source.
Finite unchanged-owner work must make monotone examined/frontier progress despite continuous disjoint jobs. Settle enough ordered membership to return a useful full page or proven final page; do not issue endless short/empty successes, global-epoch restarts or an eternal preparing response.

## Privacy, erasure and custody

Library A5 must enumerate the exact candidate/support/title derivative, registrations, old/new causes, repair/frontier/result and intent-locator stores and their owning account/source lifetimes. This report does not invent table names or a retention API.
Durable workflow input/output/status, command receipts and events live in Accounts shared-history custody, with exact account-role and source/query/transaction/workflow locators minimized according to the accepted deletion protocol. Library scanning its tables cannot certify shared history clean.
Register those locators in the same native first-apply transaction as derived work creation; include failures/replays and all account roles. Keep private titles, fact keys and query definitions out of public events, errors, cursor plaintext and public holder-discovery keys.
At owner erase T, immediately fence read, write, enqueue, replay and export/count disclosure; queued title work must recheck native T before apply. Minimize private derivative and shared durable copies, delete children before heads/counters, and await actual custody acknowledgements without waiting for consumers to come online.
There is no restore. Retain only the specifically permitted completed public dynamic output A; private working B/private/unlisted state cannot survive as a substitute snapshot.
Include directory/title first applies and concurrent repair in the fixed `library-private-follow-counts` identity participant; no third participant. Missing scan/durable locators or incomplete cleanup is not `NoData`, and a title cache is never an Access decision.
