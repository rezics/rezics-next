# Native file admission

The frozen kernel scenario binds `runCliFileAdmissionJourney` to the ordinary
`runImportCli --dump <path>` caller. One `openApiRuntime` owns Auth, Access, the
public application and the registered media worker for all four sources. The
existing VNDB statistic option provisions its ordinary statistic permission.
The fixture stages, approves and applies an account-key credential through the
real Auth internal API. Private keys, dump files and SQLite live on tmpfs with
mode 0600. No bearer, assertion, cookie or private JWK is captured in evidence.

Each source completes a real file import, rejects several replacements on the
same state, then imports a changed valid successor. Scalar controls cover
malformed syntax, truncation, duplicate record identities and an oversized
record using the exported default cap. VNDB uses real ustar bytes and pinned
native table headers, with truncated framing, an unsafe member path and a
duplicate table member. Ignored archive padding is synthetic zero data, with
no post bodies or SQL. Scalar whitespace positions a four-byte UTF-8 scalar
across the actual descriptor chunk boundary without another read or pre-parser.
Archive payloads cross descriptor boundaries; ustar's 512-byte framing remains
naturally aligned with the production 256 KiB descriptor reads.

Observations include actual CLI exit/handle counts, input passes and chunk
sizes, seal outcomes, converter/decoder module paths, persisted source records
with their digests/revisions, immutable binding journal bytes and acknowledgements,
exact native receipts and public subject responses. Native candidate queries
use only captured subject IDs and route keys. Media observation uses the existing
boundary's real worker drain and native object reader. Rejected replacements
must leave all completed source snapshots, old journals, native receipts,
subjects, candidates and media bytes unchanged, with no Auth or public request.
SQLite closure is independently checked through its closed connection.

The local file admission proof reached an existing VNDB caller defect: malformed
archive input returned 1, while scalar admission returned 2. VNDB table staging
already rejects and cleans its failed acquisition; the CLI now classifies that
failed admission as input failure. Cancellation still takes precedence. No
reader, staging, conversion, permission or transport bound changes.

The focused native command is:

```sh
bun scripts/worker-check.ts -- bun run --cwd services/kernel check test/imports/cli-file-admission.test.ts
```

The managed log owns the check result. The fixture writes credential-free raw
observations to `.temp/cli-file-admission.json` on the check host, including bundle
identity/digest, exact command/receipt keys, source/converter revisions and the
scheduled input hashes. It writes after every returned CLI call, including a
nonzero result. This connected caller supplies no new native growth measurement;
missing growth evidence stays missing. The frozen acceptance is unchanged.

RunStore, bindings, source registry, native API runtime, identitySupport,
openApiObserver, media boundary and adjacent provider/VNDB caller examples.
