# Native Realm image summary growth

This operation binding covers Content Done-when 2 and 3 through the existing
[`readRealmPresentationImages`](../../services/kernel/src/content/realm-media.ts) producer and
[Realm image summary Cost](../../services/kernel/src/content/README.md#cost-realm-image-summary-and-download).
It adds native acceptance evidence without changing the producer, API, authority or schema.

Decision: use two independent pressure sweeps with fixed selected assets, and an actually closed private PostgreSQL pool for optional dependency loss; keep publication and receipt replay in setup.

## Selected operation

The private fixture extends the existing read-only `media-realm-download-fixture.ts` export. Its post images are
setup only; selected summary evidence uses native `realm-icon` and `realm-banner` reservations, website completion,
registered Content effects and the actual Sharp workflow. The production Access factory is composed by `testAccess`
with the kernel action catalogue and native Auth verifier. No permissive Access result or injected summary is used.

| Stage | Native binding | Observation |
| --- | --- | --- |
| Setup | Native identities, protected Realm, grants, fixed 96 × 48 PNG bytes and real object storage transport | Outside summary measurement |
| Admission | Realm management reservation, uploader website completion, revision CAS and permanent claims through Realm settings HTTP | HTTP status, selected IDs and current settings asserted |
| Publication | Committed uploaded outbox event, registered effect relay, source-derived image workflow identity | Await effect and terminal image result; assert exactly one uploaded and available event |
| Replay | Same completion request/key, then retrieve the same terminal workflow | No second publication or changed derivative objects |
| Selected read | Existing two-slot summary reader, Bob's current Realm read and independently anchored active Space | Real SQL bindings, derivatives and source/final anchors asserted |
| Refused read | Anonymous and uploader/manager Alice after current Realm read revocation; erased prior selections; wrong-purpose slots | Both slots are exactly `none`, without identifying reasons |
| Optional loss | Real native checkout on an ended private pool, including one unset slot | Selected slots `unavailable`; unset slot `none`; no cached facts |
| Completion | Actual selected read after failure, final Realm head change, read revocation and independent Space removal | Available recovery; committed source/final races yield `none` |

The unavailable pool's native `connect()` rejection is asserted before observation. It is a real dependency lifecycle
failure before SQL dispatch, not a zero-row SQL substitute. The inclusive measured operation also executes live,
unset, refused, erased, swapped-purpose and recovered reads. A summary read neither enqueues work nor downloads an
object. Required publication work is completed and replayed before measurement, rather than silently omitted while
publication is pending. The earlier erased pair and current pair are separately fixed two-slot inputs; historical
claims are retained by native settings and the erased pair is never republished or replaced during growth.

Available values are compared with the actual published derivative table, including the largest derivative digest,
format/dimensions, the twelve-variant ceiling, stored placeholder and null focal point/credit. Exact object equality
preserves the existing optional schema and excludes original URLs, storage keys, accounts and source URLs.

## Independent pressure and bound

`test/content/growth-realm-image-summary.test.ts` uses the shared `checkGrowth`, physical SQL capture and
`assertGrowthAccessPaths` classifier. Each sweep uses 256, 1024 and 4096, one warmup and three measured repetitions.
The first grows unrelated same-home Spaces, Realms, native-shaped media and derivative rows. The second holds that
population at 4096 and grows an independent retained Realm revision chain, disjoint expired grants/bans and erased
media with derivatives. It also appends selected Realm revisions through the ordinary native settings HTTP command,
retaining the same selected assets. Only unrelated pressure rows use bulk SQL; they never change selected claims,
publication or authority.
The unrelated history head advances to its retained chain tip. Selected home/partition, neighbourhood, identities,
bytes, variant facts and input/page limits remain fixed. No planner, TTL or production budget is altered.

The owning bound is constant rows/statements and logarithmic indexed buffer work, with constant wire bytes. All
control/catalog SQL and refused work stay inside capture. Real relation rows must remain constant; the shared
classifier checks measured access paths against relation page counts. The test asserts exactly two source and two
final selected-media probes, exact keys, current Realm probes and independent host probes. Final race barriers are
placed before the relevant snapshot's partition anchor, before authoritative read time, and native mutations use a
separate pool. No refill, history traversal, retry or discovery is added to the operation.
