# Backend design completeness: Library, Collections, ratings and commerce

Research date: 2026-10-31. Inspected development revision:
`6d3f767467c85dbb9d3bb561d12af784407bd92c` (`dev` and the worker's starting revision).
This is research evidence and a proposed owner handoff, not an adopted product contract or a completion claim.

The backend contains substantial generic Library, rating and payment machinery. It does not yet establish the
complete public journeys promised by scope. The largest gaps are the native whole-query disclosure boundary,
logical built-in Collection execution, default shelf generation binding, durable bulk execution, complete erasure
custody, creator sales, and the integration of the shared search, subject and purchase surfaces. Some status
documents also understate code that has subsequently arrived: labels, private follow-count routes, Collection
previews and facts, copy presentation, mixed discovery transport and Content edition delivery are present.
Neither old negative status prose nor positive stories can substitute for inspecting those implementations.

whole-kernel architecture investigation or a claim that every physical plan has been proved.

## Defects, causes and owner seams

### F1 — Scoped search is a design/exposure/integration gap, not a missing filter widget

**Evidence:** `K/library/collection-routes.ts:818` admits `filter`, `sort`, `view` and pagination, not text.
`K/search/http/routes.ts:293` admits text/filter/sort and opt-in discovery; no explicit Library/Collection scope
argument is provided. Native scope preparation exists in `K/search/{scope-source,service-scope}.ts`, but that
internal consumer is not a complete public text-search journey. `W/search/header-search/types.ts` requires an
existing local `searchAction`; `suggestions.ts` throws for scope. `W/search/search-request.ts` submits catalogue
conditions to mixed discovery. `W/library/collection-filters.tsx` separately navigates a Collection AST URL.

**Cause that allowed delivery:** a common filter grammar, a scope chip and route-local filter form were each
counted as “scoped search,” without freezing the text/analyzer/order/intersection/cursor contract and following a
submitted query through the actual owner source. **Impact:** users cannot finish “search this Collection/library,
then narrow with the same filters” merely by opening the current header. A silently global fallback would disclose
the wrong population. **Seam:** Search owns text/ordering, Commerce owns owner/occurrence population, Semantic
owns catalogue meaning/disclosure, Web owns one search form. **Correction:** one bounded scoped query contract,
current actor binding, explicit unsupported/preparing states and the same AST; preserve occurrence semantics.
The settled centred field/scope chip/right Filters/phone panel do not need another product decision.

### F2 — Logical built-ins and complete native Source execution remain different capabilities

**Evidence:** `K/library/builtin-runtime.ts:130,223` resolves/discovers stable Everything/Liked and supported states
without creating headers. Empty members are based on actual native presence/reaction reads. Nonempty members call
`owner-index-members.ts` → `builtin-runtime-query.ts:99` → `collection-source.ts:534`.
That Source reads `collection-source-native-header.sql` from `library.collection` and refuses missing metadata.
`openOwnerQuery` explicitly maps a missing logical Source to dependency_unavailable. Native metadata's built-in
kind is Everything/state, while Liked's raw Content source/version lives in a separate adapter. This inspection
does not establish a complete headerless/reaction-only canonical Source producer. T3/T4 state the required positive
outcomes; T5 verifies correct failure when ready canonical state is absent. None was run to settle current readiness.

**Cause:** logical identity, raw owner truth, derived support directory, canonical complete groups and current Source
authorization were delivered as separate pieces. A descriptor or a version cannot replace the whole binding.
**Impact:** a real nonempty private Collection/Continue can be unavailable rather than useful; empty demonstrations
do not establish progress. **Seam:** Commerce Source/owner index + Content reaction source + Semantic identity.
**Correction:** finish the real logical Source and complete canonical generation, including reaction-only Liked,
label/session/copy-only Everything and supported-empty states. Keep GET pure except the separately adopted exact
members preparation allowance; do not “fix” this by making missing evidence a successful empty page.

### F3 — Default shelf transport is mounted but lacks its native generation binding

**Evidence:** `K/http/kernel.ts:558` supplies `createDefaultShelfReads` and optional `dependencies.shelves`.
`K/library/shelf-reader-defaults.ts:15` defaults generation to a thrown `ShelfReadUnavailableError` naming
`ShelfMaintenanceOps.initialize` and the native repeatable-read generation gate. `K/server.ts` does not inject a
shelf generation dependency. T7's default-kernel assertion expects pending maintenance. The unordered old entries
branch in `personal-routes.ts:273` is different from the ordered shelf/summary/types branches.

**Cause:** route composition and maintenance implementation were treated as ready reader composition; the required
generation selector was left injectable. **Impact:** a shelf interface can have real entries yet no enriched order,
summary or type directory. **Seam:** Commerce runtime/worker/read adapter and Web shelf. **Correction:** bind the
actual current generation and maintenance gates in default server composition; preserve owner/current admission
before readiness and distinguish missing generation from genuine zero entries.

### F4 — Public advanced filtering cannot yet make complete negative/order/privacy claims

**Evidence:** `K/semantic/public-filter-source.ts:61–98` has real definition resolution but projection pages,
privacy heads and reduction pages return unready; `recordPrivacyReduction` throws `AccessUnavailableError`.
Search mixed discovery is now exposed in `K/search/http/routes.ts`, and native owner filter plans/identity scoped
observations are substantial code. Neither fact fills the absent public projection/reduction writer.
`D/filtered-lists.md` explicitly requires excluded-row, source/foreign dependency and final-observation safety.

**Cause:** candidate checks, pure matchers, current-ID checks and typed Source signatures were used as proxies for
complete query observation. **Impact:** claiming exact “NOT harem,” ordering, kind counts or public Collection/Zone
filtering from a stale index would leak withheld information even when every returned row is readable. Correct
current behavior is readiness/closed, not optimistic results. **Seam:** Semantic reduction producer, Search repair/ACK,
Commerce Source and Performance shared budgets. **Correction:** complete that native chain once and reuse it for
all surfaces; do not create a private Library mirror in the public index. Existing closed grants remain appropriate.

### F5 — Bulk operation schemas and controls are implementation fragments

**Evidence:** `K/library/bulk-contract.ts:1` explicitly says its ports implement no product behavior;
`bulk-schemas.ts` avoids loading unfinished runtime; target/outcome DAOs exist. No libraryOperations route is mounted
by kernel. `KT/library/support/native-dynamic-driver.ts:135` explicitly lacks the durable bulk binding.

**Cause:** operations designed in documents, schema/storage fragments and UI selection were counted together as
completion. **Impact:** “apply to all matching” or “move millions” cannot complete through the ordinary API;
repeated browser mutations cannot preserve a frozen discovery manifest, cancellation, recovery and exact outcomes.
**Seam:** Commerce commands/work/custody, Accounts executor, Web operation UI; Semantic/Search selection source.
**Correction:** one operation admission/status/outcome/cancel slice using the designed receipts and source capture.
This is missing implementation of a design, not a reason to invent another job engine.

### F6 — Collection cover complaints contain producer, default and consistency defects

**Evidence:** covers are rendered in `W/library/collection-page.tsx` and `collection-browser.tsx`; “no cover component”
would be false. `K/library/collection-preview.ts` batches 20 parents/100 raw candidates, selects curated parents
only and keeps unresolved/dynamic previews pending. `builtin-runtime.ts` honestly emits null cover/none and pending
presentation kind for logical descriptors. `K/semantic/list-presentation.ts` and FULL facts are now actual producers,
superseding old design-status gap cells. `UI/src/components/cover-model.ts:27–114` still has finite type-family ratios:
music/unknown square, recipe/place/event landscape, person 3:4, work/game 5:7. `sharedRatio` counts those fallbacks.

**Cause:** a reusable Cover primitive was equated with complete safe Collection preview production, and old family
defaults were retained independently of the settled all-kind portrait default. **Impact:** absent or pending native
covers produce visually empty Collections; mixed/shelf/subject surfaces can disagree on frame shape. **Seam:**
Commerce cover/preview projection, Semantic actual Type/cover rights, UI primitive, Web rows and common renderer.
**Correction:** keep explicit pending/no-cover states, finish bounded safe previews, adopt portrait as the shared
default for every kind, and retain `coverFit`'s whole-image contain behavior for landscape source art. Do not
derive private-member thumbnails or a complete kind from an arbitrary visible page sample.

### F7 — Subject ratings collapse independent reads and expose no scalable population journey

**Evidence:** `W/features/pages/subject-ratings.ts:76–126` runs question, public figure, aggregate, source statistics
and own vote together; required failures return null, rendered by `subject-ratings-view.tsx:62` as a region failure.
Its optional memberships input is sliced to three. The served public caller in `subject-queries.ts:349` passes no
memberships; the private helper also defaults to none. Meanwhile `K/rating/routes.ts:201` exposes a signed population
page, and its batch figure read caps explicit populations at 20. Standard question/Global IDs are fixed in Web.

**Cause:** a fixture-sized Realm array and aggregate data object substituted for a designed population/question
selector with independent readiness. **Impact:** a source-statistic failure can remove useful native rating data;
users in hundreds of Realms cannot discover/select all eligible figures through this section. This is one region's
failure aggregation, not proof the entire subject route fails for every error. **Seam:** Content rating APIs and
Web subject regions; Accounts memberships are candidates, not figure eligibility. **Correction:** one active
population/question with bounded searchable/paged choices, independent native/source/own-vote states and explicit
freshness. Keep Global standard as the public headline. The 100 counting-Realm policy is explicit backend scope,
not evidence that the UI may render 100 sections or silently show only the first three.

### F8 — Generic question data is not a complete question authoring capability

**Evidence:** `K/rating/README.md` defines question revision, grain, scale, prior and population semantics;
`rating/routes.ts` mounts question GET but no product create/update operation. The current grain set is the four
named grains. Web uses the standard question identity. Fixture inserts and native function tests cannot supply
an ordinary authorised question editor or arbitrary new grain/metric behavior.

**Cause:** “generic ratings” combined configurable data, fixed aggregate behavior and missing product authoring.
**Impact:** an operator cannot complete a new Realm question journey through this API merely because the table
can store it. **Seam:** Content owns rating behavior and question lifecycle; definitions/configuration and Web own
their respective consumers. **Correction:** inventory the actually promised question management surface before
opening it. The current public standard question need not wait for an arbitrary metric builder; do not advertise
the latter as implemented. Any additional public authoring scope would need explicit adoption, not this report.

### F9 — Purchase wiring exists; creator sales and subject ownership summaries do not

**Evidence:** `K/commerce/{subject-offers,benefit,content-edition-buyer-fact}.ts`,
`K/content/edition-sale-native.ts` and kernel buyer-fact mounting implement real ownership/Content seams.
`W/checkout/subject-offers.ts` uses the generated client, while illustrative kernel.local responses explicitly
return 503. `W/checkout/creator-sales.ts:44` returns unavailable because neither selected native commerceSales nor
generated caller exists. The subject owned-benefits region links to existing own entitlements and declares no
bounded per-subject ownership batch (`D/research/design-status-commerce.md`). Payout statements are a separate API.

**Cause:** old missing-delivery descriptions persisted after Content integration; independently, new consumer
fixtures made sales and owned-state layouts look complete before their producers existed. **Impact:** a known
offer → order → entitlement → exact edition path has source wiring, but the seller cannot finish sales history;
subject UI cannot truthfully show a per-subject owned/absent badge from a directory or a link. **Seam:** Commerce
sales/entitlement owner, Content delivery, Accounts consent scopes, Web regions. **Correction:** deliver native
own-sales projection and registered exact scope; keep the ownership region as navigation until an adopted bounded
read exists. Do not add per-offer/per-card entitlement probes or expose buyer identities to fill a sales row.

### F10 — Local cleanup is real; complete irreversible erasure is explicitly unavailable

**Evidence:** `K/library/work-module.ts` registers retention and owner/Source workers. `erasure-owned-graph.ts`
enumerates sessions/logs/Collections/labels/index/support/preparation/custody families rather than only entries.
Nevertheless `K/library/erasure-participant.ts:25–44` lists unattributed historical fences, release-to-terminal
hold disposition, identity/control custody, bulk effects, curatorless listing history, shared receipt/outbox/work,
publication foreign actors and caches/exports/replicas/backups as incomplete. It explicitly cannot ACK, even with
no indexed local roots. T9 asserts retained public custody. Commerce's terminal benefit barrier is separate T19.

**Cause:** local purge or table-count zero was treated as whole lifecycle completion while foreign/shared custody
and late replay were unresolved. **Impact:** account deletion can fence access but cannot yet truthfully claim all
Library erasure obligations finished. Money reconciliation must retain required accounting without restoring a
deleted buyer's benefit. **Seam:** Accounts terminal protocol + Commerce Library/financial retention + Semantic/Core
receiving/history owners. **Correction:** exact owner locators, minimizer/disposition acknowledgements and late-item
fences; retain honest pending rather than delete proof blockers or turn no rows into a completion certificate.

### F11 — Mixed Home has reusable machinery but no evidenced upper-bound product composition

**Evidence:** `W/routes/index.tsx` reads a common public route page and separately queries private Continue;
`W/features/pages/home-queries.ts` preserves that privacy split. `packages/composition/src/{registry,reads,filter}.ts`
provides TypeList and common read planning. `K/search/README.md` describes actual mixed Subject/account registry,
summary discriminators and kind pagination. Its current whole-query Source still returns readiness. A shared

Current scope expressly defers feeds, recommendations and personalized rankings.

**Cause:** configurable per-type sections, mixed-search types and tiny home stories were accepted as a full home
design without defining an upper-bound bounded selection and navigation path. **Impact:** one section/tab per kind,
Realm or Context is impossible at the required quantities; merely adding more configured rows repeats the defect.
**Seam:** Web common page composition, Search mixed catalogue ordering, Semantic summary/configuration and Commerce
private Continue. **Correction:** propose one bounded mixed catalogue stream with optional compact curated modules,
one searchable/paged kind/scope selector and honest readiness. Preserve the public/private split and the explicit
feed deferral. No marketing tagline or new recommendation engine is needed.

### F12 — Evidence and documentation drift obscures both missing and delivered capabilities

**Evidence:** older cells in `D/research/design-status-commerce.md` still say labels/native copy FULL/generated

**Cause:** status fragments were appended without reconciling earlier claims, and source/test/recording/execution
