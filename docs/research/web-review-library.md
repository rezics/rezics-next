**The library is not ready for public launch.** Keep `personal_library`, `collections` and `reading_progress`
closed pending the work below and page review. This was a code/document review only; no application, browser,
screenshots or check host was run. `met` means a routed implementation reaches its owning API in source,
not that a deployed gate is open or a runtime review has passed.

All implemented flows below use the generated client (`packages/client/src/index.ts:21`,
`apps/web/src/kernel/client.ts:43`). Development can substitute recordings through `kernel/fake.ts`;
the `kernel/fake/*.ts` discovery hook (`apps/web/src/kernel/fake-modules.ts:52`) has no route modules in this tree.
There is no routed fake implementation filling the profile, dynamic Collection, label, count or restore gaps.

## Five gaps that most block launch

1. **Deletion loses recoverable facts.** Smallest complete fix: implement each existing delete's retained identity,
   authorized restore/deadline and bounded purge, then wire Undo/Restore on the existing pages. Start with entries,
   copies, occurrences and logs that still physically delete; Collection tombstones alone do not close this gap.
2. **The personal model is still hardcoded and has no labels.** Smallest complete fix: connect the resolved release
   profile to kernel admission and the existing state/copy/progress forms, add copy kinds, and expose the specified
   private label catalogue/assignment commands with a routed editor. Preserve old pins; do not invent web defaults.
3. **The library is not backed by built-in dynamic Collections.** Smallest complete fix: implement native bounded
   source/fact membership and lazy Everything/profile-state identities, then teach the existing Collection route
   the dynamic DTO. Reuse that source for shared operations; user-saved query creation remains deferred
   (`docs/dynamic-collections.md` → Saved-query language for the later runtime phase).
4. **The opening shelf lacks progress and remembered display.** Smallest complete fix: project progress through
   the owning API into the existing three layouts, reuse `ProgressRow`, remove tile surfaces, and persist display
   preferences to the account with URL precedence. Finish the remaining Shelves controls in the table before approval.
5. **The private release boundary and counts are unfinished.** Smallest complete fix: add shared library/closed
   noindex, implement authorized private target counts without identity disclosure, and consume the existing exact
   public Collection count with paging. Review the complete pages before opening their gate groups; do not infer
   approval from a working generated-client call or from robots.txt.

The recurring pattern is usable routed fixed-vocabulary operations around missing native protocols: components and storage
helpers cannot replace profile admission, membership, private counting or restoration. The recommendation is to
finish those owning APIs and adapt the existing routes and UI primitives, rather than introduce a second library
engine in web. All evidence and proposed changes are confined to this report; no implementation decision is adopted here.
