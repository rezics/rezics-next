# Public discovery, metadata and cache design

Inspected 2026-10-30–31 at `5827ec24a05f57299ea50343b540eb81bd849c54`.
This report covers the existing Web SEO scope in [scope](../scope.md), from native public sources through
crawler navigation and withdrawal. It is research evidence, not a new authority or evidence of passing native,
full-row or main checks. Source observations below describe this checkout, not deployed outcomes. The optional
backend design audit was unavailable at its specified local path; no conclusions depend on it.

The recommendation is to keep the existing offline exporter and public page architecture, finish the native
eligibility/publication producers, and join them to one canonical URL and disclosure policy. The largest gaps
are at those joins: the subject feed still returns 503, Collection SSR requests a session inside a public-cache
route, and mutable handle redirects are publicly cached. Existing serializers and feed adapters do not establish
that the complete system publishes only currently eligible public information.

## Standards that constrain the joins

Canonical, alternate and sitemap URLs must agree. Google considers redirects and `rel=canonical` strong signals,
and sitemap membership a weaker one; conflicting signals are avoidable. Hreflang sets must include self and
reciprocal alternatives. HTML and sitemap annotations are equivalent mechanisms; using both is REZICS policy,
so produce both from one URL mapping. Eight URL entries with eight alternate children mean 64 alternate elements,
not 64 counted URL entries, but all bytes count.
[Canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls),
[localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions).

Schema.org `ItemList` can represent a partial page, but `numberOfItems` describes the entire list and ordered items
need explicit positions. REZICS's complete export rule is stricter: do not turn a preview into a complete list.
Structured data must represent visible current page content; a supported class does not guarantee a rich result.
Published external links need actual identity semantics before becoming `sameAs`.
[ItemList](https://schema.org/ItemList),
[Google structured-data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).

HTTP `no-store` prevents cache storage/reuse; `private` alone only excludes shared caches. `s-maxage` governs
shared freshness. Sending a new no-store response does not itself remove an older cached representation.
Consequently current authorization and invalidation require explicit design; `Set-Cookie` is not a sufficient
cache exclusion rule. [RFC 9111, sections 5.2.2.5, 5.2.2.7 and 5.2.2.10](https://www.rfc-editor.org/rfc/rfc9111.html).

Robots disallow is not confidentiality and can prevent a crawler from seeing `noindex`. Removal depends on the
served current response, not just removing a sitemap entry. Temporary failures need truthful 5xx responses rather
than an indexable error page; search-engine removal is not instantaneous.
[Google noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing),
[HTTP statuses](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes).
Sharing consumers read the same public head: Open Graph defines title, type, image and canonical URL, with image
dimensions and alt text as structured properties. No independent private preview read is justified.
[Open Graph](https://ogp.me/).

### Withdrawal and restoration

The contract requires an anonymous page read to become 404 for unknown/hidden/removed/unreadable identity,
403 plus noindex for a platform-grant closure, and noindex for title-only or disallowed listing variants. The next
successful daily export removes ineligible URLs. A failed export deliberately preserves old discovery inventory.
It must never preserve permission to show a removed fact, private member, old profile or withdrawn image.

There is an unresolved owner-policy join: SEO says the live status changes at once, while the Web README allows
deleted/restored/withheld public HTML in shared cache for up to 60 seconds. Current warm hits/304s do not consult
the source owner. Decide whether the stated 60-second public staleness is the accepted exception, or whether
privacy/security reductions require a purge/version fence before reuse. Do not claim zero stale disclosure from
the existing TTL, and do not turn the daily sitemap inventory into a live ACL. Old immutable shard retention can
expose historical public URLs/times; its allowed retention is a separate artifact policy, not permission to keep
serving private payloads. Restoration needs fresh disclosure and the next successful inventory, without reusing a
negative permission decision indefinitely. These are cross-owner adoption decisions, not edits made by this report.

## Gaps by kind

### Missing design

- **Canonical inventory projection:** agree the existing subject-feed shape versus eligible view/profile families,
  original-language fallback and current verified handle. Also settle carried-Realm/Space canonical destinations.
  Web must not derive identity or page eligibility from stale labels, helpers or private profile reads.
- **Publication coverage:** Semantic's design is specific and reusable, but the complete rendered dependency list
  and coverage of every indexed view must be explicit. Commerce/Content/Community timestamps need a decision on
  public shown changes/removals versus their currently narrower header/activity clocks; unknown is omittable.
- **Cache withdrawal and aliases:** reconcile immediate live disclosure with the documented 60-second cache
  window, mutable alias no-store and invalidation of existing positives/negatives. Reconcile nonce/cache prose.
- **Metadata producers:** enumerate which existing public page fields can supply typed creator agent links,
  actual identity links, image and edition relations. Generated placeholder behavior versus the existing static
  card needs an owner decision within current scope. Do not add fields merely because Schema.org offers them.

### Missing runtime

- Subject public publication/repair/relay/worker assembly and the real `/v1/subject-pages` handler remain absent;
  the pending 503 currently prevents a successful all-feed sitemap replacement.
- Complete Collection source/canonical factories and their public generation integration remain unavailable;
  the existing public-header sitemap helper does not close that gap.
- Web feed mapping does not supply indexed subject views/agent canonical families. The robots fallback and
  current mutable-alias cache policy do not meet the recommended configured-origin/current-resolution boundary.
- Collection SSR explicitly selects a session inside the public route. Generic successful-HTML promotion needs
  a verified public-result boundary, especially for preparing/error and session fallbacks. These are source-level
  defects/risks identified for implementation, not observed native failures in this research attempt.

### Missing UI

- Collection filtered/unlisted variants need an explicit head policy tied to disclosed state; private curator
  controls and totals belong to post-hydration personal state. Keep public list completeness and no fake counts.
- General subject JSON-LD still needs the specified public creator/image/identity/edition projections where the
  owner actually supplies them. Existing recipe, class-selection and agent serializers should be extended, not
  replaced. Head/card output must follow the same privacy transition as visible text and media authorization.
- Crawler navigation must retain canonical links through existing full views and profiles, with later pages
  noindex. New search UI, Collection layouts or checkout features do not close these publication gaps.

### Missing proof
