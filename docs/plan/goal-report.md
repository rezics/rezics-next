## Qualified scope and rollout boundaries

The recorded run qualifies exactly the declared tests on the page above. These
boundaries remain explicit:

- **Performance.** By maintainer direction (2026-09-27) this first phase
  qualifies the main performance paths by measured checks: OPS05 (named host
  workload), SEARCH18 (search capacity) and REC02 (hot target) on the phase D
  medium fixture `fx-medium-c9f6e4fdcb52` (100,000 Works, 10,000 public
  MatchUnits), plus the multi-scale growth checks (SEARCH07, SEARCH10, relay
  batches, Event query caps). The remaining entry points rely on their written
  cost contracts and derivations. Full performance verification, an executable
  inventory of every entry point's contract, and the 500 million entity scale
  are later-phase work; see [complexity](../testing/complexity.md#inventory-and-coverage).
- **Mod provider acquisition.** By maintainer direction (2026-09-27), PKG09 and
  PKG11 qualify relation modeling from records authored in the CurseForge and
  Steam Workshop response shapes; live authenticated capture is skipped, and
  provider acquisition (crawler or another permitted surface) is still to be
  designed. The API-key capture paths remain an optional advanced-user
  configuration. PKG10 and the Modrinth, Nexus and Steam Collection surfaces
  are qualified from live keyless captures. See [packages](../testing/packages.md).
- **Physical destruction.** OPS10 reports suppression and physical destruction
  separately: the retired live Jena fileset is destroyed with evidence, while
  snapshot, backup and media copies carry an explicit unverified destruction
  status.
- **Second host.** IAM11 and OPS02 custody drills restore into a separate local
  cluster that represents a second host; they do not certify off-host custody.
- **Frontend.** Frontend, Storybook and browser acceptance are outside this Goal.

## How the program ran

- One Claude Opus 5.5 manager dispatched workers through `goalctl`. From about
  1:10 elapsed the maintainer moved most work to Codex CLI with GPT-6 Sol at
  `high` or `xhigh`; GPT-6 Luna and Grok 4.7 took bounded tasks. From
  2026-09-27 effort limits are per model and Luna runs at `max`.
- Shared hotspots were removed early: discovered model profiles, coverage
  declarations, receipt families, OAuth scopes, outbox handlers, projection
  recipes, structure profiles and a union-merged composition root with a
  normalizer.
- Integration waves exposed cross-merge regressions that repair tasks fixed
  (G-106, G-129, G-137, G-141, G-142, G-143). Docker's VM memory was raised from
  24 to 36 GiB after Fuseki was killed under load, and fault and integration
  files that reset shared graphs or assume a fresh database run in their own
  QA projects.
- Seven recorded runs led to the passing one. Each failure was a harness or
  measurement defect rather than a product regression, except OPS08's
  unhandled Account disconnect: run 1 had 17 failures (integration shard
  pollution, order dependence, stale model digests, Nix timing); run 2 the OPS08
  disconnect (G-144); run 3 a fixture cleanup timeout; run 4 29 declared tests
  that no tier executed (G-145 added a guard); run 5 OPS05's 20-second mix
  (G-146 made it a fixed-arrival measurement); run 6 an integration wall 4.9 s
  over budget from order-dependent reruns (G-148 removed the shared-state cause
  and serialized stack starts). The load tier budget changed from 3 to 5 minutes
  with its measured reason recorded in the [harness](../testing/test-harness.md#tiers-and-budgets).
- The forecast missed the 10-hour target: the last cross-owner cases (search
  joins and disclosure, Structure and Zone, erasure replay) and phase D
  isolation and timing repairs ran past it, inside the 25-hour bound.
