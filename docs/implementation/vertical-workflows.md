# Cross-owner workflow obligations

The owner commands and [acceptance cases](../../scripts/qa/cases/) carry the
implemented Work, Content, Context, source and search behavior. One successful
command from each owner does not prove a coherent cross-owner journey.

An ordinary Work journey must retain one Main Version while two Realms adopt
different eligible revisions; publication, body, media, search, discussion and
counts must resolve through the same context and current disclosure. A shared
Context journey must preserve independent personal and Realm interpretation,
exact meaning references and authorized adoption across a later revision.

Source refresh must compare captured source, base and native state without
overwriting same-value human control, recheck rights at activation and preserve
independent native decisions after withdrawal. Search must advance an index
watermark only after exact affected roots are reconciled; stale responses need a
coherent generation. Cross-owner recovery must reconcile receipts and heads
after lost responses and enforce erasure frontiers before reads reopen.

These coupled journeys require named integration or recovery cases with denied,
stale, concurrent and partial outcomes where the owner tests do not yet cover
them. Their exact owner commands remain in the respective modules and tests.
