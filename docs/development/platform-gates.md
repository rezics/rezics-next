The integration and QA stack opens every platform group through `REZICS_PLATFORM_OPEN_GROUPS`. Bootstrap writes `*` into that stack's environment after the databases are prepared. The exposure gate treats `*` the same way it would treat a `platform:use:*` grant held by every caller, so product tests are not each given a grant. Production preflight refuses the variable. The gate reads the process environment, and only when that variable is absent does an in-process QA server read the stack file bootstrap wrote. A request cannot supply the value. Tests that prove the gate itself pass an empty value, so they still show the closed default.

A closed operation answers 401 before any grant lookup when the caller has no bearer or the bearer is invalid, so a client can tell authentication from a missing grant. An authenticated caller without the grant still receives 403 `platform_closed`. GET `/v1/realms/{realm}/member-ban` and appeal reads keep one 404 (`appeal_unavailable`) whether the group is closed or the ban or appeal is absent, so the closed group does not reveal that a ban exists.
