## Outcome

Five integration files pass when run alone but fail in a batch, because each
assumes a fresh database: `g-832-lexicon`, `g-856-position`,
`post-search-disclosure`, `projection-by-frame` and `growth-search-context`
(all under `tests/qa/integration/`). After this task each one passes in the
same batch it failed in, run twice in a row on one project, and still passes
alone. Fix the test's own assumptions: scope its reads to the rows, Works and
Contexts it created (unique names per run, filters on its own IDs, counts as
deltas from a reading taken at the start). A test that truly needs an empty
population goes into `scripts/qa/isolated-integration-files.ts` with a
one-line reason, and only as the last resort, because that list costs a fresh
project per file.

Then the fault injectors and cost counters that still count background work
(listed in `.temp/manager/write-concurrency/cost-counter-audit.md`): change
those that live in `tests/qa/support/**` so that they count only the
foreground operation under test, following the pattern of the earlier fixes
named in that audit. If a counter you need to change lives outside your paths,
run `task goal -- owner <path>` and follow the worker protocol: make a
minimal change and list it under OWNER CHANGES when the file is unclaimed, or
propose it in the handoff when it is claimed.

## Read

- The five test files, and `.temp/manager/write-concurrency/mainwide/summary.log`
  plus `.temp/manager/write-concurrency/mainwide/p3-*.log` for the batches
  they failed in.
- `.temp/manager/write-concurrency/cost-counter-audit.md`.
- `scripts/qa/isolated-integration-files.ts` (what the fresh-state list is
  for).

## Do not

Change product code, weaken an assertion so that it no longer proves its
behaviour, or add retries or sleeps to make a test pass. A failure that turns
out to be a product defect goes into the handoff with its evidence.

## Checks

For each file: run it alone, then in a batch with the files it failed beside
(the same chunk from the summary log), twice in a row, all through
`task goal -- test --heavy <files>` (that takes the shared QA slot and the
heavy lock; never start a stack yourself). Report each file's before and after
result in the handoff, with the QA run IDs.
