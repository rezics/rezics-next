## Outcome

A test that fails in the regression fails because of the product, never because of the harness that ran it. The reading of the run on `main` d2a2e3166 (staged as `.temp/ref/regression-disposition.md`; search it for the cause's number) names four faults of the harness. Each is a step, committed when its test passes, in this order:

1. **A clone's removal ends no neighbour (D093).** `tests/qa/support/databases.ts` drops a test's database with `DROP DATABASE ... WITH (FORCE)`. In batch `integration-35` two relay backends were ended at 06:24:40 UTC after one file's clean-up, and the next file (`tests/qa/integration/continue-read-budget.test.ts`, which passes alone) failed with `terminating connection due to administrator command`. Find from the run's stack log and the code which connection of the next file was ended, and make the removal wait for or close its own clients first, so that a forced drop is never what another file sees. The test shows two clones on one server: removing the first while the second holds an open client and a listener leaves the second working.
2. **The QA database carries its declared fixtures (D092).** `tests/qa/integration/g-556-ranked-large.test.ts` ended with `out of shared memory` on a quiet host. Size the isolated QA PostgreSQL's lock memory in `scripts/qa/stack-environment.ts` from what that fixture takes (measure it once; say the numbers in the handoff), not by a guess, and keep the server's memory within what the QA slot accounts for.
3. **A socket path fits under any checkout (D039).** `scripts/goal/goalctl.test.ts:2401` and `scripts/goal/land.test.ts:213` stopped on `PostgreSQL socket path is <N> bytes, above the <N>-byte limit` when the checkout was a regression's own (`<checkout>/.temp/tmp/goalctl-unlanded-<random>/.temp/worktrees/g-<n>/.temp/pg-so...`). `scripts/goal/postgres-socket.ts` gives a worktree a socket directory whose path fits the limit however deep the checkout is (a short directory keyed by the worktree's path, removed with it), and still refuses with today's message when even that cannot fit. Do not change the two test files: they belong to other tasks; your test is `postgres-socket.test.ts`.
4. **Model maintenance gets the stack's configuration (D089).** `tests/qa/integration/model-custody-backfill.test.ts:219` fails alone with `Model maintenance requires a harness-owned stack configuration` (`scripts/datasets/model-bootstrap.ts:252`). The test calls maintenance as the harness now requires; the product's check stays as it is.

Do not build: a change to a product source, to `scripts/datasets/`, to a tier's budget or to the regression's selection, a retry that hides an ended connection, a fix for a cause the reading gives another Goal.
