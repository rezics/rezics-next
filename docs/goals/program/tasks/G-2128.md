## Outcome

The run on a pinned commit of `main` is the judge of the scope, and its report can be believed and afforded. Today a row counts as proved when its declaration says so, the run's classifier called 315 of 329 failures `deadline` when 7 had timed out, and its batches took 296 minutes. The survey staged in your worktree at `.temp/ref/regression-facts.md` has the code's shape and that run's figures; the run's directory can be read in the main checkout and never written.

Ordered steps, each committed when its tests pass:

1. **`deadline` means a timeout.** A failure is classed `deadline` only when its own output shows one: a test or a shard past its budget, or a kill by the runner. Any other failure is classed by its first error line. Show both on fixtures cut from the run named in the survey: three failures it called `deadline` that were not, and two that were.
2. **What the run confirmed.** A run records for every outcome test, by row and persona, whether it passed, in the run's directory and as the latest record in the state directory, with the commit and the time. `task goal -- scope` prints, for each vertical, the rows declared proved, the rows the last run confirmed and the rows it saw fail, with that run's commit and age; a row declared proved that the last run saw fail is named first. With no run yet it says so and prints the declared figures.
3. **What the run cost.** `task goal -- regress --timing <run>` prints from the run's records: wall, queue and test time by tier; the ten slowest batches and the ten slowest files; the time spent queueing and starting stacks; and the lanes it ran in. It works on the run named in the survey.
4. **The width the host has.** With no worker live a run takes as many lanes as there are QA slots; with a worker live it keeps the lane count of today. The count it chose is in its record.

Do not build: a timer or a schedule, an audit of proved rows, the reopening of a cell, a change to the batches' sizes, a change to `status` (another task holds its file), a change to memory admission.

## Decision — 2026-10-13

The program lends `scripts/goal/goalctl.ts` for the seventeen lines that route `scope` with no task and `regress --timing` to this task's code; no other task holds the file. The handoff was `partial` only because a guard this task did not touch ran out of its five seconds on a busy host; that guard has its own budget on `main` since.
