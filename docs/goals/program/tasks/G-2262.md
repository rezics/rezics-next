## Outcome

A surface's gate fails its tests and guards parts only for what the surface's own change broke. On 2026-10-13 a Library surface was returned `partial` for nine failures in QA harness tests it had not touched: seven were five-second timing tests that time out when the host runs seventy processes, one was a test `main` had been failing for seven hours, and one was a file `main` had gained after the branch's base. Its manager then asked which commits "repair" them. `runSurfaceGate` says why (`scripts/goal/surface-gate.ts`): "A failed part is final, including a failed story; no retry or baseline allowance." The unit gate (`scripts/goal/unit-gate.ts`) already has both answers for the same kind of file.

1. **A timed-out file is rerun alone.** In the tests and guards parts, a file whose only failures are timeouts is rerun alone with the unit gate's longer limit (`TIMEOUT_RETRY_MULTIPLIER`, the path `retryTimedOutFiles` takes). It passes the part when the rerun passes; the output names the file, the test and both durations, as the unit gate's "Timeout retry passed" line does.
2. **A failure `main` has does not charge the task.** A file that still fails after (1), and that the surface's change did not touch, is run once on `main` at the gate's base revision, the way the unit gate runs its `main` side. A test that fails there too is printed as a failure of `main` (file, test, revision) and does not fail the part. A test that passes on `main` fails the part as now. A file the change touched is never excused.
3. **Stories stay final.** No retry and no baseline for the stories part, the contract, types, lint or ast parts.
4. Use the unit gate's functions; do not copy them. Export what the surface gate needs. The evidence file records, per excused test, the reason (`timeout-retry` or `fails-on-main`) and the revision, so a reviewer of a landing sees what was excused.
5. The decision is made in code and tested without a stack: a test with a fake runner for each of: timeout then pass alone; timeout then fail alone; failure also on `main`; failure only on the branch; an excused failure in a file the change touched (refused); a story failure (final). The comment above `runSurfaceGate` says the new rule in one sentence.

Do not build: a retry of a story, a general "flaky" list, a change to which files a surface selects, a change to the unit gate's own decisions.
