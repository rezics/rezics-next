## Outcome

A worker cannot see its own worktree's stories rendered: the shared Storybook serves the main checkout, `task dev` is refused for workers, a static build cannot be opened, and a story test keeps no image. On 2026-10-11 four launch tasks ended partial on visual review alone, each costing a manager decision and one more session, and one worker committed its own screenshot helper into a story. Visual quality here is judged by eye from screenshots, so the harness has to hand the worker the picture.

Stories run as Vitest browser tests (`task storybook:test` and `task accounts:storybook:test`, `@storybook/addon-vitest` with the Playwright provider; `scripts/qa/test.ts` dispatches explicit `*.stories.*` files to them).

Build:
1. When `scripts/qa/test.ts` dispatches story files, it passes one environment variable naming a directory inside that run's artifacts (`.artifacts/qa/<run>/story-screenshots`), and creates the run directory and a `summary.md` line that names it, if a story run does not have them today.
2. With that variable set, every story that the run executes leaves one PNG of the viewport after its play function finished and its assertions passed or failed: `<story file path with slashes as dashes>/<story export name>.png`. A story that declares a viewport is captured at that viewport (the 390 px mobile stories keep 390 px); the others at the test's default. One place does it for all stories (the Storybook Vitest setup or a preview-level `afterEach`), not a helper per story.
3. Without the variable nothing is captured and nothing changes: plain `task storybook:test` and the browser baseline behave as today. A capture failure is reported as a warning line and never changes a story's result.
4. Both workspaces (web and accounts). File names are stable across runs; a second run of the same story replaces its file.
5. One sentence in `docs/goals/worker.md`, "Tests and checks": after `task goal -- test <story file>`, read the PNGs under the run's `story-screenshots` directory to review your own change by eye; do not add screenshot helpers to stories.

Tests: a unit test that the dispatcher passes the directory for story files and not for other tests; a unit test of the file naming; then the real proof: run `task goal -- test` on one web story file with two stories, one of them a mobile viewport story, and one accounts story file, and list the PNG paths with their pixel sizes in the handoff.

Do not build: visual comparison or baselines, a gallery page, uploads, full-page stitching, any change to which stories run or to their timeouts. `apps/web` and `apps/accounts` configuration is launch's area; this task changes only the Vitest and Storybook setup files named in its paths, with launch's consent (it asked for this).

## Mechanisms

none

## Checks

The unit tests and the real proof above in as few `task goal -- test` calls as the workspace rule allows (stories of one workspace per call), `task scripts:typecheck`, `task web:typecheck`, `task docs:check`. Hand off with the line `RESULT: done` exactly.
