## Outcome

Two gaps let regressions reach `main` on 2026-10-07 and stay there until
someone else's run found them:

1. **Repository-wide guards are not in the merge gate.** `goalctl merge` runs
   the unit files `--affected` selects for the branch. Guards that check the
   whole repository or the whole route inventory are often not selected, so
   they went red after merges: the SQL relation guard
   (`tests/qa/unit/g-1046-sql-relations.test.ts`) twice, the exposure
   inventory (`services/main/tests/platform-exposure.test.ts`), the list
   convention (`scripts/static/list-convention.test.ts`). Declare the set of
   repository-wide guards in one list (`scripts/qa/repository-guards.ts`):
   those four, the test registry (`tests/qa/unit/test-registry.test.ts`), the
   rate-limit inventory (`services/main/tests/g-543-rate-limit.test.ts`), and
   any other test you find that reads the whole route inventory, every
   migration directory or every source file (say which and why in the list).
   The merge gate always adds them to the branch's affected unit set, within
   the existing shards, budget and failure confirmation; they fail a merge
   only when the task introduced the failure, as for any file.
2. **Nothing type-checks the AppHost.** `apphost/apphost.mts` compiles under
   Node's types (`apphost/tsconfig.apphost.json`) and imports
   `services/main/src/config.ts`; a `Bun.file` call in a module reachable from
   there stopped the shared dev stack from starting (fixed in d27788c4a). Add
   an AppHost type check to the static gates run by `task check` and
   `task check:backend` (in `scripts/research/storage_architecture/check.ts`),
   and a Task command for it, recorded in `docs/development/toolchain.md` via
   `python3 scripts/documentation/toolchain_inventory.py --write`.

Update the merge row in `docs/goals/README.md` in one sentence.

## Read

`scripts/goal/goalctl.ts` (`preMergeUnitGate`, `mergeUnitFiles`,
`failingTestFiles`), the guard tests named above, `apphost/apphost.mts`,
`apphost/tsconfig.apphost.json`, `scripts/research/storage_architecture/check.ts`.

## Do not

Change the guards themselves, the affected selection, the shard or budget
logic, or the AppHost; add a second gate.

## Checks

Unit tests: a branch whose affected set lacks a guard still runs it; a guard
already failing on main is reported, not blocking. Show that the AppHost type
check fails on a planted `Bun.file` in a module `services/main/src/config.ts`
imports and passes on the real tree. `task test -- scripts/goal/goalctl.test.ts
tests/qa/unit/repository-guards.test.ts`, `task check:backend`, and the type
check covering `scripts/goal`.
