## Outcome

G-2248's completion qualification (QA `20261015t190804-a24af0`) failed while cloning the retained PostgreSQL template: the template recorded collation version 2.41 and the host's collation library is 2.43. The handoff is `.temp/ref/collation-handoff.md`. Every retained PostgreSQL source built before the host's glibc changed fails the same way, which blocks the physical erasure campaign and any confirmation that restores retained data.

PostgreSQL's documented remedy after a collation-library change is to rebuild the affected indexes and then record the new version: `REINDEX` in each copied database, then `ALTER DATABASE … REFRESH COLLATION VERSION`, and the same for the template where it is reused.

In the retained-source restore path (the copy or clone of a retained PostgreSQL template, for every adapter), detect a recorded collation version that differs from the host's. Do this on the disposable copy only:
- rebuild its indexes;
- refresh the version;
- report it in the restore evidence;
- then continue.

The published source and its manifest stay unchanged. Find out where the template was built with the older library (a container image or the host before an update). If producer and consumer can share one collation environment, make them do so, and say what you chose and why.

Prove it with a test that restores a template whose recorded version differs from the host's, then run G-2248's completion qualification command once to show the clone succeeds.
