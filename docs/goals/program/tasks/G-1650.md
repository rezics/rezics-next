## Outcome

Today `assertWorkCostAtScales` in `tests/qa/support/work-profile.ts` only re-applies the same absolute caps at every scale, so a counter that grows linearly under its cap passes. Make it compare growth with a declared class.

1. A cost contract may declare, per counter, a growth class and the dimension it grows with: `constant`, `logarithmic`, `linear` or `linearithmic`. A counter with no declaration keeps today's behaviour (absolute cap only), so existing callers pass unchanged.
2. `assertWorkCostAtScales` takes each profile's scale value for that dimension and, for every pair of scales i < j, requires `W(j) <= 1.20 * W(i) * f(n_j) / f(n_i)`, where f is `1`, `1 + log2(n)`, `n` or `n * (1 + log2(n))`. A counter that is zero at the smaller scale must stay zero. The margin is one named exported constant. The absolute caps still apply.
3. A breach throws an error that states the counter, the dimension, both scales, both values, the allowed ratio and the observed ratio. When `REZICS_QA_ARTIFACT_DIR` is set it also writes the same facts as one JSON file there, named by the label the caller passes.
4. Unknown evidence (a counter that was not observed) fails a declared class, as it fails a cap today.

Smallest change: one type, one function body, one small writer. No registry, no new module, no change to how profiles are collected, no wall-clock counters.

none

## Checks

- `tests/qa/unit/g-1024-work-profile.test.ts`, with synthetic profiles at scales 4, 16, 64:
  - a constant counter passes as constant; a linear one passes as linear and fails as constant and as logarithmic; a quadratic one fails as linear and as linearithmic; an `n log n` one passes as linearithmic and fails as linear;
  - zero then non-zero fails; an unobserved counter fails a declared class; a counter with no declaration behaves as before;
  - the breach message and the JSON artifact carry the facts in item 3.
