## Outcome

A shared owner does its job without recognising a vertical or a source (`docs/product/platform-thesis.md`; `docs/architecture/shared-capabilities.md`, Source adoption and credit, first paragraph). The audit evidence is in `.temp/ref/` (report-2.md, report-3.md).

Source adoption consumes Open Library's conversion shape. Proposals assume Book; child correspondence knows only authors and subjects; synopsis application and native title and field control require the Open Library mapping; intake embeds that provider's capture validation and rate schedule. Make conversions expose verified mapped values, types and child occurrences independently of provider, and make adoption, correspondence, field application, control, withdrawal and recovery consume them through the existing field support machinery (`source/support-attach.ts`). Keep URL and key decoding in the Open Library adapter and parameterise the rate gate.

Likely files: `services/main/src/modules/source/{native-work-proposal,child-correspondence,field-application,field-control-native,intake,provider-identity,support-attach}.ts`, `work/title-control.ts`, `routes/sources.ts`, `routes/source-supports.ts`.

Prove it with a test that fails before and passes after, on the real composition (`composeMain`), using a consumer other than the original one. Preserve exact versions, order, unknown authorship, truthful credit, rights evidence, private, refused and revoked states, idempotent recovery and bounded cost. Do not add a second engine, a framework or a per-vertical replacement, and do not move or rename a special case. Keep provider parsing and domain arithmetic in adapters. When the repair lands, remove its paragraph from `docs/architecture/shared-capabilities.md` in the same change, or narrow it to what remains.

## Design note

Writers: proposal, adoption, field application and control commands; they write the same Source support rows and native graph state as now. Readers: Source comparison, support reads and Work header reads, which see the same values for Open Library. Each still passes because the Open Library adapter now produces the provider-neutral evidence the owners consume.

Proof: A second provider (Bangumi or VNDB evidence already admitted in fixtures) adopts a Work, a child occurrence and a synopsis field through the same routes, and the existing Open Library cases stay green.
