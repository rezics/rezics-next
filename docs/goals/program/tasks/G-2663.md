## Outcome

On 2026-10-15 a wave/2 confirmation was killed at about 15:15 UTC while it built the retained Realm discussion source. The next confirmation (`confirm-20261015t151635-2863ad`) reused the same checkout path. `tests/qa/integration/outcomes/realm/ranking.test.ts` then failed in 2.4 s:

> retained source rs-realm-discussion-source-e1964525… refused: complete manifest is missing or unreadable

The boundary was `verify-existing`, in `scripts/qa/retained-source.ts` (`verified`, about line 296). All six ranking cells were reported missing, and the wave/2 merge waited for a rerun.

Refusing is right. Leaving that state behind is the fault: a build that is killed must leave nothing that looks published.

- A producer builds into a pending location and publishes with an atomic rename only after its manifest and backup are complete and verified.
- Under the key's lock, a pending or unmanifested directory whose producer is no longer alive is removed and rebuilt, with the reason reported. A live producer's directory is never touched.
- This applies to every retained-source producer, not only the Realm discussion source.

Prove it:
- a producer killed at each phase, then a fresh run that rebuilds and passes;
- a concurrent waiter that never sees a partial directory;
- a live producer whose work is never removed.
