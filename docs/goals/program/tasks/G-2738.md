## Outcome

Main's confirmation `confirm-20261017t020055-85e470` failed one cell. In `anime/anime-manga-and-vn-hub-parts-wholes-and-relations.test.ts`, the stranger persona's `POST /v1/query` to Main got `ECONNRESET`, "The socket connection was closed unexpectedly" (`.temp/ref/anime-reset-integration.log`). Main kept running: the later personas passed and its relay stopped normally. That cell was the run's first batch, which starts under the most load. The stranger test took 11.4 s.

Main listens with `app.listen({ hostname, port })` in `services/main/src/index.ts` and sets no idle timeout. Bun's default closes a connection whose request has not answered within 10 seconds. Confirm or rule out that this reset a slow request. In an earlier run, the same row's setup got `AccountAssertionUnavailable` from Main's call to Accounts (`.temp/ref/anime-account-unavailable-integration.log`), which may be the same class between services.

A slow request must end with an HTTP response within its deadline: a result, or the API's error for an unavailable dependency. It must never end with a reset socket. Apply this to every service the API composition runs (Main, Accounts and their server-to-server clients). Keep the change to server and client timeout configuration plus the error mapping it needs. Do not add retries around resets, and do not raise test budgets.
