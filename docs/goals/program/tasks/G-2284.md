## Outcome

No outcome test fails in its preparation because the host is busy, and no test file is edited for it. The staged `.temp/ref/preparation-write-inventory.md` lists about five hundred writes in `beforeAll` blocks and fixture builders of the outcome tests that demand the final status from the first answer. A compound write the API has not finished answers 202 with `pendingOperation`, and `tests/qa/support/settled-write.ts` (on `main`) reads such a write to its end; the Recipes builders use it by hand. Doing the same at five hundred sites, in files that forty tasks claim, is not the way.

1. **One place.** A persona's `main` call (`PersonaSession['main']`, built in `personaSessions()` of `tests/qa/support/personas.ts`) goes through `settledWrite` when no persona proof is running, and is untouched while one runs. `outcomeTest` in `tests/qa/support/outcome-test.ts` already knows when a proof is active (the recorder refuses a sample outside one): it enters and leaves a phase kept in `tests/qa/support/proof-phase.ts`, and nothing else decides the phase. Inside a proof the first answer is what the proof receives, as now.
2. **A preparation that wants the pending answer says so.** A call may opt out with an explicit option for the test that prepares a pending state on purpose. Search the outcome tests for preparation that asserts or stores a 202 and list each in the handoff (file, line); do not edit them: if any exists, the default for that call stays as now and the program routes the edit to the file's holder.
3. **Only a reconciling write is followed.** GET, a refusal, a 5xx and a 202 without a valid `pendingOperation` (the Agent provision's own pending body, which `provisionedAgent` handles) pass through unchanged. The bounds are the helper's.
4. Decided in code and tested without a stack: outside a proof a 202 reconciling write is followed with one key; inside a proof it is returned at once; nested and concurrent proofs keep the phase right; the opt-out; a GET and a refusal pass through.
5. Run the outcome tests of three verticals of your choice that prepare with compound writes (Recipes among them) and give in the handoff, for each: pass or fail, seconds, and how many preparation writes were followed.

Do not build: an edit to any outcome test or fixture builder, a retry of anything but a reconciling write, a longer limit, a change under `services/`.
