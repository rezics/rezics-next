## Outcome

Retained test sources (`scripts/qa/retained-source.ts`, `producerModules()` and each adapter's specification, for example `tests/qa/support/realm-discussion-source-runtime.ts` and the owner-erasure fixture) key their data by digests of the producer's transitive imports. Those imports reach orchestration tooling: changing only `scripts/goal/config.ts` changed the owner-erasure key from `7a2197cc…` to `5a242e29…` (G-2248) and invalidated published custody. Every goalctl change today therefore forced rebuilds of retained sources, which take minutes to tens of minutes each, or produced refusals that workers then diagnosed.

Make each key cover only what determines the produced data: producer code, the services and schemas it writes through, migrations, images, options and corpus inputs. Exclude orchestration tooling (`scripts/goal/**`, QA harness admission and scheduling code) through one explicit, tested rule, not a list per adapter. A change to excluded code never changes a key. A change to any included input still does.

Prove it with tests: a goalctl-only change keeps every adapter's key, a producer or schema change changes it, and the rule names its excluded roots. List the adapters checked. Coordinate nothing with G-2668 beyond rebasing; it investigates a different refusal.
