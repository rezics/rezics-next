## Outcome

A task of kind `surface` lands on types, unit tests and its row's stories, run together, and on nothing a model reads. Today `task goal -- check` runs a brief's listed tests and the guards with no notion of a surface (`scripts/goal/check.ts`), the landing runs types and the unit gate (`scripts/goal/merge.ts`, `scripts/goal/unit-gate.ts`), and the affected plan leaves stories out (`scripts/qa/affected.ts:69`): a surface could land with a broken story. The design note (staged as `.temp/ref/surface-design-note.md`, section 5) was read by the program on 2026-10-13. On the same day three parts of the API path passed alone and failed together, so this gate is proved as one path.

1. **One selection, in `scripts/goal/surface-gate.ts`,** used by `check` and by the landing: for a brief of kind `surface` it requires `rows:` naming rows declared proved on `main` (`scripts/qa/cases/outcomes.ts`), and in `tests:` at least one `*.stories.tsx` and the unit tests of the files changed; it refuses with one line for each thing missing. A row whose record is absent under `tests/qa/fixtures/outcomes/<vertical>/<row>.json` is refused too (another task writes the records; here the file's presence is the check).
2. **What runs,** in this order, stopping at the first part that fails: the contract is generated as the landing does; the web workspace's types; lint and the AST rules of the changed directories; the named unit tests and the repository guards; the named story files only, through the existing route (`scripts/qa/test.ts:67` sends story files to `task storybook:test`) in one QA slot. Never the whole Storybook, a web build or a browser journey.
3. **`check` and the landing give the same verdict** from the same selection; the landing runs it on the candidate rebased onto `main`. Each part prints its wall seconds and its seconds waiting for a slot, and the landing's evidence file keeps them.
4. A brief of another kind is untouched by all of this.

Do not build: a change to dispatch or to a brief's validation at dispatch (another task holds those files), the recorder or the replay, a screenshot comparison, a retry of a failing story, a change to the unit gate for other kinds.
