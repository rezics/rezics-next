## Outcome

`docs/architecture/content-adoption.md` (decided 2026-10-14) changes the Recipe model before Recipes open publicly. Its decision 4 asks for an inventory first. Find which Recipe data must survive the change, and which can be rebuilt by reimporting retained sources.

Read through the owners' public or operator read paths, never by writing. Use the shared dev backend (`task urls`), and a consistent backup with an isolated restore if direct inspection is needed. Inventory:

- owned Recipe drafts and publications;
- source supports and their withdrawal state;
- exact revision pins held by other resources;
- recorded answers and fixtures that embed Recipe payloads;
- the retained import corpora, including the thirty Gutenberg recipes.

Classify each item as rebuildable by reimport, or as needing conversion, and give the reason. Add a short section "Existing data inventory (2026-10-14)" to `docs/architecture/content-adoption.md` with counts and the classification. Write no product code; any scripts stay under `.temp/`.
