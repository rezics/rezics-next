## Outcome

`scripts/goal/regress.ts` adds a git worktree under `~/.cache/rezics-r/<repo key>/` for the pinned commit and for every bisect probe, and installs dependencies in each. Nothing removes them.
- 507 checkouts of about 2 GB each have accumulated since 10-07, and `git worktree list` shows 547 entries.
- The disk is at 77%.
- The class: a run's own checkouts outlive the run.

1. **At the end of a run.** When a regression run reaches a terminal status, it removes the checkouts its `checkouts.json` maps, then prunes their git worktree metadata. Use `git worktree remove --force`, then `git worktree prune`. The statuses are complete, failed and interrupted-but-not-resumable; a run that can still be resumed keeps them, and `--resume` recreates missing ones as it does today.
2. **Prune for the rest.** Add `task goal -- regress --prune-checkouts`, a dry run unless `--apply`. It removes checkout directories under the cache root that no run in `.temp/goal-orchestration/regress/*/checkouts.json` with a non-terminal manifest maps. Only paths inside the cache root, and only registered worktrees of this repository (`git worktree list --porcelain`), are touched. A running run's checkouts, like run 7's `20261009t175228-7b8d47` today, are always kept. That run holds the run lock; check how regress detects a live run.
3. Run the dry run on this host and put its counts in the handoff: kept with reason, removed, and bytes where cheap to measure. Do not apply; Program applies.

The checkouts are owned by the run that created them. Never remove a directory that no run's checkouts.json names unless it is a registered worktree under the cache root. List anything else.

## Checks

- `scripts/goal/regress.test.ts` covers four cases:
  - a finished run removes exactly its mapped checkouts;
  - a live run's checkouts are kept;
  - a resumable run keeps its checkouts;
  - prune ignores paths outside the cache root and non-worktrees.
