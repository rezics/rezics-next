## Outcome

`task test -- --affected [<base>] --list` and `task goal -- test --affected --list` print the plan at once, whatever the test slots hold. Today both pass through `withSlot` before `scripts/qa/test.ts` reaches the early exit of its list (`scripts/goal/goalctl.ts:153`, `case 'test'`; `scripts/goal/admission.ts:136`), so a command that starts no stack and runs no test waits for one of the eight ordinary slots and then holds it. At 16:22 UTC on 2026-10-13, with eight of eight slots held, five of the seven commands waiting for a slot were `--affected --list`; three earlier ones (the second efficiency audit) took 23 to 37 seconds each.

1. A list-only plan is recognised where the slot is taken, by the same argument rule `scripts/qa/test.ts` applies (`--affected` with `--list`, `scripts/qa/test.ts:134` to `147`); do not copy the parsing, share it. It runs with no slot, no waiter record and no memory admission, and its output and exit code are what they are today.
2. Everything else keeps its admission: `--affected` without `--list`, explicit paths, `--heavy`, wide runs.
3. Tests in `scripts/goal/admission.test.ts`: with every slot held, the list-only plan completes and writes no waiter record; `--affected` without `--list` still waits.
4. Show it once on the real checkout: run `task test -- --affected --list` while `task goal -- slot --holders` (or the status line) shows the slots full, and give its seconds in the handoff.

Do not build: a change to how the plan is computed, a cache of plans, a new slot class.

`task goal -- check`. Wait on a running command with one long call (`yield_time_ms: 300000`).
