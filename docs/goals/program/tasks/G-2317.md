## Outcome

A test that runs slowly never sends Main a token the Account service has already ended. Today it can: an access token lives 300 s (`services/account/src/auth.ts`, `accessTokenTtl`), and in two scheduled runs on a loaded host a preparation answered 401 `invalid_account_assertion` at about 308 s on the platform-access route, and two member reads answered 401 `account_assertion_denied`.

1. `LocalOAuthSession` counts a token's life from before its request was sent, at sign-in and at renewal, never from after the answer arrived.
2. `current()` renews when less than a default margin remains (30 s), so a request that takes seconds to leave and arrive carries a living token. A caller may still pass its own margin. Concurrent callers share one renewal, as now.
3. `tests/qa/fixtures/platform-grant.ts` keeps the session and takes `await session.current()` for each request; it no longer keeps the token as a string for the whole preparation.
4. `tests/qa/unit/oauth-client.test.ts` proves 1 and 2 with an injected clock: an exchange that takes ten seconds, a call 280 s after the request was sent, a call at 269 s, two concurrent calls inside the margin.
5. The handoff lists every other place under `tests/qa` and `scripts/qa` where a fixture or a helper shared by several tests keeps `.accessToken` as a string and can use it more than a few seconds later (file, line, how long it can be held), as proposed work; a test that takes the token and uses it at once is not listed.

Do not build: a change under `services/` or `apps/`, a longer token life for tests, a retry on 401, a change to `tests/qa/support/personas.ts` (another task holds it; it already calls `current()`).
