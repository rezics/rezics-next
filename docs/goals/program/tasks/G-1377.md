## Outcome

The first slice of the orchestration plan from research G-1369 (the report is in
your worktree at `.temp/ref/report.md`; read its "Recommended ownership" and "First
slice" sections). The aim is that managers stop keeping messaging and wake-ups alive
inside their own sessions.

1. **Durable Goal mail.** `task goal -- mail send <goal> --file <path> --key <retry-key>`,
   plus `mail inbox` and `mail ack <id>`. Use local SQLite with `synchronous=FULL`
   under `.temp/goal-orchestration/`. A message gets a stable ID only after commit;
   the same retry key returns the same ID. Each Goal acknowledges separately, and
   unknown Goals are rejected. Show existing `messages/<goal>.md` content and the
   regression inbox through the same `mail inbox` view without acknowledging
   anything. Messages are requests, never permissions.
2. **Supervised wake pump.** `task goal -- coordinator` runs in the foreground; a
   systemd user unit template (`goal-coordinator.service`) supervises it. It
   persists due wake-ups and rescans on start and periodically. It coalesces mail
   and task-exit events per Goal and starts at most one headless resume turn per
   enrolled manager, with backoff on quota or crash.
   - Commit a launch token before starting a resume through an independent tmux
     server, so a crash between launch and registration is reconciled, not
     duplicated.
   - Never resume a native session that a live interactive process still owns.
   - Restarting the coordinator must not kill workers dispatched by a manager.
   - Keep each engine's model, effort and account home exactly as goalctl
     launches them today.

Prove it on a **throwaway Codex session** created for the test, never on a live
manager. Enrolling a real manager is a manager handover I will do after review.
If the safe session handover or independent launcher cannot be shown within the
day, ship item 1 only and report item 2 as incomplete. Do not fall back to typing
into terminals.

## Checks

Unit tests with synthetic executables:
- concurrent senders;
- a retried send after a lost response gets one ID;
- two Goals keep separate unread state;
- a coordinator crash before and after launch;
- a live prior attempt blocks a duplicate resume;
- an acknowledgement lost and retried;
- a due wake survives a restart;
- worker and QA paths are unchanged.

Then the real trial: send a sentinel to the idle throwaway session, show it
answers and acknowledges, kill the coordinator, send again, restart it, and show
the second sentinel is delivered once. Report what the systemd unit needs from the
maintainer: the host has `Linger=no`, so user units stop at logout.
