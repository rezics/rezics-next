## Outcome

Cursor sessions drop mid-run, usually 40 minutes or more in. The attempt's `.err` then ends with a line such as `RetriableError: Connection stalled repeatedly` or `RetriableError: [internal] HTTP/2 keepalive ping timed out after 5000ms`, there is no result, and the worktree is dirty. Today a manager notices, saves the tree by hand and runs `resume --fresh`. Launch had four of these on 10-10; program and kernel had more.

1. When `goalctl wait` sees an attempt end this way (no result, and the engine's error output ends in a transport error), it starts the next attempt itself, in a fresh session on the same engine and effort, and keeps waiting. The message to the new session says the previous session lost its connection, lists the uncommitted files the worktree holds (or says it is clean), and tells the worker to review them, commit what stands, and continue the brief.
2. At most two automatic continuations in a row for one task. After that the task is left `exited` as today, and `wait` and `status` say it stopped after repeated transport errors.
3. Only transport errors continue. A quota, limit, authentication or any other error leaves the task `exited` as today. Keep the transport patterns in one named list beside the engine definitions.
4. `status` shows how many times a live task continued by itself.
5. goalctl never commits for the worker.
6. `docs/goals/worker.md`: the sentence about committing says to commit each step as soon as it stands, because a session can end without warning and the next session only sees what is in the tree. `docs/goals/manager.md`: one sentence, where it describes waiting on workers, that a dropped session continues by itself twice and what a manager does after that.

## Mechanisms

none

## Checks

- `scripts/goal/goalctl.test.ts`, with the test file's existing fake engine:
  - an attempt that ends in a transport error is followed by a new attempt whose message names the dirty files, and the task ends normally when that attempt returns a result;
  - three transport errors in a row leave the task `exited` after two continuations, with the reason shown;
  - a quota error and an ordinary failure start no new attempt.
- `task goal -- test scripts/goal/goalctl.test.ts`, `task scripts:typecheck`, `task docs:check`.
