## Outcome

The host's umask is 077, so `git worktree add` (task worktrees and the pinned checkouts of `confirm` and `regress`) creates files with mode 700 or 600. Under Docker Desktop, file sharing hid this. Under the native engine (since 2026-10-14), containers read bind mounts with their own users. `infra/dev/compose.yaml` mounts `./postgres/00-owners.sh` and `./toxiproxy/config.json`, and the PostgreSQL entrypoint (uid 999) cannot read a 700 init script. On 2026-10-14, all 12 started lanes of confirmation `confirm-20261014t121257-5281e0` failed with `postgres-1 exited (1)`, and G-2523 had to chmod a worktree by hand.

Make QA and dev stack startup independent of the checkout's file modes. Before Compose starts, stage every file the Compose files bind-mount into the stack's own directory (`.temp/stack/<project>/`) with an explicit mode (0644, or 0755 for scripts), and point the mounts at the staged copies. Alternatively, set the needed read bits on exactly those files and nothing broader. Derive the list from the Compose files, so a new bind mount is covered automatically. A test creates a checkout under umask 077 and asserts that the staged mounts are readable by other users. One real QA run from a worktree created under umask 077 must pass.

The interim measures stay until this lands: `UMask=0022` in the coordinator's systemd drop-in, and modes repaired by hand in existing trees.
