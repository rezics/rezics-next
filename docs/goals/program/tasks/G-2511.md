## Outcome

The web Realm creation, directory and ranking surfaces built on wave/1 list requests that no record holds yet. For every request below, make the named row's outcome test send it for each persona, exactly as production sends it (client, `actingSubject`, body), with the label the story looks up. Read the story inputs that list the requests as the specification. Change no assertion, no cell and no existing sample's label or request, and write no answer by hand. An empty, error or continuation state is produced by the test arranging that state through the API, never by editing an answer. If a state cannot be produced through the public API, name it in the handoff.

- `missingRecordedStates` returned by `apps/web/features/communities/creation-story-inputs.ts` (the create-a-Realm command, the preference read and the reads it lists; row `realm/create-a-realm`). G-2444 records that row's production requests at the same time: rebase onto its push and add only what it lacks.
- `missingRecordedStates` returned by `apps/web/features/communities/directory-story-inputs.ts` (the Realm directory; row `realm/closure-directory` and the directory row it names).
- The ranking states in `apps/web/features/realm/ranking-contract-states.ts` and `apps/web/features/realm/ranking-module-contract-states.ts`: Best/all and Top/week/month/all, persona-bound continuations, admitted private history, ordinary missing, empty, refusal, moved and unavailable answers (rows `realm/ranking` and `realm/closure-rankings`).
