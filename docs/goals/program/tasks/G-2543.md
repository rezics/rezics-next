## Outcome

`task goal -- job` (G-2528, `scripts/goal/job.ts`) works for most jobs: about 50 on 2026-10-14, 17 parked and woken correctly. Three ended with "command owner exited without recording a result":

| Task | Job | Command | Owner cgroup |
| --- | --- | --- | --- |
| G-2540 | 2139ad66 | `docker image inspect rezics/fuseki:… --format ""` | `app.slice/run-p1736098-i1629720.scope` |
| G-2540 | 5e2ace10 | `task goal -- check --only types,lint,guards` | `app.slice/tmux-spawn-6a67f639….scope` |
| G-2541 | 5be8c1b4 | `task -t .temp/image-build-measure.yml run` | `app.slice/run-p2160391-i2176720.scope` |

In all three the job's log is 0 bytes, so the executor (`job.ts --run`, spawned detached with `stdio: 'ignore'`) died before its command wrote anything, or before it spawned it. Jobs from the same process groups worked. The kernel logged no out-of-memory kill, and program's own guards do not kill job processes. Records are in each worktree's `.temp/goal/jobs/jobs.sqlite`.

Find the cause and repair it. Candidates:

- the worker's turn-end cleanup (`stopTurnProcesses`, settlement reaping or the launcher) killing processes that remain in the turn's session or process group;
- a race between the executor reading its record and the parent's transaction;
- an exception in `executeJob` before `spawn`, made invisible by `stdio: 'ignore'`.

Make failures visible regardless of cause. The executor writes a start marker and any uncaught error to the job log, and the owner records an exit signal if it is killed. If cleanup is the cause, start the executor outside the turn's cleanup scope (for example its own `systemd-run --user --scope`, or exempt it by identity). Add tests for the cause you fix and for the failure record. Then run 20 parked jobs of 30 s each while the worker turns end, and show that every one is woken.
