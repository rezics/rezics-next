## Outcome

G-2576 (`1e4adbc14`) found that Chromium cancels in-flight requests with `net::ERR_NETWORK_CHANGED` whenever the host's network changes. Since 2026-10-14 QA runs on native Docker Engine, so every QA stack that starts or stops adds or removes host network interfaces. Web Storybook now loads static assets through Node HTTP. Two other Chromium users on this host are still exposed:

- the Playwright browser journeys (`apps/web/tests/*.e2e.ts`, run through `task goal -- test`), which the wave/2 launch-coverage journeys depend on;
- Accounts' Storybook tests, which G-2576 proposed.

Make both survive a network change, either by the same transport as G-2576 or by a Chromium launch setting that stops it reacting to interface changes on a host where nothing leaves loopback. Prove it: run a journey and an Accounts story while QA stacks start and stop, reproducing the cancellation first if you can, three runs in a row clean. Apply the setting where every Chromium launch gets it, not per test.

## Checks

The reproduction, three clean runs and `task goal -- check`. Hand off the cause and the setting.
