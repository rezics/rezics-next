## Outcome

A worker and a manager turn hold only what they use. A Codex session takes its MCP servers from its account's `config.toml`; the main account's lists four (`playwright`, `outline`, `node_repl`, `browseros`), which the maintainer uses in his own sessions. On 2026-10-13 at 15:45 UTC, with 27 workers live, 27 sessions each held a Playwright MCP server (`npm exec @playwright/mcp` and its node process, 4.5 GiB together) and a `node_repl` (1.5 GiB), while six QA runs waited for memory on a 62 GiB host. No worker of that day called one of them, and each server's tool descriptions are sent with every request of the session.

1. `launchCommand` (`scripts/goal/launch.ts:33`) starts a Codex worker, a resumed worker and a manager turn with no MCP server from the account's configuration, by `-c` overrides on the command line and not by editing a file under `~/.codex*` (those are the maintainer's). Find the override the installed `codex` accepts from its own help or documentation, and prove it once by hand: start `codex exec` with the override on a prompt that asks the session to list its tools, and give in the handoff the tools it lists and that no `playwright-mcp` process was started (`pgrep -f 'playwright[-]mcp'` before and after).
2. A brief can ask for a server: an optional frontmatter line `mcp: [name]` is not built now. Say in the handoff where it would go; do not build it.
3. `scripts/goal/launch.test.ts` asserts the override on a fresh start, a resume and a manager turn's arguments, for both accounts. One sentence in `docs/development/toolchain.md` where the worker launch is described.
4. Give in the handoff the input tokens of the first request of a session with and without the override (the tool descriptions' size).

Do not build: a change to any file under a home directory, a change to the Claude launch, a new configuration file, the `mcp:` brief field.
