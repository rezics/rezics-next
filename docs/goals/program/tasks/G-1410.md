## Outcome

1. **Long-test shards.** The unit gate gives every shard the same wall-clock
   budget, `GOAL_UNIT_GATE_BUDGET_MS` (default 12 minutes; `goalctl.ts`
   around line 1890). `infra/jena/tests/semantic-source-readiness-union.test.ts`
   declares a 910 s test timeout (line 206). Under contention it cannot finish
   inside a 720 s shard. On 2026-10-07 this made the gates for G-1351 and G-1401
   inconclusive twice each, including G-1406's rerun. Fix the contradiction:
   - Read each selected file's declared per-test timeout: the numeric last
     argument of `test(...)` or `it(...)`, or `setDefaultTimeout`.
   - Run a file whose longest declared timeout plus 60 s exceeds the shard
     budget in its own shard, with a budget of that timeout plus 60 s. Every
     other shard keeps the default.
   - Keep one overall ceiling: the sum of wall time across concurrent shards is
     not the limit, but the slowest shard is.
   - If a declared timeout cannot be parsed, the file gets the default budget
     and the gate logs the file name.
2. **Refusal reason.** `task.state = 'conflict'` is set for rebase conflicts,
   composition and migration refusals, gate failures and baseline errors
   (around lines 2752-2812 and in the gate-failure branch of merge). It records
   no reason, so `status` shows a gate failure as a "conflict". Add an optional
   `refusal` field to `Task`. Set it to the first line of the returned or thrown
   message wherever state becomes `conflict`, clear it when the task leaves that
   state, and show it in `status` output.

3. **Generated artifacts.** `gen:check` (`bun scripts/generate.ts --check`,
   3.4 s) runs only in the regression (`scripts/goal/regress.ts:287`). So on
   2026-10-07 launch's G-1387 merged a new public operation with stale
   `generated/openapi/main/{public.json,exposure.ts}`, and kernel fixed it
   later. Run it in every merge gate, before the unit gate, on the rebased
   branch. If it fails, run it at the merge baseline too: the merge is blocked
   only when the baseline passes, and stale artifacts inherited from `main`
   are reported but do not block. The refusal names the fix, `task gen`.

Update the merge row in `docs/goals/README.md`.

## Checks

Unit tests with a stub shard runner:
- A file declaring 910 000 ms gets its own 970 s shard, and other files keep the
  default.
- An unparseable timeout falls back to the default and is logged.
- `refusal` is set on a gate failure, a rebase conflict and a migration
  refusal, and cleared on resume.
- Stale generated artifacts only on the branch block the merge and name
  `task gen`; ones inherited from `main` do not block.

Then the real check: `task goal -- test scripts/goal/goalctl.test.ts`, and
`bun scripts/goal/goalctl.ts test --affected --list` showing the union file's
planned shard budget, if `--list` prints budgets; otherwise a log line from a
dry plan. Run `task dev:typecheck`.
