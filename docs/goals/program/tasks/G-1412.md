## Outcome

`infra/jena/tests/semantic-source-readiness-union.test.ts` runs the full native
Maven suite in Docker. That takes 10 to 15 minutes of CPU, and its own declared
timeout is 910 s. The merge gate selects it for changes that cannot affect it.
On 2026-10-07 23:27 UTC kernel's gate for two TypeScript association files
selected it among 105 files (`.temp/kernel/structure-association-merge-2327.log`),
and its shard did not finish. Every Goal's gate pays this cost and the CPU
contention that comes with it.

The test reads only `infra/jena/Dockerfile`, the paths that Dockerfile COPYs,
and its own file. It derives the copy set from the Dockerfile's COPY lines (see
lines 49-74 of the test). First find out why affected planning selects it now:
- a directory-wide rule for `infra/jena/tests`;
- a whole-tier widening;
- or a dependency edge.
Then make the planner select it only when the change touches the Dockerfile, a
path it COPYs, or the test file itself. Derive that input set from the
Dockerfile the same way the test does, so the two cannot drift. Leave every
other selection rule unchanged. If a rule selects other heavy native files
(`infra/jena/tests/*`) for the same wrong reason, apply the same input-based
selection and name them in the handoff.

## Checks

In `tests/qa/unit/affected.test.ts`:
- A change to two Main TypeScript source files does not select the union test.
- A change to `infra/jena/Dockerfile` or to a COPYed native source does select it.
- A change to the test file itself selects it.

Run `task goal -- test tests/qa/unit/affected.test.ts`. Then, as the real check,
show `bun scripts/goal/goalctl.ts test --affected --list` from this worktree with
one Main TypeScript file changed. The union test must not appear, and the plan's
reason line must name the rule you changed.
