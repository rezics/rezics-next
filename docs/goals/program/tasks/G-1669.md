## Outcome

The first main-wide browser run (2026-10-11) ran 346 files as one batch. One journey's data preparation failed (the scoped-subjects seed got 403 `platform_closed`), the tier stopped, and 341 files never ran. Two changes:

1. **One preparation, one journey.** `scripts/qa/e2e.ts:353-358` runs each `JourneyPreparation` in order and throws on the first non-zero exit. Each preparation names exactly one `journey` (`scripts/qa/e2e-preparation.ts`). When a preparation fails or exceeds its budget: record it, leave that journey out of the Playwright run, run every other selected journey, and report the left-out journey as failed with the preparation's step name and log path, in the same result form a failing journey has (so acceptance and the regression see a failed file, not a missing one). The tier's result is failed. When every selected journey's preparation fails, the tier ends without starting Playwright.
2. **Browser files in batches.** In `scripts/goal/regress.ts` the `e2e` tier is planned as one batch of every file. Plan it in batches the way the integration tier is (reuse that planner and its batch size option; a Storybook file keeps the `--storybook` handling at line 648). A batch that fails to start costs that batch's files, not the tier.

3. **A rerun of the failures runs the whole file** (program, after the first land review). A journey that failed in preparation has no test title to select, so `task qa -- --only-failed <run>` must rerun that file in full: `e2eArgs` in `scripts/qa/acceptance.ts` builds no title filter for it, and the CLI's check of selected results accepts it. Mark the result as a preparation failure with a field, not by its name.

Smallest change: a try/catch with a list in the preparation loop, the journey filter, the result entries; and the existing batch planner applied to one more tier. No retry of a failed preparation, no new configuration, no change to how journeys declare preparations.
