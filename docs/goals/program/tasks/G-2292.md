## Outcome

The record of `anime/navigate-a-thousand-episode-inventory-thousand-chapters` holds, for each of the six personas, the answers to the requests the production contents page sends, so its story runs the production reader on a replaying fetch. Today the record holds the inventory at `limit=2` without the page's own parameters, and the Work header for the owner alone; the test already walks the inventory at `limit=100`, unlabelled.

The page is `apps/web/app/[locale]/w/[ref]/(work)/contents/page.tsx`. Read it and the builders it calls (`booksContentsInventoryQuery`, `booksContentsInventoryLimit`, `readContents`, `readWorkHeader`) only to copy each request's exact spelling; change nothing under `apps/`.

1. Each persona's proof records, under new labels, with the persona's acting subject when signed in and none for the visitor:
   - the Work header as the page reads it (`work-header`, today the owner's only: keep the owner's sample and its label);
   - the contents read the page makes before it chooses the inventory (`contents-read`);
   - the inventory's first page exactly as the page builds it — web reads this as `position=start&language=en&limit=100` — (`contents-first-page`) and the page its continuation opens, built from the first answer as the page builds it (`contents-continuation`);
   - the same request with `q=Episode 1000 重逢`: its first window (`contents-search-first-window`) and the window its continuation opens (`contents-search-continuation`). If the page's builder carries no `q`, add `q` to the builder's parameters and say so in one line of the handoff.
2. No existing sample's label or request changes, no assertion changes, no cell changes state. Never write an answer by hand: run the row's test so that it records, as `OutcomeRecorder` does for every row, and check in the record it writes.
3. `scripts/api/answer-records.guard.test.ts` passes. The handoff lists the samples added (persona, label, method, path, status), the record's bytes and samples before and after, and the recording run's seconds. If the guard refuses the record's size, hand off `partial` with its message and leave the record on `main` as it is.

An answer of 500 or above inside a proof is handed off, never recorded. A 503 in preparation: run once more, then hand off `partial` with the request, the answer and the log path.

Do not build: a change under `apps/` or `services/`, a change to the recorder, the record's format or the guard, another row's record, the layout's or a client component's reads.
