## Outcome

1. **Jena check.** Kernel's G-1326 landed `task jena:check` (`scripts/qa/jena-cli.ts`). It takes no
   arguments, uses the pinned Compose image with `--pull=never`, refuses if the image is missing,
   and runs within 75 s. Run it in every program regression cycle (`scripts/goal/regress.ts`) as its
   own entry. Make `task goal -- test --affected` (`scripts/qa/affected.ts`) select it when a change
   touches `infra/jena/**` or authored Turtle sources (the inputs `jena-cli.ts` lists). Do not add
   it to the merge gate.
2. **Shard-only failure.** `tests/qa/unit/stack-startup-parent.test.ts` ("test-side startup
   children stop before parent cancellation completes, without a QA slot") fails at line 195,
   `pids.some(alive)` true. This happens only inside a 38-file merge-gate shard, and passes alone or
   in a 3-file run. Both recorded failures took about 580 ms, although the loop polls for up to
   10 s, so the deadline is not the cause. Find the real cause from the shard's file list and order,
   and fix it at its source. The logs are in your worktree at
   `.temp/ref/merge-g1354-last-declarations.log` and `.temp/ref/merge-g1300-subject-leaf-third.log`
   (the first `bun test` line of the failing shard lists its files). Candidates include PID reuse,
   a `ready` marker from another case, shared scratch directories between cases or files, and
   `alive()` reading a `/proc` state other than Z. Apply the same fix to the similar loop in
   `tests/qa/unit/core.test.ts` if it shares the cause. Do not widen timeouts or weaken the
   assertion.
