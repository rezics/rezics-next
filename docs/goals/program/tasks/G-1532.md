## Outcome

In run 6 (`.temp/goal-orchestration/regress/20261009t051244-a3e8b7`), one file
that hung until bun's 180 s limit (`services/main/tests/read-snapshot-native.test.ts`
in `model-1`; `infra/jena/tests/semantic-source-readiness-union.test.ts` in
`unit-17`) turned every other file in its batch into `missing`. Eleven of the
run's seventeen new "failures" were files that never ran.

1. When a batch ends on a timeout, the runner records the file that was running
   (the last file header in the tier log with no result after it) as `failed`
   with a hang reason, and runs the files after it again in a new batch without
   it. A file that still has no result after that is `missing`, as now.
2. The report and the manifest name the hanging file and its log, so triage reads
   it directly.
3. A whole-tier failure with no file running (startup, admission) stays a
   deadline outcome, not a file failure.

Acceptance (unit tests over recorded logs, no stack):
- the model-1 and unit-17 logs from run 6 give one hanging file each, and the
  files after it are rerun;
- a batch that times out before any file header is not attributed to a file.
