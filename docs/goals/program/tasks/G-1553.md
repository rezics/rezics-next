## Outcome

Workers repeatedly hit a refusal when one `goalctl test` command names files of
different tiers: an owner file with a unit file, or fault/recovery files with
integration files. They then run each tier by hand and report several run ids.

1. `goalctl test <files...>` groups explicit files by their registered tier
   and runs the groups in tier order, in one QA run where the runner allows it.
   Otherwise it runs them one after another. It prints one summary naming each
   tier's run id and result. The exit code fails if any group fails.
2. Keep each tier's own admission, budgets and stack. Grouping must not put an
   owner file into a unit shard or share a stack between incompatible tiers.
3. Find where the refusal lives (the public selector or `goalctl`) and remove
   it there, rather than adding a wrapper around it.
4. One line in `docs/goals/worker.md` if its test instructions change.

Acceptance:
- A unit test: an owner file plus a unit file, and an integration file plus a fault file, each select two groups in order with their own tier.
- One real run on main with `scripts/goal/regress.test.ts tests/qa/unit/acceptance.test.ts` passes as one command.
