## Outcome

The Fuseki image tag is a digest of its inputs, so every change to native code gives a new tag. Measured on 2026-10-14 under the native Docker engine:

- `infra/jena/Dockerfile` runs the whole native suite (522 Java tests, 16 to 40 minutes) inside the image build. It downloads Jena from archive.apache.org at about 31 KB/s (49 MB, 27 minutes), although dlcdn.apache.org serves the same file in seconds and the SHA-512 check already pins the bytes.
- A QA stack whose image is missing builds it at startup and times out (G-2478's run: 182 s active, zero personas run).
- Workers then built the same tag themselves. Four built `…98eefa9729b7` at once, each with the full suite, serialized on the `rezics-native-test-files` cache lock.
- Built with tests skipped, from the fast mirror and without that cache mount, the same image takes 19 s.

Make an image build fast and single:

1. The image's module stage packages without running tests. A separate target (for example `module-test`) runs the native suite with the current Maven invocation and cache mount. The image content does not change.
2. Download Jena from dlcdn.apache.org first and fall back to archive.apache.org, keeping the SHA-512 check.
3. The native suite still runs wherever it ran before: the merge gate's affected plan runs the `module-test` target whenever `infra/jena/**` or the generated model it copies changes, and the prove phase runs it once per wave tip. Show that a failing native test still fails the gate.
4. One build per tag: stack startup, `task gen`/dev refresh and any explicit build obtain the pinned image through one command (for example `task jena:image`). It returns at once when the tag exists. Otherwise it builds under a host-wide lock keyed by tag, and concurrent callers wait for that one build instead of starting their own.
5. `docs/goals/worker.md` tells workers never to run `docker build` for the Fuseki image by hand; the command provides it.

Record the change and its reason in `docs/development/toolchain.md`. The tag changes once because the Dockerfile changes; build the new tag for wave/1 and main after landing.
