## Outcome

When the unit gate retries a file, whether isolated after a timeout, as a
never-started rerun, or as a confirm run, it classifies the result but keeps
only a classification. On 2026-10-08 trust-ops' G-1344 gate counted
`tests/qa/unit/core.test.ts` as a failure from an isolated 8 s run, but no log
named the failing case, and a fresh reproduction passed. A merge refusal must
name its evidence.

For every run the gate classifies (first run, isolated retry, never-started
rerun, confirm run, and the same on the `main` side):
- Keep each failing file's `(fail)` test names and the first 40 lines of each
  failure's error.
- Write them to the merge log and to a per-merge JSON file next to it.
- Print the refusal with the failing case names, not file names alone.
- A timeout prints the test that was running, where the transcript or owner
  progress file shows it.

Cap each file's kept output at 20 KB.

Second outcome, added by program on 2026-10-08 03:40 UTC: five type errors in
`scripts/goal/goalctl.test.ts` reached `main` because no gate-mapped typecheck
task covered `scripts/goal/tsconfig.json`. Fix them, add a one-command
`goal:typecheck` task, map `scripts/goal/` to it in `TYPECHECK_WORKSPACES` so
the merge gate type-checks goal changes, and add its `toolchain.md` row. This
widens the gate on purpose: the gate's own code must pass the same type check
as everything else.

## Checks

Unit tests with a stub shard runner:
- An isolated retry that fails keeps and prints its case name and error.
- A refusal message names the failing cases.
- A never-started rerun failure is kept the same way.

Run `task goal -- test scripts/goal/goalctl.test.ts` and `task dev:typecheck`.
