## Outcome

The web's surface for `games/work-hub-and-edition-choice` replays this row's record through the Games Work hub. The record holds the hub's projection read (`GET /v1/resources/{work}/page`, label `hub-projection`) for the member only; for the visitor, stranger, owner, moderator and operator the surface has no answer and falls back. `.temp/ref/g2227-record-gaps.md` is the surface's request.

What must be true afterwards, each request taken from the production client and sent with the path, query and body production sends (a request production does not send is not recorded):

- The hub's projection read for every persona: the visitor without an acting Person, each signed-in persona with its own.
- Read the hub's whole production path once (the Work hub route and its loaders under `apps/web/features/work-page/`, including the edition chooser, availability and the signed-in frame) and compare it with the record's labels for each persona; record every read still missing and list those beyond the projection. This is meant to be the row's last re-recording.
- A request a persona's page never reaches (the page stops earlier for it) is not recorded; the handoff says where the page stops for that persona.
- The reads one render sends together start together (`Promise.all`); reads that need an earlier answer keep their order. A label names what the request is and is fixed where the request is written (for example a name in an `AsyncLocalStorage` the recording fetcher reads), never a counter: the web chooses a sample by its label and expects exactly one.
- No assertion and no cell changes. Existing samples keep their answers apart from identities; if recording refreshes identities, every sample changes together.
- The record's requests run under their own deadline (120 s) after the proof, and the persona tests get the limit both need; the proof keeps its own deadline. One comment says which part is the proof's. One console line per persona gives the elapsed time of the proof and of the visit. The file has a 480 s wall.
- A 5xx that is the final answer: hand off with the request and the answer, do not vary it; do not run a third time.

The handoff summary names old and new identities and every new label with its request and status.

Do not build: a change under `apps/web/` or `tests/qa/support/`, a new row, a request with another persona's bearer, a read at the Account origin.
