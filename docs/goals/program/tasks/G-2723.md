## Outcome

On 2026-10-16 about 13:10 UTC the 32-core host reached a load average of 75 with about twenty workers. Seven TypeScript type checks ran at once (one at about ten cores), alongside several dependency-cruiser runs. Under that load, `scripts/static/anti-silo.test.ts` and the accepted-command guard timed out in landing gates and surface gates (G-2705's landing, G-2330's surface gate), and dependency-cruiser exited with no stderr during settlement. Those false failures cost landings and rework.

`scripts/qa/host-admission.ts` already admits a command by memory (`--gib`). Make the heavy compiler and graph commands that workers and gates start (the type checks `task goal -- check` runs, the inference gate, dependency-cruiser in `scripts/qa/affected.ts` and `scripts/lib/dependency-analysis.ts`) also wait for CPU admission, so the host keeps headroom for tests. Bound the number running at once from the host's CPU count and current pressure, the way QA starts already check CPU pressure. Waiting must be visible in the job log, and a command still runs alone on an idle host without delay.

Also make a failed dependency analysis report its exit status and signal, not only an empty stderr.

## Checks

Unit tests for admission by CPU and for the failure message. A measured run: start five type checks at once on the host and show that only the admitted number run together, with the others waiting and then passing. `task goal -- check`.
