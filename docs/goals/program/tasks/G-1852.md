## Outcome

`infra/jena/tests/semantic-source-readiness-union.test.ts` has been red in every main-wide regression since run 8. Kernel's analysis: it is not a deadlock. The regression's owner tier kills Bun at 600 seconds while the file's Docker and Maven child is allowed 900 seconds (the limits come from commit 7825acb17); seven native classes had finished and the run was cut during slow Lucene and TDB2 syncs.

The merge gate already reads a file's declared timeout and plans a shard budget from it (`declaredTestTimeout` and the planned budget in `scripts/goal/goalctl.ts`; search "declared a timeout"). Make the regression do the same when it plans and runs a batch: a batch's deadline is at least the largest timeout its files declare, plus the margin the gate uses, and a file whose declared timeout exceeds the tier's ordinary deadline runs in a batch of its own so it does not stretch fourteen other files' deadline. Reuse the gate's functions; do not write a second parser.

Smallest change: the batch planner and the deadline passed to the batch command. No new option, no change to tiers or to diagnosis.
