## Outcome

Browser QA costs what it needs and no QA stack can starve the host:

1. **Storybook once per run, only when asked.** `scripts/qa/e2e.ts` runs the
   whole web Storybook after every Playwright run (around line 358), so
   re-running one selected journey also runs about 5 minutes of component
   tests. Run Storybook only for a full e2e tier run or when explicitly
   requested (a flag); a run with selected journey files skips it and says so
   in its summary.
2. **Accounts in the harness.** The e2e tier also runs the Accounts journeys
   (`apps/accounts/playwright.config.ts`, today only `task accounts:e2e`
   against a running app) against the same QA stack's Account service, and a
   full tier run includes the Accounts stories (`accounts:storybook:test`,
   already capped by `STORYBOOK_MAX_WORKERS` like web's). Change nothing under
   `apps/`.
3. **Memory caps for every QA container.** `infra/dev/compose.qa.yaml` caps
   only Fuseki. Give PostgreSQL, RustFS, Toxiproxy and Mailpit memory limits,
   overridable by environment variables like Fuseki's, sized from what they
   actually use in a QA run (measure with `docker stats` during one ordinary
   integration batch and one large-tmpfs file; record the measured peaks in
   the handoff and in a comment beside the limits).
4. **Shared dev storage stays protected.** Branch `goal/g-403` (commit
   9286bc000, `scripts/dev/config.ts` and its test) protects the shared dev
   stack's storage from QA memory pressure but was never reviewed. Review it
   against current `main`, take what is still right and drop the rest; never
   cherry-pick it whole.
