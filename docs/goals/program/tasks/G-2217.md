## Outcome

A manager queues work that waits for another Goal's result, and the tool starts it when the result is on `main`. `depends:` names tasks of the brief's own Goal; a dependency on another Goal's task is refused (`scripts/goal/queue.ts:52`, `scripts/goal/tasks.ts:84`), rightly, since a Goal does not read another's task list. On 2026-10-13 the web Goal's surface briefs waited for two results of the program: the replaying fetch (`apps/web/features/stories/recorded-fetch.ts`) and each row's answer record (`tests/qa/fixtures/outcomes/<vertical>/<row>.json`). With nothing to write in the brief, the web manager kept its briefs outside the queue and waited for a mail from the program for each landing: two questions, two manager turns and the delay of each, for one surface.

1. A brief may carry `needs: [path, path]`: files that must exist on `main`. Lists are parsed as the other lists are (`scripts/goal/briefs.ts`, quoted items included); a path with a glob character, an absolute path or one that leaves the repository is a validation error.
2. `dispatch` refuses a brief while one of them is absent from `main` (`git cat-file -e main:<path>`, not the working tree), naming each absent file, and `queue` accepts the brief and holds it for that reason, shown by `queue` and `status` as its other waits are. The settling pass starts it when the last one exists, under the same claims and admission as any queued brief.
3. `resume` does not check `needs`: the task has started.
4. `docs/goals/README.md`: the field in the brief's frontmatter list and one sentence where `queue` and cross-Goal contracts are described.

Tests: a queued brief with an absent file is held and names it; it starts on the pass after the file is committed to `main`; `dispatch` refuses with the name; a bad path is refused at validation; a brief with no `needs` behaves as before. Use temporary repositories as `queue.test.ts` does.

Do not build: a wait for a task of another Goal by its ID, a wait for a file's content or a commit, a notification to a manager, a change to how `depends` works.
