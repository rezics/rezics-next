## Outcome

Six wave/3 repair tasks changed only tests and a few query resources, yet each one's `task goal -- check` exited 201. The inference gate measures whole projects against `scripts/api/inference-cost-baseline.json`, and wave/3 itself already exceeded that baseline. Each worker then spent a wake investigating a failure it did not cause: seven wakes and 4.86 M input tokens. The analysis is in `.temp/ref/report.md`, section 4.

When `task goal -- check` fails the inference gate, measure the check's base with the same command (the base that `checkChangedFiles` uses). If the base fails the same budgets, report the failure as inherited from the base, judge the task by its own change instead, and fail only if the task raises a metric beyond the margin over the base's own measurement. Print both measurements. The merge gate keeps judging main against the recorded baseline, so an over-budget change still cannot reach main unless its baseline is recorded deliberately.

Measure the base only after the head fails, so a passing check costs no more than it does now. Apply the same rule to any other check that compares absolute measurements with a recorded baseline, if one exists.

## Checks

Unit tests for these cases: a passing head; a failing head on a passing base; a failing head on a base that fails the same way, with and without the task adding cost. `task goal -- check`.
