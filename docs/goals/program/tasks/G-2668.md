## Outcome

`tests/qa/integration/outcomes/realm/ranking.test.ts` passed three complete six-persona runs in G-2587's worktree (QA `20261015t140935-bafa2f`, `20261015t141908-7a1a41`, `20261015t142733-fb0609`). In three program confirmations at wave/2 it never ran:

- `confirm-20261015t151635-2863ad`;
- `confirm-20261015t154135-643bb7`;
- `confirm-20261015t160947-18ae8b`, which already included the interrupted-build quarantine.

Each time it failed in about 2 s with `RETAINED_SOURCE_FAILURE` at boundary `verify-existing`: "complete manifest is missing or unreadable". The key changed between runs (`e1964525…`, then `50816e83…`), and the key lock was acquired in 11–14 ms, so no producer held it. The logs are under `.temp/goal-orchestration/confirm/<run>/qa/outcome-35/`.

Something in the confirmation's checkout or lane setup creates the Realm discussion source directory for the key without a manifest before the test's restore runs. Look at:

- `tests/qa/support/realm-discussion-source-runtime.ts` (`realmSourceDirectory` under the checkout root);
- `scripts/qa/retained-source.ts`;
- how `scripts/goal/confirm.ts` prepares checkouts and lanes;
- whether another file in the same run (`closure-rankings`, `closure-search`) prepares the same source concurrently.

Find the cause, fix it, and prove it by running `task goal -- confirm` on main with the ranking file passing. Do not raise any bound.
