## Outcome

Prove that **personal and authoring operations** touch a bounded neighbourhood as a person's data grows: library listing and filters, progress over a thousand-chapter or thousand-episode inventory, collection tracking, import and export (batch size against total library size), loans, the Recipe editor and reader for a long recipe, Work structure edits on large Works, and notification fan-out on writes.

For each operation, seed one method at three or four modest sizes. Measure work per request or per batch: SQL rows, graph calls, queue items, and served time. A cost that grows with the total rather than with the page or batch is a defect. Fix the algorithm, keep a growth test red before and green after, and never raise a cap. Hand off a table: operation, sizes, work per size, verdict, fix commit.
