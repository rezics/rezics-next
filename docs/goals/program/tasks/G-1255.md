## Outcome

Three operational gaps seen on 2026-10-07, all in `goalctl`:

1. **Pre-merge unit gate.** Kernel twice merged a task that broke unit tests
   on `main` (4, then 20) and found out in its wave, so every Goal's checks
   were red until a fix landed. `goalctl merge` runs, after the rebase and
   before the fast-forward, the unit files `task test -- --affected <main>`
   selects for the rebased branch, reruns any failing file on `main`'s HEAD,
   and refuses the merge only for failures the task introduces (a failure
   that also fails on `main` is reported, not blocking). `--skip-unit-gate`
   skips it with the reason printed. Model, integration and browser tiers stay
   out of the gate. Kernel's script
   `/home/edge/projects/rezics/rezics-next/.temp/kernel/affected-unit.sh` is a
   working prototype of exactly this; follow its logic.
2. **Refresh jumps the heavy queue.** `task dev:refresh -- --wait` (see
   `scripts/dev/refresh-stack.ts`) queues behind every heavy waiter; on
   2026-10-07 it waited sixth in line while the shared stack's Main stayed
   not-ready after a model merge. A shared-stack refresh takes a few minutes
   and unblocks every Goal, so its heavy ticket goes ahead of ordinary waiters
   (it still waits for the current holder, never preempts it). Only
   `dev:refresh` gets this priority.
3. **Weekly projection with whole-point readings.** `weekBurnRate` turns
   a 6→7 step of the integer 7-day readout into a burn rate; early in a run
   that projected 190% and refused Claude dispatch. Treat each readout as
   rounded: with a small movement, the rate uses one point less than the
   observed difference (never below zero), and `status` prints the projection
   as a range (low–high). The dispatch gate uses the low end; `status` still
   warns on the high end.

Update `docs/goals/README.md` briefly (the merge row, the refresh sentence,
the usage bullet).

## Do not

Add a daemon, a scheduler, a second queue or a database; preempt a running
heavy holder; run integration or browser tiers inside `merge`.

## Checks

Unit tests, each failing before the change: a task-introduced unit failure
blocks the merge and a failure already on `main` does not; `--skip-unit-gate`
merges; a refresh ticket is served before an earlier ordinary waiter but after
the current holder; a 6→7 step over one hour no longer projects the week past
its cap while 6→12 over the same hour still does. Run
`task test -- scripts/goal/goalctl.test.ts scripts/dev/tests/refresh.test.ts`
and the type check covering `scripts/`.
