## Outcome

`scripts/goal/goalctl.test.ts` (about 260 tests) is in the affected set of every change under `scripts/qa` or `scripts/goal`. On an idle host it takes about three minutes and passes. At host load 17-30 (twelve workers and their QA stacks) it did not finish in 21 minutes inside a merge gate, and these cases failed:

- "a unit gate timeout that remains inconclusive after an isolated retry blocks the merge": `expect(elapsed).toBeLessThan(30_000)` at about line 3711 received 40,017;
- "files a timed-out shard never started run again and the merge lands": the same kind of bound;
- a known-slow-files ordering assertion;
- a reclaim or exit case that returned a null status.

Make the file's verdict independent of host speed:

1. No assertion compares real elapsed time with a fixed bound. Where a test proves "this stopped at its deadline and did not hang", prove it with the mechanism (an injected clock, the recorded deadline, the order of recorded events), not with a stopwatch.
2. Cases that wait on real timeouts or sleeps to make something expire use the smallest real wait that still exercises the code, or a seam that already exists in `goalctl.ts` for tests (the file's fake engines and `GOAL_*_MS` environment budgets). Add a seam only where none exists, and keep it a parameter of the function under test.
3. Find the ten slowest cases (run the file once with timings) and bring the file's idle-host time down where a wait is the cost; report before and after.
4. A null exit status from a child that was killed is handled as the test intends, not treated as a pass or a crash.

Smallest change: edit the tests and, only where needed, pass a clock or a budget through. Do not weaken what a case proves, do not delete a case, do not add retries, and do not split the file.

none

## Checks

- Run the file three times while a CPU load is present (start `stress-ng --cpu 24 --timeout 600` if available, otherwise several `yes > /dev/null` loops that you stop afterwards) and once idle: same verdict, all passing.
- `task goal -- test scripts/goal/goalctl.test.ts` and `task scripts:typecheck`.
- Report the file's time idle and under load, before and after.
