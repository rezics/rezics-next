## Outcome

The competitor coverage report (`.temp/ref/competitor-coverage.md`, "Existing-mechanism qualification debt", item 1) finds two sources of launch status that disagree. The older launch registry (`launch-coverage.ts`) still records some rows as missing that the persona outcome declarations say are proved: the VN hub and API browse, the game hub and browse, recipe collection, interrupted export, and thousand-episode evidence. It may also record proved rows that the declarations hold pending.

Status must have one source of truth: what each persona gets from the API, plus the browser proofs. Make the registry derive its status from the persona declarations, the confirmation record and its own browser-proof fields, or remove the duplicated fields, so the two can no longer disagree. Keep a browser gap distinct from an API proof: an API proof never erases a browser gap.

Add a test that fails when they disagree. List every row whose displayed status changes, with the evidence for it.
