## Outcome

What a brief names reaches the worker before its first step, with no step spent and no manager acting after `dispatch`. On 2026-10-13 a worker stopped as blocked because its reference files were copied into its worktree forty seconds after it started, and another wrote two files into the main checkout before writing them in its worktree.

- **References.** A brief lists them in the frontmatter, `refs: [<path in the main checkout>, ...]`, files under `.temp/` included. `dispatch` copies each to `.temp/ref/<file name>` in the worktree before the worker's process starts, and `resume` copies those a reclaimed brief has added. A reference that does not exist, or two with one file name, refuses the dispatch before a worktree is made.
- **Operations.** A brief lists them, `operations: [<operationId or part of a path>, ...]`, and the first prompt carries for each what `task operation -- <query>` prints (`scripts/api/operation-index.ts`), sixty lines at most together.
- **The first prompt carries the brief's text**, the names of the staged references and the `tests:` files, so the worker reads none of them as a step. The worker protocol stays a read.
- **`engine: sol`** is Sol on the Codex account with more of its week left when the task starts, from the figures `task goal -- usage` already reads; `codex` and `codex-1` still name an account. A resumed session stays on its account.
- **A stray write is seen.** When a worker hands off, uncommitted changes and untracked files in the main checkout that lie in the task's claimed paths are named in the report of `wait`, and in the task's settlement reason, as stray writes; nothing is deleted.
- **No sub-agent.** A worker's engine is started with its sub-agents off where the engine has such a setting (Claude's is set today); name in the handoff the engines that have none.

Do not build: file contents in the prompt, a map of the claimed files, a sandbox, committing or rebasing for the worker, a change to the review or the gates, the worker protocol's text.
