## Outcome

When a unit-gate shard hits its wall-clock budget, `shardTimeoutFiles` names the
file that was running and the gate reruns it alone. The files in that shard that
never started are still reported as unfinished, and the gate stops as
"inconclusive after isolated timeout retry" (`goalctl.ts` around lines 2471-2482,
and the confirm path around 2505-2514). On 2026-10-07 22:03 UTC, trust-ops'
G-1343 gate went inconclusive this way. A 41-file shard was slowed by a
concurrent 18-minute native image build, 121 files passed elsewhere, and no
failure was found.

Run the never-started files again before calling the side inconclusive:
- Rerun them once, under one shared budget, in the same shards and concurrency
  as a first run of that size.
- Merge their results into the side's failing and passing sets, exactly like
  first-run results.
- The side becomes inconclusive only if a file is still unfinished after that
  rerun. Report those files as now.

Apply the same rule on the `main` side. Keep the existing isolated retry for the
timed-out file itself. Update the merge row in `docs/goals/README.md`.

## Checks

Unit tests with a stub shard runner:
- A timed-out shard's never-started files are rerun and pass, and the gate
  passes.
- A never-started file that fails on rerun counts as a branch failure and is
  compared with `main` as usual.
- A never-started file that times out again leaves the gate inconclusive.

Run them with `task goal -- test scripts/goal/goalctl.test.ts`, then run
`task dev:typecheck`.
