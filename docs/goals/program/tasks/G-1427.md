## Outcome

On 2026-10-08, five merges used `--skip-unit-gate` (G-1336, G-1344, G-1352,
G-1414, G-1420). Each manager first proved, case by case, that the "introduced"
failures fail identically on current main. The gate refuses for failures main
already has, so in practice it is off. Evidence:
- `.temp/goal-launch/merge-w57.out` and its `.json`
- `.temp/goal-launch/merge-w60.out`
- `.temp/trust-ops/fail-main.txt` against `fail-branch.txt`
- `.temp/kernel/G-1373-supervised-gate-0400-new-policy.log`

Fix the classes:

1. **Baseline.** Inherited failures are compared against a stream's
   first-merge boundary, so whatever broke on main after that counts as
   introduced. Compare against the current main commit the merge targets.
2. **Attribution.** In merge-w60, the 25 cases printed under
   `baseline-recipe-edit.test.ts` belong to other files in the same shard.
   Bun's end-of-run failure summary has no file header, so check whether that
   is the cause. Attribute every case from a per-file structured result (bun's
   JUnit reporter, or one result per file), not from text sections.
3. **Comparison key.** A file counts as introduced when it fails on both
   sides, because the error text differs (ports, ids, timings). The key
   becomes:
   - per file, the failing case names;
   - for a file-level error, its normalized first line.

   Error text stays as evidence only.
4. **Gate trees lack `.temp`.** Tests that call mkdtemp under `.temp` fail
   with ENOENT, for example the `withTree` cases in
   `scripts/static/anti-silo.test.ts`.
5. **Unattributed runner failure.** A non-zero shard exit with no failing case
   and no file error is a runner error. Report it with the output tail. G-1373
   was refused with 391 passing, 0 failing.
6. **Generated outputs.** `generated/**` is neither claimed nor checked for
   claims at land and merge. Every merge regenerates it and gen:check verifies
   it. In the meantime, G-1336 waited hours behind G-1411 on
   `generated/openapi/main/public.json`.
7. **Gate command.** `goalctl gate <id>` runs the pre-merge gate on a task's
   head without merging, so it can be rerun after a review passes.

## Checks

Unit tests with a stub shard runner:
- A case that fails on the branch and on current main, with different error
  text, is inherited.
- Cases in one shard's output are attributed to their own files.
- A new failing case in a file that main also fails is introduced, and the
  refusal names it.
- A stream with earlier merges uses current main as its baseline.
- A `generated/` file claimed by another task does not block land.

Run `task goal -- test scripts/goal/goalctl.test.ts` and `task dev:typecheck`.

Verify on real state: on a scratch task off current main that touches
`services/main/src/modules/library/`, `goalctl gate` reports
library-public-bounds and nested-pool-checkout as inherited, each case under
its own file. Put the gate output in the handoff.

## Second outcome (program, after the first scratch gate)

On the scratch gate, a comment-only touch was refused with 10 "introduced"
files. The first case named was a `pg_ctl` start failure. The branch confirm
ran all the failing files in one process; main split them across four shards.
A failure only counts as introduced when both sides are run the same way:
- For each file that fails only on the branch, rerun it alone on the branch
  and alone on main.
- **Introduced:** it fails alone on the branch with a case name that main does
  not fail alone. A file-level error main lacks also counts.
- **Order or load dependent, reported and not blocking:** it passes alone on
  the branch.
- **Runner error:** a process or infrastructure start failure, such as a
  `pg_ctl` start, embedded PostgreSQL or a port bind. Retry it once alone. If
  it fails the same way, report it as inconclusive, naming the step that
  failed. It never counts as introduced.

Verify by rerunning the same scratch gate: the comment-only touch must pass,
with library-public-bounds and nested-pool-checkout reported as inherited.
