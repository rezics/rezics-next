## Outcome

In regression run 3 (`20261007t105721-105731`) the unit tier never produced results:
all 377 unit files ended `deadline` / `unavailable`. Every one was routed as a
separate inbox entry, 377 of the 389 entries program received. The integration,
owner and fault tiers did run.

1. Find why the unit tier missed its deadline, using the run's manifest and logs
   under `.temp/goal-orchestration/regress/20261007t105721-105731/` in the main
   checkout (read them by absolute path; they are read-only evidence). Fix it at the
   source: shard the unit tier like the owner tier, give it a deadline that fits,
   or fix whatever blocked it. A unit tier of about 380 files should finish in well
   under an hour.
2. When a whole batch or tier ends by deadline or infrastructure (not by test
   assertions), route one run-level event naming the batch, its file count and the
   cause, instead of one entry per file. Per-file entries stay for real test failures.

## Checks

- Unit tests: the unit tier is split so each part fits its deadline, and a

- One real run with `task goal -- regress --only unit` that completes, with its wall
