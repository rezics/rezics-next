## Outcome

On 2026-10-08 at 14:00 UTC, the coordinator stopped waking kernel. It refused 5
wakes in a row with "Claude usage is restricted (7d projected 99% before its
reset)". The coordinator's `admit` (in `coordinatorCommand`) calls
`launchGates`, which is the worker launch check, so manager wakes are refused
like new workers and counted against `GOAL_MAX_WORKERS`.

The usage levels are meant to slow workers. For `critical`, the reason text
already says "the rest carries the manager". A manager wake is one turn, and a
Goal only advances through its manager.

Split the gate:
- **Worker dispatch and resume:** keep `launchGates` unchanged.
- **Manager wake admission:** keep the memory floor and a reached Codex account
  for the manager's engine. Admit at every Claude usage level, and don't count
  live workers.

## Checks

Unit tests:
- A Claude manager wake is admitted at `restricted` and at `critical`.
- A Claude worker dispatch is still refused at `restricted`.
- A manager wake is admitted when live workers are at `GOAL_MAX_WORKERS`.
- A manager wake is still refused below the memory floor, and when its Codex
  account is reached.

Run `task goal -- test scripts/goal/goalctl.test.ts` and `task goal:typecheck`.
Verify on real state: after merge, restart `goal-coordinator.service`.
`goalctl coordinator status` shows kernel's wake with no failures while usage is
restricted.
