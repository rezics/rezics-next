## Outcome

Program measured where workers wait, from 06:00 to 09:25 UTC on 2026-10-14. 37% of worker input tokens were polls: a worker re-sending its whole context (median 144k tokens) to ask whether a command had finished. A Codex poll blocks at most 60 s. By command waited on: the worker's own `task goal -- check` 43%, tests that start a QA stack 15%, type checks and tests chained after `task gen` 12% (`task gen` itself takes 1-2 s). Inside a check, the 38 repository guards run one after another in a single `bun test` process: 295 s summed, 301 s wall. Six files cost 81%: authentication-subject 74 s (one case 45 s), mechanism-dependencies 65 s, serialization-points 31 s, web-acting-identity 27 s, g-543-rate-limit 22 s, g-1046-sql-relations 20 s. The type check had a median of 52 s but p75 of 172 s while queued for memory (web needs 5.5 GiB plus 8 GiB reserve). Type-aware lint took 60 s and peaked at 9.2 GiB.

Codex blocks a poll for at most 60 s (`wait`) or 30 s (`write_stdin`), so a worker that waits ten minutes re-reads its context 10 to 20 times. Measured: after a pause of up to 15 minutes the prompt cache still hits 99%; at 15 to 60 minutes the median is 97%; past an hour, 10%. Waking a parked session therefore costs about one poll.

Add `task goal -- job -- <command…>`. It runs the command inline for up to 90 s. If the command finishes, it prints the result as it does today. Otherwise the coordinator (the resident process that already owns manager events) takes over: it records the job, keeps it running or queued under the existing memory and QA-slot admission, and prints `PARKED job:<id>; end your turn with RESULT: parked`. The worker ends its turn. When the job finishes, the coordinator resumes the same Codex session with the exit status, the failing lines (bounded the way check failures are) and the log path. Settlement treats `RESULT: parked` as no handoff and no manager event, and the resumed attempt does not count as a fix round (as with `continuedFor: capacity`). A job whose session cannot be resumed, or that waited over 45 minutes, is reported to the Goal's manager.

`docs/goals/worker.md` tells workers to run any command expected to take over a minute through `task goal -- job`. Tests cover inline completion, parking and wake, a refused resume, and settlement of `RESULT: parked`.
