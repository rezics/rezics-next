## Outcome

The web's surface for `zone/navigation-and-theme` replays this row's record through the Zone home editor and the Zone navigation editor (`apps/web/features/zone-editor/`: `ZoneHomeEditor` with its `save`, exit-save, `publish` and `publishReviewed` handlers, and `ZoneNavigationEditor`). The record on main holds the owner's publication (`publish-site-bundle`, 201) but no draft write: the editor's save and its save on exit send `POST /v1/content-drafts`, and the surface cannot replay either.

What must be true afterwards, each request taken from the production client and sent with the path, query and body production sends (a request production does not send is not recorded):

- For every persona that can open the editor: the home editor's save and its exit-save as `ZoneHomeEditor` sends them, with the prepared home document identity the editor now carries through save, exit-save, reload and publication, and the reload read that follows a save. For a persona that cannot author: the refusal production reaches, if it reaches one.
- Read both editors' whole production path once and compare it with the record's labels for each persona; record every read or write still missing and list those beyond the draft writes. This is meant to be the row's last re-recording for the surface.
- The reads one render sends together start together (`Promise.all`); writes and reads that need an earlier answer keep their order. A label names what the request is and is fixed where the request is written, never a counter: the web chooses a sample by its label and expects exactly one.
- No assertion and no cell changes. Existing samples keep their answers apart from identities; if recording refreshes identities, every sample changes together.
- The record's requests run under their own deadline (120 s) after the proof, and the persona tests get the limit both need; the proof keeps its own deadline. One comment says which part is the proof's. One console line per persona gives the elapsed time of the proof and of the visit. The file has a 480 s wall.
- A 5xx that is the final answer: hand off with the request and the answer, do not vary it; do not run a third time.

The handoff summary names old and new identities and every new label with its request and status.

Do not build: a change under `apps/web/` or `tests/qa/support/`, a new row, a request with another persona's bearer.
