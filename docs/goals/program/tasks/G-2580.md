## Outcome

`task repo-index:build` sets `CARGO_HOME` to `{{.ROOT_DIR}}/.temp/repo-index-cargo` and builds into `.temp/repo-index-build` under the worktree. So every new worktree downloads every crate from `static.crates.io` and compiles the parser from scratch before its first guard run. At 23:03 UTC on 2026-10-14 G-2333's guard job failed on transfer timeouts downloading `serde_core`, and each fresh worktree pays minutes for the build.

Keep the isolation from the user's `~/.cargo` (pinned Cargo 1.98.1, `--locked`). Share across worktrees:

- one crate cache;
- one built binary per input, keyed by the hash of `tools/repo-index/**`, `Cargo.lock` and the Cargo version, in a host-wide directory such as `~/.cache/rezics/repo-index/<key>`, built under a lock as `task jena:image` does for the Fuseki image.

A worktree whose tool sources match reuses the binary with no network access and no compile. A worktree that changes the tool builds its own key. Every caller (`scripts/lib/repo-index.ts` and the Taskfile tasks) resolves the binary through one function. Update `docs/development/toolchain.md`.

Prove it:

- two fresh worktrees at the same commit, where the second's first guard run does no Cargo download and no compile, with the times measured;
- a changed tool source producing a new key;
- concurrent first builds producing one build.
