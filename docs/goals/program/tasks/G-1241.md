## Outcome

658 of the 1,405 tracked `*.test.ts(x)` files belong to no QA tier
(`testArgs` in `scripts/qa/acceptance.ts`), so no regression pass ever ran
them; `--affected` reaches some, the full regression none. At baseline
`5d4ac1ea7` they held 93 failing tests: 67 in `services/main/tests`, 20 in
`apps/web`, 4 in `model/tests`, 1 each in `services/account/tests` and
`scripts/ops`. The other Goals repair theirs; this task fixes the class and
Main's share.

1. **Every tracked test file has a tier or a stated exclusion.** Register the
   bun owner tests (`services/*/tests`, `model/tests`, `scripts/**`,
   `packages/**`, and the non-e2e bun tests in `apps/web` and `apps/accounts`)
   in the unit tier, or in a new owner tier with its own deadline if the unit
   tier's 180-second budget cannot hold them (measure it). Files that need a
   QA stack (`*.integration.test.ts` outside `tests/qa`) go to the
   integration tier through the existing gate list. Keep an explicit
   exclusion list with one reason each (live network fixtures, the about
   site's own `about:check`, legacy host-Jena files, load). A new unit gate
   (`tests/qa/unit/test-registry.test.ts`) fails when a tracked test file is
   in no tier and not excluded, naming the file.
2. **Main's owner tests pass again.** The 67 failures are listed in
   `.temp/goal-program/regress/5d4ac1ea7b15/owner/fail-services_main_tests.txt`
   (log beside it). Re-run them on current `main` first:
   `services/main/tests/g-543-rate-limit.test.ts` is already fixed, and the
   `*.integration.test.ts` ones failed under a bare `bun test` with no stack,
   so run those through `task goal -- test --heavy <file>`, which routes them
   to the integration tier. For each real failure, decide: a stale test
   double or fixture (an "Unexpected query" from a mocked Fuseki, a missing
   dependency such as `session.deps.serialStats`, "Disclosure owner is
   unavailable") is fixed in the test to match current code; a product defect
   is not fixed here and goes into the handoff with the test, the evidence
   and the owning module.

## Do not

Weaken an assertion so that it no longer proves its behaviour, delete a test
to make it pass, skip it without a stated reason in the exclusion list, or
change product code. Do not edit test files outside your claim (other Goals
repair `apps/web`, `model/tests`, `services/account/tests`, `scripts/ops`);
register them in the tiers all the same.
