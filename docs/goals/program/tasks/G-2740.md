## Outcome

`scripts/goal/dispatch-lock.test.ts` puts a recording `codex` launcher first on `PATH`, but its environment inherits the machine's settings directory. Its briefs say `engine: sol`, which resolves to a configured account whose launcher is an absolute path, so dispatch starts a real model session in the fixture checkout. Three runs of the dispatch tests on 2026-10-17 started 12 real sessions costing 1.85 M input tokens.

No test under `scripts/goal` may start a real worker, reviewer or other model session, whichever engine its brief names. Isolate settings for every test that spawns goalctl or calls the launch path: an explicit settings directory with recording launchers for each engine, and a local account home. Enforce it in one place, so a new test cannot inherit the machine's settings by omission, for example a test preload or a launch-path refusal under the test runner. Keep the recording evidence the tests assert.

none

## Checks

A test that fails while a goalctl test can resolve a real launcher and passes after. Running the `scripts/goal` tests starts no session in any configured account's session store. `task goal -- check`.
