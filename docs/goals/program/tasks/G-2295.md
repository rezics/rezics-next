## Outcome

`recipes/read-a-recipe` has its record, `tests/qa/fixtures/outcomes/recipes/read-a-recipe.json`, written by its own outcome test, so that its surface can be built from recorded answers. The row is declared proved for six personas and its test records nothing today.

1. The test records as `OutcomeRecorder` in `tests/qa/support/outcome-test.ts` asks, in the form a recorded neighbour uses (`tests/qa/integration/outcomes/anime/navigate-a-thousand-episode-inventory-thousand-chapters.test.ts`): each call a persona's proof makes to the API carries a label that says what the answer is for a story (`work-header`, `private-work-refused`), and one label is one request per persona. Preparation is not recorded.
2. The record also holds what the row's page reads to render. Find the web route that shows the row under `apps/web` (read it and its readers; change nothing there) and record, for each of the six personas with that persona's acting subject and with none for the visitor, each request the page's server render makes for one visit, spelled exactly as the page's request builders spell it (parameter names, values, limits); where the page pages, also the page its continuation opens, and the empty answer where the API gives one. The handoff lists any read of the page that could not be recorded, with the reason. If no route shows the row yet, record the proofs' calls and say so.
3. The six proofs pass unchanged: no assertion changes, no cell changes state, no answer is written by hand. Run the test so that it records and check in the record it writes.
4. `scripts/api/answer-records.guard.test.ts` passes. The handoff gives the record's bytes and samples, the labels per persona, and the recording run's seconds.

An answer of 500 or above inside a proof is a fault of the API: hand off `partial` with the request and the answer, never recorded under a refusal's label. A preparation write that answers 202 is read to its end with `tests/qa/support/settled-write.ts`. A 503 in preparation: run once more, then hand off `partial` with the request, the answer, the host's load (`cat /proc/loadavg`) and the log path.

Do not build: a change under `apps/` or `services/`, a change to the recorder, the record's format, the guard or a fixture builder, another row's record or test.
