## Outcome

A landing and a worker's check fail on what the change broke, and not on how many workers share the host. On 2026-10-13, beside twenty-two workers, one guard that scans every web source took 17 to 22 seconds against the unit tier's five-second budget for a test: five landings stopped as `unit gate remains inconclusive after isolated timeout retry`, and four workers handed off a red `task goal -- check` for a file they had not changed. The retry ran the file alone with the same five seconds.

- **The retry alone gets time.** When a file of the unit gate fails only by a test's timeout, the gate runs it alone once with six times the budget for a test (`scripts/qa/core.ts` has the tiers' budgets; pass the flag, change no tier). If it passes, the gate goes on and prints one line for each such test: the file, the test and the seconds it took. If it fails for another reason, that failure is the result. If it times out again, the landing stops as today.
- **What was slow is kept.** Each test that passed only on the longer retry is recorded with its file, its seconds and the host's load average, in the gate's evidence file and in one file of the state directory that keeps the last two hundred, so that a guard which needs its own budget is found from the record and not from a stopped landing.
- **A worker's `check` does the same** for its tests and its guards: a file that fails only by a timeout is run alone once with the longer budget, and `check` prints the same line.
- **A worker's guards run in the QA slot of its tests.** Today `check` takes one slot for the tests and runs the guards outside it; five guard runs at once held 12 GB (one dependency scan of about 2 GB each) while only seven were free. One slot covers both, tests first.
- A failure that is not a timeout is never retried by this change, and no test is skipped.

`scripts/goal/unit-gate.ts` has the retry (`timed out again when run alone`); `scripts/goal/check.ts` has the worker's check. The unit gate's existing tests are in `scripts/goal/goalctl.test.ts`: change one only where this behaviour changes what it asserts, and write the new ones in `unit-gate.test.ts`.

Do not build: a change to a tier's budget or to a test's own timeout, a retry of a failure that is not a timeout, a second retry, a change to the lanes or to the slot counts, processor priorities.

none

## Checks

`task goal -- check`, and both test files once with `CLAUDECODE=1`. The tests use fixture test files with a sleep and cover: a test past the budget that passes on the longer retry, with its line and its record; one that fails by an assertion and is not retried; one that times out twice; the record's bound of two hundred; `check` doing the same for a test and for a guard; the guards running inside the slot (one slot taken, released after the guards). Wait on a running command with one long call (`yield_time_ms: 300000`).
