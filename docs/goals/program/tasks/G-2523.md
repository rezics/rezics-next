## Outcome

On 2026-10-14 the host moved from Docker Desktop (a QEMU VM with 24 GiB, which pinned up to 18 GiB of host RAM as shared memory) to the native Docker Engine 29.9 (`docker-ce`, context `default`, `/var/run/docker.sock`). Program migrated the dev and fixture volumes and the Fuseki images. The tooling still assumes a VM:

- `scripts/qa/memory-admission.ts` budgets QA containers against `docker info` MemTotal ("Docker VM") and separately checks the host's MemAvailable for 1 GiB plus an 8 GiB reserve. Natively, MemTotal is the whole host, so the container budget ignores everything else running on the host, and the two checks no longer describe one pool. With a native engine, budget containers against the host: the free pool is MemAvailable less the caps admitted but not yet resident, with one reserve. Keep the Docker Desktop path for a host that still runs it, and detect which one is in use from `docker info` OperatingSystem, as `scripts/load/docker-env.ts` already does.
- Messages that tell the reader to start Docker Desktop (`scripts/dev/cli.ts`, `scripts/load/docker-env.ts`) name the engine in use: `sudo systemctl start docker` for the native engine.
- `docs/development/toolchain.md` records Docker Engine 29.9 in place of Docker Desktop, with the reason: memory pinned by the VM and the 24 GiB container ceiling.
- `tests/qa/fault-recovery/account-key-remote-placement.test.ts` refuses without Docker Desktop host-gateway networking. The native engine supports `--add-host host.docker.internal:host-gateway`. Make it accept either.

Unit tests cover admission with a native reading (no double counting, reserve applied once) and keep the Desktop reading's behaviour.
