## Outcome

A Goal's manager is a role the coordinator runs as short fresh turns, one for each event, so that eighteen handoffs are read by eighteen turns and no turn carries another's history. On 2026-10-13 one resumed manager session read 18 matrices one after another, in a turn of 37 minutes that mail could not reach, and a resumed manager call carried 114,000 to 149,000 tokens on average.

Ordered steps, each committed when `coordinator.test.ts` passes:

1. **A fresh turn for an event.** A turn is a new headless session of the enrolled role's engine, effort, model and account; a wake never resumes. Its prompt is the role card (below, one constant) and the one event, key and body. Each queued event gets its own turn. An event is handled as today: a non-mail event on exit 0, mail once acknowledged; the rest retries with the existing back-off.
2. **A record of every turn**, kept across a coordinator restart: Goal, event key, start, end, how it ended (exit code, cut, crash), the tokens the engine's JSON output reports (input, cached, output) and the `goalctl` commands it ran (a `goalctl` invocation that carries the turn's token in its environment appends its command name). `task goal -- coordinator turns [--goal <goal>] [--since <UTC time>]` prints one line for each and a summary: turns, median input tokens, turns that ran no command but `mail ack`.
3. **Side by side.** Turns of one Goal run together, at most `GOAL_MANAGER_TURNS` (default 6); two events that name the same task never run together, the later waits.
4. **Bounded.** At `GOAL_TURN_MINUTES` (default 10) the coordinator ends the turn's process group and records it as cut. The event is queued once more and says its first turn was cut; a second cut stops it and mails the program with the event key. Nothing else stops on the bound.
5. **Checkpoint.** After ten handled events of a Goal, or thirty minutes after the first one not yet covered, the coordinator queues one `checkpoint` event. Only its turn edits `state.md`, and no two run together for a Goal.

`coordinator start <goal>` enrols the role and queues `start`. `enroll` of a live session stays for the handover; say in the handoff whether the engines have a compaction-limit setting its resumed wakes could pass (300,000), and do not build it.

Role card: "You are the manager of Goal <goal> for one event, in a fresh session; other turns of this Goal may run beside you. Read docs/goals/<goal>/state.md, then the event below and only what it points to. Decide it under the manager charter (docs/goals/manager.md; read it only for a rule the event needs). Write a decision into the brief it concerns. Edit state.md only when the event is `checkpoint`. Acknowledge the mail you were given. Start no watcher and wait on nothing: end the turn when the event is decided."

Do not build: mail levels, resuming a session for a thread, termspaces windows, landing by the coordinator. Another task adds one call to the pump loop of `coordinatorCommand` and a condition to the task events of `managerEvents`: leave those lines as they are. No change to the service unit, no documentation.

## Decision — 2026-10-13

The first attempt stopped at once, rightly: recording the commands a turn ran needs a hook in the entry, `scripts/goal/goalctl.ts`, which G-2116 claims. The program lends that file to this task for one thing: a call at the top of `main` that records the command name when the turn's token is in the environment. The recording itself lives in `coordinator.ts`. Change nothing else in `goalctl.ts`; G-2116 is changing the switch's default branch.

Codex already takes a compaction limit through `GOAL_CODEX_COMPACT_TOKENS`; nothing to build for it.
