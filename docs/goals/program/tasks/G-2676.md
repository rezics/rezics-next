## Outcome

G-2462's surface gate (`scripts/goal/surface-gate.ts`) selected about thirty unit files for the closed-roster row. It ran them in one `scripts/qa/test.ts` process under the unit tier's single 180-second budget, and failed with "QA tier budget exceeded: unit 180000ms" after 495 s, so it gave no verdict on any file. The log also shows test-harness startup failures (`.temp/ref/output.log`; the selection is in `.temp/ref/evidence.json`).

The merge gate already shards its unit selection by measured per-file budgets (`scripts/goal/unit-gate.ts`). Make the surface gate use the same sharding and per-file budgets, so a broad selection gives a verdict per file, and a file that times out is retried alone before it counts as failed. Diagnose the startup-harness failures in the same log and fix their cause.

Prove it: a selection larger than one budget passes when its files pass, a slow file is isolated and named, and a startup failure no longer occurs. Then tell web, through `task goal -- mail`, that G-2462 can continue.
