## Outcome

The 2026-10-16 efficiency audit found that the largest remaining waste is proof and guard premise churn: G-2330 and G-2704 spent about 43 M input after 15:45 UTC. Part of it was fix rounds over tests that failed in setup before reaching the behaviour they assert. G-2704's admission review test answered 403 `authority_denied` in its publication setup, then failed again on rights evidence, and each failure cost a worker round and a manager decision. The landing review commits blocking tests (`scripts/goal/land.ts:512`, classified in `scripts/goal/refusal.ts:30`), but nothing checks that a committed test fails at its assertion rather than in its setup.

Before a review test blocks a landing, run it on the reviewed head and confirm the failure comes from an assertion in the test body, not from a setup request or helper. A test that fails before its assertions goes back to the reviewer once, with the setup failure, to correct the setup. If it still fails in setup, it reaches the program as an unconfirmed finding, never as a worker fix round. The same rule applies when a worker hands off blocked on a test premise: the handoff names whether its failing test reached an assertion. A real defect found by an assertion keeps blocking exactly as now.
