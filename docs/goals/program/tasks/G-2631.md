## Outcome

Competitor coverage (report in `.temp/ref/`, rank 2, B02) found that native Global and Realm rating paths accept only fixed integer scales. A VNDB vote (10 to 100), a StoryGraph quarter star or a Goodreads half star is retained raw on import, but cannot be edited and used natively without rounding. VNDB is a launch source.

Make the judgment scale a property of the rating context, not a fixed integer:

- a scale declares its range and step, for example 1–10 in steps of 1, 0.25–5 in steps of 0.25, or 10–100 in steps of 1;
- a person's score is stored exactly in the general exact-value model (`model/definitions/value-exact-v1.ts`);
- reads present it in the scale it was given;
- aggregates combine scores across scales by an exact normalisation that never rounds what is shown back to the scorer.

An imported VNDB vote becomes an editable native vote at its own precision. This must be configuration on the existing rating owner, not a VNDB-specific path.

Add API tests:

- edit a quarter-star score and read it back exactly;
- import a VNDB vote, edit it and read it back;
- aggregate across two scales;
- a stranger cannot read a private score.
