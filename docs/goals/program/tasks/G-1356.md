## Outcome

Three small changes to `goalctl`, each from a real case on 2026-10-07.

1. **Gate timeouts.** The pre-merge unit gate treats a file that fails on
   both the branch and `main` as inherited and merges anyway.
   `tests/qa/unit/serialization-points.test.ts` timed out (37 s against
   30 s) on both sides under the four-shard gate and was waved through,
   hiding any real finding. When a failure on either side is a timeout,
   count it as inconclusive: rerun that file alone, once, on the side that
   timed out, and decide from that run.
2. **Permitted owner changes in `land`.** The worker protocol lets a
   worker change a file outside its claim when `goalctl owner` reports it
   unclaimed (listed under OWNER CHANGES). `land` still stops on the
   scope check (`changed files outside its claim`, around
   `goalctl.ts:1941`), even after a clean review; G-1339 cost a manager
   turn this way. In `land` only, accept out-of-claim files that no live
   task claims, and print them. Still stop when any such file is claimed
   by another task. `merge` without `--allow-scope` keeps today's
   behaviour.
3. **Codex resets in `usage`.** Codex weekly limits are often reset early
   by OpenAI (recent gaps of 3 to 5 days). `task goal -- usage` should
   read `https://codex-resets.com/api/v1/status`: no key, read-only, cache
   it for 30 minutes, and on failure say "unavailable" and carry on.
   Report:
   - `latest_reset.announced_at` and its age;
   - `stats.avg_interval_days`;
   - for each Codex account, the hours until 100 % at its current pace
     since the later of the window start and the latest reset.

   Credit the source in that output line as the API's terms ask
   ("Data from codex-resets.com"). Send nothing to it but the GET.

4. **Findings, not file names** (manager, added at review, 2026-10-07). A
   both-sides failure was called inherited by file name, so G-1351's two new
   restore locks passed while `serialization-points` was already red on
   `main`. Compare each test's findings: a finding present only on the branch
   blocks. Removed findings and shifted line numbers do not block. A file that
   fails identically on both sides without a named test (for example an
   import error) stays inherited.

## Checks

Unit tests:

- Gate: a timeout on one side triggers one solo rerun, and the rerun's
  result decides.
- Land: an unclaimed out-of-claim file proceeds; a file claimed by another
  task stops.
- Usage: the projection is correct from a stubbed status response, and a
  failed fetch is reported without breaking `usage`.

Run them with `task goal -- test <files>`. Then run `task goal -- usage`
once for real and paste its output in the handoff.
