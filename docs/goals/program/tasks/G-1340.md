## Outcome

With many live workers, full TypeScript checks overlap: a web check holds about
4 GiB and Main's about 3.5 GiB, and on 2026-10-07 two together with the Docker VM
left the host 5 GiB. QA runs already wait for memory (`scripts/qa/memory-admission.ts`,
`waitForMemory` with a host need and reserve). Give type checks the same:

1. `scripts/qa/host-admission.ts`: a small command wrapper,
   `bun scripts/qa/host-admission.ts --gib <need> -- <command…>`, that waits
   (printing need and available) until the host keeps its reserve after
   `<need>` GiB, then runs the command and returns its exit code. It uses the
   existing host reading and reserve settings from `memory-admission.ts`, and
   applies only in local Goal runs (the same local-QA detection), being a
   no-op elsewhere.
2. The `*:typecheck` Task commands in `Taskfile.yml` run their `tsc` through it
   with a need sized from a measurement you make (web, accounts, main, ui and
   the others; report the measured peaks in the handoff).
3. `docs/goals/worker.md` points workers at the `task <workspace>:typecheck`
   commands instead of a bare `tsc` invocation. Regenerate the toolchain
   table with `python3 scripts/documentation/toolchain_inventory.py --write`.

## Checks

Unit tests with injected host readings: the wrapper waits while memory is
short, runs once it has room, passes the exit code through, and does nothing
extra outside a Goal run. Run two typecheck tasks and show their admission line.
