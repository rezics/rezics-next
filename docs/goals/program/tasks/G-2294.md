## Outcome

A story's production reader that requests `/v1/zones/<id>/presentation` is answered by the sample recorded as `/v1/zones/<id>/presentation?`. Outcome tests write a visitor's request with a trailing `?` and no parameters; production writes the bare path; the API reads both as the same request. `requestKey` in `apps/web/features/stories/recorded-fetch.ts` already says "a query is its parameters" and still keeps the empty query apart from none.

1. `requestKey` gives one key to a path with no query and to the same path with an empty one, in both directions (recorded bare and requested with `?`, and the reverse). Two samples that differ only so are refused as ambiguous, as two equal requests are today.
2. `recorded-fetch.test.ts` shows both directions and the refusal, and that a path differing in any parameter still does not match.
3. Nothing else of the fetch changes; no record changes.
