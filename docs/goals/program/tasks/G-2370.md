## Outcome

Two stack runs within four minutes on 2026-10-13 (22:51 and 22:54 UTC, QA `20261013t224438-f6828b` and `20261013t224850-74c00a`) ended in their first seconds with `Failed to start server. Is port 33625 in use?` (the other: 36375) at `tests/qa/support/personas.ts`, where the test starts Main on the run's `MAIN_PORT`. Each cost its task a queue wait of about ten minutes and a worker turn. About one stack run in ten ends this way when sixteen run side by side.

The cause, read from the code: a QA stack's ports are picked when its configuration is written (`stackConfig` in `scripts/dev/cli.ts`, with `scripts/dev/config.ts`), as ports that were free at that instant, and are bound later: the Compose ports seconds later, the host services' ports (`MAIN_PORT`, `ACCOUNT_PORT`) only when a test starts them, often minutes later. Both picked ports lie in the kernel's local port range (`/proc/sys/net/ipv4/ip_local_port_range`, 32768 to 60999 on this host), from which every outgoing connection of every process on the host takes its source port, and a test run opens tens of thousands of connections to 127.0.0.1. `scripts/dev/cli.ts` already retries once when Compose finds a port taken; nothing covers the host services.

What must be true afterwards:

1. Every port of a QA stack, published by Compose or bound by a host service, lies outside the host's local port range as read at allocation, so no outgoing connection can hold it.
2. The ports of a run are leased to it host-wide for as long as its stack directory lives: two live runs never hold the same port, and a lease whose owner is gone (its stack directory removed, its process dead) is taken over. Use the state the stack already keeps where it serves; do not start a daemon.
3. When a leased port is still found taken at bind, the error names the port, the service and what holds it (from `ss -ltnp` or `/proc`), instead of asking whether it is in use.
4. The development stack's fixed ports and every persistent profile are untouched.
5. `scripts/dev/qa-ports.test.ts` proves 1 and 2 without Docker: allocation against an injected local port range, sixteen concurrent allocators with no shared port, takeover of a dead owner's lease. The retry in `scripts/dev/cli.ts` is kept only if a case for it remains; say which.

Do not build: a change under `tests/qa/support/` (another task holds the persona fixture; it reads `MAIN_PORT` from the environment and needs no change), a change of how many stacks may run, a port chosen by retrying until one binds.
