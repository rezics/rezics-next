## Outcome

A manager's decision often changes what a task may touch: a path added, a path given up, a dependency. The manager writes it into the brief and resumes. Today `resume` (`resumeTask` in `scripts/goal/tasks.ts`) starts the worker on the ledger's old claims; only `reclaim` reads the brief again, and `reclaim` refuses a running task. On 2026-10-14 at 00:14 UTC the api manager resumed three tasks after such decisions, found the ledger unchanged, stopped all three, and needed two more mails and a `reclaim` each before any worker could continue.

What must be true afterwards:

1. `resume <id>` reads the task's brief from `main` before it starts the worker. Where the brief's claim fields differ from the ledger (every field `reclaimTask` assigns), it applies them exactly as `reclaimTask` does, under the same checks and in the same ledger transaction as the resume, and prints one line naming the fields that changed. One implementation serves both commands; do not copy the checks.
2. A conflict refuses the resume, prints the conflict lines `reclaim` would print, changes nothing in the ledger and starts no worker.
3. An unchanged brief changes nothing and prints no extra line. A brief that fails validation refuses the resume with the validation errors.
4. The worker's copy of the brief in its worktree is the brief just read.
5. `reclaim` keeps working as it does. `docs/goals/README.md` says in one sentence that a resume registers the brief's claims and that `reclaim` remains for changing them without a resume.
6. `scripts/goal/resume-claims.test.ts` proves 1 to 4 against a temporary ledger and repository, the way the existing Goal tool tests build theirs: a path added, a path dropped, a dependency added, a conflict with another open task, an invalid brief, an unchanged brief. Keep the file well under a minute: no real worker is started (use the tool's existing dry-run or injected launcher).

Do not build: a change to what `reclaim` checks, to the queue, or to how a running task is treated; a migration of the ledger.
