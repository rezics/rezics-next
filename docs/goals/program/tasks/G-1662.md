## Outcome

Research only: change nothing, and return a report as your final answer (at most 1,200 words). Use web search for primary sources (the Codex CLI repository and documentation for the installed version, `codex --version`), and read this repository for the rest. Cite sources and files.

What is already measured and done (do not redo): over 949 Codex worker attempts, 26 billion input tokens, 98% of them cached. Resumed sessions averaged 780,000 tokens a call because the account allows a 1,000,000-token window; workers now run with `model_auto_compact_token_limit=200000`. A fresh session grows about 2,300 tokens a call from a 16,000-token base and makes 88 calls on average; 52% of calls search or read, and they produce 88% of the output characters. 29% of input went to tasks later cancelled. See "Token efficiency" in `docs/goals/manager.md` and "Tokens" in `docs/goals/worker.md`.

Answer, ranked by expected saving against risk, each with the exact change (a configuration key and value, a file and line, or a tool's default output):

1. Codex CLI settings for headless `codex exec` workers that reduce tokens: compaction (is 200,000 a good limit; is there a better trigger or a compaction prompt), the tool-output limit and its default, parallel tool calls, reasoning summaries, project-document size, how MCP tool definitions enter the context, anything else. Say which are verified in documentation or source and which are guesses.
2. How the plan's usage limit counts cached input, uncached input and output tokens, from an official statement if one exists.
3. What in this repository makes a worker spend calls or context it does not need: commands whose default output is long (`task --list`, `task goal -- test --affected --list`, QA summaries, `task i18n:check`), documents every worker is told to read, anything a worker must rediscover each session that a short generated map could give it. Name the smallest change for each.
4. The equivalent settings for `cursor-agent -p` workers, if any are documented.

Do not propose a new orchestration system, a vector index or a retrieval service. Prefer a default changed in one place over a rule workers must remember.
