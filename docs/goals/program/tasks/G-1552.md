## Outcome

Read `.temp/ref/G-1522.md`, findings 1 (Account/signup/client/PKCE half) and 9.

About fifty scripts and tests generate PKCE, authorize, handle consent,
exchange and refresh tokens with their own code
(`scripts/datasets/auth.ts`, `scripts/dev/seed/api.ts`, the integration
harnesses, `account-boundary-fixture.ts`, and many test files).

1. One local OAuth client in `scripts/lib/oauth-client.ts`: PKCE, authorize,
   consent for a consent-bearing client, code exchange and refresh, with the
   client id, scopes and redirect as plain values. `SeedApi` and dataset auth
   use it, and so do the test harnesses and test files in `paths`. Delete their
   copies.
2. Tests whose subject is the Account service's own OAuth checks (a wrong
   verifier, a replayed code, consent refusal) keep their deliberate malformed
   requests. They use the client only for the normal steps around them.
3. Keep service routing and retries where callers need them.

Production lines must drop (show `git diff --numstat main...HEAD` for non-test
files and the line total).

Acceptance:
- A trusted client and a consent-bearing client both sign in and recover an expired token without changing the granted scopes (unit test against a fake issuer).
- The converted integration files pass, or fail exactly as on main (give the main run id).
