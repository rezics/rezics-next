## Outcome

Four tooling fixes landed green on 2026-10-15 and then broke something the gates never exercised. Their repairs cost 15 turns. The analysis is `.temp/ref/report.md`, section 3.

| Change | What broke | Fix |
|---|---|---|
| A new settings field | goalctl in older worktrees refused every command | G-2672 |
| The retained-source preflight | It refused fixtures the run prepares itself, and its printed repair command failed | G-2685 |
| A dependency upgrade | It left `node_modules` stale in the main checkout and old worktrees | G-2683 |
| A configuration change | It altered retained-source keys | G-2677 |

Add canary tests that `task goal -- check` selects whenever `scripts/goal`, `scripts/qa`, `.goalctl`, a lockfile or a retained-source adapter changes:

- goalctl from a worktree on an older revision runs against the current settings and ledger;
- a stale installation is detected;
- every auto-prepared fixture passes the preflight;
- every repair command the tooling prints actually runs;
- a tooling-only change leaves every retained key unchanged.

Each canary must fail on the commit that introduced its original fault. Show that by checking out or simulating that fault.

## Checks

The canaries passing on main and failing on each recreated fault, and `task goal -- check`.
