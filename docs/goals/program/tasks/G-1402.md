## Outcome

Two small gaps in `goalctl merge` and `land`, both seen on 2026-10-07.

1. **Type check in the merge gate.** The gate runs the affected unit and guard
   files, but no type check. Kernel's `0c3fdeb8f` put two TS2769 errors on
   `main` (`services/main/tests/g-939-list-convention.test.ts`), and launch found
   them later by hand. Map the branch's changed files to their workspaces (the
   `<workspace>:typecheck` tasks in `Taskfile.yml`: main, web, accounts, account,
   content, model, dev, apphost, ui, document, observability, dataset and any
   others). Run each touched workspace's type check once, before the unit gate.
   Every type check already waits for host memory, through
   `scripts/qa/host-admission.ts`. Compare with `main` the way the unit gate
   does: a diagnostic present only on the branch blocks the merge, and one
   already on `main` is reported but does not block. Keep it within the gate's
   existing time budget.
2. **Diverged fast-forward.** `land` and `merge` rebase the branch, run the
   gate, then `git merge --ff-only` into the main checkout (`goalctl.ts`, around
   line 2616). If another merge lands in between, the fast-forward fails with
   "Diverging branches" (G-1385 stopped this way after a clean review). Rebase
   once more onto the new `main` and fast-forward. If that rebase conflicts,
   stop with the conflict as today. Rerun the unit gate only if the new commits
   touch files the gate selected.

Update the merge row in `docs/goals/README.md`.

## Checks

Unit tests with stub git and stub type-check commands:
- A branch-only TS diagnostic blocks; one already on `main` does not.
- A main that moved after the rebase is rebased once and fast-forwarded.
- A conflicting second rebase stops cleanly.

Run them with `task goal -- test scripts/goal/goalctl.test.ts`. Then show
`task main:typecheck` passing on current `main`, as the real-state check that
the mapping finds Main.
