## Outcome

The agents that read this repository (GPT-6.1 Sol, GPT-6 Luna, Claude) follow instruction files closely. OpenAI's guide for the latest models (`.temp/ref/openai-latest-model-guide.md`, section "Instruction following") says that unclear or conflicting guidance in instruction files makes the model pause and block work early, that every file the model can read should be audited for instructions that could influence its behaviour, and that the priority between instructions must be explicit. Many of this project's blocked handoffs came from instruction files. Organize the documents for these readers first; clean their text second.

1. **Audit.** List every instruction file an agent loads: `AGENTS.md`, `docs/goals/worker.md`, `manager.md`, `method.md`, `wave.md`, each Goal's GOAL.md, `.agents/skills/*/SKILL.md`, and the brief template that `task goal -- new` writes. Find every conflicting, duplicated, silent or outdated instruction, and resolve each so exactly one current statement remains. Check rules about tooling against the code; where a document and the tool disagree, change whichever is wrong. For example, the documents must not attribute decisions, but the tool requires decision headers of the form "## Decision — program, <date> UTC"; change the tool's format and its tests so a header carries no attribution.
2. **Priority.** State once, in `AGENTS.md`, which instruction wins when two conflict: the maintainer's current instruction, then the task brief and its decisions, then `AGENTS.md`, then the protocol documents, then skills and other documents.
3. **Transparency.** Add to the worker protocol: when an instruction file makes a worker pause, ask, stop or change direction, its handoff names the exact file and quotes the instruction.
4. **Organization.** `AGENTS.md` stays short and always loaded; it points to an index. Make `docs/README.md` that index, after the pattern of an `llms.txt`: one line per document saying what it holds and when to read it, so an agent loads only what its task needs. Each document has one purpose. A procedure that agents follow step by step belongs in a skill under `.agents/skills/`, loaded when needed. Duplicated text becomes a link to its single home.
5. **Text.** English only: translate or remove every non-English instruction, quotation or note, but keep non-English product data and examples of data. No attribution: remove quotations of people and markers of origin such as "the maintainer said", "(maintainer, date)", "decided by program", "Program review" and "proposal for program review"; state the rule or decision itself, keeping a date only where it is part of the meaning. Delete what is no longer true and superseded history no current rule needs. Follow the guide's writing style: short paragraphs with one idea each and the main point first, plain language, no invented compound labels or filler, lists only for parallel or ordered items, no nested lists, no emphasis through capitals or repetition, finish reversible and authorized work before asking, no warnings about hypothetical risks, and no tests that only mirror a small change.

The scope covers the files in item 1, `docs/goals/`, `docs/architecture/`, `docs/contracts/`, `docs/plan/`, `docs/research/README.md` and `docs/development/`. Leave task briefs (`docs/goals/*/tasks/`) and archived history alone. Preserve every rule still in force; if unsure whether one is current, keep it and list it with the question.
