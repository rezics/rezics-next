## Outcome

On wave/1, a moderation-decision cancellation that existed before the upgrade has `cancellation_result` null. The first cancellation after the upgrade binds its idempotency key, but every replay recomputes the answer (`services/main/src/modules/governance/store.ts` around 1500 and 1515, from 2deb8cbba). After a reconsideration advances enforcement, the same key answers with fence epoch 2 where it first answered 1, and `services/main/tests/governance-cancellation-replay.test.ts` (around line 380) asserts that change.

Program's decision (2026-10-14, from wave review G-2516): an idempotency key answers what it first answered, and a migrated cancellation gets no exception. When the first post-upgrade cancellation binds the key, store the answer it gave as `cancellation_result`, and replay that stored answer from then on, the same way cancellations made after the upgrade already behave. Recording the answer actually given invents no pre-upgrade intent or result. Change the test to expect the first answer (`toEqual(first)`), and keep everything else it asserts: the unknown historical fields, the 409 on a changed decision, the 403 after the grant is withdrawn, and the unchanged snapshots. The cancelled row's migration stays as approved.
