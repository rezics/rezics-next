## Outcome

Nine tests in five files of `tests/qa/unit/` fail on main at any host load (list and errors: `.temp/ref/harness-unit-red-main.txt`, run on 2026-10-13 23:06 UTC at load 62; a landing gate's wider list: `.temp/ref/harness-unit-red.txt`). Every landing gate of every Goal runs them, so each gate is slower and its excuses hide real regressions.

The cause, read from the code: since the change "Share QA memory readings across admission waiters", an admission takes its memory reading from a cache in its state file, valid for three seconds of its clock, and the state file defaults to the host's (`memoryStateFile`, `/tmp/rezics-qa-memory-startup.sqlite`) whenever a caller passes no `lockFile`. A test that injects its own reader and clock but no state file therefore (a) gets the cached reading instead of its reader's second answer and runs into its deadline ("Memory admission deadline reached ... no work started" after a few milliseconds), (b) stands in the host's real queue of startup waiters behind real test runs (the three arrival-order tests time out at 5 s), and (c) writes its invented readings into the cache that real admissions on this host read. (c) is the serious one: a unit test can hold back or admit a real stack.

What must be true afterwards:

1. An admission with an injected reader or an injected clock, and no state file of its own, never opens the host's state file: it gets a private state that lives and dies with the call, and its injected reader is asked every time it polls. Decide this in one place in `scripts/qa/memory-admission.ts`, for every entry point that opens the state; a test must not have to remember an option to be safe.
2. The tests of sharing in `tests/qa/unit/memory-admission.test.ts` keep proving sharing, on a state file they name.
3. A test proves the class: it runs an admission with an injected reader and no state file while a sentinel stands where the host's file would be (make the default path injectable for this, by an option or the environment, not by writing to `/tmp`), and asserts the sentinel is untouched and the reader was asked on each poll.
4. The six files in `tests` pass, three runs in a row, while other QA runs are active on the host. State the host's one-minute load of each run in the handoff.

If one of the nine failures has another cause, name it with its evidence and leave that test as it is; do not weaken an assertion or lengthen a limit to make it pass.

Do not build: a change of real admission behaviour (order, promises, the load gate, the three-second sharing between real processes), a second state mechanism, a change in `tests/qa/unit/qa-harness.test.ts` or `tests/qa/unit/core.test.ts` (other tasks hold them).
