## Outcome

A command of the Goal tool never fails because another process released a lock while it was looking at it. On 2026-10-13, with about twenty workers, a coordinator and their followers on one ledger, a `wait` died with `ENOENT: no such file or directory, stat '.temp/goal-orchestration/ledger.lock'`, and six runs, a landing's unit gate and a `close` among them, died with the same error on `.temp/goal-orchestration/qa-slots/shares`. That landing was recorded as `unit gate inconclusive: unattributed affected runner failure`.

- **One cause, in one helper.** The directory lease (`scripts/qa/process/lease.ts`: `tryAcquireDirectoryLease`, `directoryLeaseHeld`, `reclaimStale`, `readDirectoryLease`, `releaseDirectoryLease`) checks that a lease directory exists and then reads inside it; when its holder releases it in between, the read throws. Everywhere the helper inspects a lease, a path that vanished means the lease was released: the acquirer tries again at once, a reader gets "not held", and a release of a lease already gone is done.
- **Every caller is covered:** the ledger lock (`scripts/goal/ledger.ts`, `acquireDir`), the shares guard of the QA slots (`scripts/goal/admission.ts`), the slots, the gate lanes and the heavy lock. Find each place where a caller itself stats, reads or lists a lease directory outside the helper, and move it into the helper or give it the same rule. Name them in the handoff.
- **Proved by contention, not by a mock.** A test starts at least sixteen processes that each take and release one lease two hundred times with no pause, some reading the holder between tries, on a temporary directory: none exits with an error, and a counter file written under the lease ends at the exact total, so the lease still excludes.
- A lease whose holder is alive is never taken, and a stale one is still reclaimed, as the helper's tests assert today.
- An error that is not a vanished path (no permission, a full disk) is thrown as today.

Do not build: another kind of lock, a change to who may hold what, a change to the waits' lengths, a retry around whole commands.

## Checks

`task goal -- check`, and the three test files once with `CLAUDECODE=1`. `process-lease.test.ts` keeps its cases and gains one for each inspection that met a vanished path; `lease-contention.test.ts` is the test with the processes, also run once for the ledger lock through `withLedger` and once for the shares guard. Then run the contention test five times in a row and give the five results in the handoff. Wait on a running command with one long call (`yield_time_ms: 300000`).
