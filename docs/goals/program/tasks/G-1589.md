## Outcome

At 02:15 UTC on 10-10, five `merge`/`land` gates ran at once (G-1506, G-1576, G-1574, G-1548, G-1546) beside a regression run, with load around 20.
- Each unit gate starts four shards per side. Many shards are owner-tier files that each start an embedded PostgreSQL.
- `runUnitGate` gives each side a fixed wall clock (`GOAL_UNIT_GATE_BUDGET_MS`, 12 min) whatever else runs. Gates therefore starve one another, end "inconclusive: continuation made no progress", and are rerun, which adds load.
- Trust-ops' G-1568 is one example: 24 embedded-PostgreSQL files never finished at the budget, from a tiny branch.

1. **Gate lane.** A gate's unit and typecheck work runs only while it holds one of N host-wide gate lanes. N defaults to 2 and is set by `GOAL_GATE_LANES`. Use the existing process-identity lease in `scripts/qa/process/lease.ts`, so a killed gate releases its lane, rather than a second locking scheme. QA stack slots stay as they are.
2. **Budget clock.** The per-side budget starts when the lane is acquired, not while the gate waits. Waiting prints who holds the lanes, as the QA slot waiters do.
3. `goalctl status` shows the lane holders and the waiters.
