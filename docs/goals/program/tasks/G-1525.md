## Outcome

Duplicate mechanisms enter because claims own files, not decisions. A brief can prescribe a second representation, the worker builds it, and the land review only checks that the work complies with the brief. Read `.temp/ref/G-1523.md` first (research, ranks 1–3 and "Validation plan"). The worked example: G-1513 put a CC BY-SA constant and an adaptation-note policy in Main (`git show 857f41606`), although Rights owns material, assessments and obligations. G-1518 (`git show 4b72e89b2:docs/goals/kernel/tasks/G-1518.md`) asked for its own cover mark and fence, although Governance owns enforcement fences.

1. **Ownership map.** Add `scripts/static/mechanisms.ts`, one entry per mechanism: `id`, `owner` module, `entryPoints` (exported symbols), `ownedState` (tables, predicates), `protectedEffects`, `allowedAdapters` and `conformanceTests`. Start with three entries:
   - rights use, assessment and obligation evaluation (`services/main/src/modules/rights`);
   - governance restriction and enforcement fences (`services/main/src/modules/governance`);
   - language parsing (the owner named in `scripts/static/ast-grep/rules/one-language-parser.yml`).

   A test fails on a duplicate id or owner, an entry point that does not resolve, or an empty selector.
2. **Exclusive-writer guards** in the mandatory repository guards, so both `land` and `merge` run them whatever the affected selection is. The guards scan all service sources:
   - only the Rights owner writes assessment or obligation state, or decides derivative obligations from a licence;
   - only Governance writes restriction or enforcement-fence state;
   - in the language rule, replace the whole-file exemptions with the exact current violations, frozen.

   Fixtures: the historical adaptation policy and a separate cover-fence table must fail. A source mapping that carries licence data, a read that projects an assessment, and a change inside the owner must pass. Follow the existing pattern in `services/main/tests/g-896-content-sequence.test.ts`.
3. **Briefs select mechanisms.**
   - `goalctl new` emits a `## Mechanisms` section. For each concept the task touches it lists the map id and one of consume, configure, extend or new; `new` needs the reason no owner fits.
   - `dispatch` refuses a brief that has no such section or names an unknown id. A task that touches no mapped concept writes `none`.
   - The land review prompt (`scripts/goal/land.ts`) also asks which owner carries the change, and whether any new table, predicate, action or policy duplicates a mapped mechanism.
4. **Protocol.** In `docs/goals/manager.md` and `worker.md`, add one short paragraph each:
   - briefs name outcomes and owner mechanisms, never representations;
   - a worker whose brief prescribes a second mechanism stops and reports it, rather than building it.

Do not add a clone gate, a general framework, or map entries beyond the three. Do not edit owner modules.

## Mechanisms

- rights evaluation: consume (read-only references)
- governance restriction: consume (read-only references)
- language parsing: configure (rule exemptions)

## Checks

- A dry-run dispatch of a brief without `## Mechanisms` is refused.
