## Outcome

On 10-10, rerunning six integration files on main (QA `20261010t071949-1e06b4`) planned all six into one 480 s project, with no budget warning.
- The files were passing: `composition-qualifier-key` took 56 s, `erasure-held-replay-http` 92 s, and `erasure-release-proof` cases 20–30 s each.
- The project hit its 480 s wall, and every file not yet finished was reported "Shard timed out before this file completed". Two files never started.
- QA `20261010t070405-55f5a1` did the same with 11 files per project.
- So a loaded host turns passing files into failures, which regression and merge gates then count.

In `scripts/qa/cli.ts`, integration uses `planIntegrationShards(estimates, capacity)` with `capacity` capped at the slot count. Each project gets the fixed 480 s budget and is filled up to it. Fault/recovery already queues more projects than slots, each with its own deadline.

1. **Headroom.** Plan each integration project to at most 60% of its budget by the estimates, so a measured file run on a loaded host still fits.
2. **Queue instead of cram.** When the files need more projects than slots, queue the extra projects, each with its own 480 s deadline, as fault/recovery does. Do not raise the per-project budget. `stackPlanBudgetWarning` still warns when the whole tier cannot fit its tier budget.
3. **One file over the budget.** A file whose own estimate exceeds the 60% line gets a project of its own and is named in the run summary as over the integration budget, a cost defect for its owner.

`scripts/qa/core.ts` (estimates and artifact roots) is held by another task. Leave where estimates come from as it is; Program follows it up after that task lands.

## Checks

- `tests/qa/unit/integration-shards.test.ts` covers four cases:
  - six files with the measured durations above plan into enough projects, each at most 60% of its budget;
  - with three slots, the extra projects queue with their own deadlines;
  - a single file over the line gets its own project and is named;
  - estimates that already fit leave the plan unchanged.
