The Threads and Ranking journeys pass. The `realm/boards` API outcome passes with its fixture.

Decide which side is wrong:

- **The API is wrong** if a Realm that already has a projected ranking cut answers 503 while a newer projection runs. A read must answer from the last consistent projected cut, not refuse while the projection catches up; the same class as G-2575's read-basis fix.

Fix the side that is wrong, at its cause. For an API change, add an owner test where a newer projection is in progress. Then run the Boards, Threads and Ranking journeys together on one stack and replace the Boards `browser: missing(...)` entry in `scripts/qa/cases/launch-coverage.ts`.
