## Outcome

The retained-source preflight (G-2682) refuses before shard startup even when the QA run would prepare the source itself. On main this breaks the QA harness tests in G-2462's surface gate (`.temp/worktrees/g-2462/.temp/goal/surface-gate/run-aUJFQU`):

- "an erasure-only selection prepares its default small fixture before the shard";
- "launch and erasure share one prepared small fixture across their selected shards".

Each fails with "Retained-source preflight: refused" in about 0.5 s. Every gate that selects them fails as well. Separately, the repair command the preflight prints, `task goal -- prepare-source owner`, fails with "QA stack selection accepts only -t <acceptance ID>".

Make the preflight distinguish:
- a source the run prepares by itself before the shard (the default small fixture and any other auto-prepared source), which it reports and accepts;
- a source nobody will prepare, which it still refuses in seconds with the exact reason.

Make its printed repair command one that actually works, and test that command.

Prove it: both harness tests pass, a missing non-auto source is still refused, and the printed repair command succeeds on a synthetic source.
