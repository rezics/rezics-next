## Outcome

`task dev:refresh` builds the Jena image before it stops any writer
(`buildImage` in `scripts/dev/refresh-stack.ts`, around line 690). On
2026-10-07 21:39 UTC kernel's mandatory refresh failed there after about five
minutes with only "docker compose failed (exit 255)". The previous revision kept
serving, as designed, but two defects remain:

1. **Budget.** The step runs `compose(..., 300_000)`. `infra/jena/Dockerfile`
   runs `mvn package`, including the native unit tests. That run took 656 s when
   kernel qualified it. Replace the literal with a named constant sized to the
   real build, with a comment giving the reason: 30 minutes, about three times
   the measured run. Host admission already bounds memory, and failing before
   mutation already keeps the stack safe. Report a timeout as a timeout ("image
   build exceeded 30 min"), not as an exit code.
2. **Diagnostics.** `command()` buffers output in memory (8 MiB `maxBuffer`)
   and drops it, because describe and compose output can carry secrets. Build
   output is Dockerfile steps and Maven logs, not environment values. Stream the
   build's stdout and stderr to a log file in the stack directory, next to the
   refresh state, with mode 0600. Name it in the error message. This also
   removes the buffer limit for a long Maven log. Keep the no-output rule for
   every other compose and describe call.

## Checks

In `scripts/dev/tests/refresh.test.ts`, with stubbed commands:
- A build that outlives the budget reports a timeout.
- A failing build names its log, and the log holds the output.
- Output larger than 8 MiB does not fail the step.

Run them with `task goal -- test scripts/dev/tests/refresh.test.ts`. Do not run
a real refresh; the manager verifies it on the live stack.
