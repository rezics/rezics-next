## Outcome

wave/2 changes 501 files against main and merges soon. Review its diff in this area, adversarially: `git diff main...wave/2 -- <paths>`, scope **services/main/src/modules/{query,search,projection*,event,relay*,library*,progress*}, services/main/src/infrastructure/**, infra/jena/****.

Look for defects a test may not catch:

- an authority or disclosure check that a new path skips;
- a read whose cost grows with the population;
- a nested pool checkout or a transaction held across I/O;
- a swallowed error that turns into a misleading status;
- a race between a read and a write's fence;
- an unbounded loop or retry;
- a test whose assertion was weakened to pass;
- a migration that is not safe on existing data;
- a privacy leak in logs (the new worker-fault logging adds error messages).

Verify each candidate before reporting it: read the code paths and, where cheap, run a focused test or write a failing one. Do not report style.

Write `.temp/goal/review.md` with one entry per verified finding: file and line, the defect, a concrete failure scenario, severity, and the smallest correct fix. Fix none yourself; program routes the fixes. Report nothing unverified.
