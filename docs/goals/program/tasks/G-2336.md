## Outcome

The record of `realm/rules` holds the answers to the requests the production pages send, so the surface's stories run the production readers on a replaying fetch and none stands in for a read. The web Goal's surface for this row found these missing (2026-10-13 20:52 UTC), each with the client and query production uses:

- the Realm's public header for the visitor, with no query;
- the management header for the visitor, with the page's `language` and no acting subject;
- the owner's header of the Realm with no rules yet, with `language` and the owner's acting subject;
- the private Realm's header and its join page for the visitor, both with no query;
- the private Realm's public header for the member through the anonymous client, and the member's own identity read as production makes it;
- the owner's management access read: the Realm with the owner's acting subject and no `language`.

1. Read the routes under `apps/web` that render a Realm's rules, its management rules page and its settings access (read them and their readers; change nothing there) and record, for each of the six personas, every request the server render of each page makes for one visit, spelled exactly as the page's request builders spell it. Use `tests/qa/support/frame-reads.ts` for the frame's reads; record the pages' other reads beside the proofs' calls. A page is recorded in the language the row's proofs already use; add no second language unless the proofs have one.
2. No existing sample's label or request changes, no assertion changes, no cell changes state. Never write an answer by hand: run the row's test so that it records, and check in the record it writes. Identities are this run's.
3. `scripts/api/answer-records.guard.test.ts` passes. The handoff lists the samples added per persona (label, method, path, status), any read of a page that could not be recorded with the reason, and the recording run's seconds.

An answer of 500 or above inside a proof is handed off, never recorded. If the recording run fails on a 503 or a timeout, run it once more when the host's one-minute load is below 64 (`cat /proc/loadavg`); then hand off `partial` with the request, the answer, the load and the log path.

Do not build: a change under `apps/` or `services/`, a change to the recorder, the record's format, the guard or the helper, another row's record.
