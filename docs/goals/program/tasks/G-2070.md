## Outcome

The scope registry says, for each row and each of the six personas of
docs/goals/method.md, whether the row's outcome is proved, and
`task goal -- status` prints rows proved of rows in scope. Today
`scripts/qa/cases/launch-coverage.ts` has one `api` proof per row and no persona.

1. `scripts/qa/cases/outcomes.ts` (new; no `bun:test` import, `status` loads it):
   - `Persona = 'visitor' | 'stranger' | 'member' | 'owner' | 'moderator' | 'operator'`;
   - a cell is `proved(test, file?)`, `pending(test, file?)`, `notApplicable(reason)`
     or missing (a persona left out);
   - `rowOutcomes(rowId, cells, { rights? })` is the default export of one
     declaration file per row, `scripts/qa/cases/outcomes/<kind>/<slug>.ts`;
     `file` defaults to `tests/qa/integration/outcomes/<kind>/<slug>.test.ts`;
     `rights: { basis, credit }` is for rows that publish content;
   - `rowId(row)` is `<kind>/<slug of capability, plus hardCase when set>`, unique
     over the registry; `loadOutcomes()` reads every declaration file and refuses
     an id no row has, a duplicate, and a `proved` or `pending` cell whose file is
     absent or lacks its test title;
   - `scopeProgress()`: rows in scope, rows proved (every persona `proved` or
     `notApplicable`), cells by state.
2. `tests/qa/support/outcome-test.ts`: `outcomeTest(declaration, persona, fn)`
   registers the cell's test titled `<rowId> / <persona>: <test>`: `test` when
   `proved`, `test.failing` when `pending` (a pending cell that starts passing is
   red until its cell says `proved`); it throws at load for a missing or
   not-applicable cell.
3. `status` prints `scope: <p>/<n> rows proved; cells <a> proved, <b> pending,
   <c> not applicable, <d> missing`: one import and one call in
   `scripts/goal/goalctl.ts`, lent to this task. Touch nothing else there.

Do not write declaration files for real rows (delivery Goals file each row), do
not change the `api` and `browser` fields or `apps/web/tests/launch-coverage.test.ts`,
and do not build a runner, a report or a persona harness (`tests/qa/support/personas.ts`
is another task's).
