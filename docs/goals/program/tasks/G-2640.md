## Outcome

The maintainer asked for an API elegance and type-safety improvement (`.temp/ref/report.md`). This task is its step 1, the audit of the actual current implementation on main. The sibling task spikes Elysia's native capabilities in parallel.

Answer the report's eight questions with code examples and numbers:

1. how domain errors become HTTP responses (trace `services/main/src/routes/problems.ts`, `app.ts`, `api-contract.ts`, `api-responses.ts`);
2. whether error codes stay literal types through the routes, the generated contract and the Eden client (`apps/web/features/api/`, including `literal-fidelity.test.ts`);
3. how many files change to add one domain error: do it on a scratch branch and count;
4. how much response-schema duplication exists;
5. whether the generated OpenAPI lists every status and error variant a route can produce: measure it by comparing the declared responses against the statuses each handler can return, and list the gaps;
6. how many routes return raw `Response` objects and what type information that loses;
7. TypeScript cost: time of `tsc` for Main and the web workspace, the size of the app's inferred type, and Eden client type instantiation counts (`--extendedDiagnostics`);
8. which route patterns repeat often enough to be declarative: authentication, exposure, rate limit, idempotency, 202 handling.

Separate genuine complexity (security, disclosure, idempotency, 202 semantics) from accidental complexity. End with the five improvements that would remove the most accidental complexity, each with the evidence behind it.
