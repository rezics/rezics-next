## Outcome

Two inert fixture options remain from the tooling audit (item 15):
- `startMediaStack` in `tests/qa/integration/media-support.ts` declares `agents` and `rights` but never reads them. Callers still pass them, in `g-852-zones.test.ts` and `g-856-wiki.test.ts`, as if they changed the stack.
- `feed-read-support.ts` always constructs `platformAccess: new AccessExposure(stack.accessPool)` in its home deps, then constructs it again when `options.platformAccess` is set, so the option changes nothing.

1. Remove `agents` and `rights` from the media fixture's options and from every caller. Check first, with `git grep`, that nothing else reads them. If a caller relies on agents or rights being configured, make that explicit where it is actually done.
2. Either `platformAccess` is built once and the `platformAccess` option is removed with its callers, or the option really controls it. Use whichever matches what the callers need, and say which in the handoff.
3. Net non-test lines decrease; this is a pure removal.
