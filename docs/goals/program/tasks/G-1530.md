## Outcome

Read `.temp/ref/G-1522.md`, finding 1 (the PostgreSQL half).

About seventy test files start their own throwaway PostgreSQL cluster: free port,
`initdb`, `pg_ctl start`, connect, stop, delete. Several start the cluster
before their cleanup-protected `try`
(`services/account/tests/account-fixture.ts:31`), so a failed start leaves a
running postgres and a data directory behind.

1. One local cluster fixture in `tests/qa/support/postgres-cluster.ts`: start,
   connection settings, stop, and removal of the process and directory on any
   failure after `initdb`. Options only for what callers really vary (server
   settings, extensions, a role). Respect the socket-path limit in
   `scripts/goal/postgres-socket.ts`.
2. Move every file in `paths` onto it and delete their copies. Keep each file's
   own schema, migration and scenario setup; only the cluster lifecycle moves.
   Leave the WAL/PITR tests (`*pitr*`) and `scripts/research/` alone.

Acceptance:
- A unit test injects a failure after `initdb` and after start, and finds no
  postgres process and no directory left.
- The converted files pass.
