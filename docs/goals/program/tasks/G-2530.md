## Outcome

`unlandedChanges` and `unlandedChangeConflicts` (`scripts/goal/ledger.ts`, about lines 225-255) compute a task's unlanded out-of-claim files from its branch against `main`. A wave task's branch carries all of `wave/1`, so every file the wave changed counts as that task's unlanded change. On 2026-10-14 this refused the dispatch of G-2525 (`docs/development/toolchain.md` "changed by G-2438") and of G-2527 (`scripts/goal/check.ts` and `check.test.ts` "changed by G-2520"), and it blocked G-2523's toolchain update. None of those tasks had touched the files.

For a branch that carries wave work, compute its own changes against `merge-base HEAD <wave>`, using `worktreeBase` from `scripts/goal/tree-currency.ts` (added by G-2515), the same base check and resume already use. A branch without wave work keeps today's behaviour. Wave work still reaches `main` through the wave merge, which checks the whole wave's scope once. Tests: a wave task's branch holds only its own commits; a non-wave task's held files are unchanged; a dispatch claiming a wave-changed file that no wave task touched is admitted.
