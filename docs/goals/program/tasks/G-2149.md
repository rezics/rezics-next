## Outcome

The supermanager can decide, from one note of at most seventy lines, how a proved row gets its surface before the web Goal starts on twenty rows at once. The [method](../../method.md) says a surface shows each state (loading, empty, error, pending, populated) as a story fed by answers recorded from the row's outcome tests, and its gate is types, unit tests and stories; nothing of that path exists yet. This morning the same gap on the API side cost three refused drafts: the registry, the harness and the guards each passed alone and were never run together. You write the note and change no file of the repository.

Write `.temp/goal/design-note.md` in your worktree and repeat it in the handoff. It answers, with file paths and line numbers as evidence:

1. **What exists.** How the web's stories get their data today (`apps/web/.storybook/`, the 175 `*.stories.tsx`): props, a stubbed client, a seeded query cache. Where the generated client is and which features call the API through it or around it. How story tests run and how long (`story-screenshots.setup.ts`, the web's test tasks in `Taskfile.yml`).
2. **What a record is.** `task goal -- persona '<persona> <METHOD> <path>' --record <file>` writes calls and answers with no secret, time or run id (`scripts/goal/persona.ts`); an outcome test knows the row's real requests (`tests/qa/integration/outcomes/`, `tests/qa/support/outcome-test.ts`). Which of the two should write a row's record, where records live, and how one is refreshed.
3. **The smallest shared piece** that turns a record into what a story's client receives for the five states, the unrecorded ones included (loading never answers; pending is a `202`; error is a recorded problem answer). Name the owner file and what it must not become (a second client, a mock server with its own behaviour).
4. **Staleness.** How a record that no longer matches the operation's contract (`scripts/api/operation-index.ts`, the generated schema) fails a guard, not a browser.
5. **The gate.** What `task goal -- check` and a landing must run for a task of kind `surface` in a web worktree, and the seconds each part takes on this host today.
6. **The pilot row,** `books/catalogue-browse-and-search-in-its-zone`: the route and components that are its surface, the states each of the six personas can meet, and what is missing.
7. **The sequence:** the fewest tasks from here to that row's surface landed through the gate, each with its files, and what to leave out.

Where two designs are possible, give both in two lines each with their cost and say which you would choose.

Do not build: any change to the repository, a prototype, a survey of libraries the repository does not use.
