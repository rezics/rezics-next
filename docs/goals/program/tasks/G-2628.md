## Outcome

Validate the first public scope against what people already use. For each vertical, take the established products:

- **Books:** Goodreads, StoryGraph and Bookwyrm.
- **Anime and Manga:** MyAnimeList, AniList and Bangumi.
- **Visual novels:** VNDB.
- **Games:** Backloggd and HowLongToBeat.
- **Recipes:** Paprika, Mela and AllRecipes.
- **Communities:** Reddit and Discourse, for Realms.
- **Fan and community sites:** Fandom and Notion sites, for Zones.

List the features a typical user relies on daily, from each product's own documentation and public pages. Map each to REZICS:

- **A:** already covered by configuration of the existing engine. Name the row or operation.
- **B:** needs a new capability.
- **C:** deliberately out of scope.

Rank the B items by how likely their absence makes a person choose the incumbent: the weakest incumbent is the bar to beat. Read the scope registry (`scripts/qa/cases/launch-coverage.ts`, the row declarations under `scripts/qa/cases/outcomes/`), `docs/product/` and the about site's claims.

Write `.temp/goal/competitor-coverage.md`: one table per vertical, then the ranked B list with, for each item, the smallest engine-level capability that would serve several verticals at once. Prefer configuration over new mechanisms. Also flag any about-site claim the product does not yet back. Change no code.

## Checks

Every vertical covered, every A item naming its row or operation, and every B item ranked with a reason.
