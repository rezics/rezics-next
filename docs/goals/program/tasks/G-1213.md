## Outcome

`goalctl` is safe to run several tasks in one shared worktree (`worktree:` in a
brief), which the Goals keep off until this lands. Today it is not:

1. **Stop kills only its own task.** `stopTask` signals the task's process
   group, then `killWorktreeProcesses` SIGTERMs every process whose cwd is in
   the worktree and `removeWorktreeStack` downs the worktree's Compose project.
   In a shared tree that kills the other live workers and the manager's shared
   dev server, Storybook and stack. After this task: stopping a task in a shared
   tree ends that task's process group and the detached children it started,
   and leaves every other sharer, its children and the shared stack running.
   The stack and the cwd sweep still go once no other open task is live in the
   tree (and for an unshared task, exactly as today). Identify a task's own
   detached children by something the launcher already controls (for example
   an environment marker such as `GOAL_TASK_ID` set at `launch` and read from
   `/proc/<pid>/environ`), not by cwd alone.
2. **A shared branch merges once and records every delivered task.** The
   branch carries all sharers' commits. `merge` of a task in a shared tree
   refuses while any sharer is still running, checks scope against the union
   of the sharers' claims (still refusing files outside every claim), and on
   success marks every open sharer whose commits landed as `merged` with the
   same `mergedCommit`. Today only the named task is marked; a sharer's later
   `merge` sees its branch already in `main` without a `mergedCommit` and
   throws "has no commits to merge".
3. **Import de-duplication is lossless.** `dedupe-imports.ts` treats
   `import type { A }` and `import { A }` (and inline `type` modifiers such as
   `import { type A, B }`) as interchangeable, so a union merge can lose a value
   import or turn one into a type import. Drop an import only when another
   import of the same module provides every one of its names with the same
   kind (type or value). Hoisting stray imports stays as it is.
4. **Shared worktree names are per Goal.** Two Goals that both name
   `worktree: wave-1` today land in one tree and branch. Scope the tree and
   branch name by the dispatching Goal (for example `<goal>-wave-1`), and refuse
   a task joining a shared tree whose open tasks belong to another Goal.
5. **Unknown `depends` refuse.** `dispatch` silently accepts a dependency that
   is not in the ledger. Refuse it with a message that cross-Goal dependencies
   are contracts on the program's board (`docs/goals/program/state.md`), not
   task IDs.
6. **`resume` re-checks the gates `dispatch` checks**: the live-worker limit and
   the usage gate of the engine it resumes on, with `--force-usage` as the
   same escape.

Update the command table and the shared-worktree paragraph in
`docs/goals/README.md` to match the new behaviour, briefly.

## Smallest change; do not build

Change the existing functions. No supervisor, daemon, process namespaces,
cgroups, lock service or new state store; no rewrite of the union-merge
normalization (`prepareCompositionMerge`). Merge events for regression
bisection are a later task (P3): do not add them.

## Checks

- Unit tests, each failing before the change: two sleeping "workers" sharing a
  temporary worktree, stopping one leaves the other alive and its commits on
  the branch; a shared-branch merge marks both tasks merged and a second
  `merge` is a clean no-op; a sharer still running blocks the merge; type and
  value imports of one module both survive de-duplication, while a true
  duplicate is still removed; two Goals' `wave-1` resolve to different trees;
  an unknown dependency is refused; `resume` refuses at the live-worker limit
  and on an exhausted engine.
- Run the scripts' tests with `task test -- scripts/goal/goalctl.test.ts
  scripts/goal/dedupe-imports.test.ts` and `task typecheck` (or the narrower
  type check that covers `scripts/`).
- Run `dedupe-imports.ts` against copies of today's three composition roots
  and show it changes nothing there.
