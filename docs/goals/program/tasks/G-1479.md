## Outcome

On 2026-10-08, the merge gate refused trust-ops' G-1438 with "unit gate
inconclusive: unattributed affected runner failure". Evidence is in
`.temp/ref/g1438-merge8.log` and `.temp/ref/g1438-merge8.json`.

1. **A failing case reported as a runner failure.** Exactly one case failed:
   `scripts/goal/goalctl.test.ts` "a unit gate timeout that remains
   inconclusive after an isolated retry blocks the merge", at 18.8 s under
   load. It passes alone on both main and the branch, so the rule is: branch-only,
   passes alone, order or load dependent, not blocking. Instead the gate
   reported an unattributed runner failure. Find why that case was not
   attributed to its file (a missing or partial JUnit report for that shard, or
   a timeout recorded differently) and fix that class.
2. **Printed transcripts read as failures.** The first run listed
   library-public-bounds, nested-pool-checkout, search-private-budget,
   work-title-control and g-543-turnstile as failing. Some or all of these come
   from the stub gate transcripts that `goalctl.test.ts` prints, such as
   "(fail) library public bounds reject an oversize page". Fix both sides:
   - the gate never attributes a failure from text another file printed;
   - goalctl's own tests capture their child gate output instead of printing
     it.
   Check every file in that list against the evidence, and say which failures
   were real.
