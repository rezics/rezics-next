## Outcome

`goalctl` starts a manager, wakes it and tells it about its tasks; no
hand-written shell watcher and no interactive session to hand over. Three
ordered steps: hand off `RESULT: partial` after each (each lands by itself),
then you are resumed for the next.

1. `task goal -- coordinator start <goal> --engine <codex|codex-1|claude>
   --effort <e> [--model <id>]` creates the manager's session headless in the
   independent tmux server with the start message of docs/goals/manager.md,
   registers it (`goal start`) and enrols it, with no previous owner. For a Goal
   whose enrolled session is gone it replaces that session. `enroll` still serves
   a handover.
2. Mail records its sender (the caller's `GOAL_ID`; refused without one) and
   takes `--deadline <minutes>`. `inbox` and the wake body show both.
   Unacknowledged mail past its deadline wakes the recipient once more and sends
   the sender one mail saying so; `status` lists overdue mail.
3. The coordinator does what the shell waiter of 2026-10-12 did. For every
   running Goal it notices a worker's exit. A task with `land: auto` (or
   `auto-land`) and a `RESULT: done` handoff is landed by the coordinator, one
   landing at a time for a Goal, in the tmux server and outside the service's
   cgroup. The manager is woken only when a landing stops, a handoff is not
   `done`, or a worker exits without a handoff, and the wake body carries the
   reason. Verified landings are listed in the next wake and cause none. The
   program Goal, which is interactive and not enrolled, gets the same events as
   mail.

Shorten "Starting a manager" in docs/goals/manager.md to the one command and
what replaces the Codex loop. Do not build a UI, a new store (`coordinator.sqlite`
and `mail.sqlite` stay), priorities or retries beyond what exists, and do not
change how `land` decides: another task owns `land`, `resume` and `dispatch` in
`scripts/goal/goalctl.ts`. That file, its test and docs/goals/README.md are lent
to you for the `mail` and `coordinator` commands and `managerEvents` only.

The main checkout's `.temp/goal-orchestration` is live with real managers: tests
use their own state directory, and you start or enrol nothing real.
