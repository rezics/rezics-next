## Outcome

G-2599's run `20261015t075208-dbcdcf` on main passed 6 of 11 Books and Library journey cases. Evidence is in `.temp/ref/evidence.md`, and the logs are under that run's `logs/e2e-playwright.log` in G-2599's worktree. Five cases fail:

1. **g-743-library, Latin locale:** the Reading details sheet says "Attempts could not be loaded", so First read is absent.
2. **launch-real-books, ambiguous editions:** after a successful save, the reload fails with `net::ERR_NETWORK_CHANGED`.
3. **launch-real-books, mixed formats:** after save and reload, the edition chooser is absent.
4. **library-loans, direct return:** the shelf action is absent.
5. **library:** `route.fetch` socket hang-up, then `page.goto` after the test ended.

Classify and fix each at its cause:

- **1, 3 and 4** are product reads a person would see fail. Find the request and its answer, and fix the API or the page.
- **2 and 5** are transport. G-2578 made Chromium asset loads survive host network changes, which every QA stack start or stop causes since native Docker. Extend the protection to document navigations and reloads, and make the journey support stop a route handler from outliving its test.

Do not add retries around assertions or weaken them. Run the six journey files three times in a row on a loaded host, all passing.

## Decision — program, 2026-10-15 10:02 UTC

1. **Authorized:** correct `apps/web/tests/g-743-library.e2e.ts` to operate the custom combobox as a person does, by keyboard and its accessible role. `selectOption` belongs to native selects. Change no assertion.

   - QA stacks reuse a pool of pre-created Docker networks (or one shared bridge with per-stack isolation), so starting and stopping a stack changes no host interface;
   - Chromium is launched so that it does not react to host interface changes on a host where nothing leaves loopback.
   Prove it with journeys passing while stacks start and stop. Keep the transport protection you added only if it is still needed.
