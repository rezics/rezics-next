## Outcome

Finished work waits for its manager longer than it took to write (kernel:
25 hours of waiting against 14 worker-hours on 2026-10-07), because every
handoff needs a manager turn to review, merge and close. Take the manager off
that path for routine tasks.

1. `task goal -- land G-NNN` (a new `scripts/goal/land.ts` called from
   `goalctl.ts`): for an exited task whose handoff says `RESULT: done`, run a
   read-only review of the branch diff against its brief with
   `codex exec -m gpt-6.1-sol -c model_reasoning_effort=high -s read-only`
   (ask for blocking defects only: wrong behaviour, scope beyond the brief,
   weakened tests, security), then `merge` (with its unit gate, guards and
   renumbering) and `close … verified`. Any review finding, merge refusal or
   non-`done` result stops and leaves the task for its manager, printing why.
   Write the review to the task's run directory.
2. A brief may set `land: auto` in its frontmatter. `wait` on such a task runs
   `land` when the worker exits, so the manager's background `wait` delivers a
   landed task or a stop reason. Without `land: auto`, nothing changes.
3. `dispatch` and `resume` refuse while host `MemAvailable` is below
   `GOAL_MEMORY_FLOOR_GIB` (default 12), the same way they refuse at the
   live-worker cap.

4. Migration renumbering (`merge`) refused G-1275 because
   `packages/model/src/address/unicode-data.ts` contains the integer 1425 in
   Unicode table data. The check for an old number outside the task's files
   must count only provable migration references there (a migration file name
   or path, `migration <n>`, a migration/version constant), never a bare
   integer.
5. `merge` refuses with "main, task branch or sharers changed during the unit
   gate" whenever another Goal merges while the gate runs, which on a busy
   `main` is almost always, so managers retry in a loop. When only `main`
   moved: rebase again and fast-forward without re-running the gate, unless
   the new `main` commits touch a file in the task's changed or gated set, in
   which case re-gate once. A moved task branch or sharer still refuses.

Document `land`, `land: auto` and the floor in the command table of
`docs/goals/README.md` in a few lines.

## Not in scope

No daemon, queue, scheduler or second review engine; no auto-landing for
tasks without `land: auto`; no change to merge's gates.

## Checks

Unit tests with a stubbed reviewer and temporary repos: a clean `done` task
lands (merged and verified); a review finding, a gate refusal and a `partial`
handoff each stop with the reason and leave the task open; `wait` lands only
`land: auto` tasks; dispatch refuses below the floor; a bare integer equal to
an old migration number in a data file does not refuse renumbering; a merge
whose `main` moved during the gate lands without re-gating when the new commits
do not touch the task's files. `task test --
scripts/goal/goalctl.test.ts scripts/goal/land.test.ts` and the type check
covering `scripts/goal`.
