## Outcome

A manager lands a task with one command whatever stopped its last landing. On 2026-10-13 four landings stopped for the host's reasons ("unit gate remains inconclusive", "main touched task or gated files again after the retry unit gate; retry merge", a gate lane's timeout) and left their tasks in `conflict`; `land` then refuses ("land requires an exited task (conflict)") and only `merge <id>` followed by `close <id> verified` goes on, which a manager's turn does not know: each case cost a turn and a mail to the program. Four more landings were killed inside their rebase and left the worktree detached with a `rebase-merge` directory and an `index.lock`; every later `land` said only "land requires a clean worktree".

1. **`land` after a stopped landing.** `land <id>` accepts a task that its own earlier landing left in `conflict` when that landing stopped after its review for a reason that is not the task's: an inconclusive gate, `main` moving, a lane or lock wait that ran out. It lands the same head again without a second review when the head and the brief are those the review accepted, and with one when either changed. A `conflict` from a real merge conflict or a failing gate of the task stays refused, with the present message and the file or test named. The refusal that sets `conflict` records which kind it was; do not infer it from message text at the next landing.
2. **A landing restores what its own interrupted rebase left.** When a landing finds, in the task's worktree, a rebase in progress that a landing of this task started (its record says so), no live process owning it, and the task's recorded head still reachable, it aborts that rebase, returns the branch to the recorded head, removes an `index.lock` no live process holds, and goes on. It removes no file that is not identical to a file of the rebase's target and loses no commit: prove both. Anything else in progress is refused by name ("a rebase the landing did not start", "a merge in progress"), never as "a clean worktree".
3. **A settlement's child carries no turn.** `settle.ts` starts its detached child with the environment `landingEnv` gives a landing (`scripts/goal/land-outside-turn.ts`): no `GOAL_TURN_TOKEN`, no `GOAL_TURN_STATE_DIR`.
4. Decided in code and tested with temporary repositories, as `scripts/goal/land.test.ts` does: each stop kind then `land`; a changed head; a changed brief; a real conflict still refused; the interrupted rebase restored with the commits and the worker's files intact; a foreign rebase refused by name; the settlement child's environment.

Do not build: a change to what a review or a gate decides, a retry loop inside one landing, a force of any kind on `main`, a change to `merge`'s behaviour for the cases it already handles.
