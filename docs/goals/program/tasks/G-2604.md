## Outcome

Close four policy findings from the security review:

1. An application installation write races a narrowed grant.
2. A trusted device is replaced across authenticators without a policy.
3. An operator has no second factor.
4. A rights assessment can still be submitted after its grant ended.

The findings come from `docs/goals/api/later.md`; detail and file positions are in the archived end-of-run tables (`archive/goals:program-2026-10-06/study-2026-10-12/end-of-run/`; read them with `git show archive/goals:<path>`). Check each finding against wave/3 first, since some may already be fixed. Say so with evidence and move on.

For each, implement the policy the contracts imply. Where a contract is silent, follow the stricter reading and state it in the owner document:

- the write rechecks the grant inside its transaction;
- device replacement needs a fresh authentication of the replaced authenticator, or an explicit recovery path;
- operator actions require a second factor;
- the assessment endpoint refuses after the grant ends.

Add a test per finding.
