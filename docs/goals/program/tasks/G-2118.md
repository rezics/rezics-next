## Outcome

A worker proves its change with one command and reads only what failed. Over 2026-10-11 and 2026-10-12, 29% of worker tokens went to waiting on running commands and 9% to starting checks: a worker ran six commands and waited on each.

- `task goal -- check`, run in a task's worktree, runs in one blocking call what the worker protocol lists under "Tests and checks": the type check of each workspace whose TypeScript the branch changed; type-aware oxlint on the changed directories; ast-grep on the changed files; the brief's test files in one `test` call, so one QA slot; `task guards`. Changed means against the branch's merge base with `main`, uncommitted files included.
- A brief names its test files in a new frontmatter list, `tests:`, which `parseBrief` reads (`scripts/goal/briefs.ts:40-46`). Without it `check` runs no test file and says so.
- It prints one line for each check, `ok` or `failed`, with its seconds. For a failed check it prints only the failing case names and the first lines of each error, sixty lines at most for a check. The whole output goes to a file under the worktree's `.temp/goal/check/`, whose path it prints. The exit status is 0 only when every check passed.
- A type check and a type-aware lint take 2 to 3 GiB each and run one at a time; the test call and the guards may run beside them. The type check waits for host memory as the `<workspace>:typecheck` tasks do.
- It checks what the merge gate checks, from the gate's own functions for the changed workspaces and the guards (`scripts/goal/typecheck-gate.ts`, `scripts/goal/unit-gate.ts`), not from a second list: what `check` passes, the gate's type check and guards do not refuse for a reason the worker could have seen.
- `--only types,lint,tests,guards` runs a subset.

Do not build: committing, rebasing or handing off (another task), a watch mode, a cache of passed checks, a change to the gate, the worker protocol's text.

## Mechanisms

none

## Checks

`task goal -- test scripts/goal/check.test.ts`, with the commands injected so no real type check runs in it, and once with `CLAUDECODE=1`. It covers: a passing run's five `ok` lines; a failing type check printing its diagnostics and nothing of the passing checks; a failing test printing the case name; `tests:` parsed and absent; the sixty-line bound; the exit status. Then run `task goal -- check` once on your own worktree and give its output and seconds in the handoff. `task guards` once. Wait on each running command with one long call (`yield_time_ms: 300000`).
