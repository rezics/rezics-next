## Outcome

On 2026-10-15 five workers stopped as blocked and waited for program only because `task goal -- owner <path>` reported a file "changed by G-NNNN (unlanded)":

- G-2646: works.ts, changed on wave/3 by G-2595;
- G-2643: library-imports.ts, changed by G-2642;
- G-2656, G-2658 and G-2664: registry, contract and pilot files "changed" by G-2582, the wave/2 merge candidate, which had merged main and so appeared to own every file main changed.

Each time, program answered "proceed; the overlap is resolved at merge". Each stop cost a turn that re-read the whole session, plus manager latency.

Make the tool decide this:

1. **Real claims still block.** A path claimed in another running task's brief, on the same base, is a real conflict.
2. **Unlanded changes on another branch do not block.** That covers a wave branch, a merge candidate, or an exited or stopped task. `owner` reports it as an overlap to resolve at merge, and the worker proceeds and notes it in its handoff.
3. **A branch that merged main owns only its own changes.** Compute against the merge base after its latest merge of main, not against main's own commits.

Update `docs/goals/worker.md` to match, so a worker hands off only for a real claim. Prove each case with a test, using a synthetic wave branch, a merge candidate that merged main, and a running task's claim.
