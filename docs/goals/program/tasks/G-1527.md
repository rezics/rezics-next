## Outcome

Read `.temp/ref/G-1522.md`, findings 4 and 5.

1. **One process-identity and lease primitive** in `scripts/qa/process/`.
   - Several places implement liveness separately: signal 0 alone (`scripts/qa/core.ts:1021`, `scripts/goal/goalctl.ts:862`), zombie-aware (`scripts/dev/refresh-stack.ts:88`), and start-time plus boot identity (`scripts/goal/coordinator.ts:9`, `scripts/qa/container-reaper.ts:102`).
   - Directory-lock freshness and slot acquisition are repeated too (`goalctl.ts:870`, `goalctl.ts:5448`, `scripts/qa/core.ts:1065`, `refresh-stack.ts:294`, `scripts/datasets/lock.ts:11`, and a bare mkdir in `model-bootstrap.ts:375`).
   - The primitive uses the strongest identity: pid plus start time plus boot id. Release must check the lease token, as QA's does today; goalctl's ordinary slots currently release unconditionally.
   - Scheduling, queue fairness, fail-fast or queued policy, and the recovery namespaces stay with their owners.
2. **One bounded child termination.** Spawning and TERM-then-KILL escalation of the process group are implemented in `scripts/qa/core.ts:429`, `goalctl.ts:2558`, `scripts/goal/regress.ts:248` (TERM only, which can hang), `scripts/qa/host-admission.ts:29` and `refresh-stack.ts:147`.
   - Put the shared primitive in `scripts/qa/process/`, which must not import core.ts, because core installs a reaper on import.
   - Logs, redaction and admission accounting stay as adapters.

Acceptance, unit-tested against real processes:
- A reused pid, a zombie, an owner that dies during initialization, a stale lease, a signal interruption, and an old cleanup after a new acquisition never release another owner's capacity.
- A descendant that ignores TERM stops within a bounded grace period.
- Slot and queue cleanup happen only after the child has terminated.

Do not run shared-stack lifecycle commands.
