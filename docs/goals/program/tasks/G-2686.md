## Outcome

`tests/qa/unit/container-reaper.test.ts` failed twice tonight in G-2462's landing gates and passed in isolation each time, 16/16 three times on main and on the branch:

- the nested SIGTERM case missed `extra-child`;
- in canonical `run-jICjwV`, "a shim run records every scope marker and removal deletes the container and the marker" missed `rm -f marked-container` (2.127 s, against 2.146 s passing on main).

The cases depend on timing: process signals and the order of shim output under load.

Make each case wait for the condition it asserts, such as the marker file, the recorded command or the child's exit, through the reaper's own events or polling with a bounded deadline. It must not depend on wall-clock ordering. Keep every assertion. Prove it with 30 consecutive passes while the host runs other tests (for example in parallel with a unit shard), and with the original cases still failing when the behaviour is broken.
