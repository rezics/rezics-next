## Outcome

Several harness tests in `tests/qa/unit/` fail under load, or when other gates run beside them, although main passes them in isolation. Each wastes a 25-minute gate. Fix the class in each owning test or helper. Each item has file:line evidence in the research report in your refs.

- `scripts/qa/memory-admission.ts`: a deadline can abort measurement before the schema exists (`:384`); start-up catches that and then queries the missing `memory_generation` table (`:563`). This is a real defect on main. Create the shared schema before fallible measurement, and keep the original failure.
- `tests/qa/unit/memory-admission.test.ts`: admission expires after five seconds while markers wait three, so a two-CPU affinity run exits 1 (G-2331, `:237`, `:270`). Separate process start-up from the deadline under test, use readiness handshakes, keep child stderr in the failure, and test deadline arithmetic with a controlled clock. Synthetic start-up admission must not read live Goal concurrency, load or settings (`:23`, `memory-admission.ts:244`).
- `tests/qa/unit/core.test.ts:784`: the QA-slot release test asserts a two-second child start-up window before its lease assertions run. Arm the deadline after a readiness handshake.
- `tests/qa/unit/container-reaper.test.ts:481`: the fake dead owner `4:4` uses the production sweep directory (`scripts/qa/container-reaper.ts:351`), so a concurrent sweep deletes its markers. Give every synthetic runner private reaper state.
- `scripts/qa/integration-shards.ts:134`: the five-second shard-budget tests run repository-wide raw-SPARQL classification. Inject classification into the planner tests, and keep one real inventory test in a tier with a fitting budget.
- `tests/qa/unit/postgres-collation.test.ts:13`: a 60-second unit test creates, copies, restarts and repairs a real cluster. Move that physical proof to the admitted owner tier with phase diagnostics, keeping its custody and index assertions.

No assertion is weakened and no test is skipped.
