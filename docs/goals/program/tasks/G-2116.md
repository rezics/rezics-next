## Outcome

A new `goalctl` command is one new file, so two tasks that each add a command share no file. Six tasks ahead add commands, and each would otherwise claim the switch in `scripts/goal/goalctl.ts`.

- When `main`'s switch has no case for a command, it loads `scripts/goal/commands/<command>.ts` and calls its default export with the remaining arguments. The module also exports a one-line `usage`.
- An unknown command prints the usage string as today, then the `usage` line of each file in `commands/`, and exits 2 as today.
- The existing cases stay in the switch untouched; `regress.test.ts` reads the `regress` case as text.
- A command name is lower-case letters and hyphens. Any other name takes the unknown-command path, and nothing outside `commands/` is ever loaded.
- The Telegram commands are the first five files: `ask`, `tell`, `decide`, `decisions` and `flush`, each passing its arguments to the CLI function of `scripts/goal/notify.ts`. `task goal -- decisions` prints what `bun scripts/goal/notify.ts decisions` prints.

Do not build: a move of an existing command, a registry object, help text beyond the usage lines, a change to `notify.ts`, documentation.

Never call the real Telegram API and never read the real `bots.json`: a test that runs a Telegram command uses a temporary state directory and `GOAL_TELEGRAM_API` pointed at a local fake, as `scripts/goal/notify.test.ts` does.

## Checks

One call: `task goal -- test scripts/goal/commands.test.ts scripts/goal/regress.test.ts scripts/goal/notify.test.ts`, and `commands.test.ts` once more with `CLAUDECODE=1`. `commands.test.ts` covers, through the CLI: an unknown command's output and exit status; a command file found and given its arguments; a name with a slash, dots or capitals refused; `decisions` against a temporary state directory. `task scripts:typecheck`; oxlint and ast-grep on the changed files; `task guards` once. Wait on each running command with one long call (`yield_time_ms: 300000`).
