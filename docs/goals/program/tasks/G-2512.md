## Outcome

Two web surfaces built on wave/1 need requests that no record holds yet. For every request below, make the named row's outcome test send it for each persona, exactly as production sends it (client, `actingSubject`, body), with the label the story looks up. Read the story inputs that list the requests as the specification. Change no assertion, no cell and no existing sample's label or request, and write no answer by hand. An empty, error or continuation state is produced by the test arranging that state through the API, never by editing an answer. If a state cannot be produced through the public API, name it in the handoff.

- Media delivery (row `realm/closure-media`): `POST /api/main/v1/media/metadata` for a representation id(1) and Uses id(2) and id(3), where id(n) = `00000000-0000-4000-8000-` followed by n padded to 12 digits. The visitor omits `actingSubject`; the other five personas send `https://rezics.com/id/` plus their own subject. The contract states are closed = [unavailable, available], open = [available, available], empty = [unavailable, unavailable] and error = HTTP 503 `media_unavailable`; metadata has no 202. The stories are `apps/web/features/document-editor/media-delivery.stories.tsx` and `packages/ui/src/components/media-image.stories.tsx`.
- Reading page (row `books/read-non-ui-languages-non-ui-languages`): the sample `reading-page-agent-credits` for every persona. `apps/web/features/work-page/books-language-recorded-page.test.ts` fails on wave/1 until it exists; the reading-page captures for six personas named by the surface work are in `apps/web/features/work-page/`.
