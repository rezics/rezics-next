## Outcome

The Zone's about-discussion page at `/public` can be shown from its row's record for every state its surface needs. The first surface built from `tests/qa/fixtures/outcomes/zone/attached-realm-discussion.json` could show only the entry while its route read is held, because three groups of reads are not in the record. The page's reads are those of the route under `apps/web/features/` that renders a Zone's attached Realm discussion (read it, change nothing there); a story replays a request by its method, path, parameters and body, and never mixes personas.

1. **The empty published entry, for the visitor.** The visitor has `empty-about-thread` but none of the reads that bring the page to it. Record, with no `actingSubject` and no body: the Zone's route for `path=/public`, the target resource's page, and the Realm.
2. **The private refusal, for the persona it refuses.** `private-about-thread` is recorded, but not the private Zone route and the entry reads of the same persona that lead a reader to it. Find the entry the row's own preparation creates for it and record that persona's reads of it; do not invent a route.
3. **The populated discussion, for the stranger.** Record the stranger's read of the thread the `canonical-about-thread` pointer names (`GET /v1/realms/{realm}/threads/{thread}?actingSubject=…`). On 2026-10-13 the live answer could not be published: `realm-thread-v1` gives `vote.value` as the numbers -1, 0 and 1 and the generated contract expects a string, so the record's guard refuses it. That repair is the api Goal's (mail key `zone-attached-realm-discussion-thread-vote-openapi`). If it is on `main` when you start, record the read; if not, record groups 1 and 2, hand off `partial` and name this read as what is left. Never loosen the guard or write an answer by hand.
4. No assertion changes and no cell changes state; no existing sample's label, request or order changes. `scripts/api/answer-records.guard.test.ts` passes. Give in the handoff each added sample (persona, label, method, path, status), the recording run's seconds, and any read the page makes that is still not recorded, with the reason.

Three recorded answers of this row are 503 `realm_reply_unavailable` under labels that call them refusals (`withdrawn-attachment-post-refused`, `review-required-post-refused`, `impersonation-refused`). They are reported to the api Goal; do not change them or the proofs that made them.

Do not build: a change under `apps/` or `services/`, a change to the recorder, the record's format or the guard, another row's record.
