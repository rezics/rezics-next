## Outcome

The G-1428 triage is in `.temp/ref/triage-g1428.json`. It found two failures
on main that belong to program.

1. **Forced color.** Some tests fail only when the caller's environment sets
   `FORCE_COLOR`, as Grok and Cursor worker shells do:
   - SEARCH12 in `tests/qa/unit/private-node-http-delivery-fence.test.ts`;
   - both cases in `packages/observability/tests/runtime.test.ts`;
   - `scripts/ops/tests/mail-check.test.ts`.

   They parse uncolored output, so in a forced-color shell they fail even
   though nothing is broken. The merge gate already deletes `FORCE_COLOR` for
   its shards. Make that a property of every run through `scripts/qa/test.ts`,
   so each child test process gets the same environment wherever it starts.
   Leave the tests themselves unchanged.
2. **The G-903 guard.** `services/main/tests/g-903-api-inputs.test.ts`
   ("integration requests never depend on owner SELECT results") has been red
   since 38000e004. It flags:
   - `tests/qa/integration/library-import-apply.test.ts`, line 124 into the
     row PUT at line 126;
   - `tests/qa/integration/slim-command.test.ts`, line 156 into 219, and 286
     into 306.

   Make those requests take their inputs from API responses, as the guard
   requires. Do not weaken the guard.

## Checks

- A unit test shows a child spawned by `scripts/qa/test.ts` sees no
  `FORCE_COLOR`.
- With `FORCE_COLOR=1` exported, `task test --` passes on the four files
  above.
- `services/main/tests/g-903-api-inputs.test.ts` passes.
- Both integration files pass on the shared stack.
