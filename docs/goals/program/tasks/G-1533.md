## Outcome

A worker may change files outside its claim (callers of what it changed), and
`land` refuses those changes when another task has claimed the files since.
Today `dispatch` and `reclaim` check only claims, so a manager can claim a file
that an exited, unlanded task already changed, and that task can then not land
until the new one does. This happened to a 129-file caller migration.

1. `dispatch` and `reclaim` treat the out-of-claim files committed by a holding
   task (exited, not yet landed or closed) as held by that task: they refuse a
   brief whose paths include one and name the task, the same way a claim
   overlap is refused.
2. `goalctl owner <path>` reports such a file as "changed by G-NNNN (unlanded)".
3. One sentence in `docs/goals/manager.md`: land the earlier task first or drop
   the path.

Acceptance: a unit test with a ledger holding an exited task whose branch
commits an out-of-claim file; dispatch of a brief claiming that file is refused,
and it passes once the task is verified.
