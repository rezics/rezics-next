## Outcome

G-2585 recorded the Realm ranking row on a wave/2 stack (QA `20261015t010857-4fadfd`, log in `.temp/ref/`). The `main.event.projection` worker faulted with `EventSourceUnavailable` at 01:10:49 and 01:15:30 UTC. Ranking preparation then never completed: the visitor case timed out at 420 s, and owner `POST /v1/member-reply-drafts` requests were aborted at the end. The worker-fault log carries only the class, and `services/main/src/modules/event/source.ts` raises it for four conditions: owner lineage unavailable or held, an invalid seek, a retained-journal batch gap, or a batch over its member bound.

1. Make worker faults log the error message and cause, so this is never undiagnosable again.
2. Reproduce it by running the ranking outcome and its preparation on a stack, if needed alongside the closure fixture, as the earlier passing run did. Name which condition fires and why.
3. Fix the cause. A projection worker that hits a transient source condition (a held lineage) retries within its bound; it does not stop projecting. A real gap or bound violation is a data or ordering fault, fixed at its source.

Add an owner test for the condition. Run the ranking outcome three times on a stack with no fault.
