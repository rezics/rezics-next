## Outcome

The Realm closure rows' API outcomes pass: `tests/qa/integration/outcomes/realm/closure-*.test.ts`, with the shared fixture `closure-fixture.ts`. Three browser journeys written on wave/2 still get different answers (evidence in `.temp/ref/`):

1. **Direct routes, threads, directory and Zone discussion** (`apps/web/tests/realm-route-closure.e2e.ts`, G-2563): setting up the closure, `POST /v1/moderation/decisions` returns `403 governance_denied`, "decision target is outside the reported evidence".
2. **Media** (`apps/web/tests/realm-closure.e2e.ts`, G-2565): `POST /v1/media/metadata` reports a cleared public reply-backed image as unavailable, even before the closure.
3. **Roster** (same file): after a completed closure, `GET /v1/realms/{closedRealm}/members?actingSubject={founder}` returns 200 with member identities.

For each case, decide from the row's API outcome and contract which side is wrong:

- **If the journey sets up or expects differently from the proved row** (for example, a decision without the report that admits its target, or an image not cleared as the outcome clears it), correct the journey to reach the state the way the outcome fixture does, through the public API.
- **If the API is wrong** (for example, a closed Realm's management roster disclosing members where the closure contract says it must not, or a cleared image refused), fix the API at its cause, and add or extend the owner test and the outcome cell for it.

Do not weaken any closure assertion. Then rerun both journeys and replace their `browser: missing(...)` entries in `scripts/qa/cases/launch-coverage.ts`.
