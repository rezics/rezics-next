## Outcome

G-2637 and G-2638 both reported that integration runs on wave/2 needed `REZICS_REALM_SOURCE_PREPARATION=1`. The shared Realm fixture is imported eagerly, which installs logging hooks outside Bun's test runner, and the QA bootstrap's test-hook import fails outside the runner. The final wave/2 confirmation runs integration files without that variable, so it would fail for this reason alone.

Make the shared Realm fixture load lazily: only when a test that uses it runs, inside the runner. Make the QA bootstrap import no test hooks outside the runner. Prove it:

- a closure outcome and a non-Realm integration file run on a stack with the variable unset;
- a unit test shows that importing the fixture module installs no hook.

Remove any documentation that tells workers to set the variable.

## Wave

Build task of **wave/2** (`docs/goals/wave.md` with `<n>` = 2): `git reset --hard wave/2`, rebase onto wave/2, push to `refs/heads/wave/2`. This blocks wave/2's confirmation. This task may start QA stacks. Run long commands through `task goal -- job`. When you park a job, end your turn with RESULT: parked.
