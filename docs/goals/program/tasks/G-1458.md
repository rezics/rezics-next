## Outcome

Owner unit tests start PostgreSQL with its socket at
`<checkout>/.temp/pg-sock/.s.PGSQL.<port>`. Linux allows 107 bytes for that
path. `regress.ts` already keeps its checkouts under the bound
(`postgresSocketSuffix`), but the merge gate does not check it.

In the scratch verification for the gate change (`331e14d54`), 10 files failed
`pg_ctl start` because the path was too long. The gate reported them as
inconclusive and did not block. A real failure in those files would have merged
unseen.

1. Move the bound into one helper shared by `regress.ts` and `goalctl.ts`.
2. Before the unit gate runs, check every tree it will run in: the task
   worktree and the baseline tree on current main. If any tree is too deep,
   refuse as a runner configuration error, naming the path and its byte length.
   Never report the result as inconclusive.
3. Find out how the scratch tree got that deep. The likely cause is goalctl
   running from inside a worker worktree, which nests `.temp/worktrees`. Then
   either make goalctl resolve the main checkout, or refuse at dispatch and
   gate with the same message.

## Checks

- A unit test shows the gate refusing a too-deep root and naming the path.
- A test shows that a normal `.temp/worktrees/g-NNNN` tree passes the check.
- Run `task goal -- test scripts/goal/goalctl.test.ts scripts/goal/regress.test.ts`
  and `task goal:typecheck`.
