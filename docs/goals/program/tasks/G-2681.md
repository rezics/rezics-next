## Outcome

`tests/qa/integration/outcomes/realm/closure-search.test.ts` fails intermittently in program confirmations:

- all six personas once, at wave/2 (`confirm-20261015t154135-643bb7`);
- one persona on main (`confirm-20261015t191105-845dae`, visitor).

The failure is `503 search_index_unavailable` ("Public text index is unavailable") where the outcome expects 200. The logs are under `.temp/goal-orchestration/confirm/<run>/qa/outcome-29/`.

Decide which side is wrong:
- **The test:** if the public index is documented as eventually available after a committed change, the test must wait for that stated condition through the API.
- **The product:** if a committed, published state should be searchable, the product must not answer 503 while it is ready.

Find which applies, fix it, and prove it with ten consecutive runs of the file under a normal QA slot. Do not lengthen a timeout or add retries that hide a 503.
