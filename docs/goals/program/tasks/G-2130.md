## Outcome

Whoever writes an outcome test, an implementation or a story learns what the API answers a persona in one command, and no longer writes a test file to find out. Today the six persona sessions exist only inside a test process (`tests/qa/support/personas.ts`); the staged reference `.temp/ref/persona-probe-facts.md` has the facts.

- **`task goal -- persona '<persona> <METHOD> <path> [json body]' ...`** runs the calls in order within one set of persona sessions and prints for each: the persona, the method and path, the status, the headers `location`, `retry-after`, `etag` and `cache-control` when present, and the JSON answer (sixty lines; `--full` prints all). `--private` makes the fixture Realm private. It prints the time of the set-up and of each call.
- **Placeholders.** `{realm}`, `{space}` and `{zone}` are the fixture's; `{1.id}` is a field of the first call's JSON answer by dotted path, so that a second call can read what the first created.
- **The call is checked before a stack starts.** A method and path that match no operation of the index (`scripts/api/operation-index.ts`) are refused with the nearest operation ids; an unknown persona and a broken JSON body are refused too.
- **It runs where tests run:** through the QA runner on a pooled stack, in one QA slot, as the probe test file of this task, which reads its calls from a file and writes its answers to a file. Leasing, reset and parking stay the runner's. It never calls the shared development backend.
- **`--record <file>`** writes the calls and answers as JSON for a story: the visibility and, for each call, the persona, `operationId`, method, path, request body, status and answer. The file holds no time, no run id, no bearer, no cookie and no session key, so that recording twice changes only what the API changed. A file outside the repository is refused.
- No bearer, cookie or session key is printed or written anywhere.

Do not build: a server that stays up, a change to the pool, to the runner or to `personas.ts` (name in the handoff what you needed from them and did not have), a story or a change under `apps/`, an owner field in the operation index.

## Checks

`task goal -- check`, and `persona.test.ts` once with `CLAUDECODE=1`. The unit tests cover the pure parts: parsing the calls, both kinds of placeholder, the three refusals, the sixty-line bound, and a record with a bearer and a cookie in its input and none in its output. Then two real runs, with their output and times in the handoff: a visitor's read of the fixture Zone, and an owner creating something that a stranger then reads through `{1.…}`, once with `--private`. Wait on a running command with one long call (`yield_time_ms: 300000`).
