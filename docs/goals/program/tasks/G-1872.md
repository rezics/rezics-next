## Outcome

Twice on 2026-10-11 a landing review blocked a new browser test for the same thing: a local `grant()` helper that writes `access.permission_grant`, `access.representation` and `access.scope_gate` rows directly instead of calling `grantFixtureAuthority` (`services/main/src/modules/access/fixture-authority.ts`), which refuses under a closed recovery fence or scope gate and is idempotent. Workers copy from existing fixtures, and 365 files outside `services/main/src/modules/access/` write those tables today (252 in `tests/qa/integration`, 46 in `services/main/tests`, 23 in `apps/web/tests`). A review round costs a worker session, a Sol review and a gate; a static check costs nothing.

Build one static guard, on the pattern of `scripts/static/docker-ownership.ts` with its test and debt file:

1. `scripts/static/access-fixture-writes.ts` scans TypeScript under `apps`, `services`, `tests`, `scripts` and `packages` for SQL that writes one of the three tables: `INSERT INTO`, `UPDATE`, `DELETE FROM`, `TRUNCATE` and `COPY ... FROM` naming `access.permission_grant`, `access.representation` or `access.scope_gate`, case-insensitive, in any string or template literal, including a table name built by a template with the schema inline. Files under `services/main/src/modules/access/` and migration SQL are outside the rule.
2. `scripts/static/access-fixture-writes-debt.json` lists every file that does so today, sorted, one path per entry. Generate it with the scanner; do not hand-edit.
3. The test fails when a file not on the list writes one of the tables (message: the file, the table, and "call grantFixtureAuthority from services/main/src/modules/access/fixture-authority.ts"), and when a listed file no longer does (so the list only shrinks). Two fixture files under `scripts/static/fixtures/access-fixture-writes/` prove a direct write is found and a file that only calls `grantFixtureAuthority` is not.
4. Register the test with the repository guards the merge gate always runs (find where `scripts/static/docker-ownership.test.ts` is selected; if guards are a list in `scripts/goal/goalctl.ts`, add it there with its test).
5. One sentence in `docs/goals/worker.md`, "Tests and checks": new fixtures grant access through `grantFixtureAuthority`; the guard refuses a new direct write.

Do not migrate any listed file and do not change `fixture-authority.ts`. If a legitimate writer exists outside the access module that should never migrate (for example a test of the tables' own constraints), leave it on the list and name it in the handoff; the owners decide later.
