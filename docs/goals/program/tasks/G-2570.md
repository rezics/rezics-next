## Outcome

A worker that builds the web app for a browser journey leaves `apps/web/dist/` in its worktree. That directory is ignored by `.gitignore`. Some repository guards still walk the file tree with `readdirSync` and scan those generated bundles, so they fail until the worker deletes the build output. G-2559 lost a round to this today, and every browser-journey task can hit it.

Fix the class, not one guard:

- Give the guards one shared lister of repository source files: tracked files plus untracked files that are not ignored (`git ls-files --cached --others --exclude-standard`, or the repository index in `scripts/lib/repo-index.ts` if it already lists them).
- Move every guard that walks the tree onto it: about 20 files under `scripts/static/` and `scripts/qa/` use `readdirSync`.
- Add a guard-level test: a worktree with an ignored `apps/web/dist/` holding a file that would violate a guard leaves every guard green, and the same file at a tracked path still fails.

Keep each guard's detection the same. The only change is which files are read. No guard may lose a file it reads today that is tracked or untracked-but-not-ignored.

The new test passes, `task guards` is green with an `apps/web/dist/` present, and `task goal -- check` passes. Report the guard run time before and after.
