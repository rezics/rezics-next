## Outcome

What `main` proves is read from a run on `main`, and not from what tasks declared. On 2026-10-13 `task goal -- scope` says `No regression confirmation run yet` beside 22 rows declared proved: the only run that records a confirmation (`recordConfirmation` in `scripts/goal/confirmed.ts`, called by `regress`) is the whole regression, which took 296 minutes and may not start while a worker is live. Meanwhile a row's fix changes other rows: a cell declared `pending` runs as `test.failing` (`tests/qa/support/outcome-test.ts:30`), so the fix of one vertical turns another vertical's outcome file red on `main`, and nobody runs it.

1. **`task goal -- confirm`** runs every outcome test file that a declaration on `main` names (`scripts/qa/cases/outcomes.ts` loads them), on a checkout pinned to `main`'s commit at its start, and records the confirmation as the regression does, with the run's commit and times. It is a bounded run and not a wide one: each file takes a QA slot like any task's test (`task goal -- test` does this for a worker), at most two at a time, so it runs beside workers and never waits for an idle host. A file that only timed out is run once more alone, as the unit gate does now. Reuse the regression's pinned checkout, manifest and evidence paths where they fit; do not add a second format.
2. **Each cell gets one of five readings:** passed, failed, pending and still failing, pending and now passing, not run. `scope` prints for each vertical the rows the run confirmed, and names each cell declared proved that failed and each pending cell that now passes, with the file.
3. **The pump starts it** (`settlePass` in `scripts/goal/settle.ts`, where queued briefs start): when no confirm run is alive, `main` has a commit after the last confirmed one that changes a file outside `docs/`, and ninety minutes have passed since the last start (a file `confirm-interval-minutes` in the state directory overrides it; `0` stops the schedule). The run is its own process and outlives the pump's pass; a run whose process died is seen as dead and does not block the next.
4. `task goal -- confirm --status` prints the last run's commit, age, counts by reading and whether one is running.

Events for the managers (a failed proved cell reopened, a passing pending cell to declare) are another task, after the planning event lands; print them in `scope` and stop there.

Do not build: a change to the whole regression's selection or admission, to the outcome harness or a declaration, a change of a cell's declared state by the tool, a retry of a failure that is not a timeout, a browser run.

## Checks

`task goal -- check`, and the four test files once with `CLAUDECODE=1`. The tests use a temporary repository with declaration fixtures and fixture test files and cover: the five readings; a newer run not replaced by an older one that ends later; the two-at-a-time bound and the slot released after a failure; the pump's three conditions and the override file; a dead run not blocking. Then run `CLAUDECODE=1 task goal -- confirm` once on the real state from your worktree and give in the handoff its wall time, its counts by reading and every cell that failed or newly passes. Wait on a running command with one long call (`yield_time_ms: 300000`).
