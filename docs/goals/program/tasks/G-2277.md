## Outcome

The reading page of `books/read-non-ui-languages-non-ui-languages` can be shown for every persona from the row's record, by the production readers. The first surface built from `tests/qa/fixtures/outcomes/books/read-non-ui-languages-non-ui-languages.json` could replay only the member's text: the page's first read, the Work's header, is recorded once without a caller and filed under the member, and a story replays a request by its persona, method, path and parameters. The record's ids change with each recording; the requests below are named by what they address.

All are `GET` without a body, as the page sends them. Confirm each against the readers the route `apps/web/app/[locale]/w/[ref]/read/page.tsx` calls under `apps/web/features/work-page/` (read them, change nothing there); where the page sends another parameter than written here, record what the page sends and say so in the handoff.

1. **The published Work's header, each persona.** `/v1/works/{published}` without a query for the visitor; with `actingSubject={persona}` for the stranger, member, owner, moderator and operator. Each under its persona and its own label.
2. **The selection the page asks next.** After each header of (1): `/v1/main-versions/{main}/selection` with `language={the header's selectedLanguage}` when that header selects a language and without the parameter when it does not, with the same caller. Follow the answer; do not assume the member's `sv` for another persona.
3. **The owner's private Work.** Its header with the owner's `actingSubject`, then the selection read the page makes when that header succeeds.
4. **The private Work refused.** Its header without a query for the visitor and with `actingSubject` for the stranger, member, moderator and operator: the refusal as the API gives it.
5. **Credits in a second UI language.** `/v1/works/{published}/credits?language=zh-Hant` for the visitor and, with `actingSubject`, for the member. The other UI languages are not recorded: a language of the interface is shown by one further language, not by seven.
6. **The reader's settings.** `/v1/reader/settings?actingSubject={persona}` for each signed-in persona whose header of (1) succeeds.
7. No assertion changes and no cell changes state; no existing sample's label, request or order changes. `scripts/api/answer-records.guard.test.ts` passes. The handoff lists each added sample (persona, label, method, path with parameters, status), the record's bytes and samples and the recording run's seconds.

Not recorded here: a chapter. The row's Work has no chapters and the row does not promise them, so the page asks none.

An answer of 500 or above is a fault of the API, not a state of the page: do not record it under a refusal's label; hand off `partial` with the request and the answer. If preparation answers 202 or 503, run it once more before handing off.

Do not build: a change under `apps/` or `services/`, a change to the recorder, the record's format or the guard, another row's record.
