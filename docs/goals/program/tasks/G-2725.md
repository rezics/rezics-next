## Outcome

A gate that runs tests in shards concatenates their outputs, but timeout parsing reads only the last JUnit block (`scripts/goal/unit-gate.ts:1920`, parser at `:515`). An earlier shard's timeout disappears, so surface adjudication skips the candidate's isolated retry and compares the candidate against a passing main. G-2338's landing gate stayed red that way: `web-page-filtering.test.ts` timed out at 7.8 s in an eight-process guard batch, and the only passing run was main's baseline (`.temp/goal-orchestration/merges/surface-gate/run-LShfsn/`). G-2466's landing gate failed the same way at about 15:10 UTC (`.temp/goal-orchestration/merges/surface-gate/run-B4EyZ9/`).

The two policies also differ. Unit adjudication confirms a failure and accepts an isolated recovery (`unit-gate.ts:2065`). Surface adjudication mainly retries timeout-only files (`surface-gate.ts:211`). So G-2461's readiness-assertion failure in `tests/qa/unit/core.test.ts:786` never got a candidate confirmation. Aggregate every shard's report, and give unit, guard and surface adjudication one rule for confirming a candidate failure. A timeout that persists when the file runs alone stays inconclusive, and an assertion is never retried as a timeout.

Unit tests: a timeout in the first shard with a pass in the last; mixed assertion and timeout failures; a persistent isolated timeout that stays inconclusive; and the same outcome from the unit, guard and surface paths. `task goal -- check`.
