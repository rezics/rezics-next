## Outcome

Scheduled main confirmations (`scheduleConfirmation` in `scripts/goal/confirm.ts`) twice overlapped the wave/3 candidate confirmation on 2026-10-16, costing about 35 minutes of wall time (`.temp/ref/report.md`, section 3). Stopping a confirmation by SIGTERM did nothing; killing it left its lanes' QA stacks running without an owner, and they had to be removed by hand.

Make a requested confirmation (`task goal -- confirm`, with or without `--at`) take priority over a scheduled one. If a scheduled run holds the lock, the requested run stops it between outcome batches and starts. A scheduled run never starts while a requested one is running or queued. Make a confirmation stop cleanly on SIGTERM or SIGINT: it stops its lanes, each lane removes its QA stack, the lock is released and the partial record says it was stopped. Keep one active confirmation at a time.

## Checks

Unit tests for preemption, for no scheduled start while a requested run is active, and for clean stopping, using the existing confirmation test doubles. One real run: start a scheduled confirmation, request one with `--at`, and show one active run, the requested run admitted within one batch, and no QA stack left without an owner. `task goal -- check`.
