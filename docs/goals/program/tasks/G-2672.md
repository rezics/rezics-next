## Outcome

Adding `codexCompactTokens` to the main checkout's `.goalctl/settings.json` made goalctl refuse every command in worktrees whose code predated the field: "settings.codexCompactTokens is unknown". `scripts/goal/config.ts` reads both layers from the main checkout, through the common git directory, and rejects unknown fields (`additionalProperties: false`). A worktree runs its own code against settings written for newer code.

Make the loader correct across code versions:

- **Shared layer.** Read the tracked `settings.json` from the worktree's own tree, so it always matches that tree's code and schema.
- **User layer.** Read `settings.user.json` from the main checkout, because it is machine-local and untracked. An unknown field in it is ignored, with one warning naming the file and field. Known fields are still validated strictly.

Then put Sol's compaction limit back into the shared `.goalctl/settings.json` (it equals the code default, so behaviour does not change).

Prove it with tests: a worktree with older code and a user file carrying a newer field loads with a warning; an invalid value of a known field is still refused; each worktree reads its own shared file.
