## Outcome

The wave's prove phase (docs/goals/wave.md) runs every row's outcome tests once, on `wave/1`, while the host runs nothing else. Today `confirm` always pins `main` and runs at most two lanes. Its last full run took 4.5 hours.

What must be true afterwards:

- `task goal -- confirm --at <rev> [--lanes <n>]` pins the commit `<rev>` resolves to and runs the same outcome file selection, read from that checkout's declarations, with `n` lanes (default as today, at most the QA slot count). Without `--at`, behaviour is unchanged.
- A run pinned to a commit other than `main`'s tip writes its manifest and its own `confirmed.json` in its run directory. It never replaces the state directory's `confirmed.json`: the judge stays main's.
- At its end, such a run prints one summary: counts per reading (passed, failed, pending and still failing, pending and now passing, not run), then one line for each cell that is failed or not run, with row, persona and file. `confirm --status --run <id>` prints the same for a finished or running run.
- The confirmation lock still allows one confirmation at a time, so the scheduled run on main does not start during a wave run.
- docs/goals/wave.md's prove-phase paragraph names the command.

Tests, with the fake runner and prepare the existing tests use: `--at` pins that commit; the judge file is unchanged after a non-main run; `--lanes` sets the lane count and refuses 0 or more than the slot count; the summary lists a failed cell; behaviour without `--at` is unchanged.

Do not build: a change to the cell classifier, to slot or start-up admission, or to which files a confirmation selects.
