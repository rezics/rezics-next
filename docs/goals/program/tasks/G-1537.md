## Outcome

Read `.temp/ref/G-1522.md`, finding 8.

1. **Affected plan.** `goalctl` copies the affected planner's input loading
   (script manifests, graph sources, Dockerfile inputs), formats the plan as
   text, then pulls the selected files back out with a regex. Let
   `scripts/qa/affected.ts` take explicit base and changed-file inputs and return
   the typed plan, and have `goalctl` read that plan, as `scripts/qa/test.ts`
   already does. Text formatting is for people only.
2. **JUnit.** Decode testcases once, in `scripts/qa/acceptance.ts`, with failure
   details and the timeout metadata added for hanging files, and have `goalctl`'s
   report reading use it. Keep `goalctl`'s appended-report selection and its
   pinned-checkout fallback; they are not `parseJUnit`'s job.

Acceptance:
- Changing the text format cannot change the selected files (test).
- The missing-report, self-closing testcase, spoofed transcript and absolute-path cases stay covered.
