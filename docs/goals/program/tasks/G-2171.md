## Outcome

A worker whose session ends in the middle of its work goes on by itself. On 2026-10-13 two Sol sessions ended their turn while a check was still running, with a progress sentence as their last message and no handoff (G-2151: `I'm still waiting for the verification runs.`; G-2158 the same way, with three commits and six changed files in its tree). The tool recorded `worker handoff is missing or reports an error`, raised a manager event (a turn of about 500,000 input tokens) and waited for a hand to run `resume`.

1. Where an ended attempt is read (`scripts/goal/tasks.ts:128` to `:176`, beside the continuations for a refused capacity and a dropped transport): when the session ended cleanly, its last message is not a handoff (no `RESULT:` line) and the task is still open, continue **the same session** once with one short note: the turn ended before the handoff, nothing else changed, a command it started may have ended meanwhile; go on and finish with the handoff, waiting with one call of `yield_time_ms: 300000`.
2. The attempt is recorded as a continuation with `continuedFor: 'handoff'` (`scripts/goal/types.ts:29`); it is no fix round and no first attempt in the measures (`scripts/goal/measures.ts:141`), which count it as their own kind.
3. At most one such continuation follows another without a handoff between them. A second ending without a handoff is what happens today: the reason is recorded and the manager's event is raised.
4. A session that ended on an error, a refused capacity, a dropped transport or a `stop` is untouched: those paths stay as they are.

Do not build: a change to the worker's prompt or protocol, a watchdog on a running session, a change to `resume`, to the handoff's format or to the landing.

## Mechanisms

none

## Checks

`task goal -- check`, and the test file once with `CLAUDECODE=1`. The test covers: a clean end with a progress message is continued in the same session and recorded as `handoff`; a second such end raises the reason and no third attempt; an end with `RESULT: done`, a stopped task and a closed task are not continued; the measures count the continuation as its own kind. Wait on a running command with one long call (`yield_time_ms: 300000`).
