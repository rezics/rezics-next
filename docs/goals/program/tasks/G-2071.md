## Outcome

An outcome test gets the six personas' sessions on a real stack with one call,
through the public API only (docs/goals/method.md, "The unit of work").

`tests/qa/support/personas.ts`: one call returns `{ visitor, stranger, member,
owner, moderator, operator }` and the Realm and Zone they relate to, for a public
or a private Realm. Each is a session that calls Main and Account over HTTP as
that person: visitor has no credentials; stranger is signed in with no relation;
member joined the Realm; owner created it; moderator holds its moderation role;
operator has platform authority. Build them the way a person would (sign up,
join, grant a role through the API); only what no API can do goes through
`grantFixtureAuthority`. State what one call costs in seconds.

A repository guard refuses a file under `tests/qa/integration/outcomes/**` that
imports from `services/*/src/**` or `apps/*/src/**`, or calls `mock.module`.

Proof, on a real stack, `tests/qa/integration/persona-sessions.test.ts`: each of
the six sessions reads one resource of a public Realm and one of a private
Realm and gets what its relation allows. Where the code's answer for a persona
surprises you (the operator on a private Realm, say), report it in the handoff
and assert what the code does; do not change product code.

Reuse the integration tier's stack entry and `tests/qa/support/{joining-auth,org-realm,managed-organization}.ts`.
Do not build a second way to start a stack, a new tier, a DSL or helpers for one
vertical, and do not touch `scripts/qa/cases/**`: another task adds
`outcomeTest(declaration, persona, fn)`; your sessions are what its `fn`
receives, nothing else is needed from you.
