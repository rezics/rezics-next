## Outcome

Every database pool that `tests/qa/support/personas.ts` hands to code that runs as the product (the persona runtime and its request path) is built by production's own factory, `boundedPool` in `services/main/src/infrastructure/pg-pool.ts`, with the arguments production passes in `services/main/src/index.ts` and no bounds of the fixture's own. A session taken from the fixture's Content pool then answers production's `idle_in_transaction_session_timeout`, not `0`.

Why: the staged `.temp/ref/media-final-diagnostic.md` (the api Goal's media row, QA `20261013t220534-52bf10` on accepted main) shows the byte PUT refused with 503 because the fixture's Content session reported `idle_ms: 0`; the media guard was right and the fixture was not production. On main the fixture builds four plain pools (`new Pool(...)` for Account, Access, Content and the Account relay, near line 212, and one more near line 137).

- Replace each plain runtime pool by `boundedPool` as production calls it. A pool the fixture uses only for its own preparation SQL, never handed to product code, may stay plain; say for each which it is, in the handoff.
- The class, as a test: `scripts/static/qa-runtime-pools.test.ts` fails when a file under `tests/qa/support/` constructs a `Pool` directly, except for an explicit list in that test in which every entry carries its reason. It must fail on main as it is today and pass with your change.
- Change no assertion of any outcome test, nothing in the media guard and nothing under `services/`.

Do not build: a second pool factory, a wrapper around `boundedPool`, a change of `CONNECTION_BOUNDS`, a change to another support file's behaviour beyond what the test above names in its list.

## Checks

The three `tests` of the front matter; `create-a-realm` is the proof that persona sessions still work with bounded pools. One stack run should cover both integration files; pass them in one command. If a persona session now ends on a bound (an idle-in-transaction kill), that is a finding about the fixture's use of a transaction: report the statement and stop, do not loosen the bound.
