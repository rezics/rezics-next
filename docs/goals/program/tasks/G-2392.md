## Outcome

The web's surface for `recipes/read-a-recipe` replays this row's record through the production readers. The production page sends reads the record lacks. Why they are reached: the recorded Recipe's `entity-page-v1` lists `contents`; `hubPlan` (`apps/web/features/work-page/hub.ts`) therefore draws the hub's `parts` section; `Parts` (`apps/web/features/work-page/hub-sections.tsx`) renders `SeriesProgressPanel` for every signed-in reader; and that panel and its children (`apps/web/features/tracking/series-progress-panel.tsx`, `medium-progress.tsx`, through the client in `apps/web/features/tracking/api.ts`) read on mount.

What must be true afterwards:

- For the stranger, member, owner, moderator and operator the row's test records every read that panel sends on mount for this Recipe, with the path, query and headers the production client sends: the edition preference, the editions, the relations, the `correspondence-equivalent` lexicon definition and the series summary, and the medium or episode progress read only if the reader actions this Recipe answers carry that tracking capability. Take each request from the production client, not from this list; a request production does not send for this Recipe is not recorded, and say which listed one that was and why.
- This is meant to be the row's last re-recording for the surface. So before recording, read the whole production path of the page once (the frame, the Work page's server reads, and every client component the hub draws for a Recipe that reads on mount) and compare with the record's labels per persona; record every read still missing, for the visitor too, and list in the handoff the ones you added beyond the panel.
- No assertion and no cell changes; existing samples keep their answers apart from identities. The handoff names old and new identities and every new label with its request and status.
- A read answered 5xx: hand off with the request and the answer; do not vary it. The run's log names slow requests under `[persona-request]`; quote those lines if a proof runs into its limit, and do not run a third time.

Do not build: a change under `apps/web/` or `tests/qa/support/`, a new row, a request with another persona's bearer.
