## Outcome

`task goal -- regress --nightly` runs the non-browser tiers and exactly one
browser journey for each of the eight verticals of the scope registry (`kind` in
`scripts/qa/cases/launch-coverage.ts`), and nothing else in a browser: no other
e2e file and no Storybook run. The default selection stays as it is.

- `scripts/qa/cases/vertical-journeys.ts` names the journey for each vertical:
  an existing e2e file and test title, chosen from the rows' `browser` proofs as
  the one that walks the vertical's main path (find, open, act as a signed-in
  person). A vertical with no journey that passes today is `missing` with the
  reason. Write no new journey.
- Each named journey passes on `main` from a clean QA profile. A journey's setup
  fails there today ("Safety responders are not configured", "Work name scope is
  not prepared", recorded in docs/goals/web/state.md): the profile's preparation
  is part of this task. The QA harness files are the program's; for one outside
  your claim ask `task goal -- owner <path>`, change it minimally when it is
  unclaimed and list it under OWNER CHANGES.

Do not build new journeys, a retry layer or visual checks. Browser runs take the
heavy lock (`task goal -- test --heavy`). A main-wide regression is running on
this host: wait on a run with one long call (`yield_time_ms: 300000`), never by
polling.

none

## Checks

`regress.test.ts` cases for the `--nightly` selection; each named journey run
once with its test filter, results pasted; the scripts type check; `task guards`.
