## Outcome

Since the platform gates (T5) closed 247 Main operations by default, a fresh
QA browser stack has no first platform administrator:
`scripts/dev/web-auth-bootstrap.ts` and `appEnvironment` in
`scripts/dev/config.ts` never set `PLATFORM_FIRST_ADMIN_ACCOUNT`, and
`scripts/qa/e2e.ts` never designates one. Every journey or seed that touches a
closed group (saved views, catalogue import, platform admin, themes) has to
bootstrap its own grant authority; launch wrote a local workaround
(`apps/web/tests/platform-grant.ts`).

1. QA stacks started by the harness (integration, e2e) and the shared dev
   stack (`task dev`, through `appEnvironment`) designate one known test
   account as the first platform administrator, through the existing
   mechanism in `services/main/src/modules/access/platform-administrator.ts`
   and `services/main/src/config.ts` (read both; do not change them). That
   account holds `platform:grant` and nothing is opened by default.
2. One shared helper, `tests/qa/support/platform-grant.ts`, lets a journey,
   seed or integration test give a named principal `platform:use:<group>`
   through the public grant API as that administrator, and revoke it again.
   It is the one way tests open a closed group; journeys that only need
   public operations never call it.
3. Production stays as trust-ops' deployment wave defines it: nothing in this
   task sets a first administrator outside local dev and QA profiles.

Then tell the handoff which existing local workarounds the helper replaces
(launch's `apps/web/tests/platform-grant.ts`, the seeds in
`apps/web/tests/identity-pages-seed.ts`, `scripts/datasets/bootstrap.ts`):
list them; launch and kernel migrate their own files.

## Read

`services/main/src/modules/access/platform-administrator.ts`,
`services/main/src/config.ts` (`PLATFORM_FIRST_ADMIN_ACCOUNT`),
`services/main/src/index.ts` (where it is applied),
`scripts/dev/config.ts` (`appEnvironment`), `scripts/dev/web-auth-bootstrap.ts`,
`scripts/qa/e2e.ts`, launch's `apps/web/tests/platform-grant.ts` for the need,
`scripts/ops/tests/platform-governance.integration.test.ts` for how the
designation behaves.

## Do not

Change the Access module, the gate, the exposure declarations or any product
route; open a group by default; give the test administrator more than
`platform:grant`; edit `apps/web/**` (launch's area).

## Checks

A unit test that `appEnvironment` sets the first administrator for dev and
QA profiles only; an integration or e2e run in which a fresh QA stack's
journey opens a closed group through the helper and is refused without it.
Run through `task goal -- test --heavy <file>`.
