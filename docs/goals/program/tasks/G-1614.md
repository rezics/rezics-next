## Outcome

Neither the QA CLI nor the goalctl unit gate passes `--timeout` to `bun test`, and the repository has no `bunfig.toml`. So every owner, integration and fault test runs under bun's 5 s per-test default. Those tests start embedded PostgreSQL, Fuseki or a whole stack.

On 10-10, at load 15–30, three passing cases failed only on that default:
- `services/main/tests/model-generation-custody.test.ts`, at 5000 ms;
- `services/main/tests/comment-source-erasure.test.ts`, at 5000 ms;
- `tests/qa/integration/semantic-reasoning.test.ts` (MODEL19/MODEL20), at 6.9 s.

Kernel measured the last one: no phase grew, it was the default. One case now carries an explicit 15 s, which is a per-case patch.

1. **Tier defaults.** Each tier passes one per-test `--timeout`, defined in one table beside the tier budgets. `unit` keeps 5 s. `owner` gets 30 s, and `integration` and `fault/recovery` get 60 s. The goalctl unit gate (`runUnitGate`) uses the same table for the tier it runs, not its own constant.
2. **Explicit cases still win.** A case that sets its own timeout, or calls `setDefaultTimeout`, keeps it. Cost and latency claims belong in the cost contracts and budget assertions, not in bun's default.
3. Note the table and its reason in `docs/testing/complexity.md`, next to the tier budgets.

- A case sleeping 7 s passes in owner and fails in unit.
