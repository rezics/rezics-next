## Outcome

G-1407 made every process with an inherited reap scope remove that scope on
exit, SIGTERM and SIGINT: `docker ps` with the label filter, `rm -f`, a fixed
1 s settle (`reapSettleMs`), then the same again. It does this even when no
descendant ever started a container. Under the merge gate's environment
(`AGENT=1`, the reaper preload and inherited `REZICS_REAP_SCOPE`/`SCOPES`),
`tests/qa/unit/core.test.ts` "QA slots: SIGTERM, SIGINT, process exit, errors
and the run deadline release leases" now times out at its 5000 ms limit. Its
child processes each pay that cost. It fails every gate that selects
`core.test.ts` (trust-ops G-1344 and kernel G-1379, 2026-10-08).

Make cleanup cost proportional to the work:
- When the shim adds labels to a `run` or `create`, it first creates an empty
  marker file for each scope in the chain in a state directory. The runner
  that mints the owner passes that directory as `REZICS_REAP_STATE`, under
  `.temp/reap/<owner>/`, and children inherit it.
- Removing a scope checks for its marker first. With no marker, it makes no
  Docker call and no settle wait, and returns at once. With a marker, it
  behaves as now, then deletes the marker.
- The dead-owner sweep is unchanged, and it also deletes the state directories
  of dead owners.
- Do not change the test's 5000 ms limit or any assertion in `core.test.ts`.

## Checks

- Unit: removing a scope with no marker makes no Docker call.
- Unit: a shim `run` creates markers for the whole chain, and removal then
  deletes the container and the marker.
- The exact gate-environment reproduction passes (run from the main checkout):
  `AGENT=1 REZICS_REAP_PRELOAD=1 REZICS_REAP_SCOPE=g1418-core REZICS_REAP_SCOPES=g1418-core task goal:unit-files -- --preload=scripts/qa/container-reaper.ts tests/qa/unit/core.test.ts`.
  Report pass and fail counts.
- The real nested-cancel and timeout probes from G-1407 still remove their
  containers, and no labelled container remains afterwards.
