## Outcome

The host holds 247 Docker volumes attached to no container.
- **Fixture generations:** 145 are `rezics-fixture-fx-*`, including 34 `fx-medium` generations. Every build adds one, and nothing removes the ones a current restore can no longer use.
- **Abandoned stacks:** the rest come from test stacks created before the QA reaper existed, such as `rezics-catalogue-g1038`, `rezics-owner-erasure`, `rezics-obs-verify`, `rezics-sys13` and `rezics-ops-*`.

1. **Prune command.** Add one command, `task fixture:prune` (dry run by default, `-- --apply` removes), that removes a fixture generation's volumes and its `.temp/fixture/<id>` directory when no current consumer can restore it. A generation is kept when any of these hold:
   - Its id is the current build id for its size, computed the way `fixture:build` computes it.
   - Its id is listed in `PINNED_FIXTURE_IDS` in `scripts/fixture/stack.ts`. `LOAD_FIXTURE_ID` and `PHASE_D_FIXTURE` import their ids from that list, and prune keeps exactly those ids.
   - Its manifest marks it retained. The erasure campaign's retained backups are like this; check how `erasure-campaign-qualification` selects them.
   - A running container uses it.
2. **Abandoned projects.** The same command lists volumes whose compose project is neither the dev stack (`rezics-dev`) nor a kept fixture, and removes them under `--apply`. It does not list or remove a `rezics-qa-*` project; those volumes belong to the QA reaper and `stack:reset`. Do not touch volumes without a compose project label; list them separately.
3. **Prune after build.** `fixture:build` prunes superseded generations of the same size after a successful build, so the count stays bounded without anyone running the command.
4. Run the dry run on this host and put its listing (kept with reason, and removed) in the handoff. Do not run `--apply`; Program applies it after review.
