## Outcome

A test run is never ended by the time it spent waiting to start. A run's deadline (`runDeadline` in `scripts/qa/core.ts`, read in `scripts/qa/cli.ts` through `qaMemoryDeadline` from `REZICS_QA_MEMORY_DEADLINE`, or six hours) is an instant fixed before the run is admitted. On 2026-10-13 a run with a ten-minute bound waited 384 s for memory (`QA_MEMORY_WAIT_END 623907-1 384087`), was admitted, and ended in the same second with "QA run reached its deadline; releasing QA leases": no stack started and no test ran (QA `20261013t190753-d07e48`). Two tasks lost a whole attempt each this way while the queue held twelve runs.

1. **The bound is for the work.** Time a run waits for a slot, for memory, for its turn to start or for a lease does not count against its deadline: the deadline is carried as a remaining duration that runs only while the run is admitted, or is moved by each wait as the wait ends. Find every place that sets or inherits the instant (the worker's check, the landing's gates, the scheduled run, `scripts/load/cli.ts`) and say in the handoff which bound each one means; where the limit is written in a file outside this claim, name the file and the line and change nothing there.
2. **Waiting has its own bound.** A wait still ends: the waiter's own deadline stays as it is (six hours for a heavy run today), and a run that is never admitted fails with a message that says it waited, for what and for how long, never "reached its deadline" as if it had run.
3. **Preparation stays under ten minutes.** The ten-minute ceiling of restore, startup and readiness (`docs/storage/workload-budgets.md`, "Data preparation and import") is measured from admission and does not grow.
4. Decided in code and tested without Docker or a stack, with the clock as a parameter: a run admitted after a wait longer than its bound gets its whole bound; a run that works past its bound is ended as now; two waits in one run (memory, then a lease) both leave the bound whole; a waiter never admitted ends on the waiter's bound with the waiting message.
5. The handoff gives the result of one real run on this host that waited before it started: seconds waited, seconds of work, the bound, and that it was not ended.

Do not build: a longer bound anywhere, a change to admission's order or to what a stack needs, a change under `scripts/goal/` or to `scripts/qa/memory-admission.ts` (another task holds it).
