## Outcome

At 06:16 UTC on 2026-10-15, 21 QA stack start-ups waited 30 to 40 minutes with none admitted. The head of the start-up queue in `/tmp/rezics-qa-memory-startup.sqlite` was `bun scripts/dev/cli.ts stack:up --profile qa --run-id 20261015t053626-f9ec1c-e` (a browser journey from a fresh worktree on main), running with `GOAL_IN_SLOT=0` and no start-up promise outstanding. Killing it admitted the next start-up at once.

The same deadlock was seen at 03:27 and 04:31 UTC on 2026-10-14 and was thought fixed by G-2434. So the class remains in main's harness: a waiter without a QA slot at the head blocks waiters that hold slots, while it waits for a slot those holders will not release until they start.

Find the order inversion in start-up admission and the QA slot code (the files that use `startup_waiters`). Fix it so a slot-less start-up never heads the queue ahead of slot holders, either by taking its slot before entering the start-up queue or by yielding the head. Keep one shared order for memory and slots.

Prove it:

- a unit test with injected clocks that builds the exact inversion and shows it now drains;
- a live check with several concurrent journeys and owner runs on this host.
