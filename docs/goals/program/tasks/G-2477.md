## Outcome

Measured on 2026-10-14: 43% of worker input from 21:49 to 05:23 UTC was waiting steps, mostly a worker polling its own `task goal -- test` or `task goal -- check` while the run queued for a QA slot, for memory, or behind another start-up. At 05:30 UTC, 14 of 40 live workers sat in QA queues. Each poll resends the whole context, and a waiting worker holds one of the 40 live places.

What must be true afterwards:

- Inside a worker attempt, `task goal -- test …` and `task goal -- check …` start the run under the tool, outside the worker's session, and return at once. The output is one line: the run's id, and that the worker ends its turn now with the handoff's first line `RESULT: waiting <run id>`. The run keeps the same admission, slots, deadlines and result files it has today. Outside a worker attempt, both commands behave exactly as now.
- An attempt that ends with that handoff is parked. It is not a failed attempt, it does not count toward the attempt number briefs reason about, and it does not count against `GOAL_MAX_WORKERS`. `status` lists each parked task with its run and how long the run has waited.
- When the run ends (passed, failed, refused, or past its deadline), the tool resumes the same session on the same engine and account with one message. The message holds the command, the exit code, the summary lines the command prints today, and the paths of its log and result files. Resuming waits for a live place like any resume. A run that dies or cannot start resumes the worker with that fact. If the session cannot be resumed, the task's Goal gets the mail it gets today for an ended attempt.
- A worker may park more than once in an attempt. Two runs at once from one worker are refused with a clear line.
- `docs/goals/worker.md`: the paragraph on waiting with `yield_time_ms` is replaced by the new practice, in the same change.

Tests use a fake engine and a fake QA command: park and live count, resume on a pass and on a failure, a run that dies, the same account on resume, a second park in one attempt, the refused concurrent run, and unchanged behavior outside a worker. Existing goalctl tests pass unchanged.

Do not build: a change to QA slot or start-up admission (`scripts/qa/core.ts` is claimed elsewhere), a change to how engines run, or a new handoff field other than `RESULT: waiting`.

## Checks

`task goal -- check`. This task's own runs are outside the parked mode until it lands: wait on a running command with one long call (`yield_time_ms: 300000`).
