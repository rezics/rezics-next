## Outcome

`task goal -- status` reports a first-attempt share that mixes unrelated causes. `scripts/goal/measures.ts` counts every repeat attempt as a fix round unless it is a capacity, transport or handoff retry or a step after a partial handoff. Most repeat attempts are wakes after a parked job, and many follow a passing job. Of 1,650 program fix rounds, 1,426 were job wakes. The classification is in `.temp/ref/fix-classes.txt`, and it was built from handoff keywords because no recorded class exists.

Record the cause where it happens and count from the record:

- When a QA tier or integration file fails, the harness records one class: `assertion` (a test ran and failed), `timeout` (the budget was exceeded), `environment` (the stack, a dependency connection, a missing prepared corpus or a preflight refusal), or `harness` (the QA tooling itself failed). The message names the class instead of "failed or exceeded". `scripts/qa/cli.ts` already knows `result.timedOut`.
- A job's report carries the class of its first failure, or `passed`.
- The measure splits what is now `fixRound` into these counts: `jobWake` (by the woken job's result: passed, or each failure class), `baselineRed`, `environment`, and `fixRound` for everything else. The first-attempt share is `first / (first + fixRound)`. Status shows each count, and the today and whole-run figures.
- Status still prints unclassified attempts visibly, as it does now for inferred fix rounds.

Only goalctl and the QA harness change. Ledger, mail and job record formats stay readable by older worktrees.

## Checks

Unit tests for each class at the point where it is recorded and in the measure. Run `task goal -- status` against the live ledger and report the new counts for the program Goal in the handoff. `task goal -- check`.
