## Outcome

These two unit files guard the landing gate of every Goal, and they pass or fail with the host. On `main` at `240c4f601`, 2026-10-14 00:02 to 00:07 UTC, three runs minutes apart:

| Test | Run 1 (load 63) | Run 2 (load 55) | Alone |
|---|---|---|---|
| `clone keeps its active copying budget after a longer admission wait` (parent) | fail: `activeElapsedMs` 408, bound 350 | pass | fail (905 ms test) |
| `dev CLI waits past its readiness budget and gives Compose the full timeout after admission` (budget) | fail: `now` 900000, expected 400000 | pass | pass |
| `search rebuild waits past its readiness budget …` (budget) | fail, the same | pass | pass |
| `three startup waiters start in arrival order even when the newest polls first` (budget) | fail: 60 s limit | pass | pass |

A failure here stops another Goal's landing and costs a manager's ruling each time; this evening it stopped the web's surface gates.

What must be true afterwards:

1. Each of the four is decided by what the code does, not by how fast the host runs it. Find each cause first and say it in the handoff: the first compares a real elapsed time of a real child with an absolute bound of 350 ms; for the other three, find why an injected clock reads the deadline (900000) or why a waiter never proceeds in one run and not the next. A shared file, a real timer beside the injected clock or state left by an earlier test in the same process are the candidates; prove which.
2. No assertion in the two files compares a real elapsed time with a bound. Where the subject is a real child process, assert order and the values the child reports; where it is a budget, inject the clock and the sleep. `scripts/qa/stack-startup.ts` may take an injected clock for this; its behaviour for callers that pass none is unchanged.
3. What each test guards stays guarded: say for each one the regression it would still catch, and show it by breaking the code once (revert before the handoff).
4. Each file passes 20 consecutive runs, alone and with the other in one `bun test` process, while the host is busy. Give the host's one-minute load for the first and last run.

Do not build: a longer time limit, a retry, a skip, a change to any other test file. If the cause sits in `scripts/qa/memory-admission.ts` (another task holds it), hand off `partial` with the cause and the line.
