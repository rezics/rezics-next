## Outcome

`realm/ranking.test.ts` fails whenever its run crosses a UTC day boundary. In confirmation `confirm-20261016t231651-8df284`, the retained Realm discussion source was built at 23:55:49Z, recording all 12 scores in the 2026-10-16 day bucket. Main read the ranking after midnight. `readRankingPage` selects the current bucket (`services/main/src/modules/rankings/read.ts`), so every persona saw an empty Best and Top. An unchanged rerun on 2026-10-17 passed. The same applies to week and month boundaries. The evidence is under `ranking` in `.temp/ref/ranking-boundary-diagnosis.json`, and the retained database cut is in `.temp/ref/ranking-boundary-cut.json`.

Make the ranking acceptance deterministic across bucket boundaries. One option is a QA clock carried through source construction and consumption. The source build deadline is one hour, so waiting for a boundary to pass is not acceptable. Production reads keep the wall clock. Any clock override is admitted only by QA stacks, and refused at startup elsewhere. Keep every ranking assertion. A genuinely missing score or admission must still fail.

none

## Checks

A replay that builds the source before a UTC day boundary and reads after it fails before the fix and passes after it, on a fresh stack and on a reset and parked stack, with all six personas. A replay with a missing current-bucket score still fails. `task goal -- check`.
