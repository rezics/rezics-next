## Outcome

A reader of the Books Zone's browse page sees what the API answered. This is the first surface built by step three of the method, and it proves the path once before twenty surfaces follow: the row's record, the typed client, the web's own reader, the page, the surface gate. The row is proved for all six personas, who get the same public catalogue. The design note (staged as `.temp/ref/surface-design-note.md`; sections 3, 6 and 7) was read by the program on 2026-10-13.

1. **One function builds the page from the answers.** `RealmBrowseRoute` (`apps/web/features/realm/routes.tsx:265`) reads `readZoneBrowse` and `readFacets` and builds the model inline. Move the step from those two answers to what `ZoneBrowse` renders into `apps/web/features/realm/browse-page.tsx` (or `.ts`), and have the route use it with no change of behaviour, so a story runs the code the route runs. Extract only that: the release filter and the year header stay where they are. `browse-page.test.ts` covers the function on a recorded answer and on a refusal.
2. **Stories in `apps/web/features/zones/books-catalogue-browse.stories.tsx`,** each fed by the row's record (`tests/qa/fixtures/outcomes/books/catalogue-browse-and-search-in-its-zone.json`) through the replaying fetch (`apps/web/features/stories/recorded-fetch.ts`) and the web's own typed reader, never by props written by hand: populated (the recorded results, their count, the sorts, the continuation), a search with results, empty (the recorded answer with no match), error (the recorded `400 unsupported_query_shape` and what the page shows for it), loading (the call held unanswered). Pending has no story: this read answers `200` or a problem and never `202`. One story for each state. The six personas get one answer, so each state takes one persona's sample and the story's name says which.
3. Each story asserts what a reader can see (a recorded title, the recorded count, the empty text, the refusal) by role or by text, and takes no snapshot.
4. **The gate is measured.** Run `task goal -- check` and give in the handoff the seconds it prints for each part (contract, web types, lint, units and guards, stories) and the seconds each waited for a slot. The program widens to twenty surfaces on these numbers.

If the record lacks an answer that a state or the route needs (a supporting read, a search with no match), do not edit the record and do not write the answer by hand: hand off `partial` naming the request that is missing, and the row's outcome test adds it.

Do not build: a change to an operation, to the record, the replay or the gate; stories for another row or vertical; a redesign of the browse page, its filters or its year header; a screenshot baseline; a browser journey; a migration of the existing stories.
