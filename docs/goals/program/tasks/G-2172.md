## Outcome

A fix to the harness reaches the workers that are already running. A worker runs the Goal tool and the QA harness from its own worktree, so a tree started before a fix keeps the fault. On 2026-10-13 the race in the shared directory lease (`scripts/qa/process/lease.ts`) was fixed on `main` at 11:55 and 12:18 UTC; two outcome tasks based on `main` of 11:09 UTC ran the old lock for three more hours, and one lost three QA runs to `ENOENT` on `.temp/goal-orchestration/qa-slots/shares`, handed off `blocked` and cost a manager turn and a hand. The lock is state shared by every worktree, read by as many versions of the code as there are trees.

1. **`check` runs on `main`'s harness.** When the worktree is clean, `task goal -- check` first brings the branch onto `main` the way `resume` does (`updateResumeWorktree`, `scripts/goal/resume.ts:24`; reuse it or what it shares), prints the same one line, and runs the checks on the result, which is also the tree the landing will gate. A conflict aborts the rebase, names the files and stops before any check. With uncommitted changes it does not move the tree: it runs as today and prints the line of step 2.
2. **`test` and `slot` say when the tree is behind.** Before taking a slot (`scripts/goal/goalctl.ts:151`, `:158`), when `main` has a commit under `scripts/goal/`, `scripts/qa/` or `tests/qa/support/` that the tree lacks, print one line: how many such commits, and that a failure of the harness on this tree may already be fixed (commit, run `task goal -- check` or rebase onto `main`, and run again). It never refuses and never moves the tree.
3. The comparison is by ancestry (`git merge-base --is-ancestor` of the last such commit on `main`), in `scripts/goal/tree-currency.ts`; give its measured cost in the handoff. In the main checkout and in a regression's pinned checkout nothing is compared or moved.

Do not build: a tool in a worktree that executes the main checkout's copy, a refusal of `test` on an old tree, a rebase of a tree with uncommitted changes, a change to the lease, the slots or the landing, a change to the worker protocol's text (the program writes that when this has landed).

## Mechanisms

none

## Checks

`task goal -- check`, and the two test files once with `CLAUDECODE=1`. The tests use temporary repositories and cover: a clean tree behind `main` is rebased and then checked; a conflict is aborted with its files named and no check run; a dirty tree is not moved and gets the line; `test` prints the line only when a harness directory moved on `main`; the main checkout is never moved. Wait on a running command with one long call (`yield_time_ms: 300000`).
