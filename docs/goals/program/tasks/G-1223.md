## Outcome

`task goal -- regress` gives the program manager one trustworthy main-wide
regression per pinned commit and routes each failure to the Goal that caused
it, so the delivery Goals run only worker and wave checks. Today the holder
runs a hand-written shell loop (`.temp/goal-program/regress-backend.sh` is the
current one; read it) and attributes failures by hand.

1. **Pin.** `regress [--at <rev>] [--resume <run-id>]` resolves the revision
   (default `main`) to one SHA, creates or reuses a detached worktree for it
   under `.temp/regress/`, installs, and verifies only that SHA; merges landing
   during the run never change it. Stale generated artifacts at that SHA are a
   reported failure, not something the run regenerates in place.
2. **Complete manifest.** From the harness's own registry (`testArgs` and
   `expandTestPaths`, gates and subdirectories included): unit, model, every
   integration file, fault/recovery, the web browser journeys and web
   Storybook as the e2e tier runs them, and `accounts:storybook:test`. Write
   `.temp/goal-orchestration/regress/<run-id>/manifest.json` with every expected
   file and its outcome; an incomplete manifest, a zero-match batch or missing
   data is never green. Live, load and legacy host-Jena files are listed as
   excluded with their reason.
3. **Batches that share the host.** Integration runs in batches of at most 15
   files at one shard (`REZICS_QA_SHARDS`, default 1, configurable), each
   through `goalctl test --heavy`, so every batch takes and releases the heavy
   lock and other Goals' wave checks interleave. Record queue, test and total
   time per batch. `--resume` continues a stopped run without repeating
   finished batches.
4. **Merge events.** `goalctl merge` (including `--landed` and a shared-branch
   merge recording several tasks) appends `{before, after, goal, taskIds, at}`
   to `.temp/goal-orchestration/merges.jsonl` under the ledger lock. `main` is
   fast-forwarded, so `git log --merges` cannot find task boundaries; commits
   between events (manager and maintainer edits) stay in the candidate range
   and are never attributed to the nearest task.
5. **Bounded bisection.** For each failing file: rerun it in its original batch
   at the pinned SHA (same batch first, then alone on a fresh project), then
   bisect over merge-event boundaries between the last commit where that file
   passed (from earlier runs' manifests) and the pinned SHA, at most 8 probes
   per failure. Each probe uses its own pinned worktree. Outcomes:
   `attributed` (before passes, after fails, both verified), `inherited` (fails
   at the base too), `unavailable` (file absent or build fails at a probe),
   `inconclusive` (non-monotonic or the probe budget ran out; report the
   suspect range, never a guessed culprit).
6. **Classification.** Infrastructure (Docker gone, ECONNREFUSED to the
   engine, network pool exhausted, OOM in the kernel log), resource or
   deadline, order-dependent (fails in batch, passes alone on a fresh
   project), flaky (same SHA, same configuration, different result) and
   deterministic regression are reported apart. Infrastructure results are
   void and re-queued, never routed as regressions.
7. **Inbox.** Each routed failure appends one line
   `{runId, atCommit, failingTests, before, after, goal, taskIds, status, classification, artifactPaths}`
   to `.temp/goal-orchestration/inbox/<goal>.jsonl` (owner unclear: the
   program's inbox). `goalctl status` prints each Goal's unacknowledged count;
   `goalctl inbox [--ack <n>]` lists and acknowledges.

Update `docs/goals/README.md` (command table, the supermanager bullet) to the
new commands, briefly.

## Smallest change; do not build

About 650–1,000 lines with tests. A bounded command, not a service: no daemon,
scheduler, database, web UI, second test runner, ML selection, result cache
across commits, speculative merge queue, automatic revert or automatic resume
of another Goal's worker. Reuse the harness, its artifact layout and the heavy
lock as they are.

## Checks

- Unit tests with temporary git repos and a stub test runner: merges landing
  mid-run do not change the pinned SHA; the manifest includes gate and
  subdirectory files; a fast-forward merge event is found and attributed; a
  failure present at the base is `inherited`; a missing file at a probe is
  `unavailable`; a flip-flopping file is `inconclusive` within 8 probes;
  infrastructure failures are void; an interrupted run resumes without
  repeating finished batches; an incomplete manifest is never reported green.
- `task test -- scripts/goal/goalctl.test.ts scripts/goal/regress.test.ts`
  and the type check covering `scripts/`.
- One real run: `task goal -- regress --at <main SHA>` restricted to the unit
  and model tiers plus two integration batches (a flag such as
  `--only unit,model --integration-batches 2` is fine), with its manifest and
  summary in the handoff.
