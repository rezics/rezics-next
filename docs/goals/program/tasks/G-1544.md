## Outcome

Read `.temp/ref/G-1523.md`, rank 5 and its falsifier.

`scripts/static/mechanisms.ts` names each owner's directory and entry points,
but nothing stops another module from importing an owner's internals.

1. Generate dependency-cruiser rules from the map: code outside an owner's
   directory may import only the files named in its `entryPoints`, plus its
   `allowedAdapters`. Run them in the repository guards that land and merge
   always run, with the existing `.dependency-cruiser.json` rules.
2. Imports that break the rule today go into an exact debt list
   (`mechanism-dependencies.json`: importer, imported file), which can only
   shrink. No whole-file or whole-directory exemptions.
3. A selector that matches no file fails, so a renamed owner cannot silently
   turn the rule off.

Acceptance (fixtures):
- an existing allowed caller passes;
- a new import of an owner's internal file fails;
- a debt entry that no longer occurs fails until removed;
- an empty selector fails.

Rules must not force pass-through facades: when a caller needs an internal,
the fix is to name it an entry point, not to wrap it.
