## Outcome

Regression run `20261009t175228-7b8d47` executed every file in about 8 hours, then spent 5 more hours diagnosing 34 of its 193 failing files. At that rate it would have taken another day, holding the host at load 15–17.
- Each diagnosis bisects with up to eight probes, and each probe is a fresh checkout, install and test run.
- 171 of the 193 failures had already failed in the previous run, `20261009t051244-a3e8b7`. Program triaged the run from the manifest in minutes: 22 new failures, 187 still failing, 91 fixed.

1. **Inherited failures.** A failure that also failed in the most recent earlier run whose pinned commit is an ancestor of this run's commit is classified `inherited`, with no probes. It carries that run's diagnosis, if any, and its run id.
2. **New failures.** A failure that passed in that earlier run is bisected only between the earlier run's commit and this run's commit, where it passed and where it fails, instead of the whole history.
3. **Budget.** Diagnosis has a total wall-clock budget for the run (`GOAL_REGRESS_DIAGNOSIS_BUDGET_MS`, default 2 h). When the budget is spent, the remaining files are reported `undiagnosed: budget`, and the run completes with a terminal status.
4. **Summary.** The manifest and the run's final output give the same summary Program computed by hand: new, inherited and fixed since the previous run, with that run's id.

## Checks

- `scripts/goal/regress.test.ts` covers:
  - an inherited failure gets no probes and names the earlier run;
  - a new failure's probes stay inside the earlier..current range;
  - the budget stops diagnosis and still finishes the run;
  - the new, inherited and fixed summary.
- `task scripts:typecheck`, plus `oxlint --type-aware` on the changed files.
