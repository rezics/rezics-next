## Outcome

Studio v2 (G-316) works end to end but found defects in Main (its handoff
PROPOSED 1–4, 6, 7, 9 and 11):

1. **Critical — any language can go public**: `modules/work/select-main.ts`
   (~line 257) refuses a main text unless the Work's title is tagged `@en`, so
   a Work created in Chinese (or any other language) can never get a main text
   and never becomes public. Select by the Work's own languages.
2. **Chapter authority**: chapters created by `POST /v1/works/:id/chapters`
   get no author authority (`authorWorkGeneration` accepts only a
   `work.create` admission). Give the chapter's author the same baseline so
   Studio can use the atomic command again.
3. **`content.variants.read`** in the author baseline for the author's own
   Works and chapters (today 404, so editing from another device fails).
4. **Own private covers**: `MediaAccess.canReadWorks` checks explicit grants
   only, so authors get 404 on their own private Work's cover and batch
   summaries omit private Works; accept the author baseline.
5. **Withdraw a submission** is in the author baseline.
6. **`reviewMode`** in Realm directory items; a **per-Work Studio read**
   (the Agent's texts and submissions for one Work).
7. **Definite refusal**: own-work creation for an Agent missing from the graph
   throws a generic Error (`activate.ts` ~319), which clients see as an endless
   202; return a definite problem. Make the web-auth fixture Agent exist in
   Main's graph so `authenticated-create.e2e.ts` IAM03/WORK01 pass again.

Allow and deny tests for every grant. Backend only (the one e2e file aside).
