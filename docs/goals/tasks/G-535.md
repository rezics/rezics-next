## Outcome

The feed's "Join" button calls the follow API (`api().follow(realm, 'realm', true, …)`) and then
shows "Joined"; `feed-context.tsx` calls the state `joined`/`join`, and the Home follow button
treats a followed Realm as joined (`home/follow-button.tsx:20,34`). Following is not membership
(members may post where followers may not), so the label claims an authority the reader does not
have. After this change the button says Follow/Following, the state is named for following, and
nothing implies membership.

## What to read

`docs/contracts/identity-and-access.md#visible-is-not-permitted`; the three files above and the
feed catalog keys `join`, `joined`, `joinRealm`, `joinFailed`.

## Approach

Rename the state and the button to follow semantics and reuse or replace the four keys with
follow wording in all eight locales in the same change. Membership stays in the Realm's own
join flow, untouched. No API change: the follow API already reports `following`.

## Do not build

No membership action in the feed, no new endpoints, no Realm page changes, no label-to-permission
inference anywhere.

## Acceptance

Browser: follow a Realm from a post and from Home; both show Following; the Realm page still
offers its own Join where membership exists. Story tests assert the text. Class guard: a component
test fails if the feed button calling `follow` renders the word for membership.
