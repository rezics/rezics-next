## Outcome

Read [collections at any size](../../plan/frontend.md#collections-at-any-size),
the "Styled controls only" bullet under [Home](../../plan/frontend.md#home) and
the account-menu paragraph under
[Languages and themes](../../plan/frontend.md#languages-and-themes).

1. **`EntityPicker`** in `@rezics/ui`, built on its existing Combobox: an
   asynchronous picker over `load({ q, cursor }) → { items, nextCursor,
   complete }` with single and multiple selection, removable chips, optional
   include/exclude per chip, an empty-query suggestions slot, continuation on
   scroll, honest "at least N" counts, loading, error with retry, and keyboard
   use that ignores `event.isComposing`. Stories cover 10,000 items, slow and
   failing loads, CJK input and phone width.
2. **Styled controls only.** ast-grep rules reject native radio and checkbox
   inputs in `apps/web` features as `no-native-select` already rejects
   `<select>`; replace the 16 current uses (the claimed feature files) with
   `@rezics/ui` RadioGroup and Checkbox; make `task check` run the ast-grep scan
   so the rules hold.
3. **Account menu.** Desktop and phone share one structure: identity (acting
   Agent, switch), profile, library, Studio, notifications; then
   **Language ›**, **Appearance ›**, **Content preferences ›** (a link to
   settings); then settings, account and sign out. Desktop opens submenus; the
   phone bottom sheet pushes a second panel with a back control and focus
   management, using `@rezics/ui` controls. Every new string ships in all eight
   locales.

## Do not build

No sidebar, Discover or route changes (later tasks), no new design tokens, no
virtualization unless a story proves it necessary.
