## Outcome

G-1027 (commit `1fd47ac4` on main; its handoff and profiles are in the
`green-5` worktree under `.temp/g-1027/`) fixed the unified Query so a common
Work query no longer grows with the corpus (Fuseki calls 16/30/62 → 15/15/15 at
scales 0/16/80) and no longer returns an empty first page at the largest scale.
It left open:

1. **Scale.** 80 Works says little. Measure the query matrix at scales that
   resemble a real catalogue (for example 1,000, 10,000 and 50,000 Works with a
   realistic Concept vocabulary and topic distribution), prepared through the
   public API with G-1024's recipe, built once and restored.
2. **Dense and negated paths.** Unselective text, very common topics, many
   excluded topics and include-plus-exclude combinations, where a candidate
   seek cannot be selective; prove the fallback examines a bounded number of
   candidates per returned result or answers an honest bounded partial page,
   per the contract.
3. **Private and cold branches.** Signed-in readers with private memberships,
   disclosure filtering, cold caches and stale projections.
4. **Round trips.** 15 Fuseki calls for one query is a lot against
   [fixed bounds for interactive requests](../../storage/workload-budgets.md#fixed-bounds-for-interactive-requests):
   derive the bound the design needs, then batch or fold calls to meet it.

Fix every gap by plan, index or layout; encode each bound as a profile test;
report before/after tables.
