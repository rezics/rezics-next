## Outcome

Read `docs/plan/frontend.md` ("Zones") first, then the research behind it:
`/home/edge/projects/rezics/rezics-next/.temp/manager/research-zones.md`
(sections 4–8; screenshots of the KadoKado reference in `.temp/manager/refs/`).
A Zone is a Realm's publication. Today `ZoneConfiguration.presentation` is an
unvalidated reference, the theme activation API can approve a build digest but
cannot create, review, revoke or kill a theme, and nothing marks a Zone as
official. Build the Main side:

1. **`zone-presentation-v1`** in `model/definitions/`: tokens and preset
   (Clean, Editorial, Vibrant, Serial), typed modules (type, source such as a
   query block, Collection or Context, tabs and options), navigation and
   banners. Validate on write; CAS like the rest of Zone configuration.
2. **Public presentation read** `GET /v1/zones/{id}/presentation` (no token
   for public Zones, ETag, short cache) returning tokens, modules and whether
   a code package runs, with the fallback reason (safe mode, globally disabled,
   revoked, expired, viewer opt-out, none approved).
3. **Official Zones**: a marker only operators can set; `GET /v1/zones?official=true`
   and lookup by route segment, so `/r/{slug}` resolves an official Zone's Realm.
4. **First-party theme lifecycle**: create a theme, add revisions (file
   manifest and digests), review (reviewer differs from submitter), approve an
   activation bound to one host Zone, revoke, and a global execution control
   (kill switch), with receipts, audit and outbox events. Add a
   `first-party-bundle-v1` runtime with byte budgets, named slots and allowed
   origins; keep the isolated-worker runtime for later partner code.
5. **Seed** (`scripts/dev/seed/**`, unclaimed; keep changes small): official
   Realms and Zones for Fiction, Books, Mods, AI Workshop, Software and
   Kitchen with presets, modules and some curated Works, through the APIs.

This also carries the theme rows of documentation batch B32
(`docs/plan/docs-audit.md`): encode what `custom-theme-execution.md` states
and shorten it to the reasons, and merge the two custom-theme runbooks into one
short runbook for review, incident and kill-switch steps.
