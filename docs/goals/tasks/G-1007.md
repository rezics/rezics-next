## Outcome

[Follow, Join and notification](../../contracts/community-interactions.md)
says a follow carries its source (explicit, join or library) and "Leaving
removes only a join-sourced follow". G-1005 found that
`access.automatic_follow` (migration `1014_relationship_follows.sql`) replaces
an existing explicit follow's source with `join`, so a reader who followed a
Space, then joined and left, silently loses the follow (and its bell level).
G-1000's browser journey asserts the contract.

Fix it with a new migration (1028–1029; check the highest number on main
first): Join adds a join-sourced follow only when none exists and never
lowers an explicit or library source; Leave removes only join-sourced follows
and keeps the bell of a surviving follow. Repair existing rows only where
provenance can be proved (for example from the relationship history); say what
cannot be recovered. Integration test through the public API: follow → set
bell Highlights → join → leave → still followed at Highlights; join without a
prior follow → leave → not followed. Run it with
`bun scripts/goal/goalctl.ts test`.
