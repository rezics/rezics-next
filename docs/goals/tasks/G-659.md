## Outcome

The "backend one" rule (`docs/product/goal.md#backend-one-frontend-free`) fails a check
when broken, cheaply and precisely (R44 guards 2–4). After this task:

1. depcruise rule `shared-reads-do-not-depend-on-packages`: nothing under
   `services/main/src/modules/(zone|zone-modules|query|facets|search|discovery|concept-page|author-page|rankings|catalog|feed)/`
   imports `services/main/src/modules/package/` (package solving is an optional
   capability; `docs/product/capabilities.md`, "Package solving stays optional").
2. depcruise rule `web-host-loads-zone-packages-through-the-loader`: nothing under
   `apps/web/(app|features)/` except `*.stories.tsx` imports
   `apps/web/zones/official/<slug>/`; only `zones/official/index.ts` loads packages
   (the G-433 review defect).
3. `scripts/static/anti-silo.test.ts`, three checks with a committed baseline:
   a. a migration numbered above each directory's baseline head creates no table whose
      name, split on `_` and `.`, has a domain token as a whole part (game, games,
      software, mod, mods, novel, serial, book, books, anime, manga, vn, recipe, prompt,
      llm, movie, music), so `moderation` or `bookmark` never match;
   b. per-file counts of descriptive type IRIs (the admitted Work types in
      `model/definitions/work-kind-v2.ts`, full and prefixed) and of `Minecraft`,
      `modrinth`, `curseforge` and `steam` literals in `services/main/src/**` and
      `apps/web/{app,features}/**` may not rise above the baseline or appear in a new
      file; excluded: tests, stories, fixtures, `model/definitions/**`, `generated/**`,
      `modules/package/**`, `modules/source/**` adapters, `routes/package-*.ts`, and the
      current type registry files `modules/work/{type-schema,work-kinds,activate}.ts`;
   c. `ZoneWork` in `packages/zone-sdk/src/index.ts` gains no key that is a domain
      token or a known domain bag name (`mod`, `game`, `software`, `hub`, `recipe`;
      baseline: `hub`).
   A drop below the baseline passes; `bun test scripts/static/anti-silo.test.ts --update`
   (or an env flag) rewrites the baseline, which the manager runs at wave merges.

## Approach

Two depcruise rules and one bun test of plain file scans; each check gets a failing
fixture under `scripts/static/fixtures/anti-silo/` and a test proving it fails on it.
Generate the initial baseline from the tree after G-656, G-657 and G-658 merged.

## Do not build

No AST analysis framework, capability coverage matrix, clone detector, runtime digest,
new CLI or Task entry, and no edits to production code: a guard that fails on the
current tree gets a baseline entry, not a fix.

## Acceptance

each fixture (a `CREATE TABLE access.game_notes` migration above the head, a new
`'https://schema.org/VideoGame'` branch in a Main module, a `zone-modules` import of
`modules/package`, a feature importing `zones/official/games/slots.tsx`, a `ZoneWork.game`
key) makes its check fail with a message naming the file and the reusable alternative.
