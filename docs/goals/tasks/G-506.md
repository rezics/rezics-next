## Outcome

Main has one target contract and one batch resolver that every capability shares.

**Contract.** `target: readId`. It resolves to `{ resource, base, types[], work | null, revision, disclosure }`,
where `base` is one of `work`, `realization`, `release`, `occurrence` or `resource`. The contract also exports a
per-capability table of accepted bases, and `capabilityPath`, which returns `/v1/resources/{id}/{capability}`.

**Existing reads.** `GET /v1/resources/:id` and `POST /v1/resources/summaries` report `base` and the owning
`work` for:

- Works;
- releases (`rv:Release`, `rv:FixedRelease`);
- occurrences (`schema:ListItem`);
- text contributions (`rv:TextContribution`);
- semantic resources (`rv:semanticHead`).

No capability route changes here. G-650 and G-629 consume this contract, as do sibling briefs: G-630, G-833,
G-865 and G-869.

## Approach

1. **`modules/target/contract.ts`.**
   - `targetRef` (use `readId`), `targetBase` and `resolvedTarget`, as TypeBox schemas.
   - `capabilityBases`, typed `satisfies Record<Capability, readonly Base[]>`, holding the design §1 rows.
   - `capabilityPath`.
2. **`summary.ts`, `graphRows`.** Add one UNION branch per new record type, each binding `?work`.
   - Release, occurrence and realization rows take their name and disclosure from their Work. Access then
     reuses the restricted-Work path.
   - A generic `rv:semanticHead` resource takes the `character` and `role` path.
   - Add the new literals to `resourceType`. The change is additive.
3. **`modules/target/resolve.ts`.** Add `resolveTargets(session, iris, capability, redirectOf?)`.
   - It calls `readResourceSummaries` with the session's reader.
   - It reads each target's exact `revision` in one bounded query: Work `rv:head`, release head,
     `rv:structureHead`, the contribution's selected draft, or `rv:semanticHead`.
   - Missing and hidden targets both return 404.
   - A MainVersion, or a base the capability does not accept, returns 422 `target_not_bound`.
   - `redirectOf` is only a hook for G-869.

## Do not build

- Tables, caches, or per-capability graph queries.
- Client-supplied `base`, kind or aspect fields.
- MainVersion targets.
- Redirect storage.
- New routes.
- Wiring the resolver into reviews, discussion or Collections (G-650).
- Registry lookups; bindings are per base.

## Acceptance

Seed a SAO subset through the API: `sao.web`, `sao.bunko`, a volume-1 Book, one release of it, one chapter
occurrence of `sao.web`, one text contribution and one character.

- `GET /v1/resources/:id` reports each one's `base` and `work`. `sao.web` and `sao.bunko` never resolve to each
  other.
- A private Work's release and occurrence are unavailable to anonymous readers and available to its author.
  Erased resources are unavailable.
- MainVersion targets and grain mismatches return 422. A batch of 64 stays within the summary's cost bounds.
- Class guard: the exhaustive `Record<Base, …>` tables fail typecheck when a base is added without handling. A
  test asserts that `resolveTargets` never returns a target the summary marks unavailable.
