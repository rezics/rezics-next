Harness task, no product change. The integration tier (8 min) and
fault/recovery tier (6 min) run their files serially in one QA project; wave 2's
fault tier timed out after seven files and the final backend run will hold
about four times as many tests. Run a tier's files in N parallel QA projects
(sharded by recorded file duration, `GOAL_QA_SLOTS`-aware, each shard its own
`rezics-qa-<run>-<n>` project) and merge their results into one acceptance
record, so a tier's wall time fits its budget without raising it. Keep
`--record` semantics, source-stability checks, partial/uncovered accounting and
`--only-failed` reruns intact. Also isolate tests that assume a fresh shared
database (for example `access-representation-api` and `go-sumdb-trust` failed
only when run after other files): report such order dependence per file rather
than fixing product tests outside your claim. Report measured tier times before
and after in the handoff (G-045 holds the harness page). Checks: the harness unit tests and one sharded
integration run plus one sharded fault/recovery run through `goalctl test`.

Estimate 60–90 minutes.
