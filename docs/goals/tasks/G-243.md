## Outcome

Frontend work needs realistic data in a real browser, but the shared local
backend (`task dev` in the main checkout: Main :3001, Account :3002, web :3000)
has no Works; the bulk QA fixture is a synthetic load corpus. Build an
idempotent demo seed that creates a small, realistic, bilingual dataset
**through the public APIs only** (Account sign-up/sign-in and OAuth tokens,
Main commands), exactly as users would. Using the real APIs is the point: every
API gap or awkwardness you hit is a finding for the product.

## Dataset (aim for quality over size; about 2 minutes to run)

- 6–8 people with display names in English and Chinese; pen names and one
  organization as public Agents where the API allows.
- 25–40 Works across types: public-domain books with real metadata and a few
  real chapters in English and Simplified Chinese (for example *Pride and
  Prejudice*, *Alice's Adventures in Wonderland*, 《西游记》, 《红楼梦》,
  《聊斋志异》 excerpts), a translation linked to its original, a web-serial
  style original with several chapters, a few open-source packages, recipes,
  and AI Skills/Prompts if their APIs exist. Covers where the media API allows
  (generate simple placeholder images locally; no external downloads needed
  unless trivially reliable).
- 3 Spaces/Realms (for example a classic-literature Realm, a Chinese web-fiction
  Realm, a cooking Realm) with members, moderators, rules, Realm-scoped
  classification decisions that differ from Global for at least one Work, and
  adoptions of specific contributions.
- Ratings from several people in Global and Realm contexts (so distributions
  are non-trivial), classification/tags, comments and replies, a collection or
  shelf per person, one open report and one pending contribution for the
  moderation queue.

## Deliver

- `scripts/dev/seed/**`: a typed seed (`bun scripts/dev/seed/cli.ts` with
  `--dry-run` and `--reset-own` options) that is idempotent (re-running does
  not duplicate; use stable idempotency keys), prints a summary with sign-in
  credentials for the demo accounts and the web URLs of a few Works and Realms.
  Read endpoints from the checkout's environment (`task env`).
- A unit test for the seed plan (deterministic content, no network).
- Run it against the shared local stack and confirm in the web app
  (http://localhost:3000/search) that works appear. Do not reset or restart
  the shared stack; if it is down, report it.
- Add a Task entry later through the manager: in the handoff give the exact
  `Taskfile.yml` lines for `task dev:seed` (Taskfile is claimed by another task).

List every API that was missing, awkward, or needed a workaround (with the
