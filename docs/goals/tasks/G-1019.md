## Outcome

[Durable addresses](../../product/urls-and-seo.md#durable-addresses): names
are optional, an unnamed person is addressed as `/a/{sid}`, and G-961 dropped
the Access handle bridge (`1024_drop_agent_handle_bridge`). Yet Main still
mints `agent-<uuid>` as a handle (`modules/agent/handle.ts`;
`profiles/read.ts` COALESCEs it into `handle`), so
`GET /v1/agents/{id}` answers `"handle": "agent-71473997-…"` for an Agent
whose address resolves to `/a/EzJtr2FK8aM4SRKyi9SiZn`. The web then shows
`@agent-71473997-…` under "About the author" and pre-fills Settings › Handle
with it, while the header says "Choose a handle"; `manage/format.ts` hides it,
`studio/agent.ts` re-mints it, and two Main searches parse `agent-` prefixes.

Remove the class: read contracts answer `handle: null` for an unnamed Agent
(plus the canonical address where a link is needed); every UI shows the
display name and links through the address builders, offering "Choose a
handle" only to the owner; searches accept a sid, UUID or name through address
resolution instead of an `agent-` prefix; keep old `agent-<uuid>` URLs working
as one 301 to `/a/{sid}` (G-990's legacy forms). Regenerate contracts with
`task gen` (restore generated paths before handoff). Unit, integration and
story coverage for a named and an unnamed person.
