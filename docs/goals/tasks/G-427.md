## Outcome

G-421 landed the maintainer's Query milestone: `POST /v1/query` admits a
FilterDocument and compiles it onto the bounded templates, refusing
unsupported combinations with a typed refusal. G-409 built Concept pages
with a Condition bar (include, exclude, all or any within a Facet). Readers
don't see either yet outside the Concept page. The AO3 and VNDB research
(`docs/research/reference-ao3-vndb.md`, item 3) says include and exclude
should work wherever a reader narrows a list.

- **One shared Condition bar component** (from G-409's `condition-bar.tsx`,
  moved to a shared feature if that helps). It builds FilterDocument
  Conditions over the admitted Facets from `GET /v1/facets`, with value
  search, include and exclude, all or any per Facet, removable chips, and
  counts where the query's cost bound allows.
- **Search:** results come from `POST /v1/query`. Search's `sense` is a
  Concept Condition; the bar sits above results; a typed refusal says
  plainly what can't be combined.
- **Discover:** shelves and the "more" listings take the same bar.
- **Home:** the Filters popover (G-401 and G-416; keep its one control line
  and the post rhythm) edits the same Conditions.
- **Concept pages:** register G-409's Concept read as a Query template from
  the query module, calling its exported read (G-421 couldn't, since it
  lacked G-409), so Concept pages and search agree. G-426 holds
  `concept-page/**` for localized labels; don't edit it.
- Zone browse (held by G-424) follows later; state what it needs.

Use `@rezics/ui` controls, never a native select. Add English and zh-Hans
strings only. The vocabulary is Concept, Facet, Condition, Filter and Saved
Filter (`docs/contracts/queries.md`).

## Verify in a real browser

On the shared stack: in Search, look for "书店" including 悬疑 and excluding
言情, then switch between all and any. In Discover, filter Books by two
genres. In Home's Filters, include one Concept. Open a Concept page and check
the results agree with Search. Check 1440x900 and 390x844, en and zh-Hans,
using BrowserOS in your own tab or Playwright. Run one web dev server
(`task web:dev`) only while checking, and stop it when done.
