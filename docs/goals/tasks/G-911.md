## Outcome

On the shared stack after G-585, `GET /v1/search/catalogue?q=Lanterns`
returns "Camp Lanterns" but `q=Camp` and `q=Camp Lanterns` return nothing:
ranked catalogue search matches only `rv:searchBody` text, not titles or
alias name records (also noted by G-828). Readers search by name first. After
this task the catalogue search matches a Work's titles and aliases in every
language (with G-585's script, kana and width folding), multi-word queries
match titles containing those words, and a title match ranks above a body
match; private names stay hidden (the existing disclosure and restricted-name
fences apply before ranking and counts).

## Approach

Use the text index fields G-585 says already index titles (find them in the
dataset profile and assembler) in the catalogue query, combined with body
text, with a title boost. If titles are not yet indexed for catalogue
MatchUnits, add them through the existing projection and rebuild recipe, not
a second index. Keep one bounded query per page.

## Do not build

No new index, no new endpoint, no client-side search.

## Acceptance

Integration on seeded data: a single title word, a full multi-word title, an
alias in another language, and Simplified/Traditional variants each return
the Work first; a private Work's title returns nothing and changes no count.
