## Outcome

The maintainer pointed at Goodreads' author page as a reference:
https://www.goodreads.com/author/show/16669648.Ferdia_Lennon (study it and a
reader's profile there; not the Goodreads home). Build `/@{handle}` for every
Agent kind on one template (`docs/plan/frontend.md`, "Principles", "Main site
routes"):

1. **Author** (person or pen name credited on Works): photo, name, handle,
   short bio, follow button and follower count, "{name}'s works" as
   cover-first rows with ratings, taglines and completion (G-309's Agent works
   read), series where they exist, Realms they are active in, and "Readers
   also enjoyed" authors if Main can support it (otherwise PROPOSED TASKS).
2. **Reader** (a person without credits, or the reader side of an author):
   status shelves with counts when the person made their library public
   (G-294), ratings and reviews, recent public activity.
3. **Organization**: members, works, Realms.
4. **Handles**: vanity, retired (redirect to current, G-284) and native
   `agent-<uuid>` handles all resolve; the page is indexable with canonical
   and `hreflang` alternates. `@` in App Router folders means a parallel route,
   so route `/@{handle}` through `proxy.ts` or an equivalent rewrite and
   explain the choice.

Reuse `features/catalogue` (G-283: cover tiles, rows, shelves, rating line,
ShelfButton) and `WorkCover`; follow with G-282's follows API; strings in your
feature's per-locale message files; internal links through
`features/shell/localized-link.tsx`. Missing Main fields go to PROPOSED TASKS.

## Verify in a real browser

Against the shared stack (demo credentials from `scripts/dev/seed/plan.ts`):
an author with several Works, a reader with a public library, a private one,
a retired handle. Screenshots at 1440x900 and 390x844, light and dark, en and
zh-Hans, next to Goodreads. The host ran out of memory once: run only the web
dev server while you verify (no Storybook at the same time, no Accounts app),
and stop it when done.
