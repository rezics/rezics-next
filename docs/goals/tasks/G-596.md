## Outcome

- Realm rules are stored as localized text (`{ original, labels }`, any BCP 47 tag), like the
  Realm public profile already is. Today the settings command and `realm-settings-rules-v1` accept
  only `{ en, 'zh-CN' }`, both required, so the web copies one text into both keys: every Realm's
  rules claim to be English and Chinese at once.
- Zone and collection names created by `zone/owner-create.ts` keep the declared language instead
  of `@en`.
- Reads that meet untagged or missing text report it as not recorded (`und` or absent) instead of
  inventing `en`: `collection/names.ts` (`|| 'en'`), `zone-modules/editor-lists.ts` (`?? 'en'`)
  (G-514 fixes the feed's own fallback in `feed/read.ts`; `media/summary.ts:351` stays in G-501's
  ratchet because G-506/G-571 claim that file).

## What to read

`docs/contracts/content-languages.md#one-native-language-contract`;
`services/main/src/modules/realm-profile/schema.ts` (the v2 localized profile and its
`legacyLocalizedText` read of v1, the pattern to copy); `governance/rules.ts`;
`realm-admin/contract.ts`; `access/realm-management-settings.ts`;
`services/main/src/modules/display-language/select.ts`.

## Approach

Add `realm-settings-rules-v2` whose rules use the existing `localizedRuleTitle`/`localizedRuleBody`
schemas; the settings command accepts v2 only; stored v1 documents stay readable and are converted
on read. When a v1 rule's `en` and `zh-CN` texts are identical, read it as one label in `und`
(the duplicate was the web's copy, not a translation); otherwise map `zh-CN` to `zh-Hans` as
`legacyLocalizedText` does. Zone/collection creation takes a `language` for the name; omitted means
`und`, never `en`. In `feed/cards.ts` drop the `untitled chapter|未命名章节` sentinel only if G-512
confirms nothing writes it. G-515 changes the web rule editor and Realm creation form.

## Do not build

No rule translation workflow, no per-language rule revisions, no migration rewriting stored rule
documents, no new generic "localized field" framework: reuse the schemas that exist. Zone
presentation titles (`zone/presentation-format.ts`, eight fixed locale keys) belong to the Zones
brief of M6; do not version them here.

## Acceptance

API: publish rules in `ja` with a `ko` translation and read them back with language and direction;
a v1 document with identical `en`/`zh-CN` reads as one `und` label; a v1 document with different
texts reads as `en` + `zh-Hans`; replaying the same command key is idempotent; create a Zone named
in `ar` and read `ar`/`rtl` back; an untagged collection name reads as not recorded.
Class guard: a test fails if any of the claimed read paths returns `en` for untagged input.
