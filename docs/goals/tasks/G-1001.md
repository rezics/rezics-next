## Outcome

The manager's product audit of the direction-9 screenshots found three gaps
against [Discover](../../plan/frontend.md#discover) (read the two bullets dated
2026-10-03) and [collections at any size](../../plan/frontend.md#collections-at-any-size):

1. **Two searches.** The header says "Search works…" and leads to the
   works-only `/search`, while Discover has "Search everything". Make the
   header box Discover's search (opens `/{locale}/discover?q=…` on All); the
   old `/search` answers one 301 to Discover keeping its query (and a works
   type filter when it had one). Labels and placeholders in all eight locales.
2. **Generic result tiles.** Discover's Works render as an initial-letter tile
   with a title only, while rails on the Work page show cover, authors and
   rating. Each Discover result uses its type's shared card (Work, Community,
   Site, Person, List, Topic), the same component other lists use; if a type
   has no shared card yet, make one and use it in both places.
3. **Uncounted labels.** The rating scope picker's options read "1 · Ratings"
   (`scope-bar.tsx`: `${count} · ${t.ratings}`). Use plural-aware count
   messages ("1 rating", "20 ratings") in every locale, and fix the same
   pattern wherever a count is glued to a plural heading in these features.

Stories for each card and the search entry in both a Latin and a CJK locale;
unit tests for the redirect. Run your stories through
`bun scripts/goal/goalctl.ts slot -- task storybook:test -- <files> --maxWorkers=2`
(from `apps/web`).
