## Outcome
An agent that holds a person's consent, such as Claude Code, Codex or the wiki
toolkit's skill, connects to `https://<main>/mcp`. It authorizes through
Account's existing OAuth provider, following the MCP authorization spec, and
lists and calls tools. Each tool is an operation its route module declared
agent-callable. A tool call has exactly the HTTP operation's authority, acting
Agent, idempotency, receipts, rate limits (G-543) and problem responses. It
runs the same handler. The first declared set is what the toolkit needs for
candidate lookup: resource summaries and reads, relations and editions, and
catalogue search (declared by G-556 in `routes/search.ts`). M6's wiki intake adds its proposal operations by declaration alone.
This is the first slice of the executable capability registry (decision 14);
the full disposition gate is deferred G-540.

## Approach
- A route module may export `capabilities`, keyed by method and path: `{ disposition: 'supported'|'internal'|'deferred', reason?, mcp?: { tool, title, description } }`. `generate.ts` emits it as `x-rezics-capability` in OpenAPI and fails on a declaration without an operation.
- Serve `/mcp` with the official TypeScript SDK's Streamable HTTP server transport.
  - Tools are built from the generated operations that carry `mcp`: the input schema comes from the operation's parameters and body.
  - A call dispatches in-process through the Elysia app with the caller's bearer and `Idempotency-Key`. Results keep status, problem details and continuation cursors.
- Authorization:
  - Main serves OAuth protected-resource metadata naming Account.
  - Account admits public MCP clients through the registration mechanism the spec prefers: client ID metadata documents, or dynamic registration limited to public PKCE clients. Clients get a scope ceiling of the declared agent scopes, audience-bound to Main.
  - Consent and live revocation use the existing fences. Record the SDK in `docs/development/toolchain.md`.

- Manager: `services/main/src/routes/resources.ts` is held by G-897 (suitability). Expose MCP tools from the declared operations without editing it; if a change there is unavoidable, list it under OWNER CHANGES.

## Do not build
- No SDK package and no developer portal (deferred G-575/G-576).
- No personal access tokens (deferred G-582).
- No second authority or grant model.
- No per-endpoint tool dump: only declared operations become tools.
- No tool that bypasses HTTP handlers.
- No sessions or state in Main beyond what the transport requires.
- No outbound MCP change and no MCP management UI.

## Acceptance
- API integration tests:
  - An MCP client registers, completes authorization code with PKCE and consent, lists tools, and calls search and a resource read. The results equal direct HTTP results for the same bearer.
  - A write tool, from a fixture declaration, replays one effect on the same key.
  - Revoking consent makes the next call fail.
  - A token for another audience is refused.
  - An undeclared operation is not listed and cannot be called.
  - `429` from G-543 passes through with `Retry-After`.
- Class guard: generation fails if any declaration names a missing operation. A parity test compares each tool's schema to its OpenAPI operation.
