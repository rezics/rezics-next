## Outcome

A read-only expert UX review of what exists today, to steer the next slices
toward "excellent to use". Do not change code; your deliverable is the handoff.

Use the running shared stack: web on http://localhost:3000, Accounts on
http://127.0.0.1:3004 (sign up there; verification mail arrives in Mailpit at
http://127.0.0.1:8025), Storybook on http://localhost:6006. Drive a real
browser with Playwright from `apps/web` (write scripts under /tmp or the
worktree's `.temp/`). Cover desktop 1440x900 and phone 390x844, light and dark,
en and zh-CN.

Walk these journeys and judge them against `docs/plan/frontend.md` and the
comparable products it names (Google Account; Goodreads/StoryGraph, AO3,
Royal Road/Qidian readers, Modrinth, Wikipedia):

1. First visit: home, discover, search (English and Chinese queries), a Work
   page with every tab, the reader.
2. Account: create an account, verify email, sign in from the main site, the
   account centre pages, sign out.
3. The shell: navigation, account menu, Agent switcher, theme and language
   switching, keyboard use (`/`, Cmd/Ctrl-K, focus order), phone bottom bar.
4. Storybook: skim the Rezics UI and feature stories for consistency.

Deliver in the handoff a prioritized list (P0 blocks use, P1 hurts quality,
P2 polish), each with: where (route or component), what is wrong, why it
matters (cite the principle or comparable), the concrete fix, and whether it
is a frontend or an API problem. Also list the 5 highest-value next features
you would build and why. Keep screenshots under your worktree's `.temp/` and
name the key ones in the handoff. Close every browser you open.
