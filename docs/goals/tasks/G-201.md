## Outcome

The documentation grew large (about 175 pages, 27,000 lines under `docs/`)
because the system did not exist yet. It does now. The maintainer's direction:
express in code (types, schemas, tests, lint rules, generators, stories,
comments) whatever code can express, and delete the documents that code
replaces. Keep documents only for what code cannot carry: intent, decisions
with their reasons, and operating procedures.

Produce `docs/plan/docs-audit.md`: a page-by-page audit that the manager will
turn into execution briefs. This task only audits; it changes no other file.

## What to deliver

1. One table row per page under `docs/` (plus `README.md`, `AGENTS.md`):
   path, line count, verdict, the code that owns or should own the content,
   and a one-line reason. Verdicts:
   - `delete`: code already states it (name the files/tests that do).
   - `encode`: code can carry it; name the target (type, schema, test, lint
     rule, generator, story, comment) and then delete the page.
   - `shorten`: must stay, but most of it is restated elsewhere; give the target
     length and what survives.
   - `keep`: intent, decisions with reasons, or operating procedure.
   - `archive`: finished history; moves to the orphan branch `archive/goals`.
   - `merge`: fold into another named page.
2. Group rows into execution batches that one worker can finish in one sitting
   (by directory or owner), ordered by value: large pages restating code first.
   For each batch give the claimable path globs and the check that proves it
   (`task docs:check`, the owner's tests or typecheck).
3. Note link hubs (`docs/README.md`, `docs/architecture/coverage.md`, contract
   indexes) that every batch touches, and propose how to avoid merge conflicts
   between batches (for example one final hub-cleanup batch).
4. Note the tooling: `task docs:check` (see `scripts/documentation/`) checks
   links, fragments and navigation; say whether it should change as pages go.

Verify claims against the code, not titles: open the owning code for every
`delete` verdict. Be decisive; when in doubt between `shorten` and `keep`,
prefer `shorten`. Frontend design pages (`docs/development/design-system.md`,
`web-features.md`, `storybook.md`, `docs/plan/frontend.md`, `docs/experience/**`)
are being reconsidered by the frontend Goal; audit them too but mark them
`frontend-owned` in the notes.

## Checks

`task docs:check` must still pass (your only change is the new page; link it
from nowhere or from `docs/plan/README.md` only if the check requires it).
