## Outcome

G-425 seeded 18 genre and tag Concepts on every Book and serial, so Concept
chips and pages now work on the shared stack. But the proposition API creates
a separate English-only ConceptScheme for each Concept, and it can't record
localized labels or broader/narrower links. Chips therefore read "Urban · 都市"
in every locale, and Concept pages have no hierarchy. The maintainer's
contract (`docs/contracts/queries.md`, Concepts and value pages) expects a
Concept page with broader and narrower Concepts, and every name to belong to
something, read from the Resource itself.

- **A vocabulary API** in Main, following the model's versioning rules: a new
  profile or revision, never an in-place edit.
  - Create or extend a shared ConceptScheme.
  - Add Concepts with `skos:prefLabel` per language and alternative labels.
  - Link `skos:broader` and `skos:narrower` within a scheme.
  - Everything is attributed and revisioned like other statements, accepted
    per Context.
- **Reads.** Concept labels resolve in the reader's interface language, with
  fallback, everywhere chips, Concept pages and Zone browse show them; the
  Concept page shows broader and narrower Concepts.
- **Seed.** Move G-425's Concepts into one bilingual genre scheme (for
  example 小说 > 玄幻/Fantasy, 都市/Urban, 悬疑/Mystery; Classics > Gothic,
  Satire) and a free-tags scheme, replaying without duplicates.
- **Types.** Some source-adopted Chinese classics lack semantic types (G-425
  found this); fix them with the Work type command, so they stay eligible as
  Book recommendations.

Tests cover label resolution per locale, the hierarchy, versioning and
replay. The web shows whatever Main returns; change web code only where a
read's shape changes, and say so in the handoff. Don't commit generated
artifacts.

## Verify
