Phase D repair. Record run 5 (`.artifacts/qa/20260927t071628-ff07f0`, log
`/home/edge/projects/rezics/rezics-next/.temp/qa-record-5.log`) passed every tier
and case except the load test "OPS05: named 100k host mix records latency, relay
lag, memory and storage recovery". It failed `practical load thresholds` in
`scripts/load/practical.ts` with read share 0.904 (bound 0.7–0.9), 292 completed
requests (minimum 300) and selection-write p95 2,717 ms (objective 2,500 ms)
from only 2 selection writes; edit p95 was 1,774 ms. The same test passed in
record run 4 and in G-115's run (selection p95 1,255 ms). The 20-second mix uses
closed-loop writers, so slower writes lower the write count and push the read
share over its bound, and a p95 over two samples is just their maximum.

Make the measurement sound without changing any objective or bound: offer
writes at a fixed arrival rate independent of their latency, run long enough
(within the 4-minute load test budget) that every write kind has at least 20
samples before its p95 is compared, and keep the read share inside its bound by
design. Then find out why a Main default-selection write takes 1.2–2.7 s on the
restored 100,000-Work copy (graph command, fences, relay, index work) and remove
avoidable waits in the product path only if the cause is real; use `goalctl
owner` before any product edit and list it. Record the measured distribution in
`docs/storage/workload-budgets.md`. Run the load tier three times on the quiet
host (`bun scripts/goal/goalctl.ts slot -- corepack yarn qa --tier load`) and
report each run's OPS05 metrics; all three must pass. Edit files only under your
own worktree. Estimate 60–90 minutes.
