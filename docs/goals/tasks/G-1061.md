## Outcome

G-1059 fixed one race in the wiki position chooser (selecting a chapter cleared
the input and an empty-query server action at `position=all` superseded the
chapter navigation). On the shared stack after its merge, en desktop, en phone
and zh-Hant desktop pass, but **zh-Hant phone still lands on `position=all` in
2 of 3 repeated runs** (`.temp/manager/wiki-zh-phone.log` and
`wiki-final2.log` in the main checkout, read-only;
`apps/web/tests/direction-9.e2e.ts:778`). On phones the chooser lives in a
bottom sheet, so closing the sheet, restoring focus, or a late result for the
previous query can still issue a competing navigation or state reset.

Find every path that can navigate or reset the selected position after the
person chooses a chapter (sheet close, query debounce, stale server action,
URL sync, hydration), make the person's last choice win, and prove it with a
deterministic test (slow network for the query, slow hydration, phone
viewport, CJK input) plus `--repeat-each 10` of the four wiki journeys on the
shared stack with the direction-9 environment
(`REZICS_WEB_E2E_BASE_URL=http://localhost:3000 ACCOUNT_ORIGIN=http://localhost:3004`,
`REZICS_WEB_AUTH_PRIVATE_PATH=/home/edge/projects/rezics/rezics-next/.temp/stack/rezics-dev/web-auth/private.json`,
`REZICS_DIRECTION_9_ADMIN_PRIVATE_PATH=/home/edge/projects/rezics/rezics-next/.temp/datasets/administrator-72a030c5f7e58beba90986153ae1ef6c70b965857dcb6fad4e63970d132cdea3.json`;
read those files at those absolute paths and never print them) through
`bun scripts/goal/goalctl.ts slot --`. G-1060 is fixing the same family for
Discover's links (only a newer user choice may supersede a navigation): align
with its rule if it lands first. Say which runs await the merge.
