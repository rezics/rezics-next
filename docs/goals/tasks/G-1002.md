## Outcome

`task check` on main fails with 50 `web-links-use-address` errors
(`.temp/manager/round4-check.log` in the main checkout, read-only). Most come
from tests that deliberately write raw legacy URL forms (`/a/{UUID}`,
`/@agent-…`) to prove they redirect: an oracle must not reuse the builder it
tests. Others are product code and stories that should use the builders
(`features/shell/communities-relationships.ts`, `join-page.stories.tsx`). The
rule also still carries a "temporary wave-9 owner exceptions" list that was
due for removal after that wave.

1. Give address conformance tests a principled, explicit place in the rule
   (for example a named ignore group for files whose purpose is testing raw
   address forms, with a comment saying why), and keep the rule strict for
   everything else. Add a rule test for both cases.
2. Fix product code and stories to build links with `features/address`.
3. Empty the temporary wave-9 list: convert each listed file to the builders,
   or move a true conformance test to the group from step 1.

`direction-9.e2e.ts`, `direction-9-fixture*.ts` (G-999) and
`features/discover/**` (G-1001) are claimed: if they still fail after step 1,
list the exact lines under OWNER CHANGES and leave them. Run
`task check` through `bun scripts/goal/goalctl.ts slot --` and give its result.
