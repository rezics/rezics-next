fault/recovery assertion passes on current `main`, but the tier exceeds its
documented 6-minute budget (`docs/testing/test-harness.md#tiers-and-budgets`:
"Fix slow tests instead of raising the budget"). G-137's run
`/home/edge/projects/rezics/rezics-next/.temp/worktrees/g-137/.artifacts/qa/20260927t014106-16ac4d`
shows the slowest files: OPS02/OPS04 second-host restore 177 s, SEARCH15/OPS16
146 s, SEARCH20/OPS16 143 s, OPS09 122 s, OPS15/OPS16 121 s, SEARCH17 120 s,
MODEL25 98 s, then several 45–60 s drills. Adding one shared shard made the wall
time worse (host contention).

Make the whole tier pass within 360 s on a quiet host (Docker VM now 36 GiB)
without weakening any assertion: remove fixed sleeps and slow polling intervals,
avoid redundant container restarts and volume copies, share expensive setup
inside a file, shrink datasets where the assertion does not depend on size, and
balance shards by recorded durations (longest-processing-time first) so no shard
exceeds the budget. Do not change Java, migrations, schemas or product code; if
a product change is the only way, name it and its measured effect in the
handoff. Edit files only under your own worktree. Run the tier with
`bun scripts/goal/goalctl.ts slot -- corepack yarn qa --tier fault/recovery`
after your changes and report per-shard times. Estimate 60–90 minutes.
