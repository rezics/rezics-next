## Outcome

With the relay draining again, the shared stack's seed still fails first-page
reads whenever writes land at the same time:

- `GET /v1/works?limit=5` → 409 `read_basis_changed` "Restart from a current discovery generation"
- `GET /v1/agents/{id}` and `GET /v1/works/{id}/agent-credits` → 409 "Restart the read from its first page"
- `GET /v1/follows/{realm}?kind=realm` → 409
- `GET /v1/works/{id}/reader-state` → 503 `work_read_unavailable`

A person opening a page must never see an error because someone else wrote a
moment earlier. Design and implement, across the read families (the template
is `modules/work/read-contract.ts`):

1. A **first page** pins a consistent basis when the request starts (graph
   position, discovery generation) and serves it; it never returns 409.
2. **Continuation pages** keep their pinned basis for a bounded retention
   window; only an expired basis returns 409, and the client can restart.
3. Transient unavailability during relay catch-up or projection rebuilds
   returns the last consistent state (marked stale where it matters) rather
   than 503, with bounded internal retry where a snapshot cannot be pinned.
4. A QA case that writes concurrently (the seed pattern: many commands while
   the relay catches up) and asserts that first-page reads for Works, Agents,
   credits, follows and reader state never fail.

Keep the cost contracts and disclosure rules; say where a read cannot pin a
basis and what it does instead. Backend only, no dev servers.
