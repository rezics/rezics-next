## Outcome

The web keeps no type tables of its own. Type labels, cover shapes and use-versus-read wording in the eight
locales all come from `GET /v1/types` (G-637). This covers every surface that currently maps type IRIs:

- catalogue covers and labels;
- studio type picker;
- onboarding topics;
- discover filter labels;
- library "use" wording;
- manage queue subjects;
- work-page type labels.

Fixes that follow from this:

- A VideoGame (the visual-novel case) gets its registry cover and label; today it falls back to a book.
- An unknown type gets its base's default label and cover.

This brief removes R49 F4. F2, the page-kind dispatch, is G-644's.

## Approach

1. Add `features/catalogue/types.ts` with a cached server read of `/v1/types` and synchronous lookups
   (`typeEntry`, `typeLabel`, `coverOf`, `primaryActionOf`) over a module snapshot.
2. Seed that snapshot on the client through a small provider in `type-registry.tsx`, mounted once in
   `app/[locale]/layout.tsx`. The registry is identical for every reader, so the roughly 23 `coverKindOf` call
   sites keep their signatures.
3. Delete the per-type message keys the registry now supplies. Unused work-page type keys are removed by G-644, which claims those catalogs.
4. Add the ast-grep rule `web-no-type-iri-tables`, with rule tests. It fails on `https://schema.org/<Type>` and
   `rezics.com/vocab/<Type>` string literals in `apps/web/features/**` outside tests, stories and fixtures.

## Do not build

- Page-kind dispatch or new page layouts (G-644).
- Client-side type inference.
- A second label catalogue.
- A fetch per component.
- Backend changes.

## Acceptance

- **Browser, phone and desktop, en, ja and zh-Hant.**
  - Onboarding topics, catalogue tiles, the studio picker, zone facet labels and the library show registry
    labels.
  - A VideoGame tile shows the landscape cover and "Game".
  - An unknown type shows its base default.
- **API.** The web revalidates `/v1/types` with ETag and gets 304.
- **Class guard.** Adding a type IRI table back to `catalogue/work.ts` fails the ast-grep rule.
