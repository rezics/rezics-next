## Outcome

G-437 (merged: 77a6489b, e6bdd1a8; agent-profile-v2 in 023d5438) added
localized Agent names. Since then, on the shared stack (seeded before G-437,
so every Agent has a v1 profile), `task dev:seed` fails in its first step:

```
Main /v1/agents/98888c97-7ba7-4eec-bc59-70c6ed23af95/profile HTTP 422 agent_profile_validation_failed: Agent profile failed model validation
```

That Agent is the seeded person Daniel Chen. The seed's accounts step renames
him through the **v1** profile command (`agent-public-profile-v1`, display name
'Daniel Chen 陈丹尼' → 'Daniel Chen'). His current triples are only: `rdf:type
rv:Agent`, `rv:agentKind rv:PersonAgent`, `rdfs:label`, `rv:profileHandle
agent-<uuid>`, `rv:profileDisclosure rv:Public`, `rv:head`. Main's
`services/main/src/modules/agent/profile.ts` gets `command.status === 'invalid'`
back from Jena and throws. On a fresh stack the same seed passes, so the
failure depends on data written before G-437 (for example the update's new
`rv:profileNameFormat` / `rv:originalNameLanguage` / `rv:localizedName`
patterns, the revision it records, or the Jena mutation policy for this
profile). Real users all have v1 profiles, so this blocks every existing
person's rename.

1. Reproduce: seed a stack from a commit before G-437 (e.g. `c90c9516~5`),
   then run the current seed, or write a v1 profile directly and call the v1
   rename. Find exactly which check rejects it (SHACL shape or Jena policy).
2. Fix it so v1 renames and v1-to-v2 upgrades both succeed on existing data,
   and v2 stays valid.
3. Make the 422 diagnosable: include the first violation's path and constraint
   (no private data) in the problem detail and the log.
4. Integration test: a profile created before localized names can be renamed
   through v1 and upgraded to v2.
