## Outcome

On the shared dev stack every `POST /v1/reports` fails `503 revision_unavailable`
("Committed revision bytes are unavailable"), even for a Work created minutes
earlier, and other readers are exposed the same way. Cause found by the
manager: since `335bd94c` Work revisions are written through
`S3ImmutableObjects` when `MAIN_S3_ENDPOINT` is set (dev sets it; RustFS on
:9000), but `objectBytes`/`readComponentState` in
`services/main/src/modules/work/history.ts` read synchronously from
`MAIN_OBJECT_DIRECTORY` (`environment.objectDirectory`), and 57 files across
work, rating, context, contribution, classification, zone and others use that
path. The dev object directory has had no new file since 02:47.

Make every committed-revision read resolve bytes from the store the write
used, with digest verification, and decide between: (a) one async revision
reader over the configured `ImmutableObjects` (local directory or S3) used by
every caller; (b) a verified write-through local mirror plus lazy fill, if the
async change is too wide for one sitting — say which and why, and what
multi-host deployment would still need. Find out why QA did not catch this
(does QA configure S3 for Work objects?) and add a test that fails before the
fix on the configuration dev uses. Callers outside your claim may need a
mechanical signature change: keep each to the minimum and list them under
OWNER CHANGES.
