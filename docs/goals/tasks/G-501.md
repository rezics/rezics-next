## Outcome

Four guards back decision 7 and M4's exit ("the language guards fail on deliberate regressions"):
1. **Catalog gate.** `task i18n:check` fails on any missing, extra, empty or placeholder-mismatched
   key in any locale of any web, Accounts, official Zone or `packages/ui` catalog, and `task check`
   runs it. Today it exits 0 with 852 keys missing, reports 0 keys for two catalogs
   (communities, post-composer), cannot see `...spread` entries (Accounts `account` has 344 keys,
   it counts 270), and ignores `defineMessages` catalogs outside `messages.ts` and Zone strings.
2. **No implicit English** in `services/main/src`: `@en` literals in SPARQL templates,
   `language: 'en'` values, `?? 'en'` / `|| 'en'` defaults and `LANG(?x) = "en"` filters fail,
   except in a frozen `ignores` list of today's offending files (the ratchet; G-512, G-596 and
   G-513 shrink it). The text-index probe title in `work/activate.ts`/`search-readiness.ts` is a
   legitimate exception.
3. **One tag parser**: `Intl.getCanonicalLocales` and ad-hoc language-tag regexes outside the
   module G-504 names fail in `apps/`, `services/` and `packages/`, with a frozen `ignores` list
   (G-595 empties it). Persisted-profile patterns generated under `packages/model/src/generated`
   are exempt.
4. **No assumed direction** in `apps/web/features` and `apps/web/zones`: object-literal values
   `dir: 'ltr'`, `direction: 'ltr'` and `lang: ''` fail (type unions do not), with an `ignores`
   list of whatever G-515 and G-516 have not fixed when this merges.

## What to read

`scripts/i18n/check.ts` and `check.test.ts` (the current 330-line source tokenizer);
`apps/about/tests/catalogs.test.ts` (the runtime pattern to copy: import catalogs, compare leaves,
check placeholders, no empty text); `apps/web/i18n/catalogs.ts`; native-i18n values are plain data
(`{ $nativeI18n: 1, op: 'insert', pattern, bindings }`, `op: 'plural'` with `cases`);
`scripts/static/ast-grep/rules/no-native-select.yml` and its test.

## Approach

Replace the tokenizer with a runtime check: discover catalogs by file layout (every
`apps/{web,accounts}/features/*/messages.ts|messages/en.ts` with its `messages/<locale>.ts`, every
`defineMessages` module, `apps/web/zones/official/*/strings.ts`, the `packages/ui` table), import
the raw per-locale objects (not the English-merged loaders), and compare leaves; an English catalog
with zero keys is itself a failure. Keep `task i18n:check` as the entry (update its description in
`Taskfile.yml` and `docs/development/toolchain.md`) and call it from `task check`. The three ast-grep
rules follow the existing rule layout; build each `ignores` list from `main` at the time you
finish, then re-run it right before merge.

- Class found on 2026-10-01 (G-504 handoff): `apps/web/features/work-page/messages.ts` does not wire its existing locale catalogs, so zh-Hant readers see English although the translations exist. The runtime gate must fail when a `messages/<locale>.ts` file exists but its feature's `defineMessages` does not use it (and when a locale resolves to the English fallback for a key the catalog translates); fix this instance and any others the gate finds.

## Do not build

No translation memory, no "copied English" heuristic, no locale exemptions, no report formats, no
second checker next to the old one: delete what the runtime check replaces.

## Acceptance

Tests with fixtures fail for: a deleted translated key, an extra key, an empty string, a renamed
`{{placeholder}}`, a `{{x}}` outside `insert()`, an empty English catalog, a new feature catalog
not in any locale, a new `@en` in a Main module, a new tag regex in a web module, a new
`dir: 'ltr'` in a web adapter. Main at merge passes all four.
