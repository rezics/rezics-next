## Handoff and schema blocker

The audit found `role_revision` immutable and every `role_binding` pinned to one
exact family/revision. Advancing a family head does not change any existing
binding, and the public API only adds a new pinned binding or revokes one. A
proposal to approve that head change would have no live populated impact, so
no role-impact activation API was added. A separate binding migration operation
and its exact authority contract would be needed to create that behavior; the
manager must choose it as a new brief rather than treating G-036 as IAM05/30
completion.

The worker did find one owner invariant gap: direct SQL could retarget an
unreferenced role binding. Migration 033 now rejects changes to the pinned
family/revision, parties, lifetime, assigner and membership dependency, and
rejects resurrection after revoke. Its regression attempted direct SQL
retarget/recipient mutation and reactivation, then checked the denied role
admission and normal revoke. The selected real Account/Main/Access result
`20260926t132917-cc3565` passed on stable worktree source. The worker also
passed `yarn gen` and Main typecheck. `yarn check:backend` passed after merge
on `main`; selected merged API regression remains in the manager's QA queue.
