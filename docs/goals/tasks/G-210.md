## Outcome

Rezics UI (`packages/ui`, a maintained fork of SharkUI on Ark UI with the
Rezics Aura theme) has 95 components and no stories, so Storybook's MCP
manifest documents none of them and nobody has reviewed most of them against
Aura. Give these components stories and an Aura review:

button-group, input-group, input-otp, password-input, textarea, number-input, checkbox, radio-group, switch, slider, select, native-select, combobox, autocomplete, listbox, tags-input, field, date-input, date-picker, calendar, file-upload, editable, rating, segment-group, toggle, toggle-group

## Deliver

1. For each component, `packages/ui/src/components/<name>.stories.tsx` next to
   it (Storybook already loads `packages/ui/src/**/*.stories.tsx`). CSF3 with
   `satisfies Meta<typeof X>`, `tags: ['autodocs']`, a one-paragraph
   component description saying when to use it in REZICS (a community
   knowledge and catalogue site: Works, Realms, reading, ratings, moderation),
   one story per meaningful variant, size and state (default, hover/focus via
   play where useful, disabled, invalid, loading, empty, long content,
   zh-CN text such as 《三体》 and mixed Latin/CJK), and play tests with
   `storybook/test` for interactive behavior (open/close, keyboard, selection).
   Use realistic REZICS content, never lorem ipsum.
2. Dark mode: add a story (or a decorator in the story file) that renders the
   component inside a `.dark` wrapper with the page background, until a
   global theme toolbar exists.
3. Aura review: compare each component with Aura's matching component in
   `/home/edge/projects/rezics/rezics-next/.temp/arca-ui/aura/ui` (read-only)
   and the rules in `docs/development/design-system.md` (tokens, radius
   roles, card/float shadows, red never colors text, `-foreground` means
   text-safe tone on a tint). Fix material deviations in the component file,
   and put the reason for any non-obvious choice in a short code comment
   rather than in documentation.
4. Accessibility: the a11y addon runs with `test: 'error'`; fix violations in
   the component, not by disabling rules.

## Verify

Run Storybook from your worktree (`task dev` starts it on a random port; or
`task storybook`), open each story in a real browser (Playwright), take
screenshots in light and dark, and review them yourself. Screenshots go under
`.temp/` in the worktree, not in commits.

  the web tsconfig if the package has none)
