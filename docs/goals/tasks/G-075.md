Shared recovery structure; every new domain depends on it. Today
`content-recovery-coverage.ts` (version 4) hard-codes seven `content.*` and seven
`pkg.*` tables (no `source.*` table is covered), `access-recovery-coverage.ts`
lists Access tables by hand, and graph→Content references are enumerated by fixed
predicates. About a dozen phase-A schema tasks are adding tables in new Content
and Access schemas (`verification.*` just merged with 19 tables), and each would
otherwise edit these lists.

Deliver coverage version 5 that derives its table set from the PostgreSQL catalog:
every table in the owner database's application schemas, keyed by its primary
key (fail closed on a table without one). Keep an explicit, small exclusion
mechanism for disposable state (declared next to the table, for example a table
comment), and keep deterministic ordering and digests. Do the same for the
Access manifest. For graph→owner references, replace fixed predicates with a
generic rule (for example owner-row IRIs by a registered URN prefix per owner
schema) that a new domain extends without editing this module, and document the
rule in `docs/operations/recovery.md`.

Keep version-4 manifests readable or fail them with a clear version error;
retained recovery evidence need not validate under v5. Existing fault/recovery
tests must pass unchanged in meaning: run `coordinated-owner-cut`,
`content-publication-recovery`, `source-author-credit` and `work-title-control`
fault tests plus `services/main/tests/access-pitr.integration.test.ts` through
`goalctl test` (report, but do not edit, tests outside your claim). Add a unit or
fault test showing a newly created schema table is covered with no code change.
Estimate 60–90 minutes.
