## Outcome

The catalogue redesign (G-283) gives every cover card and the Work page one
primary action, Goodreads-style: **Want to read / Currently reading / Read**,
plus "add to shelf" and an inline rating. Main has generic Collections and
rating observations but no status shelves, no private "my collections" list
and no single read of "my state for this Work".

1. **Status shelves.** Per person Agent, a Work is on at most one of
   want-to-read, reading and read (with started/finished dates for read), set
   and cleared by one command with receipts. Custom shelves reuse Collections;
   decide whether status shelves are Collections of a reserved kind or their own
   owner, and say why. Default visibility follows the profile's library
   setting (G-238's library read is the public side).
2. **Reader state reads.** `GET` the viewer's state for one Work (status
   shelf, custom shelves containing it, the viewer's rating in the global and
   the current Realm Context, reading progress) and a batch form for up to one
   page of cards, so a grid of 24 covers costs one call. Signed-out callers get
   a cacheable empty state.
3. **My shelves.** List my status shelves with counts and my Collections
   including private ones, cursor-paginated, sorted by recent change.

Follow the read-family template (`services/main/src/modules/work/read-contract.ts`)
and command patterns; new event kinds need relay readers (see the inventory
test). Extend the demo seed (`scripts/dev/seed/**`, unclaimed; keep changes
small) so demo readers have shelves, through the API.
