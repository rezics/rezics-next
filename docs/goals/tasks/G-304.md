## Outcome

Studio (G-289) found that a newly provisioned person Agent can create a Work
and a text contribution, but Access gives it nothing else, so authors hit 403
on ordinary authoring. Extend the baseline member permissions (G-255,
`modules/access/baseline.ts`) so a verified person can work on what they
created, with the same receipt-proof style already used for
`contribution.create` on their own unpublished Work:

1. read their own contributions and submissions (`GET /v1/me/contributions`,
   `/v1/my/submissions` currently need representations nobody gets);
2. `work.edit` on Works they created (metadata, covers, tags proposals);
3. `content.draft` on their own Work and its chapter resources, with publish
   and search-eligibility gates keyed by resource that open automatically;
4. `submission.submit` for the author of a public text contribution, with the
   matching scope gates;
5. `media:owner:<agent>` and `media:avatar:<work>` so authors can upload
   covers and avatars;
6. acting contexts return the current vanity handle (they read `rv:handle`;
   Agents now record `rv:profileHandle`).

Each grant must be as narrow as the action, revocable with the Work or
membership, and covered by allow and deny tests (another person's Work, a
suspended account, a Work moved to an organization). Explain any grant you
decline to add.
