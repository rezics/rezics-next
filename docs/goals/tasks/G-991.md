## Outcome

On the shared dev stack every official Zone's `GET /v1/zones/{id}/presentation`
answers `400 invalid_zone_configuration` ("Zone configuration format differs"),
so official Zone pages are broken. Cause, as the manager traced it:

- `87b6b3dbc` removed `official.routeSegment` from `ZoneConfiguration`
  (`config-format.ts`) because names moved to the Access name registry, and added
  `prepareZoneNameCleanup` (`address/migrate-zone.ts`) to upgrade stored heads
  through `migrateGraphNames`.
- `migrateGraphNames` runs only in `scripts/dev/install.ts` (release install);
  `task dev:prepare` (`prepareDev` in `scripts/dev/cli.ts`) never runs it, so
  `access.name_graph_import` is empty on the shared stack and no Zone names were
  imported.
- Even in release, `migrateGraphNames` may defer ("identity addresses remain
  available"), yet stored Zone payloads then become unreadable.

Fix the class, not this stack:

1. **Readers accept every stored format they may meet.** A deferred or
   unfinished upgrade must never make stored data unreadable: reading a stored
   head accepts the legacy `official.routeSegment` (normalized away), while
   new writes keep the current shape. Apply the same rule to any other field
   removed from a persisted format in this workstream that you find
   (`git log --since=2026-10-01 -p -- '*format*.ts'` under `services/main`).
   Add a golden-fixture test of stored pre-change payloads so a future schema
   edit that breaks them fails a test.
2. **One owner-migration path.** `task dev:prepare` and release install run the
   same idempotent owner migrations, including the graph-name import, and a
   deferral is reported loudly (a failure in dev; a recorded, visible state in
   release), never swallowed into a warning nobody reads.

Then run `task dev:prepare` once on the shared stack (it is safe and
idempotent; Main keeps serving) and confirm with curl that the official Zones'
presentation reads return 200 and that their names resolve through
`/v1/addresses/resolve` (scope `zone:` or `space`, as the registry defines).
Run your tests with `bun scripts/goal/goalctl.ts test`.
