## Outcome

A Zone is a site a reader never has to leave. Under `/{locale}/r/{ref}/…` the host
renders whatever G-630 resolves, inside the Zone frame (header, tokens, protected
controls, the ordered navigation from the presentation read, breadcrumbs):

- Zone cards (modules, browse) link to `/r/{ref}/w/{id}`, or to `/r/{ref}/{segment}/{id}`
  when the card came from a mounted Collection; the Work page and its tabs
  (`contents`, `discussion`, `history`, `versions`) render inside the frame with the
  Zone's default Realm as their scope, as `?scope=realm` did. Reading (`/w/{id}/read`)
  stays global with a way back.
- A mounted document renders its published text; a mounted Collection renders a card
  grid with next/first links; a non-member URL renders the not-found page.
- A non-Work `detail` renders one typed "page not available yet" state in a single
  switch arm; the Wiki+ Zone brief replaces that arm with G-644's page.
- Canonical: a Work detail points to `/w/{id}`; documents and indexes are canonical.
- A fresh seed mounts a `guide` document and a `picks` Collection in the Books Zone,
  through the API, so the pages exist.

## Approach

1. Add the catch-all page; static Realm tab routes keep precedence. Resolve the Zone
   as `realmRoute` does (keep the UUID → official segment redirect with the path),
   call G-630 through the existing Main adapter and switch on `kind`.
2. Give the Work frame, tabs and `workHref` an optional base (default `/w/{ref}`,
   unchanged for every current caller) and reuse the existing tab views; reuse
   `TextReader`'s body for documents and `zones/card.tsx` for indexes.
3. Change `realmWorkHref` and its callers to take the Zone ref and the card's mount.
4. Render `navigation` in `zone-frame.tsx`; breadcrumbs = home → mount → resource.
5. New copy only in `features/realm/messages*`, all eight locales.

## Do not build

No client-side route matching, membership or population logic (Main decides), no
second Work page or copy of tab views, no per-type route tree, no official package
slot changes, no mount management UI (API only for now), no localized path aliases,
no sid codec (G-588), no preview UI.

## Acceptance

Through Main's API only. Real browser on the local stack, phone and desktop, light and
dark, English and one CJK locale: Books Zone home → card → Work page inside the frame
(URL, navigation, tabs stay inside, back to the Zone, Realm-scoped rating shown);
`/guide`; `/picks` page 2; a non-member URL → not found; a UUID Zone URL redirects to
the segment with its path; direct link after sign-in. Inspect screenshots. Class guard:
`apps/web/tests/g-655*.ts` fails when any Zone module or browse card whose Work is in
the population links outside `/r/{ref}/`.
