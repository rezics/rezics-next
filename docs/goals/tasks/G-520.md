## Outcome

M4 repair "private-name publication". Today the OAuth callback calls
`POST /v1/me/onboarding`, and `ensure.ts:21-26` provisions an active, public
Person labelled with the Account sign-up "Name" (`rezics_account_name` from
Account introspection → `accountDisplayName`) before the user sees a screen.
After this task, the onboarding API creates a Person only from a public name
the user typed. Without one it returns a typed `public_name_required` outcome
and writes nothing. The Account name never reaches Main.

## What to read

`docs/contracts/identity-and-access.md#one-authority-model` ("confirm the public
identity before publishing private Account data"); `services/main/src/modules/onboarding/ensure.ts`;
`services/main/src/routes/onboarding.ts`; `services/main/src/modules/agent/provision.ts`
(the saga you call; do not change it); `services/main/src/modules/agent/vanity.ts:35-39`
(`suggestVanity`); `services/account/src/introspection.ts:55-64`;
`services/main/src/modules/account/verify-assertion.ts:108-109`.

## Approach

1. The onboarding body gains `displayName` (1–200 chars, the same validation as
   `provision.ts:28-29`). Existing active Person → replay it unchanged, whatever
   name is sent (renames go through `PUT /v1/agents/:id/profile`). No Person and
   no name → 409 `public_name_required`: no provision row, no authority subject,
   no graph write. No Person and a name → provision exactly that name, then
   `suggestedHandle` from it (`suggestVanity`, falling back to `reader`).
2. Delete `rezics_account_name` from introspection and `accountDisplayName`
   from `VerifiedPrincipal`, so the type system forbids the leak. Update the
   tests that set the field.
3. Keep the profile literal `person-onboarding-v1`. It is an unreleased request
   shape, not a persisted model profile.

## Do not build

No draft/unconfirmed Agent state, private-then-public transition or new column.
No migration or backfill for dev Agents that already carry Account names: there
is no production data. No change to `provision.ts`, `graph.ts` or the model
profiles. No Account "public name" field.

## Acceptance

- API: sign in with an Account named `PRIVATE-MARKER-<uuid>`. Onboarding without a
  name → 409, and the principal has no `access.agent_provision` row and no
  session Agent. With `林梅` → 201,
  and the public Agent (`GET /v1/agents/:id`, `/v1/handles/:h`) is labelled `林梅`.
  Replaying with another name → 200, same Agent, label unchanged.
- Class guard (`tests/qa/integration/g-520-private-name.test.ts`): after a full
  onboarding, the marker appears in no Main public read (Agent, handle, credits
  search, public Realm roster) and in no Jena triple. Deleting the name check in
  `ensure.ts` makes the test fail.
- The web half (callback and onboarding screen) is G-537.
