## Outcome

G-323 made first-page reads survive concurrent writes with bounded retries and
five-minute discovery retention, but reported that sustained churn can still
exhaust retries (503/422) and that continuations of non-discovery reads
invalidate when their basis moves, because Main's Fuseki client has no retained
graph transaction ([Jena remote transactions](https://jena.apache.org/documentation/rdfconnection/#remote-transactions)).

Design and, where the design holds, implement retained read snapshots:

1. **Graph**: a read that pins a graph position can keep reading that
   position for its retention window even while writers advance — for
   example through the command module (`infra/jena/command-module`) serving
   reads at a retained dataset version, versioned named graphs, or a bounded
   copy-on-write read view. Measure the write and memory cost at the qualified
   corpus sizes and choose; record the decision and its reasons as a comment
   beside the code.
2. **Access**: authority checks in a pinned read use one consistent Access
   state for the whole read (a repeatable-read transaction or a recorded
   authority revision), still revalidated at the end so revocation is never
   bypassed.
3. Continuation pages of every read family keep their pinned basis for the
   retention window; `read-stability.test.ts` extends to continuations under
   sustained churn.

If the right answer is not to build it now, say so with measurements and
leave a precise design. Backend only, no dev servers.
