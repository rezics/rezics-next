## Outcome

Studio v1 (G-289) saved text through text contributions because Main refused
authors everything else. Main now allows it:

- G-304: authors can edit their Work's metadata, draft content on their own
  Work and chapters, publish and make it searchable (resource-scoped gates),
  upload covers and avatars, read their own contributions and submissions,
  and submit public contributions to Realms;
- G-305: `GET /v1/me/agents/{agent}/works` (the inventory), draft heads on
  contributions and content drafts with `stale_head` carrying the current head
  and `byteDigest`, `POST /v1/works` with language and localized fields, and
  atomic `POST /v1/works/:id/chapters` plus `GET /v1/works/:id/content-variants`.

Make Studio the place a serial author lives in (Royal Road, AO3 and Wattpad
author tools are the bar):

1. Studio home on the inventory read: drafts, published, in review, per
   Agent; no bounded scan.
2. A Work's chapter list (order, status, word count, last saved), create a
   chapter in place, reorder where the API allows.
3. The editor saves through content drafts (swap the save function behind
   the existing autosave engine), with cross-device conflicts from real draft
   heads; publish a chapter and republish an update.
4. Metadata editing for creators (title, description and tagline per
   language, completion status, cover upload with crop preview, tags as
   proposals).
5. Submit to Realms with the Realm's review mode shown, and submission status.

Missing APIs go to PROPOSED TASKS. Strings in per-locale message files
(follow G-288's layout for your features); internal links with
`features/shell/localized-link.tsx`; reuse `WorkCover` and catalogue parts.

## Verify in a real browser

Against the shared stack as a demo author (credentials in
`scripts/dev/seed/plan.ts`): create a Work in Chinese, add three chapters,
write with autosave, force a conflict from a second tab, publish, update,
upload a cover, submit to a Realm. Screenshots at 1440x900 and 390x844, light
and dark, en and zh-Hans. Memory is tight: run only the web dev server while
verifying (no Storybook at the same time, no Accounts app) and stop it when
done.
