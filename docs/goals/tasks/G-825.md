## Outcome

Since `f0d50d85` (G-830, Work composition) two structure profiles,
`book-composition` and `work-composition`, declare the same scope prefix and
receipt family. The relay (`services/main/src/modules/outbox/relay.ts`) requires
exactly one matching registration, so every Book- or Work-composition structure
command event fails with "Structure command event has no matching terminal
receipt" and blocks the relay behind it. After this task the relay accepts
several matching registrations when they resolve to one distinct receipt
family, and still fails on a real ambiguity (two different families).

## Approach

Change only the matching rule: collect the matches, deduplicate by receipt
family, proceed when exactly one family remains. Keep the error for zero or
several distinct families.

## Do not build

No change to profiles, scopes or receipt families; no new registry.

## Acceptance

- A Book-composition command and a Work-composition command each relay to
  their terminal receipt; the relay does not stall.
- A synthetic registration with a second, different family for the same prefix
  still fails loudly.
