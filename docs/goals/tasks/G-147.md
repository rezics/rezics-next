Phase D completion gate. GOAL.md requires that "all required paths have reviewed
complexity bounds and applicable counterexample checks", and
`docs/storage/workload-budgets.md#complexity-contracts` requires a cost contract
for every API operation, job, importer, projection and recovery/rebuild entry
point. `docs/testing/complexity.md#inventory-and-coverage` says the inventory is
not yet an executable gate. Workers wrote contracts beside their operations (the
complexity page, about 50 module README or `cost-contract.md` sections, route
comments), but nothing proves every entry point has one.

Build that gate:
1. Enumerate entry points: every operation in `generated/openapi/main/public.json`
   (448 method/path pairs), plus registered jobs, importers, projection recipes,
   outbox handlers, recovery/rebuild commands and operational scripts that the
   contract policy names (use the discovered registries under
   `services/main/src/modules/*/` and `scripts/operations/`).
2. Add a discovered registry under `scripts/qa/cost-contracts/*.ts` (one file per
   owner, like `scripts/qa/coverage/`), mapping each entry point, individually or
   as an operation family sharing one reviewed bound, to: the contract's document
   and anchor, its variables and bound as written there, and its evidence test
   identities (tier, file, exact title) or an explicit unverified-engine note.
3. Add `tests/qa/unit/cost-inventory.test.ts` that fails when an entry point has
   no contract, a cited anchor does not exist, or an evidence test title is not
   present in its file.
4. Populate the registry from the contracts that exist. Do not invent bounds:
   where an entry point truly has no written contract, list it as missing in
   your handoff, grouped by owner module, with a count. Do not write the missing
   contracts in this task unless they are few (under about 15); the manager will
   split larger gaps across workers.

Update `docs/testing/complexity.md#inventory-and-coverage` to describe the
executable gate. Do not edit `docs/storage/workload-budgets.md` (G-146 holds it).
Run the unit test and report counts: entry points, covered, family contracts,
missing. Edit files only under your own worktree. Estimate 60–120 minutes.
