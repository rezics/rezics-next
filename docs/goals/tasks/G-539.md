## Outcome

Wiki+ needs public character pages; G-644 (anonymous character pages) depends
on this. Today no semantic resource can be public:
- `canReadSemanticResource` (`admission.ts:366`) is grant-only.
- `summary.ts:376` hard-codes `row.public = false`, and the BIND at
  `summary.ts:222-223` runs with `?work` unbound. That is a latent leak, masked
  only by line 376.
- `media/access-batch.ts:22-56` repeats the grant query, so there are two
  enforcement points.
- Anonymous readers (`resources.ts:37`, `media.ts:107`, the `semantic.ts` GETs)
  skip semantic resources.

Rule (kernel pass and manager, 2026-09-30): an accepted semantic resource is
public unless restricted. It is publicly readable, anonymous included, exactly
while all of these hold:
1. Its `semantic:read:<r>` gate is not strong-closed.
2. Its current `rv:semanticHead` revision is committed and `rv:lifecycle rv:Active`.
3. It has no `rv:protectionHead`.
4. No Access policy governs `semantic:read:<r>`. A policy is the restriction
   mark; `canReadScopedResource` already uses "no policy on the scope" for
   baseline eligibility.
5. It is linked to at least one Work that is publicly readable now (manager,
   2026-09-30): characters, places and events of an unpublished draft must not
   leak through their own pages, and a resource linked to no Work stays
   private. Use the relation the current semantic model already records
   between such a resource and its Work (find it in the semantic profiles and
   the wiki fixtures); add a link predicate only if none exists, as the
   smallest profile change, and say so in the handoff. The link must be
   writable only by someone with edit authority over the resource.

Staged pages and unaccepted proposals are drafts: they have no committed head,
so they stay private. Resources without `rv:semanticHead` (Zones, Collections,
relation definitions and occurrences) keep today's behaviour. Only the
current head is public; older revisions still need a grant.

## Approach

Add `access/semantic-disclosure.ts` with a batched `publicSemantics(client, refs)`
(one bounded Jena query plus one policy lookup). Use it in these places:
- `canReadSemanticResource` accepts a null principal and actor.
- `access-batch.ts` returns public and granted resources separately.
- `summary.ts` sets `row.public` from the rule, fixes the unbound BIND and drops
  the override.
- The anonymous readers call it.

Restricting or unrestricting is the existing policy command on
`semantic:read:<r>`. Confirm that an edit grantee of the resource can issue it;
if not, add only that authority check. Update `semantic/README.md`.

## Do not build

No disclosure column, draft or accepted state, migration, or profile version
beyond condition 5's link if none exists. No Context-, Statement- or Zone-mount-based disclosure. No
private-Context resources: worldbuilding is deferred and will create its
restriction policy at creation. No anonymous Zone navigation (Zone area).

## Acceptance

`tests/qa/integration/g-539-semantic-disclosure.test.ts`, anonymous and
signed-in:
- A committed character linked to a public Work is readable, and present in
  the public summary, preview and search. Linked only to a private Work, it
  gives 404 until that Work becomes public; unlinked, it gives 404.
- A staged page, a retired or protected resource, a restricted resource (policy
  set) and a strong-closed gate each give the same 404 as absent. A grantee
  still reads the restricted one.
- An older revision needs a grant.
- WIKI03 and `zone-wiki.test.ts:229-239` pass. Mark their private members
  restricted if their fixtures relied on grant-only privacy, and say so.
- Class guard: reintroducing the unbound BIND or a second enforcement path
  fails the test.
