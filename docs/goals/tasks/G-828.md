## Outcome

Decision 12 (complete traversal) for Zone browse: today it reads a 60-row
window (`browseWindow`), so a Zone with more adopted Works silently truncates.
After this task every browse sort and filter traverses every adopted Work with
keyset paging and no window.

## Design (from `/home/edge/projects/rezics/rezics-next/.temp/manager/reviews/G-556.md`)

- Access migration 879: one table `access.zone_browse_entry(realm, work,
  adopted_order, updated_at, word_count)`, primary key `(realm, work)`; indexes
  `(realm, adopted_order DESC, work DESC)`, `(realm, updated_at DESC NULLS LAST,
  work DESC)` and `(work)`.
- Writers: the relay consumer of Realm selection receipts, the serial
  statistics projection, and one idempotent backfill (run after startup, never
  blocking it; bad rows skipped and logged).
- Reads: keyset on `(key, work)` with the length and Concept filters, 64 rows
  per batch; Fuseki checks public, type, status and language per batch; the
  cursor is the last row examined, so hidden rows never truncate the traversal.
- Relevance sort uses the merged ranked catalogue search restricted to the
  Realm. Delete `browseWindow` and the 60-row window.

## Do not build

No per-domain columns, no cache service, no change to Zone routes or Facets.

## Acceptance

API: a Zone with 1,000 adopted Works traverses each sort and filter completely
without duplicates or gaps; a Work adopted mid-traversal appears at most once;
private Works never appear or count.
