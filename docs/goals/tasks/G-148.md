Phase D repair. Record run 6 (`.artifacts/qa/20260927t085508-ab3577`, log
`/home/edge/projects/rezics/rezics-next/.temp/qa-record-6.log`) passed every test
and every one of the 276 cases, but the integration tier took 484.9 s against its
480 s budget. Two causes:

1. Order dependence. Files keep failing after other files in a shared shard and
   passing alone: run 6 `access-iam-reconcile`, `graph-query-cases`,
   `context-advanced-cases`; run 5 `source-field-cost`; run 2
   `source-score-live`, `context-advanced-cases`, `rating-global-synthesis`;
   earlier `export-api`, `context-rule-cases`, `search-grouped-native`,
   `theme-activation-api` and the files G-129/G-142 isolated. Isolating each one
   is not converging. Find the shared state these tests trip over (for example a
   singleton Global Context or classification head, dataset control or
   generation, an Access policy or scope-gate singleton, a fixed IRI or sequence
   assumption) from the failing assertions in the shard logs, and make the
   tests or their support create their own isolated state so they pass in any
   order. Do not weaken assertions.
2. Singleton project cost. 37 isolated files each start their own stack and
   stack starts are serialized (`concurrencyGate(1)` in `scripts/qa/cli.ts`);
   the five shared shards finish in about 180 s. Start stacks concurrently where
   the port-collision retry makes that safe, and move files whose order
   dependence you fixed back into shared shards.

Keep every tier budget. Run the whole integration tier twice in a row with
`bun scripts/goal/goalctl.ts slot -- corepack yarn qa --tier integration`; both
must pass with no isolated reruns and a wall under 420 s. Report per-shard times
and the root causes found. Use `bun scripts/goal/goalctl.ts owner <path>` before
any product edit and list it. Edit files only under your own worktree. Estimate
60–120 minutes.
