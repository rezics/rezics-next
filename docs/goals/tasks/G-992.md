## Outcome

G-991's run of the graph-name import on the shared stack skipped the official
Zone `mods` (holder `https://rezics.com/id/a60fd261-cec7-43ab-a727-f7331d7df8f8`):
"Skipped legacy name; holder uses its identity address — Former name is
reserved". Reserved words (`1010_name_registry.sql`) protect platform
namespaces from users; an official Space or Zone is the platform, so it should
hold such a name (see [durable addresses](../../product/urls-and-seo.md#durable-addresses)).
Ordinary holders must still be refused.

1. Let official holders claim reserved words through the registry's normal
   path (an explicit platform-authority flag checked by Main, never a
   user-supplied field), and keep refusing everyone else.
2. The import treats a completed epoch as final, so a skipped name is never
   retried. Make skipped rows repairable: a rerun retries the skipped report
   rows idempotently and records the outcome.
3. Prefer publishing the upgraded Zone bytes in `migrate-zone.ts` through the
   object store the way normal Zone writes do (G-991 had to prestage them by
   hand), if that is a small change; otherwise list it under PROPOSED TASKS.

Then run `task dev:prepare` on the shared stack and confirm with curl that
`/v1/addresses/resolve` resolves `mods` in its scope. Tests through
`bun scripts/goal/goalctl.ts test`; migrations 1027–1028 only if needed
(check the highest on `main` first).
