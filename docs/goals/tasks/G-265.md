## Outcome

The baseline member policy (G-255, merged: verified accounts take part without
manual grants) left two gaps that block the main site's community features:

1. **Replies and comments.** Ordinary members cannot reply or comment because
   there is no author-bound Content draft path for replies (author provenance
   from the acting Agent through Access to the Content draft). Implement it so
   a verified member acting as their person Agent or pen name can comment on a
   contribution revision and reply in a Realm discussion, with the existing
   review/placement rules for Realm replies, edit and delete of their own
   comments within policy, and moderation hooks intact.
2. **Publication selection.** **Product decision (manager):** the Work's
   maintainers (the creating Agent and Agents it grants maintainership) may
   select which published contribution is the Work's Main Version text for each
   language; Realms keep adopting independently through their own selections
   and submissions (G-257). Today publication selection is denied to everyone
   without explicit grants. Implement maintainer authority (grant on creation,
   transfer/add maintainers with receipts) and the selection admission.

Then extend the demo seed (`scripts/dev/seed/**`) so it creates comments,
replies and Main Version selections through these APIs with no explicit grants,
and report what the site can now show.

Owner schema first, then the command path, then reads; tests for denied (not a
maintainer, suspended, unverified), stale (selection head moved), concurrent
selections, erasure, and replay.
