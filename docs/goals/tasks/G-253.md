## Outcome

A manager wave run of the affected backend tests on current `main` (after many
merges: typed QA case declarations, Account email verification/passkeys/admin
in `services/account`, new Main read routes) failed these, under host load:

1. `tests/qa/integration/source-authenticated-api.test.ts` —
   `IAM10/LIVE01/…/PKG20: real Account and Access fence source and package
   operations` hit its 30 s timeout. It uses a real Account; the Account service
   now requires verified email for sign-in (G-205), which may be the cause.
2. `tests/qa/integration/package-install-api.test.ts` — `PKG15: unsafe hook
   output is rejected and leaves no package mount` hit the 5 s default timeout.
3. `tests/qa/integration/theme-activation-api.test.ts` — `VIEW09` replay
   returned `theme_activation_pending` 503; it depends on a 3 s approval expiry
   and a 3.3 s sleep (timing race seen before).
4. `tests/qa/unit/acceptance.test.ts:99` — `QA06: failure rerun selects failed
   names without borrowing prior passes` fails on `main` (a unit test).

For each: run it alone (`bun scripts/goal/goalctl.ts test <file>` with
`REZICS_QA_SHARDS=4`), decide whether it is a regression, a fixture that must
follow a deliberate product change (for example seed identities as verified),
or a timing flake, and fix it at the right place. Fix flakes by removing the
race (deterministic clocks or waiting for the state), not by only raising
timeouts. If the fix belongs in product code outside your claim, use
`goalctl owner` and report it; if another task owns it, hand off with the
exact change.

## Checks
