## Outcome

REZICS is natively multilingual (docs/plan/frontend.md, "Natively
multilingual, not bilingual"): every UI string ships in all eight locales.
An audit on 2026-09-28 found English and Simplified Chinese complete and each
other locale missing about 600 of ~2,560 web keys (they fall back to English
silently), for example:

| Feature | missing per locale |
|---|---|
| concept | 71 (no catalog file or loader at all yet) |
| zones | 87 |
| work-page | 81 |
| settings | 80 |
| feed | 62 |
| library | 53 |
| author | 7, shell 5, discover 2, search 2, realm 1 |

Translate every key that is missing in your locales (de, fr, es) for the web
features you claim, and create the files that don't exist (for `concept`,
add the loaders to `apps/web/i18n/catalogs.ts`: G-439 adds them for every locale, so only create your `concept/messages/<locale>.ts` files with a default export). Compare each
`messages/<locale>.ts` against the feature's English `messages.ts`
(`scripts/i18n/check.ts` prints the missing keys per feature and locale).

Write each language as a native product writer would, not word for word:
- follow the terms and tone the locale's existing files already use (read
  them first), and keep product names consistent: "Realm" is a product name in
  English only; other locales use their plain word for a community, as the
  existing files do (docs/plan/frontend.md, Languages);
- keep every placeholder (`{{count}}`, `{{name}}` …) and use the project's
  plural and insert helpers where a count or name sits in the sentence, so
  word order and plural rules are right for the language;
- UI length matters: buttons and tabs stay short.

Don't translate `manage` (G-435 owns it), `onboarding` (G-431 is rewriting it) or the games/software Zone packages
(G-433 owns them); they get a later pass.
