## Outcome

Read `docs/plan/frontend.md` ("Principles", "Zones", "Main site routes"), then
the research behind the Zone decisions:
`/home/edge/projects/rezics/rezics-next/.temp/manager/research-zones.md` and the
KadoKado screenshots in `.temp/manager/refs/kadokado-*.png` (the maintainer's
reference for Zones). A Zone is a Realm's publication; `/r/{realm}` is where
it lives. Build it so that the official Fiction Zone feels like a curated
web-fiction publication in KadoKado's spirit, and any community Realm gets a
good page from tokens and modules alone:

1. **Renderer and modules** in `features/zones/`: a typed module registry
   (hero carousel, rankings with day/week/month, editor list, new and rising,
   latest chapter updates, reader quotes, recent decisions, genre entry
   points), each module a component with stories, reading the Realm's
   curation. Every pick links to its decision. Covers use `WorkCover` from
   `packages/ui` (G-283 is redesigning it; use what is on `main`).
2. **Themes**: presentation tokens (preset, accent, scheme, density, radius,
   heading scale, surface tint, hero image) mapped to CSS variables scoped to
   the Zone, with one visual story per preset (Clean, Editorial, Vibrant,
   Serial) in light and dark; automatic text contrast; a reader toggle to turn
   Zone themes off.
3. **Official Zone packages**: the first-party code path from the Zones
   decision — `apps/web/zones/official/<slug>/` rendered server-side through
   named slots, loaded only when Main reports an approved package, with the
   token-and-layout fallback, `?safe` mode and a nonce CSP. Build the Fiction
   Zone package as the first one and make its fallback look good too.
4. **Realm tabs**: Works, Discussions, Decisions, About on the same frame,
   using the Realm reads already in Main (G-239 Realm home, G-249 profile,
   G-271 directory, G-265 replies).

Main APIs in flight: G-290 (zone presentation schema and read, official Zones,
theme lifecycle) and G-291 (rankings, module reads, taglines and serial
counts). Build against their contracts as they land on `main` (rebase often);
until then keep each module behind a typed seam with story fixtures, never a
client-side reimplementation. Missing fields go to PROPOSED TASKS.

Strings go in your features' `messages.ts` (English and `zh-Hans`; follow the
per-locale layout if G-288 has landed). Build internal links with
`features/shell/localized-link.tsx`.
