## Outcome

G-596 (merged) made the Zone owner command keep a Zone name and its language
in the manifest, but `services/main/src/routes/zones.ts` accepts neither name
nor language and the Zone reads return no language or direction. After this
task, creating or renaming a Zone over HTTP takes `{ name, language }` (BCP 47;
`und` when the writer did not choose one — never the interface locale), and
Zone reads return the name with its language and direction from the shared
language contract (`packages/model` language module, G-504).

## Do not build

No new profile, no schema:name triple on the Zone (G-596's review removed it),
no language guessing on the server.

## Acceptance

API: create a Zone named in Arabic with `ar` → the read returns `ar` and `rtl`;
a Zone named without a language reads back `und`; a rename keeps revision
fencing (stale → 409).
