Phase-A preparation foundation. Read `docs/storage/workload-budgets.md#data-preparation-and-import`,
`docs/testing/test-harness.md` (Load, Environment and isolation) and the existing
`scripts/load/{restore,corpus,practical,baseline}.ts`. Today background data is
seeded through public commands (1,000 Works took 899 s; 9,900 Works ~166 min).

Deliver `yarn fixture:build` (declare it in `docs/development/toolchain.md` first,
then `package.json`) that builds a deterministic background corpus **directly**
into owner storage for the current owners, never through public commands:
PostgreSQL owners (Content, Access, relay/outbox checkpoints as needed) via COPY
or batched inserts; the TDB2 graph via the pinned Fuseki image's offline loader
or bulk upload into a fresh dataset; jena-text/Lucene built for that generation;
objects into RustFS. Cross-owner references (Work IRI ↔ Content revision ↔
Access grant/Agent) must be consistent. Imported rows get no fabricated
interactive receipts. Then stop services and save one consistent backup with a
manifest (fixture version, seed, profile, migration/model/analyzer digests,
engine image IDs, row/triple counts).

Extend `yarn fixture:restore` to restore an isolated writable copy of that
backup, run migrations/readiness and a minimal smoke, all under the single
600-second deadline, reading only the manifest (no corpus rescan).

Make it extensible: one generator module per owner (`scripts/fixture/owners/<owner>.ts`)
with a small documented interface, so domain schema tasks add their tables later.
Profiles: `small` (about 1,000 Works) and `medium` (about 100,000 Works); size
by entities, not triples. Measure build time, bytes and restore time per profile.

Tests: unit determinism (same seed and profile give the same manifest digest);
one registered load or integration test that restores the built fixture and
performs a fresh real API Work create plus an exact read of a bulk-loaded Work.
Update the workload-budgets and harness pages with the measured facts only.
Report restore time; if the medium restore exceeds 600 s, report the bottleneck.
Estimate 90–120 minutes.
