## Outcome

G-415 gave Recipes, Prompts, Skills and Guides their own Work pages. The
manager used them in a real browser (Weekend buttermilk pancakes, Recipe
scaling skill) and found them working but below the sites people compare
them with (NYT Cooking, Serious Eats and Paprika for recipes; skills and MCP
directories and prompt libraries for prompts and skills):

- **Scaling.** At 8 servings the main line shows "3 cups" and the
  ingredient's name appears only in the small grey original ("1 1/2 cups
  flour"). The scaled line must read as a full ingredient ("3 cups flour"),
  with the original as a quiet hint. Units are not pluralized ("2 cup").
  Count ingredients do not scale: "1 egg" stays with "Keep this amount as
  written", where it should become "2 eggs" (only judgment ingredients such as
  salt, spices and leavening at large ratios deserve the note). Fractions
  should round to kitchen-friendly values (⅓, ½, ¾), and a unit toggle
  (US / metric) is expected where the quantity is measured.
- **Header action.** The header's primary button says "View recipe" or "View
  skill" on the page that already shows it. On a recipe the primary action is
  Cook this (and Save); on a prompt or skill it is Copy or Install. Don't
  repeat the page as an action.
- **Skill and prompt pages.** The meta line lacks the type ("Skill ·
  English"). "Try it" is only advice; show how to use it with common agents
  (for example a copyable install or usage snippet per agent the Work
  declares) and the requirements it declares. Keep "Tested models" and
  "Examples" only when there is data, or say how to add them.
- **Seed.** The seeded pancake recipe's Notes repeat its title and summary.
  Give it real notes, and give the seeded prompt and skill real examples.

Keep Main as the owner of scaling (`services/main/src/modules/recipe`); the
web renders what Main returns.
