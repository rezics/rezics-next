## Outcome

Security pass 1 (`/home/edge/projects/rezics/rezics-next/.temp/manager/archive/G-895/report.md`, H1)
reproduced that an `r18` assessment makes `/v1/suitability` answer
`eligible=false`, yet anonymous `POST /v1/resources/summaries`,
`GET /v1/public-previews/:id` and `GET /v1/resources/:id/statements` still
return the title and values. After this task an assessed, gated target (and
anything owned by a gated Work) is withheld from every reader the policy does
not admit, on every read and delivery path, with the same response as absent
for public reads. Unassessed content stays readable, as the manager decided.

## Approach

- One batched eligibility check in the shared disclosure boundary (the public
  Work predicate and target resolution that every read already calls), not
  per route: current target and owning-Work assessments plus the reader's
  channel evidence (age/country as the contract defines; unknown means not
  admitted for gated classes). Apply it before matches, counts, cursors and
  hydration; an assessment-store outage fails closed for assessed targets.
- Media delivery and delayed derivatives (search index, sitemap, relation and
  composition cards, notifications, exports) inherit it through the same
  boundary; where one does not, fix that call site or list it.
- Read `docs/contracts/classification-judgments.md` and
  `docs/operations/trust-and-safety.md` for the classes and gates.

## Do not build

No new assessment model, no UI, no per-route policy copies, no new tables.

## Acceptance

Adverse API tests for the three reproduced handlers plus search, counts,
media and export: gated target hidden from anonymous and unknown-age readers,
visible to an admitted reader; unassessed stays visible; an assessment outage
hides assessed targets. Class guard: every GET under `/v1/resources/*` and
public preview uses the shared boundary (route-list test).
