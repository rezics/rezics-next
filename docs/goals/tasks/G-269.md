## Outcome

The main site's Search page (G-256, `apps/web/features/search/**`) has to make a
second call to `POST /v1/resources/summaries` (untyped response, validated at
runtime) because phrase results carry only IRIs. Make search results
first-class for a UI:

1. **Typed Work cards in phrase results:** title (localized with fallback
   basis), cover, Work types, primary credits, a scoped rating summary (for the
   query's scope) and a few classification tags, reusing the discovery
   `workCard` shape where it fits, within the existing cost contract; or type
   the summaries response if embedding breaks the bound — explain the choice.
2. **Facets:** Work-type include/exclude filters and language/term facet
   counts (exact or lower-bound, honestly labelled) on phrase profiles.
   Keep match reasons and completeness information.

Then update `apps/web/features/search/**` to use them (unclaimed after G-256
closed; use `goalctl owner` and keep the change small), and verify in a browser
with Playwright (the Codex browser plugin is broken on this host).
