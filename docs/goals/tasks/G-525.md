## Outcome

Decision 8 ("Handles retain redirects, reuse restrictions and confusable
protection") and `docs/product/urls-and-seo.md#durable-addresses` ("durable
rename redirects and no automatic retired-name reuse … UTS #39"). A person or
organization is a brand that must not be hijacked. Verified defects:

- A renamed handle is kept for only 90 days (`vanity.ts:8,148-150`). After
  that `ON CONFLICT … DO UPDATE` hands it to any other Agent, and
  `tests/qa/integration/agent-handle.test.ts:116-121` asserts that takeover.
- The owner cannot take its own old handle back.
- Web handle redirects are temporary 307s (`[handle]/page.tsx:29-42` and two
  sibling pages).
- Handles have no confusable check beyond ASCII-only, so `lin_mei`/`1in_mei`
  and `rn`/`m` are both allowed.
- Display names reject only control characters, so bidi overrides (U+202A–202E,
  U+2066–2069) pass.

## Approach

1. Retirement is permanent (`retired_until = 'infinity'`). Only the Agent that
   held a handle may reclaim it; other Agents get `unavailable`.
2. Migration 874 adds an immutable SQL `access.handle_skeleton(text)` from the
   pinned ASCII subset of UTS #39 confusables, a stored generated column and an
   index. `change()` and `availability` reject a handle whose skeleton another
   Agent holds (active or retired), under the existing lock, with reason
   `confusable`. One implementation, in SQL.
3. The three web handle pages use `permanentRedirect` (308). Update the comment:
   permanent is now correct because a retired name never moves to another Agent.
   The API keeps its `resolution.redirect` flag.
4. `provision.ts` and `profile.ts` name validation also rejects bidi embedding,
   override and isolate controls.

## Do not build

No unified alias registry, handle/wiki-title alias model (M5 G-587), new
confusables dependency, non-ASCII handles or Agent merge redirects. No imported
creator claims: no imported creator is an Agent yet (authors are Open Library
references), so claims wait for catalogue Person identities.

## Acceptance

API:
- Rename A `lin_mei` → `lin_new`. `@lin_mei` resolves to A indefinitely;
  Agent B claiming `lin_mei` or `1in_mei` → unavailable/confusable; A may
  reclaim `lin_mei`.
- Concurrent claims of two confusable names → exactly one succeeds.
- A display name containing U+202E → 400.
Browser: the old handle URL answers 308 to the new one, and tabs and shelves
keep their path.
Class guard: a skeleton table test plus the updated takeover test fail if the
reuse window or the skeleton check returns.
