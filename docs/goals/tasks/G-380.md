## Outcome

G-368 found the Mods Zone's game and loader chips can't work, and the
review saw "Couldn't load Games and loaders" there:

1. No API or bootstrap creates `urn:rezics:classification-context:global`,
   so `POST /v1/classification-propositions` always cancels
   (`409 operation_cancelled`) and the seed step "Mods game and loader
   concepts" (`scripts/dev/seed/realms-step.ts`, `modsContext`) fails. The
   seed can't add it, because the product Fuseki exposes no update endpoint
   and the command module needs a sequence advance with an outbox event the
   relay knows. Bootstrap the global context in Main the way
   `semantic/command.ts` `ensureModelGeneration` bootstraps model
   generations: a system terminal and an owner outbox handler (authority
   `system`), called lazily by proposition and context creation. Adding an
   event kind the relay doesn't know would stall it, so register it.
2. The genres read (`/v1/realms/:realm/modules/genres/:context`) returns
   Concept IDs, but Discover's `term` filter matches Sense IDs; return what
   Discover can filter by, and keep the Context in the chip link distinct
   from Discover's rating Context. The web side (`apps/web/features/realm/modules.ts`
   `genres()`) is held by G-377; state the new contract in the handoff so a
   follow-up can wire it.
3. With 1 working, have the seed classify the four seeded mods by game and
   loader and refresh discovery. Skill descriptions in the Hub seed
   (`official-zones-step.ts`) are `content.slice(0, 180)`, cut mid-word
   ("…for a taste c"); write a real one-line description per Skill, and
   publish it as a new revision on a stack that already has v2.

Tests cover the bootstrap (once, concurrent callers, after a reset), the
proposition flow and the genres contract.

## Verify

Against the shared stack: `task dev:seed` completes the Mods concepts step
without `operation_cancelled`, the genres read for Mods returns the games and
loaders with counts, and a Discover query with one of its terms returns the
matching mods. Use only the backend; no web dev servers.
