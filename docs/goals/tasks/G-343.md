## Outcome

Fix finding SR-2 (High) of the security review
(`/home/edge/projects/rezics/rezics-next/.temp/manager/security-review.md`):
notification resolvers (`modules/notification-producers/subjects.ts` and
friends) disclose private Realm discussion through a path that bypasses the
normal read policy. Resolve every notification through the same current
disclosure decisions the reply and review reads use — recipient
representation and membership, Realm visibility and protection, exact current
review state — at inbox read, unread count and delivery, with a recheck where
the owner's state can change between them. Add the regression scenarios from
the review (a member removed from a private Realm, a restricted reply, a
review hidden after notification) and prove the unread count never counts
what the reader cannot open. Backend only, no dev servers.
