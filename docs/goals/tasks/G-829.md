## Outcome

The G-837 review (`/home/edge/projects/rezics/rezics-next/.temp/manager/reviews/G-837.md`)
found that Main returns a public Work's composition parts and wholes (G-830),
relations (G-831) and Collections only to readers holding an explicit Work
grant. Anonymous and ordinary signed-in readers get errors, so the editions and
connections pages and the Work hub show alerts to most visitors. After this
task these reads follow the same disclosure as the Work itself: a publicly
readable Work's parts, wholes, relations and public Collections are readable
by anyone; private Works, private members and private relations stay hidden
with the same response as absent; the `work:read` scope check applies only to
authenticated clients that present a token (as `routes/collections.ts:149-152`
already does for its own reads).

## Approach

Find each read's gate and replace an explicit-grant requirement with the
shared public-Work check the Work read already uses (`publicWork` /
`canReadWork` baseline), filtering private members per item with complete
traversal (fill pages from disclosed items; no counts that reveal hidden ones).

- Manager: `services/main/src/modules/relation/participant-read.ts` is claimed by running G-847 (spoiler boundaries); make only the minimal disclosure edit there and list it under OWNER CHANGES.

## Do not build

No new disclosure rule, table or cache; no change to write authority.

## Acceptance

API, anonymous and ordinary signed-in: a public series' parts and wholes, a
public Work's relations (both directions) and a public Collection page return
200 with only public items; a private Work's reads return the same 404 as an
absent one; a private part inside a public series is omitted without a
revealing count or cursor. Class guard: a test lists every GET under
`/v1/resources/:resource/*`, `/v1/compositions/*` and `/v1/collections/*` and
asserts anonymous access to a public fixture succeeds.
