## Outcome

Each of the twelve catalogue acceptance queries is answered through the web UI
against the seeded local stack, on desktop and phone, with screenshots reviewed:
the M6 work-levels exit evidence the Goal's milestone rule requires.

## What to read

- `docs/contracts/work-and-release.md#catalogue-acceptance-fixtures` (queries).
- G-840's fixture data and its API test (what each query asserts).
- The pages from G-837 (connections, editions, releases, ISBN) and G-838
  (tracking controls, series panel); the sibling pages queries 5, 7 and 12 need
  (review filters from area T, wiki facts with spoiler boundaries from M6b,
  contributor identity across Zones from area Z).

## Approach

- One Playwright file per query group, reading the seeded data by stable
  identifiers from G-840's loader; two browser contexts for the two-device part
  of query 6.
- Where a query's UI owner has not merged, record the query as pending with the
  owner named; never mark it passing.

## Do not build

- No product code changes. File UI defects as blockers for G-837, G-838 or the
  sibling owner, with the screenshot.

## Acceptance

- `task web:e2e -- apps/web/tests/g-841*.e2e.ts` passes every query whose owner
  has merged, at 390 px and 1280 px widths, in `en` and one of `zh-Hant` or `ja`;
  the handoff lists screenshots per query and the pending queries by owner.
- Class guard: the suite fails when a query's result on the page disagrees with
  the API answer G-840 recorded for the same fixture.

## Checks

`task web:typecheck`; `task web:e2e -- apps/web/tests/g-841*.e2e.ts`.
