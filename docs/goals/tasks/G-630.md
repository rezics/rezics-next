## Outcome

Decision 44's first step on existing machinery: a Zone's navigation mounts become its
routes (supersedes the M6 draft G-630). `GET /v1/zones/{id}/routes?path=&cursor=`
(public; optional `actingSubject`/bearer as in the presentation read) returns a typed
page model: `/` → `home`; `/{segment}` → `document` when the mount targets a Work,
`index` (≤24 visible members, existing continuation) when it targets a Collection;
`/{segment}/{resource}[/{tab}]` → `detail` only for a current, visible member of that
Collection; `/w/{work}[/{tab}]` → `detail` for a Work the default Realm publicly
adopted. Unknown paths, non-members and unreadable targets share one 404
`route_missing`. The presentation read gains `navigation`: public mounts in Structure
order (occurrence, segment, target, kind, target name), ≤50. Mounting refuses the
reserved segments `browse`, `discussions`, `decisions`, `about`, `works`, `submit`, `w`
and a segment an active mount uses (409 `zone_route_conflict`), and accepts a Work the
editor can read.

## Approach

1. `modules/zone/route.ts`: a pure path parser (segment = the mount `routeSegment`
   pattern, resource = native UUID, tab = slug passed through for the host to
   validate) and one resolver reading the Zone head and the matching active mount.
2. Kind follows the target's current type: `rv:Collection` → index/detail, a Work →
   document; other targets 404 until Collections admit them (G-650). Read type,
   disclosure and Access through `readResourceSummaries` (`modules/media/summary.ts`),
   or G-506's `resolveTargets` if it has merged; do not write a third resolver.
3. Membership: one bounded ASK for an unremoved member placement in the mounted
   Collection's selected generation, plus public readability; `w` uses the one-Work
   adoption check. Index pages reuse the visible-page reader (Work members as the
   existing work card, others as `{ id, types }`). Report `cost` like other Zone reads.
4. Mount POST: add `target` (keep `collection` as alias); authorize Work targets with
   `canReadWork`, others with the existing check.

## Do not build

No route table, migration, config-format or profile version, or Structure profile. No
template engine, localized aliases, site-revision bundle, preview, rollback or export
endpoint, saved-filter population (mounted dynamic definitions resolve 404),
Realm-less addressing, per-type route kind, copy, projection or cache. Main returns
bindings and membership; the web renders pages.

## Acceptance

API (`tests/qa/integration/g-630*.ts`): a Realm Zone with a public Collection of 25 Works
mounted at `picks` and a DigitalDocument at `guide`: `/picks` (24 items, then the 25th),
`/picks/{member}`, `/picks/{member}/discussion`, `/picks/{non-member}` 404, `/guide`,
`/w/{adopted}`, `/w/{unadopted}` 404; a private mount or member is hidden anonymously
and shown with the grant; deleting the mount gives 404 and leaves the Collection intact;
reserved and duplicate segments are refused; navigation order matches. Class guard: a
paths × membership table in `services/main/tests/g-630*.ts` fails when membership is skipped.
