## Outcome

The local stack has two Zones over the same catalogue and library, created only through
public APIs: `light-novels` (series and volumes from G-840's catalogue fixtures and the
existing books, browse by language, status and length) and `visual-novels` (browse by one
usable release with G-851's release group). A small, real VNDB dump slice supplies about
50 visual novels with their titles in original and other scripts, releases with language,
platform, territory, completeness and official or unofficial status, developers and
translator credits, and VNDB identifiers. A Work that has both a VN and an LN appears in
both Zones with the same identity and the same library state. VNDB's ODbL and DbCL
obligations are recorded as a rights offering and shown as attribution.

## Approach

- Download one dated VNDB database dump, extract only the rows for the chosen VNs (vn, titles, releases, release platforms and languages, producers, release producers), and commit them with the dump's licence notice under `tests/fixtures/vndb/`; record the archive URL, date and SHA-256 in `fixtures.lock.json`. Pick VNs so that the slice has, for one VN, a Japanese Windows complete, an English Switch complete and an English Windows trial release, and at least one unofficial fan translation with its translator group. No images, descriptions or quoted text.
- `vn-catalogue-step.ts`: create each VN as a `schema:VideoGame` Work classified with a "visual novel" Concept (created once through the classification API if absent; there is none today), its realizations and release-v2 records, credits and identifiers through Main's public commands; rerunning changes nothing.
- `ln-vn-zones-step.ts` with `config/zones/*.json`: Realm, Zone, Collections, mounts, navigation, home modules and browse facets through existing APIs; the attribution line for VNDB data in the VN Zone's configuration.
- Register both steps in `cli.ts` after the catalogue fixture step.

## Do not build

No VNDB importer, mapping runtime, API client or live refresh; no RanobeDB, AniList or
Moegirlpedia data; no new Main route, table, facet or type; no per-Zone code (G-853 owns
presentation); no characters or traits from VNDB.

## Acceptance

- API (`tests/qa/integration/g-852*.ts`) after the seed: `POST /v1/query` with the release group "English + Windows + complete" returns the expected VNs from the slice and names the matching release; both Zones resolve their routes (G-630); a Work present in both Zones has one IRI; the rights offering carries attribution and share-alike obligations; rerunning both steps changes no record.
- Class guard: a test fails if the seeded data includes any field outside the admitted slice columns (no descriptions, images or quotes).
