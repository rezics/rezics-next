## Outcome

This is the maintainer's second query milestone (`docs/contracts/queries.md`;
read all of it, it is authoritative). G-400 admitted the Facets and
`GET /v1/facets`. G-409 built Concept pages on a bounded discovery read with
a Concept-only Condition bar. The research
(`docs/research/reference-ao3-vndb.md`, item 3) shows that readers need
include and exclude, all or any within a Facet, everywhere: search, Discover,
Zones and Home's Filters.

Build the one Query input:
- **A FilterDocument model** (sparse Conditions, groups bound to one
  occurrence, all/any/none, and no hidden defaults).
- **A Query:** Filter plus text, scope, Context, sort and page.
- **A route** (for example `POST /v1/query`) where Main admits a Query
  (checking shape, node count, Facet/operator applicability, depth, sources
  and budget before any Jena work) and compiles it onto the admitted,
  bounded templates. Today's `public-*-phrase-v1` and classified profiles,
  G-404's Zone browse read and G-409's Concept read are the first templates.
- **Refusals:** an unsupported combination is a typed refusal, never an empty
  result.
- **Search:** its `sense` becomes a Concept Condition.

Keep continuations bound to policy, semantic, preference and disclosure
revisions as the contract says. Tests cover admission, compilation to each
template, refusals and budgets. Say in the handoff which client surfaces
should switch first. Don't change web code; the web moves onto it in a
follow-up. Don't commit generated artifacts; the manager runs `task gen`.

## Verify

Against the shared stack, call the new route with: a Concept include plus an
exclude; a type plus a language; a Realm-scoped Condition; and one unsupported
combination. Show that the first three match today's reads and the last is a
typed refusal. Use only the backend; no web dev servers.
