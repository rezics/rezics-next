## Outcome

G-1041 qualified the unified Query at 1,000 and 10,000 Works (report preserved
at `.temp/goal-orchestration/runs/G-1041/worktree-temp/g-1041/report.md` in the
main checkout): graph calls are bounded (5–12), but **SQL statements run 59–93
per request, and a 64-card page costs 75**, about one statement per card. The
test bound (160 statements) admits that growth. G-1025 brought Home's feed to
24 statements independent of page size (1, 4, 8); the Query must meet the same
rule of [fixed bounds for interactive requests](../../storage/workload-budgets.md#fixed-bounds-for-interactive-requests).

Find the per-card SQL (disclosure and suitability checks, previews, credits,
covers, viewer state, Access fences) with G-1024's work profile, batch each
into one statement per page or per owner, and tighten the profile assertions so
statements stay constant across page sizes 1, 16 and 64 and across the
1,000/10,000 catalogues (restore G-1041's retained backups, or rebuild with
the bulk recipe). Report before/after per cell family. Adjacent loops G-1041
named (Work head, Trending, onboarding) may adopt the public classification
batch helper if they show the same pattern.
