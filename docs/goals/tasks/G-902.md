## Outcome

The G-644 review (`/home/edge/projects/rezics/rezics-next/.temp/manager/reviews/G-644.md`, "Discussion publish blocker")
found that `POST /v1/realm-reply-placements` requires `revisionDigest`, the
member-reply-draft write result omits it, and the only read that has it
answers 404 for an unplaced reply; `tests/qa/integration/post-create.test.ts:17-21`
asserts that 404 and reads the digest from `content.revision` with SQL. So no
client can publish a Realm post through the API. After this task the draft
write result (200/201) returns `revisionDigest` (the author's own bytes; no
disclosure question), and the QA test uses only API values.

## Approach

Return the digest from the write; update the response schema and generated
contract. Class: list under OWNER CHANGES every other integration test in
`tests/qa/integration/` that reads an owner table with SQL to obtain a value a
later API call needs (grep for `SELECT` feeding a request) — each is an API
gap hidden by the test. Do not fix those here.

## Do not build

No new route, no change to placement rules.

## Acceptance

Integration: save a draft, place it with the returned digest, read the
published post — no SQL in the test.
