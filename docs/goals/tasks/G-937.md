## Outcome

Implement the backend of [durable addresses](../../product/urls-and-seo.md#durable-addresses)
(read the whole section; it is the spec). Today four stores name things: Agent
vanity handles (Postgres, `agent/vanity.ts`), community handles
(`rv:communityHandle` in the graph, `space/create.ts`), official Zone
`rv:routeSegment` (graph, `routes/zones.ts` `by-segment`) and Work addresses
(graph with receipts, `modules/address/**`, ASCII-only `ascii-lower-v1`). The
web guesses: `/r/{seg}` tries the Zone segment, then the Realm handle; an Agent
without a handle is `/@agent-{uuid}`.

After this task:

1. **`sid` codec** in `packages/model/src/address/` (Main and web import it):
   all 128 UUID bits as fixed 22-character Base58 with a frozen alphabet,
   reversible, with property tests (round trip, fixed length, rejects every
   non-canonical string). Also the shared **slug derivation** (NFC, native
   script kept, whitespace and punctuation collapsed to `-`, cut at a word
   boundary near 60 characters) and the **name normalizers** for both policies
   (ASCII handles; any-script titles limited to UTS #39 Highly Restrictive),
   with the rule that no name decodes as a valid `sid`.
2. **One name registry** in the Access schema for scopes `agent`, `space`,
   `work` and `zone:{space}`: normalized key, display form, holder IRI, state
   (current, redirect, retired) and history, unique per scope. Scope policy
   covers character set, reserved words, the existing 30-day Agent cooldown, who
   may claim (Agent controller, Space manager, the existing Work address
   authority, Zone site editors) and the canonical policy (`name` by default).
   A rename keeps the old key redirecting to the same holder; no key is ever
   given to another holder; merges redirect only to equivalent successors; the
   same handle in `agent` and `space` must have one controller (compare UTS #39
   skeletons across both). Move every existing name into it and delete the old
   stores and their code paths: there is no production data, so seeds and
   fixtures change instead of compatibility shims. VIEW01 and VIEW02 keep
   passing through the registry (adapt their named tests).
3. **One resolver**: a public read that takes a scope and a key (name, `sid` or
   legacy UUID) and returns the holder, its state and the canonical address
   (`{ prefix, key, slugSource }` where `key` is the current name under a
   `name` policy, else the `sid`), plus a batch form. A Space resolves through
   its Space identity; a Realm or Zone capability ID resolves to its Space.
4. **Addresses on reads**: the common summary read (`/v1/resources/summaries`
   and whatever shares its summary shape) returns each item's canonical address
   so clients link without a second lookup.
5. **Name writes** through one route module for all scopes (claim, rename,
   release with the scope's authority) replacing the per-owner handle and
   address writes; Space creation takes an optional handle through it.
6. **Zone routes** declare `key: 'name' | 'id'` per detail route; Main checks a
   new route path against the reserved list and existing routes.

## Do not build

No host or subdomain binding, domain verification, capability tokens, stored
or approved slugs, per-scope tables, a second resolver, or web route changes
(G-943 moves the web). Fix web fixtures and types only where a served contract
changed, and list web code that reads changed fields under OWNER CHANGES.
