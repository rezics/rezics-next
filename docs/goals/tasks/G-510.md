## Outcome

`@rezics/model` exports two small validated contracts. A block snapshot (`rezics-blocks-v1`)
with stable block and table-cell IDs that BlockNote's block JSON maps onto almost one to one; and a
locator (`rezics-locator-v1`) that pins an exact source and selects inside it. One locator type
serves paragraph comments on hosted revisions and the wiki toolkit's evidence in holders' own
TXT, EPUB and Ren'Py files. A resolver says whether a pinned block is unchanged, moved, changed,
deleted or ambiguous in a later snapshot. Content's existing comment target becomes the first
locator variant with the same JSON.

Verified gap: Content bodies are `{ body: string }` (`services/content/src/core.ts`); comments
pin revision and digest but select only by `TextQuoteSelector` and refuse repeated text
(`services/content/src/comments.ts`); the reader identifies paragraphs by array index
(`apps/web/features/work-page/reader.tsx`, per `.temp/research/g-432-sol-review.md`). Nothing
gives a unit identity that survives insertion, movement, editing or deletion.

## Approach

- `document.ts`: blocks `{ id, type, props?, content?, children?, lineage? }`; inline text with
  styles, `lang`, ruby and emphasis marks; table cells carry IDs; unknown block types round-trip
  byte for byte and are reported, not rejected; `lineage` records copy, split and merge origins.
  `blocks: []` is a valid (empty) document. Inline `lang` keeps the given tag as a bounded
  string; no tag regex here (G-501's one-parser ratchet). Services validate it with G-504's
  module when they adopt blocks.
- `locator.ts`: `{ source, selector, quote? }`. Source: hosted `{ revision, digest }` or external
  `{ representationSha256, mediaType }`. Selectors: block (+ code-point range), byte range (TXT),
  range EPUB CFI (validated as an opaque string), script `{ label, utterance, route? }`, and text
  quote (today's comment selector). Units are explicit; text never stands for identity.
- `resolveBlock(locator, pinned, later)` is pure and deterministic, using IDs and lineage only.
- Keep `locator.ts` self-contained (imports only `typebox`) so M6 can move it unchanged into the
  Apache-2.0 protocol package the toolkit publishes.

## Do not build

No BlockNote or Tiptap dependency, editor, renderer, plain-text conversion, Content storage or
migration, carry-forward job, quotation budget (M6 policy), CFI or EPUB parsing, toolkit package,
or `model/definitions` profile. No change to comment behaviour.

## Acceptance

Unit and property tests: empty and mixed snapshots (unknown block, ruby, inline `lang`, table)
round-trip exactly; duplicate IDs anywhere are rejected; inserting before two identical
paragraphs, moving, editing, deleting and splitting a target resolve to unchanged/moved/changed/
deleted/changed-with-candidates; a quote-only locator on repeated text is ambiguous; malformed
byte ranges, CFIs and script positions are rejected; random edit scripts keep untouched IDs and
unknown payloads intact. Content's comment tests pass unchanged.
