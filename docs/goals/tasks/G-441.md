## Outcome

The maintainer approved a release and language model on 2026-09-28 (via
session rezics-next-c4). It is recorded, with reasons and sources, in:

- `docs/contracts/work-and-release.md#closed-records-and-open-axes`
- `docs/contracts/distribution.md#release-kinds-and-status`
- `docs/contracts/content-languages.md#language-belongs-to-the-content-version`

This task is the first of three (T1 releases, T2 translation relation and
rights, T3 virtual releases) and the prerequisite for the others. Express the
decisions in schemas, types and tests; when a section is fully carried by
code, shorten it to a pointer.

Today an edition is a metadata component with one nullable
`contentLanguage` (`work/metadata-schema.ts:27`) that hosts nothing; a fixed
release seals one contribution, one language and one body digest
(`model/definitions/fixed-native-text-release-v1.ts`); source observations
(exact bytes, coverage, time) exist for metadata providers (Open Library,
VNDB) but not for content locations.

Deliver:

1. **Release kind and status.** Every release is one of: formal edition/CD,
   web publication, REZICS fixed release, virtual release; with status
   official / unofficial / virtual / withdrawn / cancelled (MusicBrainz
   semantics: an unofficial repost is its own release and never merged into
   the official one; a virtual release is never evidence that anything was
   published). Records of external fact are closed: a wrong one is corrected
   with evidence, never extended with a later translation.
2. **Web publications.** A web publication is its original URL plus dated,
   closed snapshots (Memento, RFC 7089): each snapshot records the exact bytes
   (object store, digest), the fetch time, and coverage, as a source
   observation for a content location. Fetching uses Main's existing bounded
   source-acquisition path and respects robots and rights; the demo uses
   fixtures, never live sites.
3. **Edition languages** per RFC 5646 and MARC 041: a list of content
   languages (not one value); `zxx` for no linguistic content; empty means not
   recorded; `und` only where a tag is required; never `mul` in place of a
   list; is-translation plus original language; the language of printed title
   and tracklist text recorded separately from content language.
4. **Revisions, not edits.** `work-metadata-v1`, `work-metadata-details-v1` and
   any release profile you change get new revisions; v1 data stays valid and
   readable (docs/contracts/queries.md: persisted ids change only by revision).
   Update Jena's mutation policy if it names these profiles.
5. **Visible.** The Work page's editions/releases section shows kind, status,
   languages and, for a web publication, its URL and snapshot history; seed a
   few native examples in a new `scripts/dev/seed/releases-step.ts`
   (registered in `cli.ts`): a Chinese classic's print editions in zh-Hant and
   zh-Hans, an English translation edition marked is-translation from zh, and
   a web serial with two snapshots. Every UI string in all 8 locales.

G-437 (running) holds `scripts/dev/seed/plan.ts` and `works-step.ts`; don't
edit them. G-410 (running) holds `services/main/src/modules/structure/**`.
