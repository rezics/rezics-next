## Outcome

G-414 shipped the Library's yearly goal, monthly stats and a first CSV import
(Goodreads and StoryGraph). The manager tried it in a real browser as Daniel
Chen with a three-row Goodreads export (`.temp/manager/fixtures/goodreads_library_export.csv`
is readable in the main checkout; copy it into your worktree):

- Pride and Prejudice, already on Daniel's Read shelf, matched, but the
  import said "Its reading shelf changed. Review it before retrying." and
  "Imported 0 books … 1 books need another look". The same status is not a
  conflict. Nothing was imported, although a private `classics` shelf was
  created.
- Frankenstein and a made-up book found no match. The only way forward was
  typing a "REZICS Work URL" or following "Search REZICS" away from the page.
- The file control is the browser's native "Choose File" button; rows have no
  covers; messages say "1 books".

A person moving from Goodreads expects to drop in the export, see how many
books were found, fix the few that weren't, press one button, and land on a
Library that holds their history. Make it that:

1. **Idempotent, server-side import.** Main takes the reviewed rows as one
   import (a bounded batch or a job with per-row outcomes) and applies each
   row idempotently: an identical status, rating, dates or shelf is a no-op
   that counts as imported; a real difference (the reader's newer rating or
   review) is shown once as a choice ("Keep mine" / "Use imported") rather
   than a failure. Retrying the same file changes nothing. Keep the reader's
   own later edits winning by default.
2. **Find every book.** An unmatched row gets an inline search picker
   (title and author prefilled, covers in results) using Main's search. When
   REZICS has no Work, offer to add it from Open Library by ISBN or by title
   and author through Main's existing Open Library source path (see
   `services/main/src/modules/source/` and
   `tests/qa/integration/open-library-*.test.ts`), so the book is adopted as
   a Work and then shelved. Never fetch Open Library from the browser.
3. **A clear review and result.** A summary before import ("212 found · 9 need
   a match · 3 skipped"), filters for rows that need attention, bulk skip,
   covers on matched rows, and a result that links to the Library with the
   counts. Use `@rezics/ui` controls throughout, including a styled file drop
   zone instead of the native file input; plural-correct messages in all
   locales (English and zh-Hans written by you; others fall back).
4. **Stats that say something.** Add to Reading stats what Goodreads' and
   StoryGraph's year pages show that REZICS can compute honestly: top
   Concepts (genres), average rating given, languages read, pages or chapters
   where known. Main computes them; no private data leaves the reader.
5. **Type-aware wording.** The Library also holds software, prompts and mods.
   A shelved app should not say "Read Aug 1 – 3". Use the Work's type for
   status and date wording (for example Using / Used for software) wherever
   the Library shows them, with the stored statuses unchanged.
