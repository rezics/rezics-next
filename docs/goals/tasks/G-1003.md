## Outcome

Read the address-resolution sentence dated 2026-10-03 in
[durable addresses](../../product/urls-and-seo.md#durable-addresses). Today
every `GET /v1/addresses/resolve` draws from the `address` family (anonymous:
30 per minute per client), and the web proxy resolves on every addressed page
view, so ordinary browsing, readers behind one shared IP and crawlers get 429.

1. Main charges the `address` budget for misses only (missing, not visible,
   malformed), keeping the enumeration defence; hits on public addresses are
   not refused by it. Keep `POST /v1/addresses/resolutions` and availability
   checks under their current rules unless the same reasoning applies (say
   which). Integration test: many hits from one client succeed; misses beyond
   the budget get 429 with `Retry-After`; a hit after exhausted misses still
   succeeds.
2. Public resolutions carry HTTP caching validators (`ETag` from the address
   revision, a short `max-age`), and the web's `readAddress` keeps a small,
   bounded in-process cache of anonymous public hits honouring them, so a
   rename shows up within that age and a miss is never cached as a hit.
3. Unit tests for the cache bounds and expiry.
