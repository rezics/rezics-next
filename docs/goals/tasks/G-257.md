## Outcome

**Product decision (manager, 2026-09-28):** a Realm curates by adopting exact
contributions, but nothing today routes a contribution or correction to a
Realm for review, so the Realm moderation queue (G-240/G-250,
`services/main/src/modules/management-reads/**`) cannot show pending items.
Introduce **Realm submissions**: an author (acting as a chosen Agent) offers an
exact contribution revision, or a correction, to one or more Realms; each Realm
decides adopt, reject (with a public reason and an internal note) or request
changes; the author can withdraw. The publish flow in Studio will offer
"submit to Realms" alongside publishing to the Main Version (Ghost-style publish
dialog: what, as whom, where, when).

Design and implement:

- Owner schema: a submission record (target Realm, exact contribution/correction
  revision, submitting Agent, state, decision with public reason and internal
  note, timestamps), with Access admission (submitting requires the baseline
  member permission being added by G-255 or explicit grants; deciding requires
  the Realm's review permission), receipts and revisions like existing
  command families.
- Adoption on accept reuses the existing Realm selection/adoption owners, so
  an accepted submission is exactly an adoption with provenance; rejection
  never changes Global state.
- Realm-keyed pending index and extension of the moderation queue read with
  these item kinds and target summaries (update `docs/plan/read-api-design.md`'s
  Management row only if you must; prefer code comments).
- Author-side reads: "my submissions" with states.
- Tests for denied, stale (revision superseded before decision), concurrent
  decisions by two moderators, withdrawal races and cross-Realm leakage.

Follow the command patterns of the Space/Realm owners and the management-reads
template. You may take the human role: if the model above is wrong for the
existing adoption semantics, say so and adjust.
