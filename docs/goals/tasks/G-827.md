## Outcome

`goalctl merge` rebases a worker branch onto `main`; git's union merge driver
concatenates both sides of `services/main/src/app.ts` (and the other union
composition roots), and goalctl then commits "Normalize Main composition roots
after rebase". On 2026-10-01 this produced a broken `app.ts` twice: a route
registered twice, a statement-ending `;` in the middle of a `.use(…)` chain, and
a dropped function parameter. Main could not start. After this task:

1. Normalization removes exact duplicate `.use(…)` lines within a chain, keeps
   exactly one terminating `;` at the end of each chain, and never removes or
   rewrites function signatures.
2. Before fast-forwarding `main`, goalctl parses every normalized composition
   root (TypeScript parse only, e.g. the `typescript` package's
   `createSourceFile` diagnostics, or `bun build --no-bundle`) and, if any fails,
   marks the task `conflict` with the file and error instead of merging.

## What to read

The normalizer in `scripts/goal/goalctl.ts` (search "Normalize Main composition
roots"); `.gitattributes` for the union files; the broken result in commit
`ee678f81` and the repair `04bdcb5a` on `main` (use them as a regression fixture).

## Do not build

No change to the union merge driver setup, to worker flow or to other commands.

## Checks

`bun test scripts/goal/goalctl.test.ts` with a regression test reproducing the
G-629 input (duplicate lines, mid-chain `;`) and one where parsing fails and
the merge is refused.
