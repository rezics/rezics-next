## Outcome

`GET /v1/resources/:id/page` returns `entity-page-v1` for any admitted resource the reader may see. It contains
the resolved target (G-506), the summary (name, avatar, disclosure), the registry entry (G-637), the Work header
when the base is a Work, and ordered section descriptors `{ id, href, count?, actions[] }`. The sections are the
ones the base binds (statements, relations, contents, releases, credits, ratings, reviews, discussion, lists)
plus the type sections its `presentation` names (recipe, prompt, skill).

This brief adds two missing inventories, both paginated with complete traversal:

- statements about the resource accepted in the reader's Context;
- relation occurrences in which the resource takes any role.

Descriptive components attach to existing resources (build-order step 1). A semantic component written through
`POST /v1/semantic/changes` (target, expectedHead, receipt) attaches to an existing Work without a second
identity. G-865's `component-correction` adapter uses that command. `/v1/recipes/works/:id` and
`/v1/hub/works/:id` stay as section hrefs; G-644 stops the web from choosing them by type IRI.

## Approach

1. Build the projection in `modules/entity-page/`.
   - Section hrefs come from G-506 `capabilityPath`.
   - Include a count only where its owner already computes it cheaply, and state its precision.
   - `actions[]` lists the commands this reader may issue.
2. Add `statement/subject-read.ts`: statements whose `rdf:subject` is the resource, in the requested or default
   Context, grouped by property, with qualifiers, sources and statement IDs, paged by opaque cursor.
3. Relations: do not add a relations read. The relations section's `href` points at G-831's two-direction
   relation read (manager, 2026-09-30); if G-831 has not merged, emit the section without a count.
4. Confirm that `semantic/change.ts` accepts an existing Work IRI as a component target. It already preserves
   predicates that other owners hold on the same subject. If it refuses, make the smallest change that admits
   it. Reserved owner types and predicates stay rejected.
5. Mount `/v1/resources/:id/page` and `/statements`.

## Do not build

- Schema-generated editors, infoboxes or copied facts.
- Per-type projections or routes.
- Relation label rendering.
- Changes to the recipe or hub reads, or to game and software facts (G-656).
- A second Access path.

## Acceptance

Through the API, with the SAO subset, a VideoGame Work and a semantic resource of an unregistered type:

- Each base gets only the sections it binds. No unfamiliar type gets book-only sections, and recipe and prompt
  Works list their type section.
- Statements traverse more than 1,000 items with no duplicates or gaps.
- A component attached to `sao.bunko`: a stale `expectedHead` is rejected, the current head returns a receipt,
  its statements show on the page, and the Work's identity and title are unchanged.
- Private items appear in neither items nor counts.
- Class guard: a base × presentation fixture matrix fails on an unbound section or on book presentation for an
  unknown type.
