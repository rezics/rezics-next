## Outcome

Translations are realizations of the same Work, and one release may cover several
Works (decision 49; Versioned capability):

- `realization-v1`: a particular text of one Work with its language tag (script
  kept), kind (`original` or `translation`), translator and publisher Agents, its
  source (an exact source realization or Main Version revision, or explicitly
  unresolved, naming the source continuity Work), status (`official`,
  `unofficial`) and verification (`verified`, `unverified`), with evidence. A
  fan translation is `unofficial` and never presented as official.
- `release-v2`: v1's kind, status and ISBN, plus provider-qualified identifiers
  (a digital store entry), platform, territory and 1–64 coverage entries, each an
  exact realization with completeness (`complete`, `partial`, `trial`,
  `unknown`) and an optional portion label. An omnibus covers three volume
  realizations without new Works. Language, platform, territory and completeness
  are triples on the release node so one Facet path can correlate them (G-851).
- v1 releases read as v2 covering their Work with the realization unknown;
  `/v1/works/{id}/releases` lists every release covering the Work.
- `GET /v1/releases?isbn13=` (and other admitted identifiers) resolves a release
  to its realizations, Works and Main Versions (acceptance query 2).
- Installed translation links read as realizations through an adapter that
  imports `readTranslationLinks` without editing it (G-538 holds that file), so no
  record is lost. Fixtures and UI record translations only as realizations; G-844
  retires the legacy write route.

## Approach

- Copy the release command's CAS, receipt and graph-state pattern for
  realizations; both new profiles are registry-only bindings (no Java case).
- Realizations project `a rv:Realization ; rv:work <Work> ; rv:head <revision>`
  so G-506's resolver resolves them as its `realization` base with the Work's
  name and disclosure; if G-506 merged with another shape, follow G-506.
- Keep `release/languages.ts` untouched (G-504 owns it); call its parsers.
- Closed-record rules carry over: evidence corrects a release; a later
  translation is a new realization and release, never an extension.
- Identifier lookup is a bounded graph query on the release identifier triples.

## Do not build

- No availability, offers, prices or loans (Offered and library owners).
- No correspondence or alignment between realizations (G-831 relations only).
- No realization per native language contribution: hosted contributions stay in
  the Main Version; a realization may point at that Main Version.
- No new Work for a translation, a printing or a split-volume edition.
- No release comparison UI or VN-specific fields beyond platform and territory.

## Acceptance

- API: Yen Press English realization of SAO volume 1 with paperback and digital
  releases; zh-Hant (Taiwan Kadokawa) and zh-Hans (Hunan Fine Arts) realizations
  stay distinct; an omnibus release covers volumes 1–3; ISBN 9780316371247
  resolves to release, realization, Work and Main Version; an unverified fan
  translation of the web Work keeps `unofficial`/`unverified`; a closed release
  rejects a later language; replay and stale heads behave as v1.
- Class guard: fixtures reject a v2 write covering a Work without a realization,
  identity inferred from equal languages, and coverage derived from titles.
