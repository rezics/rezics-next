## Outcome

Search and Discover are how people find Works. Read `docs/plan/frontend.md`
(principles: scope always visible, honest states; route map `/discover`,
`/search?q&scope`). Build both on the Main APIs:

- **Discover** `/discover`: browse without a phrase — recent, top rated in a
  scope, by Work type, by classification term — using the discovery reads
  (G-237: `services/main/src/modules/discovery/**`, see
  `docs/plan/read-api-design.md`). Shelves labelled with their scope
  ("Top rated · Classic Literature Realm"), cursor pagination ("Show more"),
  honest exact/lower-bound counts.
- **Search** `/search`: phrase search (`POST /v1/queries`, `/v1/queries/page`
  and profiles) with the scope selector beside the query box, include/exclude
  facets (Work type, language, classification term) where the API supports
  them, "why this matched" reasons on each result, a completeness line
  (exact or "≥N", scopes searched, what was excluded, index freshness), a
  restart path when a cursor expires, and URL state for query, scope and
  facets. Search-as-you-type suggestions only if the API supports them cheaply;
  otherwise submit. Respect IME composition (`event.isComposing`).
- Result cards: cover, title (Work-title face), type, credits, scoped rating
  summary, key tags; link to `/w/{slug|id}` (the Work page is being built in
  parallel by G-251 in `apps/web/app/w/**`).
- Home: the home page's discovery shelves (`apps/web/features/home/**`, unclaimed)
  may reuse your shelf component; use `goalctl owner` and keep that change small.

If an API is missing or awkward, do not work around it in the client; propose it.
