## Outcome

From the Library page a reader imports the file their current tool exports and sees every
row: matched, ambiguous (with candidates to choose from) or not found (kept private, never
dropped). They apply, watch progress, leave and come back to a partial import, and see what
each row became. "Download your library" produces the complete REZICS export with visible
progress; an interrupted download resumes where it stopped, and the page states what the
file contains and what it never contains (book text). Library rows show the attempt state
(paused, DNF, reread) through G-838's control. The browser no longer parses or matches
anything; Main does.

## Approach

- Replace `import-csv.ts` and `import-match.ts` with calls to G-854; delete the browser parsing and matching and their tests, keeping only presentation helpers.
- Import: a format picker naming each supported tool and how to get its export (Goodreads, The StoryGraph, MyAnimeList, VNDB, REZICS), plus "Other (CSV)" for NovelUpdates-style lists: after the first upload, show the headers and status values G-854 returns, let the reader map title (required), author, status, progress and dates and map each status value to a Library state or leave it unmapped, then resend with the mapping; a plain note says AniList cannot be imported; the rows view groups by outcome, with candidate choice and "keep private"; apply shows progress and per-row results; an unfinished import is listed on the Library page until finished or discarded.
- `features/library-backup/`: fetch export pages, assemble one JSON file, persist the cursor so a reload resumes, verify the final count against the export header before offering the file.
- Embed `TrackingControl` in library rows in place of the status-only control.
- Copy in all eight locales; stories for each outcome, partial import, interrupted export and phone width.

- Manager: G-854 merged the import/export API and MCP (formats incl. MAL XML, mapped CSV, resumable apply, retention with a delete operation, re-importable export). Build the Library UI over exactly those operations; show unmatched rows and per-row issues as the API reports them; never parse files in the browser beyond what the API asks. task dev refuses in workers: use storybook:test and browser tests via task goal -- test.

## Do not build

No client-side matching, scoring conversion or status mapping; no import from URLs or
connected accounts; no background sync; no new export format; no library redesign beyond
the import, export and row control.
