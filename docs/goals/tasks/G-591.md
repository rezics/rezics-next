## Outcome

G-538 (merged, `ceca4117`) made Work content of a translation of another
author's Work unable to go public on the `original-contribution` basis, in
both request orders and for chapters. Its review found the same gap in text
contribution publishing (`services/main/src/modules/contribution/publish.ts`
around line 318): a language contribution can still go public as an original
contribution. After this task the same rule holds there, reusing G-538's check
rather than copying it, and Studio shows a clear message for
`translation_basis_required` instead of mapping the 409 to "stale".

## What to read

`git show ceca4117` and its parent commit on `main` (the G-538 rule and tests);
`docs/contracts/content-languages.md#user-submitted-translations`;
`services/main/src/modules/contribution/publish.ts`; the Studio API adapters
listed in `paths`.

## Approach

Call the existing G-538 predicate from the contribution publication admission
(inside its transaction). In Studio, map the problem code to its own message in
all eight locales.

## Do not build

No new basis kinds, rights request flow, profile or table. No change to
public-domain handling.

## Acceptance

- API: a translator's text contribution to their own Work that is linked as a
  translation of another author's protected Work → 409
  `translation_basis_required`; a public-domain source → publishes; the
  author's own translation → publishes.
- Browser (phone and desktop, one non-English locale): Studio shows the
  specific message, not "stale".
- Class guard: removing the call makes `g-591-contribution-basis.test.ts` fail.
