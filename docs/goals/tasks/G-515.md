## Outcome

Wherever a person writes text, its language is theirs to choose, from any BCP 47 language, and
is sent as chosen, with direction from its script. Today the interface locale is stamped as the
content language: posts send `language: locale, direction: 'ltr'` (`composer.tsx:145`,
`api.ts:34`); replies are "written in the reader's interface language" (`realm/thread-view.tsx:33`)
and sent LTR (`feed/thread-api.ts:45`); a library review draft starts in the locale
(`library/row-parts.tsx:177`); a review defaults to the UI locale and offers only the eight UI locales
(`reviews.tsx:147–150`); an edited profile bio takes the UI locale (`profile-api.ts`
`profileSaveInput`); Realm rules are written as the same text under `en` and `zh-CN`
(`communities/create-form.tsx:77`, `manage/rules.ts`, `settings-view.tsx:147`).

## Approach

One small single-language select in `features/content-language/` built on the onboarding
picker's search and names: suggestions are the writer's saved reading languages, the text's
current language and the original; any valid tag can be typed. Default: the item's existing
language when editing; otherwise the writer's first reading language; if none, "Language not
specified" (`und`), never the UI locale. Use it in the post composer, the reply box, the work-page and library review forms, the bio
field and the Realm rules editor (one language per rule, with optional added translations, sent
as `{ original, labels }`). Set `lang` and `dir` on the text areas from the chosen language.
New keys ship in all eight locales in the same change (the catalog gate fails otherwise).

- Also (from G-512 and G-596 handoffs): the web community creation form declares the language of its name and rules; fix the existing mobile sticky action bar overlap on the writing surfaces you touch.

## Do not build

No language auto-detection, no translation features, no rules translation workflow, no global
"writing language" setting, no new API endpoints. Do not change post title/spoiler handling
(G-529).

## Acceptance

Browser (local stack, two locales): under a Japanese interface write a post and a review in
Korean and a bio in Arabic; reload; the stored language is `ko`/`ar`, the Arabic field is RTL.
Create a Realm with rules written in Japanese; Manage shows them as Japanese, not as English and
Chinese. API: captured payloads carry the chosen language, never the locale by default.
Class guard: request-contract tests fail if a composer, review, bio or rule payload takes its
language from the interface locale.
