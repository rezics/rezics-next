## Outcome

Minimal merge of duplicates (decision 50, cut line 7) as one capability for any
Resource, bound to the shared review lifecycle as G-865's `merge` kind:

- Proposing names source and survivor ResourceRefs with their heads and evidence.
  The adapter's `preview` returns a side-by-side header (multilingual titles,
  creators, grain, dates, identifiers) and bounded per-owner counts; `validate`
  rejects self and cyclic merges, Account-controlled Agents and stale heads.
- G-865 requires two independent human approvals for `merge`; a bot and its
  operator are not independent.
- `apply` runs one resumable Main task keyed by the decision. Owner handlers
  (`preview`, `apply`, `compensate`) record per-item outcomes in Access 970–971:
  a person's library entry and rating keep the survivor's value with the other
  retained as history, so one person never casts two votes; sessions and copies
  stay separate; realizations, composition parts and Collection members are
  re-pointed through their owners' commands; statements and relations are
  re-pointed, and duplicates of one statement stay as alternatives. Grants,
  account control and creator rights never move.
- The source gets a `mergedInto` link; reads of its ID, slug or an exact old
  revision return a typed `merged` result with the survivor, using the address
  resolver's hop limit and cycle rule. This brief supplies G-506's `redirectOf`
  hook (the one reserved for the dropped G-869), so every capability target
  resolved through `resolveTargets` follows the same resolution.
- Unmerge is G-865's revert: `compensate` re-points exactly the moved items and
  lists later edits as ambiguous. A split plan is refused as not yet admitted.

## Approach

- Handlers are discovered `merge-handler.ts` files per owner. This brief claims
  the handlers for the Work-level owners; add the other owners' handlers as
  minimal owner changes, or hand them off if an owner's path is claimed.
- The item rows in 970–971 are the resume point; report status through G-541's
  operation status if it has merged, without waiting for it.

## Do not build

- No split execution, workbench, batch merges, saved queues, dashboards or
  automatic duplicate detection; no per-type merge engine; no review tables or
  approval logic of its own (G-865 reviews kind `merge`).
- No UI (G-839 adds the entry; G-867 renders the proposal).

## Acceptance

- API: two SAO volume 1 duplicates with overlapping readers' statuses, sessions,
  ratings, reviews, follows, a composition part and a realization: preview counts
  match; one approval cannot apply; after two, the task is killed mid-way and
  resumes to one effect per item; the old ID, slug and an exact old revision
  resolve; a person who rated both counts once; revert restores both identities
  and lists a post-merge review as ambiguous.
- Class guard: a test enumerates owner tables and graph predicates that reference
  catalogue identities and fails when one has neither a handler nor an explicit
  exclusion (discovery as in `tests/qa/fault-recovery/recovery-coverage-discovery.test.ts`).
