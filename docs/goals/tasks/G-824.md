## Outcome

M5 complete traversal for libraries (decision 12): the rest of G-552, whose
delivered parts are merged (`cf724220`). Status shelves page past every former
bound (240 rows) with sort, order and cursor; counts are exact; the web reads
one Main page per rendered page; the client-side sort and page caps are gone.

## Design (from the G-552 review, `/home/edge/projects/rezics/rezics-next/.temp/manager/reviews/G-552.md`)

1. Rewrite the frozen legacy chapter status rows once, then delete
   `canonical.ts`.
2. A keyset shelf endpoint with `sort`, `order` and `cursor`; unavailable cards
   are skipped within the read deadline, never truncating the traversal.
3. "Added" and "finished" sorts use the existing indexes; counts are one
   `count(*) … GROUP BY status`.
4. Content migration 602 adds `title_key`, `own_rating` and `last_read_at` to
   `library_status`; the status, rating and progress writes set them, with a
   one-time backfill.
5. The web reads one Main page per rendered page with the cursor in the URL.
6. Fold the yearly totals into `/v1/me/reading-stats` and remove the separate
   `/summary` endpoint G-552 added.

## Do not build

No new projection service, cache or table beyond the three columns; no
per-medium branches; reading history stays private.

## Acceptance

API: a library of 1,000 Works with mixed statuses traverses every shelf in each
sort without duplicates or gaps; counts equal the traversal; a concurrent
status change never duplicates a row across pages. Browser (phone and desktop):
paging through a 1,000-Work shelf.
