## Outcome

G-1021 made chooser pages, ranks and saved positions cost per page through
counted order trees (`1d389d399` on main; the large G954 case fell from 278 s
to 81 s), but a literal substring search over chapter labels still scans every
label of the story, so typing in the position chooser of a 10,000-chapter
story costs in proportion to the story
([collections at any size](../../plan/frontend.md#collections-at-any-size)).

Add a normalized occurrence-label index (display label and number, with the
same per-language normalization and Simplified/Traditional folding the search
owner uses for Works), maintained by Structure writes and staged activation in
the same transaction as the order tree, with a backfill for existing stories,
recovery after an interrupted build, and a rebuild path for operations. The
chooser's search reads it with cost bounded by the page. Measure search
latency and store work at 100, 1,000 and 10,000 chapters before and after.
Also audit `reading-position/boundary.ts`'s legacy full-composition wiki
boundary that G-1021 flagged, and fix it if it scans the whole composition.
