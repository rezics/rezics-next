## Outcome

1. **Migration order.** Access migrations reached `985_*.sql`, and every
   applier sorts file names as strings (`scripts/qa/bootstrap.ts:20`,
   `scripts/dev/cli.ts:338`, `scripts/dev/release-artifact.ts:90`,
   `scripts/fixture/migrate.ts:18`, `scripts/fixture/manifest.ts`,
   `scripts/load/compatibility.ts`, `scripts/ops/migrate.ts`,
   `services/content/src/migrate.ts`), so `1000_*.sql` would run before
   `986_*.sql`. Give them one ordering that compares the leading number
   numerically, keep today's order unchanged, and add a test that a
   four-digit file applies after `999_*`. Nothing renames existing files.
2. **Zone presentation cost.** G-936 found that `discloseInventory` in
   `services/main/src/modules/disclosure/read.ts` puts `VALUES ?work` outside
   the `OPTIONAL`, so the `schema:ListItem` branch scans every chapter
   occurrence (4.3 s per collection summary at 1,000 chapters, 37 ms at 19);
   `media/summary.ts` `graphRows` already scopes it correctly. Move the
   `VALUES` inside, add a cost test that a collection summary stays constant in
   chapter count, and run `apps/web/tests/g-856-query07.e2e.ts`, which failed
   with a 503 from `GET /v1/zones/{id}/presentation` without this fix.

## Do not build

No migration framework, renaming or re-numbering, and no other query
rewrites.
