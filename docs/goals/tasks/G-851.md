## Outcome

`POST /v1/query` (and every consumer of it: Zone browse, saved views, MCP) accepts a
`where` group over a Work's releases: "a release in English, for Windows, complete,
unofficial or official" matches a Work only if one release satisfies every condition in the
group. Each matching result returns the IDs of the releases that satisfied the group, so a
page can explain why it matched. Books use the same group for "an English paperback
edition". This is the visual-novel discovery job; it is shared query behaviour, not a VN
route. Today the compiler refuses every `where` group
(`services/main/src/modules/query/compile.ts:74`) and no release facet exists.

- G-833 (release-v2: language, platform, territory and coverage completeness are triples on the release node; status official/unofficial); G-657 (registry facets only; the `zone-browse` template).

## Approach

- Add one step kind to `FacetStep`: the related node reached by a declared path (here the releases covering the Work through G-833's coverage), which a `where` group binds its Conditions to. Reuse the `occurrence` step's cost fields; do not add a second grouping mechanism.
- New facet definitions (each `-v1`, labels in eight locales): `release` (the group facet) and `release-language`, `release-platform`, `release-territory`, `release-completeness`, `release-status`, each valid only inside a `release` group; register them in accepted profiles.
- Compile the group into one SPARQL pattern that binds a single release variable, with the existing bounded candidate traversal and continuation; return `matchedReleases` per result (at most 8 IDs, with a flag when more exist).
- Keep `where` refused for every other facet with the existing typed error.

## Do not build

No VN-specific route, service or facet vocabulary; no release projection table or index
migration unless a measured query breaks the declared budget (then report before adding);
no availability, price or store integration; no ranking; no UI.

## Acceptance

- API (`tests/qa/integration/g-851*.ts`): three releases of one VN (Japanese Windows complete, English Switch complete, English Windows trial) match "English + Windows + complete" not at all and "English + Windows" once with the trial release named; a Work with an English paperback and a Japanese e-book does not match "English + e-book"; conditions outside a group keep today's semantics; results traverse past every former candidate bound with stable continuation; a non-UI language tag (for example `th`) works; a denied release never contributes a match or an ID.
- Class guard: a fixture that places conditions on two different releases of the same Work must not match, and the test fails on a deliberate change that joins conditions across releases or filters after pagination.
