## Outcome

After G-341's clean `dev:reset` and reseed of the shared stack (main checkout;
Main at http://127.0.0.1:3001, demo credentials in `scripts/dev/seed/plan.ts`):

1. **Discovery never refreshes**: `GET /v1/works?limit=3` returns
   `stale: true`, `items: []` and a projection position at sequence 8 — the
   state right after the reset — while hundreds of later events exist. The
   automatic refresh (G-270) is not advancing. Find why (refresher not started
   in this process layout, a generation lock left by the reset, a failing
   build) and fix it so discovery converges after any reset or restore.
2. **Reader state still 503s**: `GET /v1/works/{id}/reader-state?actingSubject=…`
   returns 503 `work_read_unavailable` for some Works even after G-352's
   own-rating fix. Reproduce with the seeded readers, find the remaining cause
   and fix it.
3. **Chinese titles tagged `en`**: source adoption labels Chinese titles
   (西游记, 三国演义) as English; carry the source record's language.

Each fix with a QA case that reproduces it. Backend only, no dev servers; you
may restart nothing on the shared stack — the manager restarts Main after
merge.
