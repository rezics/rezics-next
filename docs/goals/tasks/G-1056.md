## Outcome

On the shared dev stack (`http://localhost:3001`, served from the main
checkout), `/health/search-ready` has reported
`"occurrenceLabels":{"status":"indexing","pending":{"value":1,"kind":"at-least"}}`
for more than 40 minutes after the last Fuseki rebuild (sequence 7502 → 7506),
and the direction-9 wiki-position journey fails because the position chooser's
chapter search finds nothing (`apps/web/tests/direction-9.e2e.ts:768`). G-1022
moved labels to an asynchronous projection into the shared Lucene index, and
G-1044 and G-1048 added generation rebuilds and availability during them; their
tests pass on fresh QA stacks, but a long-lived stack with history, restarts and
image rebuilds does not converge.

Diagnose on the shared stack (read-only probes; Main's log through
`task aspire -- logs main`; the readiness payload; the projection's cursor and
pending set): find why the projection stays pending (a cursor that never
advances past one item, a failed batch retried forever, a generation switch
that orphans pending work, a worker not started after a rebuild) and fix it so
it converges after restart, rebuild and restore, reports progress, and surfaces
a stuck item instead of hiding it. Add a test that reproduces the stuck case.
Product fixes reach the shared stack after the manager merges; say what to
check there afterwards.

## Checks

`task gen` if the Fuseki image changes (commit what the change requires);
`task main:typecheck` through the slot; scan changed files with
`task ast-grep -- scan`.
