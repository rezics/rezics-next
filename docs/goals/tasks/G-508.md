## Outcome

Decision 4: role and trust, not visible controls, gate creation. Verified
defects: any verified Person can start imports (`POST /v1/sources/acquisitions`
checks only OAuth scope `source:acquire`, `source-runs.ts:117-124`) and can
create Software, SoftwareSourceCode and ModPackage entries through baseline
`work.create` (`baseline.ts:56-57,141`). No command can appoint a catalogue
editor: role permissions are `CHECK (permissions <@ ARRAY['work.create'])`
(`019_role_revisions.sql:15-17`, `roles.ts:113-115`), and editing another
author's Work needs a per-Work grant nothing issues. After this task,
administrators (holders of existing Access role bindings) alone start imports
and create administrator-only kinds. An administrator appoints an editor role
carrying `work.edit`; the editor's edits carry the editor as actor in history.

`docs/contracts/identity-and-access.md#visible-is-not-permitted`;

## Approach

1. Each `workKinds` entry gains `creation: 'administrator' | 'contributor'`
   (Software, SoftwareSourceCode, ModPackage → administrator). This is type
   configuration that the served type registry (G-629) keeps. For
   administrator kinds, baseline admission yields no proof, so the existing
   grant, group or role path decides.
2. Import runs require that same non-baseline `work.create` authority. Call the
   discovery in `contexts.ts`; it is G-521's claim, so do not edit it.
3. Migration 870 widens the role CHECK to `work.create` and `work.edit`,
   re-listing every existing value. `withWorkEditAuthority` accepts a role
   binding carrying `work.edit` on the catalogue scope.
4. The role path also needs a `work.create` representation, which a Person's
   provision lacks (`represented-work-proof.ts:42`). Choose the smallest fix
   and justify it in the handoff.

## Do not build

No administrator flag, table, profile or bridge to Account operator roles. No
new action family. Do not restrict ordinary contributors from creating non-own
Works: the catalogue quality pipeline owns contributor limits. No Zone changes
(Zone creation is already grant-gated; the Zone area owns "no private Zones").
No UI capability endpoint (decision 14, M5).

## Acceptance

- `tests/qa/integration/g-508-role-matrix.test.ts` covers ordinary Person,
  administrator, appointed editor and author against five actions: create own
  Book, create ModPackage, start import, edit another author's Work, bind an
  editor role. Only the documented cells pass; denials are typed 403s. The
  editor's edit shows the editor in history.
- Guard: a Work adopted from a private library row stays publicly unreadable
  (search and another reader's `/v1/works/:id`).
- Class guard: removing the kind check or re-admitting baseline imports fails
  the matrix.
