Close IAM02 ("Replay invalid issuer/audience/redirect/CSRF state: reject without
changing account state", `docs/testing/identity-and-access.md`). G-037 (commit
`0b338f4`, `services/account/src/oauth-code-guard.ts`,
`services/account/tests/oidc-authorization.integration.test.ts`) left two gaps:

1. Some invalid token exchanges (wrong client, redirect mismatch, bad PKCE
   verifier, wrong audience/issuer) still consume the pending authorization code.
   A rejected exchange must leave the code, session, consent, grant and refresh
   authority unchanged, so the legitimate client can still redeem it once. A true
   replay of an already redeemed code still fails closed (and must not mint new
   tokens). Read Better Auth 1.7.5's OIDC provider code paths before editing;
   prefer a guard at Account's boundary over patching the library.
2. The callback/state probe covers one registered client. Exercise at least two
   registered clients with swapped client/redirect/state, proving isolation.

status codes. State in `docs/services/account.md` which concerns are client-owned.
