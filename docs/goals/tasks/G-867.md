## Outcome

On a phone or a desktop, in any UI locale, a reader opens "Propose correction"
on a Work or any entity page, changes a fact, attaches a source and submits. A
steward opens the proposal from the inbox, sees before and after, the evidence
and the revision timeline, and requests changes, applies or rejects. The
proposer revises or withdraws. After application, anyone with authority can
revert, which opens a compensating proposal. Every action comes from G-865's
API; the page renders the API's `allowedActions` and typed blockers and holds
no business rules. No web page for corrections exists today.

## Approach

- `features/proposals/`: `ProposeCorrection` (it reuses T's field editors in propose mode and appears where the API says the viewer cannot edit directly), `ProposalPage` (a generic before/after change list from the API's `preview`, evidence, timeline, blockers, actions; G-868 adds the watch toggle), and `ProposalList` (Mine, Review requested, Recently decided).
- Routes `app/[locale]/proposals/page.tsx` and `app/[locale]/proposals/[proposal]/page.tsx`, with durable links to exact revisions.
- Wire the entry points: G-850 (M6 Work hub) exports a "Propose correction" placeholder, and G-644 renders capability actions on the generic entity page. Export `ProposeCorrection` for both. If G-850 and G-644 have merged at dispatch, replace the placeholder and add the action as one-line owner changes; otherwise list the wiring in the handoff.
- Wiki bundles (G-846) and chapter deltas (G-693) render through the same change list, grouped by the API's item kinds. Merge UI belongs to M6's G-839; if G-836 binds to G-865, G-839 should link to this page instead of a second review screen.
- Stories for open, changes requested, stale base, stale approval, applied, reverted, withdrawn and forbidden, in light and dark themes and at phone width; copy in all eight locales.

## Do not build

A review workbench, keyboard queue, batch actions, saved queues, dashboards,
inline comment threads, a rich editor, client-side eligibility or state
derivation, or a proposal UI per kind.

## Acceptance

- Browser against the local stack (screenshots reviewed): a member in zh-Hant at phone width proposes a synopsis correction; a steward in en on desktop requests changes from the inbox link; the member revises; the steward applies; the member reverts. Each step shows authoritative state after reload.
- API parity: every control calls exactly one G-865 operation; a test fails if the page offers an action absent from `allowedActions`.
