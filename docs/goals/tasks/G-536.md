## Outcome

Supply `task goal -- <goalctl arguments>`, `task production -- <command>` and `task production:typecheck` before M4. This is the extracted command facade from G-720.

## What to read

`GOAL.md`; `docs/goals/worker.md`; `Taskfile.yml`; `scripts/goal/goalctl.ts`; `docs/goals/README.md`.

## Pattern

Discover production command modules without editing a central dispatcher for every owner. Preserve goalctl test/slot accounting; set the program ceiling to five live workers, normally four implementation plus one QA lane. Keep the wrapper free of new product behavior.

## API flow acceptance

Run dry validation and a harmless QA-slot command; malformed arguments and child failures retain their exit status. Verify wrappers never bypass claims, dependencies or usage gates.

## UI flow acceptance

No product UI. The manager can list tasks, inspect pending work and run checks through Task before any implementation wave.

## Class guard

Wrapper tests cover argument forwarding, nonzero exits and QA slot release after interruption.

For each added or vendored dependency, verify licence, pinned upstream version/commit and local patch record; update `docs/development/toolchain.md` with the dependency change. The gate rejects missing provenance or prohibited licence components.

## Checks

Use the Task/QA facade you build: `task goal -- test` the claimed G-536 files by tier; run affected owner typechecks, `task docs:check` when documents change, and changed-file lint/format through `task goal -- slot --`. For visible changes run targeted Storybook tests, an actual browser journey and inspect phone/desktop screenshots; run all eight locales through `task i18n:check`. Run integration from a pinned checkout with `REZICS_QA_SHARDS=2`.

## Risks

Preserve exact owner receipts, current authority and explicit unavailable outcomes; do not substitute fixtures for external qualification.

## Capacity configuration

Set `GOAL_MAX_WORKERS=5` in the program’s Task facade/environment and verify argument forwarding preserves it; keep `GOAL_QA_SLOTS` at goalctl's default unless measured memory says otherwise (the program's lessons record that one shared QA stack serialized work). Workers do not each start a frontend server. Heavy suites and bulk drills retain the plan’s serialization/exclusivity.
