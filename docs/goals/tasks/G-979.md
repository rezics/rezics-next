## Outcome

`apps/web/features/discover/api.ts` keeps a hardcoded `browseTypes` table of
type IRIs for Discover's tabs (Works, Communities, Sites, People, Lists,
Topics), which `web-no-type-iri-tables` rejects (five errors) and which is the
class the maintainer flagged at the start of this workstream: the frontend must
name no type ([Discover](../../plan/frontend.md#discover), principle 8). The
served type registry lacks entries for Realm, Zone, Agent, Collection and
Concept and has no browse-category field.

1. Add those types and a browse category to the type registry Main serves
   (a new profile revision if the registry profile is persisted; never edit an
   accepted profile in place), with the localized category labels as registry
   data.
2. Discover reads its tabs and the query's type Facet from the served registry;
   delete `browseTypes`; `task ast-grep -- scan` passes for these files.
3. Tests: unit tests for the registry read and the web mapping; run your
   integration file through `bun scripts/goal/goalctl.ts test`.

## Do not build

No new types beyond those five, no per-domain branches.

## Checks

Shared worktree `green-2`: start no servers; run `task gen` locally when needed
and restore generated paths before committing; commit only your paths with
`git commit --only`.
