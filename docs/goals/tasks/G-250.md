## Outcome

The Realm moderation queue read (G-240: `services/main/src/modules/management-reads/**`)
lists report cases and decision audit only. A moderator's queue must also show
pending contributions and corrections for the Realm, and reports must reliably
land in the right Realm. From G-240's handoff:

1. Add Realm-keyed indexes for pending contributions and pending corrections
   (with review admission in their owners), so the queue can seek by Realm,
   state and type within its bounded page.
2. Enforce the Realm governance scope on report writes (today reports appear
   only when written with the exact Realm governance scope and the writer does
   not enforce the mapping).
3. Indexed type filters for the queue and a durable Access read revision, so
   the queue is consistent with revocation.
4. Extend the queue read to return the new item kinds with the fields a triage
   UI needs (target summary, author Agent, created time, state, prior decisions).

Follow the management-reads template and `docs/plan/read-api-design.md`; update
its Management row. Owner schema first, then writes, then reads; tests for
denied, stale, concurrent, revoked-moderator and cross-Realm leakage cases.
