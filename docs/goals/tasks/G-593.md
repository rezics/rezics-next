## Outcome

Two product defects found by the wave-1 regression repair (G-592):

1. **Structured publication rejected.** `services/main/src/modules/content-publication/publish.ts:90`
   requires text at `exact.body.body`, so Hub revisions (G282 in
   `feed-home.test.ts`) and Realm media sets (WIKI05 media in
   `wiki-realm-selection.test.ts`) get HTTP 400. The likely cause is the
   empty-body pre-check added by G-526 (`fbcb86ea`, `97eb6c23`), which should
   apply only to text bodies. After this task, structured bodies publish as
   before, an empty *text* revision is still refused with 422 `empty_body`,
   and the permission check still runs before any private body is read.
2. **Home read over budget.** G383 (`feed-read-budget.test.ts`): signed Best and
   Top Home reads now issue 207/209 statements against the 200 budget, even
   when run alone. Find which recent change added statements (bisect across
   this wave's merges if needed: `git log --oneline a5299f98..main`) and bring
   the read back within 200 without changing what Home shows. Keep the budget.

## Approach

Fix the empty-body check at its source (text only). For the budget, find the
extra statements with the test's statement log, then batch or remove them.

## Do not build

No weaker assertions, no raised budget, no special case per body kind beyond
"text or structured", no new caches.

## Acceptance

- `feed-home.test.ts` (G282), `feed-read-budget.test.ts` (G383) and
  `wiki-realm-selection.test.ts` (WIKI05 text and media) pass.
- `tests/qa/integration/g-526-empty-drafts.test.ts` still passes.
- A unit test proves a structured body is not treated as an empty text body.
