## Outcome

`GET /v1/types` (profile `types-v1`, public, with ETag and 304) serves every admitted type once. Each entry has:

- `type` and `base`;
- `creatable`, and `creation` (`administrator` or `contributor`, added by G-508);
- `interest` and `primaryAction`;
- `presentation`: one of book, recipe, prompt, skill, guide, game, media or default;
- `cover`: one of portrait, landscape, square or document;
- `labels`: one and other forms in the 8 UI locales.

Each base also has a default entry.

Main's hand-copied type lists are derived from the registry instead of being kept as copies: `workKinds`,
`workSemanticTypes`, `WORK_TYPE_OPTIONS`, `discoveryType`, and the create and type-edit enums. The
web's tables move over in G-651.

## Approach

1. **Source file.** `model/definitions/types-v1.ts` holds metadata keyed by type IRI. It covers the 16 Work types,
   `rv:Character`, `rv:Role`, the record types (`rv:Release`, `rv:FixedRelease`, `schema:ListItem`,
   `rv:TextContribution`), and one default entry per base. `interest`, `primaryAction` and `creation` come from
   `workKinds`.
2. **Compiler.** `model/compiler/type.ts` reads the Work set from `work-kind-v2`'s `sh:in` and the creatable set
   from `work-type-v2`'s `sh:in`, excluding `schema:CreativeWork`. It fails when the metadata and a profile
   differ, then emits `packages/model/src/generated/types.ts` with a digest. The profiles are not edited.
3. **Loading.** Main validates the generated registry at startup against `modules/types/contract.ts`, following
   `modules/facets/registry.ts`, and mounts `routes/types.ts` in `app.ts`.
4. **Derived lists.** Rewrite each list in Outcome as a derivation from the registry. Keep the exported names so
   that the roughly 15 `WORK_SEMANTIC_TYPES` SPARQL call sites stay untouched.

## Acceptance

- **Read.** `GET /v1/types` returns every `work-kind-v2` type with labels in all 8 locales, and repeating the
  request with a matching `If-None-Match` returns 304.
- **Behaviour unchanged.** Create and type-edit accept and reject exactly the same types as before, and the
  type-edit options equal the registry's `creatable` entries. Existing create and type-edit tests pass
  unchanged.
- **Class guard.** A model test adds a type to `types-v1` without adding it to the profile, and the reverse; both
  must fail compilation.

Order: after G-508 (`work-kinds.ts`), G-656 (`app.ts`) and G-500 (`model/compiler/generate.ts`, accepted-profile guard; register `types-v1` with it).
