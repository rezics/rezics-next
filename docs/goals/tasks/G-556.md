## Outcome
Public search keeps answering when the launch catalogue exceeds 20,000 searchable
units. A query that matches more than 512 candidates, such as a common word or a
frequent CJK bigram, returns the best-ranked page with a continuation instead of
an error. Every request stays bounded in time and bytes. Ranked retrieval, which
returns the top results, is distinct from exhaustive inventories. Responses state
their count precision: exact, lower bound or unknown. A Zone's browse page
traverses every adopted Work in each sort: newest, updated, and relevance with
text. It no longer reads a 60-row window of the Realm's newest adoptions.

## Approach
- Qualify the index per generation, not per request.
  - The delta journal already proves writes. Record a qualified generation once, after rebuild or startup, and check only that the request's snapshot matches it.
  - Readiness no longer counts the whole population. Keep uncertain-index detection (`SearchIndexUncertain`).
- Ranked retrieval:
  - Ask Lucene for the top `k` of one page plus a probe, with score ordering and a stable tie-break.
  - The continuation encodes the generation and the last score and ID. Extra candidates set the count to a lower bound instead of failing.
  - Apply grouping, ratings and disclosure (G-542's reader when merged) to the page's candidates only. Refill from the next ranks when items are filtered, within the page budget.
- Keep the existing budgets for calls, bytes and wall time.
- Zone browse selects by index with a keyset continuation for each sort, pushing G-657's compiled Conditions into the query. Relevance with text uses the ranked retrieval above, restricted to the Realm's adoptions. Delete `browseWindow`'s in-memory sort over the sample.
- Declare the public search operation agent-callable in `routes/search.ts` with the export G-580 consumes: `export const capabilities = { '/v1/<path>': { get: { disposition: 'supported', mcp: { tool: 'search_catalogue', title, description } } } }`. It is inert until G-580 merges.

## Acceptance
- An integration fixture of more than 20,000 public units, built once and restored per the workload budgets:
  - Search succeeds.
  - A query with more than 2,000 matches pages through the first 200 results with no duplicates or gaps and reports a lower-bound count.
  - A write between pages under a new generation gives a documented restart outcome.
  - An index rebuild keeps readiness honest while it runs.
- A Zone with 500 adoptions: browse pages through all 500 in each sort with no duplicates or gaps. An old adoption matching a filter is reachable, and the page count equals the population.
- Browser: on the Zone's browse page, go to a late page, reload, and see the same items.
- Budget assertions: Fuseki calls, bytes and time per request stay within the existing constants.
- Class guard: fixtures exceed every former constant (20,000, 512, 60), and a test fails if any public search or browse path fails, or truncates, solely because its population is large.
