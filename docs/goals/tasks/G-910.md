## Outcome

Today's restart merged over a hundred tasks; several workers report the
integration tier red on main in areas outside their scope (contracts,
projections, authority, read budgets, fixtures — G-731, G-897, G-903
handoffs). A red tier hides regressions. After this task every unit,
integration and fault-recovery test on main passes, or is fixed at its cause,
or — only for an external dependency such as Open Library's live network — is
quarantined with its reason named in the test.

## Approach

- Run the tiers on current main through `task goal -- test` (one slot at a
  time; the integration tier is large, so run it in a few chunks) and list
  every failure with its first error.
- Group failures by cause. For each class: a stale test expectation after a
  merged contract change → update the test; a product regression → fix it
  in the owning module if small (list it under OWNER CHANGES with file:line),
  or list it as a proposed task if large. Never weaken an assertion to pass.
- The manager permits edits to existing tests and small owner fixes as
  unclaimed changes listed under OWNER CHANGES, except in files a running
  task claims (`task goal -- status`, then `task goal -- scope <id>`).
- Rebase onto main between chunks; main moves while you work. If a failure
  belongs to a running task's claim, list it and skip.

## Do not build

No skipped or deleted tests without a named external cause; no budget
increases to pass; no new features.

## Acceptance

A final run of all tiers on current main: pass, with any quarantines listed
with their external cause. Handoff lists each fixed class and each proposed
task.

## Checks

`task goal -- test` over each tier; `task main:typecheck`.
