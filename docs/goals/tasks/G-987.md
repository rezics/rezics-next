## Outcome

G-983 found that no public API can issue the authority to create a Realm's
rating context: Realm role schemas and database constraints exclude rating
configuration, and Realm observations lack the global observation baseline
(details: `.temp/g-983/` in this worktree). So no Realm can stand up its own
rating population through the API, and the rating scope picker
([collections at any size](../../plan/frontend.md#collections-at-any-size))
cannot be exercised past page one.

Add the smallest public path: a Realm role permission (granted to managers by
default) that authorizes creating and configuring the Realm's rating context
through the existing `/v1/rating-contexts` command, with the usual authority,
idempotency and revision rules, and the Realm observation baseline it needs.
Then make G-983's setup recipe (more than 20 populations through public APIs)
work; run your `g-987` integration file through
`bun scripts/goal/goalctl.ts test` until it passes and give the run ID.
Migrations 1026–1029 if needed (check the highest number on `main` first; the
merge guard refuses lower ones).
