## Outcome

At 08:09 UTC the kernel OOM-killed the shared dev stack's Fuseki
(`rezics-dev-fuseki-1`, `OOMKilled=true`, exit 137) inside Docker Desktop's
23.45 GB VM. Main went `unavailable`, and every worker's browser checks
against the shared stack failed until the manager restarted it. The pressure
came from QA and isolated worktree stacks running at the same time: each
Fuseki's resident memory reaches about 5 GB (`rezics-qa-wt-g-397-fuseki-1`
showed 4.77 GiB), even with `JVM_ARGS=-Xmx2g`, because TDB2 memory-maps its
files. It also happened this morning, and the Docker VM itself was killed
at 04:20.

- **Protect the shared stack.** Give the main checkout's dev stack services,
  Fuseki first and then Postgres, a strongly negative `oom_score_adj`, so
  the kernel kills a QA or worktree stack first. QA and worktree stacks
  keep the default. `infra/dev/compose.yaml` is shared by the dev, worktree
  and QA stacks (`scripts/qa/bootstrap.ts` reads it), so drive it with a
  variable that only the main checkout's dev stack sets.
- **Bound QA and worktree Fuseki.** Give their Fuseki a memory limit and a
  TDB2 configuration that fits it, such as a smaller mmap or direct-memory
  cap and a heap that fits the limit. Measure a full integration project and
  a seeded worktree backend under the limit, and choose a limit that keeps
  them passing.
- **Report.** Record the chosen limits and why in the local stack
  documentation if the procedure changes, and add a unit test for the compose
  variables.

`scripts/qa/**` is held by G-402. If QA admission needs a memory check (for
example, refusing to start a stack when the VM has less than a threshold
free), describe it under PROPOSED TASKS.

## Verify

Restart the shared stack with your settings (`.temp/manager/dev-refresh.sh`
or `task dev:prepare` plus a Main and relay restart; coordinate the restart
time through your handoff if another worker is mid-check). Then show
`docker inspect` values for oom_score_adj and memory limits on the dev and a
QA stack. Run one integration project and one worktree backend under the
limits.
