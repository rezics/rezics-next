## Outcome

A new person signs in and today lands on `/identity` with no Agent: only the
seed script calls `POST /v1/agents`, and every Agent's handle is the
immutable `agent-<uuid>`, so profiles read `/@agent-3f2a…`. The main site needs
the ordinary product behaviour of Reddit, GitHub or Goodreads:

1. **First sign-in.** An idempotent onboarding command ensures the signed-in
   Account has a person Agent (display name from the Account profile, the
   session Agent set to it) and returns it with a suggested handle. Calling it
   again returns the same Agent. The web callback will call it (G-280 owns the
   web side; list the one call it needs in the handoff).
2. **Chosen handles.** People, pen names and organizations choose a vanity
   `@handle` as a renamable alias over the immutable native handle (see the
   comment in `modules/agent/handle.ts`; Work address claims in
   `routes/addresses.ts` are the lifecycle to reuse or mirror). Decide and
   encode: allowed characters and length (ASCII lower-case letters, digits and
   `_`, 3–30, case-insensitive uniqueness is the expected default), a reserved
   list covering every top-level route segment and staff words, availability
   check, change with a cooldown, and the previous handle redirecting to the
   Agent for a retention period during which nobody else can claim it.
   `GET /v1/handles/:handle` resolves vanity, retired and native handles, and
   says when the caller should redirect.
3. Profile reads and every read that names an Agent return the current vanity
   handle when there is one.

Put the rules in schemas and tests, not prose. Extend the demo seed
(`scripts/dev/seed/**`, unclaimed; others edit it too, keep changes small) so
demo people have readable handles, through the API.
