## Outcome

The second milestone review (screenshots under `.temp/manager/milestone-2/`,
prefixes `ac-` and `adm-`) found these on the Accounts site:

- **Connected apps (P2, N17).** A plain reader's list shows "Local official
  Zone seed" with "Operate storage ownership" and "Approve executable themes".
  People should see only apps they authorized; first-party service and
  operator clients they never used stay out of their list. Fix it in the
  Account API, not by filtering in the page.
- **Admin clients (P2, N19, earlier N34).** The OAuth clients table prints the
  full scope string (about 70 scopes for REZICS) in one cell. Show a count
  with the list on the client's page. Recent actions show raw `new-client`
  names instead of client names. Two "Local official Zone seed" clients
  remain; let the seed reuse one (`scripts/dev/seed/operator.ts`) and disable
  the rest.
- **Console errors (P2, N12).** Every admin page logs "This library called
  use() to suspend … but did not call use() when it finished". `?hl=zh-Hans`
  on the account centre and `?hl=ja` on sign-in fail hydration ("server
  rendered text didn't match"). The server and client probably pick the
  locale differently; make them agree, and add a test that fails on the
  mismatch.
- **Initials (P2, N25).** Accounts shows "D" where the main site shows "DC"
  for the same person. Use `initials` from
  `packages/ui/src/components/avatar-initials.tsx`; do not edit it.
- **Sign-up subtitle (P2, N29).** "One account for every REZICS product,
  starting with REZICS" reads awkwardly. When the product being joined is
  REZICS itself, say something like "One account for REZICS and everything
  that comes next"; name another product when one is joining. Update the
  eight locales' strings (`apps/accounts/features/*/messages/`).
