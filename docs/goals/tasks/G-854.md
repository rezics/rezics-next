## Outcome

A reader (or their agent, through the API or MCP) uploads the file their current tool
exports: Goodreads CSV, The StoryGraph CSV, MyAnimeList XML (anime and manga lists,
where light novels live), VNDB's user-list export, or a REZICS library export; or any other
CSV (such as a NovelUpdates reading list kept by hand) with a column mapping the reader
chooses. Main parses
it, matches rows to the catalogue, and returns every row as matched, ambiguous or not found,
with the source's own fields kept. The reader resolves or keeps rows private, then applies;
application is resumable and replays to one effect. Statuses, dates, ratings on the same
scale, private reviews and shelves land in the Library; rereads, pauses and drops become
G-834 sessions; nothing unmatched is published or dropped. `GET /v1/me/library-export`
returns the whole library as `rezics-library-export-v1` in resumable pages, and importing
that file into another account reproduces it.

## Approach

- `library-import/formats/*.ts`: one parser per format into one canonical row (source ids, titles, creators, status, dates with precision, score with its source scale, review, shelves, read count, raw fields). Each file cites the tool's export documentation and the date checked; the source is always the reader's own file. AniList is not offered (its terms restrict competitors).
- `formats/generic-csv.ts`: the request names which header is `title`, `author`, `status`, `progress`, `startedOn` and `finishedOn` (only `title` required) and maps each distinct status value to `want-to-read | reading | read | paused | dnf` or leaves it unmapped; unmapped values and unused columns stay private source fields. Progress becomes a G-834 position only when it is a page number or a percentage; a chapter label ("c123") stays a source value. A generic CSV create without a mapping stores nothing and returns the headers and distinct status values (at most 50); the client resends the same file with the mapping.
- Matching in Main: ISBN and VNDB identifiers through G-833's lookup; otherwise title plus creator candidates from G-556, where more than one candidate is ambiguous; a book found nowhere keeps today's Open Library candidates and reader-chosen adoption (`library-import/open-library-search.ts`, the adoption logic behind `routes/library.ts:347`), moved behind the new operations. Reuse the existing batch tables and reviewed application for resumable apply; Content 729 adds the retained private source rows.
- Mapping rules: a score becomes a REZICS rating only when its scale equals the rating Context's; otherwise it stays a private source value. A read count greater than one without dates stays source evidence; no attempts are invented. MAL "On-Hold" and VNDB "Stalled" are paused, "Dropped" is `dnf`.
- Operations in `routes/library-imports.ts`: create from file (≤2 MiB, ≤5,000 rows, as today), read rows (paged), resolve rows, apply; each with `Idempotency-Key`, typed problems and G-580 `capabilities` declarations. `routes/library-export.ts`: paged export with a snapshot token; a page served after the library changed reports the change instead of mixing states.

- Same class as M4's date-loss repair (G-517): today `services/main/src/modules/library-import/batch.ts:142-179` forces reading dates to null for every status but read. Imports keep every date the source gives, for every status.

- From G-834's review: an imported legacy `read` status must not be overwritten when the person's first attempt starts; convert it explicitly to a completed attempt (dates kept) at import.

## Do not build

No live API pulls from any tool, no scraping, no scheduled sync; no new rating scales or
score conversion; no public catalogue entries created by a personal import; no export of
book text; no second session or progress store; no deletion of the old
`/v1/me/library-import/*` routes yet (G-856 removes those the web no longer calls).

## Acceptance

- API (`tests/qa/integration/g-854*.ts`) with fixture exports in `tests/fixtures/library-exports/`: a hand-made NovelUpdates-style CSV (title, status "Reading" and "Dropped", chapter progress, one unmapped column) whose rows land as mapped with the chapter label and the extra column retained; a Goodreads file with a reread, a DNF shelf, two editions of one Work and a 3.5-star StoryGraph score; a MAL manga list with an ambiguous title; a VNDB list whose VNs are in G-852's slice. Every row is accounted for; resolving one ambiguous row and keeping another private applies correctly; interrupting after half the rows and repeating the apply gives one effect; a 1,200-entry library exports past every page bound, survives an interrupted download resumed by cursor, and re-imports into a fresh account with equal state (sessions, shelves, reviews, retained rows).
- Class guard: a golden test per format compares source → canonical row → applied state and fails on any silently dropped field or invented session.
