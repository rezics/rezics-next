Shared-structure enabler (like the receipt-family registry in
`services/main/src/modules/access/receipt-families.ts`). New domain sessions are
blocked on three hard-coded lists:

1. **OAuth scopes.** Account rejects scopes it does not list (G-054 needs
   `claim:*`; every new domain has scopes). Let owner modules declare their
   scopes (for example `services/main/src/modules/<owner>/oauth-scopes.ts` or an
   Account-side discovered registry) with consent/ceiling semantics unchanged for
   existing scopes; keep Better Auth 1.7.5 and its admitted plugins.
2. **Graph outbox relay.** `modules/outbox/relay.ts` accepts only listed actions
   and maps a fixed set of event kinds to CloudEvent types. Add a per-owner
   handler registry (`modules/<owner>/outbox-event.ts`, discovered) so a new
   graph command family delivers its events and Access seals its admission with
   no edit to `relay.ts`; existing kinds keep byte-identical CloudEvents and
   validation.
3. **Content search projection.** The Content relay projects every
   `content-body-v1` publication as text, so a `media-set-v1` publication can stop
   the cursor. Dispatch projection by the published revision's content model
   through a small recipe registry; non-text models are acknowledged, not
   projected.

Document the three extension points in `docs/implementation/api-and-events.md`
and add a one-line pointer for workers in the handoff. Checks: the existing
Account OIDC/consent tests, outbox relay tests, content projection tests and one
synthetic registered handler/scope/recipe test through `goalctl test`;
tsc/biome/oxlint. Estimate 60–90 minutes.
