## Outcome

Deferred by default (cut line 7 names only minimal merge); promote if a Sol lane
is idle. The cheapest duplicate prevention in the catalogue quality pipeline:

- `POST /v1/catalogue/candidates` searches original titles, language-tagged
  aliases, romanizations, creators, dates and identifiers (ISBN, external IDs)
  and returns candidates with the compared attributes, deterministically.
- `POST /v1/works` requires a declared grain. Only "new creative scope" (with an
  optional parent composition) creates a Work; "translation or version",
  "publication" and "collection" answer with the owner API to call (G-833
  realizations and releases, Collections). The request records the candidate
  search it followed.
- Works created by contributors without a verification grant are provisional:
  visible, marked unverified with field provenance, and excluded from trusted
  exports and recommendations until a reviewer verifies them. New contributors
  have at most three pending creations (quota module, migration 973).

## Approach

- Reuse the public search index for retrieval; add an identifier lookup only
  where G-833's lookup does not already answer.
- Provisional status is one Work fact written at creation and cleared by a
  reviewed verification; consumers filter on it.

## Do not build

- No model or Jev classification, embeddings, automatic linking or confidence
  scores (automatic linking needs measured 99.5% precision first).
- No wizard UI (G-843) and no review queue beyond the existing management reads.

## Acceptance

- API: a romanized or translated title finds the existing Work; declaring
  "translation" routes to realizations and creates no Work; a fourth pending
  creation by a new contributor gets 429 with Retry-After; an unverified Work is
  absent from trusted export and recommendation reads until verified.
- Class guard: `POST /v1/works` without a declared grain or candidate receipt is
  rejected.
