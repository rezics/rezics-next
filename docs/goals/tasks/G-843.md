## Outcome

Deferred with G-842. A contributor adding a book, volume, translation or edition
is led to the existing record before a new one is made:

- Step 1 searches Main's candidates as the contributor types a title, alias,
  creator or ISBN and offers: use existing, add an alias, add a translation or
  edition (G-837's editions flow), add a part to a series, or create.
- Step 2, only for "create", asks what the record is (new story or series, a
  translation or version, a publication, a part, a collection) with the parent or
  coverage, then calls the owner API Main names.
- A created record shows its unverified badge and field provenance until a
  reviewer verifies it; the pending-creation limit is explained with Main's
  Retry-After.

## Approach

- Search-first is the default path; creating is the last choice, never the first
  button. No business rules in the client: the grain choices and routing come from
  Main's response.

- Manager (promoted 2026-10-01): readers of the Light Novels and Visual Novels Zones need to add a missing Work. The intake API is search first with a declared grain and a candidate receipt (G-842, G-892; see `tests/fixtures/catalogue/load.ts` and `catalogueWorkBody` for the exact client sequence). Catalogue search now matches titles and aliases (G-911). No dev servers (task dev refuses in workers); storybook:test and browser tests via task goal -- test.

## Do not build

- No model suggestions or confidence scores; no bulk import UI.
- No changes to Studio's native-writing flow.

## Acceptance

- Browser, desktop and phone: typing "Sword Art Online" in Japanese, romaji or
  English offers the existing SAO records; choosing "translation" of volume 1
  creates a realization, not a Work; a new record shows as unverified; the fourth
  pending creation shows the limit. Reviewed screenshots in the handoff.
- Class guard: a component test fails if "Create new" is reachable before the
  candidate search has returned.
