## Outcome

Every piece of interface text in `apps/web`, `apps/accounts` and `packages/ui` sits in a catalog
that has one file per locale (or, for official Zones, one typed table per Zone), so the
translation lanes G-502 and G-503 can fill gaps without touching the same files and the gate
(G-501) can see them. Today about 110 keys sit outside any checked catalog, have English and
Simplified Chinese only, and fall back to English without warning:
`communities/messages.ts` (71 keys, `localeText`), `post-composer/messages.ts` (32),
`query/condition-bar.tsx` (inline `copy`, 18), `work-page/format.ts` (`unknownLanguage`), and
English-only accessible names in `packages/ui` (`aria-label="Close"` in dialog, sheet, popover,
action-bar and toast; command, select, date-input, tags-input, pagination, breadcrumb, calendar,
tour, signature-pad, sidebar). `task i18n:check` currently reports 0 keys for communities and
post-composer.

## What to read

`apps/web/i18n/define.ts`, `apps/web/i18n/catalogs.ts`, one split catalog such as
`apps/web/features/feed/messages.ts` + `messages/ja.ts` (the pattern to follow),
`apps/about/src/i18n/define.ts` (complete-by-type catalogs), `scripts/i18n/check.ts`,
`scripts/static/ast-grep/rules/no-native-select.yml` + its test (the rule pattern).

## Approach

- Convert communities and post-composer to the split layout (English `messages.ts`, a
  `messages/<locale>.ts` file for each other locale, typed `satisfies Partial<…>`); carry over the
  existing zh-Hans text. Keep the exported names (`communityText`, `postText`) and their call
  sites, including the `apps/web/app` pages, unchanged through a one-line adapter.
- Move the `shell/navigation.ts` labels (complete in 8 locales; write all eight shell locale files)
  into the shell catalog, the condition-bar copy into the search catalog, `unknownLanguage` into
  the work-page catalog and the fiction interval labels into `fiction/strings.ts`. Then delete
  `localeText` from `define.ts`.
- Make `defineMessages` require every locale in full (as `apps/about` `defineCopy` does); its
  remaining users (`work`, `search/typeahead-messages.ts`, `work-page/editions.tsx`) are complete.
- `packages/ui`: replace the English defaults with a small eight-locale table keyed by the
  locale that `LocaleProvider` already supplies (`useLocale()`). Write all eight locales yourself;
  there are about ten short labels.
- Official Zone `strings.ts`: keep each Zone's own file (Zones bring their strings), but export
  the per-locale table so that G-501 can inspect it. Do not translate them (G-503 does).
- Add `no-inline-copy`: an ast-grep rule failing on JSX text or `aria-label`/`title`/`placeholder`/
  `alt` string literals containing words, and on object literals keyed `'zh-Hans'` outside catalog
  files, for `apps/web`, `apps/accounts` and `packages/ui` (stories and tests excluded). Allow only
  the proper names that exist today (REZICS, ©, UTC, Esc, Minecraft).

## Do not build

No new i18n library, extraction tool, codegen or runtime loader. No English copies pretending to
be translations. No changes to message meaning or keys beyond moving them.

## Acceptance

- `task i18n:check` lists communities and post-composer with their real key counts and gaps.
- Every moved screen renders the same English and zh-Hans text as before (existing stories and
  `apps/web/tests/g-531*.ts` for the adapters).
- The rule's test fails when a deliberate `aria-label="Close"` or inline `{ en: …, 'zh-Hans': … }`
  object is added to a web component.

## Checks

`task web:typecheck`, `task accounts:typecheck`, `task ui:typecheck`; `task ast-grep -- test`;
`task ast-grep -- scan`; `task storybook:test` for changed stories; `task i18n:check`.
