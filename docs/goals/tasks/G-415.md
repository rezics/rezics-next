## Outcome

The maintainer's direction is that each field presents information the way
its best site does (`docs/plan/frontend.md#zones`). Zones are getting that
(G-404 Mods, G-405 Fiction and Books). The Work page itself still looks the
same for every type: a Goodreads book page (G-394). A recipe or a prompt
needs its own page:

- **Recipe**, like NYT Cooking and Serious Eats:
  - yield with a servings scaler (Main's `recipe/quantity.ts` exists);
  - ingredient list with quantities;
  - numbered steps with timers;
  - total and active time;
  - notes;
  - "Cook this" mode with the screen kept awake.
- **Prompt and Skill**, like the best prompt and skill hubs (Hugging Face,
  Anthropic's and OpenAI's skill and GPT directories):
  - the prompt or `SKILL.md`, with variables highlighted;
  - one-click copy of the exact published text;
  - tested models, example inputs and outputs, and version history;
  - "Try it" guidance.
- **Guide or document:** a table of contents from headings, reading time and
  last updated.

Books keep G-394's page. Mods are G-404's (Modrinth). Software comes later.
Choose the layout from the Work's type (rdf:type; the vocabulary is in
`docs/contracts/queries.md`, never "kind"). Add the Main reads each page needs
in the `recipe` and `hub` modules, bounded and budget-tested. G-409 holds
`work-page/classification.tsx`, and G-410 holds `contents.tsx` and the reader;
don't edit them. Add English and zh-Hans strings only. Use `@rezics/ui`
controls.
