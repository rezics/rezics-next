## Outcome

REZICS catalogues books and serials, software packages and mods, AI Skills
and Prompts, media and recipes (`docs/product/capabilities.md`), and the home
page filters by six human kinds (`docs/plan/frontend.md`, "Home"). But
`POST /v1/works` admits only `schema:Book`, `schema:DigitalDocument` and
`schema:Recipe` (`WORK_SEMANTIC_TYPES` in `modules/work/activate.ts`), so an
author cannot create a mod, a prompt or a film page, and the feed cannot filter
five of the six kinds (G-302 found this; its typed interest mapping is on main).

1. **Work kinds**: admit native Work creation for software packages and mods,
   Hub Skills and Prompts (reuse `model/definitions/hub-item-v1.ts`'s types:
   `rv:SkillPackage`, `rv:PromptTemplate`), and media (film, TV series,
   animation, music album, video) with schema.org types, each with the model
   profile and validation it needs. Keep one typed table that maps each
   admitted type to its interest kind and to the card's primary action
   (read, install, copy, watch); package and mod Works must stay compatible
   with the package owner (`modules/package/**`, read only).
2. **Feed filter**: `GET /v1/feed?interests=books,software,...` filtering by
   that table (discussions by activity kind), cost-bounded like the other
   filters; onboarding interest suggestions use the same table.
3. **Web switch**: set the five `null` entries of `interestFilter` in
   `apps/web/features/feed/state.ts` to the new filter (one line each), so the
   home kind chips appear.

Backend only apart from that one web file: no web, Storybook or Accounts dev
servers; verify with goalctl test and the shared Main.
