## Outcome

- **Policies.** The about site publishes the Terms, Privacy, Acceptable Use, Content Ratings and Age, Copyright and DMCA (with the designated agent), NCII, Child Safety, and API and Agent policies, rendered from `docs/legal/*.md`. It fills them from one typed legal-facts file (operator, addresses, contact mailboxes, DMCA agent, effective dates). A release build (`task about:build -- --release`) fails while any `[REZICS TO FILL` marker or empty fact remains, and when a source digest differs from `services/account/src/policy-versions.ts`. Development builds render the pages with a visible "draft, not in force" banner instead.
- **Sign-up.** Accounts sign-up asks for a birth month, shows the detected region, links the exact policy versions and explains a refusal. A changed policy asks existing people to accept again.
- **Unsubscribe.** An unsubscribe page confirms the one-click result.

## What to read

- `docs/legal/README.md` (placeholders and the rule never to invent facts); `docs/operations/trust-and-safety.md#safety-and-legal-readiness`.
- G-731's routes (sign-up fields, acceptance, typed refusals, unsubscribe); `apps/accounts/app/(auth)/sign-up/page.tsx`, `apps/accounts/features/proxy/account-proxy.ts` (forward `CF-IPCountry`).

## Approach

- Use Astro content rendering of the Markdown sources: no copies and no CMS. Policies stay in English with a localized notice in the other seven locales that the English text governs. Page chrome is localized.
- Legal facts live in `apps/about/src/legal/facts.ts`. The maintainer supplies the values; never invent one.
- The sign-up form follows the existing Accounts form components and stories; refusal copy states the rule without accusing.

- Manager: G-731 is reviewed but not merged, because the sign-up API now
  requires a birth month and policy acceptance that this form must send.
  Start by running `git merge goal/g-731` in your worktree (manager-approved)
  so you build against that contract; the manager merges G-731 and then this
  task back to back. Existing-session re-acceptance is behind
  `ACCOUNT_POLICY_ACCEPTANCE_ENFORCED` (default off); build the acceptance
  page and turn the default on here. No age band or adult opt-in exists at
  launch (`docs/operations/trust-and-safety.md`). No Storybook/web dev servers.

## Do not build

A consent banner (there are no trackers), age verification, translated legal
texts, a policy CMS, changes to the about feature registry (G-872 does that last),
or new about pages beyond the policies.

## Acceptance

- Browser against the local stack at phone and desktop widths: sign up in the US (13 or over) succeeds; KR at 13 and the EEA at 15 are refused with the reason; re-acceptance appears after a version bump; the unsubscribe page confirms; every policy page renders in each locale route.
- The release build fails on a seeded placeholder and on a digest mismatch (the class guard) and passes with complete facts; the development build passes and shows the draft banner.
