## Outcome

In the final verification, `g-954-reading-position.test.ts` › "API-built
10503-occurrence story traverses the old ceiling…" passed but took **391 s**
(about 27 occurrence writes per second), pushing its shard past the 480 s
integration budget. Until today it failed within two seconds, so this cost was
never measured.

1. **Profile the write path.** Measure how the cost of adding one occurrence
   changes with the story's size (100, 1,000, 10,000). Imports and all writes
   go through the API, so a write whose cost grows with the existing story
   (ordinal recomputation, manifest rewrite, validation over every sibling) is a
   defect: fix it so a write costs in proportion to the change. If the public
   API offers a batch structure command, the test should use it the way an
   importer would.
2. **Build test data once.** If a large fixture is still costly after (1),
   build it once per QA dataset and restore isolated copies, as AGENTS.md and
   [data preparation](../../storage/workload-budgets.md#data-preparation-and-import)
   ask, instead of rebuilding it in every run.

Report the measured per-write cost before and after, and the test's new
duration. Run it through `bun scripts/goal/goalctl.ts test`.
