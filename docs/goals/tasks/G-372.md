## Outcome

On the shared stack the manager found every projection frozen: the outbox
relay had exited on a single `{"event":"main_relay_failed","reason":"The
operation timed out."}` and nothing restarted it, so delivery stopped at
sequence 716 of 804 and the public Work list read `stale: true` with no items.
A manual `aspire resource main-relay start` caught up in seconds. Main's log
also repeats two errors that survive the catch-up (thousands of lines per hour):

- `Notification producers: … cannot execute INSERT in a read-only transaction`
  (code 25006). The producer is built in `services/main/src/index.ts` with a
  relay pool that sets `default_transaction_read_only=on`.
- `serial statistics projection deferred … Graph relay has a source gap`
  (`serial-projection.ts:167`), although `relay.delivered_batch` holds 1..804
  without a gap in the current data epoch.

And once: `discovery refresh tick failed … Work read deadline exceeded` from
`discovery/refresh.ts` `enroll`.

Make each worker survive and recover without an operator:

- the relay retries transient failures (timeouts, connection loss, Fuseki 5xx)
  with capped, jittered backoff and a log line per retry, and exits only when
  an event is blocked (`RelayEventBlocked`), as it does now;
- notification producers write through a writable connection and read the
  relay checkpoint read-only; replies, decisions and role changes produce
  notifications on the shared stack;
- the serial statistics projection finds no gap in a contiguous relay, and
  after a reset or a new data epoch it starts from the right position;
- one slow Work defers that Work's discovery enrolment instead of failing the
  tick;
- explain why `GET /v1/works?limit=5` (global, `order=recent`) returns no items
  while Home and Discover show Works; if global discovery should list them, fix
  the read, otherwise say so in the handoff.

Each fix gets a test that fails before it. Do not change web code.

## Verify

Against the shared stack: stop Fuseki for about 20 s with the relay running and
restart it (`docker restart rezics-dev-fuseki-1`), then show the relay caught
up without a manual start (`relay.delivered_batch` max equals the outbox head).
Show a quiet Main log for five minutes (no producer or serial projection
errors). Use only the backend; no web dev servers.
