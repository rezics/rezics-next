## Outcome

A signed-in reader's content (reading) languages live in one Main store, in the order the reader
chose, and every Main read that uses them (feed filters, display-name selection, onboarding)
reads that store. Today there are two Main stores that drift apart:
`access.person_preferences.content_languages` (preferences, onboarding) and
`access.home_state.preferences.contentLanguages` (feed), both capped at 8 (the number of UI
locales, not a language limit); the web keeps a third copy in a cookie (G-597 removes it for
signed-in readers). Account already owns the interface locale (`user.locale`); Main stores no
interface locale and must not start.

## Approach

Keep `person_preferences.content_languages` as the one store. Migration 875 folds each reader's
`home_state.preferences.contentLanguages` into it (existing person list first, then feed-only
entries, de-duplicated, canonical tags, order kept), removes the key from `home_state`
preferences, and raises the cardinality bound to 20 (matching `readerLanguages`). The feed
preferences route keeps its request shape but reads and writes `contentLanguages` through the
preferences store, under the same revision/CAS rules; fill `personal.preferences.contentLanguages`
from that store in `feed/personal.ts` so its readers keep working. Use one matching rule in
`feed/read.ts` (`contentLanguageVisible`), `feed/new-since.ts` and `feed/trending.ts`: match with
G-504's reader-language predicate (a `zh-Hant` reader sees `zh-Hant-TW`; scripts are not crossed), and a
saved reading-language preference never hides a post whose language is not recorded (today all
three paths drop it); an explicit per-request filter may. `feed/read.ts:176` reports a missing
title language as not recorded instead of `en`.

## Do not build

No new table, service or preference framework; no interface-locale storage in Main; no
per-device or per-Realm language lists; no suggestion engine. Transient feed filters in the URL
stay request state.

## Acceptance

API: write languages through settings, read them in the feed and in onboarding; write through the
feed route, read in settings; two concurrent writes with stale revisions: one wins, one gets 409;
replay is idempotent; 12 languages including `ar`, `zh-TW` and `yue-Hant` round trip in order.
Migration test: a reader with different lists in both stores ends with the merged list.
Class guard: a test fails if the feed reads `home_state` languages again.
