## Outcome

G-387 locked seven Project Gutenberg classics and split them into chapters,
but can't seed them. `GET /v1/works/<Pride and Prejudice>` has `types: []`:
Open Library adoption creates generic CreativeWorks, and `POST
/v1/compositions` needs `schema:Book`, so it answers `404
composition_unavailable`. No API changes a Work's kind. The same gap is
why classics show generic covers and labels.

- **Adoption states the kind.** An Open Library *work* record is a book.
  Adoption from `open-library-native-work-proposal-v1` records `schema:Book`
  (with provenance "from the source's record type"), unless the proposal
  says otherwise.
- **An explicit kind command for existing Works.** A person who may edit
  the Work can state its kind, for example `schema:Book`,
  `PromptTemplate`, `SkillPackage`, `ModPackage` or `DigitalDocument`,
  keeping its identity, revisions and source provenance. It is a revisioned
  change with an expected head, an idempotency key and a history entry,
  like other Work metadata edits. Model it with a profile and model
  revision if the model has none. Changing kind must not break existing
  compositions, discovery or search; say how each follows.
- **Existing stacks.** The seed's classics step (held by G-387) will call
  the command for the classics adopted before this change. State the exact
  request in the handoff.

Tests cover adoption producing Books, the kind command (authority, head,
idempotency, history) and that discovery and search reflect the new kind.

## Verify

On the shared stack, as the seed operator acting for North Star Editions,
state Pride and Prejudice's kind as `schema:Book` through the new command.
`GET /v1/works/:id` then shows it, and `POST /v1/compositions` for it
succeeds. Use only the backend; no web dev servers.
