## Outcome

Relation and role labels become graph content edited through Main in any BCP 47
language (decision 45). Meaning, viewing directions and presentation are
versioned separately:

- A presentation revision pins one relation definition revision (its compatible
  meaning), one viewing direction (`fromRole → toRole`) and one language tag, and
  holds noun form, heading, CLDR plural forms, optional grammatical forms keyed by
  case, number or gender, source, licence and review status (`draft`,
  `reviewed`).
- A wording edit creates a presentation revision and never touches meaning; a new
  meaning revision makes older presentations incompatible, so they stop being
  selected while historical occurrences keep the meaning they had.
- `renderRelation(occurrenceOrKind, viewingRole, languages)` returns the
  rendering contract: meaning and revision, bindings, selected labels, typed
  arguments, the language, script and direction actually used, review status and
  fallback provenance (script-preserving: `zh-Hant` never becomes Simplified
  without saying so). `GET /v1/lexicon/presentations` batches it for up to 64
  definitions; G-831's relation reads embed it.
- A seed through the public API defines the first vocabulary with draft labels in
  the eight UI locales: derivation kinds (adaptation, new recording, software
  fork, rewrite, reboot), sequel, spin-off, correspondence (equivalent, partial,
  revised), composition part, and credit roles (author, illustrator, translator,
  concept supervision). Any other language is accepted without deployment.

## Approach

- New owner profile `definition-presentation-v1` as a registry-only binding (no
  Java policy case), written by its own command in `modules/lexicon/` with
  expected head, receipt and outbox event, copying the pattern of
  `semantic/change.ts` without editing it (G-629 claims that file).
- Select languages through `display-language/select.ts`; do not add a second
  selector. If it still caps labels or crosses scripts, report it to G-504.
- The seed is one data file plus a loader that calls the public API, reusable by
  production bootstrap; labels are `draft` until a native reviewer marks them.

## Do not build

- No MessageFormat 2 sentence templates, morphology adapters, Lexeme import or
  translation workbench (deferred; structured rows are the baseline).
- No labels in UI message catalogues or TypeScript maps for relations.
- No inverse facts stored to display a reverse direction.
- No administrator label editor UI (deferred); no change to Facet or Zone label
  locales (M4 language owner).

## Acceptance

- API: add a relation with labels in `de` and `ar`, read both directions; a
  wording edit keeps the meaning revision; a meaning change stops selecting the
  old presentation and historical occurrences keep theirs; `zh-Hant-TW`,
  `sr-Latn`, `az-Arab`, an absent inverse label and more than twenty stored
  languages return the right script, direction and fallback provenance; replay
  and stale heads behave as other semantic changes.
- Class guard: a conformance test renders every seeded definition in both
  directions for each UI locale and fails when a label is missing without
  fallback provenance or a fallback silently crosses scripts.
