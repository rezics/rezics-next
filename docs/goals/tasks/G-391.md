## Outcome

Author pages exist for Open Library authors (`/authors/open-library/<OL…A>`)
and natives (`/@handle`). G-390 linked them from the Work page and taught
Discover's cards to produce author hrefs (`authorLinks`). The shared card
renderer still prints authors as plain strings, and G-377 left two Work-page
one-liners.

- **Clickable authors everywhere.** `CatalogueWork.authors` in
  `catalogue/work.ts:20` is a `string[]`. Make it `{ name, href | null }[]`
  and link each name in `work-row.tsx:40` and `work-tile.tsx:69`, using
  `authorHref` from `features/author/route.ts`. Carry hrefs through every
  producer: `feed/card.tsx:155`, `search/read.ts:78`, `profile/cards.ts:26`,
  `library/read.ts:113`, `realm/adapt.ts:47`, `zones/card.tsx:38`, and
  Discover's `authorLinks`. A link inside a card that is itself a link needs
  valid markup (no nested anchors) and keyboard focus. Join CJK author names
  with "、" everywhere, as `WorkCover` does, not ", ".
- **Work page cover.** `work-page/work-frame.tsx:53` passes `cover.key`. Pass
  the Work's id, for example via `CatalogueCover` with the credit names, so
  the Work page's generated cover matches every other surface.
- **About the author.** In `work-page/author.tsx:24`, take the kind from
  `coverKindOf(item.types)`, and use `initials(credit.displayName)` from
  `@rezics/ui/avatar-initials` instead of the generic person icon.
- **i18n check.** Register the `author` feature's catalog in
  `scripts/i18n/check.ts`, so `task i18n:check` covers it. Add English and
  zh-Hans strings only.

## Verify in a real browser

Against the shared stack signed out: 雨夜书店 and Pride and Prejudice have the
same cover on home, Discover, search, their Work page and a Zone. Clicking an
author name on each surface opens that author's page. Tab reaches author
links inside cards. Check 1440x900 and 390x844. Run one web dev server
(`task web:dev`) only while checking, and stop it when done.
