## Outcome

Signed-in use of the main site works for real: sessions last, sign-out works,
the browser can reach every Main operation through the BFF, and people choose
the public Agent they act as from a picker instead of typing an IRI. Every
later main-site slice builds on this.

## Known defects (verified by a scout; confirm in code)

- `rezics_refresh` is stored by `app/auth/callback` but never used, so a
  session dies with the 300 s access token.
- There is no sign-out.
- `app/api/main/[...path]` exports GET/POST/PATCH/DELETE but not PUT, so all
  13 PUT operations (notification preferences, media bytes, zone
  configuration, avatar, context selections, mutes) are unreachable; its path
  check `^[A-Za-z0-9_-]+$` rejects dots (for example
  `/v1/me/acting-context-preferences/work.create`).
- `/auth/start` requests only `openid work:create work:read`; commenting,
  rating, notifications, reports and the rest will be refused for scope.
  Scopes are declared in `services/account/src/oauth-scopes.ts` and
  `oauth-scopes/*.ts`.
- `/auth/start` answers 503 when Account asks for consent; the dev client is
  registered skip-consent by `scripts/dev/web-auth-bootstrap.ts`.
- The acting identity is a hand-typed IRI stored in `rezics_subject`, although
  `GET /v1/me/acting-contexts` and `/v1/me/acting-context-preferences/*` exist.
  Read `docs/contracts/identity-and-access.md#acting-identity-layers` and
  `docs/experience/identity-and-access-experience.md` for the rules: the
  session Agent changes through a site-wide switcher, Studio keeps its own
  Agent in the route, the resolved Agent is shown before submit and never
  silently replaced.

## Deliver

1. **Token lifecycle.** Refresh-token rotation on the server (in the BFF proxy
   and server-side Eden calls) with single-flight refresh per request, correct
   cookie attributes, and a clean signed-out state when refresh fails. No
   token ever reaches browser JavaScript.
2. **Sign-out.** Revokes the refresh token at Account, clears cookies, returns
   to the page or home.
3. **Session read.** `features/auth` exports a typed server helper (for
   example `readSession()`) returning the signed-in user (id, display name,
   email, avatar if any), the session Agent with its label, the available
   Agents, and expiry; plus an account menu component that takes that
   session as a prop (the shell task G-202 renders an account slot; do not
   edit `features/shell/**`, `app/layout.tsx` or `i18n/**` owned by it —
   put your strings in `features/auth/messages.ts` with `en` and `zh-CN`
   objects, and say in the handoff exactly which one-line change wires your
   menu into the shell).
4. **Acting identity.** Replace `/identity` typing with a picker backed by
   `/v1/me/acting-contexts` and the preference routes; the session Agent is
   shown in the menu, switching is explicit, and a stale or revoked default
   is reported instead of silently replaced.
5. **BFF.** Allow every Main method and path Main's router accepts (validate
   against a safe character set that includes dots; reject traversal), stream
   bodies, forward `Idempotency-Key`, and keep the Main path shape so one Eden
   type serves server and browser.
6. **Scopes and consent.** Request the scopes the main site needs (derive the
   list from the scope declarations; keep it in one typed constant with a
   comment on why each is there). Handle a consent redirect instead of 503:
   redirect the browser to Account's consent page when Account asks (a
   separate task builds the Accounts site that hosts `/sign-in` and
   `/consent`; until it lands the dev client may stay skip-consent).
7. **Tests.** Unit tests for refresh, sign-out, BFF path and method handling
   and the acting-identity resolution; update the e2e specs you claim.
