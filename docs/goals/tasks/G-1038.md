## Outcome

1. **Carry G-1035 onto main.** Branch `goal/green-5` commit `563e382b3`
   ("Profile native write phases and avoid unchanged name and shape work")
   conflicts with main in `infra/jena/.../CommandService.java` and
   `FilteredGraphTextIndex.java`, which G-1022 changed for the asynchronous
   occurrence-label projection. Cherry-pick it onto your branch, resolve keeping
   both behaviours, and pass the native tests of both.
2. **Find the commit count.** G-1035 measured about 2.5 s and 6 MB of TDB2
   growth per public Work at 100 Works, constant per Work: TDB2 is
   copy-on-write, so every durable commit rewrites B+tree page paths in every
   index, and one Work takes several separate commits (creation, metadata,
   credits, classification, activation, projections). Count them with the
   native phase traces.
3. **Compound and bulk writes.** Design a public API command that applies a
   Work's creation with its metadata, credits and classification and activates
   it in one admitted, CAS-checked, idempotent transaction with one receipt,
   and a bulk form that applies many independent Works per durable commit with
   per-item receipts and per-item failure, preserving admission, validation,
   recovery and audit ([writes go through the API](../../storage/workload-budgets.md#data-preparation-and-import)).
   Record the contract in the owner doc. Importers and the scale recipe use it.
4. **Qualify.** Report latency and TDB2 bytes per Work for single, compound and
   bulk writes at 100, 1,000 and 10,000 Works (disk-backed recipe), and the time
   to prepare 10,000 Works, then build that corpus once, keep a consistent
   backup, and rerun G-1032's query matrix
   (`tests/qa/integration/g-1032-query-cost.test.ts` and its scale probe) at
   1,000 and 10,000 Works, fixing any query that breaks its bound there.
