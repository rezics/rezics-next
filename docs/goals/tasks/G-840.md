## Outcome

`tests/fixtures/catalogue/franchises.yaml` becomes data created through Main's
public API, and the twelve acceptance queries run as one integration test:

- A loader (`tests/fixtures/catalogue/load.ts`) creates the SAO and Index Works
  with Main Versions, the franchise Collections, the series compositions with
  labels (Index Original 1–22, SS1, SS2; New Testament 1–22, "22 Reverse"; Genesis
  Testament from 1), the Rewrite, Reboot, SpinOff and Sequel relations with the
  contract's source URLs as evidence, the release families as realizations and
  releases (including the Index omnibus), author credits, and the ten divergent
  pairs as two Works each linked by Rewrite.
- For query 11 it adds one chain from the `expand_*` lists: Railgun anime
  (Adaptation of the Railgun manga, source revision unresolved).
- Synthetic records the queries need (an unverified fan translation of the SAO
  web Work, contradictory wiki statements, a digital store identifier) live in a
  separate `synthetic.yaml`, so `franchises.yaml` stays facts only.
- A dev seed step (`scripts/dev/seed/franchises-step.ts`) runs the loader so the
  browser acceptance sees the same data; the loader is idempotent.
- `tests/qa/integration/g-840-catalogue.test.ts` asserts queries 1–12 exactly as
  `docs/contracts/work-and-release.md#catalogue-acceptance-fixtures` words them.

## What to read

- `docs/contracts/work-and-release.md#catalogue-acceptance-fixtures` and

- The APIs of G-830, G-831, G-833 and G-834 (sessions for query 6); G-835's

  `tests/qa/integration/structure-composition.test.ts`.

## Approach

- Keep facts in the YAML; the loader maps them to API calls and never invents
  bibliographic facts. Illustrator and concept-supervision credits are written
  only if an admitted credit role exists; otherwise list them as pending.
- Queries that depend on other briefs assert through those APIs: G-835 for the
  series-progress parts of queries 6 and 9, query 5 (review targets, T's G-650
  and G-652), query 7 (continuity-scoped statements with the spoiler boundary,
  M6b's G-847) and query 12 across Zones (Z's G-655). When an owner's API is not
  there yet, mark that assertion pending with the owner named; never pass it.
  The loader itself needs only G-830, G-831, G-833 and G-834, so M6b's Zone seed
  (G-852) can use it early.

## Do not build

- No new endpoint, schema or backend change; report missing API behaviour as a
  blocker for its owner.
- No harvested descriptions or covers; no broad catalogue import.

## Acceptance

  merged and lists the pending ones by owner; running the loader twice creates
  nothing new; `task dev:seed` shows the franchises in the local web app.
