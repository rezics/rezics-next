## Outcome

`apps/web/tests/direction-9.e2e.ts` (G-959) timed out in `beforeAll` after
600 s on the shared stack (log: `.temp/manager/direction-9-run1.log` in the
main checkout) while creating its records through the public API, so 31 of 40
tests never ran. `AGENTS.md` asks to build test data once and keep routine
preparation fast.

1. Find where setup spends its time (time each API phase; look for serial
   loops, rate-limit waits, polling for projections) and make setup finish in
   under two minutes: batch and parallelize independent writes within the
   principal budgets, wait on the projection the step needs instead of fixed
   polling, and create only what each journey asserts (for example 21 rating
   populations with one rating each, not more).
2. Make the fixture reusable: key it by a stable name so a later run on the
   same dataset finds and reuses the records instead of recreating them, and
   resets only what a journey mutates.
3. Run the suite on the shared stack (`REZICS_WEB_E2E_BASE_URL=http://localhost:3000`,
   `ACCOUNT_ORIGIN=http://localhost:3004`, `REZICS_WEB_AUTH_PRIVATE_PATH` = the
   main checkout's `.temp/stack/rezics-dev/web-auth/private.json`) through
   `bun scripts/goal/goalctl.ts slot --` with `--project desktop-chrome`, once
   for timing and once to prove reuse, and report each journey's result.
   Product failures you find are PROPOSED TASKS with the failing step and
   screenshot; never weaken an assertion.

No product code changes.
