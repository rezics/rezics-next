## Outcome

Main supplies the reads behind [Discover](../../plan/frontend.md#discover) and
[collections at any size](../../plan/frontend.md#collections-at-any-size); read
both sections and [design principle 9](../../product/design-principles.md).
Today Discover calls `/v1/works` per hardcoded type, communities come from a
separate `/v1/realms` directory, the Topics list (`realm-directory/vocabulary.ts`)
scans at most 256 Concepts and 2,048 labels and returns 20 alphabetically, and
the Work page's rating scope lists the Work's adoptions (20 by UUID order).

After this task:

1. **Every type through one query.** The shared Query compiler can traverse
   Spaces (as communities and as sites), Agents, Collections and Concepts
   beside Works, with type as an admitted Facet, text search, sort and complete
   keyset traversal under the existing budgets and disclosure (private and
   unlisted resources never appear). Check first how far "capabilities on any
   admitted resource" already reaches and extend that path; do not add a
   per-type endpoint.
2. **Discover sections**: one read returning ordered sections with their reason
   (popular in followed topics, communities in the reader's languages, new
   sites), built on existing ranking and follows, excluding what the reader
   follows, explicit signals only, with an off switch honoured. Anonymous
   readers get the general sections.
3. **Concept search**: indexed, multilingual label search (per-language
   analysis, CJK segmentation, Simplified/Traditional folding as the search
   owner already does for Works) returning each Concept's broader Concept and a
   usage count, cursor-paged; an empty query returns the reader's followed
   Concepts and the most used ones in the requested scope.
4. **Rating populations**: for a target, the populations that rated it, ordered
   by number of ratings, with Global and the reader's communities flagged,
   searchable by name and cursor-paged.
5. **List convention**: one request and response schema for list reads (`q`,
   `cursor`, `limit` in; `items`, `nextCursor`, `complete` out) and a static
   test over the generated OpenAPI that fails when a collection read lacks
   `cursor`/`limit` or the response fields, with a short commented allowlist of
   inherently bounded reads. Apply it to the reads above; list other offenders
   as proposed tasks rather than editing other owners.

Keep `/v1/realms` and the vocabulary route working until G-945 moves their web
callers; mark them deprecated in the OpenAPI description.

## Do not build

No learned recommendations, new ranking signals, new search engine, per-type
list endpoints, or web UI. Fix web fixtures and types only where a served
contract changed, and list web readers under OWNER CHANGES.
