## Outcome

G-946 added immutable join requests with an append-only decision table
(`modules/realm-admin/join-requests.ts`, `routes/realm-admin.ts`). G-948's UI
needs two reads it lacks:

1. **Inbox search**: `GET /v1/realms/{realm}/join-requests` accepts `q`
   (requester name or handle) and pages with `cursor`/`limit`, returning
   `{ items, nextCursor, complete }`, filtered in the database before paging and
   bound to the same manager authority as today.
2. **Requester status**: an authorized read for the signed-in person's own
   requests to a Realm (pending, accepted, declined, withdrawn, with the decision
   time), so the requester's view survives reload and learns the manager's
   decision. It reveals nothing about other requesters and answers the same 404
   as a missing Realm to people without a request.

Tests cover search across pages, denied and stale reads, and status after each
decision.

## Do not build

No new decision kinds, notifications or UI (G-948 owns the web side).
