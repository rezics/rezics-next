## Outcome

On `/concepts/{id}` with "match any", results are Works carrying the page's Concept AND any of
the added values, minus exclusions, through the API and the page. The emitted and echoed Filter is
`{ all: [ {concept all:[page]}, {concept any:[additions]}, {concept none:[excluded]} ] }`, so a
Saved Filter created from it means what the page showed. "Match all" is unchanged.

Verified defect (R21 item 8, "Concept anchor enters an Any group") in three places:
`readConceptWorks` drives `match === 'any'` over `[concept, ...include]` flattened, so the page's
Concept becomes optional (`services/main/src/modules/concept-page/read.ts`);
`conceptWorksFilter` echoes `{ any: [concept, ...include] }` (`concept-page/contract.ts`, and
`services/main/tests/concept-page.test.ts` asserts that shape); the web builds the same Filter in
`conceptQuery` (`apps/web/features/concept/state.ts`). The Query compiler's Concept Works template
admits only one included Concept Condition (`services/main/src/modules/query/compile.ts`, the
`facet.name === 'concept' && … && !included` branch), so it cannot express the anchor today.

## What to read

`docs/contracts/queries.md#filter-contract`; the four locations above;
`conceptMembership` and `DiscoveryCondition` (drive, groups, excluded) as `readConceptWorks`
uses them; `readFilteredWorks` (Discover has no anchor and stays as is).

## Approach

- `readConceptWorks`, match any: the page Concept's interpretations and the union of the
  additions' interpretations are two required groups; drive with the smaller one. Keep cursor
  binding, counts and stale handling as they are.
- `conceptWorksFilter` and web `conceptQuery` emit the anchor shape above (anchor alone when
  there are no additions).
- Compiler: the Concept Works template maps anchor (`all` or one-value `any`) + at most one
  additions Condition (`any` or `all`) + one `none`; a multi-value `any` with no anchor is a typed
  `unsupported_query_shape` refusal.

## Do not build

No new Query template, route, Facet, projection index or client-side filtering. Do not change
Discover, Home's feed template or Saved Filter storage.

## Acceptance

API: with Works tagged {A}, {B}, {A,B}, {A,C}, the A page with additions B,C match any returns
exactly {A,B} and {A,C}; with exclusion C returns {A,B}; match all B returns {A,B}; the echoed
Filter equals the web's emitted Filter; the old flattened shape compiles to a typed refusal, not a
wider result. Web: a property test round-trips state → href → state → Filter. Browser check of the
Concept page is in G-530.
