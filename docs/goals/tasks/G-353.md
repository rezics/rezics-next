## Outcome

Make the main site fast and usable by everyone, measured, not guessed:

1. **Performance**: measure Core Web Vitals (LCP, INP, CLS) and transfer size
   for home, Discover, search, a Work page, the reader, `/r/fiction`, a profile
   and Studio, on desktop and on a throttled phone profile, with the
   production build (`task web:build` or the vinext equivalent) served
   locally. Fix the biggest costs: server rendering where the first view is
   client-rendered, image sizes and `srcset` for covers, font loading, code
   splitting of heavy islands (editor, charts, Manage), avoidable waterfalls
   in data loading. Record budgets as a test or build check so regressions
   fail (a small `task` wrapper is fine; record any tool in
   `docs/development/toolchain.md`).
2. **Accessibility**: run axe on every page type (signed out, reader, author,
   moderator) and fix violations; then check keyboard-only use of home, search
   with typeahead, the reader, Studio's editor and dialogs, and Manage triage;
   focus order and visible focus; screen-reader names for icon buttons, feed
   cards and cover links; reduced motion; zoom to 200% without loss.

Library (G-346) and Zones (G-348) are being built by others; leave their
features. Use the shared stack for data (it may be reset by G-341 for a short
while; wait if so). Run one web server at a time, only while measuring.

## Checks

- `task web:typecheck`, `task ui:typecheck`; biome and oxlint on changed directories
- `task storybook:test` for the stories you touch (a11y error level)
- the new performance and accessibility checks pass; before/after numbers in the handoff
