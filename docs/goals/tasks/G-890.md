## Outcome

A ranked backlog of class-level problems that stand between today's product and
the launch the Goal targets: light novels and visual novels as two views over
one catalogue and library, each with franchise wikis, in the eight UI locales,
on phone and desktop. Write it to `.temp/audit/g-890/report.md` (at most 200
lines) with evidence files beside it. No code changes; this is research.

## What to read

`.agents/skills/product-audit/SKILL.md` (follow its method); `docs/product/goal.md`;
`docs/product/platform-thesis.md` (capabilities, Zones as routed sites);
`docs/contracts/work-and-release.md#work-levels-realizations-and-versions` and
`#catalogue-acceptance-fixtures`; `tests/fixtures/catalogue/franchises.yaml`.

## Approach

Use the shared local stack from the main checkout (`task urls`; do not start
another stack or dev server). Walk each job once through the HTTP API and once
in a real browser with Playwright at 390×844 and 1440×900, in at least one
non-English UI locale and one content language that is not a UI locale:

1. LN reader: find a series, pick the volume and edition they can read in their
   language, add it to the library, record progress, find the next volume, and
   resume on a second session.
2. VN player: find a playable release by language and platform with translator
   provenance.
3. Library move: import the cohort's typical export (CSV or the importer the
   app offers), fix unmatched rows, export again and compare.
4. Wiki editor: start a franchise wiki for a Work, add characters and facts
   with sources, browse it as a reader without spoilers past their position.
5. Catalogue editor: correct a credit, report a duplicate, find the history.
6. Newcomer: sign up, choose content languages, keep the private name private.
7. Agent: discover operations and complete jobs 1 and 5 through the API only.

Cross them with the skill's adverse states that apply. Write only through public
APIs with a test account you create; never reset or reseed the shared stack.

## Output format

Classes ranked by the skill's order (irreversible loss and safety; blocked core
jobs; repeated friction; differentiation). For each: the broken principle,
instances with file paths, the API and UI evidence (request/response excerpts,
screenshot paths), P0/P1/P2, and the falsifying acceptance scenario. Mark
evidence versus inference. End with a table mapping each class to one of the
Goal's M4–M8 areas.

## Do not build

No fixes, no new tests, no documentation edits, no new tooling. Do not audit
deferred scope (LLM index, events, geography, commerce, points, worldbuilding,
developer extras, Agent mode) beyond noting that it stays closed and honest.

## Checks

The report exists, every P0/P1 has evidence, and screenshots are referenced by
path.
