## Outcome

A series, subseries or season Work composes other Works through the existing
Structure kernel, so volumes and episodes are Works at their own level
(decision 49). One `work-composition` profile serves every admitted Work type:

- The owner is the composing Work's Main Version; `part` occurrences target
  native Works, read-authorized per target; `group` stays available.
- A part qualifier holds its display label ("22", "22 Reverse", "SS1") and its
  inclusion (`required`, `optional`, `extra`). Composition order is publication
  order; numbering is per composition, so Genesis Testament restarts at 1.
- A Work may be a part of several compositions; inserting an ancestor is
  rejected as a cycle.
- The composition records whether the series is concluded, ongoing or unknown,
  with evidence, for G-835's progress states.
- `GET /v1/resources/{id}/parts` (paged, label, inclusion, order key, Main
  Version) and `GET /v1/resources/{id}/wholes` read both levels; a private part
  is withheld without count or title leakage.
- Composition writes never add `schema:isPartOf`, so volume Works stay visible
  in search and listings (the `search-multifield.ts` risk the contract names).

## Approach

- Add `modules/composition/structure-profile.ts` (found by the existing glob),
  `work-composition: ['group', 'part']` in `PROFILE_ROLES`, and widen the
  `profile` literal in `routes/compositions.ts`. The qualifier follows
  `book-group.ts` and `structure-book-v1.ts`.
- The cycle check is one bounded ancestor query (four levels) at admission;
  reads page the current generation through `structure/read.ts`.

## Do not build

- No `series-catalogue`, `series-tracking` or audiovisual module, table,
  migration or profile per medium; no new Structure mechanism.
- No `schema:isPartOf` for Work-level parts; no change to chapter Works.
- No second ordering mechanism: a curator's reading order is an ordered
  Collection (existing Listed capability) referencing the same Works.
- No progress, sessions, next-part logic (G-834, G-835) and no UI (G-837).
- No franchise Work: a franchise is a Collection.

## Acceptance

- API: build Index Original (1–22, SS1, SS2), New Testament (1–22,
  "22 Reverse") and Genesis Testament (1…) compositions; labels, inclusion and
  order survive replay; a reorder keeps occurrence IDs; an ancestor insert is
  rejected; a Work in two compositions lists both wholes; parts traverse past
  one page; a stale head and a denied editor fail.
- Class guard: an integration test composes a volume Work and asserts it is
  returned by multifield search, public search, author page and Zone browse; it
  fails if any composition write adds `schema:isPartOf`.
