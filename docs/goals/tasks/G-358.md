## Outcome

G-348 built first-party packages for Books, Mods and AI Workshop (Fiction had
one already), gated on an approved build digest, with the operator's approval
steps recorded in the theme runbook. On the dev stack they are not approved,
so every official Zone shows its fallback, and several package modules have
no data:

1. **Approve in dev**: the seed's official-Zone step computes each package's
   digest (`task zones:digest -- <slug>`, the same function the web uses) and
   runs the review and approval through the theme lifecycle API as the fixture
   operator, so `/r/fiction`, `/r/books`, `/r/mods` and `/r/ai-workshop` show
   their packages on the shared stack. A changed package digest must be
   re-approved by rerunning the seed.
2. **Layouts**: seed the Zones' layouts with the modules the packages render
   (Mods: game and loader filter bar, trending board; Books: author spotlight;
   AI Workshop: collections by task).
3. **Card data** Main does not serve yet: mod compatibility (game versions and
   loaders from the package owner), a prompt's tested models and its copyable
   prompt text (from the Hub item), each bounded and disclosure-safe in the
   Zone module reads.

Backend and seed only, no dev servers.
