## Outcome
Cover, avatar and community image uploads stay open at launch (decision 42). A
new upload activates as today, but no one sees it except its uploader until a
local, free classifier clears it.
- A likely explicit image is held and opens a platform case for review. The
  classifier's output is review evidence, never clearance by itself.
- A classifier error, a timeout or an outage also holds the image for review.
  It never publishes the image and never disables uploads.
- Replacement uploads take the same path.
- The upload and status APIs report `screening | cleared | held | rejected`
  without revealing scores to the uploader.
- The media owner supplies the known-identical-copy primitive that NCII removal
  needs. `suppressIdenticalCopies(originalDigest)` suppresses every asset whose
  original has those exact bytes. Later uploads of suppressed bytes activate
  already suppressed.

## Approach
- Add a clearance state per original representation in migration 600. Every public delivery predicate (avatar, uses, summaries) additionally requires `cleared`. The uploader's authorized preview is unaffected.
- Screening reuses the `transform_job` lease, fence and epoch mechanics as one more job profile.
  - A bounded Main worker loop decodes the image (cap dimensions, time and memory), downscales it and runs NSFWJS on CPU.
  - Record the model, version, weights digest and thresholds on the job result.
  - Above threshold → `held`, plus a platform case through the governance store: category prohibited imagery, automation disclosed.
  - Below → `cleared`.
  - Error or timeout → `held` with reason `screen-unavailable`.
- Decoder and runtime:
  - Choose what runs under Bun with pure-JS or prebuilt binaries, such as `@tensorflow/tfjs` with the CPU backend plus a decoder library.
  - Pin versions and licences, and record them in `docs/development/toolchain.md`.
  - Tests use a deterministic fake classifier; one smoke test loads the real model.
- Staff decisions on held images go through G-565: clear → `cleared`, restrict → `suppressed`.
- Copy index: an index on the original representation's SHA-256, plus the suppression primitive and the activation-time check. The check is idempotent and bounded per call, with a continuation for large sets.

## Do not build
- No PhotoDNA or NCMEC hash integration. PhotoDNA is deferred brief G-572, added once approval arrives.
- No Cloudflare configuration; that is M8 deployment.
- No paid API and no perceptual hashing.
- No "bypass screening" grant yet.
- No new upload routes or asset model.
- No server-side transforms beyond the screen's decode.
- No UI; G-820 shows the states.

## Acceptance
- API integration tests:
  - A benign image reaches `cleared` and is then delivered.
  - A fake-flagged image is `held`, is not delivered through any media URL, summary or preview, and opens a platform case.
  - A classifier timeout gives `held` with reason `screen-unavailable`.
  - A replaced avatar keeps the previous cleared image until the new one clears.
  - A replayed activation causes one screen and one state.
  - A lease lost mid-screen is re-leased; the stale token cannot settle.
  - `suppressIdenticalCopies` suppresses three assets with the same bytes but different owners. A fourth upload of those bytes activates suppressed.
- Class guard: a test enumerates every public media delivery path and fails if any path serves a representation that is not `cleared`.
