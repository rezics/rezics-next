## Outcome

The Work page and reader (G-251, merged: `apps/web/features/work-page/**`)
found these Main gaps; fix them in the API:

1. **Progress for readers.** Reading progress needs a `work.read` grant on the
   Work and each chapter target, so ordinary readers of public Works get none
   (`routes/progress.ts`). Admit progress for any verified reader of a public
   chapter (the baseline member policy from G-255 is the natural source), and
   keep private Works as they are.
2. **Chapter identity.** `GET /v1/chapters/{id}` has no label or position, so
   the reader cannot title a chapter. Return the occurrence label (localized
   where available), its ordinal position and the parent path.
3. **Reading settings.** Add an account-level (person Agent) read/write for
   reader settings (font size, line width, paragraph indent, theme, CJK
   options) so they sync across devices; bounded, private, no-store.
4. **Stable reads** (Work reads are claimed by G-277 now; a later task does
   this) — skip.
5. **Creator can read their new Work.** Check that the creator of a private
   Work can read it immediately after creation (Studio then Work page showed
   "not found" before G-255); fix if still broken.

Then update the web reader (`apps/web/features/work-page/**`, unclaimed now)
to use chapter labels, synced settings and progress; verify with Playwright.
