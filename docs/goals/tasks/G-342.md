## Outcome

Fix findings SR-1, SR-3, SR-4 and SR-5 of the security review
(`/home/edge/projects/rezics/rezics-next/.temp/manager/security-review.md`:
read each finding's evidence, fix and regression scenarios):

- **SR-1 (High)**: pending email-change links survive a password reset or
  recovery. Bind both stages to an immutable user ID, a security/recovery
  generation and a durable single-use intent; invalidate pending intents on
  reset, recovery and security revocations; recheck and consume under the
  same ordering as recovery.
- **SR-3 (Medium)**: native provider session endpoints bypass the step-up
  gate. Disable unused provider aliases or route them through the same
  step-up and origin policy; add a route-parity test that denies every
  sensitive alias with an old session.
- **SR-4 (Medium)**: return-path validation permits an external redirect via
  control characters. One shared policy for Accounts and the web BFF: reject
  control characters, parse against a fixed trusted origin, require a
  root-relative path, return the canonical path only after validation; cover
  encoded tabs, other controls, backslashes and network-relative input.
- **SR-5 (Low)**: passkey step-up skips signature-counter persistence. Persist
  the verified counter with concurrency handling on the no-new-session path.

Each fix ships with the regression tests the review describes; never weaken an
existing test. No dev servers beyond one Playwright check of the sign-in
redirect if needed.
