## Outcome

The second milestone review (`.temp/manager/milestone-review-2.md`, finding
4; screenshots `rd-d-stale-session-work.png` and
`rd-d-stale-session-after-click.png` in `.temp/manager/milestone-2/`): with a
session about an hour old, the header showed Daniel and Library worked, but
Want to read, Rate and Write a review on Work pages linked to `/auth/start`.
Clicking one ran a client RSC fetch that followed the redirect to the Accounts
authorize URL and failed with CORS ("RSC navigation error: Failed to fetch").
Twice this left Reviews as a skeleton and the page in a fallback font; a
third click did nothing. A fresh sign-in fixed it.

- **One signed-in state per request.** Every server read in a request sees
  the same session: when the access token has expired, it is refreshed once
  (the path Library already uses, `features/auth/refresh.ts`) and shared by
  the header and every read on the page; if refresh fails, the whole page is
  signed out, header included. Make this a property of the session layer, so
  a feature can't read the viewer differently.
- **Sign-in never breaks the page.** `/auth/start` must work however it is
  reached. A router link or prefetch to it (the Work page, catalogue and
  other features use them; those files are held by G-375 and G-377) must end
  in a full-document navigation to Accounts, never a cross-origin fetch. Fix
  it at the route or in the shared link layer, not per call site, and add a
  test that a client navigation to `/auth/start` becomes a document
  navigation. List any call site that still needs a change under PROPOSED
  TASKS.
- **Refresh-token reuse.** The reviewer suspects a rotated refresh token
  reused across two browser contexts. Two tabs with the same cookie must
  both stay signed in, or one signs out cleanly; never a half state.

## Verify in a real browser

Against the shared stack as Daniel (credentials in `scripts/dev/seed/plan.ts`):
expire the access token (shorten its lifetime in your local environment, or
edit the session cookie as the tests do), then load a Work page and use Want
to read, Rate and Write a review; repeat with the refresh token revoked; and
with two tabs. Clicking a signed-out action from a Work page lands on
Accounts' sign-in and returns to the Work page. Run one web dev server
(`task web:dev`) at a time, only while checking, and stop it when done.
