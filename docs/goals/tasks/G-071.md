Critical-path enabler, **no behavior change for existing profiles**. Today every
new graph profile needs hand edits to `CommandService.validateCanonical` (an
if-chain mapping RDF types to profile/shape), `BindingPolicy` (bound keys and
validators), a command-module version bump and literal version pins in about
20 files. G-063 and G-065 were blocked by exactly this, and about ten phase-A
schema tasks will add profiles next.

1. Let each profile definition declare its canonical focus types and, where
   needed, a declarative discriminator (a predicate value selecting the shape),
   in the IR (`model/compiler/ir.ts`). Generate a registry artifact the image
   already ships beside the shapes; the Java module loads it and resolves the
   canonical profile/shape from it. Keep the existing special cases
   (RealmPublicationSlot, RouteBinding state, PublicationSelection basis,
   ClassificationContext role) semantically identical, as data or as retained
   code.
2. Make per-profile binding requirements (required binding keys and the profile
   a binding demands) data-driven from the same registry where the rule is
   generic; keep bespoke validators (title control, author credit, head CAS) as
   code.
3. Define the command-module version once (pom.xml) with one TypeScript source
   (`services/main/src/infrastructure/profile.ts` or a generated constant) that
   every test and script imports instead of a literal. `search-private.ts`,
   `services/main/tests/search-private.test.ts` and `infra/dev/compose.yaml` are
   outside your claim: list the one-line changes they need in the handoff.
4. Prove extension: a test adds a synthetic profile through the registry alone,
   with no Java edit, and the module validates and rejects it correctly.

Checks: `model/tests/native-equivalence.test.ts` keeps every recorded outcome
and digest, `infra/jena/tests/command.integration.test.ts`, the model compiler
unit tests, the claimed Main tests through `goalctl test`, `yarn gen` locally
(do not commit generated outputs or the compose stamp), tsc/biome/oxlint.
Document the "add a profile" procedure in `docs/implementation/model-profile-validation.md`.
Estimate 60–90 minutes.
