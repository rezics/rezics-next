## Outcome

Two defects in the QA harness planner, found while diagnosing wave runs:

1. **Poisoned duration history.** A run during a Docker outage failed every
   fault/recovery file in 0.5–1.5 s. Those durations were recorded as local
   history and now override `faultRecoveryBaselineDurations`, so the planner
   thinks multi-minute drills take about 1 s and packs 13 files into one shard
   that cannot finish inside the 360 s tier budget. Exclude durations from
   failed files, from runs whose stack was unavailable, and from files that
   never started, when building history (for every tier).
2. **Silent impossible plans.** With `REZICS_QA_SHARDS=2`, `planStackProjects`
   reserves one slot for isolated files, leaving one process for every shared
   file; estimated time far exceeds the per-shard budget (480 s integration,
   360 s fault/recovery) and the run is killed with most files unstarted.
   When the capped shard count cannot fit the estimated time into the budget,
   print a clear warning with the estimate and the shard count that would fit
   (do not silently raise the cap, which exists to protect host memory).

## Deliver

The two fixes in `scripts/qa/core.ts` / `scripts/qa/cli.ts` with unit tests in
`tests/qa/unit/core.test.ts` (and a CLI test if the warning lives there).
