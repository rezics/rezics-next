## Outcome

The repository's main gates fail on main (found by G-872):
- `task check` stops at the Eden consumer gate:
  `tests/qa/client/main-contract.ts:47` posts a `metadata-only-v1` Work body
  without `grain` and `candidateReceipt`, which `POST /v1/works` now requires
  (search-first intake, G-842/G-892).
- `task about:check`: three implicit-any errors on `getCollection('legal')` in
  `apps/about/src/pages/sitemap.xml.ts` and `[locale]/legal/[slug].astro`
  (legal policies published by G-736).
`task check` stops at the first failing gate, so later gates may also fail.
After this task both commands pass end to end on current main.

## Approach

Fix each failure at its cause: the client contract fixture follows the
intake API as a real client does (search, then create with the receipt and
grain); the about site declares the `legal` content collection's schema so
entries are typed. Run `task check` through `task goal -- slot -- task check`
repeatedly until it passes, fixing each newly exposed gate at its cause. If a
failure belongs to a file a running task claims, list it and continue.

## Do not build

No gate removals, no lint suppressions without a stated reason, no relaxed
types.

## Checks

`task goal -- slot -- task check`; `task goal -- slot -- task about:check`.
