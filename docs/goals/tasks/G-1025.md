## Outcome

The [Home](../../plan/frontend.md#home) surface: the anonymous Home (All feed, trending), and the signed-in Home (Following · Best and New, the Continue strip, Saved Filter tabs, the right rail: trending in my Realms, Realms to follow, my moderation queue). Best's ranking is decided (2026-09-28; constants in `services/main/src/modules/feed/ranking.ts`): measure its cost, do not reopen the product rule.

## Method

Use G-1024's work profiles (`tests/qa/support/work-profile*.ts`, web traces,
the scale recipe; read `docs/testing/complexity.md` first).

1. **Model.** Write down the cost model each request on this surface should
   have, from the owner's cost contract, code comments and docs: round trips by
   kind and how each grows with every dimension (unrelated corpus, follows,
   memberships, history, page size, viewer kind). Where no contract exists,
   write it beside the owner.
2. **Measure.** Profile the surface at the three scales, one dimension at a
   time, cold and warm, anonymous and signed in where both apply, including
   the web page's fan-out to Main.
3. **Compare and fix.** Report every gap between model and measurement (work
   that grows with unrelated data, N+1 hydration, repeated Access or session
   checks, duplicate reads between server components, rescans of completed
   prefixes) and fix it by algorithm and data layout, never by a bigger budget,
   a timeout or a cache that hides growth
   ([perf by algorithm](../../storage/workload-budgets.md#complexity-contracts)).
4. **Algorithm.** Where an owner doc records a decision with research for the
   ranking or selection algorithm, keep it and measure against it. Where none
   exists, research current best practice and published work, decide in the
   owner doc with sources, and implement it.
5. **Guard.** Encode each cost contract as a test with the profile assertions
   so a regression fails, and put a before/after table in your handoff.
