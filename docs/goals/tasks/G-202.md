## Outcome

The REZICS main site gets its real application shell, built from Rezics UI with
the Rezics Aura theme, so every later feature slice drops into a finished frame.
Today `apps/web` is an early slice: about 108 lines of hand-written CSS in
`app/styles.css` with hardcoded colors and a Georgia body font, no loaded fonts,
no dark mode, and only `button` and `input` from `@rezics/ui`. This task
replaces that with the product's design language and layout, and restyles the
existing pages (home, search, work detail, studio) inside it.

This is the first frontend template of the Goal: later workers copy its
structure, so make it exemplary.

## Deliver

1. **Theme adoption.** Remove the hand-written styles; the app imports
   `@rezics/ui/styles.css` and uses Aura tokens only (`docs/development/design-system.md`
   is the design rulebook; red never colors text). Load Manrope, Iowan Old
   Style/Source Serif 4 (Work titles only) and Geist Mono with self-hosted
   files (for example `@fontsource-variable/*`), with CJK fallbacks chosen for
   zh-CN. Light and dark mode following the system preference with a manual
   override persisted in a cookie so SSR renders the right theme without flash.
2. **Shell.** Desktop: top bar (logo, global search, notifications slot,
   acting-identity/account slot) plus a collapsible left navigation.
   Phones: the five-item bottom navigation (Home, Discover, Create, Inbox,
   Shelves; Create emphasized) with the left navigation in a drawer. Use
   `aura-canvas` for the page ground. Keyboard: skip link, visible focus,
   `/` or Cmd/Ctrl-K focuses search. Keep the navigation items in one typed
   config so later slices add entries by one line. Routes that do not exist
   yet may link to a friendly "coming soon" state rather than 404.
3. **Account slot.** Show "Sign in" when there is no session and an avatar
   menu when there is (the session layer is a later task: read what
   `features/auth` exposes today and keep the menu a separate component with a
   small typed `session` prop so the session task can wire it without touching
   the shell).
4. **Restyle existing pages** (`/`, `/search`, `/works/[revision]`, `/studio`)
   with Rezics UI components (Card, Badge, Tabs, Skeleton, Alert, Empty states)
   and proper loading, empty, error and not-found states. Keep their behavior
   and existing tests green. The home page becomes a real landing: search
   first, then placeholder sections that later slices fill (keep them honest,
   no fake data in production paths).
5. **Per-feature i18n.** Move UI strings out of the single `i18n/en.ts` and
   `i18n/zh-CN.ts` catalogs into per-feature typed catalogs (for example
   `features/<name>/messages.ts` exporting `en` and `zh-CN` objects with one
   shared type), keeping `i18n/` for locale resolution and the merge. Parallel
   feature slices must be able to add strings without touching a shared file.
6. **Stories.** Stories for the shell (desktop, phone, signed in/out, dark,
   zh-CN, long names) and each restyled page's states, with play tests where
   behavior matters. `storybook:test` passes with the a11y checks.
7. **Docs to code.** Where your code now states what `design-system.md` or
   `web-features.md` says (layout conventions, tokens, radius tables), shorten
   those pages to the reasons and point to the code.
