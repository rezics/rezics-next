## Outcome

Maintainer decision (`docs/plan/frontend.md#home`, "Styled controls only"):
no native `<select>` in the web app. Menus and selects use `@rezics/ui` Select
and Menu (Ark UI), enforced by a lint rule, so every control matches the
design in every browser and theme. Today there are three places:

- the raw `<select>` in `apps/web/features/shell/locale-switch.tsx`;
- `NativeSelect` in `apps/web/features/search/search-form.tsx` (the search
  scope);
- four `NativeSelect` uses in `apps/web/features/manage/members-view.tsx`
  (invite duration and the others).

Move each to `@rezics/ui` Select or Menu, keeping behaviour:
- the locale switch still works without JavaScript (a form post or links);
- the search scope still submits with the form;
- the Manage dialogs keep their keyboard use and stories.

Add an ast-grep rule under `scripts/static/ast-grep/rules/` that forbids
`<select>` and `@rezics/ui/native-select` imports in `apps/web`, with rule
tests. If nothing else uses `native-select` in `packages/ui`, leave it for
Accounts; the rule covers the main site. G-401 is reworking Home's controls
at the same time, and knows to use Select and Menu.

## Verify in a real browser

Against the shared stack: the locale switch signed out, the search scope, and
a Manage invite dialog as the Fiction owner (credentials in
`scripts/dev/seed/plan.ts`), with keyboard, at 1440x900 and 390x844, light
and dark. Run one web dev server (`task web:dev`) only while checking, and
stop it when done.
