## Outcome

`@rezics/wiki-toolkit` (Apache-2.0, created by G-845) does only what models do unreliably.
`rezics-wiki units <file>` prints JSON Lines of text units (chapter, scene or utterance)
with their exact `rezics-locator-v1` locators; `rezics-wiki verify <file> <locator>` resolves
a locator in the holder's file and prints the quote with its context, or fails. It reads TXT
(declared or detected encoding, reported uncertainty), EPUB 2/3 (spine order, ruby base and
reading kept apart, range CFIs in UTF-16 offsets with a quote fallback) and literal Ren'Py
`.rpy` scripts (labels, say statements, menus and jumps as route guards; Python blocks are
skipped, never executed). Protected or unsupported input fails to parse with a plain
message. `skill/SKILL.md`, following the Agent Skills specification, teaches any agent the
whole build: find the Work and its parts through REZICS's API or MCP, run `units`, extract
atomic claims chapter by chapter with quotes chosen from unit text, call `wiki_candidates`
and `wiki_validate`, submit a `wiki-bundle` proposal (G-865), and send later chapters as
deltas. The package needs no REZICS account, sends no telemetry and fetches nothing.

## Approach

- `src/txt.ts` with iconv-lite (MIT): keep original bytes, a decoded-to-byte offset map, and byte-range locators over the representation SHA-256; propose chapter units from headings and separators and mark ambiguous boundaries.
- `src/epub.ts` with fflate (MIT) and @xmldom/xmldom (MIT): package document, spine, navigation; ignore obfuscated fonts; any other `META-INF/encryption.xml` entry fails the file.
- `src/renpy.ts`: a line-based reader of literal statements only; dynamic speakers stay unknown.
- `src/cli.ts`: the two commands above and nothing else. Register the package in the root `workspaces`, switch Main's and `@rezics/model`'s relative protocol imports to `@rezics/wiki-toolkit/protocol`, and record each dependency and its licence in `NOTICE` and `docs/development/toolchain.md`.
- `skill/SKILL.md` plus `skill/examples/` built from public-domain text only; the strict-mode section says to use a local model when the holder wants no provider to see the text. `README.md` states formats, data flows, the no-circumvention rule and the licence without claiming legal clearance.
- Fixtures under `tests/fixtures/wiki-toolkit/`: Pride and Prejudice TXT (existing Gutenberg entry) and an EPUB generated from it in the test; a Shift_JIS excerpt with its source notice; a Ren'Py script authored from public-domain passages with a branch, a dynamic speaker and a repeated line; a non-BMP CFI case.

## Do not build

No local database or ledger, no uploader or worker processes, no local MCP server, no model
or inference integration, no network code, no archive, compiled-script or runtime-hook
support, no decryption or key handling, no REZICS authentication code, no third command.

## Acceptance

- `units` then `verify` round-trips every locator of every fixture (100%); a changed byte in the file makes `verify` fail; an EPUB with a non-font encryption entry fails; the Ren'Py branch keeps its route guard and the repeated line gets distinct locators; decoded Shift_JIS text matches its source.
- A scripted, model-free run of the skill's steps against the local stack produces a bundle that G-845's validator accepts (skip with a reason until G-865 merges for the submit step).
- Class guard: a test fails if any file under `packages/wiki-toolkit/src` imports `node:http`, `node:net`, `fetch` or anything outside the package and its declared dependencies, or if any dependency's licence is not permissive; `npm pack --dry-run` lists only package files, each with an SPDX header.
