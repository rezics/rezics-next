## Outcome

The direction-9 browser suite requests `/en/a/1CE436F9-E7EB-4155-988E-D23A8514150F`
(an unnamed person's legacy UUID in upper case) and expects one 301 to the
canonical address, as [durable addresses](../../product/urls-and-seo.md#durable-addresses)
requires for every legacy UUID link; it does not get one. UUIDs compare without
case (RFC 9562), while `sid` values are case-sensitive Base58. Make every
legacy UUID form (any case, with or without hyphens if Main accepts that
elsewhere) resolve in the web address parser and Main's resolver, for every
scope and router (`/a`, `/@`, `/r`, `/z`, `/w`, `/e`, `/concepts`), answering
one 301 to the canonical form, without loosening `sid` comparison. Unit tests
for each form; run them with `bun scripts/goal/goalctl.ts test`.
