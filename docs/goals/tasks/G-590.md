## Outcome

`model/compiler/generate.test.ts` stops being a merge hotspot. Today every task
that adds a model profile edits hand-kept lists in it (historical canonical
routes, lock expectations, synthetic profile ids), and parallel tasks conflict
there at every merge. After this task the test derives those expectations from
`model/accepted/profiles/*.json`, `model/accepted/facets/*.json` and the
compiled manifest, and uses synthetic ids that can never collide with a real
profile (for example `zz-test-*`), so adding a profile needs no edit to this
file.

## Approach

Keep every assertion's meaning: an accepted profile or Facet whose digest or
binding changes fails; an unaccepted profile's error names the exact file and
content; the merge-base guard rejects rewriting an existing lock entry; the
canonical-route expectations still fail when a route is wrong. Replace literal
per-profile lists with values computed from the lock files and the manifest.

## Do not build

No change to `generate.ts` behaviour, to any lock file or to any profile.

## Checks

`bun test model/compiler/generate.test.ts` passes; `task gen:check` passes; a
deliberate edit of one accepted profile still makes the test fail (show it).
