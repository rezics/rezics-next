## Outcome

The maintainer's final deletion pass (standing direction 2). Every document
under `docs/` either carries what code cannot (intent, decisions with their
reasons and evidence, operating procedures, legal texts, the Goal program) or
is gone. What code already states (types, schemas, tests, lint rules, stories,
generated registries and comments) is deleted from the documents. What code
should state but does not yet is moved into the owning code as a comment, type
or test, or else listed as a proposed task. Links from code to deleted
documents are repointed. `task docs:check` passes, and the handoff reports lines
and files before and after, with a one-line reason per deletion. The about site's
feature registry (`apps/about/src/features.ts`) gets the same truth pass: every
capability the manager's cut lines deferred carries its post-launch label and
source, so no page presents it as available at launch (decision 37).

## What to read

- `docs/goals/manager.md` (standing directions 2 and 7); `AGENTS.md` ("Express in code whatever code can express"); `docs/README.md`.
- `git log` since the Goal restart for maintainer documentation edits. They are authoritative: never revert or silently rewrite them; a refinement goes in its own commit with the reason.
- The merged code of this Goal: most contract "Status", cost and schema paragraphs now have an executable owner.

## Approach

Work document by document, with owners first: contracts, then architecture,
plan and implementation, then research and testing. For each document:

- Keep a paragraph only if it records why, what was decided with its evidence, how operators act, or what users agree to.
- Replace restated behaviour with a link to the code that enforces it, and delete paragraphs that only repeat a schema, route list, cost bound or test name.
- Merge small documents that share an owner. Delete superseded plans and research whose conclusions now live in an owner document, after checking the owner keeps the evidence link.
- Keep unchanged unless a paragraph duplicates another: `GOAL.md`, `docs/product/{goal,platform-thesis,markets-and-growth}.md`, `docs/goals/**`, `docs/legal/**`, and the runbooks written in M8 (`docs/operations/{release,production-install,recovery,email}.md`).
- Repoint code comments that link deleted documents as OWNER CHANGES, touching comments only.
- In `features.ts`, change only delivery data: `{ later: source }` with the owner document that records the deferral (the manager records the cut lines in `docs/product/capabilities.md#deferred-rollouts`; if they are not recorded, stop and ask). Never label a principle or a launch item.

- Manager: `apps/about/src/features.ts` is G-856's (about-site alignment); list its changes under OWNER CHANGES.
- Manager (2026-10-01): time box — commit in owner-sized steps and hand off by 22:15 CST whatever is done; the remaining documents become a proposed task list. Work order: contracts, architecture, plan, implementation, then research and testing. Never delete intent text the maintainer wrote (decisions, reasons, product documents, legal); refine only by the brief's rules and say why in the commit message. Late merges may still touch a few documents (G-856, G-743, the security fixes); rebase before each commit and leave their files for last.

## Do not build

New documents, style rewrites of kept documents, code behaviour changes, a docs
generator, or deletion of decision records whose reasons are not stated
elsewhere.

## Acceptance

`task docs:check` passes, and `rg 'docs/[a-z-]+/[a-z0-9-]+\.md'` over the code
finds no dangling path. The handoff contains a table of files deleted, merged
and kept, with reasons, and the total line change. A reviewer can find every
standing decision (`GOAL.md` 1–50) at a live anchor.

## Checks

`task docs:check`; `task about:check`; `task check`.
