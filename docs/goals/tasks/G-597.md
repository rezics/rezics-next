## Outcome

A signed-in reader's reading languages are the list Main keeps (G-514): settings, the feed's
language controls and display-name requests read and write that list, in order, with no cap at
eight. The `rezics_content_languages` cookie remains only for signed-out readers. Today settings
takes a comma-separated text field and writes the cookie (`settings-sections.tsx:220–300`), the
cookie keeps at most eight entries (`display-languages.ts` `slice(0, 8)`), and the feed writes a
separate list.

## What to read

`apps/web/i18n/display-languages.ts`; `apps/web/features/settings/settings-sections.tsx`;
`apps/web/features/feed/controls.tsx`; `apps/web/features/onboarding/language-picker.tsx` (the
picker to reuse, with its onboarding messages); G-514's preferences route; the three
`features/api/*` files that pass display languages to Main.

## Approach

Replace the text field in settings with the onboarding picker (reorderable, any valid tag),
reading and saving through Main's preferences route with its revision (show a conflict and
reload on 409). Signed-in requests send Main's list as display languages; signed-out requests
keep the cookie. Raise the cookie bound to 20. Reuse the onboarding catalog for picker labels; if
a new key is unavoidable, stop and report it (settings messages belong to G-515).

## Do not build

No new picker component, no language auto-detection, no sync between cookie and Main, no
interface-locale changes (G-598).

## Acceptance

Browser on the local stack: sign in, set Japanese, Korean and Cantonese (`yue-Hant`) in settings,
reorder, reload in a second browser context: same order; the feed's language control shows the
same list; signed out, the cookie path still works. API: captured writes go to Main only.
Class guard: a test fails if signed-in display languages come from the cookie.
