## Outcome
Main limits every write per principal, by class, and returns `429` with
`Retry-After` when a class budget is spent. The classes are anonymous, new
account, member, trusted (editor or moderator roles) and service (an importer or
another operator-installed client). Uploads, public reports and case
correspondence have their own families. Report and appeal intake stay reachable
when ordinary budgets are exhausted. Imports run as a service principal with a
high budget and use the same API; a slow API is a defect, not a reason for
another write path. Accounts sign-up and other abuse-prone enrollment endpoints
require a server-validated Cloudflare Turnstile token.

## Approach
- Main uses one Elysia hook in the `rate-limit` module, registered once in `app.ts`.
  - Family comes from method and route: write, upload (`/v1/media/uploads*`), report (`/v1/public-reports*` from G-564), and ordinary reads stay unlimited except anonymous search.
  - Class comes from trusted inputs only:
    - no bearer → anonymous, keyed by an HMAC of the client IP from the configured trusted proxy header;
    - roles from Access;
    - account age from the Access principal's first-seen time;
    - service classes from an allowlist of `client_id`s in config.
  - Key authenticated budgets by the Account subject (the operator), not by Agent or token, so extra Agents and tokens do not multiply the budget. If G-508's operator identity has merged, use it.
- Budgets live in one versioned table in code, overridable by environment. Start with R19's newcomer numbers, for example uploads: new 5/day, member 30/day.
- Counter store unavailable → `503` with `Retry-After`, never fail open.
- Accounts:
  - Enable the Better Auth captcha plugin with Turnstile on sign-up and on unauthenticated email-sending endpoints.
  - The sign-up form renders the widget.
  - Development and tests use Cloudflare's documented test keys.
  - The plugin ships with the pinned `better-auth`, and the widget loads Cloudflare's script, so no package is added. If a package turns out to be needed, stop and hand off rather than touch `package.json` or `yarn.lock`: G-571 and G-580 claim those.

## Do not build
- No per-route allowlist beyond the family rules.
- No reputation scoring or network or device fingerprinting.
- No Redis or other new store.
- No per-Agent budgets.
- No change to the backpressure lanes.
- No Turnstile on authenticated API calls or on Main.
- No UI beyond the Turnstile widget. Clients already surface `429`; G-820 shows it on report forms.

## Acceptance
- API integration tests:
  - Exhaust each class and receive `429` with `Retry-After`.
  - Two tokens of one subject share one budget.
  - A spoofed `X-Forwarded-For` from an untrusted peer does not change the anonymous key.
  - With the ordinary write budget spent, public report intake still succeeds.
  - A new account hits the upload limit before a member does.
  - Counter outage → `503`.
  - Replaying an admitted key after `429` does not double-count its effect.
- Accounts: sign-up without a token is refused; with a test token it succeeds. Check this in a real browser against the local stack.
- Class guard: a test walks the generated OpenAPI and fails if any non-GET Main route resolves to no family.
