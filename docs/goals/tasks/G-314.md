## Outcome

The Manage workspace (G-299, merged) is complete on the web, but moderators
still cannot decide anything end to end. Fix in Main and Access:

1. **Decision basis**: the moderation read returns, to holders of
   `governance.moderate`, the retained evidence digests, private report
   statements, current target heads and the Realm rule basis needed to keep or
   remove reported content (`modules/management-reads/*`).
2. **Reviewers**: Realm role bundles include `review.decide` and
   `publication.adopt` where the role is meant to review, and the owner
   bootstrap grants them, so submissions can be approved, rejected or sent back.
3. **Joining a Realm**: person Agents can give the membership consent
   (`POST /v1/me/membership-consents` returns 403 today, so every roster is
   empty); add a consent mandate at provisioning and an invite-and-accept flow
   (invitation with expiry, accept, decline) instead of pasted consent codes;
   also self-join for public Realms whose settings allow it.
4. **`GET /v1/me/managed-realms`**: the Realms the acting Agent manages, with
   permissions held, open and escalated counts and latest activity.
5. **Public roster**: an Access-owned public member list (members who chose
   to be listed) and featured authors, for the Zone People module (G-310).

Every grant narrow and revocable, with allow and deny tests. Backend only:
do not run web, Storybook or Accounts dev servers; verify with goalctl test.
