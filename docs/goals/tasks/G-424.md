## Outcome

G-404 made the Mods Zone like Modrinth (browse with loader, version and
environment filters; release, dependency and changelog sections). The store
research (`docs/research/reference-stores.md`, P0) found the step that makes
a mod site trustworthy: the reader first says where the mod will run (game →
game version → loader → client or server), and every result then answers for
that environment.

- **Environment first.** The Mods browse and home start with the game,
  version, loader and side selection, remembered per reader (in a cookie, or
  Main if signed in), then categories, required dependencies and
  included/excluded Concepts. Show active conditions and counts. An
  unsupported combination is refused, never silently broadened.
- **The exact compatible release beside Get**, on cards and the mod's
  sections, for the chosen environment: its channel (release, beta or
  alpha), its date, and whether the mod is incompatible or unknown.
  Dependencies in the right direction, for that version.
- **Honest states:** unknown, incompatible, stale and unavailable are distinct,
  especially before a download.
- **Main.** An exact-compatibility read over releases (G-404's migration 815
  keeps every release), bounded and budget-tested. Access migrations 840–844
  are reserved.

Structured release data from Studio comes later (G-410 holds Studio). Use the
query vocabulary (`docs/contracts/queries.md`). Add English and zh-Hans strings
only. Run `task zones:digest -- mods` and say which digest needs approval.

## Verify in a real browser

On the shared stack: choose Minecraft 1.20.1 + Forge and then 1.21.1 +
Fabric in the Mods Zone, and check that every card's release and dependency
line matches. Seed a mod with two loaders and a beta newer than its stable
release if none exists. Check 1440x900 and 390x844 using BrowserOS in your own
tab, or Playwright. Run one web dev server (`task web:dev`) only while
checking, and stop it when done.
