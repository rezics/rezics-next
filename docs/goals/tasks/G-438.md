## Outcome

REZICS is natively multilingual (docs/plan/frontend.md, "Natively
multilingual, not bilingual"): server-sent text is written in the recipient's
locale. An audit (2026-09-28) found Account falls short everywhere it writes
to people:

- `services/account/src/email.ts:64` sends only English or Simplified Chinese
  (`locale === 'zh-Hans' ? 'zh-Hans' : 'en'`) while still stamping
  `<html lang="${locale}">`, so zh-Hant, ja, ko, de, fr and es readers get
  English marked as their language.
- `notification-digest.ts:58-62` is en/zh only, has no plurals ("Replies:
  1"), a hard-coded separator, and the jargon "Realm 邀请"; the digest has no
  request, so a user who never chose a locale always gets English.
- `admin-actions.ts:163,199` sends verification and notice email in the
  **operator's** browser language, not the recipient's `user.locale`.
- **Live bug:** `migrations/045_admin_panel.sql:42` constrains the bulk job
  `locale` to `('en', 'zh-CN')`, while `admin-actions.ts:196-199` inserts
  `'zh-Hans'`, `'ja'` …: every bulk admin job started from a non-English
  operator browser fails the CHECK.
- OAuth consent and connected-apps scope descriptions are typed
  `{ en; 'zh-CN' }` (`scope-descriptions.ts:3,58`, `views.ts:8`).
- `security-activity.ts:15` returns the English "Unknown browser" to users.

Deliver:

1. Every email (verification, email change, security notices, admin notices,
   the notification digest) in all eight UI locales (`en, zh-Hant, zh-Hans,
   ja, ko, de, fr, es`), written as natural product copy in each language
   (not word-for-word), with proper plurals (`Intl.PluralRules` or the
   project's plural helper), locale-correct punctuation, and `lang` matching
   the text actually sent. Keep one copy module per locale so reviewers can
   read each language whole.
2. The recipient's stored locale decides the language; when none is stored,
   use the locale of the account's first sign-up request, never the operator's
   or a hard-coded English.
3. A migration that drops the fixed CHECK (accept any of the eight UI
   locales), with a test that starts a bulk job from a `ja` operator.
4. Consent and connected-app scope descriptions keyed by all eight locales,
   and the Accounts consent pages showing the reader's.
5. Codes instead of English for things the client localizes ("Unknown
   browser").
