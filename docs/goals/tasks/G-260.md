## Outcome

The shared local stack (`task dev` in the main checkout under Aspire) is what
every frontend worker and the demo seed use. Fix what broke or was missing:

1. **Outbox relay.** The AppHost starts Account, Accounts, Main, web and
   Storybook but no Main relay, and `dev.env` has no `MAIN_RELAY_DATABASE_URL`,
   so the outbox is never drained (search projection and downstream consumers
   never update in dev). Add the relay as an Aspire resource (see
   `task main:relay` / `main:relay:init`) with its configuration.
2. **Search index guard.** After an unclean Fuseki stop (Docker was OOM-killed),
   `lucene.uncertain` made every query fail with `search_index_unavailable`
   until a manual `task search:rebuild`. In `prepareDev`, before Aspire starts
   Main, detect `textIndexUncertain` and run the rebuild (or fail loudly with the
   exact command). Add a `stop_grace_period` for Fuseki in `infra/dev/compose.yaml`.
3. **Operator reuse.** When the web-auth fixture is re-registered (for example
   after the issuer moved to the Accounts app on :3004), the bootstrap signs up
   a new operator, but Account's operator bootstrap is one-time (a durable
   marker), so registration fails with "Operator permission required" and
   leaves an empty `web-auth/` directory that blocks retries. Reuse the retired
   fixture's operator (its credentials are in `web-auth.retired-*/private.json`)
   or have the existing owner grant the new one through the operator API; never
   clear the bootstrap marker. Make a failed registration clean up after itself.
4. **Seed task.** Add `task dev:seed` running `bun scripts/dev/seed/cli.ts {{.CLI_ARGS}}`.
5. **Small fixes:** the web command passes `--host` (vinext wants `--hostname`);
   the Storybook `addExecutable` call in `apphost.mts` is not awaited (oxlint);
   add a typecheck project for `scripts/dev` and wire it into `task check`
   (record any new command in `docs/development/toolchain.md`).
6. **Drop the SQL grant hack** (`grantWorkCreation`) only if the baseline
   member permission task (G-255) has merged when you get there; otherwise
   leave it and say so.

Do not restart or reset the shared stack yourself; test with `task dev -- --backend`
in your worktree. In the handoff, give the exact steps the manager should run
on the shared stack.
