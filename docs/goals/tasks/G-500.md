## Outcome

`task gen` and `task gen:check` (reached by `task check`) refuse any change to an accepted
profile's rendered shapes or binding, or to an accepted Facet, and refuse deleting one. A new
`<name>-vN.ts` passes once its entry is appended to `model/accepted-profiles.json`. A worker
cannot bless an in-place edit by rewriting an existing lock entry. The one failing test in
`model/compiler/generate.test.ts` (G-071, historical canonical routes missing `space-realm-v2`)
passes.

Verified defect: the only immutability guard is the P0.3 test for 12 historical profiles
(`generate.test.ts` "P0.3"); the other ~94 profiles in `generated/model/manifest.json` and every
`facet-*.ts` regenerate silently when edited in place, and `gen:check` only compares the working
tree with itself. Grok edited a persisted profile in place in the last Goal; this closes that class.

## What to read

`model/README.md`; `model/compiler/generate.ts` (`buildArtifacts`, `generate`);

## Approach

- Create `model/accepted-profiles.json`: `{ profiles: { <id>: { sha256, binding? } },
  facets: { <id>: <sha256 of the Facet's canonical JSON> } }`, seeded from the committed
  `git show HEAD:generated/model/manifest.json` and HEAD's Facets, never from a working tree.
- In `generate()` (both modes, before writing anything) compare the built artifacts with the lock:
  a locked id whose digest or binding differs, or that no longer exists, throws
  `Accepted profile <id> changed; add a new version instead`. An id missing from the lock throws
  `Unaccepted profile <id>: append {...} to model/accepted-profiles.json`, printing the exact
  entry. `task gen` never writes the lock. Add one sentence to `docs/goals/worker.md#shared-artifacts`
  (new profile = new file plus its appended lock entry).
- In `generate.test.ts`, when git and `main` are available, every entry present in
  `git show $(git merge-base HEAD main):model/accepted-profiles.json` must be unchanged
  (skip with a printed notice otherwise). This is the baseline-rewrite guard in worktrees.
- Add `space-realm-v2` routes to `historicalCanonical` (the expectation is stale, not the code).

## Do not build

No new compiler module, CLI, config option or per-profile evidence file. No digest of TypeBox
output, JSON-LD contexts or TypeScript source text (formatting must stay harmless). Do not
edit any file under `model/definitions/`. No git hooks.

## Acceptance

Mutation tests on a temp copy (the file's existing pattern): editing a constraint in an accepted
profile, changing a shared compiler helper's rendered output, deleting a profile, and changing a
Facet's path each fail `generate`; adding `release-v2.ts` fails until its lock entry is appended,
then passes; whitespace-only edits to a definition pass; rewriting an existing lock entry fails
the merge-base test.
