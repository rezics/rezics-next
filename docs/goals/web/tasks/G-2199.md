## Outcome

The web's unit tests pass in one batch, in any order. In the regression run of 2026-10-13 on `main` three files failed for one cause (D030 in `.temp/ref/regression-web.md`): a `mock.module` replaced a module with a partial object and the replacement stayed for the files that ran after it. `apps/web/tests/showcase-zone-editor.test.tsx` mocks `next/navigation` and `../features/work-page/read.ts` without `notFound` and `readReviewer`; `site-publication-read.test.ts` then fails with `Export named 'readReviewer' not found`, and `catalogue-browse-year.test.ts:188` gets a mocked browse route (`The real browse route did not render its browse view`).

1. The three files pass when run together in the order of the batch, and each alone.
2. Fix the class: every `mock.module` in `apps/web` either spreads the real module's exports under what it replaces or is put back when its file ends. `apps/web/tests/module-mocks.guard.test.ts` fails on a new mock that does neither; say in the handoff how many existing mocks it found and what you did with each.

Do not build: a change to a route, a reader or a component, a new test runner or a change to how the batch is ordered.
