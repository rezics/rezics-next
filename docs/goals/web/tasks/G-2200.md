## Outcome

A Zone home whose shelf module is mounted on a Collection shows the catalogue preview. In the regression run of 2026-10-13 on `main` `apps/web/tests/g-655-zone-site.test.ts:141` fails (D060 in `.temp/ref/regression-web.md`): `loadModules` (`apps/web/features/realm/modules.ts`) returns the shelf with state `failed` where the test expects `ready`, and the paging state is not kept.

1. Find the cause before changing anything: run the test, read the answer the loader got and why it called it a failure. The client follows the API's contract (continuations as the API gives them, no cursor built by arithmetic); if the test's double answers something the API no longer answers, correct the double to the current contract and say which commit changed the contract.
2. The test passes with its assertions on the mounted links, the More link and the paging state unchanged.

`apps/web/features/realm/read.ts` and `routes.tsx` are held by another task: if the cause is there, hand off `partial` naming the change. Do not build: a change under `services/`, a workaround in the client for an API gap (name the gap instead).
