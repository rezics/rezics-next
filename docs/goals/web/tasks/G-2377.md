## Outcome

A Realm owner can give the Realm's own Space its Zone through the existing
API, then open that site's Browse and Works links. The Space address must
carry both Realm and Zone capabilities; attaching an unrelated Zone to a
Realm does not supply this site's capability.

Program's mail:0c47c098-2fb8-40c8-bd81-9a26a9dddd51 reports this gap, and
the manager confirms it: `create-form.tsx` submits `space-realm-v2` with
`capabilities: ['realm']`; production web code has no Zone creation call.
`ZoneSiteRoute` correctly requires the site's Realm capability before its
unmounted browse fallback. Preserve that route behavior.

## Admission and Program reading

`zone/site-pages` is the provisional owning Zone row, not a declaration of
new proof. Its current owner cell is pending and does not record creating a
Zone on a Realm's own Space. Program must confirm or correct this row
attribution and supply the six-persona command/read record at
`tests/qa/fixtures/outcomes/zone/realm-site-creation.json` before admission.
The missing file keeps the durable queue held. G-2376's Manga fixture repair
alone proves no web command flow and does not release this gate.

Record the owner's `POST /v1/zones` with the existing Realm's `space`, its
authority and stable command key, the resulting address at the URL key and
canonical key when different, and the actual production Zone/frame reads.
Retain exact authentication/authority refusals for the other personas, and
any recorded uncertain acknowledgement/retry behavior. Do not infer
permission from Realm membership, moderation or bare platform status.

record first. Implement only the smallest owner-facing action and typed
API adapter for giving an existing Realm its site. Retry a partially
completed creation without creating a second Realm, Zone or Space; retain

details and the acting Person. Refresh address resolution from the API and
derive the site's links from that answer. Use existing UI and all eight

The current claim admits only the new capability files. Before integrating
the action into the existing creation or Realm-management surface, report
the smallest exact OWNER CHANGES so the manager can admit their paths and
order them after current holders. Do not edit an unclaimed file or build
a substitute page to avoid that integration. The completed surface must be

Stories supply the replaying typed client to the production command/reader
boundary; production retains its host/browser client and authority rules.
Test receipt mapping, retained intent/key after an uncertain result, and
address/link mapping against the unchanged records. Preserve visible
identity and refusal assertions. Browse's absent mount returns 404 and

Do not build: API/schema or record changes, automatic Zone provisioning by
changing the Realm creation contract, cross-Space attachment, publication
