## Outcome

D129 passes without weakening the official Zone package import boundary.
When `getV1HubWorksById` is closed for the viewer, an AI Workshop Hub card's
Try action stays absent; when it is open, that action has the same destination
and localized link behavior as today. Non-Hub cards retain their current action.
Official packages use only React, the SDK, Rezics UI, icons and their own files.

Evidence: `apps/web/zones/official/ai-workshop/slots.tsx` imports the web shell's
`OperationGate` across the package boundary and wraps its Hub action with
`operation="getV1HubWorksById"`. `apps/web/tests/zone.test.ts:472` rejects the
import. G-2201 correctly left the gate intact because its claim prohibited SDK
changes. The existing SDK `ZoneSlotProps` supplies a host Link but no viewer gate.

The smallest change carries the existing host viewer decision through the SDK
slot contract. The web shell remains the permission owner. Choose the narrow
contract after reading the current slot host; do not publish backend operation
identifiers as a general Zone permission system. Add meaningful coverage for
open, closed and non-Hub actions and retain the package-boundary assertion.
If an additional host file is needed, claim it before editing; another task's
claim is a handoff, not permission to change it.

Do not build: another permission store or evaluator, a new API operation,
server-side authorization replacement, broader imports, changes to unrelated
cover props, or a test exception for AI Workshop.

## Mechanisms

Consume the existing shell operation gate and extend the existing Zone slot
contract only as needed. No new permission mechanism.

## Checks

`task goal -- check`; targeted stories for changed actions, with screenshots
