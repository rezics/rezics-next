# Search and composition

## Outcome

Readers can discover permitted subjects, refine lists and render configured pages across verticals. Editors can
publish safe page compositions without adding a page implementation for each vertical.

## Done when

- A documented development OpenSearch setup supplies the required analyzer and regression cases.
- Real relays index semantic public projections, publish observable checkpoints and recover/rebuild into a new
  generation with reconciled coverage before switching it into use.
- Search, facets, typeahead, ordering and cursors have typed invalid, preparing, unavailable and restart outcomes.
  Filled pages or explicit readiness replace unproductive chains of empty successful pages.
- Current native disclosure protects results, exclusion, order and displayed fields after privacy changes, even while
  indexing is delayed. Public totals and facets require their own safe aggregate proof.
- Admitted plans cover filter, source and order together, with bounded direct execution or bounded preparation.
- Shared compositions validate against the registry, reject executable input and render each launch vertical from
  configuration. Aggregate page reads keep standalone authorization and declared budgets.
- At render time, unavailable components are skipped and malformed declared slots render empty, preserving supported siblings in document order. Configured-list lookup walks the same declared slots and structural nodes, so malformed or unsupported siblings cannot crash the read or reveal a list outside those slots.
- The real default worker proves convergence, freshness, generation recovery and public rating-sort consumption.

Completion requires the scoped outcomes on main with recorded checks covering the promoted commit. Specified,
implemented, exposed, tested and promoted are separate states; a passing local check alone does not complete a Goal.

## Scope

Includes the public index tier, admitted catalogue plans and preparation, presentation profiles, compositions and
page read aggregation. [Public scope](../scope.md) owns discovery boundaries. Private library facts remain in their
owner's PostgreSQL partition; a public index is never an authorization authority. Web owns interface integration.
Realm browsing advances one explicit page at a time: successful More replaces the visible window (up to 20 rows), pending and failed reads preserve it, and broken cursors offer a first-page restart.
After profile persistence, any activation refusal remains retryable with its original head and idempotency keys; later edits stay in the separate draft.
A native save or activation Retry-After is captured once as an absolute deadline; expiry enables a manual retry of that original intent and never publishes on its own.
A curation editor baseline is admitted only when native active metadata and the returned profile share the canonical profile digest; extra native fields never replace the session reader or the success flag.
Publication success binds to the submitted profile digest; extra native JSON fields are ignored when that digest and a nonnegative head admit.
Recent queries repeat `language` values in preference order; missing selections use the current locale fallback.
Ordered language preference reorder keeps focus on the moved occurrence's surviving move control; removal focuses the next remaining Remove control, otherwise the previous row's Remove, otherwise the language selector.
History management feedback belongs to the mounted bucket and installed session observation; replacing either permanently retires pending feedback, even when the same account returns.
Subject population switches clear `context`, `node` and `cursor`, preserve the localized subject/view and fragment, and add `realm` only for a Realm retry.
Undecodable localized Subject paths stay as plain links to their original address; successfully decoded paths use canonical Subject routing.
Account share metadata uses the largest supported published variant (WebP on ties) via the shared public-image helper; missing or unusable source dimensions fall through to the Subject cover or shared card.
An Integer editor default is the lowest effective value when bounded below, zero when valid, or the highest effective
value when only an upper bound below zero is present.
Keyed-template removal confirmation binds to the reviewed keyed entry and its editor content; replacement, disappearance
or reader/visit retirement retires it, while equivalent rerenders and unrelated sibling changes keep a still-valid
intention.

## Ownership

Owns `services/kernel/{src,db,test}/search/**`, OpenSearch development setup,
`services/kernel/{src,db,test}/presentation/**` and `packages/composition/**`.
[Search](../../services/kernel/src/search/README.md),
[presentation](../../services/kernel/src/presentation/README.md) and
[composition](../../packages/composition/README.md) own behavior.
Coordinate `apps/web/src/features/pages/**` with web as a shared surface; sequence writers. Semantic owns source
projections, definitions and Zone resources; content owns the safe public rating aggregate.
When an open Subject cover changes incarnation, focus returns to its named cover group; ordinary dismissal returns to
the opener. That group uses the displayed-locale catalogue label `subject_cover_group` for the current subject title.

## Dependencies

Requires semantic public projections and current native disclosure, content's rating projection, kernel relays and
checkpoints, Access and the web shell/client. Semantic first adopts shared filtered-list owner contracts; search
then implements admitted plans, preparation and freshness. Performance derives per-plan work budgets. Composition
slots and read descriptors are agreed with web before interface consumption.

## Acceptance

Use [search outcomes](../../specs/search-outcomes.test.ts),
[page outcomes](../../specs/pages-outcomes.test.ts), analyzer and native search/presentation tests, and composition
package checks. The [real-worker harness](../../services/kernel/test/search/README.md) defines process ownership
and default-worker proof; adopting that harness is not evidence that it passed. Cover anonymous, editor, suspended,
hidden and taken-down subjects, privacy reduction during lag, rebuilds and generation changes. Carry the filtering
examples from [feature design](../development/feature-design.md) through native plans. Follow
[verification](../development/verification.md) and the owning check runners for focused checks and growth evidence.

## External conditions

Production search capacity and deployment configuration must satisfy the measured budgets. Native acceptance uses
isolated development services rather than depending on production access.
