## Outcome

G-1120 made `task dev:seed -- --zones-only` read existing official Zones instead
of replaying their creates. On the shared stack it now stops at
`seedRealms: Main /v1/zones/a60fd261-cec7-43ab-a727-f7331d7df8f8/configuration
HTTP 400 invalid_zone_configuration: default Realm is unavailable`: the update
names a default Realm that is not available to the seed's actor on this stack
(the Zone's current default may differ from the plan's, or the planned Realm was
created under another key in an earlier seed). When updating an existing Zone,
keep its current default Realm unless the planned one resolves and is readable;
compare against the Zone's current configuration and send nothing when it
already matches. Apply the same read-then-update rule to the wiki Zone in
`official-wiki-step.ts`, which still replays its create.

## Checks

`task dev:typecheck`; `scripts/dev/seed/zones.test.ts` with a case for an
existing Zone whose default Realm differs from the plan, and the seed plan unit
tests. Read the shared stack's Zone configuration read-only if useful
(`GET /v1/zones/a60fd261-cec7-43ab-a727-f7331d7df8f8` on Main :3001); do not run
seeds against it.
