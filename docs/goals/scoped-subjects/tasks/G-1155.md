## Outcome

`GET /v1/feed` lists a grouped activity under a member's id, not the group
leader's. Voting on that id answers 503 `work_read_unavailable`, because
`FeedStore.vote` requires `group_leader` (`services/main/src/modules/feed/{store,read}.ts`).
A reader who votes on what the feed shows gets an error. G-1146 found this
while seeding and worked around it there.

Make the id the feed lists for an item the id that accepts votes. Either list
the leader, or resolve a member id to its leader when voting. Pick the one
that keeps continuations and idempotency stable, and say why. A vote on an id
that is not in any group still answers as it does today. Integration test: a
grouped item from the list is voted on and the vote counts once.
