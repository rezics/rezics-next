## Outcome

An event or match page must rank its participants by their per-match figures
(decision 53), and a Work or season view lists the subjects rated in it. Today
projections can only be listed by subject (`GET /v1/projections?subject=`); the
only reverse lookup, a statement graph query, refuses on budget. Let
`GET /v1/projections?frame=<coordinate>` (with `subject` optional) list the
projections whose frame contains that coordinate, with a bounded page and
continuation, the same disclosure rules as the subject listing (hidden subjects
and projections never counted or leaked through cursors), and an index that
keeps the cost constant in the number of projections (an Access index on the
identity rows' frames, your migrations). The web already calls it best-effort
from `apps/web/features/entity-page/event-participants.tsx`.

## Checks

`task main:typecheck` through the slot; unit tests; integration tests alone:
listing by frame returns the match's player projections and no others; hidden
subjects are invisible and uncounted; cost does not grow with unrelated
projections. `task ast-grep -- scan`; run `task gen` locally and restore
generated paths.
