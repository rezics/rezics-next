## Outcome

The G-1088 review found rating-owner defects; Global questions also make the
per-Context gate platform-wide. The review is at `.temp/manager/scoped-subjects/g1088-review.md` in the main checkout (read it; finding numbers below refer to it). Fix each finding with the smallest change, add a test that fails before the fix, and say per finding what you did.

- **2 (owner side).** Target aggregate and roll-up responses report evidence
  the owner controls (the components' last admission and the Context revision),
  not the dataset-wide sequence, so an unrelated write does not change them. The
  export task (G-1094) will pin to these fields; name them in your handoff.
- **13.** The repair transaction reads the recovery fence `FOR SHARE`.
- **14.** Reads never take the Context's write gate: drop repair-on-read and add
  the resumable legacy reconstruction job the ratings contract asks for
  (bounded batches, resumable cursor, idempotent).
- **19 and 20.** Rank only members with at least max(50, threshold) ratings;
  publish only the prior's mean and weight, computed from targets the caller may
  see or stated as a Context-level public figure (choose one and document it).
- **23.** Access recomputes the rating slot from principal, Context and target.
- **26.** Target-rating observation seals serialize per (Context, target), not
  per Context: keep the authority scope string `rating:observe:<context>`
  unchanged (relay and Discover rely on it) and change only the gate key used
  for serialization. Prove two raters on different targets of one Global
  Context seal concurrently.
- **21.** Keep the sharded Context totals only if they still serve 19/20 after
  your changes; otherwise remove them in a forward migration.
