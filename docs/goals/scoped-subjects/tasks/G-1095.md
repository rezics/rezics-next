## Outcome

The G-1088 review found that reviewing a rating-question presentation is not a
separate authority and that its read is unbounded. The review is at `.temp/manager/scoped-subjects/g1088-review.md` in the main checkout (read it; finding numbers below refer to it). Fix each finding with the smallest change, add a test that fails before the fix, and say per finding what you did.

- **27.** As for lexicon presentations, drafting and reviewing are separate
  authorities: Realm rating configurers draft; reviewing needs a distinct grant
  that the Realm owner role holds by default (platform administrators for Global
  Contexts). Saving a draft never removes the reviewed text readers see: reads
  keep showing the last reviewed revision until a new one is reviewed.
- **28.** Cap reviewed languages per Context (64) with a typed refusal, and
  bound the read with a LIMIT inside the existing budget.

- **Shared-stack failure (manager evidence, most urgent).** On the shared dev
  stack (large demo graph, Global questions created by the seed), every
  `rating.question-presentation.review` admission is claimed and then expires
  unsealed: Main posts the guarded Fuseki command about every second
  (17 commands in 30 s, each `200 OK` in 150–340 ms, among ~740 queries) and the
  guard never matches, so the seed reports "pending after retries"
  (admission claimed 2026-10-04 21:50:44Z, expired 21:51:14Z). No
  `rating.question-presentation.change` admission ever ran there; the seed
  creates presentations through the review path. QA projects pass, so look for a
  guard condition that holds on a fresh graph but not on a populated one (for
  example a pattern over every Context, a Global-ownership or publicity pattern
  that the seed-created v4 Global Contexts do not satisfy, or a head/expected
  state the create path never wrote). You may read the shared stack read-only
  (Access DB URL in `.temp/stack/rezics-dev/dev.env`, Fuseki on :3030, Main
  logs through `task aspire -- logs main`), but do not write to it. Reproduce in
  a QA project populated like the shared stack, fix the guard, and make a guard
  that cannot match fail fast with a typed refusal instead of retrying to expiry.
