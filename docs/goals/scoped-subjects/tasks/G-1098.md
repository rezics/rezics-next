## Outcome

Three test-only fixes; change no product code.

1. **Race helper.** `tests/qa/support/command-race.ts` (merged by the
   addresses-discovery Goal) asserts one success among racing commands, where
   each loser answers 409, or 202 `reconciling` that settles to 409 when retried
   with the same body and key. Adopt it where these files assert a
   `[20x, 409]` race on routes that declare `202: pendingOperation`:
   g-987-realm-rating-authority (≈263), rating-global-synthesis (≈168),
   rating-question-presentation (≈488, ≈516), rating-release-target (≈255),
   support/rating-aggregate (≈165). A loaded host can legitimately answer 202
   to a loser; that is how such tests flaked.
2. **Shared lexicon definitions.** `scoped-subjects-acceptance` installs the
   `in-continuity` (and other identity-link) definitions under its own object
   prefix, so a later file in the same project resolves the key to revision bytes
   it cannot read ("committed revision bytes are unavailable"; seen when
   projection-page runs after it). Make the loader resolve existing definitions
   by key and reuse them, installing only what is missing, as other seeds do.
3. **RATE06 timing.** `services/main/tests/rating-global.test.ts` → "RATE06: stale,
   unsealed, damaged or fenced evidence makes the synthesis unavailable, never
   smaller" took 7.4 s on a loaded host against bun's 5 s default while its
   siblings take well under a second. Find what work it does beyond them and
   reduce it (preferred) or give it an explicit timeout sized to that work.
