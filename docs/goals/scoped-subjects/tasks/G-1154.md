## Outcome

On the shared dev stack, discovery has stopped refreshing. Since about 16:30
CST, after a Docker crash and restart, `/health/discovery-ready` shows the
projection at sequence 7660 while the source is past 9700. Every row in
`access.discovery_refresh` has `last_outcome = 'retry'`. Main logs
`worker_run_deferred` for `main.discovery.refresh` thousands of times, always
with "Access owner is unavailable".

1. **Cause hidden.** `normalize()` in
   `services/main/src/modules/recommendation/derived-generation.ts` turns every
   unexpected error into `RecommendationUnavailable('Access owner is
   unavailable')` and drops the original, so nobody can see why. Keep the cause:
   use `{ cause }` and log the original code and message once per deferral.
   Look for the same swallowing pattern elsewhere in the module, for example
   `ranking.ts`, and fix it the same way.
2. **Real failure.** With the cause visible, find out why refresh fails on this
   stack. It may be state a crash left half-written (a generation, a lease or a
   basis), or a schema mismatch after the recent migrations (Access 1105 and
   1110, Content 771). You may read the shared stack's databases
   (`docker exec rezics-dev-postgres-1 psql -U postgres -d access`), but do not
   hand-edit rows.
   - If a crash can leave state that blocks refresh for good, recovery must
     handle it in code, and an integration test must reproduce it.
   - If it is a schema or code defect, fix it.
   The shared stack must catch up by itself once your code is on main. Main
   hot-reloads from the main checkout.

## Checks

`task main:typecheck` through the slot; unit tests; the discovery refresh
integration files alone. After merge, the manager confirms that
`/health/discovery-ready` on the shared stack reaches `stale: false`.
