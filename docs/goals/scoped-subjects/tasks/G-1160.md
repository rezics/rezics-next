## Outcome

G-1159 (a40f7052a) added `services/main/src/modules/target/disclosed-references.ts`
and an optional `disclose` argument on `renderRelation`,
`readExactDefinition`, `readDefinitionByKey`, `readSemanticRevision` and
`readSemanticCurrent`. Some callers still filter role members and
participants through the semantic reader alone, so they drop public Concept
members:
- `services/main/src/modules/relation/traversal.ts` (`readResourceRelations`
  and its definition reads)
- `services/main/src/routes/resource-relations.ts`
- `services/main/src/routes/relations.ts`
- `services/main/src/modules/export/readers.ts`

Wire each one to `referenceDisclosure(...)` from the caller's authority.
Then make the argument **required** on every one of those functions, so a new
caller cannot forget it. A caller that really has no authority, such as a
system reader, passes an explicit "semantic reader only" disclosure, with a
comment saying why. Extend `semantic-member-disclosure.test.ts` with the
resource relations read and the relation read: a public Concept member is
visible and a hidden one is absent.
