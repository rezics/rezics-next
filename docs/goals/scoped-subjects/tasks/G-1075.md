## Outcome

`acquireHeavy` in `scripts/goal/goalctl.ts` lets every waiter poll the lock
directory every 10 s, so a manager that starts its next heavy run the moment
its previous one exits keeps winning; on 2026-10-04 a worker waited 30+ minutes
behind its own manager's back-to-back batches. Make the lock first come, first
served across all Goals:

- A waiter writes a ticket (its pid, Goal, command and an arrival time that
  orders tickets) in a queue directory next to the lock before it polls.
- It may take the lock only when the lock is free and its ticket is the oldest
  ticket whose pid is still alive; tickets of dead pids are removed by whoever
  sees them. It removes its own ticket when it takes the lock, on timeout and on
  exit (normal, error or signal).
- `status` shows the holder as today plus the number of waiting tickets.

Keep the six-hour deadline, the existing lock directory and `info.json`, and
the order heavy lock → QA slot. No new files outside the claim, no daemons.

## Checks

`bun test scripts/goal/goalctl.test.ts` with new tests: two waiters are served
in arrival order even when the earlier one polls later; a dead waiter's ticket
does not block; a waiter that times out leaves no ticket. Keep every existing
test passing.
