## Outcome

Make target ratings honest at any population size, per
[decision 53](../../../contracts/ratings.md#scoped-targets-and-roll-ups).

1. **Additive components.** Today `rating/target-aggregate.ts` recomputes
   histogram, sum and count from at most 100 sealed heads, so a widely rated
   target becomes unavailable. Maintain sum, count and a 1–10 histogram per
   (RatingContext, target) in Access SQL, updated in the same admission seal
   that advances `access.target_rating_head` (subtract the predecessor value,
   add the new one; withdrawal subtracts only). Reads use the components and the
   existing inventory witnesses for completeness, so the 100-slot bound goes
   away for target aggregates. Backfill existing heads in the migration. Keep
   Realm standing, release and Global paths as they are unless the same change
   is trivially shared.
2. **Display thresholds.** A target aggregate response always carries count and
   histogram; it carries a mean only when count reaches the RatingContext's
   threshold, and otherwise says the mean is withheld below the threshold. The
   default is 5 ratings, and 10 for the `projection` grain. Add
   `realm-target-rating-context-v3` (and the observation v3 that references it)
   with an optional display threshold and with `rv:Projection` in the grain list,
   leaving v1 and v2 untouched; creating a Context with the `projection` grain
   is admitted by a later task once projections resolve.
3. **Named roll-ups and rankings.** `POST /v1/rating-rollups` takes one
   RatingContext, up to 200 member targets and a formula, `pooled` (sum of sums
   over sum of counts) or `mean-of-means` (mean of members' means, counting only
   members at or above threshold), and returns the formula used, the value,
   member count, how many members met the threshold (coverage) and each member's
   components. The value is withheld when coverage is below half. With
   `rank: true` it also orders members by a Bayesian weighted rating whose prior
   mean and weight come from that RatingContext's components and are returned,
   listing only members with at least 50 ratings. Nothing is stored; members the
   caller cannot read are reported as unavailable, never silently dropped.

Never combine different RatingContexts, questions, scales or populations into
one number; never compute from stored means. Outbox: if your change emits a new
rating event type or action, stop and tell the manager before adding it — the
addresses-discovery Goal classifies rating events in
`services/main/src/modules/discovery/effects.ts` (an unclassified action forces
a full Discover rebuild); existing actions must keep their meaning so the
`tests/qa/integration/g-1063*` cost tests stay green.

Do not build: persisted metric definitions, a metric DSL, caches, Realm
standing or Global rewrites, cross-Context synthesis or UI.
