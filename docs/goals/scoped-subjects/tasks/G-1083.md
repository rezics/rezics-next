## Outcome

`POST /v1/rating-rollups` (`services/main/src/modules/rating/rollup-read.ts`)
validates members' readability but not whether the RatingContext accepts them.
Since G-1074, a v4 target Context declares accepted subject types and frame
dimensions (`services/main/src/modules/rating/acceptance.ts`:
`readContextAcceptance`, `ratingAcceptanceTarget`, `contextAccepts`). Read the
Context's acceptance once per request and report each member the Context does
not accept as `not-accepted` (distinct from `unavailable`), excluded from the
value, coverage denominator and ranking, exactly as unavailable members are.
v1–v3 Contexts accept everything their grain admits, as today. Keep the existing
member bound and query budget; add no new route or storage.

## Checks

`task main:typecheck` through the slot; unit tests for the member classification;
`tests/qa/integration/rating-rollups.test.ts` run alone with a new case: a v4
Character question given a Work member reports it `not-accepted` and computes
the value from the accepted members only. `task ast-grep -- scan`.
