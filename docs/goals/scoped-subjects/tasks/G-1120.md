## Outcome

After an official Zone package's source changed (franchise-wiki on 2026-10-05),
`task dev:seed -- --zones-only` on the shared stack stopped at
`seedRealms: Main /v1/zones HTTP 409 idempotency_conflict`: the seed reuses its
idempotency key for the Zone create while the request now differs. The
re-approval path `task dev:seed -- --themes-only --packages=<slug>` works.
Make `--zones-only` idempotent on a persistent stack: when a Zone already exists,
read it and apply changes (approval of the new package digest, presentation)
through the update commands instead of re-sending the create, so a rerun after
any package change succeeds and a rerun with no change writes nothing.

## Checks

`task dev:typecheck`; the seed plan unit tests (`scripts/dev/seed/official-plan.test.ts`,
`tests/qa/unit/dev-seed-plan.test.ts`). Do not run seeds against the shared
stack; the manager will.
