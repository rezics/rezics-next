## Outcome

Studio addresses now come from `studioHref`: the Agent's sid, or its handle when
it has one. `/en/studio` opens the session Agent's Studio at
`/en/studio/@<sid>`. `apps/web/tests/studio.e2e.ts` STUDIO01 (line 94) still
expects `/en/studio/@agent-<uuid>`. `apps/web/tests/authenticated-create.e2e.ts`
also opens Studio at `@agent-<uuid>` and clicks the text "A story", but the
chooser shows registry labels. See QA `20261005t132029-ba1acf` (G-1161).

Have both journeys build the expected address the way the app does: import
`studioHref` or `uuidToSid` instead of hard-coding the form. Choose kinds
by role and their current registry label, as G-1161 did for Book. If a later
step fails for a product reason, report it with the QA run id instead of
working around it.
