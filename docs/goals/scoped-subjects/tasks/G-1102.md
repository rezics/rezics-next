## Outcome

G-1100 found that when the dataset's model generation differs from the one Main
builds, model-generation initialization can never match, and rating-question
presentation reviews retried until their admissions expired. It fixed that
command with a sealed `generation_changed` refusal. The shared dispatcher in
`services/main/src/modules/semantic/admitted.ts` can still swallow
`ModelGenerationChanged` for semantic, relation and lexicon commands and answer
pending. Fix the class: every admitted command whose model-generation guard
cannot match because the generation changed seals a terminal, typed refusal
(the same `generation_changed` outcome), replays it for the same key, and never
retries to expiry. A genuinely concurrent winner keeps its current behaviour.

## Checks

`task main:typecheck` through the slot; unit tests; an integration test that
puts a dataset on another model generation and shows a semantic change, a
relation change and a lexicon presentation change each answer the typed refusal
promptly and replay it, and succeed after `dataset:bootstrap-model` style
alignment; the existing semantic, relation, lexicon and presentation
integration files still pass. `task ast-grep -- scan`.
