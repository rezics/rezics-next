## Outcome

On the shared stack, which was seeded by earlier revisions, `task dev:seed`
stops at `seedFranchises`:

```
/v1/works/01a0f538-…/releases/5e274731-… HTTP 400 invalid_release
"A correction of a closed release cites evidence"
```

The full log is `/home/edge/projects/rezics/rezics-next/.temp/manager/scoped-subjects/full-seed.log`.
Main's rule is in `services/main/src/modules/release/schema.ts`: a closed
release changes only as a correction with evidence. G-1122 also reported that
`seedLnVnZones` and `seedRealms` (and `dev:seed --zones-only`) replay Space
and Realm creates and answer 409 `idempotency_conflict`. G-1122 noted that
`ln-vn-zones-step.ts` and `scripts/ops/bootstrap/execute.ts` still write the
Space receipt's Realm on every Zone update.

Make every step converge on a long-lived stack, the way a real API client
would:

- Read the current public state first. Send no write when the facts already
  match, comparing as `releaseChanged` does.
- When the plan deliberately differs from a closed release, send a correction
  with evidence. Never weaken Main's rule.
- When a create was recorded under an earlier body, find the existing resource
  through its public read and adopt it, as the other steps do with receipt
  replays and lookups. Do not reuse a key with a new body.
- `scripts/ops/bootstrap/execute.ts` is ops code. Leave it, and name the same
  issue there under PROPOSED TASKS if it applies.

## Checks
