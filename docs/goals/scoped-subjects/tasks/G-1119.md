## Outcome

Manager screenshot review of the seeded Misaka Mikoto page on the shared stack
(`http://localhost:3000/en/e/01a10a63-9c19-7576-ac22-0bb047c1dc3b`, signed out,
desktop) found three defects:

1. **Statements without labels.** Two Statement rows show only a value
   ("A Certain Scientific Railgun", "Misaka Mikoto") with an empty label column.
   The name row repeats the page header and should not appear among Statements;
   any other row whose predicate has no label in the reader's language shows the
   predicate's fallback label from its definition (never a raw key, never blank),
   or is grouped under a clearly labelled "Other facts" heading.
2. **Roles detached from their Works.** Relations show "Appears in: A Certain
   Magical Index, A Certain Scientific Railgun" and, separately, chips
   "Role Supporting character", "Role Lead character", so a reader cannot tell
   which role belongs to which Work. An n-ary occurrence's participants render
   together: each appearance row reads as the Work with its role (and credited
   name when present), e.g. "A Certain Magical Index · Supporting character".
3. **Follow stretches the full column** on desktop. The Follow control keeps its
   compact size beside the header actions at every width.

Check the same three on a Person, a unit and a title page. Keep the honest-score
rules and identity sections as they are.
