## Outcome

Every Character page shows "Couldn't load relationships" because
`GET /v1/me/follow-state?kind=<type IRI>` answers 400 for a Character (found by
G-1097; it predates that work). The capability model says a Follow targets any
admitted resource or saved view ([platform thesis](../../../product/platform-thesis.md#capabilities),
[interactions](../../../contracts/community-interactions.md#follow-join-and-notification)).
Make follow, unfollow and follow state work for every admitted resource type,
including Characters, Persons, units, titles and projections, with the same
notification-level choices, and make the web relationship control ask with what
the API accepts. Keep Space join and membership semantics as they are.

## Checks

`task main:typecheck` and `task web:typecheck` through the slot; unit tests;
integration tests alone: follow, read state and unfollow a Character and a
projection; existing follow and notification integration files still pass; the
relationship control stories in their states. `task ast-grep -- scan`.
