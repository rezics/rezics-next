## Outcome

`AccessAdmissionRegistry.canReadSemanticResource` (and any other public-
disclosure path in `services/main/src/modules/access/admission.ts`) answers
"not public" when `configureBaseline(fuseki)` was never called. A composition
that forgets the call therefore turns every public relation definition and
semantic resource into a hidden reference. The writer gets a 422
`unavailable_reference` that is hard to trace. G-1173 found this in
`tests/qa/fixtures/author-credit.ts`. `tests/qa/integration/context-fixture.ts`
has the same gap, which makes `search-grouped-native.test.ts` fail alone
(QA `20261005t141656-6952ea`). There are about 148 registry constructions and
38 `configureBaseline` calls.

Fix the class:
- A public-disclosure read on a registry without a baseline graph throws a
  clear configuration error and does not answer "not public". Construction
  stays as it is, so the many unit stubs that never reach this path are
  unaffected.
- Every fixture and composition that does reach the path calls
  `configureBaseline`, as production does. Find them by running the
  affected tests. Change test fixtures and support files only.
- Production composition already configures the baseline. Confirm it with a
  unit test.
