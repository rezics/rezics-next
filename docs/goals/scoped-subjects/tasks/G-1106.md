## Outcome

Two gaps in `task dev:refresh` (G-1101) seen on 2026-10-05:

1. After the host OOM-killed Docker Desktop and Docker was restarted, the
   AppHost still listed `main-relay` as running but Aspire's DCP no longer had its
   executable: `aspire resource main-relay restart` answered NotFound (CLI exit
   16), and `dev:refresh`'s stop-writers step failed with exit 17. The manager had
   to `task dev:stop`, check for orphans and start `task dev` in tmux
   `rezics-dev`. Make the refresh detect a resource whose stop, restart or wait
   fails with NotFound (or a dead process behind a "running" resource), stop with
   a clear instruction to restart the AppHost the documented way (or perform that
   restart itself when no other checkout's processes would be affected), and
   never leave the stack half-stopped.
2. Official Zone packages (for example `franchise-wiki`) fall back on the shared
   web after their source changes, until someone runs
   `task dev:seed -- --zones-only` to approve the new digest. Make the refresh
   compare each installed official Zone's digest (`task zones:digest`) with its
   approval and re-approve changed ones through the same path the seed uses.

Keep the dry-run accurate for both (say which resources would need an AppHost
restart and which Zones would be re-approved).

## Checks

`task dev:typecheck`; unit tests for both new plan branches; the dry-run against
the shared stack. Do not run the full refresh; the manager does.
