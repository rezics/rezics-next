## Outcome

An independent review (G-1088) found that projections can mean less than
[decision 51](../../../contracts/semantic-model.md#identities-variants-and-projections)
says. The review is at `.temp/manager/scoped-subjects/g1088-review.md` in the main checkout (read it; finding numbers below refer to it). Fix each finding with the smallest change, add a test that fails before the fix, and say per finding what you did.

- **6, slots.** Keep the four coordinate kinds (they are persisted in v4
  acceptance values) but group them into slots: Work or Structure position is
  one slot, release or realization another, as the decision lists them. A frame
  holds at most one coordinate per slot; get-or-create normalizes a Work implied
  by a given position (drop it) and refuses coordinates that disagree (a position
  of another Work, a release of another Work). One "X in F" then has one key.
- **9, coverage.** A position frame is covered by applicability naming any
  Structure ancestor (bounded `rv:parent` chain) or its Work; a release or
  realization frame by its Work; a Work by its narrative continuities.
- **1 and 15, one home for facts.** Statement writes validate applicability
  dimensions (unknown IRIs and projection IRIs refused with typed errors);
  normalizing a Statement written on a projection refuses caller applicability
  in a slot the frame already fills unless it is the same coordinate.
- **10, frame reads.** Filter disclosure and reading position before any row
  cap, and start the in-continuity pattern from the Work participant.
- **18 and 29.** Keep one implementation of coverage (the SPARQL pattern) and
  test it on a real graph; delete the JS `covers`/`specificity` if only tests use
  them. Declare the specificity ordering's cost in the subject-read and
  traversal cost contracts and profile it on a subject with many Statements.

Update decision 51's wording only if the slot rule needs one sentence there.
