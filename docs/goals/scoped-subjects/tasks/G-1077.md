## Outcome

Build, as a self-contained feature in `apps/web/features/scoped-rating/`, the
components people use to rate, review and discuss "this character in this
episode" or "this player on this map", see honest per-frame numbers, and read a
franchise in the continuity they choose ([decisions 51–53](../../../contracts/semantic-model.md#identities-variants-and-projections)).
A later task wires them into the entity and wiki pages (G-1072 holds
`features/entity-page/**` until it merges), so this task does not edit those
pages. On `main`: `POST /v1/projections` (get-or-create) and
`GET /v1/projections?subject=`; `GET /v1/resources/{projection}/page`; `frame`
filters on resource statements and relations; projection-grain and Global
target questions with accepted subject types and frame dimensions and localized
question presentations; target aggregates with display thresholds;
`POST /v1/rating-rollups` with `not-accepted` members.

1. **Typed API adapters** for those endpoints with the existing idempotency and
   revision-head pattern (`features/catalogue/reader-store.ts` is the model) and
   retry on conflict.
2. **Rate in a frame**: a frame picker in a `Sheet` limited to types with a frame
   dimension (episode, chapter, route, match, map, continuity, game version),
   then get-or-create the projection and show the questions that accept it
   (question text from the localized presentation), with rating, review and
   discussion entry points.
3. **Projection header**: subject avatar, name and link with the frames as
   localized chips formatted from the summary's structured parts.
4. **Per-frame numbers**: a subject's projections list with each one's own
   figures; a per-episode list with a roll-up labelled by its formula ("pooled"
   or "average of episodes") and coverage; a ranking of an event's participants
   by the published weighted rating with eligibility explained. Use G-1072's
   honest-score rules: "8/10 · 7 ratings" with units, "No ratings yet",
   "N more ratings will reveal the average", no zero histograms, no internal
   model words in the UI.
5. **Continuity switch**: a labelled control, off by default, that sets a
   narrative-continuity or Work `frame`, persisted across routes like the
   reading position (`features/wiki/position*`), with an optional default
   supplied by the host page.
6. Eight UI locales; stories for each component in empty, spoiler-hidden,
   below-threshold and populated states at phone and desktop widths, using
   in-memory adapters like `work-page/fixtures.ts`.

Reuse `packages/ui` primitives (`Sheet`, `EntityPicker`, `Tabs`, `Badge`) and
the rating distribution components. Do not change APIs; list any gap under
OWNER CHANGES.
