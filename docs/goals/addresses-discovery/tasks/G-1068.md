## Outcome

`tests/qa/integration/g-1033-discovery-refresh.test.ts` fails alone on main
since G-1063 (merge `189cce0d1`): line 80 expects
`'basis-unavailable'` for a deleted or ineligible Realm basis and the worker's
`tick()` returns `'activated'`. The manager's full pass shows it alone and in
its shard (read-only artifacts:
`/home/edge/projects/rezics/rezics-next/.temp/verify/.artifacts/qa/20261004t133508-ed9587/logs/integration-r1.log`).

The test makes one scope due by moving its `due_at` an hour back, then calls
`tick()` and expects that scope to be the one claimed. G-1063 added scheduling
lanes (`access.discovery_refresh.priority`, index `discovery_refresh_lane`,
migration 1044), so the claim now orders by priority before `due_at`, and a
higher-priority scope (for example the global or rating scope) is claimed
first and activated.

First decide which side is wrong, with evidence from
`services/main/src/modules/discovery/refresh-store.ts` and `refresh.ts`:

- If priority lanes are intended (readers' scopes ahead of idle Realm scopes),
  make the test drive the scope it means to test without weakening its
  assertions: settle the other due scopes first, or make the target scope
  claimable through the same public store behaviour the worker uses. Keep
  every expected outcome (`basis-unavailable`, `basis-invalid`, `inactive`)
  and the bounded Fuseki-call assertions.
- If a deleted or ineligible basis should never be outranked into
  starvation, or anything else in the product looks wrong, stop and report it
  with evidence; do not change product code (it is another task's claim).

Do not add new `G-NNN` mentions or new `g-NNN` files; the existing test names
stay as they are.
