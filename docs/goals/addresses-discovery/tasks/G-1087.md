## Outcome

G-1086 (`c81956649`) found that `g-630-zone-routes` asserted exactly
`[200, 409]` for two racing identical commands, while the route may answer
the documented `pendingOperation` (202, `status: 'reconciling'`, retry
allowed after `retry.afterMs`; `services/main/src/api-contract.ts:81`) when
the loser arrives during the winner's admission. On a loaded host the 202
showed up in three of five runs. About 80 integration assertions share the
pattern: `rg "toEqual\(\[20[01], 409\]\)" tests/qa/integration`.

Fix the class once:

1. Add `tests/qa/support/command-race.ts`. It takes the racing responses
   and a way to resend a loser with the same body and idempotency key. It
   asserts exactly one success with the expected status; every other
   response is 409, or a 202 reconciling answer that is retried after
   `afterMs` until it settles to 409. A second success, any other status, or
   a reconciling answer that never settles within a bounded number of tries
   fails the test with the evidence. Base it on G-1086's change in
   `g-630-zone-routes.test.ts` and move that file onto the helper. Give it a
   unit test with stubbed responses.
2. Move each racing assertion whose route declares `202: pendingOperation`
   in its OpenAPI or route schema onto the helper. Leave the assertions on
   routes that cannot answer 202, and list them in the handoff with the
   reason.
3. Do not touch the scoped-subjects Goal's tests (`rating-*`,
   `projection*`, `scoped-*`, `identity-*`, `relation*`, `g-935*`,
   `g-987*`) or the post-layers Goal's (`post-*`). List the matching
   assertions in them in the handoff so their managers can adopt the helper.

Keep every other assertion unchanged; this is a test-only change. Do not add
new `G-NNN` mentions or `g-NNN` files.

## Checks

The host is memory-constrained, so run heavy QA one batch at a time through
`bun scripts/goal/goalctl.ts test --heavy …`. Run the helper's unit test and
every changed integration file at least once; run three of the changed files
five times. Scan changed files with `task ast-grep -- scan`.
