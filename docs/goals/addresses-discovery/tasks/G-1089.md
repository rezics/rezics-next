## Outcome

G-1087 moved racing-command assertions onto `tests/qa/support/command-race.ts`,
which accepts one success and otherwise 409 (or a 202 that settles to 409).
In a shared project on merged main (`77fb9ff91`, run
`/home/edge/projects/rezics/rezics-next/.temp/verify/.artifacts/qa/20261004t213242-6e8d22`,
`logs/integration-1.log`), `g-629-entity-page.test.ts:274` raced two semantic
changes. The winner answered 200, and the loser answered on its first attempt
`422 {"code":"reserved_owner","title":"Semantic change is not admitted"}`. The
same file passes alone with the loser answering 409.

So the status of a losing racer depends on timing. When the loser validates
after the winner commits, ownership checks in
`services/main/src/modules/semantic/change.ts`
(`fail('reserved-owner', …)` at ~338 and ~405: predicate or semantic type
"already belongs to another component") reject it as permanently invalid. If
it had validated a moment earlier, the expected-head compare-and-swap would
have answered 409. A client that only lost a race must get the conflict and the
current head, not a 422 it cannot retry.

Make the outcome independent of timing. When the reserving component or claim
is newer than the request's `expectedHead`, so that the request was valid at
the head it named, answer 409 with `currentHead`. Keep 422 `reserved_owner`
for requests that conflict with ownership already present at their expected
head. Check the same pattern in the other `reserved-owner` checks in the
module. Do not change `relation/**`, which is the scoped-subjects Goal's area;
if the same flaw is there, list it in the handoff.

Prove it with a deterministic test that forces the winner to commit between
the loser's admission and its validation, through the module's real seams and
without sleeping. `g-629-entity-page` must pass alone and after ten other files
(use `--heavy`; the host is memory-constrained, so run one at a time). Do not
add new `G-NNN` mentions or `g-NNN` files.
