## Design note

Define a board as a Realm-scoped discussion grouping using existing conversation identity, placement, disclosure and authority owners. Settle whether placement configuration can express the resource before adding an owner. Navigation needs stable grouping identity and bounded collection/continuation reads independent of total Realm population. No separate ranking, membership, permission or content engine.

Visitor and stranger traverse only public groups/conversations. Member navigation adds only current scoped admission with participation-history fences. Owner manages groups under Realm authority without gaining authorship or private content access. Moderator acts within declared group/Realm jurisdiction. Operator needs a corresponding bounded mandate; status alone adds no bypass. Hidden group/detail/continuation answers must disclose no inaccessible content; grouping preserves original rights and author credit.

Before implementation specify actual collection/detail, placement-management and traversal operations and all six persona answers, including empty/removed groups and stable cursor scope. An independent outcome task runs them on real composition; unsupported operations remain demonstrated contract gaps, never substituted by header controls. Program reads this design before mechanism code. If it needs a wider engine, return a narrowed contract decision.

## Decision — 2026-10-13, read by the program

Read by program: 2026-10-13. The subject stays in the first public scope, and it is not a mechanism. `docs/architecture/target-architecture.md` settles what a board is (the vocabulary table's `board` / `section` line, and "Realm 在共享分類能力上的管理與版面"): a board is a tag, a Concept or an entity reference from the classification the Realm selected, applied to a Realm placement; a placement carries many and at most one primary; a board's content is the filtered read of what the Realm has placed; managing it extends the Realm's existing management actions with a Concept target scope, with no separate permission list. A board is therefore no resource of its own: no owner, no table, no family of operations. The API already has `GET /v1/realms/{realm}/classification-context`, the classification vocabulary, proposition and resolution operations, `POST /v1/realm-reply-placements`, `GET /v1/facets` and the Realm's discussion reads. This brief is recut as the row's outcome task on those operations. A design note returns only for a cell that no parameter or target scope on an existing operation can meet, and it names that cell.

## Outcome

Replace the six placeholder cells of `realm/boards` ("needs a declared board ...") with demonstrated answers. Find the operations with `task operation -- <word>` and try them with `task goal -- persona` before writing a test. The matrix, as each of the six personas:

1. **The Realm's boards are listed:** the Concepts of the Realm's classification context that it uses as boards, in a bounded read.
2. **One board is read:** the Realm's discussions that carry that Concept, in the Realm's order, with a continuation that stays inside the board and the caller's view; a conversation the caller may not read is absent and not counted.
3. **A conversation is put on a board, taken off it and given its primary board** by its author where the Realm allows, by the owner, and by a moderator inside the jurisdiction their role names; a stranger, a visitor and a member who is not the author are refused, and an operator acts only under a mandate that names it.
4. **An empty board and a retired Concept** answer as a list that is empty and a board that is gone, not as an error of the server.

A cell whose requests all answer as the row requires is `proved`. A request the API cannot answer, or answers wrongly, makes the cell `pending` with the request, the answer and the expected answer in its note; say in the handoff the smallest addition that would make each pass (a filter parameter on an existing read, a target scope on an existing grant). No product code, and no cell left on a note that names no request.
