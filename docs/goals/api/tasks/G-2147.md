## Design note

Define a board as a Realm-scoped discussion grouping using existing conversation identity, placement, disclosure and authority owners. Settle whether placement configuration can express the resource before adding an owner. Navigation needs stable grouping identity and bounded collection/continuation reads independent of total Realm population. No separate ranking, membership, permission or content engine.

Visitor and stranger traverse only public groups/conversations. Member navigation adds only current scoped admission with participation-history fences. Owner manages groups under Realm authority without gaining authorship or private content access. Moderator acts within declared group/Realm jurisdiction. Operator needs a corresponding bounded mandate; status alone adds no bypass. Hidden group/detail/continuation answers must disclose no inaccessible content; grouping preserves original rights and author credit.

Before implementation specify actual collection/detail, placement-management and traversal operations and all six persona answers, including empty/removed groups and stable cursor scope. An independent outcome task runs them on real composition; unsupported operations remain demonstrated contract gaps, never substituted by header controls. Program reads this design before mechanism code. If it needs a wider engine, return a narrowed contract decision.
