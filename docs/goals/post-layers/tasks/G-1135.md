## Outcome

`scripts/static/anti-silo.test.ts` (baseline) fails on main only for Post
identification: `services/main/src/modules/post/identification-schema.ts` (1) and
`identification.ts` (3) name `https://schema.org/Book` directly. The engine
dispatches by declared configuration, not literals: the Book composition
profile already declares its owner type (`structure/profiles.ts`,
`ownerType`), and identification places the Post through exactly that profile.

Take the required Work type from the Book composition profile's `ownerType`
(the placing Book's check, the new Work's semantic type, the existing-Work
check and the request schema), so no Post module names the type. The request
schema may accept the profile's owner type rather than a literal; keep the
served contract value the same. Do not change the profile or add a registry.
`anti-silo.test.ts` must pass without a new baseline entry.

alone, `task main:typecheck`, `task ast-grep -- scan`.
