to released data, personas, every list surface and native acceptance. It is not a new policy, release or completion
claim. [Filtered lists](../filtered-lists.md), [definitions](../../packages/definitions/README.md),

remains: immutable definitions, third vertical, referenced candidates, Context acceptance/adoption, ranks, competing
claims and disputes, one partition/revision per command, current Access, batched related labels, asynchronous incoming

## Evidence stages

| Stage      | Required evidence                                                                                                                                                                                     |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Declared   | Named user job, personas, released population, six explicit surface cells and owner scenario.                                                                                                         |
| Bound      | Actual native suite invokes the production boundary with real Auth/Access. A pending suite name is not bound.                                                                                         |
| Exposed    | Actual mounted API and production default composition admit the job and its meaningful data. A DTO/helper/schema does not establish exposure.                                                         |
| API-passed | Recorded native command returns useful expected outcomes with every named scenario executed; missing-driver verification, unsupported required requests, fake readiness and absent data do not count. |
| Promoted   | Evidence covers the promoted main commit and required root gate, with collaborators complete. A local pass alone does not promote a capability.                                                       |

All capabilities below are declared. “Partial” in a stage names evidence for a slice, never promotion of the full
capability. No full user job is marked API-passed or promoted by this inventory. Existing native cases are retained;
the absence of recorded execution evidence here does not assert they failed. Commands below are acceptance bindings,
not a log of commands executed for this document. Each starts the actual kernel check runner. Pending native
scenarios have no executable binding yet and must not be replaced by a green missing-driver verifier.

## Shared released population and matrix rules

Use version **1** of [the one native fixture contract](../../packages/definitions/src/released-discovery-fixtures.md),
export `createReleasedDiscoveryFixture` from `services/kernel/test/support/released-discovery.ts`. Actual created IDs,
acceptance/adoption heads and the HTTP/bundled release pin are authoritative. Controlled titles/numbers are test cases,
not claims about source coverage. Missing producer/schema groups remain exact prerequisites in that contract.

Every applicable cell includes anonymous public reader, editor with the same public projection, owner Alice,
other owner Bob, acceptor/steward as needed, outsider, unscoped, delegated, valid suspended, revoked/invalid and
hidden-resource controls. Public output cannot borrow a curator/editor's private authority. Bans beat independent
read grants. Valid suspended bearer is 403 account_suspended everywhere; required missing/invalid/revoked credentials
are distinct401. Existing frozen suites with older expectations require their owner's reconciliation.

Each applicable list cell additionally needs unknown evidence (including NOT), hidden source/target/withheld harem,
source revocation/consent withdrawal, original plus terminal eligibility, duplicates/aliases, deep and sparse paging,
current cursor reauthorization and useful full/final pages or explicit preparation. Two statements may not combine
qualifiers to create a match. Public aggregate omission must not conceal membership/exclusion/order leaks.
Native start/final privacy observation includes reductions repaired and ACKed during the request. Foreign dependency
repair and source/index incarnation coverage remain actual producer prerequisites; current index data is never a grant.

The six cells are always catalogue, curated, Everything **without state**, own state, mounted Zone and configured
TypeList. Subject detail means factual projection, not arbitrary filtering of a detail object. A TypeList is the list
consumer. No cell silently defers the whole capability. User-saved personal dynamic queries and holding-derived
platform joins remain out of first scope. Profiles do not assume a universal in_progress state.

The current Zone transport is POST /v1/zones/{id}:readPage with the actual target DTO and optional query cursor:
200 commonPage plus zone; 202 retained progress with next and private,no-store; existing 503 problem when progress
cannot be established. No proposed pages:read route or fake response normalization. The technical unfiltered
GET /v1/subject-pages crawler separately permits short/empty200 until next-null.
