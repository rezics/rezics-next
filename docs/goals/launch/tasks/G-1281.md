## Outcome

The production catalogue bootstrap (`task ops:bootstrap`,
`scripts/ops/bootstrap/`) succeeds on a fresh deployment where platform gates
are on. Since trust-ops' T5, `POST /v1/sources/intakes` and the rest of source
intake, adoption and compound import are closed under `platform:catalogue-import`,
so the bootstrap principal is refused at intake unless it holds
`platform:use:catalogue-import`.

1. Before intake, the bootstrap grants its principal `platform:use:catalogue-import`
   through the public grant API (`POST /v1/access/grant-changes`, issued by a
   holder of `platform:grant`, the first platform administrator), idempotently,
   recorded in the bootstrap journal so a re-run does not grant twice.
2. Verification fails with a clear message naming the missing grant when the
   principal lacks it, instead of failing later at intake with a bare 403.
3. Verification also runs `task ops:platform-governance` and fails on its
   failures.

Trust-ops fixed the QA counterpart in `tests/qa/integration/g-724-bootstrap.test.ts`
(G-1273) by granting through `tests/qa/fixtures/platform-grant.ts`
`grantPlatformUse` after designation; follow the same order for production,
but through the HTTP grant API, not the test fixture.

## Do not

Do not write grant rows directly in the database, grant more than
`catalogue-import`, or change trust-ops' grant API or `tests/qa/**`.

## Checks

```sh
task goal -- test scripts/ops/bootstrap/platform-grant.test.ts tests/qa/integration/g-724-bootstrap.test.ts
```

Cover: a fresh run grants once and proceeds; a re-run grants nothing new; a
principal whose grant was revoked fails verification with the named message.
