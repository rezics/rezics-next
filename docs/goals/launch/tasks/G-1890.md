## Outcome

Class A (program, 2026-10-11 19:08). `apps/web/features/work-page/discussion.tsx:49`
renders every reply body with `paragraphs(item.body)`, with no spoiler handling.
A reader opening a Work page sees a declared spoiler openly; the Realm thread
and the reply tree veil it until the reader asks.

Use the existing mechanism; do not write a new one:
- `markedSpoiler` from `apps/web/features/feed/discussion.ts`;
- `SpoilerVeil` from `apps/web/features/feed/discussion-card.tsx`;
- `reply-tree.tsx:103` shows the pattern:
  `markedSpoiler(reply.spoiler) ? <SpoilerVeil>{words}</SpoilerVeil> : words`.

1. If the Work-page discussion item does not carry the reply's `spoiler`
   field, carry it from the read that feeds this list (its adapter in
   `work-page/`). If the API does not return it, report that under BLOCKERS;
   change no Main code.
2. Veil a marked spoiler with `SpoilerVeil`; an unmarked reply renders as
   today. Reuse the existing spoiler label messages.
3. Tests:
   - a component test: a marked reply's words are not in the accessible text
     until revealed, and an unmarked reply's are;
   - a story with one marked and one unmarked card.
