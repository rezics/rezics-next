## Outcome

Inventory item L32 (program, 2026-10-11, class A). The launch coverage
registry (`scripts/qa/cases/launch-coverage.ts`) records three Realm functions
that have an API proof but no browser journey ("gap"):
1. **Roles and team**:
   - a manager creates a role and assigns it to a member in Manage → Roles
     (`apps/web/features/manage/roles-view.tsx`);
   - the role holder appears on the Realm's public team;
   - the assignment survives a reload.
2. **Threads and replies**:
   - a member opens a thread from the Realm's discussions
     (`apps/web/features/realm/discussions-route.tsx`) and replies, including a
     nested reply (`thread-view.tsx`);
   - a second person sees both after a reload.
3. **Ranking**:
   - with a few threads seeded through the API and votes cast through the
     product, Best, Top and New order the discussion list as their rules say;
   - switching sort keeps the list complete.

Write one new file, `apps/web/tests/realm-community.e2e.ts`, with one test per
function. Seed only through Main's public API, with the existing seed helpers
and grants, and act as a person through the browser. Use the patterns of
`apps/web/tests/realm-create.e2e.ts` and `apps/web/tests/realm-appeal.e2e.ts`.
Each test checks the visible result a person relies on, by accessible name or
role.

Then set each row's `browser` proof in `launch-coverage.ts` to the new test, with
its exact title and a one-line `evidence`.

If a journey fails because the product is wrong (not the test), stop and report
the failing step under BLOCKERS. Do not change product code, and do not weaken
the journey to pass.
