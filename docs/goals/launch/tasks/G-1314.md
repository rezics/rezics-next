## Outcome

Security High H4 (trust-ops review,
`.temp/worktrees/<id>/.temp/ref/security-findings.md` §4; copy it there from
`/home/edge/projects/rezics/rezics-next/.temp/trust-ops/security-findings.md`):
an OAuth client whose user consented only to `work:read` can change or delete
that user's personal reading records. Ownership checks pass because the bearer
belongs to the user; they cannot tell consent to read from consent to write.

Every personal-record mutation requires the `library:write` scope;
`work:read` stays enough for reads. That covers:
- copies and loans (`routes/library-copies.ts`);
- reading status, private reviews and goals (`routes/library.ts`);
- retained imports: create, delete and apply (`routes/library-imports.ts`);
- consumption sessions (`routes/sessions.ts`);
- reader settings (`routes/reading-settings.ts`).

The main site requests `library:write` (`apps/web/features/auth/scopes.ts`,
`MAIN_SITE_SCOPES`). Trust-ops registers the scope in Account, with the
consent meaning "Change your library and reading records", in its own task.
Trust-ops' G-1302 registers it; this task depends on it.

## Not this

No new authorization registry, no change to owner checks or `actingSubject`.
Do not edit Account or Main's verifier (trust-ops').

For each route family: a `work:read`-only token is denied before any owner
write and changes nothing, and a `library:write` token succeeds. Every read
still works with `work:read` alone.
