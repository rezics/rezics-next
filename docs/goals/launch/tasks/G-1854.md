## Outcome

Inventory item L20 (class A). A cook can author and read Recipes, but the
editor has no exchange controls. The sizing is staged at
`.temp/ref/g-1747-sizing.md` ("L20 — recipe exchange", launch slices 3 and 4).
This task carries the chain as one branch: each step is a separate `resume`,
committed and tested, and the task lands once.

Steps, in order:
1. **(this session) Export.** Add a download control to the recipe editor for the
   existing `GET /v1/recipes/{id}/exports/schema-org` (Schema.org JSON of the
   selected revision).
   - A recipe over the limit gets the typed refusal: kernel's G-1760 is on main,
     answering 413 `recipe_export_too_large` past 4,096 occurrences. Show its
     message instead of a generic error.
   - The download names the revision it exported.
   - New exchange component and story in `apps/web/features/recipe-editor/`,
     with localized messages in all eight locales.
   - Adapter or component tests: success, the over-limit refusal, and a denied
     read.
2. **Import**, after kernel's G-1759 (`POST /v1/recipes/{id}/file-imports`, a
   bounded 256 KiB Schema.org file under Work edit authority) lands. Upload, see
   the imported sections, ingredients and steps, and handle stale and retry.
3. **Round-trip browser journey**, `apps/web/tests/recipe-exchange.e2e.ts`: a cook
   imports a real public-domain recipe file, edits it, exports it, inspects the
   export, and imports the supported representation into another Recipe.
   - Proves ordering, duplicate lines, language and the named over-limit outcome.
   - The real file comes from kernel's pinned cookbook records when they land;
     until then, a small Schema.org fixture.

Do only step 1 now. Change no Main code; report a needed Main change under
