## Outcome

Found by G-2043's QA (2026-10-12 13:16 UTC). In the Realm Members view, choosing
"Give role" from a member's menu WITH THE POINTER closed the menu without
opening the role dialog, while the keyboard path worked
(`apps/web/features/manage/members-view.tsx:193-212`: `Menu onSelect` opens
the dialog). The maintainer accepts by hand at 15:10, likely with a mouse.

1. Reproduce it first, in a story interaction test that uses real pointer
   events (`userEvent.click` on the trigger, then on the "Give role" item), and
   in the browser at a desktop and a phone width. If it does NOT reproduce in
   the real browser and only the story harness misbehaves, say so with the
   evidence, fix the story's interaction, and stop.
2. If it reproduces: fix the cause, not the symptom. The likely cause is the
   menu's close and focus return racing the dialog open (open the dialog after
   the menu has closed, or control the dialog from the selection state). Check
   the "take role" items and every other menu in `apps/web/features/manage`
   that opens a dialog from `onSelect`: same class, same fix.
3. A pointer test and a keyboard test per menu-to-dialog action; both pass.
