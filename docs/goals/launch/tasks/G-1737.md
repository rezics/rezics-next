## Outcome

This finishes L15 (class A). G-1736 made public browser reads omit the session
cookie and kept viewer and Mine reads on the session. Its audit (staged at
`.temp/ref/g1736-public-read-audit.md`, "Outside-owner follow-ups") named five
places outside its claim. Implement them as written there:
1. `feed/api.ts:36-39,81`, `feed/feed-list.tsx:145,293,348` and
   `feed/feed-context.tsx:60`: the public All fallback's page, restart and head
   requests use the anonymous browser client, matching `home/server.ts:52-54`.
   Actor feeds and commands keep the session.
2. `query/condition-bar.tsx:99`: summaries of missing selected values follow
   explicit sign-in state passed in by the consumer, not actor presence.
3. `work-page/scope-bar.tsx:82` and `work-page/work-views.tsx:193-213`: forward
   sign-in state to the population first-page and continuation loaders and to
   picker resets. `work-page/read.ts:44,50` keeps the bearer for viewer
   population and release-Works reads even without an eligible Agent, without
   weakening private Work reads.
4. `author/read.ts:18-24,45-54` and the external-author route callers:
   - keep the bearer for signed-in viewer shelves without an eligible Agent;
   - keep metadata explicitly anonymous;
   - separate the metadata cache arguments from body reads.
5. `api/browser.ts`: the comment describes anonymity as explicit public intent,
   not the absence of an eligible Agent.

Extend `apps/web/tests/public-reads-anonymous.test.ts` with one case per item
(request construction, no network):
- public requests omit credentials;
- viewer requests keep them;
- first page and continuation match.

Do not add a server mode parameter, change Main, or make a personal read public.
