## Outcome

G-1396 (236f3a426) added a set-based page form of the judgment badge read
(`judgment/badge.ts`, `judgment/access.ts`). Search still calls the per-item
form for each result, so its cost grows with page size. Kernel lent its two
search files for this one slice (the others are in no Goal's area). Move all
four consumers onto the page API as one coherent producer-consumer change.

Preserve each item's current rights, hidden and missing behavior, the
semantic field budget, cancellation and the final fences. No permission cache,
no budget raise and no new framework.

Prove it with `meterStatements` (as in G-1396's test):
- pages of 1 and 100 results cost the same number of calls within today's
  limits;
- the badges equal the per-item results;
- sparse hidden items and a revoked judgment behave as before.
