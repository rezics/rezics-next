## Outcome

G-1284 split a Zone into a draft and a published site bundle. Its name and
address still bypass that split. A saved but unpublished name, via
`PUT /v1/zones/:id/configuration`, becomes public at once:
- anonymous `GET /v1/resources/:zoneUuid` and `POST /v1/resources/summaries`
  read it (`media/summary.ts:307` reads the current `rdfs:label`);
- the official listing reads it too (`zone/publication.ts:286`);
- meanwhile the published home still shows the old name.

Fix it at the writer. Configuration saves the name and address suffix as
draft facts. Publishing the site promotes them to the public facts in the
same step as the bundle switch. Readers keep reading the public facts, so
`media/summary.ts` (trust-ops') doesn't change. A Zone that has never been
published keeps today's behavior, but say in the handoff what an unpublished
Zone shows publicly.

Counterexamples:
- save a new name without publishing: anonymous resource, summaries and the
  official listing keep the published name;
- publish: all three show the new one;
- lost-response replay of the publish promotes once;
- a revoked editor's draft name never becomes public.
