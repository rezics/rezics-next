## Outcome

`projectJudgmentBadge` (`judgment/badge.ts`) runs about 11 PostgreSQL
statements per support. Its callers run it per item:
- launch's classification readers: library stats, the Realm decision index,
  onboarding;
- search-grouped, search-disclosed-fields and search-disclosure public fields.

The cost therefore grows with page size (G-1368's trace,
`.temp/goal-launch/evidence/decision-page-query-cost.json`, staged in your
worktree's `.temp/ref/`).

Add a set-based, per-page form that returns exactly the badges today's
per-item calls return, including disclosure and protection, and keep the
per-item function as a thin wrapper over it. Move the callers in launch's
area (the classification readers, or the shared classification reader they
call) to the page form, reclaiming those unclaimed launch files with
`task goal -- reclaim`. For the callers outside
your claim, list each file and the change it needs under PROPOSED TASKS.

Prove the cost with an integration test using `meterStatements`
(`tests/qa/integration/feed-read-support.ts`, as in
`tests/qa/integration/support/statement-meter.test.ts`): pages of 1, 5 and 20
supports cost the same number of statements, and the badges equal the
per-item results. No migration unless a missing index blocks the set read; if
one does, name it.
