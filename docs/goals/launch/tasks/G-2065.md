## Outcome

Four browser runs reproduce it (20261012t082439-67c0df, 084022-7efe8f,
095133-3772eb, 144638-4b9348): on the Railgun anime's connections page,
clicking the "Adapted from" relation link "A Certain Scientific Railgun
(manga)" does not navigate. The URL stays on the anime's `/connections` after 5
s (`apps/web/tests/g-837-work-levels.e2e.ts:170-180`). A visitor following a
relation from an anime, manga or VN hub cannot reach the related Work.

1. Reproduce in a real browser (Playwright Chromium against a QA stack, via
   `task goal -- test apps/web/tests/g-837-work-levels.e2e.ts`) and find the
   cause: the link's href, a client-navigation (RSC) request that fails or
   hangs, a handler that prevents default, or a route that redirects back.
   Read the browser console and network log of the run.
2. Fix the cause in the web (the relation link component and the Work hub
   routes are launch's area; widen the claim with the area allowance and say
   so). Check every other relation link on the hubs (connections, parts and
   wholes) for the same class.
3. The journey's first test passes. If the second test still fails at setup
   with `invalid_semantic_change` ("Safety responders are not configured" or
   "Work name scope is not prepared"), that is a QA stack readiness issue:
   report it with the log lines and leave it.
