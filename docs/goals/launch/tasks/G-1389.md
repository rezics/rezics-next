## Outcome

Phase 1 of a class fix. G-1285 (loans) needed five review rounds to get
command identity right, and about 30 web features send their own
`Idempotency-Key`s, each in its own way. The rules G-1285 settled:
- a command's key lives from the reader's action until confirmed success or a
  definitive refusal;
- every retry of that unresolved command, including after a transport failure
  or a lost response, reuses the key so the API replays its receipt;
- after success the key is retired, and the next action is a new command with
  a new key, even with identical fields;
- conflict recovery accepts an existing record as "already done" only when it
  matches the complete intent;
- a 409 re-reads and re-applies only the newest intent, with one write in
  flight per record (G-1225 and G-1247).

Do two things.
1. Write `apps/web/features/api/command.ts`, one small helper that carries
   these rules, with unit tests for each, and move loans (`write.ts`) onto it
   with no behavior change. Keep it tiny. It's not a queue and it keeps no
   persistence.
2. Audit every browser write site (`rg -l "Idempotency|idempotency"
   apps/web/features`). For each, record in the handoff the file, whether it
   breaks a rule, which rule, and a concrete failure (for example "retry
   after lost response creates a duplicate post"). Group the violations into
   migration batches by feature, so launch can brief them next.
