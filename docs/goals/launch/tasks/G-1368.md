## Outcome

Classification now has one representation: a `classifiedAs` Statement in a
shared Context, accepted by a Statement decision (kernel retired
`POST /v1/classification-decisions`; it answers 404). Some launch readers and
tests still use the old `rv:ClassificationApplication` facts, so new
classifications never reach them:
- `library/stats.ts` (a reader's genre breakdown);
- `realm-reads/public-decision-index.ts` (a Realm's public decision list,
  kind `classification`);
- the integration tests above, which still post the retired route.

Move them to the accepted-Statement reads G-1361 introduced (onboarding
`choices.ts`/`suggestions.ts`, seed writer `scripts/dev/seed/classified-statement.ts`).
Use the same disclosure as those reads (the spoiler hint and accepted state).
Keep every read bounded: per reader or Realm, cursor-paged, no global scan.
Write tests through the API with the shared seed writer.

Not this: no change to `classification/decision.ts`, `context-statement-cases`,
`classification-vocabulary` or `work-profile-classification-child.ts` (kernel's
and program's).

- a rejected or pending one doesn't;
- a spoiler-hinted one stays hidden where it was hidden before;
- a Realm's public decision list shows a Statement decision with its kind.
