## Outcome

Class A (program, 2026-10-12 09:37 UTC). In the role-management browser
journey (`apps/web/tests/realm-community.e2e.ts`, about lines 395–420), a
manager gives a member a role. "Give role" succeeds, but the member row still
shows "No role", at line 408, the assertion `row.getByText(roleName)`.

First find WHICH is wrong, with evidence:
- **the write:** did the role-assignment command commit the assignment for
  that member and Realm?
- **the read:** does the members read used by the management list return the
  role for that member after the write (before and after reload)?
- **the page:** does the list re-read after the dialog closes, and render the
  role field it receives?

Reproduce at the lowest tier that shows it: an owner or integration test of
the write plus the members read, then a component test of the list. Then fix
whichever is wrong, with a test that fails without the fix.

The browser journey file is held by G-1870. Don't edit it. If its assertions
are themselves wrong, say so and the manager arranges a loan. Other files: find
their owners with `task goal -- owner <path>` and report them before editing
anything outside launch's area.
