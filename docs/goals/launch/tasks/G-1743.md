## Outcome

Inventory item L17, slice 2. The specification is staged at
`.temp/ref/g-1741-spec.md` ("Ordered slices", item 2). Today the navigation
editor:
- reads only the first 50 mounts, although the API continues;
- reorders by removing and reinserting mounts, which can drop metadata it
  does not represent.

1. Consume the existing continuation and revision parameters. Show incomplete
   loading honestly, and never save a partial list as if it were complete.
2. Reorder with the existing composition `move` operation instead of delete and
   recreate. Keep the route key, disclosure, presentation and other retained
   metadata.
3. Where a path edit cannot be preserved safely with the current transport, show
   the limitation instead of flattening it silently.
4. Prove it:
   - in `tests/qa/integration/zone-navigation-move.test.ts`, the move operation
     keeps mount metadata and refuses a stale head;
   - in `navigation.test.ts` (adapter), editing beyond the first 50 entries and
     reordering across that boundary keeps untouched entries and their metadata.

Change no Main code; report a needed owner change under BLOCKERS.
