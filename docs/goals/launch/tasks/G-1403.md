## Outcome

When a reader's account is erased, every private library import record of
theirs goes, including sources no uploaded file points to any more.

Trust-ops' G-1343 remaining-closure audit found the gap.
`eraseLibraryImportsForPrincipals` (`library-import/privacy.ts`):
- deletes uploaded files and the sources found through their `source_rows`;
- then deletes the other per-agent private tables;
- never removes `reader.library_import_source` rows retained independently of
  a file;
- and `deleteLibraryUploads` returns early when there are no files.

So orphan source records survive erasure and restore. Trust-ops' current
helper refuses them rather than releasing them.

Make the existing cleanup also remove the erased own-Person agent's orphan
sources, under the same Content transaction and per-agent locks, and with the
same Access proof (deleted own Person plus `account.deletion_fenced`). First
inspect the `source_rows` foreign keys and any shared source references.
Keep unrelated, active and delegated agents' data untouched, and keep
import replay and retention semantics. No new service, no per-public-name
cleanup, no fake release callback, and no relaxing of G-1343's remaining-row
assertions.
