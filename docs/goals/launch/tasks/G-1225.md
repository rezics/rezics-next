## Outcome

What a person chose is what the product keeps and shows, across retries,
devices, appearance settings and sign-in state:

- **f. Newest intent wins.** A newer choice is never overwritten by an older
  one. Today `catalogue/reader-store.ts` refreshes after a 409 and replays the
  old intent, and `reader-actions.tsx` lets writes overlap; the API already has
  CAS (expected revision or head). Per subject and field, keep one write in
  flight, coalesce later choices into the latest, and after a 409 re-apply only
  the latest intent, and only if it still differs from the server. The same
  class exists in `api/preferences.ts` (appearance retried against Account CAS)
  and `work-page/reviews.tsx` (accepts stale reads); fix both.
- **g. 202 is pending, not done.** `reader-store.ts:164` treats an accepted but
  unapplied write as success, and stars stay optimistic forever. Show the
  control as pending, read back the current reader state (it already exists in
  the store) a bounded number of times with backoff until the revision appears,
  then show the settled value; if it does not appear, say it is still being
  processed and offer a refresh. No browser-side queue, persistence or
  compensation.
- **d. Data selection survives presentation fallback.** Safe mode or turning
  off a package's appearance disables presentation code, not the reader's
  position and continuity choices (`zones/execution.ts:33`,
  `realm/realm-page.tsx:90`, `wiki/state.ts:108`, `wiki/zone-continuity.ts:102`,
  `zones/site-route.tsx:215`). The API reads already accept position and
  continuity; pass them whether or not the package runs. Also
  `scoped-rating/subject-judgments.tsx:102` omits the position and
  `scoped-rating/api.ts:164,168` drop it from projection and summary reads.
- **e. Anonymous reads are anonymous.** `api/main.ts:62` fetches the signed-in
  person's private languages even for `mainApiWithToken(undefined)`, and
  `seo/work.ts:106–111` checks the anonymous preview and then renders the
  personalized Work. Server renders meant for anonymous readers and crawlers
  send no token and no private preference, and render the anonymous
  representation Main returns.
- **h. Public reads need no acting Agent.** `scoped-rating/api.ts:84,89` uses
  the authenticated browser transport without an acting subject, which Main
  rightly rejects; use the anonymous transport for public reads, as
  `scoped-rating/sources.ts:40` already does.

## Class audit

Treat f, g and h as symptoms. Search `apps/web/features/**` for every write path
that retries after a 409 or treats a 202 as completion, and every public read
that goes through the authenticated transport without an acting subject. Fix
the ones in your claim; list the rest in the handoff as proposed tasks with
file and line.

## Do not

Do not change Main or Account APIs (they already provide CAS, pending
responses, positions, anonymous representations and anonymous reads); if one
turns out to be missing, hand off with the evidence. Do not rebuild authority
in the UI, store intents in browser storage, or add a client-side retry queue.
Library files `features/library/**` and the shared author link belong to
another live task.
