## Outcome

Inventory item L21, books slice (program, 2026-10-11): real-data fixtures, built
once through the API and restored, landing with their first journey. The
sizing is staged at `.temp/ref/g-1747-sizing.md` ("L21", slices 1–2).

Kernel pinned the books records (G-1761), with hashes and licence lines in
`tests/fixtures/fixtures.lock.json`; readers are in `tests/fixtures/sources/`:
- the Open Library edition set for work OL66554W (*Pride and Prejudice*): a
  translation, two publishers, a revised or annotated edition, an ebook and an
  audiobook (CC0);
- a 250-record Open Library library slice;
- six Wikidata labels.

The non-UI-language Gutenberg texts and the Pepys serial come later (kernel's
G-1762) and are not part of this session.

1. `scripts/load/launch-corpus.ts`: build the books corpus once through Main's
   public API from the pinned records, using the existing catalogue intake,
   release and Content operations and existing seed helpers, never SQL. Then
   retain it with the shared corpus backup driver
   (`scripts/load/corpus-backup-driver.ts`, as
   `tests/qa/integration/profile-corpus-restore.test.ts` does) and restore
   isolated copies.
   - Report the source digests and the build and restore times. Restore,
     startup and readiness stay under 10 minutes.
   - Import only what the cases need, with the count beside each.
2. First journey, on a restored copy: a reader opens the OL66554W Work, sees its
   real editions and formats, chooses one edition, and the choice persists
   after a reload. Prove it with the same case in both:
   - API: `tests/qa/integration/launch-real-books.test.ts`, the exact edition
     persisted and mixed formats listed;
   - browser: `apps/web/tests/launch-real-books.e2e.ts`, by keyboard, at phone
     and desktop width.
3. Report both exact titles. The manager records them in the coverage registry:
   "books / Choose among ambiguous editions of one Work" (now gap) and the books
   mixed-formats row.

Use only the pinned files, with no network and no covers. If the product
cannot show or persist an edition choice, report the step under BLOCKERS rather
than changing product code.

## Decisions after attempt 1 (manager, 2026-10-11)

- Formats exist. The tracking model knows `print`, `ebook`, `audiobook` and
  `web` (`apps/web/features/tracking/model.ts`, `display.ts` `formatLabel`),
  and the reading-progress journey shows "… · audiobook". Find how the existing
  seeds give an edition its format through the API (`apps/web/tests/g-743-stack.ts`,
  `journeys/work-hub.ts`) and use the same path. If the API truly cannot set a
  format on a release, report the exact operation and field.
- The Work hub's edition chooser (`apps/web/features/work-page/**`) shows titles
  only, so same-title editions cannot be told apart. That is the ambiguous-editions
  hard case itself (class A). Make each option name what distinguishes it:
  format, language, publisher, year, from the read the chooser already has. Add
  a story or test, then use it in the journey.
- QA registration (kernel, 14:23 UTC): G-1825 adds the entry itself, in the
  same change as the test, landing with `--allow-scope`. Put
  `tests/qa/integration/launch-real-books.test.ts` in `isolatedIntegrationFileList`
  beside profile-corpus-restore, with the comment "restores the launch books
  corpus", and in the command-only list next to it. Rebase onto kernel's G-1630
  first (it is in the merge gate and changes the surrounding lines); the manager
  tells you when it lands.

## Decision on the browser corpus (manager, 2026-10-11)

- The restored copy is proven by the API test
  (`tests/qa/integration/launch-real-books.test.ts`): it builds once, retains
  the backup with the corpus driver, restores isolated copies (75–100 s), and
  persists an exact edition choice there.
- The browser journeys run on the same pinned records, prepared in the browser
  stack with `--browser-prepare` (`restored: false`, a 37 s build). They do not
  yet restore a copy, because the browser runner (`scripts/qa/e2e.ts`, the
  program's) has no restored-corpus app origins.
- Accepted for this landing; launch asked the program to add restore support to
  the browser runner. When it exists, the journeys switch to a restored copy and
  `restored: false` becomes `true`.
