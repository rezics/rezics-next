## Outcome

Operators see how long the oldest review has waited in the ranking queue, not
how old the review is. Today the queue
(`access.reader_review_rank_change WHERE position IS NULL`, Access migration
1170 lines 3–11) stores only `occurred_at`, copied from the review's
`created_at` (migration 623 lines 57–59), and `horizon/lag.ts:42–43` reports
that as pending age (its comment at `:15–16,31–32` admits it).

Evidence: `/home/edge/projects/rezics/rezics-next/.temp/goal-launch/scale-showcase-evidence.md`, "Task C" item 5.

## Change

Migration 1272 adds an enqueue time set from the database clock when a row is
appended (`DEFAULT clock_timestamp()` or the append function, whichever the
1170 definition uses; start from the latest definition on `main`). Existing
rows get no invented time: lag reports their age as unknown or approximate,
explicitly. `horizon/lag.ts` reports queue-head waiting age from the enqueue
time and keeps `occurred_at` for ranking. Remove the comment that admits the
old limitation.

Do not change the ranking consumer (`services/main/src/modules/rankings/**`
belongs to the kernel Goal), build a new queue or scheduler, or backfill
enqueue times from other columns.
