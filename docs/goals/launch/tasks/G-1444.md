## Outcome

Kernel's G-1433 (73c92bad9) pages `GET /v1/recipes/works/{id}`:
- at most 100 occurrences per call, in depth-first order, each with its
  `parent`;
- `measures` on every page, and `ingredients` scaled for that page's
  records;
- an optional `next` cursor (query `cursor`), pinned to the structure
  revision and servings. A cursor for a revision that is no longer selected
  answers 409 with profile `recipe-work-page-stale`; a tampered cursor is
  refused.

Launch's pages read only the first page today.

The recipe Work page (`work-page/types/recipe.tsx`, read through
`readRecipeWorkPage`):
- renders the first page as now, then lets the reader continue with a "show
  more" control that reads `next`. Never read every page up front;
- keeps the hierarchy whole across a page boundary: a section that continues
  on the next page shows as one section, and steps keep their numbers;
- on a 409 stale cursor, tells the reader the recipe changed and reloads from
  the first page. Changing servings starts again from the first page;
- handles a refused or failed continuation without losing what is shown.

The recipe editor (`recipe-editor/`, `model.ts` reads the same route):
- Find how it saves. It must never write a structure built from a partial
  read.
- If its writes are per record, it may page as the reader does. If any write
  depends on the whole recipe (reordering across sections, deleting a
  section, publishing), it loads the remaining pages first with a visible
  progress state. Kernel's cap of 4,096 occurrences bounds that.
- Report which case applies.

Strings come in all eight locales, with non-English marked for native review.
Add a story for a two-page recipe. Add the journey
`apps/web/tests/recipe-long.e2e.ts`, at 390 px and 1280 px:
- a recipe written through the API with more than 100 occurrences (several
  sections);
- read its first part, continue to the end, and check that sections and step
  numbers are whole;
- change servings;
- edit it in the editor and confirm nothing beyond the first page is lost.

## Do not

No change to services/, no raised limits and no client-side cache of the
whole recipe. Don't touch recipe export.
