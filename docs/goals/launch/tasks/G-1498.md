## Outcome

Manager decision (2026-10-09), replacing the original diagnosis. Lease expiry
is not the fault. 131ee7729's seal, single apply and lease stall are correct,
and library-import-apply.test.ts proves them. The apply POST is asynchronous
since Oct 8: it answers 202 with the pending acceptance receipt, the caller
polls `GET /v1/me/library-imports/{id}/apply` until it leaves pending, and a
same-key replay returns the original receipt. Three older integration files
still expected a 200 that is already complete. The approved test change:
- g-854-review-fixes, g-854-library-bundle and library-copies-loans accept
  the 202;
- they poll the status through one shared helper and keep every final
  assertion on the terminal reading;
- the bundle test's same-key loop becomes the poll.

No server change. Any extra permission given in a test goes only to the
principal that performs the import, as its login scopes, never by wrapping
verification for every principal.

The large-library 409 ("Review all rows…", "Work name scope is not
prepared") is routed separately.
