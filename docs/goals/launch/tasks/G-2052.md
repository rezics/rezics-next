## Outcome

Kernel's G-2038 (ranked public search window, program class A) changes the
public query and page responses (kernel, 2026-10-12 13:56 UTC):
- `complete: boolean` is false when more candidates existed than were
  hydrated, or when the index holds more than 512;
- `total` is a lower bound when `complete` is false, with
  `totalPrecision: 'exact' | 'atLeast'`; facets carry the same precision.

The web consumes it:
- The sentence `complete` in `apps/web/features/search/messages.ts:35`
  ("Every match is counted and ranked; nothing is sampled.") shows only when
  `complete` is true. Otherwise: "Showing the first N by relevance; at least T
  in total." (N is the page's count, T is `total`), in every UI language the
  messages file carries.
- Totals and facet counts with `atLeast` precision render as "at least T", never
  as exact.
- Kernel's exact hunks for the two lines that fail typecheck
  (`search-page.stories.tsx:152`, `search-state.test.ts:122`) are in
  `.temp/ref/kernel-2038-hunks.md` when kernel sends them; otherwise follow
  the field names above.
- Stories for both states. Look at the screenshots.

Dispatched after G-2038 is on main.
