## Outcome

In the franchise wiki journey (`apps/web/tests/g-856-wiki.e2e.ts`, QA
20261008t075022-da10e4), all four signed-in reader tests (en/ja,
phone/desktop) fail at `apps/web/tests/journeys/franchise-wiki.ts:356`. On the
chapter 3 page (`GET /en/z/franchise-wiki/chapters/F6QhPhba9XnQb3dQEPAfAS-pride-and-prejudice`)
there is no link named "Chapter 2". The page renders the heading, "Up to:
Chapter 3" and the revealed characters, but its chapter-neighbour navigation
is omitted, because both the previous and the next chapter come back absent.

A chapter page links to its previous and next chapters in reading order,
whenever the reader may see them. That uses the same disclosure as the
chapter list: a hidden neighbour is skipped, not revealed. Find where the
neighbours come from, which API read and which field, and why they are absent.
Fix it at its source:
- If the UI reads the wrong field or drops the neighbours, fix it in
  `apps/web/features/wiki/`.
- If the API stopped returning them, which may relate to the reading-position
  changes in G-1365 (75474eed6..) and G-1414 (a46dac3c2), fix the server read.
  List those files under OWNER CHANGES. Keep G-1414's rules: ordinals never
  reveal hidden placements, and reads stay bounded.
Add a unit test or story for a middle chapter with both neighbours.
