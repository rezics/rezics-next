## Outcome

Saved views are closed at launch behind `platform:use:saved-views` (approved
launch matrix; trust-ops T5). Since G-1236 (7fd2749c8) the web hides closed
surfaces, so a person without the grant sees Home's Following and All tabs and
no "Pin a topic" control. `apps/web/tests/home.e2e.ts:78` ("a new person is
invited to set up Home, can put it off, and pins the current filters as a
tab") still expects every new person to pin, and now times out at
`home.e2e.ts:101–103` waiting for the pin dialog (QA run 20261006t233213-9e9eab
in the manager's wave worktree).

The journey must prove both sides of the gate through the real API:

1. A new person **without** the grant: Home shows Following and All, no pin
   control, no tab menu, no error and no 403 toast; opening a
   `?tab=<uuid>` address shows the existing "tab is gone, browse All" state.
2. The same flow **with** `platform:use:saved-views` granted through the
   platform grant API (the dev administrator holds `platform:grant`; trust-ops
   T5): the pin dialog, "Save as tab", the named tab with `aria-current` and
   its own address all work as the old assertion described.

Put the grant step in a small helper, `apps/web/tests/platform-grant.ts`, so
other journeys can open a group the same way.

## Do not

Do not change product code, loosen the gate, grant the capability to everyone
in the seed, or delete the pin assertions: they move to the granted case.
