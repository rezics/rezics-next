## Outcome

`task dev:refresh` re-approves changed official Zones again. Its
`approve-zones` step runs `task dev:seed -- --themes-only --packages=<slug>`.
That seed has failed since trust-ops' T5 with "Official ai-workshop theme:
Main /v1/themes/<id>/first-party HTTP 403 platform_closed" (repro:
`/home/edge/projects/rezics/rezics-next/.temp/goal-program/seed-ai-workshop.log`).
The first-party theme operations (`getV1ThemesByThemeFirst-party`,
`postV1ThemesByThemeFirst-party-activations`) are `platform:executable-themes`
(`generated/openapi/main/exposure.ts`), and the seeding account holds no grant.
So no official Zone has been re-approved on the shared stack since T5.

The dev stack has had a first platform administrator holding
`platform:grant` since the program's G-1265.

1. Before any seed step that calls a closed group, have that administrator
   grant the seeding principal `platform:use:<group>` through the public grant
   API (`POST /v1/access/grant-changes`). Do it idempotently, so a re-run
   grants nothing new. Follow the order `tests/qa/fixtures/platform-grant.ts`
   uses.
2. Treat it as a class: find every seed step in `scripts/dev/seed/**` that
   calls an operation whose exposure is not `public` (check each call against
   `operationExposures`). Open exactly those groups for the principal that
   makes the call.
3. When the grant is missing, a seed step fails with a message that names
   the group, not a bare 403.

## Do not

Do not write grant rows in the database, grant groups to every account,
change product code, the matrix or `tests/qa/**`, or open a group the seed
does not call.

## Checks

```sh
task goal -- test scripts/dev/seed/<the seed tests you change or add>
```

Prove it against a disposable stack or the shared stack's API:
- `task dev:seed -- --themes-only --packages=ai-workshop` succeeds;
- running it again changes nothing;
- the handoff lists every closed group the seed now opens, and for whom.
