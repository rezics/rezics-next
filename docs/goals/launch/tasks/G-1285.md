## Outcome

A reader can, in the browser:
- record that they own a copy of an exact edition (format, acquired, owned
  since);
- lend that copy to someone, or record one borrowed from someone or a
  library, with a due date;
- see at a glance what is due and what is overdue;
- return a loan or extend it.

Everything is private to them. Launch's Completion requires journeys with
expired loans.

The API exists (G-1239, `services/main/src/routes/library-copies.ts`):
- copy create, change and remove;
- loan list (`open | overdue | returned`, cursor-paged by due time, with
  `complete` since G-1279), open, extend and return;
- owner `actingSubject`, CAS `expectedVersion` and `Idempotency-Key` on every
  write.

## Design

Comparable products: Libib and BookBuddy's loan lists. Use them for the need,
not the layout. Fit the existing library page: a "Loans" view beside the
shelves showing overdue first (clearly marked), then due soon, each with
Return and Extend. Add "I own a copy" and "Lend" from a Work's library row.
A counterparty is a person reference or a free-text name such as a library.
Show free-text names as written; never resolve them to a person.

Writes follow the shared reader-store rules from G-1225 and G-1247:
- one write in flight per record;
- a 409 refreshes and re-applies only the newest intent;
- no browser-side queue or storage.

Use existing UI components and the eight-locale catalogs; English plus the
seven others, marked for native review in the handoff.

## Do not

Do not change the API, show loans to anyone but their owner, add reminders or
email, or build lending infrastructure. Shelves, ratings and status keep
their current behavior.
