## Outcome

Twenty `apps/web` unit tests in twelve files fail on `main` at the program's
regression baseline `5d4ac1ea7`. They were never in a QA tier, so nothing ran
them. For each failing test, decide with evidence whether the product or the
test is wrong, and leave every file green for the right reason.

List: `/home/edge/projects/rezics/rezics-next/.temp/goal-program/regress/5d4ac1ea7b15/owner/fail-apps_web.txt`;
log: the `apps_web.log` beside it. Run a file with `bun test ./apps/web/tests/<file>`.

Also: `showcase-zone-editor.test.tsx:322` calls `mock.module('../features/work-page/read.ts', …)`
without restoring it, so later tests in the same bun process that read wiki

Also (found by the program's P4, de99b528a): `apps/web/tests/public-search.e2e.ts`
still drives `/en/search`, but since G-1001 (e286dd5fd, 2026-10-03) Discover is
the one search surface and `app/[locale]/search/route.ts` answers 301 to
Discover keeping the selection ("Retired search bookmarks reach Discover

and add one assertion that `/en/search?q=river` lands on Discover with `river`
kept. Run it with `task goal -- test --heavy apps/web/tests/public-search.e2e.ts`.

## How to decide

1. Run each file and read the failure.
2. **Stale test** (the product changed on purpose): find the commit that
   changed the behavior (`git log -S`, `git log -L` on the product file) and
   the decision, document or code that makes the new behavior intended. Then
   update the assertion so it proves the same user outcome against the
   current product. Name that commit or decision in the handoff.
3. **Product defect** in a file nobody claims (`task goal -- owner <path>`):
   make the minimal fix and list the file under OWNER CHANGES.
4. **Do not fix, hand off with evidence instead:**
   - `session-refresh.test.ts` and `session-scopes.test.ts` (IAM01, sign-in
     sessions): if the product is wrong, describe exactly how (a refresh that
     does not sign out, two rotations, an undeclared scope) and stop there.
   - `zone.test.ts` (official Zone packages may import only React, the SDK,
     Rezics UI, icons and their own files): if a package imports something
     else, list each import with file and line and what it should use instead.
   - `g-944-shared-browser.test.ts` needs the shared stack; if it fails only
     because the stack is unavailable, say so and leave it.
   - Anything whose fix lies in a file another task claims.

## Do not

Do not delete or skip a test, loosen an assertion until it passes, or change
a test to match a product defect. Do not rename these files in this task.

## Checks

```sh
task goal -- test apps/web/tests/<each file you changed>
bun node_modules/typescript/bin/tsc --project apps/web/tsconfig.json --noEmit
```

In the handoff, give one row per failing test: stale or defect, the evidence
(commit, decision or file and line), what you changed, and the final result.
