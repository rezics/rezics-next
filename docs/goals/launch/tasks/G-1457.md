## Outcome

G-1431's journey (`apps/web/tests/realm-create.e2e.ts`, QA
20261008t120117-f276b3) shows three defects in a founder's first minutes:

1. **The privacy choice says one thing and does another.** The create form
   offers Public and Restricted. Restricted's help says "Anyone can read. You
   decide who can join and post.", but `create-form.tsx` sends it as API
   `private` (member-only reading), with a comment claiming the form promises
   member-only disclosure. The API has three levels, `public`, `restricted`
   and `private` (`realm-admin/contract.ts` `realmSettings.visibility`).
   Decision: the form offers exactly those three, each mapped one-to-one to
   the API value, with help that says what each does:
   - Public: anyone reads and anyone may join.
   - Restricted: anyone reads, and the founder decides who joins and posts.
   - Private: only members read.

   Review and posting defaults follow the choice as they do now. Manage's
   settings use the same three words and help. Strings come in all eight
   locales, with non-English marked for native review.
2. **The founder's new Realm home says "Couldn't load the discussions.
   Something went wrong on our side."** (390 px and 1280 px screenshots in
   that QA run). Find which read fails and why. A new Realm with no threads
   shows the empty state, which invites the first post. Fix it at its
   source, in the read or in the web's handling. If the cause is outside
   these paths, report it under BLOCKERS with the request and the response.
3. **A missing or unreadable Realm never shows the "This community isn't
   here" screen.** The space proxy answers with an empty 404 body. The page
   shows that screen for both cases alike, so a private Realm and a missing
   one stay indistinguishable to an outsider.

Extend `apps/web/tests/realm-create.e2e.ts`. Create one Realm for each of
the three choices and assert:
- what an anonymous reader sees in each: Public and Restricted readable,
  Private shown as "isn't here";
- the founder's home shows the empty discussion state, not an error;
- a missing handle shows "isn't here".

Keep its existing steps.

## Do not

No change to Access or the realm-admin contract. Don't make a private Realm
distinguishable from a missing one.
