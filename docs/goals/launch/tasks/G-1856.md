## Outcome

Analysis only, read-only, about 30 minutes. Do not change code.

Launch's G-1833 found that the Realm reply composer failed every fresh reply
with no visible placement: it read the reply's digest through the public
`GET /v1/member-replies/{reply}`, which exposes a reply only once it has a
visible placement. The composer now keeps the draft's own `revisionDigest`.
That worker reported that nested reply submission, a reply to a reply, also
uses a public digest lookup and omits `originRealm`, but may not fail the same
guaranteed way.

Answer, with file and line:
1. Which code submits a nested reply, and every read it makes before placement.
2. Whether any of them can answer 404 or unavailable for a reply that is not yet
   placed or visible: after an unban, under review, a first reply, or a hidden
   parent. Give the exact condition, or why it cannot happen.
3. What omitting `originRealm` changes: a wrong Realm, a refusal, or nothing.
4. Your class: A (a person's reply fails or lands wrong) or B. If A, give the
   exact change (files, functions, tests) for one implementation session.
   Prefer reusing G-1833's approach (keep the draft response's digest), which
   is on its branch `goal/g-1833`.
