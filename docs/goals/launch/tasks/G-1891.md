## Restore startup (manager, 2026-10-12 05:55 UTC)

The retained backup `launch-recipes-139f15c221bb728ebfca` was captured from a
PostgreSQL that was not shut down cleanly ("database system shutdown was
interrupted; last known up at 04:19:40"). So every restore runs crash recovery,
and under host load that outlasts the health check (run
`20261012t053643-514b4d`). That violates the consistent-backup practice.
- Make the retained backup consistent once: restore it, let recovery finish,
  stop PostgreSQL cleanly, and retain that copy, using the backup driver's own
  stop and capture path.
- If the driver captures without a clean stop, fix that in the driver
  (`scripts/load/corpus-backup-driver.ts`, unclaimed) with a test, and say so;
  it is a class fix for every retained build.

Then run the combined proof once: `scripts/qa/e2e.test.ts`,
`tests/qa/integration/launch-real-recipes.test.ts` and
`apps/web/tests/launch-real-recipes.e2e.ts`.
