## Land review 1 (2026-10-12 08:22 UTC): exact revision, never all revisions

`realm-directory/vocabulary.ts:17` builds the record target without a
revision. `discloseInventory` resolves current revisions only for name and
title targets, so the record target reaches `DisclosureStore` with
`revision = NULL`, which matches EVERY restricted revision. A restriction on an
old head H1 then hides the current head H2. Rule: pass the Concept revision
that belongs to the selected labels on both targets (record and name/title),
for both vocabulary search and the Realm topic lookup. Search the two
resolvers for any other target built without its revision. Test: a
restriction on H1 with H2 current keeps H2 visible in both paths; a
restriction on H2 hides it.

## Land review 2 (program, 2026-10-12 08:35 UTC): resolve the revision, do not require it

`realm-directory/read.ts:33` now requires `rv:head` on the topic Concept, so a
v1 Concept made by `POST /v1/classification-propositions` (whose head is only
on its Sense, `classification/proposition.ts:145–155`) became "Topic is
unavailable". Resolve the Concept's revision from its own `rv:head`, else from
its Sense's head, and pass that exact revision. Only a Concept with neither is
unavailable. Tests: a v1 Concept created through the propositions API works
as a Realm topic and in vocabulary search, and an exact-revision restriction
on it still hides it.
