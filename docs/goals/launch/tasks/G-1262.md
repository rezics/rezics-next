## Outcome

Operational logs from launch's modules carry no personal data: no Agent or
Work IRI, no SQL value, no serialized database error. Trust-ops found these
console sites (each serializes an error object whose database `detail` can
carry an Agent IRI or SQL value, or logs a native IRI):

- `library/status.ts:402`, `library/follows.ts:88`
- `library-import/retention-worker.ts:38`
- `follows/recovery.ts:109` and `:168`
- `zone-browse/store.ts:35` (error object) and `:101` (logs `realm` and `work` IRIs)
- `notification/delivery-worker.ts:30`
- `notification-producers/producer.ts:278`, `:299`, `:613`, `:618`, `:621`
- `realm-directory/worker.ts:46`

Route each through `logWorkerFault` from `packages/observability` (error class
and code only), which trust-ops' G-1260 adds. Leave the fixed strings at
`notification/digest.ts:106`, `producer.ts:269` and `:610`, and
`notification-producers/saved-views.ts:150` as they are.

Guard the class: `services/main/tests/launch-log-privacy.test.ts` scans
`services/main/src/modules/{library*,progress*,reading-position,realm*,space,zone*,presentation,theme,saved-filter,follows,notification*}`
and fails on any `console.*` call whose arguments are not string literals
(or `logWorkerFault`), with the file and line in the message.

## Do not

Change no behavior beyond the log calls, and do not edit `packages/observability`
(trust-ops'). Line numbers may have moved: find each call by its content.
