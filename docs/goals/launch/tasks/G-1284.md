## Outcome

First-of-kind backend contract for launch (L4): a Zone is a site that needs no
Realm. Its home page is a Content document with text and a first-party
Showcase block. Editors save drafts without changing what the public sees, and
publishing the site makes exactly the published revisions public.

Decisions already made (design record
`/home/edge/projects/rezics/rezics-next/.temp/arch-review-2/target-architecture.md`
§7 and §8; launch GOAL.md "Zone is the site"):

- Home and custom pages are Content `DocumentSnapshot`s on the Blocks profile,
  reusing Studio's draft, language version, revision and publish machinery; no
  parallel page AST, no stored renderer spec (json-render or otherwise).
- Showcase is an `extensionBlock` whose definition carries its payload schema
  and version. An unknown block can be saved and exported and renders as an
  explicit placeholder in public. Kernel K2 (C2 first slice, 7adef77bc) has the
  Blocks payload pattern; follow it.
- Saving a page draft never changes the Zone head. A site publication bundles
  exact revisions: page, routes, navigation, theme. The public reads only the
  published bundle.
- Zone does not depend on Realm. A Realm-less Zone uses the same read path and
  renderer as a Zone with a Realm; drop `defaultRealm`'s role in page assembly
  wherever this slice touches it.
- Third-party blocks stay closed by construction. Add one comment beside the
  closed module-type set in `zone/presentation-format.ts` pointing at
  `docs/contracts/api.md` "Platform exposure": whoever introduces a
  third-party block representation calls `requireSelectedPlatformCapability`
  with a refusal test (trust-ops request).

`services/main/src/modules/zone/owner-create.ts` is on loan to kernel's K8a (G-1245); do not edit it.

## Smallest change

- Create a Realm-less Zone through the existing create path (`space/create-zone.ts`).
- Point its home route at a Content document.
- Write that document through the existing Content draft and revision
  operations; call them, do not copy them.
- Add one site-publish operation that records the exact page revision, routes
  and navigation it publishes.
- Give the public Zone home read the published document with its blocks
  resolved; the Showcase block keeps its existing data source.
- Every new operation declares `exposure` and a rate-limit family (launch has
  consent for `read`/`write`; send the public list to the manager before
  merge).

If the Content owner (`services/main/src/modules/content-publication/**`,
kernel's) lacks an operation you need, hand off with the exact request
instead of building around it.

Do not build:
- a page builder, theme engine or navigation editor beyond what the home
  needs;
- a second document store, a block marketplace or third-party blocks;
- web editor UI (a separate task consumes this contract).

Counterexamples through the real API:
- a Zone created with no Realm serves its published home to anonymous readers;
- a saved draft is visible to editors in preview and invisible to the public
  until the site publishes;
- a revoked editor cannot publish;
- a lost publish response replays to one publication;
- an unknown block saves, exports and renders as a placeholder;
- retiring and recovering the Zone keeps the published bundle.
