## Outcome

`apps/web/tests/session-scopes.test.ts` (IAM01: "the main site requests only
declared Main resource scopes, and classifies every one") passes. Trust-ops'
G-1277 (51f6ec5ca) made Account register the closed-group scopes, keep them
out of third-party consent and refuse them in dynamic registration, while
first-party clients may still request them. What remains is launch's
classification in `apps/web/features/auth/scopes.ts`:

- `type:admit`: request it (add to `MAIN_SITE_SCOPES`). Administrators holding
  `platform:use:platform-admin` use it on the main site.
- `wiki:propose` and `quota:reserve`: closed-group scopes. Put them in
  `SCOPES_NOT_REQUESTED` with a one-line reason, unless a web feature already
  calls an operation needing them for granted users (search `apps/web/features`
  for calls to the claims, wiki candidate or quota reservation operations; the
  wiki claims dialog is the likely one). If one does, request the scope instead
  and name the call site in the handoff: hiding the surface for ungranted users
  is G-1236's gate, not the scope list.

## Do not

Do not change Account, the scope registry or the test's rule; classify only.
