## Outcome

Four integration files in launch's area fail on current main, for everyone.
Program and kernel judged the product right and the tests stale. Update the
tests and fixtures, never the product:

1. `g-915-realm-policy` and `g-946-space-settings`: since 2026-10-07,
   `POST /v1/spaces` initializes Realm Access in the same transaction. A new
   Space starts at admin generation 1 with the owner bootstrap written.
   - Drop the tests' second `admin.initialize`.
   - Read the generation from `GET /v1/spaces/{space}/settings` and assert
     relative to it, not to `'0'`.
2. `zone-showcase-disclosure` (2 of 5 fail with 403 `authority_denied` at the
   showcase-editor GETs, ~108 and ~170): Zone editor admission needs the
   content-draft baseline proof, which needs a verified email, and the fixture
   principal has none.
   - Verify the fixture account's email through the Account API, as a person
     would.
   - Don't write the row, and don't relax the baseline.
3. `g-1042-ranking-followups`: `growRealmThreads` stores every filler with a
   NULL parent in `access.realm_thread_reference`, so the capped chain is
   invisible and `complete` is true.
   - Build the parent chain the way a reader's replies would, through the API
     if the fixture can.
   - If a fixture has to stay in SQL for scale, give it the same parent rows
     the API would write, and say why in a comment.
   - `growRealmThreads` lives in `services/main/tests/g-1034-fixture.ts`
     (launch's fixture). Other users of that fixture must keep passing; run
     the g-1034 files that import it.
