## Outcome

Launch closes when each launch kind and the listed Realm and Zone capabilities
pass paired API and browser journeys with real data, including the hard cases
(`docs/goals/launch/GOAL.md`, Completion). Nothing records which tests those
are, so nobody can count what is proved and what is missing. Build that record
in code.

1. `scripts/qa/cases/launch-coverage.ts` (beside `launch-journeys.ts`) exports
   `launchCoverage: readonly LaunchCoverage[]`, one row per kind × capability,
   plus a row per hard case where it applies:
   ```ts
   type Proof = { file: string; test: string } | { missing: string };
   interface LaunchCoverage {
     kind: 'books' | 'recipes' | 'visual-novels' | 'anime' | 'manga' | 'games' | 'realm' | 'zone';
     capability: string;      // what a person can do, in a few words
     hardCase?: 'ambiguous-editions' | 'mixed-formats' | 'non-ui-languages' | 'thousand-chapters'
       | 'revoked-editors' | 'interrupted-exports' | 'two-device-progress' | 'expired-loans';
     api: Proof;              // a tests/qa/integration or services/*/tests test through Main's API
     browser: Proof;          // an apps/web/tests/*.e2e.ts test
   }
   ```
   `missing` names the launch inventory item that will add the proof:
   `L10` (Zone page discussion), `L11` (boards), `L12` (games), `L13` (anime
   and manga opening), `L17` (Zone site authoring), `L19` (manga and game
   progress, two devices), `L20` (recipe import and export), `L21` (real-data
   fixtures), `L26` (showcase), or `gap` when no item covers it yet.
2. Fill the rows from the tests that exist. Capabilities to cover, from GOAL.md:
   - for each catalogue kind:
     - the Work hub and edition choice;
     - catalogue browse and search in its Zone;
     - collection tracking and progress;
     - library import, export and loans (books);
     - authoring, reading and exchange (recipes);
   - Realm:
     - create;
     - membership and admission;
     - roles and team;
     - rules;
     - boards;
     - threads and replies;
     - ranking;
     - moderation and appeal;
   - Zone:
     - site pages;
     - navigation and theme;
     - publication;
     - a Zone without a Realm;
     - attached Realm discussion.

   A test counts only if it exercises that capability through the real API or
   browser; a viewport wrapper or a repeated query test does not make a second
   proof.
3. `apps/web/tests/launch-coverage.test.ts` fails when:
   - a named file is missing;
   - a named test title is not found in its file;
   - a kind has no row;
   - a hard case appears in no row;
   - `missing` is neither one of the item names above nor `gap`.

   It prints the count of proved pairs and the rows still missing, and it does
   not fail on `missing` rows.

Do not write or change any other test; this task only records what exists.
