## Outcome

When a Work's stewardship moves to a new maintainer or controller, the
recipient can work on it in Studio as if they had made it. Trust-ops' G-1338
(2138207d147a) made Studio's backend authority use the current maintained or
controller proof, with writer identity kept as provenance. Two journey gaps
remain, and they are launch's:
1. **Inventory:** the recipient's Studio inventory still selects by the
   original creation actor's admissions, so transferred Works are absent. Find
   Works by current authority, bounded and paged.
2. **Action identity:** chapter UI actions derive their acting identity from
   writer provenance. Act as the current authoring subject, and show the
   original writer as provenance, not as the actor.

A private read grant alone must never enable edits. Use trust-ops' current
authority helper; if the chapter response lacks the current authoring subject,
add it as a field of the read (not a new evaluator).

Not this: no new authority evaluator, no change to writer provenance or
creation records.

Counterexamples:
- A creates a Work and transfers it to B: B's Studio lists it, B edits a
  chapter as B, and the page shows A as the original writer;
- A no longer sees it as theirs to edit;
- C, with only a private read grant, sees it read-only.
