## Outcome

Trust-ops' G-1993 (on main) makes every disclosure read go through the cut
contract (`services/main/src/modules/disclosure/read.ts` header):
`configureDisclosureAncestrySource`, `resolveDisclosureSelections`,
`captureDisclosure` reading the current parent heads, and `fenceDisclosure`.
The contract adds one bounded probe: a batched current parent-head statement
per `DISCLOSURE_COST.parentHeadBatch` (64) targets. Trust-ops found three
launch tests that now fail because they exercise the contract (mail
2026-10-12 11:31 UTC, `.temp/ref/trust-1993-findings.txt`).

| Rule | Sites | Test that must fail without the fix |
|---|---|---|
| A read cost expectation moves ONLY by exactly the parent-head probe: `ceil(targets / DISCLOSURE_COST.parentHeadBatch)` batched statements, constant for a fixed page size. Express the new bound through the imported constant, never a bare number. Prove it at two page sizes (for example 10 and 50 targets): the added count must be the same. If the added cost grows with page size, it is a defect in the adapter: fix it there (one batch per page), do not move the expectation. | `community-read-guards.test.ts` (graphCalls [1,1] became [2,2]), `g-908-collection-page.test.ts` (queries 3 became 5) and the read adapters they cover | The two-page-size assertion fails if the probe is per entry. |
| Realm reply roots get a semantic-head-aware ancestry source: the Realm reply reader registers its owner ancestry (reply, then thread, then Realm) through `configureDisclosureAncestrySource`, so `resolveDisclosureSelections` issues the descriptors before capture. A missing source answers unavailable, never visible. | `access-reply-roots.test.ts` (live DB, DisclosureStore checkout counts), the Realm reply read adapter | The live-DB test passes with the source; a test with the source removed answers unavailable. |

`composition-target-batches.test.ts` belongs to G-2032 (running); leave it
alone. Kernel owns the search, typeahead and summary callers and
`private-name-kernel-reads.test.ts`.
