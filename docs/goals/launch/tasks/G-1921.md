## Outcome

Read-only design pass; change no code. Program decision (2026-10-11 22:21 UTC).

A published Zone home document has no identity of its own. Its Content must use
the Zone ID as its resourceId (`services/main/src/modules/zone/configuration.ts`),
and a Zone has no admitted target base (`services/main/src/modules/media/summary.ts`).
So nothing can be "about" a home page. Launch's L10 discussion found it first;
the entry is hidden on home frames for now.

Answer two things, each with file and line:
- **(a) The smallest identity for a published home document.**
  - It is its own resource, with an exact revision and roots retained across
    edits, published through the Zone publication owner.
  - Which owners change: Zone publication, Content, media summary, and any
    other.
  - What migrating existing Zones costs: a data migration or a lazy assignment,
    and how many rows.
  - How its URL and the Zone URL relate.
  - Reuse the existing graph and resource mechanisms; no new domain backend.
- **(b) Every other function that has to be about a home page and cannot be
  today.** For each, state whether it can name content on a home page, and if
  not, where it fails:
  - a rights notice or takedown against home content;
  - a report;
  - moderation;
  - history and revisions;
  - erasure;
  - search;
  - anything else you find.

The program classes the item from (b): if a notice or report cannot name home
content, it is A; if discussion is the only one, it is B. Put (b) first in your
handoff.
