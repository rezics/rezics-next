## Outcome

G-1590 measured one reader's Realm reply through the product commands (draft,
identity, review, placement) at 720–1,044 ms on a QA stack, and slower as the
Realm grows. Writes go through the API, and a slow write path is a product
defect.

Judge this by algorithm, not by this machine's speed. The cost of one reply
must stay constant as the Realm and thread grow, touching only its bounded
neighbourhood: the parent, the thread root and the Realm's counters.
1. Profile one reply's four commands on a Realm with 100 and with 1,000
   threads, using G-1590's corpus once it exists, or a smaller seeded one.
   Record per command: Postgres statements, Fuseki requests, and anything that
   scales with Realm or thread size (full scans, unbounded projections, a
   recount).
2. Fix every cost that grows with size: index it, keyset it, or update
   incrementally. Merge round trips the commands repeat (re-reading the same
   head several times). Keep every authority and disclosure check.
3. Add `services/main/tests/realm-reply-write-cost.test.ts`: one reply's
   statement and request counts are equal at 100 and 1,000 threads, and under
   a named budget.

Report the before-and-after breakdown and the wall time per reply. If the
route file name differs, use the real one and say so.
