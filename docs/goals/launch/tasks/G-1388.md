## Outcome

Diagnose first. G-1372's browser journeys hit two seed failures. Both seeds
go through the API:
1. Wiki (`g-856-wiki.e2e.ts`): `POST /v1/zones/{id}/mounts` returns 400
   `invalid_request`, "Persisted profile validation rejected the request".
   Integration fixtures hit the same message when raw graph writes left
   native membership incomplete (kernel's fixes 4c98d4bf7, 23d7ea59f, and
   launch's G-1383). Find out whether this seed, or something it calls,
   writes raw facts. If it does, move it to the API. If it uses only the
   API, an API sequence leaving a populated list unwritable is a kernel
   product defect: report the exact request sequence and the native report
   under BLOCKERS.
2. Catalogue (`g-853-zones.e2e.ts`): `POST /v1/compositions/{id}/changes`
   returns 409 `read_basis_changed`. A client that writes against a read
   basis must re-read and re-apply its intent on 409 (the reader-store
   rule). Make the seed do that, bounded. Don't blind-retry the same
   request.

Never weaken an assertion. If a journey still fails after the seeds succeed,
report the product failure.
