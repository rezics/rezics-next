## Outcome

Inventory item L19, slice 4: a correctness repair. The sizing is staged at
`.temp/ref/g-1747-sizing.md` ("L19 — typed progress"; games). Today's game
progress (`apps/web/features/tracking/game-progress.tsx:55`):
- reads only the first required part for an unfinished "Played" status;
- writes whole-game status over the parts that happen to be loaded;
- pages required parts inside optional routes;
- leaves stale display after a partial failure.

Fix it so that:
1. With more than 20 required parts, every one stays reachable (page through
   the required parts on their own, not inside optional routes).
2. Incomplete paging never claims whole-game completion. A whole-game write
   covers every required part, or says it cannot.
3. An unfinished play survives a reload.
4. After a later write fails, the earlier successful writes stay visible and
   the failure is shown.

Prove it in `apps/web/tests/game-progress.test.ts` (component and adapter) and
in stories for the paged, partial-failure and reload states. Use the existing
tracking API helpers; change Main only if a needed read does not exist (report
under BLOCKERS rather than adding one).
