## Outcome

Read-only; change no code. Write one file, `.temp/journey-map.md`, in your
worktree; the manager copies it into each journey worktree. Today's Luna journey
sessions spent about three quarters of their commands searching and reading
(program, 2026-10-11). This map replaces that search. Keep it under 600 lines.
Every entry gives a file path and line, and each helper its exact signature.

Sections:
1. **How to run and read one journey:**
   - `task goal -- test apps/web/tests/<file>.e2e.ts`;
   - where the QA run keeps `e2e.xml`, `playwright/*/error-context.md`,
     screenshots and `logs/e2e-main.log`;
   - how to read a failure;
   - the warm stack pool;
   - one call per step.
2. **Sign-in and identities:** the helpers that sign in a member, a moderator
   and a Zone or Realm owner, and open a second browser context (second
   device), with their signatures and an example call.
3. **Seeding through the API:** each seed helper in `apps/web/tests/*seed*.ts`
   and `tests/qa/fixtures/**`, what it creates, and its signature. Name
   `grantFixtureAuthority` (services/main/src/modules/access/fixture-authority.ts)
   as the only way to grant authority; a guard now fails direct writes.
4. **Existing journeys by surface:** a table with one row per
   `apps/web/tests/*.e2e.ts`. Give the surface it covers (Realm, Zone editor,
   Zone site, books, anime, manga, games, recipes, library, composer, search,
   identity), its test titles, and which one to copy for a new journey on that
   surface.
5. **Selector and waiting conventions:**
   - role and name selectors;
   - hydration waits (`waitForReactHandler`);
   - menus and dialogs;
   - the projection catch-up patterns the passing journeys use, and the
     anti-patterns reviewers rejected.
6. **API routes per surface:** the web feature folder and the Main routes it
   calls, for the surfaces in section 4.
7. **Registry:** how a passing journey is recorded in
   `scripts/qa/cases/launch-coverage.ts`, and its validator test.
