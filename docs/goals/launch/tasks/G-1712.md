## Outcome

Program decision (2026-10-11): class A. A guard that misses 198 statements is
a false ruler.

`services/main/tests/realm-reply-write-cost.test.ts` guards one Realm reply's
four commands (draft, identity, review, placement) with
`REALM_REPLY_WRITE_COST`. It reports 514 SQL because:
- its fixture app omits Account verification (198 statements);
- it omits governance, so `composeDisclosure` configures no disclosure reader
  (10 Access statements each in draft and identity).

Launch's analysis measured the complete owner composition with the shared
meter, identical at 100 and 1,000 owner threads. It is staged at
`.temp/ref/g1619-spec.md` ("Measured baseline", "Measurement method") and
`.temp/ref/g1619-breakdown.md`.

| Command | Content | Access | Account | SQL | Fuseki reads | Guard calls |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Draft | 14 | 113 | 54 | 181 | 27 | 27 |
| Identity | 13 | 113 | 54 | 180 | 30 | 32 |
| Review | 12 | 63 | 18 | 93 | 3 | 5 |
| Placement | 24 | 182 | 72 | 278 | 10 | 13 |
| Total | 63 | 471 | 198 | 732 | 70 | 77 |

Do this:
1. Build the fixture app from the production composition, with Account
   verification and governance, so the disclosure reader is configured. Do not
   stub any owner behaviour.
2. Measure with the shared meter (`foregroundCounted()`, `meterPool` over every
   owner pool including Account, `meterFuseki`). Keep the existing guard-call
   convention, and itemise graph reads separately.
3. Replace `REALM_REPLY_WRITE_COST` with an itemised guard per command and per
   owner (Content, Access, Account, total SQL, Fuseki reads, guard calls). Set it
   at the measured counts, which are deterministic, with a comment naming each
   owner's share. Any growth fails.
4. Keep the 100- versus 1,000-thread equality, now per command and per owner.

Every decision test in the file must keep passing unchanged:
- hidden root 404;
- missing question 403 before admission;
- sealed and unsealed refusals;
- retry after visibility.

If your measured counts differ from the table, report both and use yours.
Change no product code; this task only corrects the ruler. The batching that
would lower the counts is a separate, deferred item.
