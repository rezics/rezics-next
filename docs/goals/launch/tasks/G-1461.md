## Outcome

G-1432 shipped the Zone home page editor (`/manage/z/[space]`). The
manager's screen review (QA 20261008t130207-5642af) asks for three things
next.

1. **Writing first on a phone.** At 390 px, four full-width buttons (Save
   draft, Publish, Preview, View site) sit above the editor and push the
   writing area below the fold.
   - Give the actions a compact row or a sticky bar: one primary action
     (Publish), one secondary (Save draft), and Preview and View site as
     lighter actions.
   - The editor's first lines are visible without scrolling, at 390 px and
     at 1280 px.
   - States (draft only, stale, publishing) stay as clear as now.
2. **Entry from Manage.** Someone who may edit a Zone finds "Edit site"
   where they manage it, for a Realm-less Zone and for a Realm's Zone. Use
   what Manage's navigation already shows. Don't add a second list of Zones.
3. **Navigation.** The author edits the Zone's navigation: add a link to a
   page or route the Zone has, rename it, reorder it and remove it. Save it
   as a draft and publish it with the site, using the Zone's existing
   navigation component and its revision (`navigation`, `navigationRevision`
   in the Zone configuration), through the existing APIs and command keys.
   A stale save keeps the author's edits, as the home page editor does. If an
   operation is missing, report it under PROPOSED TASKS; don't change the
   API.

Theme editing is a later slice. Strings come in all eight locales, with
non-English marked for native review.

Extend `apps/web/tests/zone-site-authoring.e2e.ts`, keeping every existing
step:
- open the editor from Manage;
- add and reorder two navigation links, publish, and check the anonymous
  site shows them in that order;
- remove one and republish;
- take 390 px and 1280 px screenshots of the editor with the writing area
  visible.
