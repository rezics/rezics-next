## Outcome

Class A, found by launch's Realm roles browser journey (G-1715, branch
`goal/g-1715`, `apps/web/tests/realm-community.e2e.ts`, QA
`20261011t163034-c6206b`).

A moderator creates a role:
`POST /api/main/v1/realms/{id}/role-changes` answers 201, and the page shows
"Role saved." It then still shows "No roles yet", with no heading for the new
role.
- `roles-view.tsx:91` calls `router.refresh()` after the save.
- `read.ts:85` reads `GET /v1/realms/{realm}/roles` with the acting subject.
- So the server read, or what the page renders from it, does not include the
  role just created.

1. Find the exact cause, with file and line. Possible causes:
   - the roles read is a projection that lags the write;
   - a cache, or Next's router cache, serves the old list;
   - the read filters out a role with no members or with an acting subject
     mismatch;
   - the command writes somewhere the read does not look.
   Reproduce it with the G-1715 journey or a focused test.
2. If the cause is in the web app, fix it in this claim. After a successful
   save the list shows the role, without inventing state the server has not
   confirmed. If the read lags the write by design, render the receipt's role
   until the read includes it.
3. If the cause is in Main (`services/main/src/routes/realm-admin.ts` or its
   modules), change nothing there. Report the owning file, the exact fix and
   a test, under BLOCKERS; the manager routes it to the owner.
4. Add a focused test that fails before the fix and passes after it. Rerun the
   Roles journey once: `task goal -- test apps/web/tests/realm-community.e2e.ts`
   from your rebased branch, with G-1715's file brought in read-only (do not
   commit it).

QA economy (program, 2026-10-11): one `task goal -- test a b c` call for all files a step needs (one stack, not one per file); prove at the lowest tier that proves it (unit/owner needs no stack; integration only across a service boundary); rerun a file only after a change that could affect it, never "to be sure"; heavy non-test commands (web build, depcruise, type-aware lint, yarn install) one at a time and not during your own QA run.
