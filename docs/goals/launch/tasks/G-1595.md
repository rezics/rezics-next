## Outcome

Launch's completion criteria pair every hard case with an API journey and a
browser journey. Two exist only in the browser:
- interrupted exports: `apps/web/tests/g-856-library-export.e2e.ts` ("download
  interrupted by reload resumes where it stopped", 1,200 records);
- expired loans: `apps/web/tests/library-loans.e2e.ts` (overdue loan, extend,
  return).

Add the API half of each, against the same public operations the web uses:
1. `tests/qa/integration/library-export-resume.test.ts`:
   - a reader with 1,200 library records starts an export and reads part of
     it;
   - the client stops (drop the connection or abandon the cursor);
   - resuming from the last acknowledged position yields every remaining
     record exactly once, in order, with no duplicates or gaps;
   - restarting from scratch also works;
   - the export's read cost stays bounded per page.
2. `tests/qa/integration/library-loans-expiry.test.ts`:
   - a loan past its due date reads as overdue;
   - extending the due date clears it;
   - returning the loan ends it;
   - whatever access the loan granted ends when it expires or is returned,
     as the product defines it. Read the loan module to see what a loan
     grants, and assert exactly that.

Seed through the API. If the product misbehaves (duplicates, gaps, or access
that survives expiry), report it under BLOCKERS with request, status and body,
and don't work around it.
