## Outcome

Program class A (2026-10-12 11:32 UTC): visual novels are in the first public
scope, and the launch registry (`scripts/qa/cases/launch-coverage.ts`) has the
VN "Work hub and edition choice" row unproved on both API and browser.

Prove it on the VNDB corpus (`scripts/dev/seed/vn-catalogue-step.ts`, the
seeded VNDB Works and their releases), using the SAME Work hub the books use.
The books' proofs show the shape:
- API: `tests/qa/integration/g-835-series.test.ts` saves an exact realization
  and release preference through Main, and the hub summary names the
  selected edition.
- Browser: `apps/web/tests/g-743-hub.e2e.ts` and `g-850-hub.e2e.ts` (journey
  `work-hub`): open the hub, pick another edition by keyboard alone, save it,
  reload, and see the persisted label. Run it at a phone and a desktop width.

For a visual novel the editions are its VNDB releases (language, platform,
release date, and the age rating where the source licenses it). Cases:
1. A signed-out visitor opens a VNDB Work's hub and sees its releases with
   language and platform. There are no edit controls.
2. A signed-in reader chooses a release by keyboard, saves it and reloads; the
   hub names the chosen release. A second device reads the same preference.
3. A VN with one release shows it without a needless chooser. A VN with many
   releases pages or groups them within the hub's existing bounds.
4. CJK titles and release names render (Japanese interface and Japanese
   original titles).

If the hub is wrong for a VN (it says "edition" where a release is meant, drops
platform or language, or shows book-only fields), that is the finding: fix it
in the hub (launch's area; widen the claim with `--allow-area` and say so in the
handoff), with a story for the VN state. If the defect is in a Main read or the
VNDB import (`source/field-vndb.ts`, `vndb-concept-run.ts`), stop and report
the exact field and the read; the manager routes it.

The registry row is NOT yours; the manager updates it after you land.

## Decision on the release date (manager, 2026-10-12 11:36 UTC)

The VNDB import keeps only the release YEAR (`publicationYear`;
`tests/fixtures/vndb/load.ts:156`, `vn-catalogue-step.ts:335`), and Main's
`ReleaseView` exposes no full date. A year shown as a year is honest, not
wrong. Prove the hub with what Main returns: language, platform and year. The
full-date preservation through import, storage and the Main read is named
class B (manager to program), and it does not block this task. Do not edit the
import or Main for it.
