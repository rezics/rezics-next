## Outcome

On main, a freshly published recipe's Work page shows "The wiki could not be
loaded" in Explore the wiki (`recipe-published-phone.png` in QA
20261008t140122-183e4f; the same since QA 20261008t092836-2d8d73). A recipe
has no wiki, so the section should say so. Instead one of its reads fails.

`readWikiZone` (`apps/web/features/work-page/wiki-server.tsx`) reads the
entity projection (`readEntityProjection`), then the Work's Statements
section (`readStatements`), and returns the first failure. Find which of the
two fails and how.
1. Run `apps/web/tests/recipe-authoring.e2e.ts` with a temporary log in
   `readWikiZone` of each read's HTTP status, problem code and message, and
   the Statements href.
2. Report the failing request, its status and code, and the server function
   that throws (from `logs/e2e-main.log` in that QA run). Remove the log
   before committing.

Then:
- If the failure is in launch's web code (the wrong href, a missing acting
  subject or position, a failure treated as fatal where the API means
  "nothing here"), fix it here. A Work with no wiki-Zone Statement shows the
  section's "no wiki" state, and a real outage still shows the failure.
- If the server fails, for example a 503 because Statement seek coverage
  isn't current for a just-published Work (`reading_seek_unavailable`,
  `work_read_unavailable` or similar), change no server code. Report the
  request, the code, the message and the owning module under BLOCKERS. The
  manager routes it.

In both cases, add a unit test for the mapping you rely on (`wiki-server.test.ts`).

## Do not

Don't hide a real failure behind "no wiki", and don't edit the journey or
change services/.
