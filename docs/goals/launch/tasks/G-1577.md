## Outcome

These browser-side reads of public data go out with the session cookie but no
acting subject:
- `concept/concept-works.tsx:26`
- `discover/query.ts:14`
- `discover/shelf.tsx:88`
- `communities/setup-checklist.tsx:26`
- `post-composer/composer.tsx:142,178`

A public read must not carry credentials it doesn't use:
- a cookie on a public read makes the response depend on who's signed in;
- it defeats shared caching;
- it can leak a private reading into a page meant to be public.

`browser.ts` already has an anonymous client (`credentials: 'omit'`). For each
site, decide:
- if the read is public, use the anonymous client;
- if it really is a signed-in read, pass the acting subject the API needs.

Say which you chose for each site under CASES. Line numbers may have moved;
find each by its read.

Add `apps/web/tests/public-read-credentials.test.ts`, a scan in the style of
the closed-operations guard. A browser-side call to a public read operation
either uses the anonymous client or passes an acting subject. Make it fail on
the old code.
