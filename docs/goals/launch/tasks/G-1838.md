## Outcome

New red on main, class A, caused by launch's G-1736 (program, run 11):
`apps/web/tests/public-read-credentials.test.ts` › "browser Main reads match
the route class" fails. The guard requires a browser call to any route that
reads the bearer to carry the session; anonymous transport is only for routes
classed public. G-1736 switched these calls to the anonymous browser option:
- `features/search/browser.ts`: `.v1.search.typeahead.get(` reaching
  getV1SearchTypeahead;
- `features/discover/topic-picker.tsx`: `discoveryApi()` reaching postV1Query,
  getV1DiscoveryConcepts, getV1DiscoverySections and getV1Rating-populations;
- `features/concept/browser.ts`: `readConceptWorks()` reaching postV1Query.

The guard's expected list also no longer shows its one known entry
(`features/new.tsx: .v1.works.get( reaches getV1Works, which has no read class`).

The program classed G-1736's anonymous-reads work B, and the existing guard is
the rule on main. So:
1. Restore session transport at these call sites for every page, signed in or
   not. A signed-out browser has no session to send, so its result is the same.
2. Update `apps/web/tests/public-reads-anonymous.test.ts` (G-1736's test) to
   match: these reads keep the session. Remove or adjust only the assertions
   for these sites.
3. Find why the `features/new.tsx` expected entry no longer appears. If a later
   merge legitimately gave that route a read class or removed the call, say
   which commit, and only then update that one expected line in the guard
   (`public-read-credentials.test.ts`, which you may then edit for that line
   only). Otherwise leave the guard untouched.

The guard must pass with no other change to it.
