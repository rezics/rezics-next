## Outcome

G-1413 (92a888dbd) added `services/main/tests/contribution-draft-route.test.ts`.
Its first case, "draft GET spends the exact-draft budget on the current Work,
the anchor and the identity", passed on the G-1413 branch (QA
20261008t092508-e629a0). It now fails on main, run alone (QA
20261008t104006-9168f7): the draft GET answers 503 instead of 200. The test's
fake Fuseki throws `unexpected draft query: …` for any query it doesn't
expect, so production code on main now sends one more query on this path. No
commit since 92a888dbd touches `routes/contributions.ts` or
`modules/contribution/`; the extra query comes from something they call.

Find out, and report:
1. The exact unexpected query: add a temporary log of the thrown message,
   run the test, and remove the log before committing.
2. The function that sends it, and the commit that added it
   (`git log -S` or bisect between 2d5be3df4 and main).
3. Whether the query runs inside the exact-draft budget
   (`fusekiReadBudget`) or outside it.

Then:
- If the new query is a defect in this read path, launch's area (for
  example a repeated or unbounded read), fix it at its source and the test
  passes unchanged.
- If it's legitimate production behaviour from another owner, change no
  code and no test. Report the query, its owner, the commit and whether it is
  budgeted, under BLOCKERS. The manager decides the test change.
