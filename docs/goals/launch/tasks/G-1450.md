## Outcome

The program's bisect (G-1428) shows two cases of
`services/main/tests/library-write-scope.test.ts` failing on main since
launch's G-1365 (75474eed6):
- "PUT /v1/compositions/{id}/occurrences/{occurrence}/progress refuses
  read-only consent before ownership, owner records or graph writes"
- "the denial matrix covers every declared and mounted personal-record
  mutation"

G-1365's progress order projection changed what the read-only PUT does, and
it added the owner method `progress.configureOrderProjection`, which the
denial matrix doesn't list. This is the H4 class (trust-ops'
`.temp/trust-ops/security-findings.md` §4): a `work:read`-only token must be
refused before any owner write, and that includes the projection.

Make the read-only refusal come first again on this route, before the order
projection and any owner record. Declare `progress.configureOrderProjection`
where the matrix's declared personal-record mutations live, with its
`library:write` requirement, so the matrix covers it. Change no assertion. If
declaring it needs an access-module change beyond a declaration, list it
under OWNER CHANGES for trust-ops' review.
