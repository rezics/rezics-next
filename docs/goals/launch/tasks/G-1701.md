## Outcome

A launch regression. A signed-in reader's small public projection page answers
503:
- The page and reading-boundary summary adapters repeat name-owner queries for
  resources whose just-loaded graph rows already prove they are not Agents.
- That exhausts the 160-call Fuseki budget. The final fence's 161st query raises
  `FusekiReadBudgetExceeded`, wrapped as `DisclosureUnavailable`.
- Commit 3fd6f5303 made the owner optimization opt-in and enabled it only for
  `WorkReadSession.summaries` and `targetSummaries`, so four page adapters were
  left out.

The full analysis is staged at `.temp/ref/g1678-disclosure-spec.md`. Implement
its "Exact implementation" and "Tests" sections:
1. Pass the existing `settleNonAgentNameOwners: true` in each `SummaryInput` of:
   - `entity-page/read.ts` `resolveSummary` and `visibleResourceReferences`;
   - `entity-page/relations.ts` `readPageRelations`'s `summarize`;
   - `reading-position/boundary.ts` `disclosureSummaries`.
2. Extend `services/main/tests/community-read-guards.test.ts` over the four
   adapters:
   - known non-Agent references skip the redundant owner query;
   - private Agents and absent or untyped references still probe and stay
     indistinctly unavailable;
   - mixed batches stay covered.
3. In `tests/qa/integration/scoped-subjects-support.ts`, build the read app from
   `...stack.composition.dependencies` before the fixture overrides, so
   acceptance exercises production governance and reading-position owners.
4. Extend `tests/qa/integration/scoped-subjects-acceptance.test.ts` with a
   separately granted reader:
   - grant exactly the journey's semantic and Work read grants;
   - finish preparation and index catch-up, then measure only the projection
     page GET (`CountingFuseki.queries`);
   - assert 200, the expected subject, episode frame and fact, and the complete
     request within `WORK_READ_COST.graphCalls`;
   - cover anonymous, hidden, absent and final-fence revocation.

Do not:
- change `WORK_READ_COST`, retry a 503, or drop the opening or final disclosure
  pass;
- cache authorization across reads;
- grant the reader a platform capability, or change fixture publicness.

Agents and missing or untyped identities keep their probes. Keep every SQL
policy, recovery, owning-Work head, media and final authority fence.
`media-summary-disclosure.test.ts` and `disclosure-name-policy.test.ts` must
still pass unchanged.

## Decisions since this brief (trust-ops, 2026-10-11)

Trust-ops accepts the flag on one condition. `settleNonAgentNameOwners` skips
the probe only for ids with a loaded non-Agent row. So a hidden non-Agent id
would cost one probe less than an absent id: a hidden-versus-absent difference
in read count and cost, and at the margin a 200 versus a 503.

- For each of the four adapters, add the hidden-id equality case with
  `tests/qa/support/hidden-id-equality.ts`. The same request, once with a hidden
  non-Agent id and once with an absent id, must show the same foreground read
  counts, the same cost fields and the same response. Register each read in
  `scripts/static/hidden-id-reads.json` with
  `bun scripts/qa/hidden-id-equality.ts --write`.
- Include the same pair for `WorkReadSession.summaries` and `targetSummaries`,
  so the existing gap shows. If that pair differs, report it as a finding for
  trust-ops; it is not this task's to fix.
- If an adapter's pair differs, the flag is not allowed there as it stands. The
  accepted owner-side fix makes the settle decision independent of row
  presence: an id the loaded graph read proves absent takes the same path as a
  proven non-Agent, and neither probes. That change is in trust-ops'
  `media/summary.ts`; report it under BLOCKERS rather than editing it.
- No decoy probes and no padding. Report the hidden-versus-absent counts per
  adapter.
- Trust-ops, follow-up the same day:
  - G-1701 adds its read entries to `hidden-id-reads.json` with the generator
    and lands with `--allow-scope` (trust-ops' G-1628 does not run this round).
  - If a pair differs, launch makes the owner-side settle change in
    `services/main/src/modules/media/summary.ts` (claimed here; trust-ops'
    G-1626 does not run this round). The change is limited to settling absent
    ids the same as proven non-Agents, and only if the proof that an absent id
    cannot be an Agent name owner holds; otherwise no flag for that adapter.
    Agent and private-Agent paths still probe.

## Decisions after attempt 2 (trust-ops, 2026-10-11)

- Registry: G-1701 adds its four reads, and only those exact reads, to `scripts/qa/hidden-id-equality.ts` (the source registry) and their route equality cases to `tests/qa/integration/hidden-id-equality.test.ts`. It regenerates `scripts/static/hidden-id-reads.json` with the generator and lands with `--allow-scope`; trust-ops' G-1628 does not run this round.

Extend the same owner-side settle to those two paths if the same proof is available there, and add their pairs (2/2 and equal `graphQueries`) to the same equality test. If the proof is not available (a different graph read shape), say why and stop; trust-ops briefs it separately. Never hide the cost field as a substitute.
- Kernel consents (2026-10-11): a minimal change in `work/read-session.ts`, landed with `--allow-area`, on four conditions:
  - the same settle rule as `media/summary.ts`;
  - equal hidden and absent cost and reported `graphQueries` for every outcome, with the equality test and the registry entry;
  - the option or proof passed from the read already made, with no new query path and no change to cursors or response shapes beyond `graphQueries`;
  - the commit mailed to kernel on landing (kernel's G-1591 rebases on it).
