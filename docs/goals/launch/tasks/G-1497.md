## Outcome

Regression run 5 (program G-1487, `.temp/goal-program/integration-triage-run5.json`,
cluster `request-cost-contract`) fails 10 integration files deterministically
since 78659e73a ("Community: batch live rule and banner reads and guard API work
at scales"), with `services/main/src/modules/realm/profile-cost.ts` named as
the owner:
- the threads profiles make 25 Fuseki requests against a cap of 17;
- the other community surfaces make 16 against 15, and 8 Postgres statements
  against 6.

That commit installed the caps, and the routes exceed them. Fix the reads,
not the caps: find the extra round trips (an unbatched per-item read, a read
repeated per section, a hydration done twice) and remove them, so each
profile meets its cap and stays flat as realm size, follows, history depth,
memberships and unrelated works grow. Change a cap only if it was wrong, and
say why in the commit.
