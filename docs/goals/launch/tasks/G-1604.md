## Outcome

Progress is recorded on occurrences (parts: chapters, episodes, game parts).
A Work with no parts, such as most visual novels from the VNDB catalogue,
which is in launch's public scope, has no occurrence to mark. A reader can't
say they're playing it or have finished it (found while landing manga and game
tracking).

Give a partless Work the same progress meaning as any other Work, through the
existing progress model. Don't add a second representation:
1. Find how the progress model treats a Work's own standing (started,
   completed, abandoned) versus per-part completion, and whether a Work-level
   occurrence or the Work itself is the right target. Record the decision and
   its reason under CASES.
   - If the model has a Work-level progress record, use it.
   - If it needs one, add it in the progress module with the same
     expected-version write and conflict handling the episode panel uses.
2. The tracking UI for a partless Work offers what fits a whole Work: not
   started, playing or reading, completed and dropped, with undo. The other
   device sees the same state.
3. Paired journeys:
   - API: `tests/qa/integration/partless-progress.test.ts` (mark completed on
     one session, read it on another, undo, conflict on a stale version);
   - browser: `apps/web/tests/partless-progress.e2e.ts` (two contexts at
     390 px, a visual novel with no parts, mark playing then completed on one,
     see it on the other, and a screenshot).
   Seed through the API.

Keep the write and the read bounded: one Work, constant statements.
