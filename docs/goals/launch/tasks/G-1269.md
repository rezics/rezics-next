## Outcome

A notification never reveals an Agent's private profile name to a recipient
who may not see it, on any delivery channel (in-app, mail, push). Today
`services/main/src/modules/notification/subjects.ts` builds the actor as
`{ id, name }` straight from `publicAgent(...)` (`currentNotificationAgentReader`,
around lines 91, 99 and 115), bypassing the private-name check trust-ops added
in G-1259 (fbb0dd726) under `services/main/src/modules/disclosure/`
(`name-policy.ts`, `notifications.ts`).

Gate the actor's name for the actual recipient and channel before the
notification is composed or sent: keep the id; when the name is private for
that recipient, omit it (the existing unnamed-agent rendering applies) rather
than substituting another value. Use the disclosure module's functions; do not
write a second name policy. Details:
`/home/edge/projects/rezics/rezics-next/.temp/trust-ops/private-name-callsites.md`
(row "Notification actor descriptions").

## Do not

Do not edit `services/main/src/modules/disclosure/**` or
`services/main/src/modules/profiles/**` (trust-ops'; shared Agent cards are
their G-1268). Bounded work: one batched name read per notification batch,
not one per recipient-actor pair if the module offers a batch form.

## Checks

```sh
task goal -- test services/main/tests/notification-actor-name.test.ts <existing notification unit tests>
bun node_modules/typescript/bin/tsc --project services/main/tsconfig.json
```

Counterexamples: an actor with a private name notifying a non-controller
recipient shows no name in in-app and mail; the same actor's controller sees
the name; a public name shows to everyone; a name made private after the
event is not revealed by a later delivery.
