## Outcome

Kernel's G-1465 (f647b38d4) makes `GET /v1/recipes/works/{id}` fill a page
depth-first across sections. Each page holds up to 100 occurrences within
a constant read bound per call, so a two-section, four-step recipe is one
call. G-1444 added an interim walk for the reader's first view and each
"Show more": `RECIPE_READER_PAGE_BUDGET`, which follows `next` up to 6 calls
or 100 occurrences, because kernel's pages used to end at every section
heading. The walk is now a second mechanism with no reason to exist.

The reader reads one page per view: the first view is one call, and each
"Show more" reads one more page. Remove `RECIPE_READER_PAGE_BUDGET` and its
walk. Keep the error behaviour G-1444 settled:
- a failed first page is the recipe region's failure only;
- a failed later page keeps what is shown and offers "Show more" again;
- nothing throws out of `readRecipeWorkPage`.

Keep the editor's full read before structure writes exactly as it is. Update
the unit tests to the one-page rule.
