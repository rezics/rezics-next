## Outcome

Found while landing manga and game tracking:
- `GET /v1/reading-positions/{work}?position=mine&limit=1` returns the resume
  item (`scope: "resume"`) without the chapter label that a positions page
  already attaches to its items.
- So when the last-read chapter lies past the page the panel has loaded, the
  panel shows "Continue from" with an unnamed part.

The resume item should carry the same label fields as a positions page item,
read through the same bounded label lookup:
- one occurrence, so a constant number of reads;
- a label that is private or missing reads as absent, never as an error.

Then the panel names the chapter, or the episode, from the resume item itself.

Add `services/main/tests/reading-position-resume-label.test.ts`:
- a 1,200-chapter structure with chapter 1,150 read: the resume item names it;
- an unlabelled occurrence resumes with no label;
- the read's statement count doesn't grow with the structure's size.

Update the web mapping and its unit test.
