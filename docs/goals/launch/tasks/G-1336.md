## Outcome

Recipes are a launch kind. A cook can create and edit a recipe in the browser:
- title and description in the recipe's own language;
- yield and timings;
- ingredient sections with quantities, units and notes;
- ordered steps, which can reference ingredients.

They can publish it and read it back on its Work page, which
`work-page/types/recipe.tsx` already renders.

Kernel's K8a (G-1245, 0efe4da103dd) moved Recipe create, change and read onto
the existing Composition operations; the duplicate recipe transports are
gone. Use those operations through the generated SDK. Writes follow the
reader-store rules (one write in flight, a 409 re-applies only the newest
intent, no browser-side queue).

Design: comparable products (BBC Good Food, NYT Cooking) show the need: fast
ingredient entry, reorderable sections and steps, a clear preview. Decide by
best practice; do not copy their layouts. It must work on a phone. Keyboard
entry of an ingredient line should be one field that parses quantity, unit
and name, editable as parts.

## Do not

No recipe backend, no browser-managed persistent write sequence, no nutrition
calculation beyond what the API already returns. Hand off if the Composition
API lacks something the editor needs.

- a step referencing an ingredient;
- a stale edit from a second tab;
- reload;
- the published Work page.

marked for native review).
