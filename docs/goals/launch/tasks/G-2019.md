## Outcome

Class A, the cover-inventory finding (program 05:34; trust-ops' G-1981 read
side is on main). `zone/campaign-art.ts` asks disclosure about the Asset and
its Use. Request the EXACT Use attachment only: the Use id the page references
plus its Asset. Then an Asset that is also attached elsewhere, through a
private or restricted Use, neither hides nor exposes this page's image. The
contract and examples are in `services/main/tests/media-disclosure-attachments.test.ts`
(18 cases), with the read side in `services/main/src/modules/media/store.ts`
and `media/visibility.ts` on main.

Tests, first and failing:
- a campaign-art page whose Asset is also attached to a restricted or private
  Use still renders its own public image;
- the reverse: an unrelated restricted Use of the same Asset does not leak
  through this page.

## Step review (2026-10-12 09:33 UTC): exact parent revision

`campaign-art.ts:85` calls `disclose` with `work: realm` but no `workRevision`,
so `DisclosureStore`'s `workRevision IS NULL` predicate applies a restriction
on an old Realm head R1 while R2 is current, and hides the image. This is the
same class as F7's exact-revision rule. Pass the Disclosure owner's resolved
current-parent revision on both the Asset and the Use target, or call the
owner's API that resolves it; never omit it. Test: a restriction on R1 with R2
current shows the art, and a restriction on R2 hides it. Search the change for
any other disclose call without the parent revision.
