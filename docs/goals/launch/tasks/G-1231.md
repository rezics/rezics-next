## Outcome

A person can reach every Saved Filter they own: the list pages with a cursor
instead of stopping at 100 with `complete:false`, and a request bound is no
longer a product limit. Today a counter rejects the 51st named filter
(`saved-filter/contract.ts:15,38–45`, `store.ts:57–61,82–84`, Access
migration 840 line 11), the list offers no cursor, and
`routes/saved-filters.ts:55–58` sends up to 100 Concepts to a summary read
limited to 64 (`media/summary.ts:451–455`).

Evidence: `/home/edge/projects/rezics/rezics-next/.temp/goal-launch/scale-showcase-evidence.md`, "Task C" item 2. Saved views stay closed behind their platform
gate (trust-ops T5); this task does not open them.

## Smallest change

Drop the `named_count <= 50` ceiling (migration 1428) and its counter; a
principal-class rate limit already bounds abuse. Add a keyset cursor over the
existing listing index (check that nullable pin positions order correctly), with
a page no larger than the summary budget. Keep the eight display tabs and the
per-filter typed refusal; add a regression where an unsupported filter is
followed by a valid one and the valid one still delivers.

Do not build a Saved View engine, a second listing index, a summary service or
an exposure change.
