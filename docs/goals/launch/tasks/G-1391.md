## Outcome

Diagnose, then fix where the cause lives. In G-1388's run of
`g-853-zones.e2e.ts`, a signed-in reader opening the Visual Novels Zone's
browse page filtered by release
(`/…/visual-novels/site/browse?releaseLanguage=en&releasePlatform=Switch`,
`apps/web/tests/journeys/zones.ts:389`) sees "Couldn't load this list"
instead of "Starlit Crossing". Trust-ops' G-1366 (6ee3f226f) made
release-filtered browsing of public Works an ordinary public catalogue read.
Signed out, it may already work; signed in, the read fails.

Write a minimal integration repro (the claimed test file), signed out versus
signed in on the same seed. Find which request fails and why: exposure,
platform group, rate-limit family, a viewer-specific query branch, or the
web adapter. If the cause is in launch's unclaimed web or Zone code, reclaim
the file (`task goal -- reclaim`) and fix it. If it's in another Goal's code,
hand off with the file, line, cause and failing request under BLOCKERS.
Signed-in readers must see at least what signed-out readers see.
