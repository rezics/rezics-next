## Outcome

A reader who imports a library sees the apply finish. G-1372's
`library-import.e2e.ts` (seeded through the API, closed-importer 403 verified)
found this instead: apply returned 202 six times and stayed at "0 of 3", then
showed "Unavailable" and "Continue", so the 200-row step was never reached.
Find the root cause. It could be the apply worker or relay not running in the
QA stack, a stuck lease, an admission refusal shown as pending, or the UI
polling the wrong resource. Fix it where it lives. If it lives outside these
paths, name the file and the cause under BLOCKERS.

A 202 means accepted and in progress, so progress must advance or a terminal
state must arrive within a bounded time. "Unavailable" must come from a real
terminal or refusal state, never from the client giving up.
