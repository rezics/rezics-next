## Outcome

Every image drawn through the shared image component shows for signed-in
readers, as it does for signed-out ones, with their content preferences
(NSFW masking, revealed state) applied.

Reported by the showcase editor task and reproduced on the shared web (port
3000): `apps/web/app/api/media-viewer` sends the reader's OAuth bearer token to
Account's `/api/account/content-preferences`, which accepts only a Better Auth
session (`services/account/src/http.ts` `accountSession`). It answers 401, the
viewer never becomes ready, and every image stays a placeholder when signed
in. `services/account/src/introspection.ts` already reads content preferences,
which suggests the intended path.

1. Find the intended way the web's server reads a signed-in reader's content
   preferences with the credentials it holds, and use it; the reader's
   session cookie must not be forwarded to another origin.
2. A test that fails before the fix: a signed-in viewer becomes ready and an
   ordinary image renders; an NSFW image stays masked by default.
3. Audit the class: any other web server call that sends the OAuth bearer to
   an Account route that accepts only sessions. Fix them or list them.

Smallest change. Do not change the masking policy or the image component.
