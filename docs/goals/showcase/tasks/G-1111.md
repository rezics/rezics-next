## Outcome

Zone moderators state the [showcase](../../../contracts/presentation.md#showcase-carousel)
as slides, not banners: profile `zone-presentation-v2`.

1. **Document.** `slides` replaces `banners` (at most six, in order): a slide
   targets a Work IRI or an `href`, with an optional kicker and title (localized
   like module titles), a schedule (`startsAt`, `endsAt`), and optional campaign
   art that overrides the Work's showcase art: landscape and portrait
   backgrounds, logos (language, tone, anchor), cutout, each a public Realm
   publication-item Use as banners use today, with an optional focal area.
   Tokens gain `titleEffect` (`plain`, `outline`, `gradient`, `glow`;
   presets carry one). Everything else is as in v1.
2. **Compatibility.** A stored v1 document reads as v2: each banner becomes a
   slide with its `href`, title and image as landscape art. Writes accept only
   v2 and validate strictly (duplicate ids, schedules, targets, art roles).
   Never edit the v1 profile in place; add `model/definitions/zone-presentation-v2.ts`.
3. **Read.** `GET /v1/zones/:id/presentation` returns, per slide, its resolved
   campaign art with `srcset` candidates from G-1109's batch read, in the same
   bounded batch as `readZoneBannerMedia` today (rename it by what it does);
   unusable art leaves the slide's text and target intact. A configuration
   write requests renditions for newly referenced art.

Smallest change. Do not resolve a Work's own showcase art here (the web
combines it from G-1110's batch read), and do not touch web code
(`apps/web/features/zones/` belongs to G-1108 while it runs).
