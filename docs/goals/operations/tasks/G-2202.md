## Outcome

Main starts from the release payload. In the regression run of 2026-10-13 on `main` three fault-recovery files fail before their drill starts (D026 in `.temp/ref/regression-operations.md`): `Cannot find module '../../../../../model/compiler/registry.ts'` from the packaged `services/main/src/modules/governance/effects.ts`. `scripts/ops/release-payload.ts` omits a file that Main imports at run time, and whether `infra/release/Dockerfile` copies the model tree was raised in a review and never verified.

1. The payload holds every file that Main's entry reaches by import. Derive the set from the imports and not from a list kept by hand, so that the next import cannot leave the payload behind; `scripts/ops/release-payload.test.ts` fails when Main imports a file the payload lacks.
2. Build the payload and start Main from it once (the drill in `tests/qa/fault-recovery/second-host-format-upgrade.test.ts` does it); give the command, its seconds and the first healthy answer in the handoff. Say what the Dockerfile copies and whether the image needs the same correction.

Do not build: a change under `services/` or `model/`, a change to an API contract, a new deployment step. `docs/operations/external-conditions.md` is the maintainer's list: solve nothing on it.
