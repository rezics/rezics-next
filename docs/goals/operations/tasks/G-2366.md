## Design note

Read by program: 2026-10-13

Program's approval in mail:d0fb5521-54d2-4e9d-be21-cd94797bcf8b, extended by mail:6dd0658d-6144-43e2-bb0e-a9eb46488a2f, is conditional on all four requirements:

1. Compute the key from digests of the inputs that shape the source: the producer's files, migrations and fixture's declared inputs. Never key it by commit; an unrelated commit must not rebuild a source.
2. Allow one builder per key. A run needing an absent key takes the lock and builds; every other run needing that key waits for it, then verifies the manifest. Two runs never build the same key side by side.
3. State bounded retention in code: how many sources per producer are kept and which is removed first. Remove and rebuild a source that fails its manifest; never repair it.
4. Build on `scripts/fixture/`'s existing read-only volume copy, directory layout and manifest. Add per-file hashes, the RDF digest, the owner-state descriptor and isolated restore without rerunning the producer or corpus smoke checks. Reuse `copyVolume`; there is no second volume-copy implementation. The owner-erasure source is the first adapter and this task's proof; API implements the retained-Content producer as the second adapter in G-2249 step 1.

Building a source is preparation under the ten-minute budget, outside every test's envelope. A consumer's first act is the manifest check.

One source-retention owner under `scripts/qa/` handles keyed preparation, immutable publication, manifest verification and selection; producer adapters provide the source-specific cut and proof metadata. The key binds producer identity/version, source-affecting inputs and compatibility facts. Physical identities and timing remain provenance, not a reason to rebuild identical inputs. The consumer restores fresh writable resources from the retained source and never shares writable authority, graph, object or PostgreSQL state with another operation. Retaining only the historical base is insufficient: this fixture also depends on the newer signed coverage, retained post-cut relay and genuine source-erasure proof. Keep these bound to the same source manifest without changing their historical relationship.

This extends existing retained-fixture practice to sources built by actual APIs; it does not add another corpus generator or erasure protocol. The smallest change is a shared lifecycle with producer adapters and a harness hook, leaving operation assertions in their current files. Program's dated reading is recorded above. Queue until G-2281 releases `scripts/qa/cli.ts` after its gated merge; do not borrow or edit that landing task's brief. Operations releases G-2248's fixture editing claim to this task after its accepted partial landing; G-2248 retains its pending physical qualification, with no concurrent fixture edits.
