## Outcome
Managers need a focused task goal -- allowance <account> command giving fresh authenticated quota, credit balance and reset-card counts; optional --continue handles exhausted allowance ONLY under that account's configured pastAllowance policy. The maintainer authorizes codex-2 resetCards then existing credits; codex-1 has no such permission. Never buy credits, auto-change accounts, or consume a card during this implementation/test session. Do not spawn nested agents.
Use the installed Codex app-server JSON-RPC schema (provided exact local captured protocol) with bounded requests and process cleanup. Disable inherited MCP servers. Account home and launcher come from configuredAccounts. Consume only when backend ordinaryUsageAllowed is explicitly false, after a fresh read inside an interprocess lease, selecting an available nonexpired card with earliest expiry. Re-read status after redemption, so concurrent continuations cannot consume another card for an already-restored account. Null permission means unknown and must not trigger spending. Credits are reported as an authorized fallback, never falsely claimed consumed or purchased.
Keep output/logs free of email, account IDs, token/card IDs and credentials. Return actionable status for manager resume; quota errors must never turn into a different account/model. Avoid changing config.ts/land.ts/settings (held by G-2743), user settings, or account launchers. Manager will call this command on actual quota exits; no new daemon or scheduler framework.
