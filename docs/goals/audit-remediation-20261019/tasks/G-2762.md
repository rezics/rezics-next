## Decision: consume the Web operation deadline

Continue this existing request-budget owner for the Main boundary reported in
G-2784's attempt-5 handoff. Its Web commits `e2c6eba364` and `7b2c1e5d20` are on
`wave/audit-20261019`; they forward the absolute Unix-millisecond deadline in
`x-rezics-server-deadline`. `withFusekiReadRequest` currently starts a new
`limits.deadlineMs` duration, leaving the shared operation boundary incomplete.

Consume a valid forwarded deadline before admission, preflight or readiness
reads. Cap both the existing monotonic budget deadline and its cancellation
timer by the remaining absolute duration and the local owner limit; a caller
must never enlarge an allocation. Reject an already expired deadline before
starting any read or native child. Preserve the tighter parent deadline,
request cancellation, typed phase/retry/receipt diagnostics and all authority
fences. Missing or malformed headers retain the existing bounded behavior;
they confer no new allowance. Extend the existing owner, without a parallel
budget mechanism or increased timeout.

Add meaningful stack-free regressions for an expired deadline starting no work,
a partly spent deadline surviving preflight and nested reads/retries, a future
header unable to extend local limits, and absent/malformed headers retaining
the existing cap. Keep the independent public outcomes unchanged. Reconcile
with G-2784's actual Web header contract on the wave, run affected stack-free
checks and types/lint/guards, and push the complete continuation to the wave.
Report the exact public/composition/native prove selection and any remaining
cross-hop gap. The 100 ms composition grace and 300 ms native disconnect
release, mixed readers and real cancellation/retry still require later proof;
this continuation starts no stack and authorizes no individual landing.
