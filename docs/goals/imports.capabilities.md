language syntax for aliases, so scalar and bullet-list `别名` values remain
`und` and are never relabelled from provider, glyphs or work country.

Ordinary Bangumi conversion and the selected-family type 2 route share one pure
extractor. Exact `中文名` and scalar or bullet-list `别名` values become
`schema:name` or `schema:alternateName` facts with the exact Bangumi subject
citation after the source identity is bound. Existing top-level `name` and
`name_cn` labels remain unchanged; name facts do not assert work language.
Repeated keys are considered independently, exact property/language/text tuples
deduplicate, and other names remain distinct. Only the pinned template and these
two fields are consumed. Unsupported keys and forms produce bounded diagnostics
without source prose. The original infobox stays in the existing bounded source
projection and digest.

- Touches: one source record, at most 24 total distinct name values and at most
  16 omission diagnostics, with one source citation per proposed fact.
- Bound: no more than 65,536 infobox characters or 64 field occurrences are
  scanned; the parser does not recurse through arbitrary wiki markup or retain
  arbitrary keys. The existing journal, source rights admission and facts fence
  govern proposals and refresh.
- Growth check: `services/importer/tests/bangumi-subject-names.test.ts` exercises
  the selected-family JSONL operator, exact proposals/citations, neighbor
  exclusion, unchanged and changed input, identity reuse and bounded omissions.
  `services/kernel/test/imports/bangumi-subject-names.test.ts` authors the
  ordinary production-caller review, adoption, reopen and facts-fence journey;
  its native execution remains controller-owned.

## Bangumi character source names

Selected default Bangumi character records retain their exact `infobox` payload
through `planCrossMediaSeed` and the shared `cross-media-entities@10` converter.
The reviewed `Crt` grammar supplies cited `schema:name` facts from `name`,
`name_cn` and `简体中文名`, plus cited `schema:alternateName` facts from its
labelled `别名` rows. A malformed alias group is withheld as a whole; usable
names and summary remain independent. Unsupported custom labels are omitted
with bounded diagnostics while known labels remain usable. The source character ID alone binds the
native Character. Names do not resolve performers, merge identities, or change
appearance and voice-credit qualification. The common publication manifest
owns acceptance/adoption and current public reads; this local journey does not
claim Search indexing.

Decision: `第二中文名` uses `zh`, `英文名` uses `en`, `日文名` and `纯假名` use `ja`, `罗马字` uses `und-Latn`, and `昵称` uses `und`; top-level `name` stays `und`, `name_cn` stays `zh`, and `简体中文名` is a `zh-Hans` preferred name; within nicknames only the observed full-width comma splits entries and slash sequences stay intact.

- Touches: one default-selected character payload, up to 16 preferred names,
  64 alternate names and 85 ordinary converter commands, including up to two
  existing physical-profile facts.
- Bound: 1 MiB source line; 32 KiB infobox; depth 2; 64 fields and aliases;
  4 KiB/500 codepoints per name; 16 diagnostics; existing 65,536-byte
  normalized record cap. Unsupported nested fields are not interpreted.
- Growth check: `packages/conversion/tests/bangumi-character-names.test.ts`
  pins alias language and refresh behavior. The real Auth/Access default-seed
  and common-publication scenario is
  `services/kernel/test/imports/bangumi-character-names.test.ts`; broader native
  acceptance remains controller-owned.

## Bangumi character physical profile

Decision: keep only explicitly unit-bearing released quantities, preserve source units and literal zero, and withhold Bangumi blood type until a current native Concept binding exists.

The selected default Bangumi seed already elects character IDs through the selected works' `subject-characters` rows and carries each exact `character` row into the common source registration. `cross-media-entities@10` reads the pinned Crt infobox for `身高`, `体重` and `血型`; the source scalar and indexed path enter deterministic source evidence. Only explicit released centimetres/metres and kilograms/grams become quantities. Blank and explicit unknown values remain unknown; unitless, ranged, approximate, fictional-unit, mixed-prose, duplicate and over-bound values remain unavailable field evidence. Blood type stays withheld because the repository has no Bangumi blood-type source vocabulary binding to current native Concepts. Character identity remains the selected `character:<id>` binding.

- Touches: one selected Character record, at most one released height and one weight fact, bounded source evidence, and sanitized field-path diagnostics. Existing names, kind, appearance and licensed summary handling remain on their current paths.
- Bound: 65,536 UTF-8 source bytes, template depth 2, 64 fields, 128 retained scalar code units, 64 quantity characters, 2 quantity facts and 16 diagnostics. Unsupported or oversized values do not create partial quantities; the existing converter command ceiling and common publication manifest remain authoritative.
- Growth check: conversion `bangumi-character-measurements.test.ts` covers explicit source units, unknown/unitless and unsupported values, independent field removal and caps. Kernel `bangumi-character-measurements.test.ts` covers selected identity, exact source citation, proposal versus public adoption, journal reopen and current-fence suppression; its native execution is deferred to integration.
