### F2 — Medium: unrelated Agent mandates authorize rights assessment and rule publication

**Evidence.** Limited representation mandates are real: acceptance can write action `work.create` (`services/main/src/modules/access/representations.ts:310-316`), and ordinary represented-work proof constrains action to the requested action or `agent.control` (`services/main/src/modules/access/represented-work-proof.ts:54-61`). Rights authorization joins representation to the Agent's `rights.assess` grant without constraining the representation action (`services/main/src/modules/rights/store.ts:260-270`). Governance rule authorization repeats the omission for `governance.rule.publish` (`services/main/src/modules/governance/rules.ts:209-219`), including private rule reads (`254-265`). Route authentication does not supply that missing mandate check (`services/main/src/routes/rights.ts:180-187`; `services/main/src/routes/reports.ts:141-148`).

**Exploit, source-derived.** A caller allowed only to create Works for an institution can consume that institution's assessor/rule-publisher grants, changing rights bases, obligations or moderation rules without the matching mandate. A supported public-domain assessment is a live publication/search eligibility basis (`services/main/src/modules/rights/store.ts:177-185`).

**Smallest fix and acceptance.** Reuse the existing authority owner to require an exact-action or control mandate. Audit membership-backed grants in both queries: the normal governance decider checks the current membership episode/generation (`services/main/src/modules/governance/store.ts:321-324`). Agent holds both grants, caller holds only work.create: both writes and private rule query deny; proper mandates succeed; expired/revoked mandates and ended membership bases deny. Do not widen unrelated mandates.


Rule as a table: the finding is of the kind 'which callers': enumerate every query that joins representation to a permission grant WITHOUT constraining the mandate action (grep representation joins in rights/*, governance/*, access/*, preferences/*, space/*, media/*), and in the handoff give the table (site, action constrained before/after, fixed yes/no); fix all that authorize an ACTION of the grant through a mandate of a different action. Reuse the existing represented-work proof (access/represented-work-proof.ts: requested action or agent.control).
