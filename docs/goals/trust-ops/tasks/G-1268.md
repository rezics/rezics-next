## Outcome

G-1259 added one bounded, fail-closed name-policy check in `disclosure/`. It
is shared with governance in one SQL snapshot. A withheld name answers through
the existing unavailable shape, and authorized private reads still see it.
Five readers still return a person's display name without consulting that
check. Route each through it, batched per page:

1. **`profiles/read.ts` `readAgentCards`.** The `publicAgent('?agent')` read is
   around line 216, and `cards.set(... displayName ...)` around line 280. This
   one fix covers every caller: follows, feed and its presentation, query
   work cards and resources, and realm-reply threads.
2. **`access/roster.ts`**, around lines 30 and 43 (`p.display_name`). The
   public roster keeps the member identity but withholds a private name.
3. **`access/contexts.ts`**, the agent and public labels: around lines 227,
   280, 329 and 447.
4. **`discovery/credits.ts`** `namedDiscoveryCredits`, around lines 65, 75
   and 96.
5. **`catalogue-intake/search.ts`** creator matching, around lines 200, 206
   and 237. A private name never matches or appears.

`readAgent` and `readHandle` already check preferences: reuse their rule, and
do not add a second one.

## Do not build

- No new policy store.
- No per-caller name rules.

## Checks

- One test file: for a person with a private name, an anonymous viewer gets no
  name from each of the five readers, an authorized viewer does, and making
  the name public shows it.
- Batch cost: one policy read per page, not per item.
