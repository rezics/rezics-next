Take that file's change (cherry-pick only that hunk, `git checkout 79f56efe9 -- services/main/src/modules/erasure/request.ts` on your branch, then review it yourself), keep it minimal, and add a focused regression test `services/main/tests/erasure-target-completion-request.test.ts` that drives the request path (the existing owner-level test harness for erasure/request.ts, see tests/ or services/main/tests/erasure-*.test.ts for how request.ts is exercised) and proves: a normal erasure reaches `verified` with every target completed and evidence recorded once; a Content target whose proof is not `erased` leaves the erasure unverified/unavailable and its targets uncompleted; a retry after a partial failure completes the remaining targets without re-completing the done ones (completion is idempotent/monotone).
