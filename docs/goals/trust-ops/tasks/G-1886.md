## Outcome

Class A defect (GOV03 "replays and reversals have one effect"), reported by kernel's G-1868 proof (branch goal/g-1868, test tests/qa/integration/rights-public-restriction.test.ts, QA 20261011t183814-8d0d25): two concurrent POST decisions with the SAME idempotency key on one platform case: the first advances the case generation; the second gets 403 `claim the case before deciding` instead of replaying the first request's outcome.

Cause (read `GovernanceStore.decide`, services/main/src/modules/governance/store.ts ~551-680): the replay check (`this.replayDecision(principal, input, request)`) runs BEFORE the write transaction. A request that passes it while the first is still in flight then enters the write transaction after the first committed; inside, for `authority_kind === 'platform'` the claim lookup is keyed on `(case_id, case_generation)` of the CURRENT generation, which the first decision already advanced, so no claim matches and it throws GovernanceDenied('claim the case before deciding'). The key lookup must come first, under the case lock.

Fix (minimal, inside the existing owner): inside the write transaction, immediately after the case row is locked FOR UPDATE and BEFORE the claim check, look up the idempotency key on the same client: same key + same request digest => return the existing decision's outcome through the existing replay path (resumeDecision / the replay result type, no second effect, no second generation advance); same key + DIFFERENT request digest => the existing key-conflict outcome (GovernanceConflict) as today; no key => proceed as before (claim check unchanged for new decisions). The decider authority checks for the replaying principal stay (a replay never bypasses authority: the pre-transaction decider check already ran for this principal/acting subject). Do not weaken the claim requirement for NEW decisions, do not loosen any assertion, no second mechanism, no migration.

Tests (new file services/main/tests/governance-decision-replay.test.ts, owner tier or the existing governance harness; read how other governance tests build a case + claim + decide): (1) two decisions with the same key issued concurrently (Promise.all) on one claimed platform case: both succeed, the same decision id/outcome, exactly one decision row, one generation advance; (2) a sequential retry with the same key after the generation moved replays; (3) same key with a different request body => conflict; (4) a NEW key on the advanced generation without a fresh claim still gets 'claim the case before deciding'; (5) a replay by a principal without decision authority is still refused. Then run kernel's proof file ONCE to confirm the concurrent step passes: `bun scripts/goal/goalctl.ts test tests/qa/integration/rights-public-restriction.test.ts` — it lives on kernel's branch goal/g-1868 (worktree .temp/worktrees/g-1868); do not edit it; if you cannot run it from your worktree, say so and rely on your new test.
