### F7 — Medium: vocabulary and Realm-topic directory bypass governance removal

**Evidence.** The deprecated vocabulary and Realm directory routes remain unauthenticated public APIs (`services/main/src/routes/realm-directory.ts:48-71`). `readSharedVocabulary` queries active shared Concept labels, checks only legacy protectionHead, then matches/sorts/slices and returns IDs/labels/hasMore without disclosure (`services/main/src/modules/realm-directory/vocabulary.ts:11-40`). Realm topic selection separately returns the supplied topic's ID/label under that same legacy-only guard (`services/main/src/modules/realm-directory/read.ts:27-41,88-89`).

Active Concepts are reportable graph/record targets with exact anchor evidence (`services/main/src/modules/public-report/owners.ts:74-75,244-252`; `services/main/src/modules/governance/evidence.ts:179-184`). Search restrictions are explicitly Access-owned and return an Access receipt before graph-shape validation (`services/main/src/modules/governance/effects.ts:29-39,177-179`); continuation installs the enforcement row (`services/main/src/modules/governance/store.ts:1260-1274`). Neither path creates legacy protectionHead. Shared disclosure recognizes that search enforcement (`services/main/src/modules/disclosure/read.ts:54-58,163-180`), but the outer read envelope only checks positions/dependencies/recovery, without filtering these labels (`services/main/src/modules/work/read-session.ts:389-411`).

**Exploit.** Any anonymous caller searches a unique label of a shared Concept with a committed graph/record/search restriction and receives its ID/label, or supplies its ID as a Realm topic and receives the label even with no directory items. These public discovery APIs bypass the authoritative search fence. No live restriction was created for this review. F10 separately concerns target-owned disclosure effects; this finding uses the reachable Access-only search effect.

**Smallest fix and acceptance.** Batch exact Concept/name targets through the existing disclosure owner at search before matching, hasMore and topic-label selection. Restricted Concept is absent from full/unique-label vocabulary searches and does not alter disclosed hasMore. Restricted/unknown topic has the same public unavailable result with no label; unrestricted topic works. Audit both resolvers together.
