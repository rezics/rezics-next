## Outcome

PRODUCTION DEFECT (class A): since commit abbd3f255 `httpTelemetry()` installs `@elysia/opentelemetry` even without an exporter and the dependency's wrapper drops the `server` argument, so `server.requestIP(request)` is lost for every Elysia service: all anonymous callers collapse into one rate-limit key (`oauth-register:unknown`, `anonymous:unknown`), forwarded addresses cannot be authenticated, and a trusted `CF-IPCountry` is not propagated. The Sol specification G-1843 (whole spec at `.temp/ref/spec-g1843.md`) gives the exact repair: keep every existing patch hunk, add matching hunks for both `dist/index.mjs` and `dist/index.js` so the wrapper takes `(request, server)` and forwards it in both the bypass and the traced branch; refresh the patched dependency through Yarn and commit yarn.lock (no version change); never hand-edit node_modules. Do NOT raise or disable ceilings, change expected 201 to 429, add skips/sleeps/retries, accept unverified client headers, disable request telemetry, or add another limiter. Two commits in one branch, one landing.

Impact (from the specification, for the reviewer):

Confirmed cause at the common transport wrapper, confirmed current isolated registration failure. Additional impacts inferred from source, not separately runtime-qualified in this analysis:

- Main's rate-limit hook obtains native peer identity in beforeHandle, mapResponse, and error handling. Anonymous calls can collapse into `anonymous:unknown`, so one client can spend other clients' write/search/address/family budgets; configured forwarded addresses cannot be authenticated by the missing peer. Signed-in principal classification itself is not derived from this socket metadata.
- Account's same boundary admits a trusted `CF-IPCountry` into `x-rezics-request-country`. Missing peer information prevents trusted country propagation and can lose authoritative market evidence. Existing market-policy tests are the qualification surface.
- Account's enrollment challenge derives its caller key from the sanitized address and can similarly collapse callers to `unknown`. The target-email ceiling remains a separate intentional policy.

The common wrapper repair fixes all these consumers at their existing transport boundary. Do not raise/disable ceilings, modify expected 201 to 429, add skips/sleeps/retries, accept unverified client headers, manufacture isolated client keys in the test, disable request telemetry without an exporter, or add another limiter/peer-decision mechanism. The exact real-socket and trace-context guards preserve both the security boundary and the purpose of the introducing commit.

If the specification's premise is false when you read the code, STOP and report the exact first failure. QA only through `bun scripts/goal/goalctl.ts test <explicit files>`; final immutable install through `task install`.
