## Outcome

Launch (QA 20261008t134100-19de84: 70 faults; 20261008t140122-183e4f: 93) sees
`main.database.nested-checkout` worker faults whose line names only the guard, so nobody
can find the caller. Production runs in `log` mode: `NestedPoolCheckoutError` is logged
through `logWorkerFault` and the checkout proceeds.

Make the fault actionable without leaking data and without a hot-path cost spike:

1. At the moment a hold is adopted (`adoptHold`) record a bounded origin: the first stack
   frame outside `pg-pool.ts` and `node_modules`, reduced to repository-relative
   `path:line` (and the function name if present), captured cheaply (set
   `Error.stackTraceLimit` to a small number for the capture, and do NOT format `.stack`
   until a fault is actually reported).
2. When a nested checkout is detected, the fault carries: the outer holder origin(s) still
   active for that pool (at most 3, oldest first) and the inner caller origin, plus the pool's
   existing identity if one exists. Put them on `NestedPoolCheckoutError` as bounded string
   fields (each at most 200 chars, at most 3 outers) and make `logWorkerFault` output include
   them in the structured log line (look at `packages/observability/src/log.ts` for how
   extra fields are rendered; if it cannot carry them, extend it minimally and say so in
   the handoff). Never include SQL, parameters, ids, URLs, credentials or user data: only
   repository-relative path, line, function name.
3. Rate-bound it: the same (outer, inner) pair is logged in full at most once per minute
   per process; repeats increment a counter reported on the next full line.
4. `throw` mode keeps its behaviour (same error, now with the fields).

Do not change the pool size, the guard's rules, release/reacquire behaviour or what counts
as nested; do not fix any caller in this task.

## Checks

`pg-pool.test.ts` and `nested-pool-checkout.test.ts`: the fault names the real outer and
inner test call sites by path:line; no field exceeds the bounds; a query string passed to
the inner `pool.query`/`connect` never appears; repeated identical pairs are rate-bounded;
the capture overhead per `connect()` is measured in a test with a loose bound (report the
number). Show the origin test fails with the capture removed. `task goal -- test`, lint,
AST, types. No `--heavy`.
