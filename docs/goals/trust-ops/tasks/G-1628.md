## Outcome

Program decision (2026-10-10): build the ONE batched visibility check keyed by the requested id in the Access module and convert four reads: `GET /v1/public-previews/{resource}`, `GET /v1/resources/{resource}`, `GET /v1/works/{id}/history`, and the content-revision comments read (`GET /v1/content-revisions/{revision}/comments`). SKIP `GET /v1/claims/{claim}` (being retired by kernel) and leave `GET /v1/addresses/resolve` and `POST /v1/resources/summaries` in the registry as debt (kernel's address work and launch's envelope settle first).

The invariant (see docs/development/hidden-ids.md, helper `tests/qa/support/hidden-id-equality.ts`, inventory `scripts/static/hidden-id-reads.json`): a HIDDEN id (exists, caller may not see it) and an ABSENT id answer identically in status, body bytes, cost envelope and side effects, with NO decoy or padding work on either side (two earlier attempts failed review for exactly that).

Design: `visibility-batch.ts` in Access exposes one entry point `visibleOf(caller, ids)` that, in ONE statement/graph call whose cost does not depend on whether any id exists, returns the subset the caller may read (join id -> owning resource/referent -> disclosure and grants). Existing readers call it first with the requested id(s); an id that is not in the visible set (absent OR hidden) takes the SAME early return; only visible ids continue to the resource-specific reads. Reuse the existing disclosure/admission primitives inside it (consume, do not copy SPARQL or SQL from disclosure/read.ts; register it as an `access-authority` entry point in scripts/static/mechanisms.ts if the mechanism guard requires). Do not change any authority decision: the visible set must equal what each route showed before for every caller class (owner, maintainer, member, outsider, anonymous).

Per read: keep every existing authorisation test green, then register the read with the helper and show hidden == absent for status, bytes, cost (graph calls, SQL statements) and side effects. Where a read cannot be made equal without decoy work, STOP on that read, leave it frozen debt in the inventory and say exactly why.

## Mechanisms

access-authority: extend — the batched visibility entry point lives in Access and reuses its disclosure/admission; readers consume it.

## Checks

Unit tests for `visibleOf` (batch of 0/1/many, absent/hidden/visible mix, constant statement count as the batch grows), the four reads through real HTTP on real PostgreSQL via the helper (QA ids), existing route tests unchanged, regression: owners/maintainers still read their non-public resources (200). Mutation proof for the helper-equality test of each converted read. `task goal -- test` per file, no `--heavy`. Lint, AST, types, `task gen` if a contract moves.
