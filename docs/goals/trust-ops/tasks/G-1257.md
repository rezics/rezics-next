## Outcome

Governance needs at least two permanent `platform:grant` holders (record §9),
and a second holder is appointed through the ordinary grant API
(`POST /v1/access/grant-changes`, profile `platform-grant-change-v1`). Today the
appointed holder receives no assignment ceiling, so it cannot grant or revoke
anything. The existing host tests supply the ceiling through fixture SQL.

When `platform:grant` is granted through the API, the same audited operation
gives the recipient the assignment ceiling that `platform:grant` implies: it
may grant and revoke `platform:*` within the issuer's own ceiling, never above
it. When `platform:grant` is revoked or expires, that ceiling goes with it,
and the last-permanent-holder rule still holds. Express the ceiling as the
grant's consequence, not as a second record the issuer must remember to create.

## Checks

- Remove the fixture SQL that supplied the ceiling. The host test must pass
  through the API alone:
  1. the first holder appoints a second;
  2. the second grants `platform:use:saved-views` to a third principal;
  3. the first revokes the second, whose grant ability ends.
- A grant beyond the issuer's ceiling is refused.
- `task main:typecheck`.
