## Outcome

A name marked private, through a person's profile preference, never becomes
public through any reader, projection, search index, export, sitemap or
credited-name occurrence. Authorized private reads still see it.

A read-only scout of the current code (2026-10-07) found:

- **What exists.** `DisclosureStore` (`disclosure/read.ts`, around line 89)
  checks governance and Work fences. Search, exports
  (`export/readers.ts:505`) and sitemaps consume it. A private profile
  preference suppresses native public-name indexing before the preference
  commits (`preferences/store.ts:101`).
- **The gaps:**
  - `DisclosureStore` does not consult profile name preferences.
  - Work summaries (`work/read-session.ts:186`) omit that owner.
  - Relations hide `creditedName` (`routes/relations.ts:65`) only when the
    participant is unavailable.
  - `referenceDisclosure` (`target/disclosed-references.ts:48`) can admit a
    name through semantic permission. So readability does not establish
    public-name permission.
  - `readName` (`work/read-contract.ts:11`) has no withheld state.
  - The native `PublicNameProjection.java:130` walks all dependent concepts.
    That breaks the bounded-neighbourhood rule.

What to build:

1. **One bounded, fail-closed name-policy check in `disclosure/`.** Given the
   viewer and the name's owner, it decides whether that name may be shown.
   It costs one indexed preference read per owner, batched for a page.
   Unknown or unavailable means withheld.
2. **Apply it where disclosure owns the reader:** search, export readers,
   sitemap, and the disclosure assembly used by summaries.
3. **Name every remaining call site in another Goal's area** in the handoff,
   with file and line and the exact call. Do not edit them; the manager routes
   each to its owner:
   - kernel: Work summaries in `work/read-session.ts`, `routes/relations.ts`
     `creditedName`, `target/disclosed-references.ts`, a withheld variant of
     `readName`, and replacing the native projection's dependency walk with
     parent fences and resumable batches;
   - any others you find.
4. **A withheld name answers as unavailable** (an existing response shape),
   or as an explicit withheld variant where the identity must stay visible.
   Choose one and say why.

## Do not build

- No second disclosure store.
- No per-name permission rows.
- No change to who may read a private Work.

## Checks

- Unit tests for the check: owner, viewer, withheld, unavailable and batch
  cost.
- One integration test through `task goal -- test`, covering:
  - a person with a private name: an anonymous search, an export and a
    sitemap omit it;
  - an authorized viewer still sees it;
  - flipping the preference to public shows it.
- `task main:typecheck`.
