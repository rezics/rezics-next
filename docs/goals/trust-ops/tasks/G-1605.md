## Outcome

Invariant (privacy and anti-enumeration): any read that accepts ids must answer a HIDDEN id and an ABSENT id identically: same status, same body bytes (except request ids), same cost envelope (statement counts, graph calls, bytes), same media/generation side effects. Program found one instance after the fact (`POST /v1/resources/summaries`, Launch G-1504, fixed by Launch with a per-route envelope-equality test). Express the invariant in code so it holds for every id-accepting read, not one test per route:

1. **Inventory (generated, not hand-written):** from the generated OpenAPI/operation metadata, list every GET/POST operation whose path or body takes ids that name resources (path params, `ids`/`resources`/`targets` arrays, query ids). Write the list to `scripts/static/hidden-id-reads.json` with, per operation: `registered` (has an equality test registered), or `exempt` with a short reason (e.g. the id is the caller's own, or the route returns the same refusal for any unauthorised caller by construction). Generator script + a test that the file equals the generated list (a new id-accepting operation fails until classified), in the style of `scripts/static/mechanism-dependencies.json`: unregistered entries are frozen DEBT that can only shrink.
2. **Shared helper:** `tests/qa/support/hidden-id-equality.ts`: given an operation, a caller, one hidden id (exists but the caller may not see it) and one absent id, assert equal status, byte-equal bodies modulo request ids, equal cost envelope (use the existing request-cost counters the QA harness exposes, e.g. the Fuseki/SQL call counts the cost-contract tests read) and no differing side effects (media generation, rate-limit charge). One call per operation.
3. **Register:** convert the existing `/v1/resources/summaries` test onto the helper, and register the highest-risk reads first: reads of Works, Statements, entity pages, search facets by id, export selections, Realm member and role reads, alias resolution, Claim and verification reads, comments by target. For each operation you register, if the helper fails, STOP on that operation and report it (file, line, what differs); do not patch around it inside this task unless the fix is local and obvious (mapping a hidden id onto the absent answer), in which case fix with a falsifier.
4. Short `docs/development/hidden-ids.md` (one page: the invariant, how to register, how to exempt) – only what code cannot carry.

## Mechanisms

access-authority: consume — hidden vs absent is decided by Access disclosure; this task adds a verification layer, not a second decision path.

## Checks

The inventory generator + guard test; the helper's own unit tests (a deliberately leaky fake fails each of status/body/cost/side-effect); at least 10 registered operations with real PostgreSQL + real HTTP integration passing; list the operations that failed and what differs. `task goal -- test` per file, no `--heavy`. Lint, AST, types.
