## Outcome

Kernel's G-1964 review (Content withdrawal) found a P1 window that exists on main today: the exact public Content route's FINAL publication query runs after the last Rights assessment check and does not consult Rights; three tests demonstrate it (Rights `not_supported`, graph erasure, a Rights hold committed during the query -> 200 with `serializedJson`). Publication and graph tombstones live in Fuseki, assessment heads in Content PostgreSQL, holds in Access PostgreSQL: there is no combined final-delivery authority. The same window exists in comment delivery (`routes/content.ts` around :203 and :304). Program/manager decision: build the cheaper, movement-detecting authority.

THE HELPER (in the Rights owner, `rights/delivery-cut.ts`): `withDeliveryCut(target, work)`: (1) read the target's Rights assessment head AND the preservation-hold version token (the Access hold/preservation state that can make the Content undeliverable; find its owner: modules/public-report/preservation.ts and the Access hold tables) BEFORE calling `work` (the Fuseki publication query and the rest of the delivery read); (2) run `work`; (3) read both again AFTER; deliver only if both equal; otherwise a bounded replay (at most 2 attempts) and then the typed unavailable-retry outcome, never the content. Reads are bounded (one indexed statement per store, constant), the token is a monotone version or the head id, never a scan. It composes with the existing disclosure final fence (fresh snapshot) rather than replacing it.

Tests (production composition, real stores): Rights moves to not_supported during the query -> not delivered (200 with serializedJson no longer happens); a Rights hold committed during the query -> not delivered; a graph erasure during the query -> not delivered (via the existing erasure check re-run inside the cut or through the Rights head if erasure moves it: say which); no movement -> delivered; movement twice -> typed retry outcome; constant statement count with and without movement.

WIRING in services/main/src/routes/content.ts (the exact public Content route and the comment delivery sites ~:203 and ~:304): `routes/content.ts` is HELD by Kernel's G-1964 (unlanded) and will be edited again by the manager's exact-revision authority fix (security B F1) after it lands: do NOT edit it.
