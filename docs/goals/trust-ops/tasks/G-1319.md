## Outcome

Fix the class of site-tooling config failures introduced/exposed by production
validation imports. About's Astro config imports production-env.ts, whose new
safetyResponders import pulls heavy Main runtime modules using import.meta.dir
that Vite does not provide. Keep the actual validated responder semantics but
make config imports portable/lightweight (extract the existing pure function
only if needed, with its current exports preserved). Do not port the whole
service or bypass production validation. Accounts' default Storybook also
fails parsing the application Vite configuration; diagnose its actual import
path and make Storybook use its supported component configuration, preserving
normal Accounts dev/build. Two security workers needed temporary configs.

No new validator, duplicated policy, broad module rewrite, dependency upgrade,
test-only workaround or shared backend lifecycle action during kernel repair.

## Checks

Reproduce first. Verify default About dev/build and the two legal build tests
through targeted Task commands, plus normal Accounts Storybook's changed
recovery/consent stories and Accounts config typechecks. Use focused regression
coverage for portable validation imports. No full tiers and no --heavy for own
test files. Leave review servers stopped and report screenshots if captured.
