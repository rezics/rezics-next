## Outcome

Close the inherited missing deadlock signal at the existing boundedPool boundary
(shared by Main/Account), including query failures an owner catches/translates.
Use existing privacy-safe logWorkerFault with one fixed deadlock event selector
and SQLSTATE40P01 only; preserve original errors/query result/callback/Promise
semantics, client lifecycle, checkout guard and timeout bounds. One event per
failed query, including pool.query and borrowed clients; no duplicate pool/client
report. Reverify existing shared-to-exclusive scope lock protections and identify
any concrete residual class paths without changing unrelated owners. Short owner
runbook states how to select/count this signal and that configured production
rule evaluation/notification remains external and unqualified.

No new telemetry framework, polling service, pool/authority layer, automatic
retry, query/parameters/connection string/error-message logging or alert engine.
If current instrumentation already emits the exact safe signal, prove/reuse it.

## Checks

Own tests through Task/goalctl without heavy. Real isolated PG deadlock with two
max1 pools proves40P01 emits exactly once even when caught, caller rollback and
reuse remain intact; normal query, nondeadlock error, callback and borrowed query
forms preserve behavior and do not leak the seeded private SQL/parameter/error
text. Existing pg-pool nested-checkout tests unchanged. Main types, changed
format/type lint/AST, docs check, affected preview only. No shared lifecycle.
