## Outcome

Reporting already runs end to end, from intake through triage, decision,
effect and notice to appeal. A scout of the code on 2026-10-07 found:

- **Intake.** Public intake (`public-report/store.ts:105`) and authenticated
  reports (`routes/reports.ts:147`).
- **Triage and claims** in `safety-queue/store.ts:161`.
- **Decisions** in `governance/store.ts:453`, which check authority,
  generation, rules and target heads. Effect receipts are at `:1221`.
- **Notices.** The affected party gets credentials and reasons; reporters get
  `SafetyDecisionMail` (`governance/notices-mail.ts:53`).
- **Appeals** reopen review (`public-report/store.ts:225`, migration 933).

Close these four gaps:

1. **Every affected party is notified.** A graph target's notice participant
   is only its first author (`governance/effects.ts:137`). Identify all
   affected parties (authors, controllers or stewards) through a bounded,
   resumable continuation, never by loading them all at once.
2. **Decisions that need notices carry reasons.** Legacy decisions can omit
   reasons while notice mail requires them. New decisions of a notifying kind
   are refused without reasons. Existing rows without reasons get an explicit
   "reason not recorded" notice, not a crash or silence.
3. **Decision validation is bounded.** It reads all retained reports and
   evidence for the case (`governance/store.ts:625`). Replace that with indexed
   membership checks on the items the decision cites.
4. **Reporter mail is paged.** One worker invocation loops over every
   reporter. Persist a recipient continuation and process one page per
   invocation. A retry never sends duplicate mail, because each notice has its
   own idempotent receipt.

Cost does not grow with the number of reports, reporters or affected parties
per step. Reporter identities stay private to staff.

## Do not build

- No new moderation queue.
- No change to the appeal policy.
- Do not touch `notification-producers/**`: it is launch's area, and
  `producer.ts` is held by G-1230. If ordinary notifications need the same
  continuation, propose it.

## Checks

- Unit tests for each gap.
- One integration test through `task goal -- test`, covering:
  - a Work with two authors and three reporters: a takedown notifies both
    authors with reasons and mails all three reporters, across pages, with no
    duplicate on retry;
  - a decision missing reasons is refused;
  - decision validation reads only the cited items (count the statements).
- `task main:typecheck`.
