## Outcome

A Realm member who was banned can appeal. Agreed with launch (2026-10-08), whose UX
consumes it. Smallest change that reuses existing parts; no new evaluator, registry or
second case system.

Facts to build on (verify before use): the ban receipt is `access.realm_admin_receipt`
(`id` = `receiptId`, `realm`, `principal_id`, `action`, `reason`), written by
`changeMember` in `modules/access/realm-management.ts`; `access.membership_ban` holds
`reason_ref = receiptId`, `expires_at`. Governance cases live in `access.governance_case`
(`modules/governance/schema.ts`), with process `platform_appeal` and step kind `appeal`
already existing, and decisions go through `decide` / `POST /v1/moderation/decisions`.

Operations (declare `exposure` as `platform:realm-appeals` — closed by default, opened
later by changing the declaration; follow `routes/public-reports.ts` /
`routes/works-import.ts` for the pattern, run `task gen`):

1. `POST /v1/realms/{realm}/member-receipts/{receiptId}/appeal` body `{ statement }`
   (1-2000 chars), idempotency key required. Only the sanctioned principal of a `ban`
   receipt of that realm may open it; one open appeal per receipt (a replay with the same
   key returns the same case; a second distinct request while one is open is a 409). It
   opens a governance case for that realm referencing `receiptId`, reusing existing case
   kinds/processes where possible; add a case kind or column by migration only if the
   existing ones cannot carry the realm and receipt reference.
2. `GET /v1/realms/{realm}/member-receipts/{receiptId}/appeal` returns what the member
   and the Realm's moderators may read: realm, action, the recorded ban reason,
   `bannedUntil` or permanent, when it happened, appeal state and, when decided, the
   resolution outcome and the decision's public rationale. NEVER the moderator's or
   decider's identity (`acting_subject`), by omission in the response schema and a test
   that scans the whole body.

The decision uses the existing governance decision path under the Realm moderators'
existing authority for that realm; it does not unban (unbanning stays the separate
realm-admin action). A non-sanctioned principal gets 404 on both operations (no
existence signal), an unauthenticated one 401.
