## Outcome

Two small corrections left by the controller-continuity and platform-gate work.

1. **One problem type for continuity refusals.** Revoking the last controller
   already answers 409 `controller_continuity` through the policy route
   (`PolicyControllerContinuity` in `access/policy-errors.ts`). Two other paths
   still report the same refusal as `idempotency_conflict`:
   - principal deactivation, in `admission.ts`, which wraps a continuity
     `ControlConflict` as `AdmissionConflict`;
   - maintainer removal, in `work/maintainers.ts`, which does the same.

   `commandError` in `routes/problems.ts` maps every `AdmissionConflict` to
   `idempotency_conflict`. Throw a distinct continuity error on these paths
   and map it to the same 409 `controller_continuity`.
   - `work/maintainers.ts` lies in kernel's area. Run `task goal -- owner` on
     it. If it is unclaimed, make only the one-line error change and list it.
     If it is claimed, hand off with that blocker.
2. **The eligibility preview matches admission.**
   `hasNonBaselineWorkCreateAuthority` in `admission.ts` calls
   `platformAdministratorProof` without the `work.create` resource
   requirement. Pass `{ action: 'work.create', scope: 'work:create:root' }`,
   as the acting-context eligibility reader does. Then the preview says "yes"
   only when admission would admit.

## Checks

- Unit tests covering:
  - each path answers `controller_continuity`;
  - a real idempotency conflict still answers `idempotency_conflict`;
  - the eligibility preview is "no" for a platform-admin holder that lacks the
    `work:create:root` grant, and "yes" with it.
- `task main:typecheck`.
