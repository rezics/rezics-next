## Outcome

Launch's G-1238 creates a Realm in one operation, instead of three web writes
that can leave a public, open, rule-less community behind. Its Access half is
this task.

Provide `AccessRealmManagement.initializeCreated(...)`. Launch codes against
that name now:

```text
initializeCreated(principal: VerifiedPrincipal, input: {
  realm: string; actingSubject: string;          // the founder as acting subject
  creationKey: string; creationDigest: string;   // from the Space creation admission
  settings: <the existing Realm settings input>;  // visibility, review mode, who may submit, self-join
  rules?: <the existing localized rules input>;
}, env: WorkActivationEnvironment)
  → { realm, accessRevision: string, replayed: boolean }
```

1. **In one Access transaction**, it does what `initialize` plus the settings
   and rules writes do today:
   - founder enrollment and grants;
   - the scope gate;
   - settings, saved through the existing `saveRealmSettings` and
     `saveRealmAccessSettings` validation;
   - rules.

   It records `(creationKey, creationDigest)` with the resulting revision.
2. **Idempotent on replay.**
   - The same key and digest returns the recorded result with
     `replayed: true` and writes nothing. A founder grant revoked since then
     stays revoked.
   - The same key with another digest is a conflict.
   - A replay after a partial earlier failure completes the initialization,
     because the transaction makes "partial" impossible.
3. **Callable server-side** from `space/create.ts`, in the same request,
   after the graph Space exists. It may be retried on its own, by replaying the
   creation key.
4. **Bounded.** It touches only this Realm's rows and one indexed lookup of
   the creation key.
5. **Leave the existing `initialize` and settings routes working.** Remove
   nothing that the web still calls; launch moves the web over.

## Do not build

- No second settings validation.
- No change to the graph Space.
- No route. Launch exposes it through its create operation.
- No generic "operation replay" framework.

## Checks

- Unit tests and `task main:typecheck`.
- One host-PostgreSQL integration test through `task goal -- test`, covering:
  - initialize with settings and rules, then read back;
  - replay returns `replayed: true` with no writes;
  - revoke the founder grant, replay, and the grant stays revoked;
  - the same key with another digest conflicts;
  - invalid settings are refused with the existing validation errors and leave
    no rows.
- The handoff states the exact exported signature and error classes, for
  launch.
