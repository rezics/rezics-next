## Outcome

`apps/web/tests/session-scopes.test.ts` (IAM01, "the main site requests only
declared Main resource scopes, and classifies every one") is red. Main
declares two scopes that Account does not register:
- `type:admit` (`services/main/src/modules/types/store.ts`), in the
  `platform-admin` group;
- `wiki:propose`, in the `wiki-agents` group.

Both groups are closed at launch, but a closed group still has granted users.
Administrators hold `platform:use:platform-admin` and need `type:admit`.

1. **Register both scopes** in Account's scope registry
   (`services/account/src/oauth-scopes/`), with descriptions in every UI locale
   the registry already carries. Follow how an existing family is declared.
2. **Mark scopes whose operations sit only in closed platform groups** as
   closed-group scopes. Per the launch-matrix decision (Q15), they are hidden
   from third-party consent screens and refused in dynamic client
   registration. The first-party sites may still request them for granted
   users. Mark at least `type:admit` and `wiki:propose`, and check the other
   families against `generated/openapi/main/exposure.ts`. If a family's
   scopes serve only closed groups (for example commerce, event, package,
   theme, vote), mark them too and list them in the handoff.
3. **Keep the rule in code.** A test fails when Main declares a scope that
   Account does not register, or when a closed-group scope appears in
   third-party consent.

## Do not build

- No change to Main's scope declarations or to the web's request list.
  Launch owns `apps/web`; tell the manager if IAM01 still needs a web change.

## Checks

- Account unit tests for the registry and the consent filter.
- `task account:typecheck`.
- Run `apps/web/tests/session-scopes.test.ts` through `task goal -- test`, and
  report the result.
