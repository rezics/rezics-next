## Outcome

Rate limits apply to every principal class, and pool exhaustion fails quickly
instead of hanging. There are three bounded changes.

1. **Verified search is charged.** In `rate-limit/hook.ts`, a verified reader
   currently skips the search budget entirely ("escapes anonymous search
   capacity"). Charge verified search to the principal's own class budget, as
   every other family is charged (record §13: "all principal classes consume
   read and query budgets"). Anonymous search stays charged per peer.
   - Keep the topic-phrase lookup (`routes.ts`, around line 180) consistent
     with this.
2. **`service` is a workload class only.** `store.ts` `classify()` returns
   `service` for any token whose client is on the allowlist, including a
   person's token issued through that client. Grant `service` only to a
   verified workload principal: a client-credentials token whose subject is the
   client itself. A person's token through an allowlisted client keeps that
   person's class.
   - Classification stays bounded: one indexed lookup per token, cached for at
     most the token's lifetime. A new token never pays more than that.
   - Re-verify the first-round finding on unbounded classification before heavy
     queries (`.temp/arch-review/README.md`, R7/IAM-24, and the token cache).
     Fix only what still holds.
3. **Pool waits are bounded.** `boundedPool` (`infrastructure/pg-pool.ts`) sets
   server-side lock and transaction timeouts but no `connectionTimeoutMillis`,
   so an exhausted pool waits forever (node-postgres defaults to 0).
   - Give every request-serving pool a default checkout wait, chosen against the
     request bounds documented in that file. Main, relay and Account all go
     through `boundedPool`; check each call site.
   - Make nested checkout detectable in code. A caller that holds a client from
     pool P and borrows a second client from P deadlocks under load.
     - Add a check, such as an AsyncLocalStorage marker in `boundedPool`, that
       throws in tests and logs in production.
     - Fix the violations you find in the paths you claim.
     - List the violations in other areas, with file and line, as proposed tasks
       for their owners. Do not edit them. Make sure the check does not turn
       other Goals' suites red before their owners fix them; for example, keep
       it in log mode outside your own tests until then, and say how to switch
       it on.

## Do not build

- No larger pools to escape a deadlock.
- No new principal classes.
- No rate-limit store redesign.
- No per-route budget tables beyond the existing families.

## Checks

- Unit tests of the rate-limit module and `pg-pool.test.ts`; `task main:typecheck`.
- One integration test through `task goal -- test <file>`, covering:
  - verified search consuming the member budget;
  - a person's token through an allowlisted client not getting `service`;
  - an exhausted pool returning a timeout error within the configured wait;
  - nested checkout being detected.
