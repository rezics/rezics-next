## Outcome

Kernel's `runWorkerTick` (services/main/src/worker-tick.ts) runs one worker tick on a fresh
async resource so a pooled `connect()` hold made by that tick (AsyncLocalStorage.enterWith
in infrastructure/pg-pool.ts) does not leak to later workers sharing the startup async
context; leaking makes unrelated workers fault as nested checkouts. Put
`RealmPolicyRecoveryWorker.tick` (modules/access/realm-management-recovery.ts) on it: run
the `withWorkerTelemetry('main.realm-policy.recovery', ...)` call inside
`runWorkerTick('main.realm-policy.recovery', ...)` (see content-projection-worker.ts and
outbox/worker.ts for the pattern), keeping the telemetry name, the page cursor handling,
the error logging, the rescheduling in `finally` and `stop()` behaviour exactly as they are.
No other change.

## Checks

A test in the style of `services/main/tests/worker-tick-isolation.test.ts`: with the
nested-checkout guard in throw mode and a real bounded pool, a recovery tick that holds a
client (fake `recoverRealmPolicies` dependency via a real pool and the real worker) does
not make a second worker started afterwards in the same context fault, and the test
fails without the `runWorkerTick` wrapper (state the mutation). `task goal -- test`, lint,
AST, types. No `--heavy`.
