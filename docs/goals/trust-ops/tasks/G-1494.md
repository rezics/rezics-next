## Outcome

Program's regression run 5 (read `/home/edge/projects/rezics/rezics-next/.temp/goal-program/integration-triage-run5.json`, clusters from G-1235 commit ffa8883e4 "platform grants") shows ~58 integration files failing because every closed operation now needs `platform:use:<group>` and the test stack's principals hold none: platform-closed (27 files), expected 401 received 403 (14), expected 200 received 403 (9), expected 201 received 403 (4), corpus-catalogue-batch 403 (2), bootstrap-no-platform-grant (1), seed-operator-unauthorized (1, scripts/dev/seed/platform-use.ts is launch's file: do not edit it; tell the manager if it must change). Fix the class, not 58 files.

Decisions (manager, 2026-10-09):
1. The integration/QA stack opens every platform group by default through ONE explicit, test-stack-only setting (an environment variable read where the exposure gate resolves open groups, e.g. `REZICS_PLATFORM_OPEN_GROUPS=*`), set by the QA stack bootstrap (scripts/qa/bootstrap.ts is claimed; scripts/qa/stack-environment.ts belongs to program's running G-1493: if the setting can only live there, stop and report the exact hunk instead of editing it). Production defaults stay closed. `scripts/ops/production-env.ts` preflight MUST refuse the variable in production (a test proves it), and the setting must be impossible to enable by a request. Exposure tests that test the gate itself (platform-exposure*, platform-gate*, platform-closed behaviour) opt back in to the closed default explicitly per test file/suite, so they still prove closed-by-default. No feature-flag service, no second evaluator: the existing gate resolves "open" from this setting exactly as it would from a grant `platform:use:*` held by everyone.
2. Anonymous (no or invalid bearer) calls to a closed operation answer 401 before any grant check, so clients know to authenticate; authenticated callers without the grant keep 403 `platform_closed`. Exception that stays: routes that deliberately hide existence behind an identical 404 (GET /v1/realms/{realm}/member-ban, appeal reads) keep their mapping in access/exposure-routes.ts. Update the OpenAPI responses (401 on closed operations) via `task gen`, and the SDK/MCP marks if they derive from it.
3. Record both decisions where the exposure contract lives (docs/development/platform-gates.md if it exists, otherwise the module's header comment and the test names) in two short paragraphs with the reason.

## Checks

Run the 58-file cluster in batches with explicit `task goal -- test <paths>` (integration tier, one QA process at a time, max 5 files per command; `triage` json lists them under the cluster ids) and report before/after counts. Prove with tests: production preflight refuses the variable; a closed-default exposure test still returns 403 for an authenticated caller without grant and 401 for anonymous; an open-groups stack returns 200. No `--heavy`. Lint, AST, types, `task gen`.
