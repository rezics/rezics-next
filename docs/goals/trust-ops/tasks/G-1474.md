## Outcome

Class defect found by launch's G-1467 and routed by program. `createMainApp`
(services/main/src/app.ts ~341) registers a catch-all `.error(...)` hook before the route
plugins, and Elysia runs it first, so route-local `error` hooks never run: a typed
refusal thrown from a hook becomes `500 internal_error` (library-import's read-only
refusal answered 500 instead of 401). `routes/wiki.ts` survives only because app.ts
calls `wikiSchemaError` explicitly. Bare-app unit tests cannot see it.

Fix the class in one place:

1. The app-level hook maps every typed refusal to its own status/problem through ONE shared
   mapping (reuse `routes/problems.ts`' existing mapping of typed errors, e.g. the one that
   maps AccountAssertionInsufficientScope to 401; extend it, do not write a second table).
   Inventory first: grep all route-local `.error(`/`onError` hooks and every typed error
   class thrown from hooks/handlers, and fold each into the shared mapping with its current
   intended status. Unknown errors stay 500 `internal_error`.
2. Remove the dead route-local hooks (and the explicit `wikiSchemaError` call if the shared
   mapping subsumes it).
3. A static guard in `scripts/qa/repository-guards.ts` (existing guard style) rejects
   `.error(`/`onError` route-local hooks under routes that mount in `createMainApp`, so
   dead mappings cannot return.
4. Tests THROUGH `createMainApp`: one per intake refusal (413, 408, 401) and one that lists
   every route that previously declared a local error hook and proves its typed refusal
   keeps its status. Show the 500 reproduction fails the new test on the old code.

Leaking error detail stays as forbidden as it is now: responses carry the problem code
and title only, never messages, stacks, SQL or ids from the thrown error.

## Checks

Real `createMainApp` tests (the repository's usual harness) plus the repository guard and
its test. `task goal -- test`, lint, AST, types, `task gen` if any OpenAPI changes (it
should not). No `--heavy`.
