## Outcome

Second half of C1's authority rules (record §9, list items 2–3).

1. **Management authority follows the current controller and steward of a
   Work, Definition or Space.** It never follows the principal that originally
   provisioned it. Today the creator baseline is bound to the provisioning
   principal in four places:
   - `access/baseline.ts` (around line 112);
   - `access/author-baseline.ts` (around line 24);
   - `access/definition-creator.ts` (around line 55);
   - `space/create-authority.ts` (around line 32).
   After a controller handover, the new controller can manage and the old
   principal cannot.

   The creation receipt stays as provenance evidence only. Agent profile and
   avatar already judge by the current controller; follow that pattern.
2. **One continuity invariant guards every change that affects the effective
   controller.** That covers:
   - a handover, revoking a representation or grant, and ending a stewardship;
   - deactivating a principal (`admission.ts`, `deactivatePrincipal`, around
     line 1650). Today this bypasses the last-controller guard.
   No sequence of these, including concurrent ones, leaves a resource that
   another principal manages with no current controller. The check is per
   resource and indexed, so it never scans a team or every resource of a
   principal.

3. **No nested pool checkout in admission.** While holding a client from a
   pool, `admission.ts` borrows a second client from the same pool through
   `withCommandOwnerAuthority(this.pool)`, around lines 874, 913 and 1506 (the
   last via `editorial-review/admission.ts:97`). Under load that deadlocks.
   Pass the held client instead. `pg-pool.ts` now detects nested checkout:
   run your tests with `REZICS_NESTED_POOL_CHECKOUT=throw`. If the
   `editorial-review` file must change, run `task goal -- owner` on it first.

Re-verify IAM-03 and IAM-04 in `/home/edge/projects/rezics/rezics-next/.temp/arch-review/README.md` (around lines
105 and 163) before you fix them. `space/create-authority.ts` lies in launch's
area. Launch agreed that this task changes that one file (dispatched with
`--allow-area`). Any other `space/**` change goes in the handoff as a request
to launch.

## Do not build

- No per-resource permission fan-out.
- No rebuilt Person ID: the `https://rezics.com/id/{uuid}` key already holds.
- No second continuity check per resource kind.
- No change to admission's exported signatures beyond what T1 left.
- T5 (G-1235) may run beside you and holds `access/grants.ts`, `exposure*` and
  `platform-*`. If continuity needs a hook in `grants.ts`, list it in the
  handoff.

## Checks

- Access unit tests; `task main:typecheck`.
- One integration test through `task goal -- test <file>`, covering:
  - a handover, after which the new controller manages and the old principal is
    denied, for a Work, a Definition and a Space;
  - concurrent deactivation and revocation of the last two controllers, where
    one succeeds and the other is refused;
  - deactivating the sole controller, which is refused, or which succeeds only
    together with a handover.
