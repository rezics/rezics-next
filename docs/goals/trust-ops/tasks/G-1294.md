## Outcome

Qualification needs "no open High security finding". This task reviews REZICS
and hands off a ranked list of findings. It fixes nothing, except that it may
add a failing test that proves a High finding, under the claimed
`security-review*` names.

Review these surfaces, roughly in order of risk:

1. **Account (`services/account/**`):**
   - sign-in, sessions and session fixation;
   - password, passkey and TOTP, and step-up reauthentication;
   - recovery, guardian consent and email change;
   - the OAuth/OIDC provider: authorization code with PKCE, redirect URI
     matching, consent, dynamic registration, token introspection, refresh
     rotation and revocation;
   - Turnstile;
   - the operator admin panel and its roles;
   - CSRF on cookie-authenticated routes;
   - account enumeration.
2. **Main authorization (`services/main/src/modules/access/**`, routes):**
   - admission and claim;
   - the platform exposure gate, including whether any route escapes it or
     its rate limit;
   - IDOR on `/v1/me/*` and resource reads;
   - actingSubject spoofing;
   - grant ceilings.
3. **Server-side request forgery and outbound calls:**
   - connected apps and the MCP client (`connected-apps/protocol.ts`);
   - notification providers;
   - source and catalogue fetchers;
   - package resolvers.
4. **Uploads and media:** content type, size and decompression bombs, image
   parsing, and the safety pipeline.
5. **Injection:** SQL built from strings, SPARQL built from strings,
   JSON-LD, and HTML or Markdown rendering in the web (XSS) and the Accounts
   app.
6. **Secrets and configuration:** production env checks, default secrets,
   and log leakage (G-1260 handled logs).

For each finding, give:
- severity: High, Medium or Low, using CVSS-style judgement: High means
  account takeover, authorization bypass, cross-tenant data exposure, remote
  code execution or SSRF to internal services;
- `file:line` evidence;
- a concrete exploit sketch, conceptual and never weaponized;
- the smallest fix;
- which Goal's area it falls in.

Re-verify before reporting. Drop anything you cannot show in code. Also list
the areas you checked and found clean, so the review's coverage is explicit.

## Do not build

- No fixes. They become separate tasks.
- No scanners or new tooling.

## Checks

- Any proof tests you add fail on current main for the High finding they
  prove, and pass once the fix is applied.
- The handoff is the findings list, ranked.
