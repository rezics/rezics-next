## Outcome

Launch (G-1459, anime and manga Zones): `POST /v1/query` `work-publication-years` lists EVERY Work by year, so a Zone filters by format after the read, scanning up to 8 pages per request and capping there; a Zone's year view is a scan, not one keyset page. Wanted: an optional `concept` parameter (a format/type concept IRI) applied IN THE SEEK INDEX, so a Zone reads one page of its own Works by year with the same cursor, and launch drops the post-read filter.

Today's physical design (read it first): the template's posting lives in `access.template_seek_entry(epoch, graph, predicate, anchor, type, key, id)` (migration 1761), maintained by the native `TemplateIndexService` as statements and decisions change (`DATE_PUBLISHED`, `FIRST_PUBLICATION_*` in `query/year-fact.ts`); the reader pages by `(key = year-sortkey, id)` with a signed cursor, page cost bounded (5,000 extra entries); `template-schema.ts` defines the request/response contract and `serverBoundInputs`.

1. DESIGN FIRST, in RESULT and in the template's header comment, in 15 lines: how a concept scopes the posting without a second index system. Constraints: (a) the answer for a concept is exactly the unscoped answer filtered by "the Work is classified with that concept" under the SAME disclosure and acceptance rules the existing classification read uses (accepted global classification Statement, not erased, readable); (b) one keyset page is a bounded read of one PK prefix: a posting row per `(concept, year, work)` (a Work has few format/type concepts), maintained by the same native writer on BOTH events that change membership: a first-publication date accepted/withdrawn and a classification statement accepted/withdrawn (or its concept retired); (c) no per-request join across the classification population; (d) the cursor binds the concept (a continuation under another concept is refused with the module's existing restart behaviour); (e) concepts are not a closed list in code: any classification concept IRI is accepted (a vertical's concept is data). If the design needs a new column or table, say so; otherwise reuse `anchor`/`type` as the scope key (state the value shape).
2. IMPLEMENT: request schema gets `concept` (optional IRI, validated like the other template IRI inputs; absent = today's behaviour byte for byte, same cursor). The `.rq` and the reader use the scoped prefix when present. Native maintenance of the scoped postings (Java) + the TS reader. Backfill: existing Works must appear in scoped postings after the next index qualification/rebuild (state how: the startup qualification or a one-time derivation from RDF; it must not be an on-demand scan per request).
3. PROVE: unit (`services/main/tests/year-template-concept.test.ts`: request validation, cursor binding, absent concept unchanged), Java (`TemplateIndexConceptTest`: the writer adds/removes scoped postings on date accept/withdraw and on classification accept/withdraw; a concept change moves a Work between scopes), integration (`tests/qa/integration/year-template-concept.test.ts`): three Works (two anime-format with years, one manga-format, one dated Work with no format, one undated), through the public API: concept=anime returns exactly its two in year order in ONE page of limit 20, a page of limit 1 continues with the cursor and a cursor from another concept is refused, withdrawing a classification moves the Work out, and the unscoped read is unchanged. The page cost counters show one bounded read for a scoped page (report the numbers).
4. Existing `year-fact-public-statement.test.ts`, `g-1437-*` year template files and the template guard tests (`grep -rl "work-publication-years" tests services/main/tests scripts | head`) stay green; report run ids. NATIVE: pin changes; `task gen`, image build with Maven; if G-1546/G-1573/G-1592/G-1593 have not all landed, leave the pin-file commits to the manager. Net line count reported; a growth names the correctness gain.
Commit after each step.
