## Outcome

Two small cleanups.

1. **Dead code.** The maintenance dataset reset now admits the Work-name writer after every reset through `admitIntegrationWorkScope` (scripts/qa/stack-startup.ts; cli.ts calls it after bootstrap and after each reset). `exclusiveWriterStartupFiles` (scripts/qa/isolated-integration-files.ts), the old `--force-recreate fuseki` step that used it in scripts/qa/cli.ts, and any helper only they used (for example `resetDisposableExclusiveStack` or other fallback leftovers; grep) have no callers. Verify with grep, delete them, and delete tests that only pinned them (replace by nothing; do not weaken a test that still checks live behaviour). If `scripts/qa/cli.ts` is claimed by another task at dispatch, tell the manager and stop.
2. **Numbered-seek cost cases.** `tests/qa/integration/g-1021-reading-cost.test.ts` and `g-1022-reading-cost.test.ts` seek a chapter NUMBER on a work-composition root. `services/main/src/modules/reading-position/traversal.ts` answers numeric queries on work-composition with 503 `reading_seek_unavailable` ("Episode-number seek is unavailable until its indexed Structure read is ready") unconditionally; the capability is deferred past launch (decision in docs/goals/kernel/state.md). Change ONLY the numbered-seek cases so they assert today's contract: the numeric seek answers 503 `reading_seek_unavailable`, at a flat cost (same assertions on the cost counters that the other requests of the file make, and a comment that the slice, when built, turns the case back into a seek and this refusal assertion forces the update). Every other case in those two files (chooser pages, CJK seeks, saved positions, caps) stays exactly as it is. Run both files alone (`USER=edge LANG=C.UTF-8 LC_ALL=C.UTF-8 task goal -- test <path>`), report run ids and what else in them is still red and why.

Do not build the seek. Do not raise a cap.
