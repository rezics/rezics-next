## Outcome

Launch (QA `20261009t223237-b47096`, branch `goal/g-1459`, `tests/qa/integration/anime-manga-zones.test.ts`) states a first-publication date through the PUBLIC Statement API and `work-publication-years` returns no rows. Cause, verified in code: the year template (`services/main/src/modules/query/templates/work-publication-years.rq`) and its native posting (`infra/jena/command-module/src/main/java/com/rezics/jena/TemplateIndexService.java:35,112,413`) select statements whose `rdf:predicate` is exactly `https://schema.org/datePublished`; a public Statement create writes `rdf:predicate <the property definition's component>` (`statement/graph.ts:279`); the only code that produced `rdf:predicate schema:datePublished` was the Claim fold's retained-claim meaning domain (`prepareRetainedClaimStatementMeaning`, `statement/graph.ts:148`, `schema.ts:183`), which is being deleted. So no product path can state a date the template reads. The Bangumi importer does not state a date either (`importBangumiWorkFacts`: format and counts only). Fix at the source.

Design (the smaller change first; say in RESULT which you took and why):
- A. PREFERRED, no native change: the reviewed binding already named in `statement/qualification.ts:25-39` ("the one reviewed predicate binding ... `statement-first-publication-date-v1`") applies to the public path. A property DefinitionRevision whose notation is `DATE_PUBLISHED_DEFINITION_NOTATION` binds the statements created under it to the reviewed external predicate: a public `POST /v1/statements` with `relationDefinition` = that revision and `predicate` = that definition's component (Launch's request) is stored with `rdf:predicate https://schema.org/datePublished` (and keeps `rv:relationDefinition` so the component stays recoverable). Reads and the Statement resource read return the date under the component the caller used. Implement it in the Statement meaning/write path, not in the template, with the binding keyed on the definition's notation read from the sealed revision (the check `qualification.ts:538` already validates the notation). A value outside date/dateTime/gYear is refused with the existing problem shape.
- B. Only if A cannot work: the template and `TemplateIndexService` select by the relation definition's notation instead of the predicate literal. That is a native change: STOP, commit what is independent, and RESULT says why; the manager sequences it after the other native tasks.
- Seeding: a fresh stack must have the definition without each caller creating it: add the property (notation `statement-first-publication-date-v1`, no roles) beside the declared-count properties in `scripts/dev/seed/relation-lexicon.ts` (`seedWorkFormat` or a sibling the bootstrap and importer share; a notation is unique, so a caller that also creates it gets the existing one) and say which call the dev bootstrap uses. Nothing Bangumi-specific.
- Do NOT build any fold, raw update, hold release or retained-Claim path. Do not touch `claim-fold*.ts` or the Java fold policy (another task deletes them; do not conflict: if your change needs a line in the same file, say so).
