## Outcome

The maintainer's thesis: a new vertical is configuration, never built per source. Case 2 of `docs/goals/kernel/reports/thesis-test-provider-and-composition.md` ("Case 2 — section list", read it first: the table of about 25 rows with file:line, why, replacement and size, and the owner-decision table) fails today: a new composition kind (an ordered list of Works with sections and a text note per entry) cannot be registered without editing the six-id profile enum, the nine-role list, the qualifier union, the route unions, two SHACL `sh:in` lists and a forked work-composition shape. Make a structure profile REGISTRATION (the object `StructureProfileRegistration` that `structure/profiles.ts` already loads by glob from `*/structure-profile.ts`) the whole allowlist: id, owner type, roles (with `target: required|forbidden|optional`), qualifier fields (`text`, `enum`, `boolean`, `rational`, `iri-list`), selection-required roles, which existing reader authorizes targets, and which measures/completion it carries. A kind is then one registration file plus a fixture, with no change under `structure/format.ts`, `structure/profiles.ts`, `routes/compositions.ts` or the structure shapes' `sh:in` lists.

ACCEPTANCE = the report's Case 2 rows (every row in that table is either changed as the "Replacement" column says, or the RESULT says why it stays and who decides, citing the owner-decision table). In particular: `format.ts:38,40,44,77,176,308,336,363`, `profiles.ts:93,129`, `routes/compositions.ts:43,57,66,239`, `stage.ts:136`, `change.ts:680`, `disclosure-read.ts:56,57,74`, `structure-composition-v1.ttl:15,66`, `structure-work-composition-v1.ttl:14,26` (delete the fork), `OccurrenceLabelIndex.java:43`, `read.ts:244,367`, the three hand-written qualifier projectors (`composition/`, `recipe/`, `zone/structure-profile.ts`) become one field-template projector for the declared fields, keeping the Work cycle guard (`composition/structure-profile.ts:43`) and the Zone reserved route segments as owner checks.

PROOF (the thesis test, as a test): `tests/qa/integration/structure-profile-section-list.test.ts` registers a NEW profile `section-list-v1` through a single new registration file under the test fixtures or `services/main/src/modules/**/structure-profile.ts` per the glob rule (roles `section`, `entry`; qualifier `entry: { note: text }`; disclosure by the work reader; owner type CreativeWork), then through the PUBLIC API: `POST /v1/compositions` creates it, an insert with a note round-trips, an update of the note works (the qualified-occurrence update path fixed by G-1571), an unreadable target is withheld, a Work cannot contain itself. It must pass with an empty diff under the files named above except the registration. Existing profiles (book, work, recipe, zone, collection, wiki) pass their existing tests UNCHANGED: run `grep -rl "composition\|structure-profile\|recipe-structure" services/main/tests tests/qa/integration | head -60`, run those touching structure/composition/recipe/zone/collection and report run ids; plus `composition-change-cost.test.ts`, `recipe-change-sequence.test.ts`, `g-1014-structure-cost.test.ts`.

Rules: stored artifacts stay immutable: the structure object format versions by hash of bytes (`format.ts:7`); a profile id that the format enum pinned stays valid for every existing object; do not edit a persisted profile in place. The OWNER decisions in the report stay decisions: a registration can name only an EXISTING reader/permission (`work:read`, resource, structure-target); inventing a permission or disclosure rule is not data. NATIVE: the one Java line (`OccurrenceLabelIndex`) and the shape changes change the Fuseki pin: do `task gen`, build the image (Maven must pass), leave the pin-file commits to the manager if G-1546/G-1584/G-1573 have not landed (check `git log main -3 -- infra/dev/compose.yaml`; if main moved, take main's pin files and regenerate). NET LINE COUNT: the report sizes this at about 70 lines added against about 150 deleted (two shapes forked, five qualifier branches, three hand-written projectors); report `git diff --stat main...HEAD` for non-test source; if the change GROWS the code, state the correctness gain that justifies each added file (the field-template projector replaces three, so growth is not expected). Commit after each cluster (format/profiles, routes, disclosure, shapes+Java, projector, test).
