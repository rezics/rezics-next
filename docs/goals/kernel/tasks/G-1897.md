## Outcome

Program's decision (2026-10-12): (A) with one boundary. A COPYRIGHT restriction on an IMPORTED cover suppresses every other IMPORTED cover asset with the same original digest, and restoration lifts them together. It does NOT touch an asset with the same bytes that a user uploaded (that is the user's own claim and may be the rights holder's own upload; decision 55 splits responsibility: covers we import are shown on our basis and taken down on notice, so every imported copy of one file stands or falls together). NCII is different (content decides; its path stays unconditional and unchanged).

Where: `services/main/src/modules/governance/effects.ts`, the `apply()` media branch (about lines 165-195): today `store.suppressIdenticalCopies(plan.media.digest, continuation, 100, plan.suppression)` runs only when `plan.ncii`, and `restoreIdenticalCopies(plan.lift, ...)` only when the plan carries a lift; and `MediaStore.suppressIdenticalCopies` / `restoreIdenticalCopies` / `registerCopySuppression` in `services/main/src/modules/media/store.ts` (about lines 1155-1330, README section about `suppressIdenticalCopies`). The planning half (where `plan.ncii`, `plan.suppression` and `plan.lift` are decided and the saved suppression basis is written) is in the same effects file's `plan` function and in governance (read it fully first): extend the plan with a copy SCOPE (`all` for NCII as today; `imported-cover` for a copyright decision whose media target is a cover-only imported asset) and the SAME saved basis and lift mechanism, so replay, continuation, lost acknowledgement and restoration behave exactly as the NCII path does.

The predicate for "imported cover": `media.asset.cover_only` (set at asset creation by the imported-cover provenance and immutable by the migration `2130_media_imported_cover.sql` trigger) joined from the digest lookup (`media.representation` kind `original` and `byte_digest`, already indexed by `imported_cover_original_digest_lookup` in that migration). The sweep candidates are ONLY assets with `cover_only = true`; an ordinary asset with the same bytes is never a candidate, never suppressed, never lifted by this path. Bound the sweep with the existing 100-per-batch continuation and a typed incomplete outcome over the cap (as the NCII path); restoration lifts exactly the copies THIS decision suppressed (the saved lift), not copies suppressed by another decision.

Proof (new `services/main/tests/imported-cover-copy-suppression.test.ts`, owner tier with the Media store on its test database as the existing media store tests do; read `services/main/tests/` media and governance effect tests for the setup): (1) a copyright restriction on imported cover A suppresses imported cover B with identical bytes (B's state `suppressed`); (2) an ordinary user-uploaded asset C with identical bytes is NOT suppressed; (3) restoration lifts A and B together and leaves C unchanged and any copy suppressed by an unrelated decision still suppressed; (4) replay and a lost acknowledgement after the first batch do not double-suppress; (5) the NCII path is unchanged (existing tests pass); (6) a cover-only asset with different bytes is untouched. The integration proof is `tests/qa/integration/imported-cover-lifecycle.test.ts` (on the cover proof branch, the final case flips from expected-failure to passing when this lands: do not edit it).
