## Outcome

Found by the recipe amounts task's inspection (a function defect, class A, small): the importer (`services/main/src/modules/recipe/importer.ts`, functions `ingredient` and `structuredIngredient`) stores `amountLexical: value`, i.e. the WHOLE ingredient line ("1½ cups flour"), as the quantity's lexical form; but the readers derive the ingredient NAME by removing `amountLexical` (and the unit) from `originalText` (`services/main/src/modules/recipe/operations.ts` about line 42 `ingredientName(line.originalText.value, line.amountLexical, line.unitText)`, and `services/main/src/modules/recipe/display.ts`), so for an imported line the name is stripped to nothing. `services/main/src/modules/recipe/export.ts` line about 28 even compares `amountLexical !== originalText.value`, so it knows the two can be equal. Launch's corpus journey did not hit it only because the pinned lines go through paths that keep the text.

Do: (1) establish the contract: `amountLexical` is the QUANTITY text as written (for "1½ cups flour" it is "1½"; for "2 to 3 tablespoons butter" it is "2 to 3"), `originalText` is the whole line (read `docs/contracts/` recipe text, `structure/format.ts` line about 140, `quantity.ts`, and the owner tests to confirm; if the documents say otherwise, follow the documents and say so); (2) FIX THE IMPORTER so `amountLexical` is exactly the matched quantity text (the leading amount or range as parsed by `exactAmount` and the range parser from the amounts task, which is on main), never the whole line; a line with no parseable amount keeps NO `amountLexical` (it stays unparsed with its original text); (3) make the NAME derivation robust for DATA ALREADY IMPORTED (stored lines whose `amountLexical` equals the whole original text): when `amountLexical` equals `originalText.value`, re-derive the quantity prefix by parsing the original text (same parser), so the name is never empty; do not rewrite stored data; (4) tests `services/main/tests/recipe-ingredient-name.test.ts` (owner tier): imported lines with fractions, mixed numbers, ranges and no amount keep their name through `ingredientName`, `display` and `export`; a stored line with a whole-line `amountLexical` still yields its name; export round trips the quantity text. The existing recipe importer, operations, display and export tests must stay green (run them in the same call). Do not change routes, schemas or the model.

Worktree discipline: relative paths only. QA discipline (Program): ONE goalctl test call; no reruns of passing files; fixtures grant access through grantFixtureAuthority. One session; commit and report.
