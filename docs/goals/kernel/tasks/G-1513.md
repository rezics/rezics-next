## Outcome

The maintainer's decision 55, as amended (`docs/contracts/source-lifecycle.md#platform-imports-and-user-contributions`, commits 167c2919f and ca5e77528; read that section and `docs/contracts/license-grants.md` first): Bangumi's copyright page (bgm.tv/about/copyright) puts subject information (summaries and chapter information included) and character information under CC BY-SA 3.0; users' blogs, posts (吐槽) and images belong to their authors. For the Bangumi importer (`scripts/datasets/bangumi.ts`, the Bangumi Archive dump, G-1435 wrote the facts):

1. **Import** subject and character information, summaries included (titles, aliases, dates, counts, status, staff and relations, summaries, character fields).
2. **Never import** Bangumi user posts: blogs, 吐槽 (tsukkomi), reviews, comments, ratings text, user collections text. Verify against the real captured records in `services/main/tests/bangumi-captured-subjects.json` and the archive schema what free-text fields exist and which belong to users; skip those fields at the importer level (not hidden at read time), and add a test that fails if a field from a user-post list appears in the produced import payload.
3. **No covers or images.** The publishers own the art, so the uploader's licence does not cover it: the importer must not carry any image or cover URL/field into a Work.
4. **Source and licence on every imported statement and text.** Each imported statement and each imported text (summaries) records its source (the Bangumi subject or character URL, `https://bgm.tv/subject/{id}` or `/character/{id}`) and its licence (CC BY-SA 3.0, with the licence URL `https://creativecommons.org/licenses/by-sa/3.0/`). Find the existing provenance mechanism (Statement acceptance and the source evidence edge, PROV export, `rv:` source/licence predicates, the catalogue-import source-reported rows; see `services/main/src/modules/work/catalogue-import.ts` and `docs/contracts/source-lifecycle.md`) and use it; do not invent a parallel one. Prove that the source and licence travel through the public reads (`GET /v1/resources/{id}/statements`, the Work page read) and the PROV export of the same Work: write an isolated integration test through the API that imports two captured subjects (one anime, one manga) and one character and asserts source URL and licence on a fact, on the summary, in the statements read and in the export.
5. **Edits stay CC BY-SA.** An edited or translated imported summary is an adaptation and stays CC BY-SA 3.0. Check how `license-grants.md` and the native edit path treat a user edit of an imported text field: does the licence/source stay attached when a user edits it natively? Report exactly what happens today with a test or a code citation. If the licence is dropped on edit, fix it in the smallest way (the edit keeps the imported source+licence as an adaptation note) or, if that needs a design decision, stop and report the options.

Do not build: a new provenance model, an image pipeline, the web display (Launch's G-1459 shows "Bangumi", "CC BY-SA 3.0" and a link), or changes to non-Bangumi importers. Keep the import going through the API (writes go through the API). Do not raise caps.
