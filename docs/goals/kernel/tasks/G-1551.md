## Outcome

G-1544's mechanism guard (`scripts/static/mechanisms.ts`, `scripts/static/mechanism-dependencies.json`, enforced on land and merge) froze 146 crossings into Access, an exact list that can only shrink. `services/main/src/modules/access/rating-aggregate-inventory.ts` (558 lines; 9 importers: `rating/release-aggregate.ts`, `rating/target-inventory.ts`, `rating/experience-aggregate.ts`, `rating/legacy-reconstruction.ts`, `rating/global-aggregate.ts`, `rating/target-aggregate.ts`, plus `access/admission.ts`, `routes/dependencies.ts`, `composition.ts`, `routes/problems.ts` and tests) is rating logic written inside Access. Move it into the rating module (`git mv` to `services/main/src/modules/rating/aggregate-inventory.ts`; keep the content and behaviour identical), update every importer, and for each primitive it needs from Access import it through an EXISTING Access entry point (see the `access-authority` mechanism in `scripts/static/mechanisms.ts`); if it needs something Access does not expose as an entry point, report it instead of widening the entry-point list (Trust-ops owns Access: do not add entry points without asking the manager). Where `access/admission.ts` imports the inventory (an Access file depending on rating): decide with evidence whether that is a real dependency of the admission (then it is a crossing from Access into rating that the guard must accept as an exact pair or be inverted by passing the inventory in) or can be inverted at the composition (`composition.ts`); prefer inversion and say what you did.

Remove the exact entries this makes stale from `scripts/static/mechanism-dependencies.json` (the guard fails on a stale entry); the list may only shrink: do not add any entry. Run the guard tests and every test that imports the moved file. Behaviour change: none; no cap changes.
