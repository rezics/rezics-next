## Outcome

Class A, REPRODUCED (QA run `20261011t114710-4e4a7b`, branch `goal/g-1738`, commits `8015998db` and `29e4f0a53`, test file `tests/qa/integration/query-filtered-mine-owner.test.ts`, red by design there): a signed-in member's `POST /v1/query` with a concept filter and `scope: mine` answers 401 `account_assertion_denied` ("Account assertion is invalid or inactive") instead of 200 with their own Works. Cause, from the reproducer's analysis: the concept-works branch of `services/main/src/routes/query.ts` (about lines 138 to 147) sends a compiled filtered-mine request, which carries `actingSubject` and `scope: mine`, through `publicWorkRead`; the request that `services/main/src/modules/display-language/public-request.ts` rebuilds for the nested read drops the authorization header, and `services/main/src/modules/work/read-session.ts` (about line 386) then rejects the retained `actingSubject` because the rebuilt request is unauthenticated.

Repair: a compiled filtered query whose scope is `mine` is read through the SAME authenticated owner path that `GET /v1/works` with `scope=mine` already uses (`services/main/src/routes/discovery.ts` lines about 54 to 56, the authenticated Work session with `actingSubject`; read it and reuse it, do not build a second authenticated path). Public and non-mine filtered queries stay on `publicWorkRead` unchanged. Do NOT make mine public to avoid the denial; the owner-only isolation must hold: another signed-in member and an anonymous caller must NOT see the member's own Works and must get the module's existing denial, not a 5xx. Cache header for the mine answer: `private, no-store`. A continuation page binds the same scope and owner.

Proof: bring the reproducer onto your branch (`git show goal/g-1738:tests/qa/integration/query-filtered-mine-owner.test.ts`, commit it with the fix), run it alone until green with its four assertions (own Work present with 200; other member and anonymous do not receive it; continuation binds scope), then the existing Query and discovery tests of the changed files (`grep -rl "scope: 'mine'" tests/qa/integration services/main/tests`). Turns green: nothing in run 9 (new finding); it closes the signed-in "my filtered list" gap the G-1713 audit flagged.
