## Outcome

The first public Bangumi-like page needs these facts (Launch mail `launch-wave2-kernel-reply-1008`; kernel decisions in brackets). A new vertical is configuration, not a handler: add data, not code paths.

- **Format**: exactly one value per Work from a closed list TV, movie, OVA, ONA, special, manga, one-shot. [Represented ONLY as a format concept scheme, classified with `rv:classifiedAs` Statements plus acceptance exactly like genres, so a Zone filters it with the existing concept facets. Do not also use `schema:TVSeries`/`schema:Movie` for this meaning, and do not add a manga type.] Find how the genre/concept scheme is declared and seeded (`facet-concept`, the concept scheme seed, `scripts/dev/seed`) and add the format scheme the same way; at most one format concept per Work is enforced where the scheme mechanism can express it, otherwise by the importer.
- **Counts**: declared episode count (anime) and declared volume count (manga) as `PropertyDefinition`s with literal Statements, following `tests/qa/integration/g-693-wiki-journey.ts` for how definitions and literal Statements are authored and accepted. No chapter count, season property or magazine.
- **Status**: the Work `completionStatus` enum (work/metadata-schema.ts) gains `upcoming` and `cancelled` beside `ongoing`, `completed`, `hiatus`; update the shape/model source (SHACL Turtle where it is the author source) and the generated outputs with `task gen`.
- **Importer**: `scripts/datasets/bangumi.ts` sets the format concept (map Bangumi's subject type/platform to the six values; unknown stays unclassified), the declared count and the status; it writes through the API like every import.
- **Year and season** are NOT stored: they derive from the existing first-publication date Statement (`schema:datePublished`). Do not add a season.

Do not build: a new Work type, a handler, a new read/facet (G-1437 owns the year template), new credit roles (G-1436), any web UI.

## Checks

- Unit test `services/main/tests/anime-manga-facts.test.ts` proving the definitions validate, a Work accepts one format and rejects an unknown one, `upcoming`/`cancelled` validate, and the importer maps the six formats from captured real Bangumi records (use real captured output, not synthetic strings).
- Isolated integration `task goal -- test tests/qa/integration/anime-manga-facts.test.ts`: import two Works through the API, read the format through `facet-concept` and the counts through `GET /v1/resources/{id}/statements`.
- `task gen` outputs committed, `task main:typecheck`, model checks the change selects (`task goal -- test --affected --list`).
- A model change means the manager runs `task dev:refresh -- --wait` after landing; report whether it is needed.
