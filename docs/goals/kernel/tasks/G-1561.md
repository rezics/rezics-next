## Outcome

`tests/qa/integration/discovery-continuous-writes.test.ts` ("discovery activates under a steady stream of unrelated votes and shelf changes, and a vote on its Work reports it stale until a delta covers it", G-1179/G-1183) hit its 240,000 ms test cap on main (QA `20261009t181000-5b1326`, ordinary class, 241 s). Earlier survey runs also failed it at the same cap. It may be host load (the Docker VM has been OOM-killing QA stacks because of leaked stacks: Program was mailed) or a real cost regression in the discovery build, catch-up or delta path.

1. Before running, check the host: `docker ps | grep -c rezics-qa` and `free -g`; if more than ~30 QA containers or less than 8 GiB available, wait (the leaked stacks are Program's to prune) and say so in RESULT. Run the file ALONE, twice, on the current main; report both run ids and times.
2. If it passes alone inside the cap on a quiet host: report it as load, change nothing, and say how much headroom it has (time of the slowest phase).
3. If it fails or has under 20% headroom: find where the time goes with evidence (timestamps or counters around the steady-write phase, the activation, the catch-up and the delta; the request-cost contract counters; Fuseki and SQL call counts per phase), identify which phase grew and the change that grew it (`git log` of `services/main/src/modules/discovery/**` and of the worker-tick, composition and projector code), and fix the cost in the product code at its source (a bounded neighbourhood, not a larger cap or a smaller write stream). Never raise 240_000, never reduce the number of writes or votes, never weaken an assertion.
4. If the file needs more than the ordinary allocation by design, say so with measured memory and move it to the matching class in `scripts/qa/resource-classes.ts` only with that evidence.

Commit after each step.

The file alone (twice) before and after any change; `task main:typecheck`; the discovery unit/owner tests next to any changed module (`grep -rl discovery services/main/tests | head`, run three); `task gen:check`.
