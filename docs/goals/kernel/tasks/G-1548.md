## Outcome

Program's decision: `rv:restoreHold` on and off, and a bare data-epoch cutover (sequence 0, `RestoreCutover`, no hold, routing epoch unchanged) are reachable only inside a full restore cutover (`cutoverRestoredGraphLineage` sets the hold; no public route does). `services/main/tests/work-read.integration.test.ts` (and the read-session restore-hold filter tests) hand-write these states. A state no operation produces is not a state a read must survive; a CRASH state is produced at the real crash point with fault injection, not by hand-built triples. Build a **fault-injection seam at the real crash point inside `cutoverRestoredGraphLineage`** (find it: `grep -rn "cutoverRestoredGraphLineage" services infra scripts`), used from the **fault/recovery tier** (`tests/qa/fault-recovery/`), no public route.

Design constraints: the seam is an explicit, narrow test hook that makes the cutover stop (or throw) at named points ("after the hold is written", "after the data epoch swap, before the hold clears") so the real intermediate states exist in the real graph, then the test calls the real recovery path to finish or roll back. It must be impossible to trigger in production (not reachable from any route; compiled out or guarded by a QA-only environment/flag that production compose and release manifest do not contain; add a guard test that the production compose does not set it, the way the repo guards similar flags), and it must not change the cutover's behaviour when unused. If the cutover is native (Java), the seam lives in the command module and the image pin moves: after `task gen` rebuild under the heavy slot, report Maven totals and the pin, rebase on main first (another native task is in flight), do NOT run `dev:refresh`.

Then write one fault/recovery test using it: produce (a) the held state (hold on) and read through a Work read: it must answer unavailable (the restore-hold filter), (b) release/finish and read again: available, (c) the bare epoch-swap state if it is a real intermediate state of the cutover (state which point produces it, else say it is not a real state and should be dropped). Replace nothing in work-read.integration.test.ts (another task edits that file); report the exact seam names for its author.
