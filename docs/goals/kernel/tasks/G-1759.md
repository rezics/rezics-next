## Outcome

Launch L20a (Program: A, decided 2026-10-11). A cook can author and read Recipes, but cannot import a recipe FILE: source intake is `platform:catalogue-import`, and the browser scopes exclude source intake and adoption, so an ordinary cook cannot create the retained source observation that `POST /v1/recipes/{id}/imports` (`importRecipe` in `modules/recipe/importer.ts`) requires. Evidence and plan: `.temp/goal-launch/evidence/g-1747-sizing.md` section L20 (staged in your worktree at `.temp/ref/g-1747-sizing.md`).

Provide ONE constrained public operation, `POST /v1/recipes/{id}/file-imports`, under WORK EDIT AUTHORITY of that Recipe (the same authority that governs editing it; no catalogue-import platform grant), that: accepts a bounded Schema.org Recipe file (JSON or JSON-LD, at most 256 KiB, one Recipe; refuse HTML, scripts, remote URLs and arbitrary JSON-LD graphs: no fetching of any kind), retains the exact bytes through the EXISTING Source retention owners as a source observation owned by this Work (find the owner helpers `grep -rn "retain\|observation" services/main/src/modules/source/intake.ts services/main/src/modules/recipe/importer.ts`; reuse them, do not build a second retention path), and then runs the existing `importRecipe` owner with an expected structure head. Replaying the same file with the same idempotency key must not duplicate sections, ingredients or steps; a stale expected head answers the existing stale-head conflict; a reader without edit authority gets the existing denial (hidden equals absent for a hidden Recipe); an unparseable file answers a typed 422 without retaining anything public.

Declare its exposure and rate limit as every public operation must (find how `routes/recipes.ts` and `scripts/static/` declare exposures and rate families; this operation is open to an authenticated cook with edit authority, not a platform capability). Trust-ops reviews the new public exposure: mail them the exposure declaration and the diff BEFORE landing (new variants of public operations escape the closed-by-default declaration unless a test refuses an ungranted caller: include that test).

Proof: `tests/qa/integration/recipe-file-import.test.ts` through the API with a REAL retained file (use a public-domain recipe file from `tests/fixtures`; if none exists use a small hand-written Schema.org Recipe with sections, a fractional quantity and a non-ASCII title, stored beside the test with its provenance in a comment): success retains and imports; the same key replays without duplicates; a denied editor; a stale head; an oversized file; an HTML file; an ungranted caller refused. Unit file `services/main/tests/recipe-file-intake.test.ts` for the bounds and the parser. Out of scope: HTML scraping, arbitrary JSON-LD extraction, complete metadata and measures roundtrip (separate, unsized).

## Mechanisms

access-authority: consume — the existing Work edit authority for the Recipe; no new decision and no new permission.
