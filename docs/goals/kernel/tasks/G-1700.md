## Outcome

Class A, same defect class as the landed owner-recovery fix (read that commit: `git log --oneline -3 -- services/main/src/modules/owner/object-coverage.ts`): a verified digest cache can satisfy a custody or verification read after the physical object has disappeared or changed, so a false proof is possible. Wrap the retained-store reads of `outbox/receipt-custody.ts` and `semantic/model-custody.ts` in the existing `withoutVerifiedImmutableObjectCache` helper (`immutable-objects.ts`), preserving signal and byte bounds, integrity checks, typed failures and the permitted local fallback; do not clear the global cache in a fixture and do not turn caching off for ordinary reads. Audit `erasure/custody.ts` too and only REPORT it (it is Trust-ops' area; do not edit). Proof: two new unit files modelled on `owner-recovery-cache.test.ts` (warm-cache loss and corruption, valid selected-store bytes with no local file, abort and byte-limit handling). Waits for the rating and semantic task that currently claims `model-custody.ts` to settle.
