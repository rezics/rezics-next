## Outcome

READ-ONLY MEASUREMENT; change no owner path. `docs/goals/kernel/reports/digest-construction-inventory.md` (staged at `.temp/ref/digest-construction-inventory.md`) classed two digests HIGH by code reading only (no data was sampled). Program wants them measured on retained data:

**Row A. Source/native field `valueDigest`** (`services/main/src/modules/source/support-attach.ts` lines ~110, 134, 143; rehashed in `services/main/src/modules/source/withdrawal.ts` ~136-146). The SOURCE side hashes `JSON.stringify(value)` of the value JSON-parsed from retained raw bytes at a JSON pointer (key order = the source file's order); the NATIVE side hashes `JSON.stringify(adapter(revision))` of a value read from a native Work revision or a Structure occurrence record (key order = the native representation's). The two are compared before attaching, `value_digest` is stored, and withdrawal rehashes both.

**Row B. Qualifier-index record equality fingerprint** (`services/main/src/modules/structure/qualifier-index.ts` line ~20, `createHash('sha256').update(JSON.stringify(value))`, used at ~79-81 and ~102-103; the supplied record is constructed at `services/main/src/modules/structure/graph.ts` ~328, the retained record comes from a `StructureTree` lookup).

Answer, for EACH row, with numbers:
1. How many retained values/records exist, and how many are OBJECT or ARRAY valued (scalars cannot differ by key order).
2. Of those, how many would hash UNEQUAL if the two sides assembled the same value with a different key order: recompute each retained pair under the writer's order and under a sorted-key canonical form and compare (for Row A: the stored `value_digest`, the source value from the retained raw bytes, and the native value read through the adapter or tree; for Row B: the retained record and the record the current constructor would build for the same occurrence).
3. Whether any attach, withdrawal or index operation has ALREADY failed or wrongly passed for that reason (receipts or step rows with `FieldWithdrawalConflict`/refusals, `value_digest` mismatches, index delta disagreements) in the retained data.
4. A one-line verdict per row: `LIVE MISMATCH` (some retained pair already disagrees or a refusal has happened for this reason), `LATENT` (object-valued retained values exist and only an order change could break them), or `NONE` (no object-valued retained value, so the risk is hypothetical today).

The manager then runs the same script against the shared development dataset; so write it to print ONE JSON object and to be safe to run on a live stack (statement timeouts, LIMITs, paged scans, a hard cap on rows with the count of rows it did not examine).
