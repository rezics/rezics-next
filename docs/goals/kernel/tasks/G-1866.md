## Outcome

Class A, same defect class as the landed owner-recovery fix (read that commit: `git log --oneline -3 -- services/main/src/modules/owner/object-coverage.ts`): a verified digest cache can satisfy a custody or verification read after the physical object has disappeared or changed, so a false proof is possible. Wrap the retained-store reads of `outbox/receipt-custody.ts` (the model custody half is the sibling task G-1700, running separately) in the existing `withoutVerifiedImmutableObjectCache` helper (`immutable-objects.ts`), preserving signal and byte bounds, integrity checks, typed failures and the permitted local fallback; do not clear the global cache in a fixture and do not turn caching off for ordinary reads. Audit `erasure/custody.ts` too and only REPORT it (it is Trust-ops' area; do not edit). Proof: one new unit file (`receipt-custody-cache.test.ts`) modelled on `owner-recovery-cache.test.ts` (warm-cache loss and corruption, valid selected-store bytes with no local file, abort and byte-limit handling). WAITS for Trust-ops' G-1792 (erasure/custody.ts roots and the historical result, which is on `receipt-custody.ts`) to land; G-1826 and G-1784 are on main (the lock lifecycle): rebase on current main and read their `receipt-custody.ts` before wrapping, so the cache bypass goes around the NEW functions.

Worktree discipline: relative paths only. QA discipline: one goalctl test call; no reruns of passing files.
