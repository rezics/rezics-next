## Outcome

`task search:rebuild` (`scripts/operations/rebuild-content-search.ts`) cannot finish on the shared dev dataset (22 GiB TDB2). Program ran it on the stopped-writer stack at 01:55 UTC (Fuseki up alone): exit 1 after 214 s with a bare `TimeoutError: The operation timed out.` and no context. Fuseki's log: the rebuild's verification read `SELECT ?variant ?resource ?decision ?eligibility ?revision ?digest ...` (services/main/src/modules/content-publication/rebuild.ts ~line 314, run inside one `Promise.all` with four other full-population reads) answered 503 after 10.9 s against Fuseki's 10 s query timeout; the sibling read was cancelled at 10.96 s; the probe and the others passed. The query joins the `current`, `revisions` and `receipts` graphs for EVERY content variant in one SELECT (receipt patterns by predicate, with `LIMIT MAX_REBUILD_UNITS + 1`), which does not scale: the bounded-neighbourhood rule is violated.

1. REPRODUCE on a real-size dataset without touching the shared stack: a copy of the dev Fuseki volume exists as the docker volume `kernel-g1584-fuseki` (read-only for you: make your OWN writable copy, `docker volume create <yours>` then `docker run --rm --network none --user 0:0 -v kernel-g1584-fuseki:/from:ro -v <yours>:/to --entrypoint sh <postgres image from infra/dev/compose.yaml> -ec 'cp -a /from/. /to/'`; about 22 GiB, 460 GiB free; delete your volume when done). Start a throwaway Fuseki container of the CURRENT pinned image (`infra/dev/compose.yaml` fuseki service: same image, entrypoint and environment) on your copy at a spare port (no Main, relay or Account) and run the exact reads of `rebuild.ts` against it with timings, per read. Report each read's duration and result count (the number of content variants, public MatchUnits, receipts).
2. FIX the reads, in `rebuild.ts`: replace each whole-population join with a keyed, paged read: (a) page the DECLARED variants (`?variant rv:publicSearchEligibilityHead`) by ordered keyset (`FILTER(?variant > <last>) ORDER BY ?variant LIMIT N`, N a named constant), (b) for each page fetch the heads/decision/eligibility/revision/digest and receipts with `VALUES ?variant { ... }` (or per-subject joins keyed by the page's variants, receipts by `rv:variant ?variant` bound, not scanned by predicate), (c) page the public MatchUnits the same way and compare page by page; keep the single-statement `publicTextInventory()` and probe reads. Keep every result exact (no sampling): the same declared/heads/rdf/index comparison, over pages, and a unit that has no head or no unit still fails the rebuild with the same typed error. No read may exceed a named per-read budget (state it; keep under the 10 s Fuseki query timeout with a margin, on your copy).
3. NAME THE STEP. A timeout must say which step and page it was in: wrap the reads so a `TimeoutError`/abort becomes `ContentRebuildUnavailable('<step>: timed out ...')` with the step name (declared page, heads page, units page, inventory, probe, control) and the page ordinal, and the CLI prints it (no bare `The operation timed out.`). Check `scripts/operations/search-state.ts`/`search-startup.ts` for the same bare timeout where they call Fuseki or the module (startup wait, `commandHealth`, rebuild command) and give each a step name.
4. PROVE: on your copy, the rebuild's verification passes in under a stated time with every read under budget (report durations). `services/main/tests/content-rebuild-bounds.test.ts`: with a fake fuseki that records queries, assert no read contains an unbounded multi-graph join: every heads/receipts read carries a `VALUES` or keyset bound and a `LIMIT` of the page size; the timeout step naming; a missing head still fails typed. Integration `tests/qa/integration/content-search-rebuild.test.ts` if an existing rebuild integration file exists (`grep -rl "rebuildPublicContentSearch\|resumeActivatedContentRebuild" tests scripts | head`), extend it instead and run it alone; report run ids.
5. Do NOT run `task search:rebuild` on the shared stack and do not touch the shared Fuseki: Program runs it. Coordinate with G-1584 (it changes native startup qualification and uses its own copy): do not edit its Java files.
Commit after each step.
