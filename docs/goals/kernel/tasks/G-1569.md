## Outcome

Abstraction audit A2, report-only. REZICS' thesis (maintainer): a new vertical or provider is configuration, not code: "cost is the point". Test it with two unseen cases and write ONE report; change no product code and add no test.

Case 1, an unseen PROVIDER mapping: a catalogue source Main has never heard of (call it `acme-catalogue`), with a record shape of its own, mapped into Works, Titles, credits and facts through the existing Statement/Source machinery, activated with data (a mapping, a source profile, an allowlist) and NO new Main branch or native change.
Case 2, an unseen COMPOSITION BINDING: a new composition kind (for example an ordered list of Works with sections and per-entry notes, not a Recipe, not a Structure of chapters) bound to a Work-like owner, with its qualifiers, ordering and disclosure declared as data.

For each case, walk the real code from the entry point and list, as a table, every place that would need a code change today and the smallest data-driven change that would remove it. Start from these suspects and add whatever else you find: `infra/jena/command-module/src/main/java/com/rezics/jena/SourceProjectionPolicy.java` and the Open Library constants in `services/main/src/modules/source/*` (acquisition.ts, graph-projection.ts, intake.ts, field-*.ts); `services/main/src/modules/structure/format.ts` (the six profiles) and the Recipe-only qualifier union; `services/main/src/modules/composition/disclosure-read.ts` branches; `profiles.ts`; any `switch`/`if` on a provider id, profile name, structure kind or family in `services/main/src/**`; `scripts/static/` registries; the Bangumi importer mapping (the existing example of a provider declared outside Main: how much of it is data?).

For each blocker the report gives: file:line, what it hard-codes, why (a real decision or incidental), the data-driven replacement, what test would prove the new provider activates with no code change (name the fixture), and a size estimate in files/lines. End with a ranked list: the three changes that remove the most blockers per line, and anything that can NOT be data (a genuine owner decision), with the reason. Keep the report under 600 lines; tables, no prose padding. Write it to `docs/goals/kernel/reports/thesis-test-provider-and-composition.md` (create the directory; this is a decision record for the manager and Program to read, not a document to maintain).

Do not build the change. Do not edit product files. Commit the report.
