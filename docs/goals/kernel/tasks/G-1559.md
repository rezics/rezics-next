## Outcome

Program's tooling audit item 12: Content's typed-query pilot (`services/content/src/typed-schema.ts`, drizzle table definitions) earns one read (`ownerControl` in `core.ts:5`) and carries unused schemas (`receipt`, `outbox`, ...). The SQL migrations are the DDL owner, so the layer adds a second description of the tables.

Choose the smaller change, say why in RESULT, and do it:
- (a) Prune: keep only `ownerControl` and the imports it needs; or
- (b) Replace the singleton query in `core.ts` with the typed `pg` call the surrounding code already uses, delete `typed-schema.ts` and drop the `drizzle-orm` dependency from `services/content` if nothing else in the workspace imports it (check `grep -rn "drizzle-orm" --include=package.json .` and source imports; `yarn` only installs: update the lockfile via the repository's Task command, see `docs/development/toolchain.md`, and update that document in the same change if a tool is removed).
Prefer (b) when `ownerControl` is the only drizzle use in the whole repository; prefer (a) otherwise.

Prove: every importer of the schemas (grep), the owner-control read behaves identically (the existing Content tests that touch the sequencer/owner control, `grep -rln "owner_control\|ownerControl" services/content | head`, run them), `task content:typecheck` or the equivalent. Do not touch migrations. Commit after each step.
