## Outcome

The maintainer decides after this whether to converge local consistency (contract C3) before opening. Inventory, per file and per kind, every place that PERSISTS or DEPENDS ON a site-wide order: `rv:sequence` (about 200 source files reference it), the global outbox position and sequence-bound cursors, the site-wide model generation guard (`modelGeneration`, about 22 files), before/after graph positions in receipts and cursors, and any read that requires a quiescent graph. For each persisted kind give: where it is written (file:line), what stores it (graph receipt, Postgres cursor, outbox event, backup manifest), whether data written by users AFTER opening would carry it (so converging later needs a dual-read period or a rewrite) and what the converged form is (local revision, dependency token, stream-scoped position; use `docs/goals/kernel/GOAL.md` Outcome and record section 10 where it names them). End with a size for converging BEFORE opening: number of files, native changes, migrations, tests, in sessions (S/M), and the smallest slice that removes the cost of deferring, with its order. Read Program's decision first: architecture convergence is deferred past opening except what this inventory changes. Evidence the maintainer needs: the one-line answer "converge now: N sessions" or "defer: the dual-read cost is X".

## Output

READ-ONLY ANALYSIS. Change no product code and no test. The only file you write is `docs/goals/kernel/reports/G-1642-specification.md` (committed), the specification a Luna session at `max` implements in one session each, so each item names: the files and lines, the change, the tests that prove it (existing files by path, new files by name), the acceptance IDs it turns green, the Mechanisms line it needs, and whether it needs the native image build. Split anything that would not fit one session. Say plainly what you could not establish and what evidence would settle it; do not guess. Per finding classify A (a function is incomplete or wrong), B (can follow opening) or C (defer), with the reason. Commit the specification and give the RESULT as its path plus one line per item.
