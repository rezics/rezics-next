## Outcome

Program's rule for the class behind two regression failures (`work-title-control` LIVE03/MODEL17 line 132, fixed in `087fce615` by excluding worker ticks inside `tests/qa/fixtures/title-control.ts`; `protection-work-api.test.ts` failing the same bounded-count assertion in a shared project): a test that counts queries on a stack client measures the READ only if background worker ticks (realm-directory refresh, discovery refresh, rankings, notifications, feed, media workers...) are excluded; a count that includes ticks measures the scheduler. Fix the class once, not a second copy.

1. ONE METER. `tests/qa/integration/support/operation-cost.ts` already marks scheduler boundaries (`runBackgroundOperation`, `isForegroundOperation`, `attributeScheduler` over the worker classes) and Main has `currentWorkerTick()` (`services/main/src/worker-tick.ts`). Build one helper there or beside it (`query-cost-meter.ts`): `foregroundCounted(): boolean` = `isForegroundOperation() && !currentWorkerTick()`, and `meterFuseki(client)` / `meterPool(pool)` (returning a Proxy-wrapped client plus `{ queries, bytes, reset() }`) that increments only when `foregroundCounted()`. Move the title-control fixture's inline logic onto it (no behaviour change for that file).
2. MIGRATE EVERY COUNTER. Find them all: `grep -rln "nativeFuseki.query\s*=\|fuseki.query = \|\.query = async\|queryCount\|queries\.push\|calls\.push\|countQueries\|measureQueries\|new Proxy(.*fuseki" tests/qa services/main/tests | head -60` and read each hit: list EVERY test or support file that counts queries/SQL statements on a stack client (graph or Postgres) in a table in RESULT, with its decision: migrated to the meter, or exempt with a reason (the file's stack runs no workers, or it counts a client that is not shared with workers, or it deliberately counts the tick: say so). Known: `title-control.ts` fixture, `protection-work-api.test.ts`, and the files the grep above lists (public-selection-oracle, structure-bootstrap, g-845-wiki-intake, g-893-zone-cards, reading-settings, g-835-series, g-851-release-query, search-card-rich, g-946-join-requests, follows-authors, g-1001-work-cards, export-scoped-batch, g-1003-address-navigation, g-834-session, read-stability, projection-by-frame, ranking-progress, verification-lineage-bounds, g-1051-sql-profile, realm-join-concurrency, recipe-update, g-831-relations, media-rendition, library-status, structure-qualifier-root, composition-qualifier-key, g-847-reading-position and others the grep finds). Do NOT change any asserted number except where a tick had inflated it and the count with ticks excluded is the true one: then change it with the reason in the commit message and never raise a cap.
3. GUARD. `tests/qa/unit/query-cost-meter-guard.test.ts`: fails when a test file under `tests/qa` or `services/main/tests` wraps a stack client's `query` for counting without using the meter (pattern scan with an allowlist of exempt files, each with its reason in the allowlist). A new counter that bypasses the meter fails the guard.
4. PROVE: run the changed files that are cheap to run (each alone, report run ids; run in groups of 5; the heavy `catalogue-disk` and `large-tmpfs` ones are not run: list them as not run), `work-title-control.test.ts` and `protection-work-api.test.ts` three times each alone and once in a shared 5-file project. Commit per cluster of files.
