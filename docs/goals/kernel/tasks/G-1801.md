## Outcome

Inherited production-readiness item of `docs/goals/kernel/GOAL.md` ("Content document recovery: restore a document from a bad revision or after deletion, or prove with a test that it already works"). Establish what exists: the Content owner (`services/content`), revision history, withdrawal and erasure, `docs/contracts` on content governance, and the read and edit routes of the Content documents (Works' chapter documents, Realm replies' drafts, Zone pages). For each of the three user-visible functions, answer from code and existing tests (cite files and test names, run the focused tests read-only if needed): (1) restore a document to an earlier revision after a bad edit; (2) recover a document after deletion or withdrawal by its author, and what is permanent after erasure; (3) what an editor sees (revision list, compare, restore control) at the API level. If a function already works, name the test that proves it and propose no work; if not, specify the smallest slices, with the hidden-equals-absent and erasure rules preserved. Do not design a new document model.
