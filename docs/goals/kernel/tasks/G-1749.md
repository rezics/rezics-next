## Outcome

Class A: OPS01, "pinned release provisions four owners and re-provisions without changing their data" (`tests/qa/integration/fresh-install.test.ts:56`, `expect(readFormatMarker(options)).toEqual(saved)`). With the stream-separation repair (QA stdout/stderr, landed separately) the second install's JSON now parses, and the real failure shows: the format marker written by the SECOND install differs from the first only in the per-run evidence flag `ownerMigrations[catalogue-statements].noop` (first run `noop: false, converted: 0, replayed: 0`; second run, found already complete, `noop: true`). Source: `scripts/dev/install.ts` (about line 181 `saveFormatMarker(options, { ..., ownerMigrations, ... })`) writes the CURRENT run's evidence on every install; `services/main/src/modules/statement/upgrade.ts` (lines about 124 and 177) returns `noop: true` for an already-complete owner and `noop: false` for the run that did the work.

DECISION (kernel, recorded here with its reason): the marker's job is to say which release, image, epochs and migration outcomes this installation is in; the install that APPLIED the migrations is the informative evidence, and a re-install that finds every owner already `complete` must not erase it with `noop: true`. So: when an existing marker is in state `ready` with the same release digest, image id and epochs, and every owner in the current run's evidence is `complete`, the saved marker keeps its existing `ownerMigrations`; a run that applies or defers anything writes its own evidence as today. If `tests/qa/unit/g-991-owner-migrations.test.ts` pins `noop` evidence in the marker so that this decision contradicts it, STOP and say exactly which assertion and why, do not weaken it. Do not change the `noop` meaning in `statement/upgrade.ts`.

Proof: `tests/qa/integration/fresh-install.test.ts` alone (OPS01, QA run id in the RESULT; then its five-file shard unchanged) and a unit case in the existing owner-migrations unit file: second run over a ready marker with all owners complete leaves the marker bytes identical; a run with a deferred owner rewrites it; a changed release digest rewrites it. Run `task scripts:typecheck`.
