## Outcome

Class A (Program confirmed, do not wait for any profile; the profile later serves as the failing check). MAIN-ONLY, no native image. THE RULE: a write to a unit the page does not show can never change what the page returns, therefore it must never replay or fail the read. `services/main/src/modules/work/read-session.ts` today records the DATASET position (`dataEpoch:sequence`) when a session starts and, after the operation, compares it again and throws `WorkReadMoved('Graph changed during the read')` (lines ~391-398; the summary generation compare ~247-252) when the sequence differs. The sequence is the whole dataset's write sequence: ANY committed write anywhere moves it, replaying the session up to six times against ONE 160-call/4 MiB budget (`workRead`, ~344-421), so a rich Zone/Work page (about 33 Fuseki calls) fails under ordinary write load (class: a busy site is a failed read; `docs/goals/kernel/reports/gated-reads-design.md`).

Chosen shape (Program's test: correct AND needs no native image): FENCE ONLY THE UNITS THE PAGE SHOWS. The session already tracks per-unit tokens: selected head / dependency tokens (lines ~121-133, ~197), summary dependency tokens (~241), avatar/media rows and the media owner epoch (~217-220, ~271-275), realm membership proof (~174), disclosure/authority re-check at the end of every attempt. Make THOSE the fences, and remove the dataset-wide sequence compare as a replay trigger for every caller that does not pass `movingGraph` or `localBasis` (the class, not the page: enumerate every caller of `workRead`/the session: `grep -rn "workRead(" services/main/src`, the routes and modules that pass the options (`read-header.ts`, `media/summary.ts`, `work-contents/read.ts`, `metadata-read.ts`, `also-enjoyed`, `query/template-read.ts`, routes `works`, `resources`, `zones`, `follows`, `memberships`, `library-export`, typeahead/search snapshot `SearchSnapshotMoved` in `routes/search.ts`/`modules/search/typeahead.ts` which compares the graph position to the search cut) and state per caller which units it shows and which tokens fence them). Still report `sourcePosition` (the position the read STARTED at: continuation cursors bind to it; say so in the contract).

Requirements:
1. Correctness: if a shown unit changes between its first read and the end-of-session check (the Work head, its Structure, the selected MainVersion/publication, a cover/avatar row, the media owner epoch, the realm membership, an authority/disclosure change), the session replays or answers the typed moved/unavailable result exactly as today. If an UNSHOWN unit changes, nothing happens. Prove both per surface. Do NOT weaken any existing fence (authority, disclosure, Rights, erasure re-checks remain at the end of EVERY attempt).
2. Cross-unit consistency: where a page's units are read at different times from the graph, the per-unit tokens must cover the invariants between them (a Work head and its Structure head; a selected publication and its MainVersion): state the invariants and the token that covers each; if one cannot be covered by a token, say which and keep the dataset compare ONLY for that read (narrowly), never for the session.
3. Retry envelope: keep the replay but bound it: an attempt starts only if the remaining budget covers the previous attempt's measured cost (calls and bytes); otherwise answer the typed moved/unavailable result at once, not a budget error that hides the cause. Expose the attempt count in the read telemetry/profile so tests can assert it.
4. Tests: Main tests for the fence set (unit level, a stub session with a mutable graph/rows); ONE integration file `work-read-session-concurrent-writes.test.ts` through the product API: for the Work resource page, the Zone resource page, home and the typeahead/search snapshot: pause the read after hydration (the existing race hook style), commit an UNRELATED write (another Work's edit, a rating elsewhere), the read returns 200 with ZERO replays and the same call count; commit an AFFECTED write (the page's own Work head, its cover, its Structure), the read returns the fresh result or the typed answer; a growth check: the page under N = 0, 8, 32 unrelated concurrent writes: attempts == 1 and Fuseki calls constant (use the request profile; the retained seed set is being rebuilt, build the unrelated writes live).
5. Contract: `docs/contracts/work-read.md` (create or extend the nearest) states the rule, the per-caller fences and the retry bound.
