## Outcome

Decision 55 (docs/contracts/source-lifecycle.md#platform-imports-and-user-contributions, amended): platform imports may carry a Work's cover, credited to its rights holder, with a takedown. Slice 1 (Program: "go, at the single default key") is the Work cover and its mark, with no importer yet.

`docs/contracts/media.md` ("Covers, banners and aspect ratios") says the adopted CoverSet and BannerSet are maps by canonical width:height ratio and that these APIs remain pending; the Showcase-art section says selections "extend the avatar selection slots ... under the authority that selects the Work's cover". Read both sections, `services/main/src/modules/media/` (store, commands, presentation, showcase-store, summary's 'cover' component target) and `PUT /v1/resources/{work}/showcase/art` / the avatar selection route FIRST: reuse the existing selection (Use) machinery for the Work's cover rather than a new store. Report in your RESULT what already exists and what you added.

Deliver, at the single default ratio key (the portrait 2:3 preset; other keys later):
1. **Adopt**: select an already-stored media asset as the Work's cover with `expectedSelection` (observed state) and an `Idempotency-Key`, under the same authority/scope pattern as the Work's avatar (state who may do it; the importer's principal class must be able to, platform imports run as a platform agent: use the existing grant/exposure mechanism, closed by default, do not add a bypass). Role cover only; refuse showcase/banner roles here.
2. **Mark** stored with the adoption and returned by every read of the cover: `rightsHolder` (optional text, the publisher or studio when the record names one), `source` (a name, e.g. "Bangumi"), `sourceUrl` (the subject link), and an explicit statement that it is NOT under an open licence (`licence: null` or `copyright: 'rights-holder'`; choose a closed vocabulary and document it). The cover read for a Work is public (anyone who can read the Work), cached like other public art, and shows the mark.
3. **Remove (takedown)** with an effect separate from a user clearing a selection: `PUT/DELETE` (as the contract style dictates) that clears the cover and records a **fence** on (Work, source URL): a later adoption of the same source URL for that Work is refused (typed result `cover_fenced`), so an importer re-run cannot restore it; the Work's facts are untouched; the fence can be lifted only by an authority with the right grant (state which; closed by default). Takedown must also remove the stored copy's public readability (the asset stays only as evidence under the owner's custody per the existing media/erasure rules; say what it does today) so a takedown actually removes it.
4. **Read**: a public read returning the Work's cover (asset reference/URL for the renderer, mark, fence-free) through a route Launch can bind to; because another running task holds `services/main/src/modules/work/`, put the cover read in its own route (for example `GET /v1/resources/{work}/cover`) in a new module, and report the exact response shape; the Work read integration comes later.
5. **Tests**: unit (adopt, mark returned, refuse non-cover roles, remove sets the fence, adopt of the fenced URL refused, idempotent replay, closed by default without grant); isolated integration through the API: upload an image through the media API, adopt, read with mark anonymously, take down, try to adopt the same source URL again (refused), read shows no cover.
6. Update `docs/contracts/media.md` for what is now built (one short paragraph, delete "remain pending" for the cover at the default key).

Do not build: the importer fetch (slice 2), the rights-complaint hook (slice 3), banners, other ratio keys, web UI. Do not raise a cap. No Claude/Grok engines. Native/graph shape changes follow the repo's model rules (`model/definitions`, `task gen`, commit generated files); if the shape needs a native (Java) change, stop and report instead.
