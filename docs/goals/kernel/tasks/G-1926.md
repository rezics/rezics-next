## Outcome

The seed owner retains its 4/16/64 checkpoints (the manifest `retained.json`, the per-stage manifests and the stopped backups) under `<checkout>/.temp/work-profiles/seed-checkpoints`, built by `tests/qa/fault-recovery/work-profile-seed-build.test.ts`. Every worktree therefore has its own directory, and every growth check (library, Recipe page, Zone navigation, ranked search, community cost) would run the sixteen-minute BUILD again before it can restore. Backups already have a shared host root: `fixtureRoot` in `scripts/fixture/stack.ts` (the git-common `.temp/fixture`, overridable by `REZICS_FIXTURE_ROOT` for a write-bounded worker). Put the seed directory beside it: one retained set per host and compatibility generation, built once, restored by every checkout.

Exact change: `seedDirectory` in `tests/qa/support/seed-checkpoints.ts` is derived from the shared fixture root (a `work-profiles/seed-checkpoints` child of the directory that holds `fixtureRoot`'s parent `.temp`, i.e. the git-common `.temp/work-profiles/seed-checkpoints`), with the same override rule as `fixtureRoot` (when `REZICS_FIXTURE_ROOT` is set the seed directory moves with it, so a write-bounded worker stays inside its checkout). `work-profile-seed-checkpoints.test.ts` line 49 stops joining `root` itself and uses `seedDirectory`; the build test already uses it. The compatibility id inside every manifest already invalidates a retained set when generators, model, schema, migrations or engines change; keep that and say it in one sentence in `docs/storage/workload-budgets.md` (the build paragraph): a retained set is shared by checkouts and rebuilt when the manifest's compatibility id no longer matches.

Two concurrent builds must not corrupt one set: the build writes `retained.json` by rename after the whole set is complete (it already does); add one exclusive lock file in the seed directory taken for the whole build (fail fast with a message naming the holder pid and run id rather than waiting), released in a `finally`. A restore does not take it.

## Proof

Unit tier only (`tests/qa/unit/seed-checkpoints.test.ts`): (1) the directory is the shared one by default and follows `REZICS_FIXTURE_ROOT` when it is set; (2) a second build lock refuses with the holder's pid and run id; (3) a stale lock whose pid is gone is reported with the same message and the exact removal command, never removed silently. No integration or BUILD run: the BUILD is expensive and the retained set is not needed for this change.
