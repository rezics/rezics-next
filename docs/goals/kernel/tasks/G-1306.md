## Outcome

Record §10 Event histogram currently reads every EventTime on a query,
rebuilds buckets, caps the whole source at 2,000 slots, and binds reads to a
site-wide sequence (`event/queries.ts`). Replace that with incrementally
maintained interval/bucket data via the existing owner outbox/projection path.
Use bounded seek batches with durable checkpoints and per-target isolation;
initial populated backfill is resumable. Query only its bounded indexed
range/page and bucket window; no source inventory read in a request. Bind
cursors to relevant Event data/collection revisions, so unrelated writes keep
them usable. Current EventTime exact-manifest validation, actual/planned,
possible/definite, topic acceptance and disclosure remain correct. An index
without coverage returns explicit unavailable/partial plus progress, never a
fallback scan. Recheck current authority before using a cached basis.

Read staged `.temp/ref/target-architecture.md` §10 and product-audit plus
api-ui-design skills. Keep the existing EventTemporalQueries facade and the
existing projection/consumer lifecycle; list any owner integration needed
outside claimed paths in the handoff.

Not to build: no scheduler service, generic projection framework, second
history engine, arbitrary query endpoint or retained dual reader.
