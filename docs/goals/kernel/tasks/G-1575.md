## Outcome

Decision 55 lists dates among the facts the importer states with their source and licence. `importBangumiWorkFacts` (scripts/datasets/bangumi.ts ~lines 989-1040) states the format and the declared episode/volume counts only, so with real Bangumi data the anime and manga Zones' year views (`work-publication-years`) are empty. After G-1574 a first-publication date stated through the public Statement API under the property definition with notation `statement-first-publication-date-v1` is read by the year template. Make the importer state each subject's first air (anime) or first publication (book/manga) date that way.

1. Find the date in the Bangumi record the importer already receives (`BangumiFactSource`: the archive subject row `date` and/or the API subject's `date`, and the infobox keys that carry the first broadcast/release date, `放送开始`, `发售日`, `发行日期`, `上映年度`, `开始`; check the real data shape in the fixtures and the archive reader, and the existing `bangumiWorkFacts` function, which already documents "read from the first-publication date" at ~line 949). Pick the first available in a fixed precedence, normalise to `xsd:date` (YYYY-MM-DD) or `xsd:gYear` (YYYY) only when the source gives exactly that precision; a partial or unparseable value states nothing (no guess, no invented day).
2. Extend `BangumiWorkFacts` with the date (`{ lexical, datatype }`) and `importBangumiWorkFacts` posts one Statement per subject: `profile: statement-v1`, personal speaker, `subject` the Work, `predicate`/`relationDefinition` the seeded definition (use the seed helper G-1574 added beside the declared-count properties; do not create a second definition), literal value, `evidence` = the same Bangumi subject-page evidence the other facts use (`bangumiStatementEvidence('subject', id)`), then the global acceptance decision exactly as the count statements do, with a replay-stable idempotency key (`${prefix}:first-publication-date`). A subject with no usable date posts nothing.
3. Source and licence: the evidence and the statement carry what the other facts carry; do not add a Bangumi-specific field to any Main schema or endpoint. Nothing under `services/main` changes for this task. If the public API does not let the importer attach the licence/source the way decision 55 requires for dates, say what is missing; do not work around it.
4. Tests: unit (`scripts/datasets/bangumi.test.ts` or the existing importer test file): date extraction precedence and precision cases, including a year-only date, a missing date, a malformed one, a book and an anime; the posted body for a dated subject and no post for an undated one. Integration (`tests/qa/integration/bangumi-work-facts.test.ts`, or the file that already covers `importBangumiWorkFacts`; find it with `grep -rl importBangumiWorkFacts tests scripts`): a dated subject lists in `work-publication-years` with its year, an undated one does not, a replay writes nothing new. Run alone, report run ids.

Commit after each step.
