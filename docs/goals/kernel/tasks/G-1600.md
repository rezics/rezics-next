## Outcome

Program's finding (2026-10-10, shared dev stack): after an interrupted `task search:rebuild` the stack can neither serve search nor rebuild it. Live state observed after G-1584's fix (Fuseki on `2281b90d62d1`, startup audit logs `startup-audit failed: public anchor absent` then `journal invalidated: startup audit returned no baseline [qualify]`, repeatedly, so the receipt-pin cause G-1584 fixed is not the blocker here): the public search graph `urn:rezics:search:public` has 41,763 triples and 346 `rv:MatchUnit`s but NO `urn:rezics:search:public:anchor a rv:SearchGraphAnchor`; the control graph's `rv:textIndexGeneration` is `urn:rezics:text-index-generation:3af06346-dc8a-4049-ae0c-2b5fa0db8b10` (it was `fd5c289a-...` before the first rebuild attempt), sequence 10572; the job file `.temp/stack/rezics-dev/content-rebuild.json` is `{"id":"08d89a2a-b1ac-49cf-884b-3a70c7a6a673"}` with four `content-rebuild-*.log` files; and a later `task search:rebuild` exits in 3 s with `Content units remain after terminal clear; offline rebuild refused` (`scripts/operations/search-state.ts` `assertNoContent`: "A terminal clear receipt preserves partial replay on retry. It does not prove this job completed an offline pass, so nonempty retries refuse."). The sequence that produced it: attempt 1 (old code, 214 s) quarantined (removed the anchor, `quarantinePublicContentSearch`), cleared units, ran the offline indexer, then timed out in the old whole-population verification, BEFORE replay and activation; the dev stack then ran and Main's projection fed Content units back into the quarantined graph; attempt 2 saw units after a terminal clear and refused. Public reads are closed by design while quarantined (`assertQuarantined`: "Public reads stay closed until the offline rebuild and activation finish"), so a rebuild that stops after quarantine leaves the stack closed and unrecoverable by the same tool: that is the defect. An interrupted rebuild must not leave a state no later rebuild accepts.

1. MODEL THE JOB. Read `rebuild.ts` (`quarantinePublicContentSearch`, `clearQuarantinedContentUnits`, `replayQuarantinedContentCut`, `activateRebuiltPublicContentSearch`, `readQuarantine`, `isReceiptCommitted`, the receipt families `quarantine`, `profile`, `clear`, `offline`?, `activate`) and `search-state.ts` `rebuildPublicContentSearch`. Write the states of one job as a list in the module header comment and in `docs/operations/search-index.md`: not started; quarantined (anchor removed, receipt); cleared (terminal clear receipt); offline-indexed; replayed (to which cut); activated (generation rotated, anchor re-added). For each state say what a rerun must do.
2. MAKE EVERY STATE CONVERGE. A rerun of `task search:rebuild` (same job id from the job file, or `--job <uuid>`, or a fresh job when the stack is quarantined by a previous job) must reach `activated` from ANY of those states, including the observed one (quarantined, units present again because the projector re-fed them, generation already rotated by an earlier activation attempt or profile command). Rules: (a) units present after a terminal clear are not an error when the job is quarantined: the graph is closed to readers, so the rerun clears them again in bounded batches (same keyed pages as G-1587) and re-asserts the clear receipt for the new cut; (b) the offline indexer pass is repeated if the job has no `offline` receipt for the current graph state, never skipped; (c) replay is from the stored quarantine cut with the checkpoint adopted idempotently; (d) activation writes the new generation AND re-adds the anchor in the same guarded command, and refuses (typed, naming the step) only when a real invariant fails; (e) a stack whose control has no job file but whose anchor is absent (quarantined by an older tool) can be adopted: `--job` of the quarantine receipt's id, or the tool reads the latest quarantine receipt itself. Never run while a Main writer is live (existing `assertWritersStopped`). No raw SPARQL update from the CLI: every write is an existing guarded native command with its receipt; if a state needs a command the module has no policy for, say exactly which and add the smallest one (native; then leave pins to the manager).
3. THE WRITERS WHILE QUARANTINED. Main's content projection fed units into the quarantined graph. State in RESULT whether that is correct (the projector appends to the graph the replay will re-feed: then replay must be idempotent against it) or a defect (a projector must not write while the graph is quarantined: then make it wait on the anchor/quarantine, reusing the existing gate); decide with evidence from `content-publication/relay.ts` and the native command's quarantine check, and fix the defect if there is one.
4. PROVE IT AS FAULT TESTS, not by a copy of the shared stack: `tests/qa/fault-recovery/search-rebuild-interrupted.test.ts` on a QA stack with Content published (a few Works with text): run the real rebuild with a crash injected at each step boundary (after quarantine, after clear, after offline index, after replay, before activation) using the module's existing test seams or one small QA-only seam per boundary (inert unless an env flag, refused by `scripts/ops/production-env.ts` as G-1548's seam is), then run the rebuild again and assert: it finishes, the anchor is present, `deltaSince=-1` is available, a typeahead query answers the published text, and the units equal the Content population. Include the observed state explicitly: anchor absent + units present + generation rotated. Unit `services/main/tests/content-rebuild-resume.test.ts` with a fake fuseki for the decision table of step 2. Run them and report run ids; `content-search-rebuild.test.ts` (G-1587) and `content-rebuild.test.ts` in fault-recovery stay green.
5. Write the operator note in `docs/operations/search-index.md`: the exact command for the stuck stack (what Program runs on the shared dev stack after this lands: stop dev, `task search:rebuild`, start dev; expected output lines; how long), and how to read the step names.
Commit after each step. Never weaken a refusal that protects a live index: the only new acceptance is "quarantined and closed to readers".
