## Outcome

Class A (Trust-ops review of G-1959, asymptotic scale criterion: "every operation touches a bounded neighbourhood"; today the growth cases at 4/16/64 prove SQL statement and request counts only, not Jena visits). TEST SUPPORT ONLY; no product or Java change (the native counters already ride the `x-rezics-command-work` response header, allowlisted in `packages/observability/src/http-measurement.ts`, and arrive as `rezics.fuseki.<counter>` span attributes via `fusekiCommandWork` in runtime.ts).

1. `WorkProfile` (tests/qa/support/work-profile.ts) gains `nativeVisits: Record<string, number>`: the SUM over the request's Fuseki call spans of every `rezics.fuseki.*` counter whose name is in the shared allowlist (use the allowlist export, not a copy; a counter present on a span but not allowlisted is a profile error), plus `nativeVisitTotal`. A request with no native counter has `{}`/0, not null; a missing span collection stays the existing typed failure.
2. The growth verdict helper used by the registered growth files gets a `nativeVisits` dimension: for each counter name present at any scale, the value at the largest scale must not exceed the value at the smallest scale by more than the declared allowance (default: equal; a declared per-counter linear allowance with its reason is allowed only for counters whose algorithm is page-bounded by design, e.g. page-size multiples). Absent at one scale and present at another is a failure.
3. Qualified existing growth files need NO edit beyond their verdict call if they already use the helper; list the registered growth files that consume it and the ones that do not (they are reported, not edited).
