## Outcome

`docs/contracts/space.md` (Visibility, listing and history) says Visibility and Listing apply to Realm and Zone; History and Admission are Realm-only. Today `PUT /v1/spaces/{space}/settings` (`spaceSettingsCommand`, routes/realm-admin.ts) manages only Realm Spaces: a `space-zone-v1` Space cannot have its disclosure changed or read through it. Program's decision (G-1534 phase 2): there is NO separate zone disclosure write; extend the one settings command to Zone Spaces for the two settings the table gives them.

1. `GET` and `PUT /v1/spaces/{space}/settings` accept a Zone Space. The view for a Zone carries Visibility and Listing only; the command for a Zone refuses a History or Admission value with the existing problem shape (read how a non-applicable setting is refused today; do not invent a new problem). A Realm keeps all four, unchanged.
2. Authority: the same rule the Realm path uses for the owner (controller mandate / manager); for a Zone, the Zone's editor administrator holds it, as for `zone.edit`. Read how Access resolves a Zone administrator and reuse it; do not add a new capability. If the answer needs a new grant, STOP and mail kernel.
3. The change takes effect on the next read, as the contract says; whatever the Realm path invalidates (read basis, listing, sitemap, search), the Zone path does through the same call, not a copy.
4. STOP condition: if making a Zone private or unlisted needs a change to how Zone storage or the zone component documents are laid out or read (services/main/src/modules/zone/**), do not make it; commit what is independent, write RESULT naming exactly what Zone storage must do, and the manager briefs Program.
5. Tests (`services/main/tests/space-settings-zone.test.ts`, embedded Postgres, `USER=edge LANG=C.UTF-8 LC_ALL=C.UTF-8`): Zone settings read; Visibility and Listing change round-trip with a receipt; History/Admission refused on a Zone; a non-administrator is refused; Realm settings behave as before (run the existing realm settings tests). Then ONE integration proof: find a file in `rawSparqlIntegrationFiles` (`grep -rn rawSparqlIntegrationFiles tests scripts | head`) that flips a zone-only Space's disclosure by raw SPARQL, convert that site to the command, run the file alone, report the run. Do not convert other sites.

Commit after each step. Never raise a cap, never weaken an existing test.

## Mechanisms

access-authority: consume — the Zone administrator authority is resolved through the existing Access entry points; no new grant, no new owner command.
