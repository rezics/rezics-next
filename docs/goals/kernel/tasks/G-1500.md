## Outcome

Regression run 5 (cluster `http-expected-201-received-503`, QA 20261008t212104-a2d39c; Launch's diagnosis): `tests/qa/integration/realm-submission-api.test.ts:224` sends `POST /v1/contribution-publications` (profile text-publication-v1) and gets 503 `revision_unavailable` ("Access admission store could not be reached"). It is thrown by `editAccess` in `services/main/src/modules/contribution/history.ts` (~line 561) via `proveEditDigest` -> `reconcileExactHeadReceipt`, added by the private-contribution receipt reconciliation. `editAccess` takes `env.accessAdmission` or `env.eventTemporalAccess` (production sets `eventTemporalAccess: pool` in `services/main/src/index.ts:266`); the shared integration media stack (`tests/qa/integration/media-support.ts`) sets neither, so an edited draft cannot be published there.

Give the integration media stack the same Access admission wiring production has: attach the stack's Access pool as `eventTemporalAccess` (or `accessAdmission`) on the Main environment it builds, exactly as `index.ts` does, so every integration test that builds Main through `media-support.ts` sees the production dependency. Do NOT change `editAccess` to tolerate a missing store (that would reopen the fail-open path the reconciliation closed). Then check other test support that builds a Main environment for contribution publication (grep for `contribution-publications`, `editAccess`, and other helpers that construct `WorkActivationEnvironment`, e.g. `feed-read-support.ts`, `home-support`) and wire any that publish edited drafts the same way; report which you changed.
