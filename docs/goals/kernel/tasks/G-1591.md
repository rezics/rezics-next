## Outcome

Launch's class finding (G-1577 review): `publicWorkRead` (`services/main/src/modules/work/read-session.ts`) takes the disclosure viewer from the bearer, so "public" Work reads (`GET /v1/works`, concept-works and resource-list `POST /v1/query`, the followed-concept-feed template, typeahead's presentation selection) answer differently for a signed-in reader through age and category opt-ins and mutes, yet their cursor bindings (`discovery-works-v1`, `concept-works-v1` and others) exclude the viewer. A continuation token minted for one viewer is accepted for another, so a list's pages can disagree: gated Works vanish mid-list or appear after page 1.

0. DECISION (Program, 2026-10-10; record it with its reason in the owner's API document under `docs/`, the one that describes public reads and cursors, not in GOAL.md): each public list or read takes ONE explicit mode, a query parameter `mode` with values `public` and `viewer`. `public` is the DEFAULT: the anonymous view, whatever credential is sent: identical for everyone, cacheable, age/category opt-ins and mutes never apply. `viewer` requires a credential (401 without one) and applies that bearer's own opt-ins and mutes. There is NO `actingSubject` on these reads: reading as someone else is impersonation and nothing needs it. Why: the credential says who you are, not what you asked for; public responses stay cacheable (cost); a client that forgets the mode gets the public view, never a personalised list with opt-in content; nothing has launched, so the contract change across about ten routes is cheap now.
1. AUDIT. List every read that mints a cursor and runs under a disclosure viewer: `grep -rn "decodeReadCursor(\|encodeReadCursor(\|publicWorkRead\|publicViewer" services/main/src | head -80`. For each: route, binding profile id, whether it takes the viewer from the bearer today, and whether its answer can differ per viewer. Report the table.
2. CONTRACT AND IMPLEMENTATION: add `mode` (default `public`) to every public list/read whose answer can differ per viewer (the `GET /v1/works`, concept-works and resource-list `POST /v1/query`, the followed-concept-feed template, typeahead's presentation selection and the others the audit finds; `mine` scopes and routes that are already private stay as they are). `publicWorkRead` takes the mode: `public` builds the anonymous disclosure viewer even when a bearer is present (a bearer must not make the answer differ; do not even verify the account for the public view if that saves a statement, but keep rate-limit principal accounting as is), `viewer` requires the bearer and uses its disclosure profile. Responses in `public` mode keep their existing cache headers or become cacheable where the route is otherwise cacheable (state which); `viewer` responses are `private, no-store`. OpenAPI/SDK regenerate (`task gen`), exposure declarations unchanged.
3. CURSOR BY CONSTRUCTION: one helper on the session builds every cursor binding and always includes the mode and, when the mode is `viewer`, a stable digest of the principal's disclosure profile (the same value `disclosureViewer` uses; not the raw account id). Every cursor-minting read goes through it; a unit scan guard fails when a cursor call site does not. A mismatch (token minted under another mode or viewer) uses the module's existing restart/`read_basis_changed` behaviour; no new problem type.
4. WEB CLIENT: Launch's web app must pass `mode=viewer` where it shows a signed-in list. You do NOT edit `apps/web`; list in RESULT every web call site that hits an affected route and whether it should be `viewer` (a signed-in shelf/home/following list) or stay `public`; the manager mails Launch. Keep the generated client types in `packages/` compiling (`task web:typecheck` must pass; a new optional parameter does not break callers).
5. Tests: unit `services/main/tests/public-read-cursor-viewer.test.ts` (helper includes mode and viewer digest; the scan guard; `public` ignores a bearer's opt-ins; `viewer` without a credential is 401); integration `tests/qa/integration/public-read-cursor-viewer.test.ts` (a list read as `public` with and without a bearer returns identical items and identical cursor; a `viewer` read with opt-ins differs; a page-2 continuation minted in one mode is refused/restarted under the other; same mode and viewer continues). Run the existing cursor/paging tests of the changed modules (`grep -rl "cursor" tests/qa/integration services/main/tests | head -40`) and report run ids.
Commit after each step.
