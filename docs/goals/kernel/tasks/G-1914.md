## Outcome

Program's decision (2026-10-12, class A). Finding from an inspection: `services/main/src/modules/feed/trending.ts` reads at most 20 ranked Works, applies the viewer's hide and mute rules AFTERWARD and never refills; a ranking disclosure rejection throws `WorkReadMoved`. A viewer who hides or mutes the top 20 items gets an EMPTY Trending page though eligible lower-ranked Works exist; `feed/cost-contract.ts` still describes a refill that is not in the code.

Do: (1) implement a BOUNDED REFILL: continue the ranked read past rejected entries in chunks until the page is full or a hard cap on entries examined is reached (the cap derived from the page size and written as a named constant with its reason; the same shape as the typeahead prefix walk contract in `services/main/src/modules/search/prefix-walk.ts`: advance a cursor past rejected entries, answer `hasMore` with the cursor beyond the cap, never a longer scan); a disclosure rejection of a ranked entry skips that entry (counted as rejected) instead of throwing WorkReadMoved unless the position truly moved; keep order stable (rank, then identity) and hidden == absent (a rejected entry is indistinguishable from an absent one); (2) correct `feed/cost-contract.ts` to what the code does (page size, chunk, cap, the per-rejected-chunk constant); (3) unit tests (`services/main/tests/feed-trending-refill.test.ts`): top N rejected with N below, at and above the cap fill the page or answer hasMore with the cursor; no throw; order; (4) the growth check at 4/16/64 hidden items through the feedback route `POST /v1/me/feed-feedback` (existing Works axis, no raw writes) in `tests/qa/integration/feed-trending-growth.test.ts`, calling the EXISTING verdict `assertWorkCostAtScales` from `tests/qa/support/work-profile.ts` (do NOT edit that file: it is held by another task) with the class declared beside the cost contract (expected: work bounded by page + constant per rejected chunk; counters exchanges, bytes, SQL statements, Fuseki calls). If WorkProfile lacks a dimension or counter you need, assert what exists and say what is missing.

Constraints: no new acceptance row (attach to existing IDs); fixtures grant access through grantFixtureAuthority; relative paths only; ONE goalctl test call per step; rebuild nothing native. Stop at the commit and report with the measured numbers.
