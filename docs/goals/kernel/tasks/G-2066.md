## Outcome

Class A, a rights rule (Program 15:20; Launch's G-2064 finding: a signed-out reader of an IMPORTED recipe, "Puff Paste" from Gutenberg, sees no structure). Decision 55 (docs/operations/external-conditions.md, docs/contracts/source-lifecycle.md): an import publishes what its source licenses. Today `verifyOriginalWorkStructureContribution` (services/main/src/modules/work/structured-publication.ts:254) admits ONLY a complete local structure authored by the acting subject and explicitly refuses any revision carrying `rv:importSource` / `rv:importSourceRevision` (the first ASK), so `publish` answers `rights-unavailable` for an import.

Add EXACTLY ONE further admitted basis, and nothing else:
- a structure revision that an IMPORT wrote (it carries `rv:importSource` and `rv:importSourceRevision`, written by structure/change.ts:657 from the import's source record), whose source record's licence is in the PUBLISHABLE set. The publishable set today is public domain (Gutenberg). Take the licence from the contribution's OWN source evidence (the source record the revision points at, the same evidence the import recorded), never infer it from the Work, its title, its Realm or the acting subject.
- A member's own entry (no import source) stays under the original-contribution basis exactly as now: a member who pastes the same text by hand is STILL refused the import basis (and still needs original-contribution).
- An import whose licence is unknown, missing or outside the set stays refused (`rights-unavailable`).
- The receipt/decision records which basis admitted it (original-contribution vs import-source-licence) so the reader sees the source credit with the structure; reuse the existing source-credit surface (Work page source mark), do not add a vocabulary: if the decision already carries a rightsBasis value, extend its value set minimally and say so in the result.

Do:
1. Read-only first: find where the import records its source record and licence (structure/change.ts:657, the import commands/adapters, docs/contracts/source-lifecycle.md) and where `publish` records `rightsBasis` (input.rightsBasis, publicSource). Put the licence field names and the publishable-set definition in one function (`importSourcePublishable(licence)`), used once.
2. Implement the basis in structured-publication.ts only (one verifier branch, one decision field). Do not touch the original-contribution verifier's queries.
3. Tests (new file services/main/tests/structured-publication-import-basis.test.ts, real composition where the other publication tests do): (a) imported structure with a public-domain source publishes and the public read returns its structure with the source credit; (b) the same text pasted by a member by hand is refused the import basis (rights-unavailable) and is admitted only through original-contribution as before; (c) an import with an unknown licence is refused; (d) an import whose revision claims a publishable source but whose source record is another Work's is refused (evidence binds to this contribution).
4. Trust-ops reads the diff for the rights rule before it lands: in the handoff state in one table which ASK/queries decide the basis and what each refuses.
