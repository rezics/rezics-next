## Outcome

Native step of the gated reads design (`docs/goals/kernel/reports/gated-reads-design.md`: read all of it first, sections 2 to 4 and the paragraph "Native work is necessary"; Program accepted the rule 2026-10-12). Today a text query opens its own Lucene reader per query (`FilteredGraphTextIndex.java` about line 1235) and `CommandService.java` (about line 792) starts broad writer epochs before update work, while `SearchDeltaJournal.java` (about line 1013) relies on the epoch to establish RDF/Lucene agreement; Main therefore refuses reads when ANY writer is active or a global cursor moved (public Content search, private Content search, private contribution search, /health/search-ready). A read must instead be served from ONE CONSISTENT CUT, and must not wait on an unrelated writer.

Do (Java, native, one session; Main changes only where the contract needs a typed capability flag):
1. A short PUBLICATION/CAPTURE critical section in the existing owner (not a new lock family): it covers the real commit and the bounded qualification publication; a reader CAPTURES, inside it and together, the RDF read transaction, the COMMITTED Lucene reader and the qualification (generation); the capture lock is released BEFORE the bounded query executes; the same captured reader is passed through nested proof helpers (no helper reopens a reader). Whole-command writer serialization stays separate and unchanged; do NOT lock reads behind the whole-command monitor (`CommandService.java` about line 674): that preserves traffic-dependent delay. No cross-HTTP historical TDB sessions: use one native request or copied bounded facts.
2. An EXACT-UNIT PROBE command: one native request that, on the captured cut, validates the unit's posting, body and language and evaluates the phrase on that one committed reader, returning present/absent/damaged (a damaged or missing posting never becomes a complete "absent"). Typed bounded request and response; a `consistentCaptureAvailable` and `exactUnitProbeAvailable` capability reported by the command health so Main adapters can detect the build (Main step lands separately).
3. Proofs (Maven, in the module tests named above): (a) a writer of ANOTHER unit holding its epoch open does not delay or refuse a read or a probe, and the read sees a cut (all of a prior commit, none of an in-flight one); (b) a commit during a read does not change what that read returns (captured reader); (c) the probe returns damaged for a missing posting and absent only on a complete cut; (d) the existing journal and delta tests stay green (RDF/Lucene agreement preserved); (e) native visit counters (`CommandWork.count`, `_visited` names) report the probe's work so the growth check sees it. Run the full native suite once.

Do NOT build the image (the manager builds it, once, with the typeahead and counters branch if timing allows). Report the native input files and the derived pin. Constraints: no second registry, no compatibility layer; relative paths only; ONE goalctl test call per step; fixtures grant access through grantFixtureAuthority.
