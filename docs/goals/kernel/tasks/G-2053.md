## Outcome

Test-only, mechanical. Two integration files landed on 2026-10-12 with raw SPARQL updates and joined the ceiling in `scripts/qa/raw-sparql-integration-files.test.ts` with a note that their owner owes the migration. Remove both from that ceiling by writing the same state through the product's commands or API, so the guard `raw SPARQL integration files only shrink` passes with both entries deleted.

The raw writes to replace (find them with `grep -n "fuseki.update\|nativeFuseki.update"`):

1. `tests/qa/integration/work-read-session-concurrent-writes.test.ts` (one write, near line 645): `INSERT DATA { GRAPH <urn:rezics:graph:current> { <shown.work> rv:mergedInto <unrelatedPublic.work> } }`, a committed Work merge. The product path is the merge command (`services/main/src/modules/work/merge-command.ts`; find its route and how other integration tests call it with `grep -rn "merge" tests/qa/integration/*.ts | head`). The test then reads `/v1/resources/summaries` with the survivor phase: keep every assertion.
2. `tests/qa/integration/structured-work-publication-native.test.ts` (three writes, near lines 141, 154, 190): `schema:isPartOf` links from a Work to its parent and from the parent to an ancestor, and one `DELETE DATA` of the ancestor link. The product path is whatever API or command establishes and removes a Work's parent (search `services/main/src/modules/work` and `docs/contracts` for `isPartOf`, `parent`, `part-of`). The test asserts that parent admission looks only at the immediate parent: keep every assertion and its names.

Rules:
- Same assertions, same test names, same measured quantities. If the product path changes a measured count (for example one more GET), say which and why in the result, and adjust only that expected number with the reason in a comment.
- The helpers in `tests/qa/support` and `tests/qa/integration/*support*` are the first place to look for an existing command wrapper; reuse, do not write a new raw write.
- Do not add a test-only writer to product code. If a state has NO product path, stop for that one write, keep its raw update and its ceiling entry, and say so in `BLOCKERS` with the exact state (graph, subject, predicate): the file stays in the ceiling and the other is still migrated.
- Reads by raw SPARQL query are not what the guard counts; leave `fuseki.query` reads alone.
- Run each migrated file once on the QA stack through goalctl (see Checks) and report pass/fail counts.
