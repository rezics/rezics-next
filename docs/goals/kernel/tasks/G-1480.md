## Outcome

Launch (mail `launch`, G-1459, QA 20261008t162613-ed8ac2): the declared episode and volume counts written by the Bangumi-like facts task are `PropertyDefinition`s (kind `property`), and the public `GET /v1/lexicon/definitions/{key}` that Zones use to name a fact cannot return them: `services/main/src/modules/access/semantic-disclosure.ts` `publicInTransaction` publishes only `rv:RelationDefinition`, and `readExactDefinition` (services/main/src/modules/semantic/admitted.ts) returns null unless the kind is `relation`. So a count's Statements read 200 but the reader cannot get its label.

Make a PUBLIC property definition, with its reviewed presentation (label and language-selected names exactly as a public relation definition returns them), readable through the same lexicon route and the same disclosure rules as a public relation definition: same visibility test (public only when its owner/disclosure says so; a private or unpublished property definition stays hidden and answers like a missing key), same response shape plus a `kind` discriminator if the route does not already carry one, same cache/validators, same cost bound. Reuse the relation code path; extend it by kind, do not copy it. Read how relation definitions are published (`publicInTransaction`, the lexicon routes under `services/main/src/routes/` and `services/main/src/modules/lexicon/`) before editing. Check the generated OpenAPI/MCP descriptions (`task gen`) and update if the response union changes; commit generated outputs in your branch.

Tests: unit with the existing lexicon/disclosure test patterns (a public property definition is returned with its presentation; a private one is not disclosed; a relation definition still works; an unknown key is 404 as before); isolated integration through the API: define a count property as the Bangumi-like facts do, publish it, read `GET /v1/lexicon/definitions/{key}` anonymously and as a signed-in reader.

Do not build: a new route, a new definition kind, editing of definitions, or any web change.

## Checks

- `task goal -- test` for the new unit and integration files and the existing lexicon/disclosure tests you touch (run ids, counts); `task main:typecheck`; `task gen:check`.
