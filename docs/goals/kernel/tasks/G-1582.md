## Outcome

Launch's decision (2026-10-10): one meaning across the discovery reads. "No discovery generation has been produced" is an empty answer, not a fault; only a real outage or a held fence is 503. G-1579 did it for `GET /v1/discovery/concepts` (`DiscoveryNotProduced`, thrown by `DiscoveryStore.active` only when `access.derived_generation_head` has no discovery row). Apply the same rule to the two reads Launch's Discover page still faults on, on a fresh deployment:

1. The resource list's `conceptCountBasis` (`services/main/src/modules/discovery/concepts.ts:76`, used by `query/resources.ts`, `query/work-cards.ts`, the onboarding choices/classifications): when the basis is "never produced", the basis is EMPTY (no active generation, zero counts), and the readers that take it treat that as a normal empty population: no thrown error, no logged fault, the same response shape they produce for an empty basis today (read how an empty/inactive basis is already handled, `{ basis, active }`, and reuse it). A Work card's concept counts are absent, not an error.
2. `GET /v1/discovery/sections` (`discovery/sections.ts`, route `routes/discovery.ts`) for a reader with followed topics: an empty page of the sections profile (no sections, complete, no cursor, the same source position the page schema requires). Today it answers 503 `discovery_ranking_unavailable` for `RecommendationUnavailable`; keep that for every other unavailable class.
3. The distinction is by CLASS: only `DiscoveryNotProduced` becomes empty; `RecommendationUnavailable`/`RecommendationMissing` for any other reason (held recovery fence, missing generation row, Access outage) stays exactly as it is, 503 and logged. Add no new class; reuse G-1579's.
4. Grep for any other reader of `DiscoveryStore.active` or `conceptCountBasis` on a public render path (`grep -rn "\.active(\|conceptCountBasis\|discoveryReader" services/main/src | head -30`) and apply the same rule where the answer is a list or count; list each in RESULT with its decision; where a read has no meaningful empty answer (a pinned cursor, a restart), leave it and say why.
5. Tests: owner/unit `services/main/tests/discovery-never-produced.test.ts` (never produced -> empty basis and empty sections page; held fence, missing generation row, Access outage -> unchanged 503); integration `tests/qa/integration/discovery-never-produced.test.ts` on a fresh stack: `POST /v1/query` resource list, `GET /v1/discovery/sections` with a followed topic, `GET /v1/discovery/concepts` all 200, empty, and the log has no `main.route.dependency_unavailable` fault for them (assert through the same captured log mechanism other tests use, or state that none exists and assert the status only). Rerun G-1579's two new files and the existing discovery files (`grep -rl "discovery" tests/qa/integration services/main/tests | head -30`, run the ones touching these reads). Report run ids.

Commit after each step.
