## Outcome

Credits today are author, translator and editor; the credit read template (`query/templates/work-credits.rq`) is author-only and bound to Open Library. The Bangumi-like page needs the roles animation studio, director and artist beside the existing author role (original creator, story) (Launch mail `launch-wave2-kernel-reply-1008`).

Add the three roles as data in the same place and shape as the existing `credit-*` lexicon keys (`scripts/dev/seed/relation-lexicon-data.ts`, catalogue-import role mapping) and generalise the credit read to a reviewed template parameterised by role (typed parameter from the closed role list, response schema, access budget), so a fourth role adds only a lexicon entry and a fixture, not a handler. The Open Library path keeps working unchanged (its tests are the regression guard). Role order in the response is fixed (author, director, artist, animation studio) and every credit keeps its source evidence edge.

Do not build: a new view framework, a credit handler per role, cast/voice-actor credits, web UI. Keep the template change as small as the existing template mechanism allows; if the mechanism cannot take a role parameter without a new capability, stop and report exactly why.
