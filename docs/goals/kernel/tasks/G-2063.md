## Outcome

Class A, acceptance path (Program 14:35 UTC: on the shared stack at main 9e9b68644 broad prefixes `a`, `ha` answer 200 at 1.43-1.48 s and `the`, `b`, `三` answer 503 `search_index_unavailable` / SearchRequestTimedOut at the 1.5 s deadline; `harry` 0.06 s). Measured by the manager with Fuseki's request log: `the` issues at least 130 Fuseki queries before the deadline, `harry` about 25; on 5314eae2b the same prefix answered well inside the budget.

Cause from the code (verify with a count before changing anything): since the work-read fence commits, `readPublicTypeahead` runs every native walk batch through `session.selection(...)` (read-session.ts). `selection` runs the whole batch read (`queryTypeaheadCandidates` + `present`, i.e. identity query, field query, names, disclosure, page presentation) once in a probe session, and registers a dependency whose fence callback runs that WHOLE read again; then the session's own `summaries` (twice), `searchPageAuthors` and the final prefix re-walk are re-run again at `fenceDependencies`. One page therefore makes roughly twice the reads it needs, and each batch repeats it. `selection` exists for "admission scans that inspect many unshown candidates"; a typeahead batch holds at most `pageSize - items.length` (<= 10) entries, so its candidates can be retained and fenced individually.

Do:
1. First add the measurement: a test in `services/main/tests/typeahead-prefix-walk.test.ts` (or its helper) that counts `fuseki.query` calls of one `readPublicTypeahead` request on a fixture with >= 40 matching Works, for prefix lengths one and three, and asserts a constant bound that does NOT depend on how many candidates the prefix matches (state the bound in the test, derived from batches x reads per batch). Run it on main to record the present count in the result.
2. Remove the whole-read replay: read each walk batch directly on the session (captureDependencies true) so that the selected inputs (heads, disclosure decisions, names, summaries, authors) are fenced by their own cheap per-dependency re-reads, and nothing re-executes `queryTypeaheadCandidates`/`present` at the fence. Keep every fence guarantee: a moved head, a changed disclosure decision, a changed author name or a moved prefix generation still throws SearchSnapshotMoved / WorkReadMoved (the existing tests hold them; keep every assertion).
3. Make reads per page of candidates one batch each: one identity query, one field query, one disclosure submission, one types read, one summaries read (and its single fence), one authors read, for the <= 10 entries of a walk batch. If a read is issued per entry, batch it.
4. Do not raise a deadline, a budget or a limit. Do not change the strict or legacy disclosure code (`disclosure/read.ts` is Trust-ops'; do not edit it).
5. Result states: reads per request before and after for prefixes `a`, `ha`, `the` (from the test), and which fences remain, one line each.
6. (Program 14:50) The defect CLASS is "a fence callback that replays the whole read". FIRST and read-only, before any edit, list EVERY caller of `session.selection` (and every `observeDependency` whose callback re-runs a whole read): summaries, the Work page, Zone pages, search matches, the sitemap, anything else `grep -rn "\.selection(\|observeDependency(" services/main/src` finds. Put one table in the handoff: caller (file:line) | what its fence callback re-runs | bounded by (candidates it can hold) | verdict (fixed here / same fix, named follow-up / bounded and fine). Any other caller that replays its whole read gets the same fix in this task if it is within the paths you were lent or is Launch/other-area (then a named follow-up with its file:line), never silently left.
7. (Program 14:50) The test bounds READS PER REQUEST independent of the candidate count, for a ONE-batch prefix and a FIVE-batch prefix (a prefix whose first native batches are mostly rejected/hidden entries), on the REAL composition (composeMain), asserting `fuseki.query` count per request <= a constant stated in the test, and the same count for both prefixes up to the batch factor (reads per batch constant). This is the growth check the reader lacked when the fence landed.
