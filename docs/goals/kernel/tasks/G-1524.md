## Outcome

T1 of the Bangumi/rights rework (Program accepted the audit `.temp/ref/audit-bangumi-rights.md`, staged into this worktree; read sections 1a, 2 (gaps 1) and 4 first). Maintainer direction: Bangumi is configuration of general REZICS features; licence, credit and takedown are carried by the general rights records (`services/main/src/modules/rights`: material, use assessment, obligations). Nothing Bangumi-specific in Main.

Build gap 1 as a GENERAL feature: **public reads expose the current rights obligations of their source.**
1. The Work header read (the Work description) and `GET /v1/resources/{id}/statements` attach, per text or fact set, the CURRENT assessment's obligations for the `wiki_display` use (instrument, kind: attribution / share_alike / change_indication ..., appliesTo, notice). One batched lookup per read (bounded: state the SQL statements and Fuseki calls added; the request-cost contracts of the existing community/read files must not grow: Launch's G-1497 cut round trips there, so fold the lookup into an existing statement or batch it for the whole page, never per item), disclosure-safe (a hidden material reveals nothing), cached like the read it decorates.
2. A material with NO current head reads `unassessed` (a distinct explicit state), never `unprotected_fact`. Fix the export path that labels a missing assessment `unprotected_fact` while its result is `undetermined` (`rights/store.ts` around lines 92 to 97 and 463 to 476 in the audit; re-check line numbers) and teach the export supported set `change_indication` (store.ts ~454 to 457).
3. The shape is generic and stable (Launch binds it for every source): choose field names in the existing read contracts' style, put them in the OpenAPI (`task gen`, commit generated files), and document them in the rights README and `docs/contracts/license-grants.md` in a short paragraph (delete text the code now states).
4. A read of material that has an assessment from ANY source (not Bangumi: use a captured VNDB or Open Library fixture, or a hand-written material through the API) returns its obligations; prove it.

The audit lists the old Bangumi-specific Main fields (`workDescription.source/licence/adaptation`) as being removed by cutting G-1513; they should not be on main when you start (check `git log`). If they are, delete them as part of this task and replace with the generic obligations.

Do not build: the derivative rule (T2), the acquisition gate (T3), any Bangumi mapping (T4), UI. The rights module is Trust-ops' area: keep the diff to `rights/` small and write it so a reviewer can read it in one pass; list the rights-module files you changed in your RESULT (Program sends the diff to Trust-ops before landing).
