## Outcome

G-1469 (docs/operations/tdb2-integrity.md and infra/jena/tests/tdb2-integrity.test.ts, already on main) found the mechanism behind the 2026-10-08 dev fault. On Jena 6.2.0 a write transaction can fail AFTER TDB2 wrote its commit point to the journal but before every component finished committing; the quad indexes then name the transaction's nodes while the node file's readable length still ends where it began (reads fail with `Out of bounds`), the failed commit never releases the writer lock (later writers hang), and the next open of the store replays the journal and heals everything. Today Fuseki stays up after such a failure, serving failing reads and holding the lock forever. Read the report in `docs/operations/tdb2-integrity.md` first; its pin test shows the current behaviour.

Make the command module fail-stop: route every `dataset.commit()` in `infra/jena/command-module/src/main/java/com/rezics/jena/` (CommandService, runWorkScopeDirectory, runTitleCandidate, ClaimFoldInventory, CommandInvariant, OccurrenceTextSchema, SearchDeltaJournal, CommandModule, ErasurePurge, TemplateIndexService and any other call site you find with grep) through ONE small helper. On any Throwable from commit it makes a best-effort `abort()`/`end()` (swallowing secondary errors), logs one line with the exception class and message, and halts the JVM (`Runtime.getRuntime().halt(...)` with a distinct non-zero status after flushing the log) so the container restarts and TDB2 replays the journal. Normal-path behaviour, return values and the 10-second command budget do not change. The halt action is injectable in the helper so a unit test can observe it.

Test (failing before, passing after): a unit test with a `DatasetGraph` whose commit throws after a simulated partial commit asserts the helper aborts, logs and invokes the halt hook exactly once, and that a normal commit never does; a test that no `dataset.commit()` call site remains outside the helper (a source scan test in the Java test sources is fine). Add `restart: unless-stopped` to the `fuseki` service in `infra/dev/compose.yaml`; the production compose is a later artifact, so add the same requirement as one line to the production checklist in `docs/operations/` (find where the deployment/ops checklist lives, `docs/operations/deployment.md` if it exists), and add the fail-stop behaviour and the new exit status to `docs/operations/tdb2-integrity.md` in two or three sentences (keep it short; delete text that the code now states).

This is a native change: run `task gen` (pin), rebuild the image under the heavy slot (`task goal -- slot --heavy -- docker build -f infra/jena/Dockerfile -t <pin from compose.yaml> .`), report the Maven totals and the new pin. Do not run `task dev:refresh`. Do not change the commit semantics of the Jena library, add a watchdog process, or touch Main/relay code.
