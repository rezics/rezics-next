## Outcome

Case 1 of `docs/goals/kernel/reports/thesis-test-provider-and-composition.md` (read "Case 1 — acme-catalogue", the "Capture and identity", "Projection, statements, command" and "Native title, synopsis, credit" tables, and "Owner decisions"): a catalogue provider Main has never heard of cannot be mapped into Works, titles and credits, because the provider identity is spelled `open-library` / `work` / `/works/OL…W` / `open-library-work-map-v1` in about 14 places along the command path. This is ranked change 1: replace the repeated literals with the OBSERVATION'S OWN provider, namespace and external id, plus ONE allowlist lookup that supplies the mapping revision, the key template, the id pattern and the capture profile for that provider/namespace. (The one projector that reads field dispositions is a separate later task; here only identity moves.)

ACCEPTANCE = the report's change-1 sites (and every row of the Case 1 tables whose "Replacement" is "copy the request's / observation's provider, namespace and external id" or "mapping revision / key template / id pattern from the allowlist"): `sources.ts:28,38,95,105,617`, `open-library.ts:7,82,90`, `intake.ts:25,172,221` (rate gate by provider with the allowlist's interval, capture validity by the allowlist's URL template and id pattern), `provider-identity.ts:103`, `open-library-conversion.ts:8,95,117`, `graph-projection.ts:13,54`, `SourceProjectionPolicy.java:57,72` (mapping literal must equal the receipt's and be in the reviewed allowlist; key = the mapping's key template applied to the external id), `EditorialFieldPolicy.java:166`, `source-open-library-work-v1.ttl:12,14,17,42,53` and `source-reification-v1.ttl:26` (provider, namespace, id pattern, key pattern and mapping revision become parameters of ONE source-record shape), `title-control.ts:534`, `native-work-adoption.ts:607,694`, `native-work-proposal.ts:12`, `field-control-native.ts:27,64`, `author-credit.ts:27,38,54,85`, `author-credit-schema.ts:15`. Rows whose Replacement is the field-disposition projector (`reification.ts`, `open-library-conversion.ts:126`, `SourceProjectionPolicy.java:84,95`, `field-vndb.ts`, recipe SLOT, Bangumi fact functions) are NOT this task: leave them and say so.

THE ALLOWLIST: a data file the reviewed manifest pins by hash (the way source profiles and the command module's other reviewed inputs are pinned; read how `SourceProjectionPolicy` pins profiles today and follow it), one row per `{provider, namespace}`: capture profile id, mapping revision id, external id pattern, source key template, URL template and minimum interval (the Open Library row reproduces today's constants exactly). A provider not in the file fails closed with the existing refusal. Adding a provider is a row plus a mapping, reviewed, with no Main branch. Remote fetching for a new host stays an owner decision: the allowlist row names the URL template; turning fetching on for a host is not done here (the report's assumption: the operator supplies the bytes).

PROOF: `tests/qa/integration/source-provider-unseen.test.ts` with fixture `acme-catalogue-work-v1` (one retained JSON object with `catalogueId`, `heading`, `blurb`, `credits[]`, as in the report): add a second allowlist row for `acme-catalogue`/`work` (a TEST allowlist input, not a production row), POST its bytes through the manual intake, convert, and the title, synopsis (as source text, not accepted) and one credit are projected and adopted; Open Library behaviour is byte-for-byte unchanged (all existing source tests pass UNCHANGED: `grep -rl "open-library\|source/\|sources" services/main/tests tests/qa/integration | head -60`, run those touching source/intake/conversion/author-credit and report run ids). The acme case needs ZERO edits under `services/main` or `infra/jena` beyond the allowlist data (state the empty diff). A Java unit proves the policy accepts the allowlist's mapping and key template and refuses a mapping literal that is not in it. NATIVE: pin change; `task gen`, build the image (Maven must pass); if G-1546/G-1584/G-1573/G-1592 have not all landed, leave the pin-file commits to the manager. NET LINE COUNT: the report sizes this at about 35 lines added with 14 literals removed; report `git diff --stat main...HEAD` for non-test source; if the change grows the code, name the correctness gain per added file. Commit after each cluster (allowlist data + lookup, TS call sites, Java + shape, test).
