## Outcome

`readExactContributionDraft` (used by `search-private.ts`) resolves a create or edit head only when the original receipt for that head reconciles with its immutable bytes and its actor. Today it checks the anchor, payload and current identity only. Build on the landed `readOriginalContributionCreateSource` in `history.ts` (G-1373, c74746511).

The smallest change:

- Read the edit receipt (`textContributionEditReceiptIri(admissionId)` in `edit.ts`), recompute the edit `requestDigest` with the edit actor, and refuse the head when they differ. The receipt does not record the actor, so read the original Access admission's `acting_subject` by id: add the one read to `access/admission.ts`.
- Wire both checks into `readExactContributionDraft` for create and edit heads, so a removed create receipt or a forged edit `requestDigest` refuses.
- Treat language tags case-insensitively where `search-private.ts` compares the stored literal's `xml:lang` with `exact.language` (Jena returns `en-us` as `en-US`); add a case that shows it.

Start from the staged falsifier test `.temp/worktrees/g-1373/.temp/goal/private-original-source.test.ts` (sha256 10bdcd96fa652995c3a11486a96002f3f4b60d54272965ecbda2f307625412ff); its patch adds it at `tests/qa/integration/private-original-source.test.ts`. Copy the files from that directory into your worktree's `.temp/ref/` first if you cannot read it. The three falsifiers must pass without changing their assertions.

Do not build: native private delivery, a private search descriptor, erasure handling (Trust-ops C6 owns it), any new module or framework. Report if the reconciliation needs more than these files.
