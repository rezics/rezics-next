## Outcome

Contract C0 of the kernel Goal. Today an authored profile can never change:
`model/compiler/generate.ts` (`assertAccepted`, about lines 128–199) refuses any
digest that differs from `model/accepted/profiles/*.json` and
`model/accepted/facets/*.json`, so every optional field or relaxed constraint
became a new `-vN` family (18 families now). REZICS is unreleased; the design
record (`/home/edge/projects/rezics/rezics-next/.temp/arch-review-2/target-architecture.md`
§4, read only §4) decides:

- **Accepted means the current reviewed basis.** A change may update or delete
  an authored profile or Facet in place; review of the definition diff and the
  generated diff is the acceptance. Delete the append-only lock and the 134 + 18
  hand-written digest files. Keep what still protects something: the manifest's
  artifact digests, the `task gen:check` drift check, registry routing
  ambiguity checks, and anything that resolves bytes an existing record pins.
- **Exact stored artifacts stay immutable.** Before deleting the lock, find out
  whether anything resolves the shapes or manifest an older revision pins
  (`rv:manifest`, `rv:modelGeneration`, `rv:shapeRevision`, the revision anchor
  resolver in `docs/implementation/graph-records.md`, the Jena command module's
  manifest loading). If old bytes are needed after an in-place edit, say where
  they are custodied today and keep that path working; if nothing needs them,
  say so with the evidence. Do not build a new custody store in this task.
- **One relation-occurrence definition.** Fold `relation-occurrence-v2` into the
  current occurrence profile: the participation shape gains the optional
  `rv:creditedName` (one `rdf:langString`, at most 200 characters); the
  `rv:participationFormat` marker, `rv:CreditedNameV2`, the v2 profile file and
  its routing and validation branch in `services/main/src/modules/relation/`
  go. Keep the existing profile IRI (`relation-occurrence-v1`); removing `-vN`
  from IRIs belongs to the later all-profile migration. The served API
  (`creditedName` on participations) does not change.
- **Practice.** Update the documents that state the append-only rule
  (`docs/implementation/model-profile-validation.md` step 1,
  `docs/contracts/model-profiles.md` where it applies, `model/README.md`) to
  the versioning table in record §4: optional property or relaxed constraint →
  same profile; tightened constraint → new constraint revision with an
  admission coverage check; different meaning → new term; block payload
  changes version only that block. `docs/goals/worker.md` belongs to the
  program Goal: put the wording it needs in the handoff instead of editing it.

Populated state: the shared dev stack and QA fixtures may hold participations
with the v2 marker. REZICS keeps no compatibility layer from the unreleased
period, so do not add a dual shape, a startup backfill or a migration API.
Query the shared stack read-only (`task urls`) to count marked participations,
and state in the handoff exactly what a stack needs after merge (for example
`dataset:bootstrap-model` plus reseed). Do not write to the shared stack.

Not to build: no semantic fingerprint, SHACL equivalence checker, replacement
lock file, review-signature scheme or new versioning framework. The other 17
`-vN` families stay as they are; this task changes only relation-occurrence.
The TS SHACL DSL (`model/compiler/ir.ts`) and the arbitrary generator stay;
another task replaces them.
