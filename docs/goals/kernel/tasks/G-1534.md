## Outcome

Program's decision (final): NO `fixtureApply`, no flag-gated arbitrary-quad writer. A state no public operation produces is not a state the read must survive; the only exception is a crash state, which is produced at the real crash point with fault injection, not by hand-built triples. Rewrite the files that hand-write graph state with raw SPARQL so they reach their states through real operations, then delete the raw-SPARQL assembler and `rawSparqlIntegrationFiles`.

The list of sites with what each seeds and why it was raw is in `.temp/ref/raw-sparql-sites.md` (staged here; 11 sites in: `tests/qa/integration/also-enjoyed.test.ts` lines 33, 50, 115; `g-1016-optional-hydration.test.ts` 35, 186; `g-506-target.test.ts` 218, 248, 260; `feed-read-support.ts` 270 (used by `g-542-endpoints.test.ts` via `seedHome`); `services/main/tests/work-read.integration.test.ts` 119, 285). Re-grep for any other `fuseki.update(` / `nativeFuseki.update(` / `INSERT DATA` in `tests/qa/integration` and `services/main/tests` and `scripts/qa` helpers: the full set of files in `rawSparqlIntegrationFiles` (scripts/qa/isolated-integration-files.ts; its ratchet test is scripts/qa/raw-sparql-integration-files.test.ts) is yours.

Per site, Program's rules:
- (b) **Types**: record the type with `PUT /v1/works/{id}/type` (find the exact route; the head advances, which is fine unless the test asserts head stability: if one does, say which and why).
- (c) **AuthorCredit with an external key**: acquire through the source path with a fake provider record (as the Open Library acquisition does; find the existing fake-provider fixtures in tests/qa or services/main/tests), or use the native agent-credit command if the read under test treats both alike.
- (a) **Erased revisions**: use the erasure operation. Its extra epoch, receipt and sequence are real, so assert against them, not around them.
- (d) **Erasure between two reads of one request**: reproduce with a real erasure at an existing in-process seam if there is one; if none exists, keep the after-erasure assertion in the integration test and cover the fence and sequence rule in a unit test of the read; do NOT add a seam only for the test.
- If a site needs a state that a real operation should produce but no operation does yet, that is a missing operation: STOP on that site, name the missing operation precisely in your RESULT (route/command, what state it should produce, why the read needs it) and leave the site untouched. Do not add a fixture for it. Do not weaken or delete an assertion; if a rewritten test can no longer assert something because the state is unreachable, say so explicitly.

When every file is off raw SPARQL: delete `rawSparqlIntegrationFiles`, the raw-SPARQL assembler config (`infra/jena/fuseki-text-qa.ttl` if nothing else uses it: grep), the stack-environment/stack-startup branches that choose it, and replace the ratchet test with a test that the list does not exist / no integration file contains a raw Fuseki update (a repository guard scan). Keep `integrationStackAdmitsWorkScope` behaviour consistent so all integration stacks admit the Work-name writer.

Never raise a cap, never skip a case, never stage a per-test platform grant. USER=edge LANG=C.UTF-8 LC_ALL=C.UTF-8; run files alone with `task goal -- test <path>` (at most 3 at a time). Commit after every file made green.
