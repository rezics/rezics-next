## Outcome

Contract C6, first slice (design record §2, §3 "寫入路徑" and §14 row 8:
`.temp/ref/target-architecture.md`). Must hold:

1. **One real command runs slim.** Pick one existing component write (Work
   metadata edit or chapter Post publication) and make its graph write carry
   only current public semantics plus a compact commit proof of about 3–6
   quads, keeping CAS, policy, focused SHACL and the receipt. Measure before
   and after in quads, bytes and commit time on the same fixture
   (`scripts/load/slim-command-measure.ts`), and report the numbers.
2. **Proof retirement rule.** The full receipt and outbox stay in the owner's
   PostgreSQL. The graph's compact proof retires only after the owner has a
   durable receipt, the exact payload object exists in object storage, and
   reconciliation has matched them; a lost response still resolves to the
   same receipt. Never "graph commits, then PG writes" without that path.
3. **Model generation custody.** Revisions pin `rv:manifest`, but nothing
   stores the manifest and shapes of an activated model generation. On
   activation, store them by digest in object storage so any pinned revision's
   exact model can be read back; activation fails if custody fails.

Current facts stay in the default graph (record §3: about half the bytes per
quad of a named graph and fewer fsyncs). Qualify that with the command,
SHACL and text graph scopes together; do not just move the graph.

Not to build: no engine change, loader in place of the API, second receipt
runtime, RDF Delta or history engine.
