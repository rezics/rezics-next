## Outcome

Launch's G-1594 found a product gap behind "revoked editors": `POST /v1/work-maintainer-changes` (`services/main/src/modules/work/maintainers.ts`) has only `add` and `transfer`, and `transfer` drops the ACTING maintainer; nothing lets a Work's owner remove ANOTHER maintainer. Program decided the authority rule: case (b), creator-protected. Add `action: 'remove'` to the same operation, and bring the module onto Access where its state lives.

RULE (the Work's owner is derived from the immutable receipt log, no new column): the OWNER Agent is the `target` of the latest `transfer` receipt for the Work, or, if none, the Agent of the Work's creation (`access.work_maintainer_receipt` `create` row's target, falling back to `access.work_maintainer_set.creation_admission`'s acting subject; read the migration 370 and `recordInitialMaintainer` in `maintainer-proof.ts` to find which fields carry it, and say which). `remove` is allowed only when: the acting Agent IS the owner Agent and the verified principal controls it (the existing `maintainerControllerProof`, same freshness and verified-email rules as add/transfer); the target is a current maintainer other than the owner (the owner leaves only by its own `transfer`); the set generation matches (CAS); the idempotency key and request digest behave exactly as for add/transfer (digest includes the target and action `remove`; same-key-same-intent replays the receipt, same key different intent is `AdmissionConflict`); the set is never left without a maintainer (the owner always remains, so this holds; assert it anyway); no claimed selection or claimed author command is in flight (the same fences as add/transfer). A co-maintainer can still `add` as today. Refusals use the existing problem shapes and do not reveal who the owner is to a caller who is not a maintainer.

EFFECT: the removed maintainer's next write is refused through the existing per-write maintainer check (`access.work_maintainer` membership; prove it with a write attempt), and nothing they could see leaks: their reads fall back to the public view. The receipt carries `action: 'remove'` and the new maintainer list.
