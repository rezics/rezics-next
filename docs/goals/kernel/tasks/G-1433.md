## Outcome

`readRecipeWorkPage` (services/main/src/modules/recipe/work-page.ts) walks the whole Recipe hierarchy in one call and throws `Recipe exceeds page limit` past 4,096 records or `Recipe page exceeds 1 MiB`: an unbounded read that fails closed. Launch asks for a bounded, hierarchy-preserving read the work page can page through (Launch adapts the web component afterwards, `apps/web/features/work-page/*`; do not edit apps/web).

Change it so one call returns at most 100 occurrences of the selected Recipe revision plus an opaque `next` cursor, in a deterministic depth-first order that preserves hierarchy (a group's children follow the group; each record keeps `parent` so a client can rebuild the tree). The cursor pins the structure revision (`header.head`) and the traversal position (the stack of parents with their `after` keys, bounded depth), is signed or digest-checked so a tampered cursor is refused, and a cursor whose revision is no longer the selected one answers a typed stale result rather than mixing revisions. Measures (servings and the nutrition basis, at most 64) are read once and returned with the first page only; scaled ingredients are computed per page from that page's records (scaling is per record, see `scaleIngredients`), using the same servings factor, which the cursor also pins. Cost fields report pages and occurrences per call, and every call is bounded by one page of reads plus the cursor's parent re-reads (state the exact bound in a comment).

The route in services/main/src/routes/recipes.ts exposes the cursor (query parameter `cursor`, response `next`); keep the first-page response shape compatible except for the new `next` and the page cap. Keep `Servings` validation and the non-Recipe `null`. Remove the whole-hierarchy throw and the 1 MiB check on the aggregate; keep a per-page byte ceiling.

Do not build: a generic pagination framework, a new store, caching, or any change to Structure reading (`readCompositionPage` stays as is). Cut the big-recipe scenario to a fixture of about 10,000 occurrences in nested groups to prove paging is complete, ordered and each call stays bounded.
