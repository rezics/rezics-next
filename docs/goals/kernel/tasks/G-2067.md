Base: main (not the earlier attempt's branch). Today `readPublicTypeahead` hydrates per native batch of <= 10 entries inside `fillPrefixWalkPage`, through `session.selection(...)` whose fence callback replays the whole batch read. 1. Walk the native pages first (cheap command calls; same request/cursor/generation validation and `SearchSnapshotMoved` checks) until the examined cap (40 entries) or `more` is false, collecting the entries and the recorded walk requests/responses (the prefix-selection fence replays exactly these walks as now).

The fence replay then runs the same single hydration once (about two hydrations per request in total, whatever the prefix).
