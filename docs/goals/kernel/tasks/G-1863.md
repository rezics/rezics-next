## Outcome

Slice 8 of `docs/goals/kernel/reports/G-1800-specification.md` ("8. Dataset importer uses the media APIs"; read the whole report first), under Program's cover re-cut (2026-10-11, approved): an imported cover is an ordinary Media asset in the Work's avatar slot, uploaded through the existing media API, with its provenance (source, record, evidenced holder, source link) on the asset revision. Slices 1 to 3 are on main (the normalized cover candidate and the frozen bytes with their roles in `scripts/datasets/{types,bangumi,snapshot}.ts`, the Media-owned provenance and migration 2130). The API side (slice 4: principal-scoped Source evidence verification before the upload reservation, covers pinned to the Work's avatar slot, other roles refused; slice 4b: a re-import of a taken-down cover is refused by (source, record) and by original digest) is in a sibling task still running on branch `goal/g-1831` and NOT on main yet: read its request and response shapes from there (`git show goal/g-1831:services/main/src/modules/source/cover-evidence.ts`, `git show goal/g-1831:services/main/src/modules/media/commands.ts`, `git show goal/g-1831:tests/qa/integration/source-cover-attachment.test.ts` and `git diff main...goal/g-1831 -- generated/openapi/main/public.json`), build against those shapes with a fake HTTP transport, and say in your result exactly which shape you assumed so the manager can reconcile after that branch lands.

Change: a generic image phase in the importer that verifies the frozen blob, maps source and observation and the native Work identity returned by earlier API receipts (never choose identity from the source URL), reserves and uploads with provenance, and selects it as the Work's cover through the existing avatar selection operation. Reuse the existing immutable request and checkpoint journal; extend it for media phase responses and status, no new ledger. Deterministic intent keys include snapshot, candidate and target. Replays consult current fences even when a previous upload or selection succeeded; a stale-head refusal never overwrites an editor's newer selection. Submit the small cover-evidence observation even when the main record needed multipart intake; keep its canonical source record identity, scoped coverage and the separate envelope and original-capture digests. Add bounded binary transfer to the existing DatasetApi transport (it JSON-stringifies all bodies today); use the actual Main upload destination and authentication; NEVER send credentials to the provider image URL. Checkpoint the byte digest and the local blob reference, not raster bytes in JSON journals. Handle token renewal, transfer failure and a lost successful JSON response through the existing retries. A refusal for a restricted, suppressed or unavailable cover leaves the imported facts in place (cover pending, facts preserved).

Proof (extend `tests/qa/unit/dataset-import.test.ts`; fake HTTP checks exact pinned bytes, digests and keys): `cover import resumes lost reserve transfer and selection replies`, `cover pending denied restricted and unavailable outcomes preserve imported facts`, `a configured second provider uses the identical cover API sequence` (the second fixture supplies an already mapped native Work and canonical source identity; it must not run through the closed provider-specific acquisition switch), `import retry never replaces an editor cover after stale selection`, `a refused re-import of a taken-down cover leaves the facts and reports pending`. Keep the importer facts' original checks and the absence of unexpected network access. Live acceptance is the end-to-end proof task later.
