## Outcome

`docs/goals/kernel/tasks/G-1591.md` (read it first, including its DECISION 0) is class A for wave 2: Launch's signed-in lists and cookie-free public reads wait on it. It is independent of the Claims-into-Statements work (no shared files) and must land alone. It is too large for one session as written (audit, contract across about ten routes, a cursor-binding helper with a scan guard, OpenAPI and SDK, web call-site inventory, tests). Do its step 1, the AUDIT, as a read-only analysis and specify the rest as Luna/max slices.

1. THE AUDIT TABLE: every read that mints a cursor and runs under a disclosure viewer (`grep -rn "decodeReadCursor(\|encodeReadCursor(\|publicWorkRead\|publicViewer" services/main/src`), one row each: route, binding profile id, whether it takes the viewer from the bearer today, whether its answer can differ per viewer (age and category opt-ins, mutes), its current cache headers, the file and line. Include the reads `mine` scopes and already-private routes (and say they stay as they are).
2. THE SLICES: order, files and lines, the change, which slice builds the one cursor-binding helper (mode and, for `viewer`, a stable digest of the principal's disclosure profile, the same value `disclosureViewer` uses, never the raw account id), which slice adds the scan guard that fails when a cursor call site does not use it, which slices add `mode` per route family, OpenAPI and generated SDK (`task gen` outputs, `task web:typecheck`), the API document under `docs/` that must record the decision and its reason (find the owner doc that describes public reads and cursors), the tests that prove each slice (existing cursor and paging test files by path, new ones by name), what a mismatched token does (the module's existing restart or `read_basis_changed`, no new problem type), cache-header changes per route (`public` cacheable where the route otherwise is, `viewer` private no-store), and the rate-limit principal accounting that must stay.
3. THE WEB CALL SITES: every `apps/web` call that hits an affected route and whether it should pass `mode=viewer` (a signed-in shelf, home, following list) or stay `public`. Kernel does not edit `apps/web`; this list is mailed to Launch.
4. LANDING ALONE: confirm that no slice depends on the Claims-into-Statements task and which Launch change must follow (the web client passing `mode=viewer`) so a signed-in list never silently turns anonymous: state the safe order (additive optional parameter first; the default flips at the same time as the client passes the mode, or before it with the client change in the same wave).

## Output

READ-ONLY ANALYSIS. Change no product code and no test. The only file you write is `docs/goals/kernel/reports/G-1713-specification.md` (committed). Say plainly what you could not establish; classify each slice A, B or C against the finish line with the reason.
