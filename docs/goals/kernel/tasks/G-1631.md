## Outcome

Three independent items from regression runs 8 and 9; do them in this order, one commit per step (step 3 is research first).

1. THREE 503s WHERE THE CONTRACT IS 409 (older than G-1623; kernel confirmed they still fail with the 404/409 status restoration applied, so the cause is not that change).
   - `tests/qa/integration/rating-gate.test.ts:218`: with `access.scope_gate` held `FOR UPDATE` by another session, `POST /v1/rating-observations` answers 503 `dependency_unavailable` (the body of `AccountAssertionUnavailable`/`AdmissionUnavailable`, `routes/problems.ts` near line 559) where the test expects 409 and a later same-key success.
   - `tests/qa/integration/semantic-change-race.test.ts`: expects 409 on a race and gets 503.
   - `tests/qa/integration/rating-global-synthesis.test.ts`: `toMatchObject` differs by 1 expected and 4 received lines (read the artifact for the lines).
   Find which commit changed each answer (`git log -S` on the error class and the route; the tests passed at an earlier run), decide by the contract (a held gate or a lost CAS race is a 409 retry, not a failed dependency), fix the code or, if the contract changed on purpose, change the test and record why in the commit. Do not widen `AdmissionUnavailable`. A lock timeout (`55P03`) inside a command transaction must map to one named, retryable refusal, not to the generic dependency answer; say where that mapping lives now.
2. THREE NATIVE TESTS HANG AT THE UNIT TIER DEADLINE: `infra/jena/tests/native-integer-preservation.test.ts` (new), `semantic-source-readiness-union.test.ts` and `work-name-scope-basis.test.ts` hang until the 180 s tier deadline in run 9 (the last two since run 8). They pull a jar from the network or run a docker image inside the unit tier. Classify each: a test that needs the image or the network is a native-tier test and is routed there by `scripts/qa/` (find how `affected`/tier assignment names such files) and is NOT run in the unit tier; a test that should be unit-fast gets an explicit short timeout and a skip with a named reason when the prerequisite is absent (never a silent pass). Program's preference (2026-10-11): move the three native proof tests to the tier that already has the image rather than skipping them. The unit gate must stop paying the tier deadline for them.

3. A VALID RECIPE EDIT REFUSED AFTER EARLIER TESTS (research; Program 2026-10-11, product question first). Independent re-run of the recipe fix: in one shared database, in the order `realm-submission-api`, `recipe-work-page`, `g-829-public-reads`, then `recipe-update`, both `recipe-update` cases fail at `tests/qa/fixtures/author-credit.ts:337` (called from `recipe-update.test.ts:76`) with 400 "Persisted profile validation rejected the request" where 200 is expected; each passes alone. The harness says "assumes a fresh database", but production never has one. The 400 is a native command answering `status: 'invalid'` (`routes/problems.ts` `CommandRejected` branch, line ~370, which drops `error.result.report`). Do, in order: (a) reproduce by running those four files in that order on one stack and capture `error.result.report` (temporary log; remove it); (b) name which persisted-profile validation (shape and focus) rejects it and which earlier file's state (a replaced model or shape head, a retained generation, a leftover definition) makes it do so; (c) decide: if a valid edit is refused because of leftover state, that is a product defect and the fix goes in the code that reads the head; if the earlier test legitimately leaves the dataset in a state production could also reach, the refusal is right only if its report reaches the caller, so fix the route to carry the report as a problem detail; if the state is only reachable by a test that rewrites heads, move that test to its own database (`isolatedIntegrationFileList`) and say so.
