## Outcome

Contract C2, first slice. Today every graph constraint is a TypeScript object
in the SHACL DSL (`model/compiler/ir.ts`) that the compiler renders to Turtle.
The design record (`/home/edge/projects/rezics/rezics-next/.temp/arch-review-2/target-architecture.md`
§4, "模型來源與生成物") decides that SHACL Turtle is the author source and a
bounded converter reads RDF terms from it to emit TS types, TypeBox and the
JSON-LD context. G-1217 (merged before you start) made profiles editable in
place. A read-only scout mapped this slice: `/home/edge/projects/rezics/rezics-next/.temp/kernel/scouts/K2.md`.

1. **Post in Turtle.** Post's shape becomes `model/definitions/post-v1.ttl`;
   its command metadata (canonical routing, bindings) stays in TS beside it.
   The compiler discovers Turtle-authored profiles alongside TS ones and
   refuses a duplicate profile ID. The other profiles stay on the DSL in this
   slice.
2. **Bounded converter** (`model/compiler/shacl.ts`): parse Turtle into RDF
   terms with a standard parser (N3.js; pin it and record it in
   `docs/development/toolchain.md`) and support exactly the constructs Post and
   the block payload use (named NodeShape, property, simple IRI path,
   min/maxCount including 0, IRI hasValue, nodeKind IRI, datatype incl.
   langString, uniqueLang, min/maxLength, class, closed). Any other construct
   fails generation by name; nothing is silently dropped. JSON container, null
   and exact lexical rules stay explicit in the converter, not inferred from
   SHACL. Post's generated outputs stay byte-for-byte equivalent except for
   the new field.
3. **Fix the shared lowering defects the scout re-verified**, since the
   converter must not inherit them: a quoted literal enum must not get
   `@type: @id` (`release-v3` context), `uniqueLang` must be enforced in the
   generated schema, and a minCount/maxCount over distinct values must not
   admit duplicates. Fix them in `outputs.ts` for every profile; the generated
   diff shows which contexts and schemas change.
4. **One block payload with its own version.** `work-reference-block-v1`: a
   closed shape holding only a Work reference (IRI) and one language-tagged
   title. Add its exact definition/version branch to the document rules in
   `packages/document/src/schema.ts`; unknown and future block payloads stay
   opaque and round-trip unchanged; retained revisions never read as corrupt.
5. **Spoiler is the optional field added in the same change** (launch's review
   finding FE-12): the author's spoiler declaration, a boolean, optional on the
   Post shape. Carry it through reply drafts (`routes/member-replies.ts`,
   `routes/realm-replies.ts`, `content-publication/reply-draft.ts`) and
   publication, and return it on Post reads. Reuse a standard term if one fits;
   otherwise one `rv:` term, named in the handoff. Adding it must produce no new
   profile family or document version. The web composer and feed readers are
   launch's: list the served-contract change under OWNER CHANGES; do not edit
   `apps/web`.

Material, not to merge: branch `goal/g-432` (a withdrawn chapter author-note
implementation) shows an earlier attempt at a block; read it only if it
helps item 4.

Not to build: no general SHACL compiler or plugin loader, no new registry or
framework, no document-to-RDF storage layer, no renderer, no
reference-resolution service, no compatibility family, no profile options
beyond what Post and the block use. Do not migrate other profiles and do not
delete the DSL; later slices do that. No `sh:in`, `sh:or` or path expressions
until a profile needs them.
