## Outcome

Program's mechanism guard (`scripts/static/mechanisms.ts`, frozen list `scripts/static/mechanism-dependencies.json`, 137 pairs) lets code outside a mechanism owner import only that owner's registered entry points; the existing crossings into Access are frozen and can only shrink. Shrink them, starting with these clusters (file counts from the frozen list):

- `routes/access-authority.ts`, `access-memberships.ts`, `access-policy.ts`, `access-roles.ts`, `access-topology.ts` -> `group-intent.ts` (5) and `groups.ts`: these routes ARE the Access module's HTTP adapters. Decide per file: either the route's use goes through an existing registered entry point (`AccessGrants`, `AccessMemberships`, `AccessAdmissionRegistry`, ...), or the shared intent/problem type moves out of Access into the one place both sides already depend on (a contract type is not the owner's decision), or the file is declared an Access allowed adapter in `scripts/static/mechanisms.ts` (`allowedAdapters`) ONLY if it carries data and decides nothing; say which and why for each.
- `routes/dependencies.ts`, `routes/problems.ts`, `composition.ts` -> `contexts.ts`, `groups.ts`, `roles.ts`, `private-recipients.ts`, `managed-organizations.ts` (about 14 pairs): these are wiring and problem mapping. Prefer one registered composition entry point of Access (`access/…#composeAccess` style, only if it REMOVES more pairs than it adds) over registering five more files.
- `modules/onboarding/ensure.ts -> contexts.ts`, `modules/proposal/execute.ts -> managed-organizations.ts`: a module reaching into Access internals for a decision: route it through the owner's entry point, or show it asks for data only.
Do NOT add a registered entry point per crossing (that moves the pair count into the registry without removing coupling). `access/work-edit-authority.ts` is Program's to register (its 6 importers resolve with it; leave them).

Acceptance: `mechanism-dependencies.json` shrinks by at least 20 pairs (report the count before and after and the list removed); NO pair is added; the guard (`scripts/static/mechanism-writers.test.ts`, the mechanism guard test; find it with `grep -rl mechanism-dependencies scripts`) passes; behaviour unchanged: the Access route tests and `tests/qa/unit/dataset-bootstrap.test.ts`, `tests/qa/integration/access-baseline-seed.test.ts`, `tests/qa/integration/web-auth-bootstrap.test.ts` plus the route files you touched (find their tests with `grep -rl <route name> services/main/tests tests/qa`). NET LINE DECREASE in non-test files is required and reported (`git diff --stat main...HEAD`); if moving a type makes the diff larger, choose the cheaper option or stop and say why. No behaviour change, no new framework.

Commit after each cluster.

## Mechanisms
