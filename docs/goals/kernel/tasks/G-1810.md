## Outcome

Launch's L10 lookup question (mail from Launch to Trust-ops and kernel, 2026-10-11) and Trust-ops' hidden==absent equality rule: `WorkReadSession.realm()` in `services/main/src/modules/work/read-session.ts` (about lines 166 to 180) reads `readRealmPolicy` and, for a PRIVATE Realm, `this.deps.access.realmReadProof(principal, actingSubject, realm)` (a membership read) before refusing with `WorkReadMissing`; for an ABSENT Realm it throws `WorkReadMissing` right after `readRealmPolicy` alone. So an authenticated caller (principal and actingSubject present) pays ONE MORE read for a hidden private Realm than for an absent one, and every route built on `WorkReadSession.realm` (Realm threads, Realm works, the new about-thread lookup) leaks existence through the read count.

Repair (kernel decision, option (a) of Launch's question; the meter stays "equal counts for every outcome", no decoy beyond this): when the Realm policy is absent and the caller has a principal and an actingSubject, perform the SAME membership read shape against the requested Realm id first (`realmReadProof`, which returns no proof for an unknown Realm) and then throw the same `WorkReadMissing('Realm is unavailable')`; an anonymous caller (no principal) reads nothing extra on either path, which is already equal. The two outcomes (hidden private Realm, absent Realm) must make the SAME number of graph queries and the SAME number of access reads, answer the SAME 404 and the same problem body. Public Realms are unaffected. Keep the proof bookkeeping (`realmProofs`, `fenceRealms`) exactly as is; do not weaken the membership move check.

Proof: new unit `services/main/tests/work-realm-hidden-absent.test.ts` with a counting dependency double (count `environment.fuseki.query` calls and `access.realmReadProof` calls): hidden private Realm versus absent Realm, for an authenticated caller with an actingSubject and for an anonymous caller: equal counts, equal error class and message; a member of the private Realm still reads it; a public Realm is read. Add the Realm read to the registry `scripts/static/hidden-id-reads.json` using the helper `tests/qa/support/hidden-id-equality.ts` if a route-level entry for the Realm threads read exists or is the natural place (read how neighbouring entries are declared; if none fits, say so in the RESULT and do not invent one). Waits for Launch's G-1807 to release its claim on `read-session.ts`.
