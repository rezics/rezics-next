## Deferred product direction

Bring REZICS to a level of completeness that exceeds the strongest relevant
products in each supported domain. The maintainer explicitly names VNDB and
Bangumi for catalogue depth, Steam for games, and Reddit and Fandom for community
spaces and shared knowledge. These are comparison targets, not evidence that
REZICS already meets the bar. Assess further domain leaders when the actual
user job warrants it, including books and recipes in the first public scope.

API first remains the architecture: capabilities, authority, data fidelity and
bounded operation costs define behavior; interfaces make those capabilities
understandable, efficient and satisfying. A unified engine should propagate a
good solution across domains without erasing their professional requirements.
Do not lower a domain's outcome to make it fit an incomplete generic surface.

This Goal is additional to the fixed 61-class audit remediation, which continues
independently. Research and implementation must respect that Goal's active
claims and reuse its fixes and evidence. Do not inflate its finding count or
mistake audit closure for product completeness. Initially research existing
capabilities, complete journeys and credible alternatives before assigning
nonconflicting implementation slices.

Research starts with codex-2, GPT-6.1 Sol at max. The maintainer also authorizes
Claude for frontend implementation, refinement and research when its session
allowance recovers, superseding the older managers-only assignment. Independent
review remains codex-1, GPT-6.1 Sol at xhigh. Machine allowance policies and live
observations remain untracked. Coordinate shared Claude capacity with the
separate about repository; release its reserved share only after verified
completion. Use available allowance for useful completed work.

Acceptance needs real, sufficiently populated scenarios, public API proofs,
actual rendered and interaction evidence, and task-specific comparison against
the relevant leader. Include discovery, comprehension, contribution, feedback,
return visits and failure recovery across desktop, phone, keyboard, assistive
technology and supported languages. A feature checklist, attractive empty state
or architectural argument cannot establish superiority.

Record researched gaps, evidence, decisions and executable next slices in the
[state](state.md). New libraries need a concrete user benefit, comparison with
existing dependencies and native APIs, and proportionate integration evidence.
Revisit worthwhile libraries as decisions arise; include the maintainer's
TanStack Hotkeys reference in the first investigation.
