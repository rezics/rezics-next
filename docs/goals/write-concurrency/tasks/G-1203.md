## Outcome

G-1188's serialization guard flags
`services/main/src/modules/source/author-name.ts:264`: every author-name
change runs `UPDATE source.author_name_generation SET generation = generation + 1 WHERE id`,
a single row defined in Content migration 400, and holds it until commit. So
author-name writes for unrelated authors run one at a time. Readers at `:90`
and `:164` use the generation as a "has anything changed" fence.

Replace it with what each reader needs:
- If a reader fences one author's name, use that author's head revision
  (`source.author_name_head`).
- If a reader needs to know whether anything changed, use a change-log or
  count signal in the shape G-1199 used (Access 1240, Content 840), with a
  bounded prune.

Drop the singleton row only when nothing reads it. Keep response shapes and
idempotency.

## Checks

- A test where an author-name write is held open and a write for another
  author commits within one second.
- The existing author-name tests through `task goal -- test`.
- `task main:typecheck`
