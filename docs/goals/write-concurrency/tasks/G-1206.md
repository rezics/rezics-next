## Outcome

Main-wide regression (QA `20261005t210745-1a017c`, it also fails alone):
`tests/qa/integration/g-1032-query-cost.test.ts:500` expects the OTLP
`postgresStatements` to equal the locally counted statements plus two probes
per asynchronous read commit. It gets 54 instead of 56.

The difference is one asynchronous commit's two probes. The likely cause is
that `sql.asyncCommits()` counts a commit made by a background worker (the
Realm directory, co-reader or discovery tick) during the measured window, so
the local side gains two that OTLP's request profile does not have. That is
the class G-1182 and G-1193 fixed for other counters.

Confirm the cause:
- If it is attribution, scope the async-commit counter to the measured request,
  the same way `tests/qa/integration/support/counting-fuseki.ts` scopes graph
  queries.
- If the product really issues two fewer statements, because a later merge
  folded a read, update the expectation and name the commit.

Change test files only.
