## Outcome

Main-wide regression (QA `20261005t225936-039b05`, fails alone):
`tests/qa/integration/realm-visibility-policy.test.ts:49`. In a Realm whose
policy admits outsiders' replies, a non-member's
`POST /v1/realm-reply-placements` answers 403 `authority_denied` where 201 is
expected. The same file passed at `d5a17aab8`.

The suspects are this Goal's authority changes after that commit:
- G-1166 `827fd3249` and its predecessor commit, which made ordinary
  commands share scope gates;
- G-1187 `19b0625c3`, per-source authority fences and admission witnesses;
- G-1202 `647b071c8`, retry fences and grant fan-out;
- G-1204 `29f970360`.

Bisect with `task goal -- test tests/qa/integration/realm-visibility-policy.test.ts`,
then name the commit and the exact check that now denies.

Fix the product so a policy-based admission, which grants authority with no
membership or grant row, is admitted again. Keep refusing it when the policy
changes between register and claim. Do not loosen any check for members or
grants. Look for the same gap in other policy-only paths, such as open-Realm
self-join and public submission, and add a test for each one you fix.
