## Outcome

On 2026-10-06, Access migration 1171 backfilled existing rows of a table that
an earlier migration (882) makes immutable. Every QA run passed because QA
databases start empty. On the shared stack, `task dev:refresh` ran
`stop-writers` and then failed in `prepare-storage`, which left Main and
Account stopped until the manager fixed the migration and refreshed again.

Before `stop-writers`, rehearse each pending SQL migration against the live
owner database: run it in one transaction and roll it back. On failure, abort
the refresh while writers are still running, and print the migration and the
error.

Keep the plan's order otherwise (`scripts/dev/refresh.ts`), and keep the
rehearsal read-only in effect. Locks taken during the rehearsal must be brief;
if a migration needs a lock the running stack holds, the rehearsal may time out
and the refresh should report that instead of hanging.
