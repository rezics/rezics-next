## Outcome

Review findings P2-4 and P2-7 (G-1195):
- P2-4: `rankings/projection.ts:149-152` lost its reset when the checkpoint's `content_sequence` is ahead of the owner's sequence (restore), and lowering can skip events. Restore the reset and make lowering replay from the owner's position.
- P2-7: `access.editorial_event` rows start with `sequence NULL`; `EditorialReviewStore.commitEvents` numbers them after commit only below the xid horizon, while the proposal read lists only `e.sequence > $2`, so a writer reading its own proposal right after a write can miss its own event. The response of the write or the next read must include the writer's committed event (e.g. read pending rows of this proposal by entry, or number the writer's own events before returning when the horizon allows, falling back to listing pending rows).
