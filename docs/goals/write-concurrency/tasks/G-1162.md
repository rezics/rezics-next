## Outcome

Every Content write takes `content.owner_control` FOR UPDATE through
`UPDATE … SET sequence = sequence + 1 WHERE singleton`
(`services/main/src/modules/content-sequence.ts:27`, `services/content/src/core.ts:236`,
`comments.ts:298/518`, `services/main/src/modules/progress/store.ts:162`,
`realm-reply/content-store.ts:130/174`) and holds it until commit. So every
reading-progress save, session update, draft, comment, publication, reply and
media command on the platform runs one at a time. The progress and Content core
transactions also set no `lock_timeout`. Worst of all, the session command
calls `assertOwner()` (`session/store.ts:181`) after taking the lock; that is an
Account introspection over HTTP (up to 3 s) plus an Access transaction.

Make Content writers take no row shared by unrelated targets. Consumers must
still never miss an event, including across restore. Follow the pattern in
[GOAL.md](../GOAL.md#pattern) and the research note
`.temp/research/global-write-serialization-2026-10-05.md` (copy it from the main
checkout).

Downstream code relies on contiguous `(data_epoch, sequence)` positions:
- `ContentProjectionCursor.acknowledge` requires `next = expected + 1`
  (`projection-cursor.ts:37`), and so does `adoptRebuildCheckpoint`;
- recovery coverage, `rankings/realm-threads.ts:286` and
  `structure/progress-outbox.ts` read the outbox by sequence;
- media and presentation results return `position` to API callers.

The recommended smallest design keeps those contracts. Writers insert the
receipt and outbox rows stamped with `xid8`, with no sequence yet. One
sequencer, which is the only holder of the owner position lock, assigns
contiguous sequences to rows below the snapshot horizon, in `(xid, id)` order.
Consumers read only sequenced rows.

Find every caller that uses a position synchronously, and decide what a write
returns instead: for example, the operation id and a pending position that
callers can wait on. If a served response shape changes, follow the
served-contract steps in the [program](../../README.md#integration-and-qa).

If you find a simpler design that keeps every guarantee, propose it in the
handoff and use it. Do not build a general event-store module, new services or
configuration options.

Constraints:
- **Keep the signature of `advanceContentSequence`.** Callers in
  `services/main/src/modules/media-rendition/` belong to the showcase Goal's area.
  If its return type cannot stay, stop and report instead of editing them.
- **Session owner check.** Move the Account and Access owner check before the
  Content transaction, and re-check inside the transaction only what is local.
- **Bounded waits.** Every Content write transaction you touch sets
  `lock_timeout` and `statement_timeout` as the other stores do (2 s / 5 s).
- **Restore.** The epoch leads the order. A logical restore
  (`tests/qa/fault-recovery/erasure-restore.test.ts` uses pg_dump) does not carry
  the transaction counter, so the sequencer must not stall or skip after one.
