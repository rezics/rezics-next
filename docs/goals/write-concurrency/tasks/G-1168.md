## Outcome

These one-row counters give gap-free positions or generations. Writers bump
them, through triggers or directly, and hold the row until commit:

| Counter | Defined in (migration) | Taken by |
| --- | --- | --- |
| `access.reader_review_rank_head` | access 623:9-45 | every review create or delete (`review/store.ts:135/146/188`); moderation (`governance/report-review.ts:97`) |
| `access.site_moderation_position` | access 932:3-17 | every public report (`public-report/store.ts:108/117`, via the trigger in 933) and every platform case decision |
| `access.editorial_event_clock` | access 882:3-22 | every editorial action (`editorial-review/store.ts:231`); read by the editorial notification consumer (`notification-producers/producer.ts`, `runEditorialOnce`) |
| `access.realm_count_position` | access 395:10-42 | every Realm join or leave (both counters) |
| `access.realm_growth_position` | access 860:13-84 | Realm joins and leaves, and feed discussion changes |
| `reading_position.generation` | Content 727:15-27 | statement trigger on each revelation write; `wiki/evidence.ts:80` loops up to 4096 writes while holding it |

Apply the [GOAL.md pattern](../GOAL.md#pattern) as G-1164 applied it to the
notification producer log. Writers append a row stamped with `xid8`, and each
consumer reads below the snapshot horizon in one statement.

Where a reader needs a contiguous position, for example a cursor contract or a
count page fence, add one sequencer that assigns positions below the horizon;
only the sequencer may lock. Where a generation only signals "changed", use a
change row instead of a counter. The per-Realm member count may stay per-Realm,
but it must not serialize joins across different Realms.

Keep consumer guarantees and response shapes. Migrate existing positions so
nothing is delivered twice or lost.

Smallest change per counter. Reuse G-1164's consumer shape and add no new
module or abstraction. If a counter turns out to be needed exactly as it is,
explain why in the handoff and leave it.
