## Outcome

Main-wide regression: `tests/qa/fault-recovery/g-571-screen-recovery.test.ts:51`
fails alone on current main (QA `20261005t191745-836b8c`). After an image
representation is removed and an in-flight screen settles, the upload's
clearance reads `rejected`; the test expects `cleared` (the late screen result
must be fenced out, not applied).

Suspects:
- G-1162 (`7f0cdfeb0`), which moved `media-screen/store.ts` and
  `media/store.ts` to the post-commit Content sequencer. Positions are now
  assigned after commit, so a fence comparing positions or reading a position
  inside the writer's transaction may see `null` or a different order.
- G-1157 (`7fbc4a14f`).

Bisect with `task goal -- test tests/qa/fault-recovery/g-571-screen-recovery.test.ts`
at the suspects and their parents, and name the commit.

Fix the fence so deletion and erasure still exclude in-flight screen results,
using whatever identity G-1162 left stable (operation id or receipt entry)
rather than a contiguous position that no longer exists at write time. Do not
change the sequencer.
