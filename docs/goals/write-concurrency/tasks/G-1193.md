## Outcome

Main Goal now runs background workers in every Main composition: the Realm
directory refresh (G-1165), the scheduled co-reader refresh and discovery fold
(G-1179, G-1183) and the producer and digest ticks. Tests that assert "the
same cost at N and at M" or "at most K calls" count those workers' work as
well.

G-1182 scoped `CountingFuseki` to the foreground async context, and G-1186
fixed four files. These still fail alone on main:
- `post-catalogue-scale.test.ts:302`: graph calls are 10 vs 19 and 11 vs 7
  between samples;
- `private-search-native.test.ts:598`: the query and health deltas differ by
  decoy count;
- `rating-components.test.ts:110`: graph queries and Access pool checkouts
  differ between 0, 100, 101 and 130 raters.

Fix the class:
- Give the Access and Content pool checkout counters, and any other cost
  counter or interceptor the tests use (`fuseki.health`, query observers), the
  same foreground scoping as `CountingFuseki`, in
  `tests/qa/integration/support/`.
- Move the three files above, and every other integration test with its own
  counter or interceptor, onto the scoped counters. Find them with
  `rg -l "queries\+\+|calls\+\+|checkouts|observed\.push|fuseki\.health" tests/qa/integration`.

Keep budget values. Change one only if it was miscounted, and give the
arithmetic. Do not stop background workers in test stacks, and do not change
product code.

## Checks

- Run the three named files three times each through `task goal -- test`.
- Run every other file you move onto the scoped counters once.
- `task ast-grep -- scan` on the changed files.
- If a file still varies after scoping, report it as a possible product cost
  regression rather than adjusting its budget.
