## Outcome

Main-wide regression item from scoped-subjects (its G-1174, cancelled
unfinished). Start from its unverified work in progress:
`git cherry-pick 5d6bfaf16` from branch `goal/g-1174`. That commit touches
`semantic-disclosure.ts`, `context-fixture.ts`,
`search-grouped-native.test.ts` and a new `access-public-disclosure.test.ts`.
Review it, finish it and verify it. Keep its commit or replace it.

`AccessAdmissionRegistry.canReadSemanticResource`, and any other
public-disclosure path in `services/main/src/modules/access/`, answers "not
public" when `configureBaseline(fuseki)` was never called. A composition that
forgets the call therefore turns every public relation definition and semantic
resource into a hidden reference, and the writer gets a 422
`unavailable_reference` that is hard to trace.
- `tests/qa/fixtures/author-credit.ts` had this gap.
- `tests/qa/integration/context-fixture.ts` still has it, so
  `search-grouped-native.test.ts` fails alone (QA `20261005t141656-6952ea`).
- There are about 148 registry constructions and 38 `configureBaseline`
  calls.

Fix the class:
- A public-disclosure read on a registry without a baseline graph throws a
  clear configuration error instead of answering "not public". Construction
  stays as it is, so unit stubs that never reach this path are unaffected.
- Every fixture and composition in your paths that does reach the path calls
  `configureBaseline`, as production does. Find them by running the affected
  tests. Change only test fixtures and support files.
- Production composition already configures the baseline; confirm it with a
  unit test.
