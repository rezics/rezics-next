## Outcome

Three counters, each a single row, tell projection builders that their source
changed. Triggers update them inside the writer's transaction, so every
writer holds the row until commit:

| Counter | Defined in | Bumped by | Builder locking |
| --- | --- | --- | --- |
| `access.discovery_source_fence` | migration 315; function replaced in 1044, triggers in 1060 | every judgment vote and spoiler hint, moderation enforcement, principal deactivation, rating heads | discovery builder holds it FOR SHARE while it commits batches of up to 250 works × 84 entries (`discovery/store.ts:247-252`, `:543`, `refresh-store.ts`). So votes wait on builds, and reads wait on votes. |
| `access.also_enjoyed_source_fence` | migration 785 | every rating seal, library visibility change, onboarding step | — |
| `reader.also_enjoyed_source_fence` | Content migrations 415 and 602 | every shelf-status change (`PUT /v1/works/:id/reader-status`), session projection | — |

Migration 315's comment gives the reason: "sequence.nextval alone could be
observed before its source transaction commits".

Replace each counter with the [GOAL.md pattern](../GOAL.md#pattern): writers'
triggers append a change row (the source key where useful, plus `xid8`) with no
shared update. A builder records the horizon it built at, and treats only
changes below that horizon as covered. Staleness is "a change row exists after
my cursor".

Keep the builder's consistency guarantee: no build may publish rows mixing
source states it did not account for. Use the same horizon gate as G-1164's
producer log. Once G-1164 merges, its consumer statement in
`services/main/src/modules/notification-producers/` shows the shape.

Change the triggers in new migrations and the builders and readers in your
paths. The writer code under `services/main/src/modules/access/**`,
`judgment/**` and `rating/**` must not need edits. If it does, stop and report.
Keep the existing behaviour of `discovery-refresh-retirement.test.ts`
(scoped-subjects' G-1154 fix in `recommendation/ranking.ts`, migration 1120).

No new services, caches or options. Remove a fence only when nothing reads it.
