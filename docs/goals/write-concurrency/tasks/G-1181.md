## Outcome

Main-wide regression at `1dae3f67a` (QA `20261005t160239-17126e`):
`tests/qa/integration/g-530-draft-cover.test.ts:101` fails alone. A signed-in
reader fetches a published Work's cover and gets `cache-control: private,
no-store`; the test expects `public, no-cache`.

The cause is showcase's G-1157 (`7fbc4a14f`, `0dca46415`), which made
`services/main/src/routes/media.ts:133` answer `public, no-cache` only when the
request has no `authorization` header.

`no-store` on public bytes means a signed-in reader's browser never caches a
cover or showcase image and downloads it again on every view. That is a
performance regression for exactly the users who browse most.

Decide the rule from the media contract (`docs/contracts/media.md`, the showcase
art and delivery sections) and RFC 9111:
- **Same bytes for every reader** (public target): `public, no-cache` with
  validators (ETag / 304), whether or not the request is signed in.
- **Bytes that depend on the viewer** (private or draft): `private, no-cache`
  when revalidation is safe. Use `no-store` only where the contract says the
  bytes must never be stored.

Keep G-1157's 304 behaviour and its cache labels for anonymous readers. Update
the contract sentence if the rule was not written down. Change the test
expectation only if the contract really requires something else, and explain
why.
