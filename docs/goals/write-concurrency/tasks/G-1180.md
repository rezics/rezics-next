## Outcome

Main-wide regression at `1dae3f67a` (QA `20261005t145650-7b2446`, artifacts under
`.temp/verify/.artifacts/qa/`): `tests/qa/integration/access-baseline-seed.test.ts`
fails alone. In "baseline seed member journey" at line 284, it expects 7
`createdRealms` and gets 0.

The seed's Realm creation runs inside `state.optional('Space / Realm creation', …)`
(`scripts/dev/seed/realms-step.ts:89-103`), so every error is swallowed into
`findings` and the test never prints them.

The likely cause is scoped-subjects' G-1146 (`23dfa8e4b`, merged after the
previous full pass). Official Realms now read their Zone first through
`adoptZoneSpace(get, …)`. On a fresh QA stack with no operator input (no Zone
grant), that read may answer something other than 404, which throws.

1. **Confirm the cause** from the swallowed finding. Run the test at
   `23dfa8e4b^` and `23dfa8e4b` if it is still unclear.
2. **Fix the seed** so the member journey creates its Realms on a fresh stack
   and still adopts the Zone's Space when one exists. Keep G-1146's intent:
   one Realm per Zone, no duplicate Space under a new key.
3. **Fix the class.** When a step's expectation fails, the baseline seed test
   prints the `findings` it collected, so a swallowed error is never invisible
   again.
