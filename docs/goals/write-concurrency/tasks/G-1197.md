## Outcome

Review finding P1-1 (G-1195): since G-1183, a co-reader build is registered whenever the head's basis is not covered, on every discovery tick (100 ms while busy), so under continuous shelf or rating writes builds run back to back; superseded generations only become `expired` and nothing ever deletes their `access.also_enjoyed_signal` / `access.also_enjoyed_pair` rows (`785` declares max_retained 3, retain_for 1 hour).

Add a bounded purge of signal and pair rows for expired, cancelled and failed generations older than `retain_for`, modelled on `DiscoveryRefreshStore.purge` and run from the same tick. Register an automatic build only when the active head is older than a minimum interval (a constant beside the existing costs, e.g. a few minutes), so build cost is paced independently of write rate; privacy-relevant changes keep withholding reads exactly as G-1183 made them.

Smallest change; no new services or options. Read the finding in full in .temp/research/write-concurrency-review.md (main checkout) first.

## Checks

- Integration: under a steady deterministic stream of shelf changes, at most one automatic build per interval, and purged rows disappear for superseded generations past `retain_for` (use an injected clock or interval).
