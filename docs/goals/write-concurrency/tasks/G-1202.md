## Outcome

The review of G-1187 (section "G-1187" in
`.temp/research/write-concurrency-review.md`, main checkout) found no P0 or P1.
Read the full findings before changing anything. Fix these P2s:

1. **G1187-P2-1: vote retries can re-dispatch after the body grant is
   revoked.** Vote replay must pin its saved body-grant and mandate
   generations, or record them in `authority_witness`, so a retry after
   revocation fails (`vote/access.ts`).
2. **G1187-P2-2: delegation fan-out caps count without serialization.** Two
   concurrent delegated-grant or manage-invitation creations can both pass a
   cap. Take a per-root or per-ceiling advisory lock keyed by that root, not a
   constant key, around the count and the insert (`grants.ts`,
   `invitation.ts`).
3. **G1187-P2-3: catalogue replay locks its admission before its witness
   sources**, so it can deadlock (40P01) with a revocation. Lock the witness
   sources first, in a new Access migration that replaces
   `catalogue_import_admit`.
4. **G1187-P2-4: scope gates' `group_generation` can no longer change but is
   still compared.** Remove those comparisons, or point them at
   `access:group-inventory`, in `policy-decisions.ts`,
   `interaction-decisions.ts` and `represented-work-proof.ts`.
5. **G1187-P2-6: register writes each admission twice.** Set
   `authority_witness` in the admission INSERT. For CHECK constraints on large
   tables in your migration, use `NOT VALID` then `VALIDATE`.

Keep every authority semantic G-1187 established, and keep
`scope-gate-concurrency` passing.
