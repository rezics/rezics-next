## Outcome

G-1202 fenced vote retries against the body grant and mandate generations
their first attempt used, so a retry after revocation fails. It found the
same gap, which predates it, in proposal execution:
`services/main/src/modules/proposal/access.ts` retries execution without
checking the saved authority sources or the scope epoch.

Apply G-1202's pattern (`vote/access.ts`, commit `72d4ec567`):
- the first attempt records the exact authority sources it used, in its own
  row or in `authority_witness`;
- a retry re-checks them, and the scope epoch, before re-dispatching;
- a revoked source fails the retry with the same error the first attempt
  would have produced.

Keep idempotent replay for unchanged authority.

## Checks

- **New test:** a proposal execution retry after its authority source is
  revoked is refused; a retry with unchanged authority replays.
- The proposal unit and integration files through `task goal -- test`.
- `task main:typecheck`
