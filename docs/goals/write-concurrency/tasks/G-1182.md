## Outcome

Since G-1165 (`4db8a0625`), `createMainApp` starts the Realm directory refresh
worker, which queries the same Fuseki client on its own one-second timer. Tests
that bound `stack.fuseki.queries` deltas around one operation (`CountingFuseki`
in `tests/qa/integration/media-support.ts:60`, used by about 56 integration
files) now flake: discovery-projection saw 9 graph queries against a limit of 8,
and also-enjoyed and g-1063-cost were seen to flake too.

Make the count measure only the operation under test. For example, attribute
queries to the async context of the measured call (`AsyncLocalStorage`), or
exclude the queries the background workers issue. Do not stop the directory
worker in test stacks: the directory tests rely on it.

Change test support only; product code is out of scope. Keep every existing
budget assertion unchanged unless it was miscounted, and say which if any.

## Checks

- Run the files that flaked, each three times, through `task goal -- test`:
  discovery-projection, also-enjoyed and the g-1063 cost files.
- Run the realm-directory and media-delivery files that use `CountingFuseki`
  once.
