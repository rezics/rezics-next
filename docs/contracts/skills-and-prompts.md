# Hub content rollout gaps

The current [Hub owner](../../services/main/src/modules/hub/store.ts) admits inert
Agent Skills directory imports and exact Prompt revisions. Requirement sidecars
and bounded dependency locks have [executable cases](../../scripts/qa/cases/ai-hub.ts).

The selected Hub capability still needs native Skill and Prompt contribution,
review, release, publication, download and export flows. Releases and downloads
must pin artifact integrity, license and provenance. Repository-package imports
need an explicit profile that preserves unsupported fields and residuals; an
arbitrary folder does not become a valid Skill by normalization.

MCP software/project identity, package release, deployment endpoint and observed
server capability are different resources. Endpoint reachability cannot prove
ownership, compatibility or invocation permission; observations need their own
time and schema revisions. [Connected apps](connected-apps.md) govern current
consent and schema drift. Untrusted execution and persistent hosting retain their
separate [admission decision](../research/ai-hub-execution.md).
