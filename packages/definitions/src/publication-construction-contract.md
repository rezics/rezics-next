# Definition publication construction bounds

[Definitions](../README.md) owns release validity; [Filter](../../filter/README.md) owns admission meaning;
[Semantic publication](../../../services/kernel/src/semantic/README.md#definition-publish) owns commands and stored
reads. Construction now uses linear uniqueness diagnostics and owned facet/declaration indexes in the actual
validator, saved-filter validation, public Filter entry points and publication/read callers. The release schema,
format, catalogue, canonical digest identity and pattern policy remain unchanged.

## Validation and diagnostics

Bounded descriptor/JSON/byte admission precedes canonical sorting, hashing and schema diagnostics. Accessors,
inherited data, cycles and sparse arrays are rejected without evaluating getters. Existing collection limits
retain their `limit` precedence over schema/pattern defects. Canonical JSON remains capped at 4 MiB.

The unchanged release schema determines every uniqueness site, including library import record kinds, CURIE
lists, facets, relation filters, targets and units. The pinned TypeBox engine retains its original schema,
branch applicability, traversal order and eight-node diagnostic-context budget. Its Check predicate already uses
linear map/Set hashing. For Errors, a private, call-local diagnostic view supplies the duplicate indices with
one Set/hash walk and append per member instead of the native reducer's repeated accumulator spreads. The pinned
engine alone decides when to request those indices and whether its uniqueness error fits the current context.
No submitted array, installed dependency or schema is modified. The view retains original key order and indices;
TypeBox hash identity preserves malformed structural/numeric members, including -0 and collisions. All actual
native Check and replacement collector hashing is included in instrumentation. There is no quadratic Errors
fallback and no replacement schema engine.

The outer pointer map still preserves first code, lexical pointer order and its 64-result ceiling. The malformed
crowded witness reaches the original eight schema diagnostics; a separate schema-valid population of semantic
IRI faults reaches exactly 64 sorted results in both original and delivered validation. Malformed null units
retain the original child errors without adding an array pointer after the native context budget is exhausted.
Hash traversal, encoded bytes, diagnostic view copies and object key sorting remain real work.

## Construction lifetime and Filter callers

`createFilterConstruction` owns a descriptor-only snapshot and its indexes for one explicit construction lifetime.
Definitions uses it once for all saved filters and relation qualifier membership. Each type's own facets precede
its listed bases' **direct** facets, in list order with stable first-seen deduplication; grandparents do not recurse.
An untyped union stays separate from selected returnable types. Admission retains the selected Sets and probes
membership per leaf rather than rebuilding a union per filter. Display enumeration charges actual returned entries.
Qualifier and unit membership Sets are built once; datatype, value/pattern, same-statement, item/string/query limits
and typed refusal order remain Filter's authority.

Raw `admitFilter`, `validateFilter` and `facetProperties` create fresh indexes per call. They observe same-object
pattern, qualifier, base and facet edits immediately, including the untyped union. Reuse by object identity occurs
only after every retained node is proven frozen through own data descriptors; a shallow freeze is insufficient.
Patterns are cached only in that construction lifetime. Explicit sessions retain their owned snapshot when the
caller's original graph changes. No WeakMap of arbitrary mutable inputs supplies authority.

## New publication shape admission and historical reads

The adopted NEW-publication caps count submitted entries, including duplicates:

| Collection                    | Maximum | Refusal pointer                    |
| ----------------------------- | ------: | ---------------------------------- |
| Each type's bases             |    4096 | `/types/<escaped-key>/bases`       |
| Each type/property's mappings |     256 | Corresponding `mappings` pointer   |
| Each property's qualifiers    |    4096 | Corresponding `qualifiers` pointer |

`publicationLimits` is bounded admission, not a historical flag or a changed release format. New publications
and fresh bootstrap enforce these limits with existing `limit` diagnostics (HTTP 400 `out_of_range`). Caps never
substitute for linear algorithms: native growth experiments run the shared historical-compatible core at all
64/512/4096 scales, including mappings above the NEW-publication cap.

`readRelease` still verifies actual stored bodies through that same core, checks the exact canonical digest,
and deep-freezes them. It does not apply new shape caps to trusted historical rows. For a cap-exceeding submitted
body, publication first admits JSON/bytes, owns a copy, computes its canonical digest and makes exactly one indexed
published-existence point on the **same pool**. Only actual published existence admits historical replay/new-key
processing. There is no caller exemption, alternate digest, composed-release authority or cross-pool cache test.
Current command authorization at fresh T precedes receipt disclosure. Existing exact replay, existing-digest/new-key,
key conflict and command effects remain unchanged. A missing digest receives the new-cap refusal without writes.

The native mounted HTTP test exercises a historically valid cap-exceeding pin by executing the unchanged original
Definitions/Filter validator and pre-cap publication caller in one isolated module graph against the mounted
routes and real Auth/Access/DB rows. Each author receives the existing `gate:definition_publication` account
grant through native grant administration, alongside its resource authority; the development group remains closed.
The shared fixture's governor token includes the existing internal `gate:any` scope needed to administer that
native grant. Ordinary fixture people retain their mounted-action scopes and receive no extra resource grants.
Tracked verbatim source snapshots are pinned to
`2c86ce30efc2aabc94a7683bfea367a69263aa39`; their manifest records Git blob identities and SHA-256 hashes.
The loader verifies those bytes and the unchanged relative pattern/profile/schema and semantic dependencies,
with pinned TypeBox, canonicalize and recheck versions. It needs no runtime Git, network or invocation directory;
SQL imports retain the kernel's native Reylo loader. Assertions record all three actually loaded old modules.
A distinct fresh process running the delivered core reads that pin exactly, including its ETag, and exercises
201 replay, existing-digest/new-key 200 bookkeeping, mismatch 422, unpublished-cap 400 and revoked-authority 403
without denied effects. Replay and new-key each observe one actual same-pool published-existence probe.
The byte-admissible mounted fixture has 4097 bases and 257 mappings; a valid historical qualifier list above 4096

## Remaining publication composition

This section owns the residual algorithm and handoff plan for an already byte-admitted HTTP release. The parent
[CPU contract](../../../services/kernel/src/semantic/definition-publication-contract.md) retains its proposed
checkpoint policy and native execution schedules; the [heap observations](../../../services/kernel/src/semantic/definition-publication-heap-contract.md)
remain observations. This specification does not deliver their runtime or certify resource closure. Existing HTTP
ingress belongs to Performance: retain `http/body.ts` and `http/app.ts`'s bounded reader, UTF-8/JSON parsing,
route limits and reservation admission. Compose with that owner; add no publication reader, parser, limiter,
semaphore or worker pool. In particular, do not transfer/detach the Request's retained body buffer behind its owner.

### Actual work and live representations

Let W be admitted transport bytes, B be release JSON bytes, N/E be the submitted tree's value nodes/edges, and L
its key/string bytes. W is bounded by `MAX_BODY_LIMIT` (4,259,840), B by `RELEASE_LIMITS.bytes` (4,194,304).
These are distinct checks: JSON whitespace/escapes and number spelling make wire length unsuitable as the
canonical-byte counter. Every parsed value consumes a token and every edge syntax, so N/E/L are bounded by
the admitted representation; they are not independent unbounded work hidden behind the property count.
This observation does not bound arbitrary pre-admission direct-caller graphs or Proxy traps.

The current successful path pays for ingress chunk retention and a contiguous owned buffer; decoded text and
parsed envelope; the request-envelope JCS/hash in the mounted handler; `releaseAdmission`'s descriptor/size walk;
another admission and JCS in `validateRelease`; schema Check; library/semantic validation and expected-value JCS;
one Filter snapshot/index lifetime; release-digest JCS/hash; and native JSONB serialization/binding. A cap-exceeding
submission additionally clones the body before its digest/existence await. Invalid schema diagnostics can retain
the original tree plus `diagnosticView`'s clone, per-array hooks, native error context and duplicate hashes/indices.
The final 64 errors do not bound all intermediate violations or full pointer strings. `readRelease` separately
retains validated, frozen graphs in its current process Map; a successful same-pool existence point does not bound
that Map's cumulative memory or establish policy-version identity.

The output is not just B bytes: it includes selected facet Sets, the untyped union, qualifier/unit Sets, pattern
sources/proofs, saved-filter normalized nodes and diagnostics. Count actual insertions and emitted entries. If Eb
is the submitted base-reference count, direct base expansion visits at most 16 Eb facets; each type's own list
contributes at most 16 more. Historical bases and mappings remain bounded by B, without the new-publication
shape caps. Unknown base IRIs do not recurse. Qualifier/unit indexing follows declaration entries; typed leaf
admission probes selected type Sets and qualifier membership without rebuilding their unions. LinkML induction
is a producer-time compiler operation, not part of HTTP publication. Effective Type list hints are already emitted
inert metadata and add at most four references per hinted Type; they confer no resource or publication proof.

Charge schema-selected member hashing by actual traversed nodes/bytes, including malformed objects, and key
sorting by actual comparisons/compared bytes. Distinct-source sorting likewise compares source bytes. A generic
linear validator claim omits these costs, the native checker, pointer construction and VM/native allocation.
The existing 72 malformed comparisons, 119 parity rows, original source identities and pattern controls remain
mandatory; the plan must preserve their unchanged outcomes except the explicitly adopted HTTP work precedence.

   exceeding the current greatest retained pointer, a pointer cannot later enter as that threshold only decreases;
   retained entries therefore keep their first code. Keep TypeBox's original eight-node applicability/order budget.
   Traverse with explicit frames and materialize candidate pointers from path segments as needed; do not retain

Filter's existing `createFilterConstruction` already supplies the required one-call owned snapshot and indexes.

### Peak, retirement and receiving custody

For each phase account for simultaneously reachable representations, not their sum across time: ingress chunks
and contiguous W; decoded text and parsed graph; parent immutable snapshot; worker clone; schema diagnostic view;
Filter snapshot/indexes; proof/checker working state; canonical release/envelope strings and hash buffers; bounded
reply; parent JSONB serialization, driver/native parameter buffers and returned row/result objects. An owned
byte string, a JS string, a JS object graph and a native parameter allocation are separate charges. No allocation
coefficient c, heap multiplier, K or idle margin follows from B alone or from the existing eighteen heap samples.

The receiving command must retain custody of the exact immutable snapshot until native parameter/result use
ends. A worker completion drops its clone, diagnostic view, construction and checker job roots before reporting
disposal; a timeout/abort/error only stops waiting. Core keeps active or retired slots and byte reservations charged
until its actual disposal/physical-exit proof, including late results and failed replacement/startup. Parent ingress
reservation release after response must compose with that surviving charge, with no accounting gap or double
release. Shutdown drains/retires publication work before pool closure. Reuse requires the execution owner's proof
that old roots/results cannot attach to a new job; logical finish, detached buffers and GC samples alone do not
prove physical reclamation. Semantic must not implement a second semaphore or independently replenish a slot.

Current source exports are `validateRelease`, `releaseAdmission`, `publicationLimits`, `releaseDigest` and
`analyzePattern`/`safePattern`; none is an aggregate preparation/checkpoint or physical-disposal capability.
`Admission.run` is request admission, not evidence of CPU retirement. Until Core delivers its actual execution
interface, bind no guessed port or success-shaped stub. No new kernel-wide policy value is indispensable to this
algorithm plan; numerical admission/margin approval remains with the existing parent owners after real evidence.
