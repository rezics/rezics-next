# Access

Access owns account state and lifecycle, bearer identity evidence, resource permission evaluation, grants, principal assignments and creation authority.

## Cost

These bounds follow the TypeScript adapters, their SQL, `db/access/migrations/` and `db/access/schema.sql`; they are derivations, not measurements or asserted query plans.
The criterion is a fixed number of anchored hops and results, with work proportional to changes times index depth, regardless of database size.
`A` is total accounts; `G` is stored grants and denials for one resource/action, including applicable role grants and temporal history; `O` is distinct candidate organizations on that resource, including denial subjects; `R` is roles in a type's template; `Gt` is total grants and denials; `m` is members of one organization.
Additional sizes are `H` (all stored grant/role-grant/denial rows on that resource, across actions), `h` (stored membership intervals in one organization), `q` (intervals for one member overlapping `[at,infinity)`), `M` (membership intervals in total), `D` (assignments), `C` (coordination holds), `U` (handle claims), `F` (fence receipts), and `K` (membership slots).
Thus `G <= H <= Gt`, `m <= h`, and `q <= h`; none of `G`, `O`, `m`, `H`, `h` or `q` has an enforced cap: temporal non-overlap restricts simultaneous membership, not future intervals or history.
`b` counts actions changed, `a` distinct actions authorized (management plus new/old actions), `d` is 0 or 1 principal assignment, and `k <= 2` is actor/principal identities needing membership evidence (automated identities are skipped).
`L(N) = O(log(2+N))` shared blocks for a B-tree probe, with constant rows for a unique key; a batch of `x` point mutations costs `O(x L(N))` blocks.
All named indexes below have the relation's `_pkey` name: ordinary keys are B-trees, whereas `organization_member`, `resource_grant`, `resource_role_grant` and `resource_denial` use temporal `WITHOUT OVERLAPS` GiST keys, not B-trees.
For compact bounds, `I_T(x)` means indexed temporal access examining `x` qualifying/rechecked rows and its shared blocks: ordinary selective traversal is about `L(T)+x`, but GiST supplies no B-tree worst-case guarantee, so the conservative bound for both examinations and blocks is `O(T+x)`; temporal writes include that overlap-check cost.
`H` is a conservative resource-prefix bound because there is no separate action-leading index: action/role predicates may reduce it to `G`, but cannot impose a result cap; `ANY` role lists and distinct/union processing also scale with their input.
`P` below denotes permission preparation, `Q` the final check, and `E = O(k O (1+q))` the serialized role evidence; sums of these symbols include their rows, blocks and statements, not only CPU time.
Counts are Access SQL statements on a successful attempt, excluding the shared command envelope: a constant number of transaction/settings/time/receipt/fence statements, a point receipt read, one partition counter update and constant outbox/write-basis/receipt inserts in the command's partition.
Retries repeat those costs (parent preparation repeats too); contention retries stop after three, a grant uniqueness/exclusion conflict can invoke a second executor, and fenced-partition polling is deadline-dependent rather than a size-dependent scan.

Permission preparation exceeds the criterion even with ideal indexes because O and q are uncapped and the loop issues up to two statements per candidate organization.
The final formula exceeds the criterion because grants/denials and JSON membership evidence are uncapped, including denial-only anonymous requests and unrelated-action resource-prefix work; EXISTS can stop early but supplies no worst-case cap.
Parent authorization, standing installation, grant/delegation commands, account updates, membership changes and tombstones inherit those permission costs, even when their own point mutations are bounded.
Membership change and organization tombstone additionally exceed the criterion because `lifecycle-owners.sql` counts an uncapped organization's rows; membership replacement also deletes every interval for the target member.
Temporal GiST keys do not establish logarithmic shared-block bounds from schema alone, and their conservative worst-case traversal can grow with Gt or M even for fixed result counts; future growth checks must distinguish this from the already demonstrable linear neighbourhoods.
Catalogue processing and action-list expansion scale with trusted catalogue size and a/b/R rather than A, but no numeric template or action-list cap is enforced.
Bearer verification scales with raw JWT/JWKS inputs and cache misses, while its account and assignment database work stays point-anchored; the one-second permission evidence budget and request deadlines bound elapsed authority, not rows or shared blocks.
The account/public projection is a point read, and tombstoning scrubs only its account row while retaining authority/coordination history; these files contain no denial-projection writer or bulk erasure implementation from which to derive an additional bound.
No inspected Access SQL joins distinct partitions or uses a global lock/counter: assignment/account joins share the principal anchor, membership/account joins share the organization anchor, and handles/holds/parents are consulted separately before target checkout.
The shared executor serializes writes through one `core.partition.position` counter per partition, not one global counter, so contention can grow within that partition without requiring all partitions on one machine; external parent/creation/provisioning/recovery ports still need their own locality proofs.
