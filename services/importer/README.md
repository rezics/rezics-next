# Importer

Importer owns bounded source acquisition, run and record journals, candidate preparation, replay, media integration and cost. It calls ordinary permissioned APIs; Kernel owns authorization, execution, acceptance and readback. Conversion is pure and owns provider mappings and value fidelity ([contract](../../packages/conversion/README.md)); user cases and evidence limits are in [Imports capability acceptance](../../docs/goals/imports.capabilities.md).

## Sources, mapping and writes

| Provider     | Admitted input and grain                                                                        | Rights and exclusions                                                                       |
| ------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Bangumi      | JSONL native subjects; unsupported types remain skipped members.                                | Metadata and attributed summaries: CC BY-SA 3.0. Cover rights are separate.                 |
| VNDB         | Public COPY with genuine headers and grouped native keys; API tables retain response revisions. | Permitted metadata: ODbL 1.0 and LicenseRef-DbCL-1.0; no prose, posts, user data or images. |
| Open Library | Five-column TSV Work and Edition rows with distinct identities.                                 | CC0-1.0 bibliographic metadata only; no unknown-licensed prose or covers.                   |
| Wikidata     | JSONL Q-items with genuine revisions and exact claims.                                          | CC0-1.0 structured data only; no user text, unsupported claims or Commons images.           |

Registration owns rights and attribution; a dump field, alias or caller descriptor cannot override it. Metadata terms do not license creative text or images. Active revisions are Bangumi `bangumi@16`, VNDB `vndb@8`, Open Library `open-library@5`, Wikidata `wikidata-6`, and cross-media entities `cross-media-entities@15`; selected Bangumi entities compose `cross-media-entities@15+bangumi@16`. Vocabulary revisions belong to [Conversion](../../packages/conversion/README.md#package-api).

The durable source tuple is configured alias plus exact external ID. The alias is bound to one normalized API origin before effects; destination placement is not authorization. Source records cannot choose providers or converter revisions. Importer validates external records and provider responses at entry, then trusts internal types, callers and modules. Current permission and exact source/facts fences are checked before effects. No SQL writer, extra scope or grant is introduced.

Conversion maps one selected normalized record with current bindings and exact released descriptors. It does not acquire, resolve identities, authorize, accept, adopt or read public results. Importer records source and request journals, prepares ordinary create/propose commands and retains exact actor, destination, body, key and response through retry. A run stages and validates one complete generation, checks mass disappearance, then seals before writes. Unknown delivery resumes the same sealed intent before source reacquisition; changed terminal receipts remain distinct. Retryable 429/503 stays bounded; authorization and fence refusals remain refusals.

## Command line, metadata and recovery

Run `bun services/importer/src/cli.ts` with `--source`, `--dump`, `--state`, `--api`, `--account-key`, `--account`, `--client` and `--auth`. `--help` needs no credentials, SQLite or network. `--dump -` reads plain stdin. Compression is explicit: gzip for Open Library/Wikidata, zstd for VNDB/Wikidata; it is never inferred from names. zstd requires one local regular file and trusted executable. Decoded input defaults to 256 GiB with at most one-window overshoot. gzip is refused for VNDB/Bangumi and zstd for Bangumi/Open Library before credentials or state; dump-set members remain none/gzip.

Decision: Every ordinary Bangumi alias admits pinned five-column PersonDetail TSV (`/type/person`, `person:N`, `unversioned`, cache ETag, JSON), retaining Person identity when careers disappear. Identity, type and the 64 KiB response cap are validated before Auth. ETags remain cache metadata. `--bangumi-person-career-bindings-file` supplies a finite JSON profile with `schemeId`, `schemeUri` (`https://rezics.com/schemes/bangumi/careers`) and up to seven `{code,id}` Concepts. These IDs are lookup hints: the existing mapper requires current native Scheme/Concept facts and released P106, with at most eight current reads per Person, including unchanged source refreshes. Missing bindings omit careers alone; unavailable reads retain the complete baseline for retry. Imports remain proposals pending independent acceptance and adoption.

Preview, capture comparison, inspection, disappearance review, diagnostics, resume, retention, staging retirement, backup and snapshot validation operate on bounded exact generations or pages. Diagnostics do not publish or rewrite. Interrupted unsealed acquisition is discarded. Optional checkpoints hash and resume the same bytes for large Bangumi, Open Library, Wikidata and VNDB COPY inputs. Sealed work resumes from its journal; a rejected source is not silently replaced.

Built-in descriptors provide each provider's record URL, attribution and metadata terms. Only a complete validated sealed generation sends metadata through the public source-record API under current `subject:batch_write` authority and its exact source tuple. Descriptor size is at most 8 KiB; a run has at most one intent per bound record, or two when an unresolved intent precedes a change. Each coordinator attempt allows at most eight invocations and each HTTP call at most five. The immutable request/result journal uses no expected revision for first write and the last returned revision thereafter; response-loss replay uses the original bytes and key.

## Native execution boundary

Kernel owns runtime, authorization, command execution and native reads. Importer does not add privileged writes, acceptance shortcuts or SQL adoption. Decision: review exact original `bangumi_cross_media`/`vndb_cross_media` claims through the released asynchronous merge contract; retain sealed intent and original bindings while observing native operation completion and separate public canonical reads. Client binds these exact methods while whole-Kernel declaration publication is pending. HTTP 202 is admission; HTTP 200 merge or an application reread is not completion. Current Person identifiers exclude deprecated rows and require every remaining value to agree. Native redirects resolve reads on the same API; manifest assertions and dependent credits keep original source ownership. Credits wait for current canonical delivery, not another binding or publisher.

## Deletion

Vanished source fields retract only matching importer-owned candidates through ordinary APIs. Subjects, adoption and unrelated statements survive. Current source/media fences prevent refresh from restoring withdrawn facts; see [deletion](../../docs/deletion.md).

## Cost

Bounds below describe importer-owned logical work, not PostgreSQL physical visibility/vacuum work. Indexed point reads use exact primary/owner keys and O(log R) or O(log B) navigation; keyset pages examine their bounded output plus navigation, never OFFSET or history scans. `R` is retained source/run records, `B` binding/journal rows, `M` one record/request/response bytes, `r` page/batch rows, `q` commands per record, `C/U` compressed/decoded bytes, `S` supplied records, `D` dependencies, `H` retained generations, and `K` concurrently active records. Transactions add BEGIN/COMMIT (or rollback); connection schema/PRAGMA work is excluded. Kernel internal cost belongs to Kernel.
