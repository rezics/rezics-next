# Importer

The importer owns source dump ingestion, durable SQLite run and record state, and replayable requests for platform writes through the kernel API.

## Cost

These bounds follow `src/`, without measurements: R is stored records (including retained run history), B is binding/journal rows, M is one record/request/response's bytes, r is one page/batch's records, and k is rows changed; H is records already seen in a dump, C is a supplied chunk's backing bytes, S is supplied table/snapshot rows, D is disappearances, and q is commands for one record.
An indexed point operation examines at most one matching row plus O(log R) or O(log B) B-tree navigation; a keyset range examines its bounded results plus that navigation, without OFFSET, history enumeration, or COUNT scans.
Below, PK means the declared primary-key index, SELECT/INSERT/UPDATE/DELETE counts exclude connection-time schema/PRAGMA work, and each transaction adds BEGIN IMMEDIATE plus COMMIT (or ROLLBACK on failure); methods make zero kernel calls unless explicitly described.
Run/record pages cap r at 100, VNDB pages at 16, internal VNDB ranges at 32, and command/result batches at 100; accepted run projections/public envelopes and binding snapshots cap M at 65,536 bytes (source-record projections add a small wrapper), while private record plans cap M at 2 MiB and q at 300 (classification alone caps q at 100); record metadata has fixed field byte limits of 64/512/256/64/128 for source/key/revision/digest/converter revision.
Growth checks below cite exact existing titles only for the exercised paths; outcome checks cover limits and failure handling rather than every growth path.

The table loader can still retain unbounded chunk backing from arbitrary entry providers, although `readArchive` enforces caller-supplied backing and total-byte limits.
The HTTP adapter bounds owned request/final-response buffers, attempts, waits and elapsed time, but a supplied request stream can transiently expose uncapped backing storage.
Run leases and atomic SQLite updates coordinate workers sharing one database file and single writer, which still exceeds the multi-machine criterion.
Run-store and resolver descriptor validation enumerate caller object keys before rejecting oversized input, so accepted JSON caps do not bound hostile object width.
The concrete media resolver bounds calls and scheduled waits per invocation, while injected coordinator providers and repeated run invocations have no lifetime API-call bound.
