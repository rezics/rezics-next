# Control-plane deletion and simplification

## Recommendation and boundary

Adopt one durable job lifecycle in Bun and SQLite, one mechanical dev landing queue, and one source-bound
promotion pipeline. Delete duplicate lifecycle representations before extracting the remaining responsibilities.
Keep current-attempt fencing, immutable source identity, owned-process cancellation, bounded resource admission,
and the full promotion gate. They prevent concrete failures; removing their extra implementations is the saving.
Do not add a new orchestration service to simplify this controller.

This is a proposal, not an adopted change to delivery policy. No controller or harness code changes accompany it.
The report stays at the contract's named path rather than creating a second research authority under `docs/research/`.

The retained source is commit `7eca27f3e695e35a16f5a5d8f518bf4ef261511c`. At this revision there are **96**
non-`*.test.ts` TypeScript files under `tools/goal/src`: 92 at its root and four provider adapters, totaling
**46,338 lines**, including test-support modules. The four named harness files total **14,146 lines**;
the 22 first-party harness modules inventoried below total **24,847 lines**. Release/probe entry points under
`tools/goal/scripts` add more. These are physical line counts, not a claim that every line executes in production.
The launch brief's earlier counts are consequently not the deletion baseline.

The inventory covers every source module, its operational guards and recovery families, the harness dependency
closure, and release/probe entry points. It does not audit application business logic or third-party code.
Source was inspected statically, including import edges, entry points, test names, selected large-function ranges,
incident notes and repository history. No live database, process or host inventory was acquired. Thus an unused
export, an optional adapter or an apparently empty legacy table is not declared dead merely from this snapshot.

In the tables, **delete** removes the mechanism, **merge** removes its independent policy/state implementation
while preserving the stated guarantee, and **keep** names a current purpose. Decisions describe the end state;
stages below specify when removal is safe. An incident dash means no specific incident was established in the
bounded evidence, not that absence of incidents proves correctness. Importer lists include type-only consumers;
CLI, preload and script entry points are called out separately. Tests establish prevention scenarios, not proof
that those scenarios occurred on a host.

Git worktrees and the existing systemd/SSH check hosts; no upstream implementation should be copied.

The shared pattern is a small set of authorities: desired job state, owned execution, immutable candidate and
result. Their responsibilities may have many functions, but they do not each need another custody protocol.
Mature projects also contain large files; file size alone is not proof of poor behavior. Here the incident trail
and duplicate ownership/state machines justify deletion. Module-size targets below are refactoring guides,
not another brief-admission cap.

## Target design and invariants

A job record should own a source snapshot, contract hash, command specification, resource profile and generation.
A physical-execution record should own its host/run identity and native result; a single job may have several
physical executions only when policy explicitly permits retries. Observers deliver events; they do not re-decide
which task, source or original proof those executions belong to.

Use SQLite transactions and unique keys for local claims, retry intents and result delivery. Use short directory
leases only where filesystem/Git operations cross the database boundary. Record intended ref advancement,
perform expected-old-head `update-ref`, then reconcile the stored intent after a crash. Never hold the global
landing lock across network transfer, test execution, dependency installation or artifact maintenance.
A host-side resource lease/cgroup still spans the physical run; it serves a different purpose from a ref writer lock.

The minimal execution phases are preparation, queued, claimed/running, native-terminal and settled; cancelled
and unknown-custody are explicit dispositions. Native result, artifact return, cleanup and message delivery are
independent facts. For example, native exit 1 plus a failed return transfer remains a failed command with an
unsettled return; a failed delivery retries delivery. It never reruns the command implicitly. A successful command
with unknown owned processes cannot release their slot as though cleanup were proven.

Keep the worker and check handles as adapters for existing consumers. Ordinary dev work commits and performs its
scoped typechecks, enters a mechanical candidate/ref queue, and is checked at the bound integrated revision by
the asynchronous verifier. Unchanged claims retain their bound clean source and frozen acceptance; integration
completion alone never manufactures green acceptance. Promotion freezes its own current candidate and passes
all required checks before main advances. Original-proof execution retains its stricter authorization and no-replay
rules; those rules do not spread back into ordinary product delivery.

The design needs no code from another Goal. Interfaces can be introduced behind the current CLI, store and
runner adapters. A migration can translate old records lazily on access, but cannot infer that unknown executions
are terminal or that a changed contract is equivalent.
