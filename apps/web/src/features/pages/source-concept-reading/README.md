# Source concept visits

The reader uses the catalogue admission for one subject, locale and original role. Replacing any of them starts a fresh visit; a retired admission cannot return through an equal account or address.

A failed hierarchy request retains a separately identified last readable page only when subject, release, revision, context, type, role and session receipt all match; retry repeats the failed input and navigation intent.

Decision: retain the delivered eight hierarchy page addresses within the existing 8 KiB visit descriptor. Truncation announces the retained window and offers a fresh first-page restart; tests exercise that current limit rather than the former five-address window.

Whole-subject failure withdraws source data and private advice. Native correction advice remains independent of hierarchy readiness. The existing classification and work-tag origin rules also apply to direct callers.

Decision: Concept and Global Music Context companions consume `subjectGraphVisitReturn` for graph returns, preserving its exact admitted address and original anchor even when the companion Subject differs. The shared parser owns graph filters, direction, depth, selected node or exact edge, locale, public Context/Realm intent and the 2,048-byte limit; neither receiver rebuilds the address or adds a grammar. Music's graph branch requires a Global companion Context without Realm; its ordinary same-Subject quotation/release rules stay unchanged. Graph coordinates grant no native reading or correction authority. Reload and return use the existing current-reader read and focus owners, and replacing the address or caller retires pending companion results. This adds constant bounded parsing, no reads and no retained graph body.

The human name and definition lead the visit. Aliases retain their language; the original identity and release are optional disclosures. Scheme, code and broader sections iterate original native assertions, including distinct assertions of the same target. Each whole assertion, its target, inspection address, qualifiers and citations uses the existing numeric `rezics:spoilerLevel` gate and current reader preference. A boolean warning is not native spoiler admission. Unlabelled or withheld item values never fall back to their IDs. Bounded inverse rows without an inspectable assertion show unavailable evidence.

Inspection reuses `FactInspectionEntry` and its exact holder/property/statement/Context value explanation address. Local evidence disclosures reset after each completed read and on source, locale, preference or caller replacement. Follow uses `FollowTargetControl` with the source's current-origin lifetime; its native operation advice and sealed recovery remain library-owned. Correction still requires the exact advertised action and operation. Works/filter admission and cursor ownership are unchanged.

Admission uses the existing fact limits: 1 MiB UTF-8, 4,096 statements, 32 qualifiers, 32 reference groups and 32 parts per group; the inverse window is capped at 20 rows. Oversized input fails explicitly before aliases or evidence expand. For admitted source bytes B, statements S, qualifier/reference parts Q and hierarchy cap H, adapter work is O(B + S + Q + H), with bounded extra serialization/copy passes. The byte admission also charges each repeated disclosed item/property/unit summary; label selection, copied strings, reference rendering and nested summaries therefore fit the same 1 MiB expansion budget. IDs do not bound text or response bytes. No source catalogue/history traversal, per-row Subject reads or automatic hierarchy loading is introduced. The existing signed-in Subject preference query remains its owner's one exact account-preference read; follow state and explicit inspection use their existing bounded owner endpoints.

Decision: Works wait behind each required native scheme-assertion reveal because their selectors expose scheme identities; the original filter admission, tuples and route state remain unchanged.
