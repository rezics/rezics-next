# Music location reader

The ordinary Subject overview gives released places, administrative areas, events and instruments distinct identities
and a bounded reader for their admitted relationships. It uses the current typed Subject read and the actual active
definitions release. Generic Subject facts and the existing correction access stay in the ordinary page. The dedicated
[MusicContext profile](../music-context-profile/index.ts) remains available for its existing route and correction path.

Only a released Type admits a music-context identity. Forward properties must be admitted on that Type; inverse
properties must be admitted on a released source Type and target the current identity. Relationship labels, direction,
qualifiers and references come from those definitions and the native assertion. A destination links only when the
current page returns its exact readable summary. Unsupported Types have an explicit state; sparse facts, hidden targets
and unsupported coordinate strings never become invented values or links. No map, editor, generated declaration or
provider mapping is added.

Decision: previous navigation evicts the oldest address first at eight addresses; Start explicitly reads the selected
stream again. Related Subjects open in a same-locale new tab; a keyboard return within 30 seconds restores the source
link only after the window lost focus and while the exact accepted reading and focus origin remain current.

## Cost

One selected stream window uses the current exact Subject read, the shared active-definition pointer and immutable
Release reads, and at most one native relation or links page: at most four additional reads, with no target hydration
or writes. The Subject response is limited to 2 MiB. A Release keeps the existing 1,024-Type and 4,096-property bounds;
at most 64 relation streams are accepted. Each native page has at most 20 rows, each at most 128 KiB serialized UTF-8
JSON, and at most 2,686,976 total bytes. Opaque cursors are at most 4,096 UTF-16 units and an immediate repeat is
unavailable. The reader retains one accepted page, up to eight accepted navigation addresses, one pending address and one keyboard
origin. No historical response bodies are retained. Previous reads the original opaque address and session, with no
calculated offsets; after oldest-first eviction, Previous stops at the earliest retained address. Start discards that
trail on success. Stream selection discards the old cursor and trail immediately, reads that stream's start, and shows
any retained response explicitly as the last accepted reading. Only dependency-unavailable permits that retained page;
denied, withheld, invalid and stale responses remove it and its navigation. Retry resends only the exact unavailable
address and session. Native session chaining applies to new forward reads, never to rewrites of retained addresses.

Refresh current Subject invalidates the existing route loader without altering its URL or local region parameters.
It drops the old page, addresses and native session before requesting a new admitted Subject. Only the requested public
stream key is carried into the new observation of the same Subject/context/locale/viewer. The native reader validates
it against the new descriptors. If it is no longer admitted, the reader explains this and offers an explicit read of
the current choices; there is no automatic second page request or retry. The existing route owns private admission.
Completion messages remain local; page navigation does not move focus. Work is O(Release
metadata + current Subject/page bytes), independent of total catalogue size; transport and runtime allocations add
transient memory.

Focused tests pin distinct identities, released direction, partial-date qualifiers, hidden summaries, stale observations
and exact same-locale Subject destinations. Stories use authored examples and do not establish native configuration or
rendered acceptance; integration owns broader acceptance, theme/viewport rendering and native publication checks.
