# Music location reader

The ordinary Subject overview gives released places, administrative areas, events and instruments distinct identities
and a bounded reader for their admitted relationships. It uses the current typed Subject read and the actual active
definitions release. Generic Subject facts and the existing correction access stay in the ordinary page. The dedicated
[MusicContext profile](../music-context-profile/index.ts) remains available for its existing route and correction path.

Only a released Type admits a music-context identity. Forward properties must be admitted on that Type; inverse
properties must be admitted on a released source Type and target the current identity. Relationship labels, direction,
qualifiers and references come from those definitions and the native assertion. A destination links only when the
current page returns its exact readable summary. Unsupported Types have an explicit state; sparse facts, hidden targets
and unsupported coordinate strings never become invented values or links. A withheld destination is named without
exposing its identifier or implying that the view is empty. No map, editor, generated declaration or provider mapping is added.

Decision: related Subjects open in a same-locale new tab; closing it returns keyboard focus to the source relation link.

## Cost

One selected stream window uses the current exact Subject read, the shared active-definition pointer and immutable
Release reads, and at most one native relation or links page: at most four additional reads, with no target hydration
or writes. The Subject response is limited to 2 MiB. A Release keeps the existing 1,024-Type and 4,096-property bounds;
at most 64 relation streams are accepted. Each native page has at most 20 rows, each at most 128 KiB serialized UTF-8
JSON, and at most 2,686,976 total bytes. Opaque cursors are at most 4,096 UTF-16 units and an immediate repeat is
unavailable. The reader retains one accepted page, one pending address and one keyboard origin. Work is O(Release
metadata + current Subject/page bytes), independent of total catalogue size; transport and runtime allocations add
transient memory.

Focused tests pin distinct identities, released direction, partial-date qualifiers, hidden summaries, stale observations
and exact same-locale Subject destinations. Stories use authored examples and do not establish native configuration or
rendered acceptance; integration owns broader acceptance, theme/viewport rendering and native publication checks.
