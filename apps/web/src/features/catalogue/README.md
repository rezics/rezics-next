# Catalogue creation

Music context, catalogue file and Concept creation use `creation-host/use-creation-host.tsx`
for the mounted metadata reading, last good release, retained term/fact types, archived choices,
refresh exclusion and review revision. Profiles retain native preparation, commands, field admission
and labels. `CreateSubjectForm` remains the term editor and review/command authority.

Decision: a refresh attempt retires review authority even if recovery returns the same digest;
archived choices remain available during a failed refresh so retained drafts can be recovered explicitly.
The existing `useCatalogueLifetime` boundary fences reader/address replacement without another observer.
Concept owns classification return and leave confirmation; file hash/codec explanations remain profile notices.
The shared statement summary projects values through `PartValue`, preserves evidence order, and renders
translated normal, preferred or deprecated rank meanings without reconstructing command operands.

Album, Character, People, Literary, Screen, Addon, publication and changed-fact reviews adopt
`statement-summary.tsx` directly within the catalogue UI boundary. Released property labels and identifiers
remain visible for the main assertion, ordered qualifiers and each original reference group, including empty
groups; `PartValue` owns value states, time precision, calendars and uncertainty. Missing labels retain their
property identifiers. Consumers retain their profile headings, admission notices, related labels and exact
field-return controls. Album and Character still apply `creationStatement` before rendering; changed-fact
review projects the current native rank separately so deprecated assertions remain deprecated without changing
editable operands. Current and proposed assertions remain independent, with an explicit absent baseline.
Review is a projection of the caller's captured draft: it neither prepares commands nor renews caller authority.

Recipe creation and correction also consume `StatementSummary` unchanged for ordinary assertions. Recipe keeps
its field meaning, exact term/row return and authored-document presentation local: the validated `DocumentBody`,
language and licence appear once per supplied side. Only a supplied proposed originality declaration is shown;
current readings do not infer historical originality. Local document evidence uses the same `PartValue` semantics
and retains property identifiers, fallback languages, ordered groups (including supplied empty groups) and rank.
Correction lists render the existing `recipeEvidenceChanges` current/next observations independently, including
replaced and removed groups, without claiming stable citation identities. Returning to a field retires unsent
review; explicit revised review uses sanitized evidence while an uncertain command retains its original operands.
