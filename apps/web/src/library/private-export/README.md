# Web private Library export consumer guide

Web owns the signed-in `/library/export` visit, separately from public Collection ItemList export and personal-list
import writers. Commerce owns the capture, its source fence, authorization, expiry, limits and native record
meanings. The [native contract](../../../../../docs/library-export.md) is authoritative for those details.

Decision: new captures use version 4; stored version 1, 2 and 3 captures keep their original sections, record shapes,
manifest fields, byte accounting and cursor epochs. Version 3 keeps the 17-section version 2 inventory and adds
`journal.assessment` with `meaningRevision: 1` and `units` from 0 through 20 or `null`. Missing assessment in a
stored version 1 or 2 journal remains absent.

## Versioned coverage

The installed `libraryExports` methods are the only transport. If a mounted method is absent or its response does not
match the generated contract, the visit stays unavailable. Web does not build a second export or fill gaps from other
private readers.

Version 1 remains the fixed historical coverage. It has no annotation, provenance or journal claims and no section
totals. Version 2 adds the `annotations`, `provenance` and `journals` sections and declares row and record-byte totals
for every section, including sections with zero rows. Version 3 retains that inventory and accounting while adding
the private journal assessment. Version 4 appends `vndbUploads`, `vndbEvidence`, `anilistUploads`, and
`anilistEvidence`, uses `private-library-owner-facts-v4`, and counts all 21 sections. Web keeps the native record
fields and meanings intact, including absent, null, invalid and zero provider values.

- Annotations are independent owner facts. Their revision remains when note and priority are both cleared.
- Provenance keeps the accepted native provider and record IDs and preserves unknown, absent, cleared, private and
  source-visible values as distinct states. A source-visible choice does not publish this Library.
- Journals belong to live occurrence rows and keep their native occurrence/session IDs and independent journal and
  progress revisions. Partial dates remain partial, cleared dates remain `null`, and empty reflections remain
  distinct from `null`. Web does not infer an import-to-journal link.
- Native Collection, Entry and progress recovery admit original versions 1 through 4.
  Version 3 assessments stay unsupported for Collection recovery. Version 4 provider evidence stays in native validation, accounting and unsupported coverage.
  Downloaded evidence does not set votes.

Decision: admit the published V4 vocabulary through the installed client declarations while treating provider records
as opaque JSON and replaying cursor tokens unchanged. Provider scores, dates and identifiers grant no write action.
Recovery sends the original file bytes to native validation. No browser manifest rebuilding, section removal or
version conversion occurs. Current and retained exports keep their exact inventories and original retry bytes.

The connected producer stories and focused tests consume the V1/V4 HTTP responses in `recorded.json`, generated by
`apps/web/scripts/record-private-library-export.ts` from a disposable database and the installed producer. They retain
the signed cursor strings, every empty continuation, native metadata and provider records, and the final artifact
string. Existing illustrative V2/V3 cases preserve their original inventories and absent/null/zero assessments.
Recording retained V2 status on the base producer raises `TypeError: Invalid cursor`; retained epochs remain opaque
to Web, and V2/V3 keep the existing illustrative compatibility cases.

Decision: replay recorded visits at their captured clock in stories and tests, preserving the original expiry,
response fields, cursor tokens and artifact bytes; production continues to use the live clock and local delivery.
Provider upload identities and parsed evidence have distinct localized labels beside their own section totals.

## Export presentation and focus

Decision: review, capture progress and the completed artifact form the primary task. Download or exact save retry
stays beside completion and its warnings; every native omission remains visible. Labelled native disclosure holds
the full manifest and all supplied section totals, indexed once per manifest. Restore destinations follow the task,
explain their independent purposes and retain the existing owner-bound original-archive reuse. Creating or
saving an archive never implies restoration. Export-to-restore links use router navigation so the completed
original bytes remain in memory; the completed departure message explains that reuse separately from device save.

Keyboard activation may orient to the persistent task heading only in its immediate render when the initiating
control disappears or becomes disabled and focus intent is still current. Pointer, keyboard or focus movement
revokes that intent. Background stage, notice, busy and page updates announce through one stable polite status
without moving focus. The same rule covers capture, cancel, exact command retry, replay, save and restart.
Default opening stays still; viewport selection is manual. Stories distinguish producer recordings from illustrative
states. The mounted cancellation case in the [export regressions](../../../tests/private-library-export.test.tsx)
expects asynchronous outcomes to preserve moved focus. The same file pins ordering, disclosure, immediate keyboard
intent, exact save retry and original replay identity. Execution and native keyboard/eight-locale phone and desktop
acceptance belong to integration verification.

## Capture and local file

The person starts a capture explicitly. Web binds every page and final manifest to the original capture ID, version,
coverage, timestamps, sections and fifteen-minute expiry. It continues through empty intermediate pages, but rejects
mixed captures, unsupported versions, malformed terminal pages and any mismatch between assembled records and the
native totals.

Pages contain at most sixteen records and 120,000 encoded record bytes. Version 2, 3 and 4 records are at most 65,536
encoded bytes; the stream stops at 100,000 records or 32 MiB of record bytes. Cursors are at most 4,096 characters.
Version 1, 2, 3 and 4 cursor epochs remain separate and opaque to Web. Native work is `K + C + R`: K returned pages (including empty
continuations), fixed create/status/cancel calls C and explicit retries R. Assembly is O(N+B), with retained memory
bounded by record bytes, final framing and manifest, plus one page. Final serialization uses one bounded JSON string
and one encoded byte buffer.

No partial, stale, limited, expired, cancelled or unfinished stream offers a file. A failed local save retries the
same completed bytes. If those bytes are lost, replay starts from the original cursor under the same capture. Cancel,
unmount and viewer or CSRF replacement clear in-flight private state and ignore late results. A completed artifact
stays with this signed-in owner in process memory so Collection, Entry and progress recovery can reuse those exact
bytes. Another account cannot inherit them. Private bytes stay out of URLs, persistent browser storage and shared
caches.

Decision: offer Cancel only after creation resolves an identity; an uncertain create retains its original key and
only explicit Retry can resend it. Cancelling immediately stops traversal and clears incomplete bytes. Pending
cancellation coalesces activations; an uncertain acknowledgement retains the exact command for explicit Retry,
without a replacement capture. Only an admitted terminal result acknowledges disposition; expiry and native
refusal remain distinct from cancellation. Restart requires an acknowledged disposition and deliberate action.

Decision: pin export-to-restore with journey tests for owner-keyed completed-archive custody, exact original
artifact bytes, opaque sequential cursors, original-intent retries, Collection readback and other-member denial;
keep the existing named upload, review and result stories. Recovery destination labels are localized.
Decision: native Web fixture personas alice (owner) and bob (other member) plus actual Kernel commands prove the
export-to-restore walk; dump seed identities are not required for owned Library facts. Unreadable archive bytes pass
through to the native decoder.
