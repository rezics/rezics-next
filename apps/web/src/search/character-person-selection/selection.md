# Character and person operands

Character search uses native inverse P453 appearances. People uses native inverse P725 voice-performer statements,
not every creator relation. P3831 constrains the same statement. The mixed Search page remains the broader name route.
No work selection is required for name search. Ordered label languages, spoiler threshold and sort remain authored inputs.

Work choices use native suggestions constrained to the released concrete CreativeWork types; their actual type, date and available
creator/relation context distinguish imported entries. Role choices use only the active release's P3831 target types,
and are offered only when that qualifier is admitted on the mode's statement property and a work is resolved.
A role choice is an operand, not a promise that a selected work has a matching statement. An empty result is honest.

The reversible UI budget is eight selected works and one role, within the native predicate's existing bounds.
Changing works or mode clears role advice. Apply submits exact IDs as repeated work parameters and an optional role;
labels and typed suggestion text never enter identity. Removing unresolved URL values is the repair path.

Retained identities are read individually through the existing suggestion BFF's public subject-get adapter, bound to
its current release and target types. Concealed, missing, redirected or unlabelled subjects remain unresolved. An unavailable
read never becomes a label match. Refused scopes never retry as Global. Labels are presentation only and can change.

The Search visit composes the shared browser observation and public retiring address lease. Reader, address, locale,
release or operand replacement retires candidates, labels and picker focus. Label resolution is bounded and abortable;
obsolete completions cannot enable Apply. The shared EntityPicker owns keyboard selection and candidate retries.
Metadata and selected-label failures have explicit manual retry. Pending or refused selected operands disable Apply;
unrestricted name search remains available when there are no selected operands. Any deliberate form edit hides the
previous results and continuation until Apply, retaining unrelated inputs.
