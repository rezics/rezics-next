# Public profile reading preferences

The overview and non-Realms views consume one browser-only own-account preference response per mounted public
page and explicit activation. `session/observation.ts` owns session incarnations; local address/read leases only
fence application of prepared server responses. Anonymous HTML, metadata, public identity and contributions remain
independent of that response. Native Settings outcomes distinguish unavailable, preparing, closed, signed-out and
mismatched reading from successful conservative preferences. Failure retires the private query; retry acquires a
fresh lease and query under the current page and reader, without a public page reread.

Decision: retain a compact read-again trigger throughout the signed-in episode so completion announces its status
without moving focus; reset local cover and spoiler disclosure when the preference response changes, preserving public
navigation and the existing populated/empty contribution return-recovery mounts.

The Settings editor remains Performance-owned. Content owns contribution context and native actions; this adapter
supplies neither author-context preparation nor operation authority.

Stable composition component identities are required to keep public links and existing return-recovery hosts mounted during preference updates; reading response scope resets disclosure controls without replacing those hosts.
