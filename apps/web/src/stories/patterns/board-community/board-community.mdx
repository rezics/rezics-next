# Community feed

The board route uses `BoardCommunity` and `BoardFeed`: a banner fallback and initials, the native board title,
optional Realm summary, current participation, sort links, disclosed opening text and supplied activity counts.
The shared shell owns navigation. The About column follows the feed on a phone and sits alongside it on desktop.
Each row reuses the existing batch author identity, shared byline, row overlay and adaptive overflow menu.

Plays open the actual thread and composer routes, change sort and continue the exact returned page. Overflow uses
the shared dropdown or phone sheet. Use the same IDs at phone390/desktop1280, with locale and theme globals.
Loading, empty, error, protected and closed are separate states. SourceUnavailable removes optional Realm metadata,
without creating Global authority. These recorded-response states do not prove native permissions or signing.

Global boards offer the existing composer path after sign-in and have no Join. Realm creation entry waits for the
existing private membership/participation query. A refused or unavailable read offers no creation permission;
accepted membership commands still wait for the native standing refresh. The composer retains native refusal,
CSRF and unchanged-intent retry behavior.

Board DTOs currently supply no board description, member count, banner, avatar or rules. The optional Realm summary
is the one-line description. Decorative token surfaces and initials are image fallbacks; no owner image stands in
for a community. The identity batch currently supplies no avatar summary. No media thumbnail is guessed from a
post's media ids, and no per-card detail/profile/media request is added. Counts absent from a response stay absent.
Ranking time lives in the optional order help, with no invented freshness claim when missing.
