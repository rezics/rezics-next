# Creator sale reading

The existing `/creator/sales` visit reads the current creator's native page through
`useCreatorCurrentOrigin` and `readCreatorSalesCurrent`. It admits at most twenty sales and preserves the opaque
cursor, including its existing 4096 UTF-16-code-unit bound. The captured title retains its existing 1024-unit
bound. Opening an inspection, copying a reference and preparing destinations add no requests.

The list keeps the recognizable captured title, exact recorded price and currency, tax meaning, settlement and
ordered time. Inspect sale focuses the reading heading. The selected reading exposes the full wrapping title,
exact amount, raw integer, captured money-unit precision, tax meaning, distinct settlement explanation, exact
recorded timestamp and labeled sale, offer and work references. Unknown money units show amount unavailable and
the stored integer; they never borrow today's currency precision. The amount is a charged unit price, not a
revenue total or payout. Pending, failed and unknown payment observations cannot establish earnings.

Escape or Close returns focus to the surviving initiating button without changing the address. Copy includes the
localized Sale reference label; missing or refused clipboard access offers selectable text and reports failure.
A reference is not an export, receipt or permission to read the buyer's order. Copy success belongs only to the
still-open selection that initiated it, including when the same sale is closed and reopened.

## Lifetime and cost

Build one O(N) identity index per admitted page/address/source, N <= 20, referencing the existing page rows.
Selection and lookup are O(1); the renderer inspects one row and compares at most three exact sale references.
Retain only the current page, one inspected identity and up to three comparison identities with opaque source/selection tokens. Do not accumulate pages or store private sale data in browser storage,
URL search parameters, fragments or history state. Index preparation adds no reads, enrichment or preview calls.

Decision: select up to three exact sales; browser Back restores an in-memory departure only on the same admitted
source, locale, cursor and visit, while every replacement observation requires deliberate reselection.

Locale, requested cursor, account, exposure or read replacement retires inspection and all pending clipboard
results synchronously. Even an equal-ID response is a fresh observation. The current Query observation count and disabled structural
sharing distinguish replacement responses, including equal results. Stale handlers cannot reopen a replaced source, navigate its destinations or publish copy
feedback. Authorization remains exclusively with the existing origin; preparation, loading and refusal cannot
retain an old reading. A native partial projection may contain supplied rows and its preparing notice; that
projection state does not imply authorization preparation or completeness.

Explicit refresh uses the existing current-source Query reader at the original cursor, retires selection during
the request and admits a new observation before reselection. Page links retain ordinary native pagination. The native `next` remains opaque. A stale cursor offers a
restart; empty first and continuation pages remain distinct, and a preparing projection never asserts zero sales.

## Destinations and ownership

Only UUID-validated `offerId` and `targetSubjectId` become links. The offer uses the ordinary localized public
offer reader; the work uses the canonical Subject overview helper with an unavailable-label slug, never an inferred
work kind, current work title or benefit. Each reader applies its own availability and admission. A retired or
unreadable destination does not change the recorded sale or guarantee a current price. Standard anchors and browser
Back preserve the sales address/cursor; no private metadata or arbitrary return URL enters the public destination.
The sale's `orderId` stays a sale reference and never becomes a buyer-only order link.

Creator Offers and Royalty Statements remain adjacent navigation; inspection also prepares the ordinary statement
list destination without a period or line claim. Statements have independent period and line
authority. No delivered relation associates a sale with a specific statement, and a paid purchase never proves
creator payout. Commerce retains offer, sales, settlement and payout contracts; buyer entitlement and payment
controls keep their existing owners. This visit introduces no new native method, statement join, financial engine,
refund command or aggregate.

Constructed Creator Sales stories cover the supplied states and interactive reading loop. They do not establish
native execution, browser geometry, authorization or runtime acceptance; integration owns those checks.

## Received-page review

Review controls match captured title text, exact work and offer references, and supplied payment state within the
received page only. All active conditions apply together. Reset restores the original rows and native ordering,
without fetching another page. No-match is separate from native empty and preparing states. Facet counts and currency
observations describe all received rows, not an account inventory or the currently filtered subset. Work references
do not gain an inferred work title. Equal offer references and captured titles never collapse sale identities.

Comparison retains up to three exact order IDs from the same page even when filters hide them, and visibly names
hidden selections. Each card preserves captured title, work/offer references, original creation observation, charged
unit price, raw integer, currency, tax meaning, unit provenance and native payment state. Recorded-unit metadata is
compared as supplied facts only. The money core is not delivered on this base; existing display adapters remain the
seam, and no arithmetic, sorting by money, conversion or combined amount is introduced. Comparison is read-only.

Reference copying names sale, offer, work or recorded terms and previews exactly the bounded text to be copied.
The terms copy is one observation, never a receipt, payout, statement match or reconciliation. Changing the reference
kind retires feedback; changing the source or selection retires every clipboard completion and expanded detail.

Departure capture stays in the existing mounted reader and contains source identity, locale, native cursor, selected
order ID and validated destination. Only the exact localized offer, Subject overview, creator offer-list and statement-list addresses
are supported, with no extra search or fragment. Browser page suspension invalidates pending selection effects.
On same-document return, the original admitted source and exact order must still exist at the original address.
A full reload, replaced observation, different account, locale/address or visit discards the capture and requires
reselection. No private identity is persisted in storage, history state, query parameters or public destinations.
