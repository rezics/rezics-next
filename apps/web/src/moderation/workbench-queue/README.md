# Workbench directory visit

The served `/moderation/workbench` loader prepares the retained private reader before dispatch. Session replacement
is observed synchronously, including an equal successful response and a batched account switch back to the original
account. Fetch start does not replace a successful session. The route's original abort signal participates in the
request through preparation, server dispatch, native parsing and final publication. Locale and navigation replacement
retire controls and late focus recovery.

Production discovery stays on `nativeModerationDirectoryUnavailable` until the official installed KernelClient
callable and response-derived types arrive. The local directory contract is a consumer seam, not a production DTO or
coverage claim. Board and catalogue exact reads remain usable independently. Only native `viewer.open` advice can
create an enabled directory selection; queue and case owners retain command authority and uncertain command intent.

Decision: directory return preserves the original opaque frontier and optional Realm filter as local search operands,
then checks that page again; it never restores old advice or accepts a return URL.

Decision: a per-query-client in-memory queue chain retains at most nine validated cursor addresses and the independent
directory return operands; explicit native movement, refresh and same-session case/History handoffs preserve it, while
direct visits, reloads and unapproved navigation start without predecessors.

`directoryCursor` belongs to discovery; `cursor` belongs to one exact selected queue. `directory` records discovery
return context and `directoryRealm` preserves its filter independently of a Board's disclosed parent. These operands
survive queue filters, tabs, pagination, exact report inspection and case return. They never select a reader identity
or confer access. An explicit directory restart clears the frontier; a failed continuation retries it unchanged.
Catalogue offers reports and resolved queues only. Subject inspection stays with the existing catalogue owner.

One replacing page is admitted per private visit. Sparse empty pages with a native `next` retain continuation;
complete empty, preparing coverage, denied advice, unavailable authority, expiry and continuation failure remain
separate states. Expiry removes labels and controls at the exclusive native horizon and requires deliberate restart.
A changed native source during recovery requires restart. Directory failure never clears an independently admitted
exact queue. Case return uses only validated local operands and keeps report, target, decision and appeal IDs distinct.

Keyboard recovery focuses the current retry control or current Workbench boundary only while the original focus
handoff remains owned. Announcements describe the current page, and long labels wrap on narrow screens.

### Touches, bound and growth

The private return chain stores only queue identity, up to eight previous cursor addresses plus the current address,
the independent directory cursor/filter, the private reader fence, and one report ID during a case excursion. At the
field limits this is at most 83,180 bytes of UTF-16 string payload: nine 4,096-character queue cursors, one 4,096-
character directory cursor, four 128-character identity/report values, two UUIDs, the seven-character locale, and
bounded queue/filter/order/mode/transition labels. This excludes JavaScript object overhead and the short-lived focus
control reference. No queue rows, action advice, credentials, command drafts or predecessor list enters URLs, shared
hydration or persistent storage.

One native page read of at most 20 rows backs each explicit Next, Previous, current-window Refresh, First or Retry.
Case inspection performs its existing one exact report read; returning performs one captured queue read before current
controls reappear. History keeps its existing independent reads. There is no prefetch, refill, cursor scan or per-row
read. Replacing any page retires its prior selection and advice, including an equal replacement.
